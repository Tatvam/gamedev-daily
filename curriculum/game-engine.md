# Game engine curriculum

How to use: take the FIRST unchecked item, top to bottom. After publishing its page, change `- [ ]` to `- [x]` and append ` (published <YYYY-MM-DD>, <slug>)` to that line. If you discover something worth covering that is not listed, append it to the Backlog section.

## Track 1: The game loop, scenes and lifecycle

- [ ] **The game loop** — How every engine repeats the same three jobs many times per second: read input, update the world, draw the frame. Demo: A step-through visualiser where you press Next to advance one phase of the loop at a time and watch a ball's state and the screen change only in the matching phase.
- [ ] **Update versus render** — Why simulation and drawing are separate steps that can run at different rates without breaking the game. Demo: Two sliders set the update rate and the render rate independently while a moving square shows what stutter, wasted frames and smooth motion look like.
- [ ] **Delta time in Godot and Unity** — How multiplying by the time since the last frame (the delta argument of _process in Godot, Time.deltaTime in Unity) makes movement speed independent of frame rate. Demo: Two squares race across the canvas, one moving a fixed amount per frame and one using delta time, while a frame rate slider shows the first one changing speed.
- [ ] **Fixed timestep and the accumulator** — How an accumulator lets the simulation run in equal steps even when frames arrive unevenly, and why interpolation hides the leftover time. Demo: A visualiser shows the accumulator filling and draining as you change frame time with a slider, with a toggle for render interpolation on a bouncing ball.
- [ ] **Frame pacing and vsync** — Why evenly spaced frames feel smoother than a higher but uneven average frame rate. Demo: A scrolling pattern and a live frame time graph respond to a jitter slider and a vsync toggle so you can see and feel the difference between steady and uneven pacing.
- [ ] **Nodes in Godot, GameObjects and components in Unity** — How Godot builds objects out of a tree of specialised nodes while Unity attaches components to generic GameObjects, and how the same player character looks in each. Demo: A side-by-side builder where you click to add a sprite, collider and script to a player and watch the Godot node tree and the Unity component list grow differently.
- [ ] **The scene tree and transform hierarchy** — How a child's position, rotation and scale are combined with its parent's to give its final place in the world. Demo: Drag and rotate a parent arm with two child segments on the canvas and toggle between showing local and global coordinates for each part.
- [ ] **Packed scenes in Godot, prefabs in Unity** — How both engines store a reusable template of an object and stamp out instances that can override individual values. Demo: Edit a template enemy's colour and size with sliders to see every instance update, then override one instance and watch it keep its own value.
- [ ] **Lifecycle callbacks: _ready and _process in Godot, Awake, Start and Update in Unity** — The order in which each engine calls your code when an object is created, enabled, updated and removed. Demo: A timeline stepper adds a parent and two children to a scene and lights up each callback in order for both engines as you click through.
- [ ] **Freeing objects safely: queue_free in Godot, Destroy in Unity** — Why engines delay deletion until the end of the frame and what goes wrong when an object is removed in the middle of an update. Demo: A loop walks over a row of enemies and removes some of them, with a toggle between immediate and deferred deletion that reveals skipped and broken entries.

## Track 2: Input, communication and data

- [ ] **Polling versus event-driven input** — The difference between asking every frame whether a key is down and being told at the moment a key changes. Demo: A key timeline shows your real presses against what a polled game sees, with a frame rate slider that makes quick taps go missing.
- [ ] **Input action maps: InputMap in Godot, the Input System in Unity** — How naming actions such as jump and move, instead of reading raw keys, lets one script support keyboards, gamepads and rebinding. Demo: A rebinding panel lets you assign any key to each action and immediately drive a character with the new layout.
- [ ] **Analogue sticks and dead zones** — How raw stick values are cleaned up with axial and radial dead zones so characters do not drift or snap to the axes. Demo: Drag a virtual thumbstick and compare the raw vector with the processed one while changing the dead zone type and size.
- [ ] **The observer pattern** — How an object can announce that something happened without knowing who is listening. Demo: Click a subject to fire an event and watch subscribed observers light up, with buttons to subscribe and unsubscribe each one.
- [ ] **Signals in Godot, events in Unity** — How Godot signals and C# events or UnityEvents implement the observer pattern, and how to connect and disconnect them safely. Demo: Drag wires from a player's health_changed signal to a health bar, a sound and a screen flash, then damage the player to see which connected listeners react.
- [ ] **Loading assets: load and preload in Godot, Resources and Addressables in Unity** — The difference between loading an asset up front, on demand and in the background, and the frame hitch each choice can cause. Demo: A running animation with a frame time graph lets you trigger a simulated large load as blocking or asynchronous to compare the hitch.
- [ ] **Asset references and dependency graphs** — How one reference to a scene can pull many textures and sounds into memory, and how referring to assets by path or address avoids this. Demo: Click any asset in a dependency graph to highlight everything it loads and watch a memory bar change as you switch links between hard and soft references.
- [ ] **Custom Resources in Godot, ScriptableObjects in Unity** — How data assets let many objects share one set of values, and when you need a unique copy instead. Demo: Edit a shared weapon data card with sliders to change every enemy that uses it, then press Make Unique on one enemy to break the link.
- [ ] **Serialization** — How engines turn live objects into text or bytes and back again, and why references and cycles need special handling. Demo: Edit an object's fields and watch its JSON and compact binary forms update live, then add a reference cycle to see naive serialization fail and an ID-based version succeed.
- [ ] **Building a save system** — What to save, how to identify objects across sessions, and how version numbers keep old saves working. Demo: Move and recolour objects in a small scene, save and load them through a text box, and toggle a format change to see migration code repair an old save.

## Track 3: Architecture patterns

- [ ] **Finite state machines** — How splitting behaviour into named states with explicit transitions removes tangled if statements. Demo: Control a character with the keyboard while a live state diagram highlights the current state and the transition that just fired.
- [ ] **Hierarchical and pushdown state machines** — How nested states share behaviour and how a stack of states handles pause menus and interruptions. Demo: Push and pop states such as play, pause and dialogue on a visible stack and see which state receives input and which ones still draw.
- [ ] **The component pattern** — Why composing objects from small reusable parts scales better than deep inheritance trees. Demo: Tick components such as movement, health, glow and gravity on and off for an entity and watch its behaviour change immediately.
- [ ] **Entity component system (ECS)** — How storing components in tables and running systems over matching entities differs from objects that update themselves. Demo: A table of entities and components sits beside a canvas, and toggling each system highlights the rows it queries and the entities it moves.
- [ ] **Coroutines in Unity, await in Godot** — How both engines let a function pause and continue on a later frame so that sequences read from top to bottom. Demo: A stepper advances frame by frame through a door-opening sequence and shows where the function is suspended and what resumes it.
- [ ] **The command pattern** — How wrapping actions in objects gives you undo, redo, replays and input remapping from one idea. Demo: Move a piece around a grid, then use Undo, Redo and Replay buttons while the command history list updates beside it.
- [ ] **Object pooling** — How reusing a fixed set of objects avoids the cost of constant creation and destruction. Demo: A bullet fountain runs with pooling on or off while counters show allocations per second and a graph shows simulated collection pauses.
- [ ] **The event bus** — How a central message channel decouples systems, and the debugging cost that comes with it. Demo: Fire game events and watch them travel through a bus to subscribers, then switch to direct references to compare the web of connections.
- [ ] **Service locator: autoloads in Godot, singletons in Unity** — How global services such as audio and saving are made reachable from anywhere, and how to keep them replaceable. Demo: Swap the registered audio service between a real one, a silent one and a logging one while the game code shown on screen stays unchanged.
- [ ] **Behaviour trees** — How selectors, sequences and conditions combine into readable AI that is ticked every frame. Demo: Move a player near a guard and step through each tick of the guard's tree as nodes light up as running, succeeded or failed.

## Track 4: Rendering and animation

- [ ] **Cameras and viewports: Camera2D in Godot, Camera in Unity** — How a camera converts world coordinates into screen coordinates through position, zoom and rotation. Demo: Drag, zoom and rotate a camera rectangle over a world map in one panel and see the resulting screen image in the other.
- [ ] **Layers and draw order: z_index and CanvasLayer in Godot, sorting layers in Unity** — How engines decide which sprite is drawn on top and how sorting by vertical position fakes depth. Demo: Walk a character around trees while changing layer numbers and toggling Y sorting to see it pass in front of and behind them.
- [ ] **Culling** — How engines skip drawing objects that are outside the camera's view, and what the visibility test itself costs. Demo: Move a camera over a field of a thousand objects and watch culled ones turn grey while a counter shows how many are drawn.
- [ ] **Draw calls and batching** — Why drawing many sprites that share a texture and material is far cheaper than switching between them. Demo: Sprites using three procedural textures are drawn in a random or sorted order while a counter shows the number of batches and a slider changes the sprite count.
- [ ] **Tilemaps: TileMapLayer in Godot, Tilemap in Unity** — How grids of tile indices store large levels cheaply and how chunks and autotiling rules work. Demo: Paint tiles on a grid with the mouse, toggle autotiling to see edges chosen by neighbour rules, and show chunk borders that redraw only when edited.
- [ ] **2D lighting: Light2D nodes in Godot, 2D lights in Unity** — How 2D lights cast shadows by projecting the edges of blocking shapes away from the light. Demo: Drag a light around boxes and watch the shadow polygons update, with a toggle that draws the construction rays.
- [ ] **Sprite animation: AnimatedSprite2D in Godot, Animator in Unity** — How a sprite sheet and a frame timer create animation, and how frame durations change its feel. Demo: A procedurally drawn walk cycle plays beside its sprite sheet with a highlighted current frame and sliders for frame rate and per-frame hold time.
- [ ] **Tweens and easing** — How Godot's Tween and Unity coroutines or tween libraries move values along easing curves instead of at constant speed. Demo: Pick an easing function from a list and watch a box move, scale and fade with it while the curve is plotted alongside.
- [ ] **Animation state machines: AnimationTree in Godot, Animator Controller in Unity** — How states, transitions and blend parameters choose and mix animations. Demo: A speed slider blends a stick figure between idle, walk and run while a graph shows the active state, transition progress and blend weights.
- [ ] **Skeletal animation** — How bones in a hierarchy move a character, and how forward and inverse kinematics differ. Demo: Rotate the bones of a procedural arm directly, then switch to inverse kinematics and drag the hand to a target.

## Track 5: Audio, UI and physics

- [ ] **Audio buses and mixing: audio buses in Godot, the Audio Mixer in Unity** — How sounds are routed through buses for music, effects and master volume, and how ducking keeps dialogue clear. Demo: Generated tones play through a small mixer with volume sliders, mute buttons and level meters for each bus, plus a toggle that ducks music under a voice tone.
- [ ] **Spatial audio** — How distance attenuation and panning place a sound in the world relative to the listener. Demo: Drag a sound source around a listener and watch volume and left-right pan meters respond, with a slider for the falloff curve.
- [ ] **UI anchors and containers: Control nodes in Godot, RectTransform in Unity** — How anchors, margins and containers keep interface elements in place when the screen changes size. Demo: Resize a simulated screen by dragging its corner and watch a health bar, minimap and menu follow the anchor presets you pick.
- [ ] **Resolution scaling: stretch modes in Godot, the Canvas Scaler in Unity** — How games handle different resolutions and aspect ratios with stretching, letterboxing, expanding and integer scaling. Demo: Drag a window to any size and switch between scaling modes to see the same pixel art scene distort, gain bars or show more of the world.
- [ ] **Physics bodies: static, kinematic and rigid bodies in Godot and Unity** — What each body type is for and who is responsible for moving it. Demo: Drop and push three bodies of different types in a small sandbox and compare how each responds to gravity, collisions and direct movement.
- [ ] **Collision layers and masks** — How layer and mask bits decide which objects can collide, in Godot's per-object layers and masks and Unity's layer collision matrix. Demo: Tick boxes in a layer matrix and watch players, enemies, bullets and pickups start or stop colliding in a live scene.
- [ ] **The physics step: _physics_process in Godot, FixedUpdate in Unity** — Why physics code belongs in the fixed step and how mixing it with per-frame code causes jitter. Demo: A timeline shows physics ticks against render frames while a moving object is drawn with and without interpolation at frame rates you choose.
- [ ] **Broad phase and narrow phase collision detection** — How engines use grids or trees to find likely pairs before running exact shape tests. Demo: Moving circles are tested by brute force, a uniform grid or a quadtree while a counter shows the number of pair checks and the partition is drawn on screen.
- [ ] **Tunnelling and continuous collision detection** — Why fast objects pass through thin walls and how swept tests and raycasts stop it. Demo: Fire a bullet at a thin wall with a speed slider and a continuous detection toggle, with each step's position drawn to show the gap it jumps.

## Track 6: Performance, tooling and networking

- [ ] **Memory management: garbage collection in Unity C#, reference counting in GDScript** — How each engine reclaims memory, and why per-frame allocations cause hitches in one while reference cycles cause leaks in the other. Demo: A slider sets allocations per frame and a graph shows simulated collection spikes, with a second panel where you link objects into a cycle and watch reference counts fail to reach zero.
- [ ] **Profiling** — How to measure where frame time really goes before optimising anything. Demo: A simulated frame is drawn as a stacked bar against a 16.6 millisecond budget and you toggle or scale systems to find the one that breaks the budget.
- [ ] **Data-oriented design and cache friendliness** — Why laying data out in tightly packed arrays can be many times faster than scattered objects. Demo: A benchmark updates the same particles stored as an array of objects and as typed arrays, shows real timings, and animates which memory cells each approach touches.
- [ ] **Multithreading and job systems: the Job System in Unity, WorkerThreadPool in Godot** — How work is split into jobs across processor cores and why shared data causes race conditions. Demo: Tasks are dealt out to worker lanes with a slider for worker count, and a toggle lets two workers write the same counter to show lost updates.
- [ ] **Editor scripting: @tool scripts in Godot, custom editors in Unity** — How to extend the editor with your own gizmos, inspectors and tools to speed up level building. Demo: A mock editor viewport gives you draggable handles for an enemy patrol path and an inspector panel that updates as you edit.
- [ ] **Hot reload and fast iteration** — How engines swap code and data while the game runs and what state can and cannot survive a reload. Demo: Edit a movement formula in a text box while a simulation runs and toggle between keeping state and restarting on every change.
- [ ] **Debugging tools** — How debug drawing, logging levels and an in-game console make invisible state visible. Demo: A small game has toggles for overlays showing hitboxes, velocity vectors and paths, plus a scrolling log with filters.
- [ ] **Build pipelines: export presets in Godot, build profiles in Unity** — What happens between pressing Build and having a game that runs on a player's device. Demo: Step through a pipeline diagram of import, compile, strip, compress and package while toggling options that change the bars for build size and build time.
- [ ] **Client and server authority** — Who owns the truth in a networked game and why clients cannot be trusted with it. Demo: Two client views and a server view show the same player, with a cheat button that teleports one client and a toggle between client and server authority.
- [ ] **State synchronisation: snapshots and interpolation** — How servers send periodic snapshots and clients interpolate between them to show smooth movement. Demo: Sliders for latency, send rate and packet loss affect a remote player drawn with raw snapshots and with interpolation side by side.
- [ ] **Client-side prediction and rollback** — How a client applies its own inputs immediately, then rewinds and replays when the server disagrees. Demo: Move a character under a latency slider with prediction on or off, and step through a correction to see the rewind and replay of stored inputs.
