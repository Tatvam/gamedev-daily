# Game history and optimizations curriculum

How to use: take the FIRST unchecked item, top to bottom. After publishing its page, change `- [ ]` to `- [x]` and append ` (published <YYYY-MM-DD>, <slug>)` to that line. If you discover something worth covering that is not listed, append it to the Backlog section.

## Track 1: 8-bit and arcade era tricks

- [ ] **Atari 2600 (1977): racing the beam** — With only 128 bytes of memory and no frame buffer, programmers had to set the graphics registers for each scanline just before the television's electron beam drew it. Demo: A scanline stepper draws a frame one line at a time while you change sprite registers between lines and see what happens when the code is too slow.
- [ ] **Space Invaders (1978): the speed-up that came from the hardware** — The invaders move faster as you destroy them because the processor had fewer of them to move and draw each cycle, and designer Tomohiro Nishikado kept the effect as the difficulty curve. Demo: A recreation moves one invader per tick so you can click to remove invaders and watch the remaining ones march faster, with a toggle for a fixed-speed version.
- [ ] **Asteroids (1979): drawing with a vector beam** — Instead of filling a grid of pixels, the vector display steered the beam directly along each line of a shape, which gave sharp lines and a bright glow. Demo: Toggle between a simulated vector beam tracing ship and rock outlines and a low resolution raster version of the same scene, with a slider for beam speed.
- [ ] **Pac-Man (1980): the level 256 kill screen** — The level number is stored in a single byte, so at level 256 the routine that draws the fruit counter overflows and scribbles over the right half of the maze. Demo: Step through the fruit drawing loop with a level slider and watch the counter wrap around and corrupt a tile grid.
- [ ] **Donkey Kong (1981): the kill screen at level 22** — The bonus timer is calculated from the level number in one byte, and at level 22 the result overflows and leaves too little time to finish the stage. Demo: A level slider feeds the timer formula with 8-bit arithmetic shown step by step, and a tiny climbing stage shows whether the time is enough to reach the top.
- [ ] **ZX Spectrum (1982): attribute clash** — The screen stores colour for each 8 by 8 block rather than each pixel, so only two colours can appear in a block and moving sprites stain their surroundings. Demo: Drag a sprite across a coloured background with the block colour rule turned on or off, and with the attribute grid drawn as an overlay.
- [ ] **Nintendo Entertainment System (1983): sprite flicker from the eight-sprite limit** — The hardware can show only eight sprites on one scanline, so games rotate the drawing order each frame to make sprites flicker instead of vanish. Demo: Drag more than eight sprites onto one row and toggle priority rotation to compare permanently missing sprites with flickering ones.
- [ ] **Super Mario Bros. (1985): clouds and bushes share one graphic** — The cloud and the bush are the same tiles drawn with a different palette, which saved space in the cartridge's small graphics memory. Demo: A palette swap toggle recolours one procedurally drawn shape from cloud to bush, with a counter showing the tiles saved.
- [ ] **Pokemon Red and Blue (1996): MissingNo. and the memory layout** — The old man's catching lesson temporarily stores the player's name in the memory used for wild encounter data, and the coast of Cinnabar Island reads that stale data as Pokemon to encounter. Demo: A memory grid visualiser lets you type a name, run the old man's lesson and surf the coast to see which bytes are reinterpreted as species and levels.

## Track 2: 16-bit era graphics tricks

- [ ] **Amiga (1985): copper gradients** — A coprocessor called the copper can change colour registers at chosen scanlines, which let games show smooth sky gradients with far more colours on screen than the palette normally allowed. Demo: Toggle per-scanline palette changes on a scene with a small fixed palette and drag the rows where the sky colour is rewritten.
- [ ] **Out Run (1986): a 3D road from scaled scanlines** — The road is drawn one horizontal line at a time with each line shifted and scaled, and roadside objects are scaled sprites, which creates convincing depth without any polygons. Demo: A pseudo-3D road renderer has sliders for curve, hill and speed and a toggle that colours each scanline segment to show how the illusion is built.
- [ ] **Prince of Persia (1989): rotoscoped animation** — Jordan Mechner filmed his brother running and jumping and traced the frames to get lifelike movement, then reused the same frames for the hero's shadow double to save memory. Demo: Step through a procedurally drawn run cycle built from reference poses, compare it with a two-frame cycle, and toggle an altered copy that reuses the same frames as a second character.
- [ ] **F-Zero (1990): Mode 7 racetracks** — The Super Nintendo can rotate and scale one background layer, and changing the scale on every scanline turns that flat map into a floor with perspective. Demo: A flat procedural track map is drawn with per-scanline scaling that you can toggle, with sliders for camera height, angle and horizon.
- [ ] **Sonic the Hedgehog (1991): parallax from line scrolling** — The Mega Drive (Genesis) can scroll each scanline of a background by a different amount, so one layer can look like many layers of clouds, hills and water moving at different speeds. Demo: A procedural landscape scrolls with a slider for the number of bands, and a toggle switches between whole-layer scrolling and per-line scrolling.
- [ ] **Sonic the Hedgehog (1991): running through loops** — Sonic follows the ground using sensors that measure the slope angle, and he moves along that angle with a single ground speed that must stay high enough to hold onto walls and ceilings. Demo: A character with visible ground sensors runs through a loop while you change the starting speed to see where it falls off.
- [ ] **Another World (1991): polygons for cinematic animation** — Eric Chahi drew characters and scenes as flat polygons played back by a small virtual machine, which made large fluid animation fit in very little space. Demo: A scene is drawn from a short list of polygon commands beside a bitmap version, with a readout comparing their sizes and a slider to step through the draw list.
- [ ] **256-colour pixel art of the early 1990s: palette cycling** — Artists such as Mark Ferrari animated water, snow and light by rotating entries in the colour palette while the pixels themselves never changed. Demo: A procedural waterfall scene animates by cycling palette ranges, with the palette shown as a strip and toggles for each cycling range.
- [ ] **Star Fox (1993): the Super FX chip** — The cartridge carried its own extra processor that drew polygons into a frame buffer, which the console then displayed as an ordinary background layer. Demo: A software rasteriser draws a flat-shaded ship with a polygon budget slider and a frame rate readout, showing the trade between detail and speed.
- [ ] **Donkey Kong Country (1994): pre-rendered sprites** — Rare built its characters as 3D models on Silicon Graphics workstations, then rendered them to small sprites with a reduced palette that the Super Nintendo could display. Demo: A shaded 3D-looking shape is rendered at high quality, then shrunk and reduced to a small palette with toggles for each step of the conversion.

## Track 3: 3D on limited hardware

- [ ] **Wolfenstein 3D (1992): raycasting** — The game casts one ray per screen column across a 2D grid map and draws a wall slice whose height depends on the distance the ray travelled. Demo: A top-down map editor shows the rays leaving the player next to the resulting 3D view, with a slider for the number of columns.
- [ ] **Doom (1993): binary space partitioning** — Each map is split in advance into a tree of convex pieces, so the renderer can visit walls in front-to-back order without sorting them every frame. Demo: Draw a few walls, watch the tree being built split by split, then move the player and step through the traversal order.
- [ ] **Doom (1993): visplanes** — Floors and ceilings are drawn by merging neighbouring screen columns that share the same height, texture and light into regions called visplanes, which had a fixed limit that maps could overflow. Demo: A simple rendered room colours each visplane differently and counts them as you add floor areas with different heights until the limit is reached.
- [ ] **PlayStation (1994): warping textures and wobbling polygons** — The console maps textures without perspective correction and snaps vertices to whole pixels, which makes textures bend and models jitter. Demo: A textured floor quad is drawn with affine or perspective-correct mapping and with or without vertex snapping, plus a slider that subdivides the quad as developers did to hide the warping.
- [ ] **Quake (1996): the potentially visible set** — A long calculation done in advance stores which areas of a map can ever be seen from each other area, so the game skips most of the level at run time. Demo: Move a player through a grid of rooms and doorways and see the rooms in the precomputed visible set light up, with a toggle to draw everything instead.
- [ ] **Quake (1996): lightmaps** — Lighting and shadows are calculated in advance and stored as small low resolution textures that are blended over the wall textures. Demo: Place lights in a 2D room, bake a lightmap at a resolution set by a slider, and toggle it over a procedural brick texture.
- [ ] **Crash Bandicoot (1996): paging levels in and out of memory** — Levels much larger than the console's two megabytes of memory were cut into small pages that were loaded from the disc as the player moved along a mostly fixed path. Demo: Walk along a corridor level while a memory bar shows pages being loaded ahead and dropped behind, with sliders for memory size and disc speed.
- [ ] **Quake III Arena (1999): the fast inverse square root** — The released source code contains a routine that estimates one divided by the square root of a number using a bit-level trick with a magic constant and one step of Newton's method, and it is often wrongly credited to John Carmack. Demo: Plot the estimate against the true value with toggles for zero, one and two refinement steps, and show the bits of the number as the trick is applied. (verify before publishing)
- [ ] **Silent Hill (1999): fog that hides the draw distance** — Thick fog and darkness hide the point where the console stops drawing the town, and turn a technical limit into the game's atmosphere. Demo: Walk down a procedural street with sliders for draw distance and fog density and a toggle that removes the fog to reveal objects popping in.
- [ ] **Shadow of the Colossus (2005): distant detail and faked high dynamic range** — The team drew far terrain with simplified models and used bloom-style post-processing to imitate bright light that the PlayStation 2 could not display directly. Demo: A layered landscape swaps far terrain for simplified versions with a distance slider, and a bloom toggle shows the glow effect on a bright sky. (verify before publishing)

## Track 4: Compression, storage and low-level optimisation

- [ ] **Super Mario Bros. (1985): a whole game in about 40 kilobytes** — Levels are stored as short lists of objects, such as a pipe at one position or a row of bricks at another, rather than as full tile grids. Demo: Build a level from a list of object commands and compare its size in bytes with the same level stored as a full tile grid.
- [ ] **Metroid on the NES: the password is the save file** — The long password packs the player's items, location and progress into bits with a checksum, so the cartridge needs no battery to let players continue. Demo: Toggle items and energy tanks and watch a simplified password scheme update live, then type a password back in to restore the state.
- [ ] **NES cartridges: bank switching with mapper chips** — Extra chips in the cartridge swap different blocks of program and graphics data into the console's small address space, which let later games grow far beyond the original size limit. Demo: A memory map shows a fixed window and a switchable window, and clicking bank numbers swaps which block of a large cartridge is visible.
- [ ] **Myst (1993): designing around CD-ROM seek times** — Early drives were slow to move the read head, so the team kept images small and arranged related files close together on the disc. Demo: A disc visualiser plays a walk through linked scenes with files placed randomly or grouped by location, and totals the time the read head spends travelling.
- [ ] **Resident Evil (1996): door animations as loading screens** — The slow door opening sequence between rooms plays while the next room loads from the disc, and adds tension instead of a progress bar. Demo: Move between rooms with a disc speed slider and switch between a plain loading bar and a door animation that lasts as long as the load.
- [ ] **S3 Texture Compression (1998): sixteen pixels from two colours** — Each 4 by 4 block of a texture is stored as two colours and a 2-bit choice per pixel between those colours and two blends of them, which graphics hardware can decode directly. Demo: A procedural image is compressed block by block with a before and after toggle, and clicking any block shows its two stored colours and index grid.
- [ ] **Pokemon Gold and Silver (1999): compression that made room for a second region** — Satoru Iwata is credited with writing compression tools that freed enough cartridge space to help the team include the Kanto region. Demo: A step-through visualiser compresses a tile map with run-length and back-reference encoding and shows the space freed on a cartridge bar. (verify before publishing)
- [ ] **RollerCoaster Tycoon (1999): written in assembly language** — Chris Sawyer wrote almost all of the game in x86 assembly language, which helped it simulate thousands of park guests on ordinary computers of the time. Demo: A park with a slider for guest count runs with a cheap per-guest update or a deliberately wasteful one, with a frame time graph showing the difference.
- [ ] **Grand Theft Auto III (2001): streaming a city from the disc** — The game loads and unloads models and textures around the player as they move, so the whole city never has to fit in memory at once. Demo: Drive a dot across a city grid while blocks load in a radius around it, with sliders for vehicle speed, disc speed and memory to show where streaming falls behind. (verify before publishing)
- [ ] **Grand Theft Auto Online (2021): the loading time fix found by a player** — A player discovered that loading spent minutes parsing one large text file with a slow scan and a slow duplicate check, and published a fix that Rockstar later confirmed and patched. Demo: Parse a list of items with the slow method and the fixed method while a slider sets the item count and a chart shows time growing quadratically or linearly.

## Track 5: Procedural generation landmarks

- [ ] **Rogue (1980): a new dungeon every game** — Each floor is built by placing rooms in a three by three grid of cells and joining them with corridors, so no two runs are the same. Demo: Press Generate to build a floor step by step with a seed box, showing the grid cells, rooms and corridors being added.
- [ ] **Pitfall! (1982): 255 screens from a polynomial counter** — David Crane generated every screen from one byte stepped through a reversible shift register sequence, so the world needed almost no storage and could be walked in both directions. Demo: Step a shift register left and right and watch its bits decode into the pits, logs and treasures of each screen.
- [ ] **Elite (1984): eight galaxies from a handful of numbers** — Planet names, positions and economies are all generated from a small seed by a fixed number sequence, so thousands of worlds fit on a home computer. Demo: Edit seed numbers to regenerate a galaxy map, and click any star to see its name and statistics derived step by step.
- [ ] **Diablo (1996): random dungeon levels** — Each dungeon floor is assembled by an algorithm that places rooms and corridors on a grid and then dresses them with tile patterns, so every play through has a different layout. Demo: A generator grows rooms outward from a starting room on a grid with a seed box and a step button that shows each placement.
- [ ] **.kkrieger (2004): a first-person shooter in 96 kilobytes** — Textures, models and sounds are stored as recipes of generation steps and built when the game loads, rather than stored as finished data. Demo: Build a texture from a stack of operations such as noise, blur and colourise, and compare the size of the recipe with the size of the finished image.
- [ ] **Dwarf Fortress (2006): worlds with generated history** — The game builds terrain from elevation, rainfall and temperature maps, then simulates years of events to give the world civilisations and legends. Demo: Generate fractal elevation and rainfall maps with sliders, combine them into biomes, and press a button to advance years as settlements spread.
- [ ] **Spelunky (2008): random levels that can always be finished** — Each level is a four by four grid of room templates, and a guaranteed path from entrance to exit is chosen first before the remaining rooms are filled in. Demo: Generate a level and toggle an overlay that shows the solution path and the type of each room.
- [ ] **Borderlands (2009): millions of guns from parts** — Each weapon is assembled from interchangeable parts such as barrels, stocks and sights, and each part changes both its look and its statistics. Demo: Press Roll to assemble a procedurally drawn gun from parts, with its statistics shown as bars and a lock on each part to re-roll the others.
- [ ] **Minecraft (2011): endless terrain from noise and a seed** — Layers of smooth noise shape the land, and the world is generated in chunks only where players go, always the same for the same seed. Demo: A side-view terrain is built from noise with sliders for octaves and scale, a seed box, and chunks that generate as you scroll.
- [ ] **No Man's Sky (2016): a universe that is never stored** — Every planet is calculated from its coordinates and a seed using deterministic functions, so visiting the same place always rebuilds the same world. Demo: Pan across a star map where each planet's colour, size and terrain come from a hash of its coordinates, and return to any spot to confirm it is unchanged.

## Track 6: AI, netcode and design tricks hidden in code

- [ ] **Pac-Man (1980): four ghosts, four targeting rules** — Each ghost picks a different target tile based on Pac-Man's position and direction, and this gives them distinct personalities from very simple rules. Demo: Move Pac-Man around a maze and see each ghost's target tile and chosen path drawn, with toggles for chase and scatter modes.
- [ ] **Street Fighter II (1991): combos that began as a bug** — The team found that some moves could be cancelled into others before the first had finished, and left the behaviour in as a hidden technique. Demo: Hit a dummy with a timeline of start-up, active and recovery frames displayed, and toggle the cancel window to see two hits connect or fail.
- [ ] **Mario Kart series: rubber banding and items by race position** — Computer drivers speed up or slow down to stay near the player and trailing racers are given stronger items, which keeps races close. Demo: A simple race has sliders for rubber band strength and item bias, with a graph of the gap between first and last place over time. (verify before publishing)
- [ ] **Age of Empires (1997): 1500 archers on a 28.8 modem** — Instead of sending the position of every unit, each computer runs the same deterministic simulation and only the players' commands are sent. Demo: Two side-by-side simulations receive the same commands with a latency slider, and a toggle adds a tiny difference to one machine to show a desync grow.
- [ ] **Metal Gear Solid (1998): Psycho Mantis reads the memory card** — The boss comments on save files from other Konami games found on the memory card, and is far easier to beat after moving the controller to the second port. Demo: Tick which pretend save files are on a memory card and which port the controller uses, then start the fight to see the boss react to your choices.
- [ ] **Halo: Combat Evolved (2001): thirty seconds of fun** — Designer Jaime Griesemer described building the game around a short loop of combat that stays fun when repeated in varied settings, a quote that is usually shortened. Demo: A small arena plays a repeating encounter where toggles vary the enemy mix, cover and weapon to show how the same loop changes. (verify before publishing)
- [ ] **Resident Evil 4 (2005): the hidden difficulty scale** — The game quietly raises and lowers an internal difficulty rank based on how well the player is doing, which changes how aggressive and dangerous enemies are. Demo: A small shooting gallery adjusts a rank value as you hit or get hit, with a toggle to reveal the rank and a switch to lock it.
- [ ] **GGPO (2006): rollback netcode** — Tony Cannon's library runs the local player's input at once, guesses the remote player's input, and rewinds and replays the game when a guess turns out wrong. Demo: Two characters are controlled across a simulated connection with a latency slider and a switch between input delay and rollback, with rollbacks flashed on a frame timeline.
- [ ] **Left 4 Dead (2008): the AI Director** — A director system tracks how stressed each player is and spaces out hordes and quiet periods to build tension and then release it. Demo: A survivor walks through a level while an intensity graph rises and falls, with a toggle between director pacing and constant spawning.
- [ ] **Fallout 3: Broken Steel (2009): the train that is a piece of armour** — Because the engine had no vehicle system, the moving train was made as an item worn by a character who runs along the track. Demo: A train glides along a track with a reveal toggle that shows the running character underneath carrying it. (verify before publishing)
- [ ] **Celeste (2018): forgiveness mechanics** — The developers documented hidden assists such as coyote time, jump buffering and corner correction that make hard jumps feel fair. Demo: A short platforming room has toggles for each assist and a counter of successful jumps.
