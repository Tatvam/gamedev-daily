Squash and stretch: weight without new art

How squashing and stretching a character while keeping its area the same adds weight and energy to jumps and landings, with no new art.

Your character jumps, rises, falls and lands, and through all of it the sprite stays the exact same rectangle. The motion is correct, but it looks like a cardboard cutout sliding on a wire. Two numbers per frame, a width scale and a height scale, can make it look like it has mass and muscle.

Deform the shape, keep the amount

Squash and stretch means deforming a shape while it moves: it gets shorter and wider when it hits something, and taller and thinner when it moves fast. It is the first of the twelve principles of animation set out by Disney animators Frank Thomas and Ollie Johnston, and the classic exercise is a bouncing ball.

A squash on landing says "this hit the ground hard". A stretch while moving says "this is fast". Without them the eye must judge speed and impact from position alone, and a rigid shape tends to read as light or stiff.

The volume rule

The shape should look like it holds the same amount of stuff. In 2D, keep the area the same: if the height scale is sy, the width scale is sx = 1 / sy. Break this rule and the character seems to shrink or grow instead of bend.

Three moments drive it

Track a single number, the deform d, and set the height scale to 1 + d. Positive is stretch, negative is squash.

  1. Take-off. On the frame the jump starts, set d to +0.35: an instant stretch.
  2. In the air. Pull d toward a stretch that grows with vertical speed, up to +0.25. At the top of the arc the speed is zero, so the shape is briefly round.
  3. Landing. On the frame of contact, set d to a squash scaled by impact strength, up to −0.35. Strength is the same 0 to 1 value as in the particles lesson: landing speed minus 200, divided by 700, clamped.

Between events a spring pulls d back to its target: each frame it accelerates toward the target and loses some speed to damping. A soft spring overshoots once, so after a squash the character gets briefly taller before settling. That wobble makes it look elastic rather than resized.

Scale from the feet

The pivot is the point a scale is applied around, often the centre by default. Squash around the centre and the bottom edge lifts off the floor; stretch and it sinks in. Put the pivot at the feet.

Starting points to tune

Take-off stretch +0.35, air stretch up to +0.25, landing squash up to −0.35, spring stiffness 300 and damping 14 (settles in about a third of a second). Clamp the height scale between 0.4 and 1.8. These are starting points, not rules: a heavy knight wants half these values, a bouncy slime double.

The code

The demo's right blob in LÖVE, with the same names and numbers. Only the drawing uses the deform; the position and the collision box are untouched.

local G, HOP, BIG = 1800, 500, 850
local FLOOR, W, H = 380, 44, 44
local AMOUNT = 1.0                   -- the Amount slider, 0 to 2
local STIFFNESS, DAMPING = 300, 14   -- the spring that pulls the shape back
local keepArea = true

local blob = { x = 300, y = FLOOR, vy = 0, grounded = true, d = 0, dv = 0 }

local function jump(speed)
  if not blob.grounded then return end
  blob.vy = -speed
  blob.grounded = false
  blob.d, blob.dv = 0.35 * AMOUNT, 0              -- stretch on take-off
end

local function land(impactSpeed)
  local strength = math.max(0, math.min(1, (impactSpeed - 200) / 700))
  blob.d, blob.dv = -0.35 * AMOUNT * strength, 0   -- squash on landing
end

function love.keypressed(key)
  if key == "space" or key == "j" then jump(HOP) end
  if key == "k" then jump(BIG) end
end

function love.update(dt)
  if not blob.grounded then
    blob.vy = blob.vy + G * dt
    blob.y = blob.y + blob.vy * dt
    if blob.y >= FLOOR then
      blob.y = FLOOR
      blob.grounded = true
      land(blob.vy)                  -- before the speed is zeroed
      blob.vy = 0
    end
  end
  -- in the air, stretch with speed; on the ground, rest at 0
  local target = 0
  if not blob.grounded then
    target = 0.25 * AMOUNT * math.min(math.abs(blob.vy) / BIG, 1)
  end
  blob.dv = blob.dv + ((target - blob.d) * STIFFNESS - blob.dv * DAMPING) * dt
  blob.d = blob.d + blob.dv * dt
end

function love.draw()
  local sy = math.max(0.4, math.min(1.8, 1 + blob.d))
  local sx = 1
  if keepArea then sx = 1 / sy end           -- same area, so it bends, not shrinks
  local w, h = W * sx, H * sy
  -- pivot at the feet: the bottom edge stays on the floor
  love.graphics.rectangle("fill", blob.x - w / 2, blob.y - h, w, h, 10, 10)
end

With a sprite instead of a rectangle, pass sx and sy as the scale arguments of love.graphics.draw, and set the origin to the bottom centre of the image so the pivot is at the feet.

Pitfalls

  • Scaling the hitbox. Deform only what is drawn. If the collision box squashes too, landings change the character's size for a few frames and they can clip into ceilings or fall through gaps.
  • Pivot at the centre. The character floats above the ground when squashed and sinks into it when stretched. Scale from the feet for ground contact. For a wall hit, a pivot at the side that touches the wall works the same way.
  • Forgetting the facing flip. Many games mirror a sprite by making its x scale negative. Multiply the squash width by the facing sign after computing it, or one of the two will overwrite the other.
  • Anticipation that delays the jump. Animators often squash before a jump to wind up. In a game, a crouch before take-off is added input latency. Stretch on the press frame instead, unless your game is deliberately weighty.
  • Too much, too often. If every step wobbles, nothing stands out. Save big values for big events.
  • A spring that explodes. A stiff spring updated with a very long frame can overshoot further each step. Clamp dt, or update the spring in small fixed steps.

When not to use it

Rigid things such as crates and robots look wrong when they bend; give them shake or dust instead. Realistic art styles tend to clash with cartoon deformation. In low-resolution pixel art, scaling by non-whole numbers smears pixels; some games accept that, others draw a few hand-made squash frames instead. And in games where the player reads exact positions and sizes, such as precise fighting games, keep the deformation small so the drawing still matches the hitbox.

In real games

Squash and stretch on jumping and landing is common in 2D platformers. One case that can be checked is Celeste (2018), whose developers published the source code of its player character. In that code the sprite scale is set to 0.6 wide by 1.4 tall when a jump starts. On landing it is squashed toward 1.6 wide by 0.4 tall, in proportion to how fast the player was falling, and each frame both scales move back toward 1 at a steady rate.

Those numbers do not keep the area exactly: 0.6 × 1.4 is 0.84. The volume rule is a guide for the eye, and a squash lasting a few frames need not be exact.

Your turn (15 minutes)

Add the deform d, the spring and the three events to your player's drawing code. Draw with the pivot at the feet. Then make one of these choices and tune it: a heavy character (halve every value, raise the damping to about 20 so it does not wobble) or a light one (raise the amount, lower the damping to about 8).

You are done when a friend who watches only the character, with the sound off, can tell a hop from a long fall, and when switching the deform off makes the character feel noticeably stiffer to you.

Takeaways

  • Squash on impact, stretch while moving fast, round at rest and at the top of a jump.
  • Keep the area roughly the same: width scale is one over height scale.
  • Drive it with one value and a soft spring, so it overshoots once and settles.
  • Scale from the feet, and only scale the drawing, never the hitbox.
  • Use less for heavy or rigid things, and none where precise reading of shapes matters.
