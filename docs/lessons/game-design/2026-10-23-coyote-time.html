Coyote time: jumping after the edge

Why letting players jump for a moment after running off a ledge makes platforming feel fair, how long the window should be, and how to code it.

You run toward a gap, press jump right at the edge, and fall in anyway. You are sure you pressed in time. By the game's rules you did not: your feet left the ground two frames before the press arrived. The game is technically correct and the player feels cheated.

The player and the game disagree about where the edge is

Most platformers allow a jump only while the character is grounded: standing on something solid in the current frame. That rule is exact, and that is the problem. The player is judging the edge with their eyes, through a screen that shows the past, with a thumb that takes time to move. When they aim for the last possible moment, a good share of their presses land a few frames after the feet have left.

To the player those presses were on time. Punishing them feels like the game ignored the button, which is worse than a fair miss.

The fix: a short grace window

Coyote time is a short window after the character walks off a ledge during which a jump still counts as a jump from the ground. The name is usually traced to cartoon coyotes who run off cliffs and hang in the air until they notice.

How it works in code

Keep one number, the coyote timer. While the character is grounded, fill it to the full window every frame. In the air, count it down. A jump is allowed when the character is grounded or the timer is above zero. The moment a jump starts, set the timer to zero, so the window cannot be used for a second jump in mid-air.

Counting in seconds rather than frames keeps the window the same length at any frame rate. If your game runs on a fixed step, counting steps is fine too.

Starting points to tune

A window of about 100 ms (6 frames at 60 frames per second) is a common place to start. Below about 50 ms many late presses still fail; above about 150 ms some players start to notice jumps that begin in thin air, especially with a close camera or a slow character. Try your own game at several values; these are starting points, not rules.

What the player feels

Without coyote time, a late press at the edge is a coin flip, and players learn to jump early "to be safe", which makes long gaps feel stingy. With it, pressing at the edge simply works and attention moves from the button to the level. Done well, nobody notices it; players tend to notice only when it is missing.

Try it

The runner never stops. Jump each gap as late as you dare, first with coyote time off, then on. Every press leaves a ghost outline where you pressed it: green on the ground, blue inside the window, red too late. The strip at the top times each press against the window, in frames.

Then drag the window to 200 ms and watch how far past the edge a jump can now start. That is the point where it starts to look like flying.

The code

This is the demo's runner in LÖVE, with the same numbers. Height y is measured upward from the tops of the platforms, which all sit at the same height. The two marked lines are the whole technique; everything else is an ordinary jump.

local RUN_SPEED = 260       -- pixels per second, the runner never stops
local GRAVITY = 2200        -- pixels per second squared
local JUMP_SPEED = 700      -- pixels per second at take-off
local COYOTE_TIME = 0.100   -- seconds; the demo's slider (0 turns it off)
local SIZE = 22             -- the player is a 22 pixel square

local platforms = { { left = -300, right = 300 }, { left = 410, right = 600 } }
local player = { x = 0, y = 0, vy = 0, grounded = true }
local coyoteTimer = 0       -- time left to jump after walking off

local function overGround(x)
  for _, p in ipairs(platforms) do
    if x + SIZE > p.left and x < p.right then return p end
  end
  return nil
end

function love.keypressed(key)
  if key ~= "space" and key ~= "w" and key ~= "up" then return end
  if player.grounded or coyoteTimer > 0 then
    player.vy = JUMP_SPEED
    player.grounded = false
    coyoteTimer = 0           -- spent: no second jump from this edge
  end
end

function love.update(dt)
  if player.grounded then
    coyoteTimer = COYOTE_TIME -- refilled every frame on the ground
  else
    coyoteTimer = math.max(0, coyoteTimer - dt)
  end

  player.x = player.x + RUN_SPEED * dt
  if player.grounded and not overGround(player.x) then
    player.grounded = false   -- walked off: the timer starts running down
    player.vy = 0
  end
  if not player.grounded then
    local oldY = player.y
    player.vy = player.vy - GRAVITY * dt
    player.y = player.y + player.vy * dt
    if oldY >= 0 and player.y <= 0 and overGround(player.x) then
      player.y, player.vy, player.grounded = 0, 0, true
    end
  end
  -- walls, falling into the pit and respawning are left out here
end

The check is grounded or coyoteTimer > 0 rather than the timer alone. With the window set to zero, the timer alone would never let the player jump at all.

Pitfalls

  • Forgetting to spend the timer. If a jump does not set the timer to zero, a second press in the first 100 ms of a jump gives a free double jump. This is the most common coyote time bug.
  • Counting frames at a variable frame rate. Six frames is 100 ms at 60 frames per second and 200 ms at 30. Count seconds, or count fixed simulation steps.
  • Giving the window after every kind of leaving. Walking off an edge should start it. Jumping should not. Being knocked off by an enemy, or a platform crumbling away, is a design choice: decide on purpose rather than by accident.
  • Mixing it with an air jump. In a game with a double jump, a late press inside the window should use the ground jump and keep the double jump for later. If it spends the air jump instead, players lose a resource they never meant to use.
  • A window so long it shows. Coyote time works because it is invisible. If a jump visibly starts well below the ledge, players may read it as a bug or an exploit. Gravity still pulls during the window in this demo; some games pause the fall for the length of the window instead, which hides the dip.
  • Designing gaps that need it. Test your widest gap with the window off too, so it stays possible for a player who jumps at the real edge.

When not to use it. Coyote time suits games where reaching the edge is the hard part. It matters less when movement is slow and deliberate, or on a grid. In a competitive game where every player gets the same rule it is still fair, but a long window can be abused to gain distance. Keep it short there.

In real games

Celeste uses coyote time. In a 2020 thread about the game's forgiveness mechanics, its director Maddy Thorson listed it among several hidden helpers, alongside jump buffering and corner correction, and noted that the team did not invent these techniques.

It is now a common part of platformer character controllers, often next to jump buffering. Because a good window is invisible, you usually cannot tell from playing whether a game has one, or how long it is.

Your turn (15 minutes)

In your own platformer, add a coyote timer as above with a window of 0.1 seconds. Then make the window a value you can change while playing, for example with two keys that add or remove 0.02 seconds.

Run off the same ledge ten times at 0, 0.1 and 0.2 seconds, pressing jump as late as you can. Note how many jumps work at each value and at which value the jump starts to look like it leaves from thin air. You are done when you have picked a value between those two points and written down why.

Takeaways

  • Players judge the edge by eye and press a little late. A strict grounded check punishes presses that felt on time.
  • Coyote time lets a jump count as a ground jump for a short window after walking off a ledge.
  • Fill a timer while grounded, count it down in the air, allow a jump when grounded or the timer is above zero, and set it to zero when a jump starts.
  • About 100 ms is a common starting point. Tune it by watching late presses succeed without jumps visibly starting in mid-air.
