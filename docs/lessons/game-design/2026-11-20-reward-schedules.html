Reward schedules: fixed, variable, by count and by time

How paying rewards by count or by time, on a fixed or a random schedule, shapes when players keep going and when they stop.

Two games give out exactly the same number of potions per hour. In the first, every tenth enemy drops one, and players happily put the controller down after each drop. In the second, any enemy might drop one, and players keep saying "just one more" long past bedtime. The amount of reward is the same. The rule that decides when it arrives is different.

Two questions decide the schedule

A reward schedule is the rule that decides which of the player's actions earn a reward. Psychologists studied these rules for decades, most famously Charles Ferster and B. F. Skinner, who measured how pigeons and rats pressed keys and levers under each one. Every schedule answers two questions.

Count or time? A ratio schedule pays after a number of actions: kill enough enemies, get the drop. An interval schedule pays for the first action after some time has passed: the crop is ready after four hours, and acting earlier does nothing.

Fixed or variable? A fixed schedule always uses the same number. A variable schedule picks a new number each time, around an average the player cannot see.

What the schedule tends to do to behaviour

The diagram shows the usual laboratory shapes. Each line is a cumulative record: the total number of presses climbing over time. A steep line means fast pressing, a flat stretch means a pause, and each small tick marks a reward.

Fixed ratio: pause, then burst. Right after a reward, nothing is close, so there is a natural rest point. Once the player starts again, they push steadily to the next one. Bigger ratios tend to make longer pauses. In games this is the "I'll stop after this level" schedule, and that is a feature: players can see the goal and choose to leave.

Variable ratio: fast and steady. Any action might pay, so there is never a moment when stopping is obviously sensible. Responding tends to be high with few pauses, and it keeps going for a long time after rewards stop. This is what makes loot drops exciting. It is also the schedule of a slot machine.

Fixed interval: slow, then speeds up. Acting early is pointless, so players ignore the thing until it is nearly due, then check more and more often. In games this becomes an appointment: come back at the right time.

Variable interval: slow and steady. The reward could be ready at any moment, but acting faster does not make it come sooner. Players tend to check at a modest, even pace, the way you glance at a fishing float.

Starting points to tune

For small, frequent rewards, a fixed ratio of 3 to 10 actions is a common place to start. For random drops, choose the average first, then decide the worst run of bad luck you will accept, perhaps 2 to 3 times the average, and plan to cap it. For timers, match the interval to how often your players really play: minutes inside a session, never shorter than the gap between sessions you expect. These are starting points, not rules.

When not to use each one

Do not put a variable ratio on something the player needs to progress, such as a key that drops from a random enemy. Bad luck then blocks the game, not just the bonus. Do not put fixed intervals on a game people play in long sittings: the timer interrupts play and asks them to wait. Some games need no schedule at all: in a puzzle game, solving the puzzle is the reward.

These schedules can be used against the player

A variable ratio paid for with real money is gambling in all but name: the player pays for a chance, and the schedule removes the natural stopping point. Fixed intervals become a leash when missing a day resets a streak or loses a reward, because the player returns out of fear of losing something, not because they want to play. Both work, and that is the problem. Show the odds, cap bad luck, keep timers forgiving, and never sell a random reward for real money.

The code

The same four chests in LÖVE, with the same names and numbers as the demo. Keys 1 to 4 press the chests. The only difference is that this clock starts when the game starts, while the demo's clock starts at your first press.

local RATIO = 5      -- ratio chests: presses per coin (the average, for variable)
local INTERVAL = 5   -- interval chests: seconds per coin (the average, for variable)
local clock = 0
local chests = {}

-- Set up the next coin for a chest, at time now
local function rearm(c, now)
  if c.kind == "FR" then
    c.need = RATIO
  elseif c.kind == "VR" then
    c.need = math.random(1, 2 * RATIO - 1)                       -- averages RATIO
  elseif c.kind == "FI" then
    c.readyAt = now + INTERVAL
  else -- "VI"
    c.readyAt = now + INTERVAL * (0.1 + 1.8 * math.random())    -- averages INTERVAL
  end
end

local function press(c, now)
  c.presses = c.presses + 1
  c.count = c.count + 1                     -- presses since the last coin
  c.longest = math.max(c.longest, c.count)
  local paid
  if c.kind == "FR" or c.kind == "VR" then
    paid = c.count >= c.need                -- ratio: counts presses
  else
    paid = now >= c.readyAt                 -- interval: watches the clock
  end
  if paid then
    c.coins = c.coins + 1
    c.count = 0
    rearm(c, now)
  end
  return paid
end

function love.load()
  for i, kind in ipairs({ "FR", "VR", "FI", "VI" }) do
    chests[i] = { kind = kind, presses = 0, count = 0, coins = 0, longest = 0 }
    rearm(chests[i], 0)
  end
end

function love.update(dt)
  clock = clock + dt
end

function love.keypressed(key)
  local i = tonumber(key)                   -- "1" to "4"; nil for other keys
  if i and chests[i] then press(chests[i], clock) end
end

function love.draw()
  for i, c in ipairs(chests) do
    love.graphics.print(c.kind .. "  coins " .. c.coins .. "  presses " .. c.presses
      .. "  longest wait " .. c.longest, 20, 24 * i)
  end
end

An interval chest pays the first press after its timer runs out, and the next timer starts from that press, so a player who comes back late gets one coin, not several.

Pitfalls

  • Pure randomness with no cap. With a 1 in 20 drop chance, about one player in thirteen goes 50 kills without a drop. Cap the bad luck; later lessons on pity timers and shuffle bags show how.
  • Fixed ratios that are too long. The pause after a reward tends to grow with the size of the ratio. A goal of 200 kills reads as a wall, not a target. Break long goals into short steps.
  • Timers that punish absence. Rewards that expire or streaks that reset turn a pleasant appointment into an obligation. Let unclaimed rewards wait, or let a streak survive a missed day.

In real games

Random item drops from enemies in action role-playing games are variable ratio schedules: each kill is one more roll. Quests that ask for a set number of items are fixed ratios. Farming and life-simulation games that grow crops on a timer, and mobile games with daily login rewards, use fixed intervals.

Regulators have taken notice of variable ratios sold for money. In April 2018 the Belgian Gaming Commission concluded that the paid loot boxes in Overwatch, FIFA 18 and Counter-Strike: Global Offensive broke Belgian gambling law, and Blizzard and Valve removed paid loot boxes from their games in Belgium in response.

Takeaways

  • A schedule is count or time, and fixed or variable. That gives four schedules.
  • Fixed ratios give clear goals and natural rest points. Variable ratios remove the stopping point, which makes drops exciting and makes them easy to abuse.
  • Interval schedules reward checking back, not effort. Fixed ones make appointments; variable ones make steady glancing.
  • Cap random bad luck and keep timers forgiving. Never sell a variable ratio for real money.
  • The laboratory curves are a first guess. Playtest to see what your players actually do.
