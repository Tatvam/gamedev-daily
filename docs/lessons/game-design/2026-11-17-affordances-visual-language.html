Affordances and visual language: teaching players what hurts

How consistent shapes and colours let players predict what hurts, breaks or can be climbed, and how one broken rule teaches them to distrust everything.

A tester walks carefully around a red crate, then steps on a pretty blue flower and dies. "That's cheap," they say. The flower was always deadly in your head, but nothing on screen said so, and the red crate said "danger" when it meant nothing at all.

Your game failed to tell them its rules. This lesson builds a small, consistent visual language so players can read the world before they touch it.

Players read objects before they touch them

An affordance is what an object lets you do: a chair affords sitting, a ledge affords grabbing. The psychologist James J. Gibson coined the word, and Don Norman brought it into design in The Design of Everyday Things. In the 2013 edition Norman added a second word, signifier: the visible sign that tells you an action is possible, like the flat plate on a door that says "push".

In a game the difference matters more than in real life. Almost every affordance in a game is invented. A wall is climbable because you wrote code that says so, not because it has handholds. So the player has only the signifiers to go on. If those signs are vague or contradict each other, the only way to learn the rules is to get hurt.

A visual language is a set of promises

A visual language is the set of consistent signs a game uses for its rules: this shape always hurts, this colour can always be climbed, this texture always breaks. It works like any language. After a few examples the player stops learning objects one at a time and starts predicting new ones. A spiky red plant they have never seen before is obviously dangerous, because every spiky red thing so far has been.

Three habits tend to make a visual language strong:

  • Borrow from the real world. Spikes, thorns and blades look sharp. Cracks look weak. A lip on the edge of a wall looks grabbable. When you build on what people already believe, the first lesson is free.
  • Same meaning, same look. Different meaning, different look. If red means danger, red decoration is a lie. If two kinds of hazard look alike, the player cannot learn the difference between them.
  • Say it twice. Put the meaning in shape and colour. Roughly 1 in 12 men and 1 in 200 women have some form of colour vision deficiency, and red against green is the most common pair that gets confused. Shape also survives fog, dark rooms and busy scenes.

One broken rule costs more than one hit

The worst thing for a visual language is an exception: a harmless-looking flower that kills. The player loses some health, but they also learn that the signs cannot be trusted. From then on they tend to poke at everything, or avoid everything, and your carefully drawn signs stop working everywhere, not just on that flower.

Games can still surprise players. A late twist works when the new rule gets its own look and being fooled once is cheap.

Numbers to start from

These are starting points to tune, not rules:

  • Danger colours: reserve one colour (or one colour family) for things that hurt, and use it for nothing else. Two is fine if the second also has its own shape.
  • Channels: at least two for anything that can kill or end a run: shape plus colour, or colour plus motion.
  • Exceptions: zero for danger. Players forgive a decoration that looked collectable much more readily than a decoration that killed them.
  • The greyscale test: take a screenshot and remove the colour. If you can still point at every hazard, your shapes carry the meaning on their own.

Rule of thumb

Write your visual language down as a short table before you make the art. If a new object does not fit a row, either give it a new row with its own look, or change the object.

When not to spell it out

Clear signs have a cost. Painted ledges can look like a tutorial pasted over the world, and some players find that breaks the mood of a realistic game. Horror games sometimes keep danger ambiguous on purpose, because uncertainty is the feeling they sell. Exploration games may want the player to experiment. In those cases the language can be quieter: worn handholds instead of paint, light instead of colour. Quiet still has to be consistent, though. Ambiguous is a choice; inconsistent is a bug.

The code

This is the room the demo builds, with the same numbers. The important function is dress: every object asks it how to look, so the visual language lives in one place. The highlighted lines are the whole rule. Drawing is left to your own drawShape, since stars and rounded squares are drawn differently in every engine.

local ROOM_SIZE = 12   -- objects per room
local HARMFUL = 4      -- how many of them hurt
local rules = { consistent = true, shapeSignals = true, breakers = 0 }

local ALL_COLOURS, SAFE_COLOURS = { "red", "green", "blue" }, { "green", "blue" }
local ALL_SHAPES, SAFE_SHAPES = { "spike", "round", "square" }, { "round", "square" }

local function pick(list) return list[love.math.random(#list)] end

local function dress(obj)          -- the visual language, in one place
  if not rules.consistent then     -- looks say nothing about harm
    obj.colour, obj.shape = pick(ALL_COLOURS), pick(ALL_SHAPES)
    return
  end
  local looksHarmful = obj.harmful and not obj.breaker
  obj.colour = looksHarmful and "red" or pick(SAFE_COLOURS)
  if not rules.shapeSignals then obj.shape = pick(ALL_SHAPES)
  elseif looksHarmful then obj.shape = "spike"
  else obj.shape = pick(SAFE_SHAPES) end
end

local room, hurtsTouched, safeLeft

local function newRoom()
  room, hurtsTouched, safeLeft = {}, 0, ROOM_SIZE - HARMFUL
  for i = 1, ROOM_SIZE do
    local obj = { harmful = i <= HARMFUL, touched = false }
    obj.breaker = obj.harmful and i <= rules.breakers  -- harmful but dressed as safe
    dress(obj)
    table.insert(room, love.math.random(#room + 1), obj)   -- random position
  end
end

local function touch(obj)
  if obj.touched then return end
  obj.touched = true
  if obj.harmful then hurtsTouched = hurtsTouched + 1
  else safeLeft = safeLeft - 1 end
end

In a real project dress grows cases for "climb" and "breaks". Designers place objects by meaning and the look follows, so nobody paints a deadly flower blue by accident.

Pitfalls

  • Decoration that speaks the language. Red banners and spiky ornaments say "danger" whether you mean it or not. Check decoration against the table too.
  • Colour as the only channel. A red and green language fails many colour-blind players. Run the greyscale test.
  • Too many meanings. Players hold a handful of rules comfortably. If you need twenty colours for your hazards, you probably have too many hazard types.
  • Teaching with a punishment. If the first spike kills instantly, players learn the rule but resent it. Introduce a sign somewhere cheap first.

In real games

Mirror's Edge (2008) uses a feature called Runner Vision that tints objects useful for movement red, such as pipes and ladders. The manual for its sequel, Mirror's Edge Catalyst (2016), describes full, classic and off settings for it: a visual language with a strength setting.

The 2023 remake of Resident Evil 4 marks ladders, breakable crates and other interactive objects with yellow paint. When the demo came out it started a long online argument among players and developers about whether such marks are helpful or immersion-breaking, and the same argument came back with later games.

Many shooters use red barrels for explosives and many platformers use spikes for hazards. The more games share a sign, the less yours has to teach it.

Your turn (15 minutes)

Take three screenshots from your game. For each one, list every object that hurts, every object you can interact with, and every object that is only decoration. Then write your visual language as a table with one row per meaning and two columns: shape and colour.

Now convert the screenshots to greyscale. Mark every object whose meaning you can no longer tell, and every decoration that uses a sign from your table. You are done when you have a list of objects to change, and each one has a row in the table it should match.

Takeaways

  • Game affordances are invented, so players can only learn them through signs. Signs that are inconsistent teach by damage.
  • A visual language maps each meaning to one look, and each look to one meaning. Decoration must follow it too.
  • Carry anything dangerous on two channels, such as shape and colour, so it survives colour blindness and poor visibility.
  • One exception costs trust across the whole game, not just one hit point.
