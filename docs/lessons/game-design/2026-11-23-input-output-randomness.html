Input and output randomness: roll before or after the choice?

Why dice rolled before a decision give the player a problem to plan around, while dice rolled after it decide whether the plan worked.

The game says your shot has a 95 percent chance to hit. You take it, it misses, and the mission falls apart. You made the right call and the game punished you anyway. Move that same roll to before the decision and it becomes something to plan around instead of a verdict.

When the dice roll matters as much as how

Every random event in a game happens at some point relative to the player's decision.

  • Input randomness happens before the decision. You draw a hand of cards, roll your dice, or see which pieces the shop offers, and then you decide what to do with them. Luck sets up the problem and you solve it.
  • Output randomness happens after the decision. You choose to attack, and then a roll decides whether it hits. You choose the odds and luck decides the result.

The terms are commonly credited to board game designer Geoff Engelstein, and they are now widely used by video game designers too.

What each one feels like

With input randomness, a bad roll is a hard puzzle, not a loss. The player asks "what is the best I can do with this?" Players tend to blame themselves for a loss, which keeps them trying.

With output randomness, the player picks the option with the best odds and then waits. The wait creates tension, which is the whole appeal of a critical hit or a last-second shot. But when the roll goes wrong, a correct plan still fails, and players tend to blame the game.

The numbers

Take the fight in the demo below. Each turn the ogre shows how hard it will hit. You have two dice, and each one either attacks (its number is damage) or guards (its number blocks damage). You have 18 health, the ogre has 30, and you must win within 10 turns. The demo works out the best possible strategy for each version exactly, so these are the win rates of a perfect player, next to a player who picks at random:

Every die averages 3.5 in every row, and the random player does equally badly in both versions. What changes is how much a good player can do with the luck. With dice 1 to 6, moving the roll before the choice cuts a perfect player's losses from 21 percent to 11 percent. The more swing the dice have, the bigger that gap.

Rule of thumb

If you want skill to decide the outcome, roll before the choice. If you want suspense and upsets, roll after it, keep the swing small, and show the odds honestly. These are tendencies to test, not laws.

When not to use input randomness

Input randomness is not always better. Showing everything up front can make each turn a slow puzzle; some players freeze while they work out every option. It also removes surprise. In a party game or a game for mixed ages, output randomness lets the weaker player win sometimes, which can be exactly what the table wants. Most games mix both: they deal a random hand, then roll a small random amount after the choice.

Output randomness can be gambling

A paid roll whose result you only learn afterward, such as a loot box, is output randomness pointed at the player's wallet. The suspense that makes a critical hit exciting is the same feeling that keeps people buying. If a roll costs real money, it is gambling in all but name, and some countries regulate it.

The code

The fight from the demo in LÖVE. The only difference between the two versions is where roll() is called: at the start of the turn, or inside choose. Keys 1 to 4 pick a plan.

local FACES = { 1, 2, 3, 4, 5, 6 }  -- try { 0, 1, 2, 5, 6, 7 } for more swing
local HERO_HP, OGRE_HP, TURNS = 18, 30, 10
local MODE = "input"  -- "input": roll, then choose. "output": choose, then roll
-- true = that die attacks, false = it guards
local PLANS = { { true, true }, { true, false }, { false, true }, { false, false } }

local hero, ogre, turn = HERO_HP, OGRE_HP, 1
local intent, dice, message = 0, nil, ""

local function roll()
  return FACES[love.math.random(#FACES)]
end

local function startTurn()
  intent = love.math.random(2, 8)          -- the ogre shows its next hit
  if MODE == "input" then dice = { roll(), roll() } else dice = nil end
end

local function choose(plan)
  if MODE == "output" then dice = { roll(), roll() } end
  local attack, guard = 0, 0
  for i = 1, 2 do
    if plan[i] then attack = attack + dice[i] else guard = guard + dice[i] end
  end
  ogre = ogre - attack
  if ogre > 0 then hero = hero - math.max(0, intent - guard) end
  message = "Rolled " .. dice[1] .. " and " .. dice[2]
  turn = turn + 1
  if ogre <= 0 then message = message .. ". You win."
  elseif hero <= 0 or turn > TURNS then message = message .. ". You lose." end
  startTurn()
end

function love.load() startTurn() end

function love.keypressed(key)
  local over = hero <= 0 or ogre <= 0 or turn > TURNS
  local plan = PLANS[tonumber(key) or 0]
  if plan and not over then choose(plan) end
end

function love.draw()
  love.graphics.print("You " .. hero .. "  Ogre " .. ogre .. "  Turn " .. turn, 20, 20)
  love.graphics.print("Ogre will hit for " .. intent .. ". " .. message, 20, 40)
  if dice then love.graphics.print("Your dice: " .. dice[1] .. ", " .. dice[2], 20, 60) end
end

Set MODE to "output" and nothing else changes, yet the game plays differently. In output mode plans 2 and 3 mean the same thing, because the dice are not known yet.

Pitfalls

  • Big swings after the choice. A roll that can turn full success into total failure makes the decision feel pointless. Keep output rolls small, or let a miss still do something, such as half damage.
  • Hiding the odds. If the player cannot see a chance, they cannot plan with it, and every miss feels unfair. Show the number, and make it true.
  • Too much input to read. A huge random hand every turn is a lot to take in. Fewer, clearer random pieces tend to work better.
  • No way to respond. Input randomness only helps if the player has real choices. If every hand has one obvious play, the luck is just output randomness wearing a disguise.

In real games

Slay the Spire is built on input randomness. You draw a random hand and see what each enemy intends to do next turn before you play a card, and most cards do a fixed amount. Dicey Dungeons goes further: you roll your dice at the start of each turn and then decide which piece of equipment each die goes into.

XCOM: Enemy Unknown shows a hit chance before each shot, and the roll happens after you commit. That is output randomness, and the stories players tell about missed high-percentage shots show both its drama and its sting. Board games such as Risk resolve battles with dice after the attack is declared.

Takeaways

  • Input randomness happens before the decision and gives the player a problem to solve. Output randomness happens after it and decides whether the plan worked.
  • The same dice with the same average can make skill matter a lot or a little, depending only on when they are rolled.
  • Output randomness creates suspense and lets weaker players win sometimes, but big swings make good decisions feel pointless.
  • Most games mix both. Keep the rolls after the choice small and their odds visible and honest.
  • Paid output randomness is gambling. Treat it that way.
