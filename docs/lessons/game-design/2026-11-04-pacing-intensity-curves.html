Pacing and intensity curves

How alternating build-ups, peaks and rests keeps players engaged longer than constant action, and how to drive a level from an intensity curve.

You build a level, fill it with enemies, and it plays well for a minute. Then it starts to feel like a chore. You did not run out of enemies. The player ran out of attention, because every second asked for the same amount of effort.

Adding more enemies does not fix that. Changing when they arrive usually does.

Intensity over time

Intensity is how much the game is asking of the player at a given moment: how many threats there are, how fast they move, how little room there is to make a mistake. Draw it against time and you get an intensity curve. Pacing is the shape of that curve: where it rises, where it peaks and where it drops.

Why constant action wears thin

Players tend to get used to whatever pressure they are given. A steady stream of enemies starts out exciting and soon becomes background. The player is still working hard, but it feels like work, not like a climax.

Contrast is what makes a peak feel big. A wave of eight enemies after ten quiet seconds lands harder than the same eight in the middle of a constant stream. Rests also let the player breathe, look around and get ready for the next push.

The opposite mistake, a level that stays quiet throughout, never builds tension, so the player gets bored instead of tired.

The shape that tends to work

A common pattern repeats four phases: a build-up where the pressure rises, a peak, a release where it falls away quickly, and a rest where little happens. Each wave usually peaks a little higher than the last, and the biggest peak comes near the end, followed by a short calm.

The shape works at several scales: a flurry of attacks and a gap inside one fight, arenas and corridors across a level, chapters building to a boss across a game. Jesse Schell discusses a closely related idea, the interest curve, in The Art of Game Design.

Make the curve data, not an accident

Write the curve down and let it drive the game. Store intensity values from 0 to 1, one every few seconds. Each frame, look up the value for the current time and turn it into something concrete: enemies per second, enemy speed, the share of tough enemies. Now pacing is a shape you can read and edit, not a pile of spawn triggers.

Check two numbers on any curve: its average, which sets the total amount of action, and the longest stretch without a rest, the longest time intensity stays above your rest line. Equal averages can feel completely different when the second number differs.

Starting points, not rules

For a short arcade level, try pushes of 10 to 20 seconds, rests of 5 to 10 seconds, and a quarter to a third of the time resting. Call anything below 30 percent intensity a rest. Tune by playing, not by staring at the graph.

Try it

Play one run on the "Flat" preset, then one on "Waves". Both spawn the same number of rocks in 60 seconds; only the timing changes. Notice how the flat run feels by the 40 second mark, and how the last peak of the waves run compares. Then drag the points to design your own curve.

The code

The curve is a table of 13 values, one every 5 seconds, the same as the demo. intensityAt blends between the two nearest values. The spawner turns intensity into rocks per second and keeps the leftover fraction of a rock in spawnDebt, so low intensities still spawn the occasional rock instead of none.

-- One intensity value from 0 to 1 every 5 seconds of a 60 second level ("Waves")
local GAP, LENGTH = 5, 60
local PEAK_RATE = 3       -- rocks per second at intensity 1
local REST = 0.3          -- below this counts as a rest
local curve = { 0.1, 0.4, 0.7, 0.15, 0.15, 0.6, 0.9, 0.15, 0.15, 0.7, 1.0, 1.0, 0.1 }

local t, spawnDebt = 0, 0

local function intensityAt(time)
  local u = math.max(0, math.min(time / GAP, #curve - 1))
  local i = math.min(math.floor(u), #curve - 2)   -- segment, counted from 0
  local a, b = curve[i + 1], curve[i + 2]
  return a + (b - a) * (u - i)
end

function love.update(dt)
  if t >= LENGTH then return end
  t = t + dt
  spawnDebt = spawnDebt + PEAK_RATE * intensityAt(t) * dt
  while spawnDebt >= 1 do
    spawnDebt = spawnDebt - 1
    spawnRock(love.math.random())   -- your function: a rock at a random height
  end
  updateRocks(dt)                   -- your function: move rocks, check hits
end

-- Design check: the longest time the curve stays above the rest line
local function longestStretch()
  local samples = 1200
  local step = LENGTH / samples
  local best, run = 0, 0
  for k = 0, samples - 1 do
    if intensityAt((k + 0.5) * step) >= REST then
      run = run + step
      if run > best then best = run end
    else
      run = 0
    end
  end
  return best
end

For the "Waves" curve, longestStretch() returns about 17.6 seconds. For "Flat" it returns the whole 60. Print it whenever you edit a curve.

Pitfalls

  • Rests that are empty. A rest with nothing to do is padding. Give it low-stakes things: pickups, a view, a line of dialogue, an upgrade choice.
  • Rests that are not safe. If rests sometimes hide ambushes, players stay tense through them and the curve flattens. Use quiet-moment surprises rarely and on purpose.
  • Every peak the same height. Identical waves feel like a loop, not a journey. Raise each peak a little, or change what it asks for.
  • Counting only enemies. Intensity is what the player feels. One fast enemy in a narrow corridor can be more intense than ten slow ones in an open field, so playtest the curve.
  • One curve for every player. A gentle wave for an expert can be a wall for a beginner. The next two lessons look at matching challenge to skill.

When not to use it

In score-attack and endless games, steadily rising pressure is often the point, and the player's failure ends the run. In puzzle and turn-based games the player already sets the pace, so imposed rests tend to feel like waiting. In competitive multiplayer, pacing comes mostly from the players and the map, not a timeline. And a level under half a minute may be just one build and one peak.

In real games

Many wave-based games put a break between waves for building or shopping: a rest phase in its plainest form.

The save rooms of the early Resident Evil games are a well-known example of a designed rest: a small room that enemies do not enter, with its own calm music, placed between tense stretches.

Valve's Left 4 Dead (2008) generates pacing at run time with a system it calls the AI Director, which varies how many enemies appear based on how the players are doing. Michael Booth's 2009 talk on the game's AI lists dramatic pacing among its goals. The talk could not be checked for this lesson, so its internal rules are not described here.

Your turn (15 minutes)

Play one level of your game with a stopwatch. Every 5 seconds, write down a number from 0 to 3 for how hard the game is pushing you, and plot the numbers.

Find the longest stretch without a 0 or a 1. If it is longer than about 30 seconds in an action level, add a rest inside it: move a group of enemies later, or open a quiet side room. Play and plot again. You are done when your curve shows at least two clear rests and its tallest peak is in the last third.

Takeaways

  • Intensity is how much the game asks of the player right now. Pacing is the shape of intensity over time.
  • Constant action tends to become background noise. Peaks feel big because of the rest that came before them.
  • A common shape is build, peak, release and rest, repeated with rising peaks and a climax near the end.
  • Store the curve as data and drive spawning from it, so you can see and edit the pacing as a shape.
  • Check the average and the longest stretch without a rest. Equal averages can feel very different.
