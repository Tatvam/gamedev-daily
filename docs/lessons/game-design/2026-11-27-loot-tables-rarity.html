Loot tables and rarity: how long does a full set take?

How weighted drop tables turn weights into chances, and why the rarest item decides how long it really takes to collect a full set.

You give a boss five drops and make the legendary one a 2 percent chance. "About 50 kills," you think. A week later one player has beaten the boss 150 times and still has no legendary, while carrying 70 copies of the common one. Both of them are using the same table, and the table is working exactly as written.

Weights, not percentages

A loot table is a list of things that can drop, each with a weight: a number that says how common it is compared with the others. The chance of an entry is its weight divided by the total of all weights. Weights 50, 25, 15, 8 and 2 add up to 100, so they read as percentages, but they do not have to. Weights 10, 5, 3, 1.6 and 0.4 give exactly the same chances.

Weights let you add an entry without rewriting the others, but every new entry quietly makes the rest rarer. Add a sixth item with weight 10 and the legendary falls from 2 percent to 2 / 110, about 1.8 percent.

Rolling the table

To pick an entry, lay the weights end to end, pick a random number from 0 up to the total, and walk the list subtracting each weight until the number falls inside one.

Rarity tiers and nested tables

A common pattern is two rolls: first the rarity tier (common, rare, legendary and so on), then which item of that tier. A new legendary sword then dilutes only the other legendaries, not the chance of some legendary. A "nothing" entry is also common; it scales every real drop down by the same factor.

How long does a full set take?

Players care less about one drop than about "when will I have all of them?" That is the coupon collector's problem: keep drawing until you have seen every item at least once. With five equally likely items the first drop is always new, and each new item after that is harder to find, because more of the table is things you already own.

With n equally likely items the average is n × (1 + 1/2 + 1/3 + ... + 1/n). For five items that is 11.4 drops, more than twice the five you might guess.

With unequal items there is no neat formula, but you cannot finish before you find the rarest item, and that alone takes 1 / p drops on average, where p is its chance. A 2 percent legendary means 50 drops, and the common items mostly turn up while you wait.

Design for the unlucky player, not the average one

The average hides a long tail. A starting rule: decide the most drops you will ask of an unlucky player, make that the "9 in 10" number, and work back to the rarest weight. Then tune by playing.

Ways to shorten the tail

  • Duplicate protection. Reroll a duplicate once, or remove owned items entirely (then five items take exactly five drops).
  • A pity timer on the rarest entry caps the worst case directly.
  • Salvage. Turn duplicates into a currency that buys the missing item.

When not to use a weighted table

  • Required progress. If the player cannot continue without an item, give it or guarantee it.
  • Short games. In a run of 30 drops, most players never see a 2 percent item. Fine for a secret, not for a set.
  • Items that are just bigger numbers. "The same sword, plus 10 percent" adds grind but little surprise. Rarity tends to feel best when rare items change how you play.

Rarity can be used against the player

When each draw costs real money, the full-set cost is the true price of the rarest item, and one tiny weight can make that price huge while each draw looks cheap. A set with one missing piece is a well-known way to keep people paying. If you sell draws, show the odds for every entry before purchase.

The code

rollLoot is the whole drop table. dropsToCollectAll plays one collector; running it a thousand times makes the demo's bars.

local LOOT = {
  { name = "Common",    weight = 50 },
  { name = "Uncommon",  weight = 25 },
  { name = "Rare",      weight = 15 },
  { name = "Epic",      weight = 8 },
  { name = "Legendary", weight = 2 },
}

local function totalWeight(tbl)
  local total = 0
  for _, entry in ipairs(tbl) do total = total + entry.weight end
  return total
end

local function rollLoot(tbl)
  local roll = love.math.random() * totalWeight(tbl)   -- 0 up to the total
  for _, entry in ipairs(tbl) do
    if roll < entry.weight then return entry end
    roll = roll - entry.weight
  end
  return tbl[#tbl]   -- only reached through rounding
end

-- One player opens drops until they own every entry. Every weight must be above 0.
local function dropsToCollectAll(tbl)
  local owned, have, drops = {}, 0, 0
  while have < #tbl do
    local entry = rollLoot(tbl)
    drops = drops + 1
    if not owned[entry.name] then
      owned[entry.name] = true
      have = have + 1
    end
  end
  return drops
end

function love.load()
  local players, results = 1000, {}
  for i = 1, players do results[i] = dropsToCollectAll(LOOT) end
  table.sort(results)
  print("half of players done by " .. results[math.floor(players * 0.5)])
  print("9 in 10 done by " .. results[math.floor(players * 0.9)])
end

love.math.random() with no arguments returns a number from 0 up to, but not including, 1. With the default weights the two printed numbers should land near 38 and 115.

Pitfalls

  • Off by one with whole numbers. If you roll a whole number with love.math.random(total), it runs from 1 to the total, so the test becomes roll <= entry.weight. Mixing the two styles gives the first entry one extra slot and the last one none.
  • Silent dilution. Every new entry makes all the others rarer. Print each entry's real percentage after every change, or use tiers so new items only dilute their own tier.
  • A weight of zero. An item with weight 0 can never drop, so a "collect them all" loop never ends. Skip zero-weight entries when counting a set.
  • Rounded odds. "0%" for a 0.4 percent item is wrong. Show decimals for rare entries.
  • Trusting the average. Test with the "9 in 10" and "99 in 100" numbers. With thousands of players, the 1 in 100 player is a real person.

In real games

Colour-coded rarity is common in loot-driven games. World of Warcraft's item quality ladder is a well-known example: grey for poor, white for common, green for uncommon, blue for rare, purple for epic and orange for legendary. The demo borrows the idea and adds a letter per tier, so colour is never the only cue.

Collectible card games sold in random packs are coupon collector problems with money attached, and they commonly mix weights with guarantees, such as a set number of rarer cards per pack. Apple's App Store review guidelines ask apps that sell random items to disclose the odds before purchase. I found news reports of that rule from late 2017 but could not open the current guideline text, so check the live wording.

Takeaways

  • An entry's chance is its weight divided by the total. Adding an entry makes every other entry rarer.
  • Roll from 0 to the total and walk the list; tiers rolled first keep new items from diluting other tiers.
  • Collecting a full set takes far longer than one drop: five equal items take 11.4 drops on average, and the rarest item tends to set the pace.
  • Design for the "9 in 10" player, not the average. Duplicate protection, pity timers and salvage shorten the tail.
  • When draws cost money, the full-set cost is the real price. Show the odds.
