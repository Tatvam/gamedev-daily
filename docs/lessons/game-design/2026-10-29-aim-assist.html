Aim assist: friction and magnetism

How slowing the reticle near a target and bending near-miss shots onto it help stick players aim, without the game taking the aim away from them.

You push the stick toward an enemy, the crosshair sails past it, you pull back and it sails past the other way. By the time you settle, the target has moved. The player blames themselves, but the problem is the stick.

Why sticks need help

A mouse maps hand movement to reticle movement, and the reticle, the crosshair, stops the moment the hand stops. A thumbstick maps tilt to speed, and the whole range from slow to fast fits into a few millimetres of thumb travel. The reticle arrives at a target at speed and the thumb cannot let go precisely enough to stop on it.

Aim assist is the set of hidden rules that make up the difference. This lesson covers the two that change the least about who is in control.

Friction: slow the reticle near a target

Reticle friction, also called slowdown, lowers the reticle's speed while it is near a target, so a push that would have overshot ends on the target instead. It scales the player's input: the speed the stick asks for is multiplied by a number below 1. With the stick centred, friction does nothing, because zero times anything is zero.

Magnetism: bend a near miss

Bullet magnetism acts at the moment of firing. If the shot would just miss, the game sends it to the nearest target anyway. The player chose where and when to shoot; the game only rounds a near miss up to a hit.

The line between assist and autopilot

Both techniques only adjust something the player is already doing. Compare snap aim, which pulls the reticle onto a target by itself. Snapping can suit a casual or accessibility mode, but it takes the decision away. A useful test: if the player lets go of the controls, does anything aim? With friction and magnetism, nothing does. A third kind, often called adhesion, carries the reticle along with a moving target. It helps tracking, but it moves the view without input, so it sits closer to that line.

Starting points to tune

In the demo, friction reaches 28 px past the edge of a target with a 10 px radius and, at the default strength, cuts speed to 60 percent. Magnetism reaches 12 px past the edge. Try a slowdown of 30 to 60 percent and a magnetism zone smaller than the target itself. In 3D the zones are usually angles from the camera, and commonly switch off beyond a weapon's useful range. These are starting points to tune, not rules.

What the player feels

Without assist, aiming on a stick feels slippery and attention goes to fighting the reticle. With light assist, the reticle seems to settle on enemies and good shots land; players rarely notice, they just feel competent. With too much, the reticle drags on every target it passes, and hits start to feel like the game's work rather than yours.

Try it

Play a 20 second round with both toggles off, then with friction, then magnetism, then both. Every round uses the same targets in the same order, so the readouts compare fairly. Watch the bars at the bottom left: "stick" is how hard you push, "reticle" is how fast the reticle really moves. In a friction zone the second bar drops and the reticle turns orange. A dashed orange line marks a shot that magnetism bent. Then set strength to 100 percent and try to sweep past one target to reach another. That drag is what too much feels like.

The code

This is the demo's aiming code in LÖVE, with the same numbers. Moving and respawning targets, the fire cooldown and drawing are left out. The keyboard acts as a digital stick; a gamepad's analog stick would replace readStick. The marked lines are the two techniques.

local MAX_SPEED, RESPONSE = 200, 18      -- reticle px/s, how fast it reaches that speed
local FRICTION_ZONE, MAX_SLOW = 28, 0.8  -- px past the target's edge, slowdown at full strength
local MAGNET_ZONE = 24                   -- px past the edge at full strength
local STRENGTH = 0.5                     -- the demo's slider, 0 to 1
local FRICTION, MAGNETISM = true, true   -- the demo's toggles

local reticle = { x = 180, y = 130, vx = 0, vy = 0 }
local targets = {}  -- { x, y, r = 10 }, moved by your own code

local function nearest(x, y, extra)
  local best, bestD = nil, math.huge
  for _, t in ipairs(targets) do
    local d = math.sqrt((t.x - x) ^ 2 + (t.y - y) ^ 2)
    if d < t.r + extra and d < bestD then best, bestD = t, d end
  end
  return best
end

local function readStick()
  local ix, iy = 0, 0
  if love.keyboard.isDown("left") then ix = ix - 1 end
  if love.keyboard.isDown("right") then ix = ix + 1 end
  if love.keyboard.isDown("up") then iy = iy - 1 end
  if love.keyboard.isDown("down") then iy = iy + 1 end
  local m = math.sqrt(ix * ix + iy * iy)
  if m > 1 then ix, iy = ix / m, iy / m end
  return ix, iy
end

function love.update(dt)
  local ix, iy = readStick()
  local mult = 1
  if FRICTION and nearest(reticle.x, reticle.y, FRICTION_ZONE) then
    mult = 1 - MAX_SLOW * STRENGTH  -- scales the input, never adds to it
  end
  local k = math.min(1, RESPONSE * dt)
  reticle.vx = reticle.vx + (ix * MAX_SPEED * mult - reticle.vx) * k
  reticle.vy = reticle.vy + (iy * MAX_SPEED * mult - reticle.vy) * k
  reticle.x = reticle.x + reticle.vx * dt
  reticle.y = reticle.y + reticle.vy * dt
end

local function onTargetHit(t)
  t.hit = true  -- your score, effects and respawn go here
end

local function fire()
  local hit = nearest(reticle.x, reticle.y, 0)
  if not hit and MAGNETISM then
    hit = nearest(reticle.x, reticle.y, MAGNET_ZONE * STRENGTH)  -- bend a near miss
  end
  if hit then onTargetHit(hit) end
end

function love.keypressed(key)
  if key == "space" then fire() end
end

One strength value drives both effects, so a single settings option can scale them together. Neither can move the reticle while the stick is centred.

Pitfalls

  • Friction on a moving target. If a target moves faster than the slowed reticle, friction makes tracking it harder, not easier. Keep the slowed speed well above typical target speed, or pair friction with a little adhesion.
  • Friction on things you should not shoot. Zones on allies, hostages or dead bodies fight the player when they look away. Only live targets should have them.
  • Crowds. When zones overlap, the reticle drags everywhere and magnetism may pick a target the player did not mean. Shrink zones in crowds, or prefer the target the stick is pointing toward.
  • Too strong. When almost every shot lands, aim stops being a skill and hits stop feeling earned.
  • Hiding it from the player. Assist works best unseen during play, but it should not be a secret. A strength setting lets players turn it down for challenge or up for help.

When not to use it. Mouse aiming is already precise; adding friction to it tends to feel like the game is fighting the hand. In competitive play where controller and mouse players meet, any assist becomes a fairness question, and players argue about it fiercely. In games where precise aim is the whole test, such as a trick-shot or a sniper puzzle, assist removes the thing being tested.

In real games

Aim assist is standard in console shooters played with a gamepad, and it is commonly limited to controller input when the same game also supports a mouse. The Halo series is a well known example. The Halopedia fan wiki describes a slowdown near enemies that the game files call "magnetism", applied only to controller players, with a radius that varies by weapon, and lists it separately from auto-aim, which players call bullet magnetism. I found that description in search results and could not open the page to confirm the details.

In Destiny 2, aim assistance is a per-weapon stat that the game does not show on screen; players read it through third-party tools. Again this comes from guides I saw in search results rather than an official page.

At GDC 2013, Nick Weihs of Insomniac Games gave a talk titled "Techniques for Building Aim Assist", about the systems in Resistance 3. Its listing describes friction, magnetism and centring among the techniques covered. I saw only a search summary of the listing.

Your turn (15 minutes)

In your own game, or a small test scene, plug in a gamepad or use keyboard aiming and put three targets on screen. Add the nearest function and friction first, with a debug key that draws the friction zones. Time yourself hitting ten targets with friction off and on. Then add magnetism and do it again. You are done when you can name a strength where hits feel easier but you still feel responsible for them, and a strength where the reticle starts to drag.

Takeaways

  • A thumbstick maps tilt to speed, so stick players overshoot small targets; aim assist makes up the difference.
  • Friction multiplies the player's input by less than 1 near a target. It never moves the reticle on its own.
  • Magnetism turns a shot that just missed into a hit, only at the moment the player fires.
  • Snap aim and strong adhesion move the view without input. Use them knowingly, for example in an assist mode.
  • Keep the zones small, apply them only to real targets, and give players a strength setting.
