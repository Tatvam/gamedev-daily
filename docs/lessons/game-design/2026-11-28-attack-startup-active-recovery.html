Anatomy of an attack: start-up, active and recovery

How splitting an attack into start-up, active and recovery frames creates commitment, and how recovery length decides whether a missed or blocked swing gets punished.

In many first combat prototypes the sword swing is instant: press the button and the enemy takes damage. Nothing interrupts it, nothing follows it, and the best plan is to mash.

Fights get interesting when an attack takes time and that time has a shape. This lesson splits a swing into three phases that turn presses into decisions.

Three phases, counted in frames

Action games commonly describe an attack as three back-to-back phases, measured in frames. At 60 frames per second one frame is about 16.7 milliseconds.

  • Start-up is the wind-up: the frames between the press and the first moment the attack can hit. Nothing can be hit yet, but the attacker is already committed.
  • Active frames are the window in which the attack's hitbox exists and can connect.
  • Recovery is the follow-through: the hitbox is gone, but the attacker cannot block, dodge or attack again until it ends.

The total is how long the player is locked in. That lock is commitment: once the button is pressed, the game stops listening until the move is over. Without it there is no wrong moment to press.

What each phase does to the player

Start-up decides how fast you can react. A person's simple reaction to something they expect is commonly measured at around a fifth to a quarter of a second, roughly 12 to 15 frames. Add an 8-frame start-up and the player needs about 20 to 23 frames to answer a threat. An enemy wind-up of 30 frames can be interrupted; one of 15 cannot.

Active frames decide how forgiving the timing is. A longer window catches an opponent who steps in late. Very long ones turn the attack into a wall.

Recovery decides the price of being wrong. If the attack misses, or the opponent blocks it, recovery is the gap they can step into. A punish is an attack that lands in that gap. Whether one is possible comes down to a single comparison: the attacker's recovery against the start-up of the defender's fastest answer.

Fighting game players call this number frame advantage: how many frames earlier one side can act again after an exchange. Write down the start-up of your enemies' fastest answer, and you know how much recovery your player's moves can afford.

Starting numbers

AttackStart-upActiveRecoveryFeels like
Quick jab4 to 62 to 38 to 12fast, safe, weak
Medium swing8 to 123 to 515 to 20the everyday tool
Heavy blow18 to 254 to 625 to 40a gamble with a big payoff

These are starting points to tune by playing, not rules. Slower, heavier games stretch every column. The shape matters more than the values: a stronger attack should cost more time, usually in start-up and recovery.

Rule of thumb

Make power and safety pull against each other. If the strongest move is also the fastest and the safest, the player will use nothing else.

The code

An attack is a frame counter and a few comparisons. Count in fixed steps, not drawn frames, so the move lasts the same number of frames on every machine. The names and numbers match the demo's defaults.

local STEP = 1 / 60                       -- one frame at 60 per second
local STARTUP, ACTIVE, RECOVERY = 8, 4, 18
local COUNTER_STARTUP = 12                -- the dummy's fastest answer

local attack = nil                        -- nil means the player is free
local accumulator = 0

local function hitDummy() end             -- replace with your damage or guard code

local function phase(a)
  if a.frame < STARTUP then return "startup" end
  if a.frame < STARTUP + ACTIVE then return "active" end
  return "recovery"
end

-- Frames of recovery left when the counter lands. Above 0 means punishable.
local function opening()
  return RECOVERY - COUNTER_STARTUP
end

function love.keypressed(key)
  if key == "j" and attack == nil then    -- busy: the press is ignored
    attack = { frame = 0, hasHit = false }
  end
end

local function step()
  if attack == nil then return end
  if phase(attack) == "active" and not attack.hasHit then
    attack.hasHit = true                  -- one hit per swing
    hitDummy()
  end
  attack.frame = attack.frame + 1
  if attack.frame >= STARTUP + ACTIVE + RECOVERY then
    attack = nil
  end
end

function love.update(dt)
  accumulator = accumulator + dt
  while accumulator >= STEP do
    step()
    accumulator = accumulator - STEP
  end
end

function love.draw()
  local text = "ready, opening " .. opening()
  if attack ~= nil then text = phase(attack) .. " " .. attack.frame end
  love.graphics.print(text, 10, 10)
end

In the demo the dummy is always in reach, so the first active frame connects. In your game, test the hitbox against the target on each active frame.

Pitfalls

  • Letting the animation decide the numbers. A beautiful 40-frame swing may be far too slow to play. Decide the frame counts first, then time the animation so the strike pose sits on the active frames.
  • Recovery the player cannot see. If the character looks ready but cannot act, the punish feels like a bug. Hold a follow-through pose until recovery ends.
  • Swallowing presses. Commitment means ignoring a new attack, not losing it without a trace. Many games remember a press made in the last few frames of recovery and start it on the first free frame, the same idea as the jump buffering lesson.
  • Hitting more than once per swing. A hitbox that lives for 4 active frames will deal damage 4 times unless you mark the swing as having hit.
  • Counting drawn frames. If the counter advances once per drawn frame, the move is shorter on a 144 hertz screen. Advance it in a fixed step.
  • Cancels everywhere. Letting every move cancel into a dodge erases recovery and the reason to choose carefully. Limit cancels or give them a cost.

When not to use it. Long start-up and recovery tend to feel wrong where attacking is constant and cheap, such as shoot-'em-ups and twin-stick shooters. There, delay reads as input lag. Keep start-up to a frame or two and put the cost in ammunition, cooldowns or movement instead.

In real games

Fighting games are where this vocabulary comes from. Players commonly look up "frame data" for each move, listing start-up, active and recovery frames and the frame advantage on block. Street Fighter 6 includes a frame meter in its training mode that colours each phase of a move as it plays, so players can see their own openings.

Melee action games are commonly built the same way without showing the numbers. Games in the style of Dark Souls are known for heavy commitment: once a swing starts it plays out, and an enemy's long recovery is the moment to attack.

Your turn (15 minutes)

Take the main attack in your game and write its start-up, active and recovery in frames. If it does not have phases yet, add the counter from the code above and give it 8, 4 and 18.

Then find the fastest enemy attack and note its start-up. Subtract it from your recovery. You are done when you can say whether your main attack is punishable if blocked, by how many frames, and you have made one deliberate change: cut recovery to make it safe, or give it enough power to justify the risk.

Takeaways

  • An attack is start-up, active and recovery frames. Together they are how long the player is committed.
  • Start-up decides how quickly an attack can answer a threat. Active frames decide how forgiving the timing is.
  • Recovery minus the start-up of the opponent's fastest answer tells you whether a blocked or missed attack can be punished.
  • Make stronger attacks cost more time, so power and safety pull against each other.
  • Count frames in a fixed step, show recovery in the pose, and buffer presses instead of losing them.
