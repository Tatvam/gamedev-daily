Pseudo-random distribution: making 25 percent feel like 25 percent

Why true randomness feels unfair in streaks, and how raising the chance after every miss keeps the same average with far fewer droughts.

Your sword has a 25 percent chance to land a critical hit. You swing twelve times without one, then land two in a row. The player decides the game is broken. It is not. That is just how true randomness behaves, and players tend to hate it.

Streaks are normal, and players read them as unfair

With true randomness, every roll is independent: each attack has exactly the stated chance, whatever happened before. That sounds fair, but independent rolls clump. At 25 percent, ten misses in a row happen about 1 time in 18. Over a 200-attack fight, the chance of seeing at least one run of ten or more misses is about 96 percent. Crits also come back to back a quarter of the time.

Players do not judge a game by its long-run average. They remember the streaks. Many people also believe in the gambler's fallacy: the feeling that after many misses, a hit is "due". With true randomness it is not, so the streak feels like the game cheating.

The fix: raise the chance after each miss

Pseudo-random distribution, or PRD, makes the gambler's fallacy come true on purpose. Count the attacks since the last crit, N. The chance of a crit on this attack is C × N, where C is a small constant. Every miss makes the next crit more likely. A crit resets N to zero.

C is chosen so that the long-run average equals the chance you advertise. For 25 percent it is about 0.0847, so the first attack after a crit has an 8.5 percent chance, the second 16.9, the third 25.4, and by the twelfth attack a crit is certain.

Same average, narrower spread

Both systems give one crit every 4 attacks on average. What changes is how far a single wait strays from that average. With true randomness at 25 percent, 1 wait in 100 lasts 17 attacks or more, and there is no upper limit. With PRD, the longest possible wait is 12 attacks, and a crit straight after a crit drops from 25 percent to 8.5 percent. In that 200-attack fight, the chance of a ten-miss drought falls from 96 percent to about 2 percent.

There is no neat formula for C. You find it once with a short search: guess a value, work out the average rate it produces, and adjust. The code below does exactly that. Starting values:

When not to use it

PRD changes what the shown number means. "25 percent" is now the average, not the chance of any single attack. That has costs:

  • It can be gamed. A player who knows the rule can "charge" the counter by hitting something harmless, then switch to the target that matters while the chance is high. Keeping a separate counter per target, or resetting it when the target changes, closes that gap.
  • Rare events get rarer early. At 5 percent, C is about 0.0038. The chance of no crit in the first ten attacks goes up, from 60 percent to 81 percent. PRD shines for common effects, roughly 15 to 50 percent, and helps less for rare ones.
  • Some players want real dice. Where players calculate odds, as in tactics games, a hidden rule that bends them can feel like a lie once discovered. Say what you do, in a tooltip or the manual.
  • Sometimes swing is the fun. A party game may want wild streaks and the stories they create.

The same trick can work against the player

Hidden odds that move are a tool. Used here they protect the player from bad luck. The same machinery can make a paid reward feel closer than it is, or quietly lower the odds after a win. If real money buys a roll, show the true odds and do not change them in secret. Some app stores and countries already require paid random items to show their odds.

The code

The whole system is rollCrit, ten lines. The rest finds C once at load time. Set MODE to "true" to compare with plain dice.

local NOMINAL = 0.25          -- the crit chance the player is told
local MODE = "prd"            -- "prd" or "true"
local attacksSinceCrit = 0

-- The average crit rate a given C produces, worked out exactly.
local function rateFor(C)
  local expected, survive, n = 0, 1, 1
  while survive > 0.000001 do
    local chance = math.min(1, C * n)
    expected = expected + n * survive * chance
    survive = survive * (1 - chance)
    n = n + 1
  end
  return 1 / expected
end

-- Search for the C whose average rate matches the advertised chance.
local function findC(p)
  local low, high = 0, p
  for i = 1, 40 do
    local mid = (low + high) / 2
    if rateFor(mid) < p then low = mid else high = mid end
  end
  return (low + high) / 2
end

local C = findC(NOMINAL)      -- about 0.0847 for 25 percent

local function rollCrit()
  if MODE == "true" then return love.math.random() < NOMINAL end
  attacksSinceCrit = attacksSinceCrit + 1
  local chance = math.min(1, C * attacksSinceCrit)
  if love.math.random() < chance then
    attacksSinceCrit = 0
    return true
  end
  return false
end

function love.keypressed(key)
  if key == "space" then
    local damage = 10
    if rollCrit() then damage = 25 end
    print("Hit for " .. damage)
  end
end

The search for C runs once at load time; never run it every attack. Keep one counter per effect, and one per target if charging is a risk.

Pitfalls

  • Using the advertised chance as C. If you write 0.25 * N, the real rate comes out near 45 percent. C must be solved for, not copied.
  • One shared counter for everything. If crits, dodges and stuns share a counter, one effect's luck changes another's. Give each effect its own.
  • Forgetting the counter during cooldowns. If an effect cannot fire while on cooldown, decide whether attacks during the cooldown still raise the chance. Raising it means the effect fires almost at once when the cooldown ends.
  • Rolling more than once. Calling rollCrit twice for one attack, for example once for a preview and once for real, advances the counter twice. Roll once and keep the result.

In real games

Dota 2 is the best-known example. Its community wikis document that effects such as critical strikes and bashes use pseudo-random distribution, with a constant of about 0.0847 for a 25 percent effect, which matches the value above. Those wikis credit Warcraft III, whose engine the original Defense of the Ancients ran on, as the source of the rule. These are fan-maintained sources rather than official documentation.

Other games bend luck in the player's favour in related ways. Community analysis of XCOM 2's configuration files reports a hidden bonus to hit chance after misses on the easier difficulties; I could not check the exact numbers, so I leave them out.

Takeaways

  • True randomness produces long streaks often, and players tend to read streaks as unfairness.
  • Pseudo-random distribution sets the chance to C times the attacks since the last success, so misses raise the odds and a success resets them.
  • C is solved so the long-run average matches the advertised chance; for 25 percent it is about 0.0847.
  • It works best for common effects. It can be exploited by charging the counter, and it changes what the displayed number means.
  • Hidden odds can protect players or exploit them. Be open about it, especially when money is involved.
