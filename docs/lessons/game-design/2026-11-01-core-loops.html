Core loops: action, reward, investment

How a game's repeated cycle of action, reward and investment works at the scale of seconds, minutes and sessions, and how to check yours closes.

Your prototype plays well for two minutes. You collect things, the counter goes up, and then the counter stops meaning anything. Nothing you earned changes what you do next, so every minute feels like the first. The play is fine. The loop around it is not closed.

A loop is a sentence that ends where it started

A core loop is the cycle of play a player repeats most often, where each step leads into the next one. Most core loops can be split into three parts:

  • Action: what the player does. Run, shoot, plant, pick.
  • Reward: what the action gives back. Coins, loot, experience, a new room.
  • Investment: what the player spends the reward on, which changes the next round of action. A bigger bag, a better sword, a new ability.

The investment step is the one that closes the loop. Without it, rewards pile up as score. With it, each round is a little different from the last because the last round changed it.

A quick test is to say the loop out loud as one sentence: "I pick berries to earn coins so I can buy a bigger bag, which lets me pick more berries." If the sentence cannot get back to its first verb, the loop is open.

Loops inside loops

Games usually run several loops at once, nested by time. The reward of a small loop feeds the action of a bigger one.

Each scale answers a different question for the player. The seconds loop answers "is this fun to do?" The minutes loop answers "why am I doing it?" The session loop answers "why come back tomorrow?" A weak loop at one scale is hard to rescue with the others: great upgrades do not save dull picking, and great picking tends to go stale with nothing to work toward.

What the player feels

With the loop open, the first trips are fine, then the player notices that trip ten is the same as trip one. With the loop closed, each investment makes the next trip visibly different: a bigger haul, a shorter walk, bushes that grow back while you watch. The player starts planning: "two more trips and I can afford boots." That small plan is a reason to keep playing.

Starting points to tune

In a first session, aim for the first full minutes loop to take under a minute, and the first investment to be affordable within two or three loops. Make each investment change the next loop by enough to notice; a 30 to 50 percent change is a common place to start for early upgrades. Later loops can grow longer. These are starting points to tune, not rules.

The code

This is the demo's loop in LÖVE, with the same numbers. Movement is a stub called movePlayer; put your own there. The three marked lines are the three parts of the loop: action, reward and investment.

local EFFECT = 0.5            -- each upgrade level adds 50 percent
local BASE_COST, COST_GROWTH, MAX_LEVEL = 5, 1.7, 4
local SHOP_RIGHT, PICK_RANGE = 80, 22

local player = { x = 40, y = 110, bag = 0, coins = 0 }
local levels = { bag = 0, boots = 0, soil = 0 }
local bushes = { { x = 150, y = 50, ripe = true, timer = 0 } }  -- add more

local function capacity() return 3 + math.floor(3 * EFFECT * levels.bag) end
local function speed() return 110 * (1 + EFFECT * levels.boots) end
local function regrowTime() return 6 / (1 + EFFECT * levels.soil) end
local function cost(name)
  return math.floor(BASE_COST * COST_GROWTH ^ levels[name] + 0.5)
end

local function movePlayer(p, pixelsPerSecond, dt) end  -- your movement

local function buy(name)
  if levels[name] < MAX_LEVEL and player.coins >= cost(name) then
    player.coins = player.coins - cost(name)
    levels[name] = levels[name] + 1          -- investment
  end
end

function love.keypressed(key)
  if key == "1" then buy("bag") elseif key == "2" then buy("boots")
  elseif key == "3" then buy("soil") end
end

function love.update(dt)
  movePlayer(player, speed(), dt)
  for _, b in ipairs(bushes) do
    if not b.ripe then
      b.timer = b.timer + dt
      if b.timer >= regrowTime() then b.ripe = true end
    end
    local dx, dy = b.x - player.x, b.y - player.y
    if b.ripe and player.bag < capacity() and dx * dx + dy * dy < PICK_RANGE ^ 2 then
      b.ripe = false
      b.timer = 0
      player.bag = player.bag + 1            -- action
    end
  end
  if player.x < SHOP_RIGHT and player.bag > 0 then
    player.coins = player.coins + player.bag -- reward
    player.bag = 0
  end
end

Each upgrade changes a different part of the loop: capacity makes the reward bigger, speed shortens the walk, and regrowTime brings the action back sooner. That spread gives the player real choices.

Pitfalls

  • Rewards with nowhere to go. Coins, gems and points that buy nothing turn into noise. Every reward should feed some action, even if only a score the player is chasing on purpose.
  • Investments the player cannot feel. A 2 percent bonus is real in a spreadsheet and invisible in play. Make the change show up in the next loop: in numbers on screen, in speed, in size.
  • A first loop that is too long. If the first upgrade is ten minutes away, many players will not stay to find out that there is a loop at all.
  • Investment that deletes the action. An upgrade that picks berries for you removes the part that was fun. Idle games do this on purpose; in most other games it empties the seconds loop.
  • Designing only the big loop. A clever upgrade tree on top of a dull action tends to feel like a chore. Prototype the seconds loop first and make sure it is fun alone.

The manipulative version. The same structure can be tuned against the player. A compulsion loop is a loop built to keep people repeating it whether or not they enjoy it, often with waiting timers, energy limits and unpredictable rewards that pull them back. Many free-to-play games use these on purpose, sometimes to sell ways to skip the wait. If your loop only works because the player feels they will lose something by stopping, that is worth noticing and saying honestly to yourself.

When not to build an investment step. Not every game needs an economy. In an arcade game, a puzzle game or a short story game, the loop is often action and reward alone, and what the player invests is their own skill or understanding. Adding upgrades there can blur a clean challenge. Roguelikes often reset most investment at the end of each run, so a run is the loop and only a little carries over.

In real games

Jaime Griesemer, a designer on Bungie's Halo games, is widely credited with the phrase "thirty seconds of fun": a short combat loop that is enjoyable on its own and is then repeated across different weapons, enemies and places. It is a description of the seconds-to-minutes loop.

Stardew Valley's farming follows the shape of the demo: plant, water, harvest, sell, then buy seeds, tools and buildings that change the next season. Action role-playing games in the style of Diablo run a fight, loot, equip loop: better gear lets the player take on harder monsters, which drop better gear.

Your turn (15 minutes)

Write your game's loop as one sentence at each of the three scales: "I ___ to get ___ so I can ___, which ___." If a sentence cannot get back to its first verb, find the missing investment. Then time one minutes loop in your game with a stopwatch and count how many loops until the first thing you can buy. You are done when you have three closed sentences and two numbers, and you know which of them you want to change.

Takeaways

  • A core loop is action, reward and investment, and the investment is what closes it.
  • Loops nest by time: the reward of a seconds loop is one step of a minutes loop, which feeds a session loop.
  • Each investment should change the next loop enough for the player to feel it.
  • Make the smallest loop fun first; a good economy rarely saves a dull action.
  • The same structure can be tuned to compel instead of entertain. Notice when yours does.
