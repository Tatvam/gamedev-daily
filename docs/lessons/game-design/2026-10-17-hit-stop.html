Hit stop: freezing time to make hits land

How pausing the attacker and the target for a few frames on impact makes hits feel heavy, how long to freeze, and when not to.

Your sword swing has a good animation, a sound and knockback, and it still feels like waving a stick through fog. The blade passes through the enemy in one frame and the contact is gone before the eye finds it. The usual fix is not more effects. It is stopping time, very briefly.

A hit you can see is a hit you can feel

Hit stop (also called hit freeze, hitlag or hit pause) holds the attacker and the target still for a short moment at the instant of contact. Then everything carries on as if nothing had happened: the swing finishes, the target flies back.

Why does stopping make a hit feel stronger? A few reasons tend to work together:

  • It gives the eye time. A fast swing is only in contact with its target for a frame or two. The freeze turns that frame into a pose the player can actually see: blade touching body.
  • It suggests resistance. A real weapon slows when it meets something solid. A sudden stop reads as "that was heavy".
  • It makes the release sharper. Motion that starts from a dead stop looks faster than motion that was already going. The knockback after the freeze pops.

What actually freezes

The freeze is a countdown, usually measured in seconds or frames. While it runs, the game skips the update for the characters involved: no animation timers, no movement, no physics. Drawing still happens every frame, so the screen keeps showing the frozen pose. Most games still read input during the freeze and act on it afterwards.

How long?

Shorter than you might think. At 60 frames per second one frame is about 16.7 milliseconds, so:

  • Light hits: about 3 to 5 frames, 50 to 80 milliseconds.
  • Heavy hits: about 6 to 12 frames, 100 to 200 milliseconds.
  • Rare finishers: longer, sometimes paired with a camera zoom or slow motion, because it happens once per fight.

The useful pattern is that the freeze scales with the strength of the hit. Then the length of the pause itself tells the player how hard they hit, before any number appears.

Starting points to tune

Light hit 80 ms, heavy hit twice that. A tiny shake of the target during the freeze, 2 to 3 pixels, so it does not look like the game has crashed. These are numbers to begin from, not rules: a fast action game will want less, a slow, heavy one more.

Try it

Hit the dummy a few times with hit stop off, then switch it on and hit again. Try both a light and a heavy strike. Then drag the freeze slider to 200 milliseconds, and down to 20. Turn on quarter speed to see the frozen frames clearly on the timeline below the scene.

With hit stop off, swing and reaction blur into one event. At 60 to 100 milliseconds the contact snaps into place. Past about 150 milliseconds on a light strike the game starts to feel sticky, as if it lagged.

The code

This is the demo's logic in LÖVE, with the same names and default numbers. The important part is the first block of love.update: while the freeze counts down, the rest of the update does not run. When it runs out partway through a frame, the leftover time is used, so freezes stay accurate at any frame rate.

local STARTUP, ACTIVE, RECOVERY = 0.08, 0.06, 0.20  -- seconds
local HIT_AT = STARTUP + ACTIVE / 2   -- blade meets the dummy mid-swing
local HITSTOP_LIGHT, HITSTOP_HEAVY = 0.08, 0.16
local KICK_LIGHT, KICK_HEAVY = 5, 9   -- dummy spin, radians per second
local SPRING, DAMPING = 120, 10
local SHAKE, SHAKE_HZ = 3, 30         -- pixels, wobbles per second

local hitstop, freezeLength = 0, 0
local attack, queued = nil, nil
local dummy = { angle = 0, spin = 0, kick = 0 }

local function startAttack(heavy)
  if attack then queued = heavy return end   -- remember the press
  attack = { t = 0, heavy = heavy, hit = false }
end

function love.keypressed(key)
  if key == "j" or key == "space" then startAttack(false) end
  if key == "k" then startAttack(true) end
end

local function onHit(heavy)
  hitstop = heavy and HITSTOP_HEAVY or HITSTOP_LIGHT
  freezeLength = hitstop
  dummy.kick = heavy and KICK_HEAVY or KICK_LIGHT  -- applied after the freeze
end

function love.update(dt)
  if hitstop > 0 then
    hitstop = hitstop - dt
    if hitstop > 0 then return end   -- frozen: skip everything below
    dt = -hitstop                    -- use the rest of this frame
    hitstop = 0
  end
  dummy.spin = dummy.spin + dummy.kick
  dummy.kick = 0
  if attack then
    attack.t = attack.t + dt
    if not attack.hit and attack.t >= HIT_AT then
      attack.hit = true
      onHit(attack.heavy)
    end
    if attack.t >= STARTUP + ACTIVE + RECOVERY then
      attack = nil
      if queued ~= nil then startAttack(queued) queued = nil end
    end
  end
  if hitstop > 0 then return end     -- a hit this frame: freeze now
  dummy.spin = dummy.spin + (-SPRING * dummy.angle - DAMPING * dummy.spin) * dt
  dummy.angle = dummy.angle + dummy.spin * dt
end

function love.draw()
  local shakeX = 0
  if hitstop > 0 then   -- small, fading wobble on the target only
    shakeX = SHAKE * (hitstop / freezeLength) * math.sin(hitstop * 2 * math.pi * SHAKE_HZ)
  end
  drawPlayer(attack)              -- your own drawing functions
  drawDummy(dummy.angle, shakeX)
end

Set both freeze lengths to 0 to get the version without hit stop. The kick waits in dummy.kick, so the dummy reacts only after the freeze, as in the diagram.

Pitfalls

  • Freezing the whole game when you should not. Stopping everything is fine for a two-character duel. With many enemies, or other players, freeze only the attacker and the target, and let the rest of the world, the music and the interface keep going.
  • Dropping input during the freeze. If presses made during the pause are ignored, combos feel unresponsive. Read input as usual and act on it when the freeze ends.
  • Stacking on fast multi-hit attacks. A flurry of ten hits with 80 milliseconds each turns into almost a second of stutter. Use much shorter freezes for each hit of a flurry, or freeze only on the last one.
  • One length for every hit. If a jab and a finisher freeze for the same time, the pause stops carrying information. Scale it with damage or attack weight.
  • A perfectly still freeze. A long freeze with nothing moving can look like a frame rate hitch. A small shake of the target or a spark says it is on purpose.
  • Timers that keep running. A cooldown or combo window that counts real time quietly shrinks during the freeze. Freeze all gameplay timers through the same check.

When not to use hit stop

Rhythm games, where the music cannot pause. Shooters with rapid fire, where every bullet would stutter the screen; there, hit stop tends to be kept for kills or heavy weapons. Bullet-dense games, where a freeze makes it harder to read the other threats on screen. And anything competitive online, where a local-only freeze puts players out of step unless the freeze is part of the shared game rules.

In real games

Fighting games and character action games have used hit stop for decades. The Super Smash Bros. series calls it hitlag. According to the SmashWiki article on the topic, it freezes both the attacker and the character who was hit, and its length is worked out from the attack's damage, with a different formula in each game. Players there can also nudge their character slightly during the freeze, a technique the community calls Smash directional influence.

Masahiro Sakurai, director of the Smash series, covers hit stop in his YouTube series Masahiro Sakurai on Creating Games.

Your turn (15 minutes)

Find the one place in your game where the player hits something. Add a hitstop timer and the early return at the top of the update for the attacker and the target, set to 80 milliseconds. Add a key that toggles it.

Play ten hits with it off and ten with it on. Then give your strongest attack twice the freeze. You are done when the strong attack feels heavier than the weak one with your eyes closed to the damage numbers, and a fast series of presses never feels like the game ignored you.

Takeaways

  • Hit stop freezes the attacker and the target for a few frames at contact, so the player can see and feel the hit.
  • Start around 80 milliseconds for light hits and scale it up with the strength of the hit.
  • Delay the reaction, do not skip it: knockback starts after the freeze.
  • Keep reading input during the freeze, and freeze only what is part of the hit.
  • Skip or shrink it for rapid fire, rhythm games and busy screens, where pauses read as stutter.
