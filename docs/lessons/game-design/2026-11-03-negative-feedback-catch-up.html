Negative feedback loops: catch-up and rubber banding

How catch-up mechanics keep a race close by helping whoever is behind, how to tune their strength, and what they cost the best player.

You crash on the first corner of a racing game and the pack is gone. Nothing you do for three laps changes your place, so you quit. Or you drive a perfect race and the computer cars stay glued to your bumper anyway, and you suspect the game is cheating.

Both feelings come from the same design choice: how strongly the game pulls the racers back together.

A loop that pushes back

In the last lesson, a positive feedback loop made success produce more success, so gaps grew. A negative feedback loop, also called a balancing loop, does the reverse: the further things drift from even, the harder the game pushes back. "Negative" does not mean bad, only that the loop opposes the current direction.

In games, these loops usually appear as catch-up mechanics: rules that help whoever is behind, or hinder whoever is ahead. When a racing game quietly speeds up cars that fall behind and slows cars that pull ahead, players call it rubber banding, because the racers act as if tied together with elastic.

The model in the demo

Four runners race 200 metres. Their top speeds are 8.4, 8.0, 7.8 and 7.6 metres per second. Every half second each one gets a new random pace between 92 and 105 percent of top speed, and a 5 percent chance of a stumble that drops it to 20 percent for that half second.

The catch-up rule is one line. Each runner gets a speed bonus for every metre it is behind the leader, capped at 30 percent:

boost = math.min(gap * STRENGTH, MAX_BOOST)
speed = top * pace * (1 + boost)

With a strength of 2 percent per metre, a runner 5 metres back runs 10 percent faster, and the leader gets nothing. On its own the rule never carries anyone past the leader, because the boost fades to zero as the gap closes. It squeezes the pack together, and then luck decides more of the order.

What the player feels

Without catch-up, one early mistake can end your race, and a good lead turns the rest into a lonely drive. Fair, but often dull. With mild catch-up, a crash costs places but not hope, and the leader always has someone close behind. With strong catch-up, the leader feels punished for driving well, and the first half stops mattering.

Starting points to tune

Express the boost as a share of speed per unit of gap, then cap it. In this model, 1 to 2 percent per metre with a 30 percent cap keeps the pack close without making the fastest runner a coin flip. Your units differ, so measure the spread and how often the best player wins instead of copying numbers. These are starting points, not rules.

Visible or hidden

Catch-up shown openly, such as better items for players at the back, is a rule players can learn and argue about. Hidden rubber banding is different: the player believes they won a close race by skill when the game manufactured the closeness. Many players accept that in a casual racer. Discovered in a game they took seriously, it tends to feel like cheating.

Try it

Run one race with catch-up off, holding the whole way: you win easily and the graph lines spread apart. Then switch catch-up on and run again. Then press Crash halfway through a race, once with catch-up off and once with it on. Finally, set "applies to" to rivals only and notice how it feels to lead.

The code

The demo's race in LÖVE, with the same numbers. Hold Space to run. The marked lines are the whole negative feedback loop. The demo also adds the crash button and a fixed step, which are left out here.

local LENGTH = 200        -- metres
local STRENGTH = 0.02     -- 2% extra speed per metre behind
local MAX_BOOST = 0.3     -- never more than 30% faster
local RIVALS_ONLY = false -- true: the player never gets help

local racers = {
  { name = "You", top = 8.4, dist = 0, pace = 0, player = true },
  { name = "Fox", top = 8.0, dist = 0, pace = 1 },
  { name = "Owl", top = 7.8, dist = 0, pace = 1 },
  { name = "Elk", top = 7.6, dist = 0, pace = 1 },
}
local paceTimer = 0

local function leaderDistance()
  local best = 0
  for _, r in ipairs(racers) do
    if r.dist > best then best = r.dist end
  end
  return best
end

local function newPace()
  if love.math.random() < 0.05 then return 0.2 end -- a stumble
  return 0.92 + 0.13 * love.math.random()
end

function love.update(dt)
  local lead = leaderDistance()
  if lead >= LENGTH then return end               -- race over
  paceTimer = paceTimer - dt
  if paceTimer <= 0 then                           -- new pace every 0.5 s
    paceTimer = paceTimer + 0.5
    for _, r in ipairs(racers) do
      if not r.player then r.pace = newPace() end
    end
  end
  local you = racers[1]
  local target = love.keyboard.isDown("space") and 1 or 0
  you.pace = you.pace + (target - you.pace) * math.min(dt * 4, 1)
  for _, r in ipairs(racers) do
    local boost = 0
    if not (RIVALS_ONLY and r.player) then
      boost = math.min((lead - r.dist) * STRENGTH, MAX_BOOST)
    end
    r.dist = r.dist + r.top * r.pace * (1 + boost) * dt
  end
end

function love.draw()
  for i, r in ipairs(racers) do
    local y = 40 * i
    love.graphics.print(r.name, 10, y)
    love.graphics.rectangle("fill", 60 + r.dist * 3, y, 12, 12)
  end
end

To brake the front instead of boosting the back, multiply the leader's speed by a little less than 1, for example 0.95. To build "better luck at the back", choose from a stronger list of random items the further back a player is.

Pitfalls

  • Boosting past the leader's top speed by a lot. A trailing car that suddenly outruns the best car breaks the fiction. Cap the boost so it looks like a good run, not a jet engine.
  • Help that only goes to the computer. Rivals-only rubber banding is the version players complain about most. Keep it weak, or help the player when they fall behind too.
  • Making the lead worthless. If the halfway leader wins no more often than anyone else, early skill means nothing and players learn to coast.
  • Steps instead of slopes. A rule like "+20% if more than 10 metres behind" makes racers bounce on the threshold. A boost that grows smoothly with the gap settles more gently.
  • Hiding it to fake skill. Using secret catch-up so players feel more skilled than they are, or so a losing player keeps playing longer, is manipulation. You should be able to explain the rule to a player without embarrassment.

When not to use it. Time trials, speedruns, ranked competitive play and score chasing are about measuring skill, and catch-up blurs the measurement. It is also wrong where a big lead is the reward the player worked for, such as outrunning a boss.

In real games

Mario Kart is the best-known example of open catch-up: the items a racer can get from an item box depend on their position, and racers near the back receive stronger ones. The Spiny Shell, introduced in Mario Kart 64, chases down whoever is in first place.

Computer-controlled opponents in arcade racing games commonly use hidden rubber banding of the kind in this demo, which is why "rubber band AI" is a familiar complaint among players.

Outside video games, golf handicaps let players of different skill compete on a close score, and drafts in American professional sports leagues give the weakest teams early picks of new players.

Takeaways

  • A negative feedback loop pushes back toward even: the further behind, the more help.
  • Catch-up keeps contests close and makes comebacks possible, so the second half still matters.
  • It costs fairness: the best player wins less often, especially when only their opponents get help.
  • Make the help grow with the gap, cap it, and measure both the spread and how often the leader still wins.
  • Prefer catch-up players can see. Hidden rubber banding feels like cheating once found.
