Signposting: guiding players with light, lines and landmarks

How light, colour, lines, landmarks and pickup trails guide players through a level without a map marker, and what each cue is good at.

You built a level that you can walk through in forty seconds. Your first tester spends four minutes in it, walks the same dead end three times, and finally asks "where am I supposed to go?" You know the way because you built it. The tester has only what the screen shows them.

The quick fix is a glowing arrow. This lesson is about the other fix: making the level itself point the way.

Let the world do the pointing

Signposting means guiding the player with things that belong in the game world: light, colour, shapes, sight lines and objects. The alternative is a waypoint marker, an interface icon that always points at the goal. Markers are reliable, but they tend to change how people play. Players start watching the arrow instead of the world, and the level becomes a corridor between two icons.

Signposting works because people already read spaces this way. We tend to walk toward bright openings, follow edges and paths with our eyes, and steer by tall things we can see from far away. A level designer arranges those things on purpose.

Five common cues

  • Light. In a dark space, players tend to move toward the brightest opening. A lit doorway at the end of a corridor is an invitation.
  • Colour. A colour used only for the route, or only for things you can interact with, becomes a language. It only works if you do not also use it for decoration.
  • Lines. Leading lines are edges in the scene that pull the eye in a direction: a pipe along a wall, a crack in the floor, a row of lamps, the edge of a road.
  • Landmarks. A landmark is a large, unique object visible from much of the level, such as a tower, a mountain or a beam of light. It tells players where they are and which way the goal lies.
  • Pickups. A trail of coins or other small rewards, sometimes called breadcrumbs, marks a route step by step.

Each cue answers a different question

These cues are not interchangeable. Each works at a different distance and answers a different question. A landmark seen across the level answers "which direction?" but says nothing about which corridor gets you there. A pickup trail answers "which way at this junction?" but you only see it up close. Light sits in between: it says "this opening is important", but only when the player has a clear line of sight to it.

Contrast is what makes a cue visible

A cue only stands out against its surroundings. A lit door in a dark room pulls hard. The same door in a brightly lit room is just a door. A yellow ledge means "climb here" only if nothing else in the level is yellow. This is why signposting is a whole-level decision: every light and colour you add elsewhere makes your cues weaker.

Some starting numbers to tune from, not rules:

  • Pickup spacing: close enough that the next one is visible from the last. In the demo below that is one pickup every 3 tiles with a 2.5 tile light radius.
  • Landmark placement: visible from most of the play space, and at or beyond the goal, so that walking toward it is never wrong for long.
  • Light: put the brightest spot at the end of a sight line, such as a straight corridor or a doorway the player faces on entry. Light around a corner does nothing until the player turns the corner.

Rule of thumb

Use the weakest cue that works for most players, and keep a stronger one ready for players who are lost. Silence is not neutral: a junction with no cue at all is a coin toss.

The code

The world drawing is up to your engine. What is worth copying is the bookkeeping: finding the route so you can lay a pickup trail along it, checking whether the player can see a light, and measuring a run the way the demo does. The highlighted lines place the trail and record the moment the exit was first seen.

local TILE = 24
local CRUMB_EVERY = 3            -- tiles between pickups on the trail
local LANTERN = 2.5 * TILE       -- reach of the player's own light, px

-- Set up by your level loader. map[row][col] is true for a wall, false for floor.
local map, path, exitTile, player, cues
local run = { started = false, done = false, time = 0, walked = 0 }

local function isWall(col, row)
  local r = map[row]
  return r == nil or r[col] ~= false
end

local function centre(tile)    -- tile = { col, row }, numbered from 1
  return (tile[1] - 0.5) * TILE, (tile[2] - 0.5) * TILE
end

-- Breadth-first search: the shortest list of tiles from start to goal.
local function shortestPath(start, goal)
  local function key(c, r) return r * 1000 + c end
  local parent = { [key(start[1], start[2])] = false }
  local queue, head = { start }, 1
  while head <= #queue do
    local c, r = queue[head][1], queue[head][2]
    head = head + 1
    for _, d in ipairs({ { 1, 0 }, { -1, 0 }, { 0, 1 }, { 0, -1 } }) do
      local nc, nr = c + d[1], r + d[2]
      if not isWall(nc, nr) and parent[key(nc, nr)] == nil then
        parent[key(nc, nr)] = key(c, r)
        queue[#queue + 1] = { nc, nr }
      end
    end
  end
  local result, k = {}, key(goal[1], goal[2])
  while k do
    table.insert(result, 1, { k % 1000, math.floor(k / 1000) })
    k = parent[k]
  end
  return result
end

local function placeCrumbs(route)
  local crumbs = {}
  for i = 3, #route - 2, CRUMB_EVERY do
    local x, y = centre(route[i])
    crumbs[#crumbs + 1] = { x = x, y = y, taken = false }
  end
  return crumbs
end

-- A light is only a cue if nothing blocks the line to it.
local function canSee(x1, y1, x2, y2)
  local steps = math.ceil(math.sqrt((x2 - x1) ^ 2 + (y2 - y1) ^ 2) / 6)
  for i = 1, steps - 1 do
    local x = x1 + (x2 - x1) * i / steps
    local y = y1 + (y2 - y1) * i / steps
    if isWall(math.floor(x / TILE) + 1, math.floor(y / TILE) + 1) then return false end
  end
  return true
end

local function dist(ax, ay, bx, by)
  return math.sqrt((bx - ax) ^ 2 + (by - ay) ^ 2)
end

function love.update(dt)
  local ox, oy = player.x, player.y
  movePlayer(dt)                 -- your input and collision code
  local moved = dist(ox, oy, player.x, player.y)
  if moved > 0 then run.started = true end
  if not run.started or run.done then return end

  run.time = run.time + dt
  run.walked = run.walked + moved
  local ex, ey = centre(exitTile)
  local d = dist(player.x, player.y, ex, ey)
  local lit = cues.litExit and canSee(player.x, player.y, ex, ey)
  if run.firstSaw == nil and (d < LANTERN - TILE / 2 or lit) then run.firstSaw = run.time end
  if d < TILE / 2 then
    run.done = true
    run.ratio = run.walked / ((#path - 1) * TILE)   -- 1.0 = the shortest route
  end
end

Build the level, then call path = shortestPath(startTile, exitTile) and placeCrumbs(path) once. Log run.firstSaw and run.ratio from playtests: a high ratio with an early first sighting means players saw the goal but could not work out how to reach it.

Pitfalls

  • Cues that compete. If three doors are lit, light means nothing. Decide what each cue means and keep it for that job.
  • Lights out of sight. A light placed around a corner, or behind the player as they enter, does nothing. Check what the player sees from the doorway, not from the editor's camera.
  • A landmark is not a route. Players walk toward a tower and hit a wall. Where the direct line is blocked, add a closer cue that shows the way around.
  • A trail that leaves no choice. Pickups pull hard because they are rewards. A trail through every junction turns exploration into following, and players may skip side areas you wanted them to find.
  • Overdoing it. Painting every climbable ledge one loud colour works, but some players find it patronising, as recent online arguments about "yellow paint" show. Treat it as a strength to tune, not an on or off choice.
  • Colour alone. A cue that relies only on hue can be invisible to colour-blind players. Pair colour with brightness, shape or motion.

When not to use it

Getting a little lost is the point of some games. Exploration games tend to want players to make their own mental map, and horror games often use uncertainty on purpose. Even there, a landmark that helps players stay oriented is usually welcome. Strong signposting also matters less in short, linear levels where there is only one way forward.

In real games

In Journey (2012), a mountain with a beam of light at its peak is visible from the start and stays in view through much of the game. It is a landmark used as the goal of the whole journey.

Mirror's Edge (2008) colours many surfaces and objects the runner can use, often red, against a mostly white city. The game calls this Runner Vision. It is colour used as a route language, and the game lets players turn it off.

The Dead Space games sit closer to a waypoint marker. A button draws a line along the floor toward the current objective. It is part of the world, but it appears only when the player asks for it.

Many platformers, including the Mario series, place lines of coins to suggest where to jump or where a hidden path lies.

The idea is older than video games. Walt Disney is widely reported to have called a tall landmark that draws visitors toward it a "weenie". The castle at the end of Main Street in his parks is the usual example.

Take a screenshot of the first view a player gets of one room in your game. Shrink it to about 100 pixels wide, or squint at it. Can you still tell where the exit is? If not, add one cue: brighten the exit, darken the dead ends, or run a line toward the door.

Then watch one person play the room without telling them anything. Note each spot where they stop or turn back. You are done when they leave the room without stopping at a junction, or when you have added one cue at each spot where they did.

Takeaways

  • Signposting guides with things in the world, such as light, colour, lines, landmarks and pickups, instead of interface markers.
  • Each cue works at a different distance: landmarks for direction, light and lines for the route through a room, pickups for the next step.
  • A cue is only as strong as its contrast with the rest of the level, so reserve your guiding colours and lights.
  • Light needs a line of sight. Put it where the player is already looking.
  • Use the weakest cue that works, and keep a stronger one for players who are lost.
