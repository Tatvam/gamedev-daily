Tilemaps: grids of numbers, chunks and autotiling

How a tilemap stores a level as a grid of small tile numbers, how neighbour rules pick edge tiles, and why engines redraw it in chunks.

You build a level out of a thousand individual sprite objects, one per square of floor. The scene takes seconds to open, the editor crawls, and changing the shoreline of a lake means hand-picking the right corner piece for every square. Tilemaps exist so that none of this happens.

A level is a grid of small numbers

A tilemap is a grid in which each cell stores a small number, the tile index. The number does not hold a picture. It says which picture to use from a tileset, a collection of equally sized images usually packed into one texture. The level is the grid; the art lives once, in the tileset.

This is cheap in three ways. Memory: a 1000 by 1000 map is a million numbers, a few megabytes, where a million objects would each carry a transform, a name and engine bookkeeping. Drawing: every tile of a layer shares one texture, so the batcher from the previous lesson merges them into few draw calls. Lookup: finding the tile under a point is a division, not a search. The cell is floor(position / cell_size), and the cell's corner in the world is cell * cell_size.

Who owns what

The tilemap owns the grid of numbers. The tileset is a shared asset that many maps can use, so editing a tile's image changes it in every level at once. Your code owns neither the drawing nor the meshes: you write numbers into cells, and the engine turns them into geometry later, before the frame is drawn.

Autotiling: let the neighbours choose the tile

A ground area looks right only if its border cells use edge pieces: a tile with a shore on the left side, one with a shore on top, and so on. Choosing those by hand is slow and breaks every time you change the shape. Autotiling picks the piece from the cell's neighbours instead.

The simplest version looks at four neighbours. Each one is worth a power of two: north 1, east 2, south 4, west 8. Add up the values of the neighbours that are ground and you get a number from 0 to 15, called the mask. Draw sixteen tiles in that order, each with an edge on the sides that have no ground, and the mask is the tile index.

There is one consequence to keep in mind: changing one cell changes the mask of its four neighbours, so up to five cells can need a different tile after a single edit.

Four neighbours cannot see diagonals, so an inside corner, where ground continues on both sides but the diagonal cell is empty, gets no notch. Sets that also look at the four diagonal neighbours fix this. They need more art: the common "blob" layout uses 47 distinct tiles.

Chunks: redraw only the part that changed

Turning cells into geometry costs time, so engines group the map into square chunks of cells and build each chunk's geometry once. Drawing a chunk is then one cheap call. When a cell changes, only its chunk is marked dirty and rebuilt. An edit next to a chunk border can dirty two chunks, because a neighbour's tile changes too.

Chunk size is a trade-off. Large chunks mean fewer draw calls but more work per edit, and culling (the earlier lesson on skipping what the camera cannot see) can only throw away whole chunks. Small chunks rebuild quickly but add calls.

How Godot and Unity express it

Godot 4.3 and later uses one TileMapLayer node per layer; the older TileMap node with several layers inside is deprecated from 4.3. A TileSet resource holds sources, usually a TileSetAtlasSource cut from one texture. A cell is set with set_cell(coords, source_id, atlas_coords), and points are converted with local_to_map and map_to_local. Autotiling is built in as terrains: in the TileSet editor you mark which sides and corners of each tile belong to a terrain, then paint with the Terrains tab or call set_cells_terrain_connect. Godot's chunks are called rendering quadrants, sized by rendering_quadrant_size (16 cells by default), and cell changes are applied in a batch at the end of the frame rather than on each call.

Unity (2022 LTS and Unity 6, 2D Tilemap package) uses a Grid component on a parent with one child per layer holding a Tilemap and a TilemapRenderer. Cells hold references to tile assets (TileBase, usually Tile, which are ScriptableObjects) and are set with SetTile(Vector3Int, TileBase); WorldToCell on the Grid converts a point. The TilemapRenderer's Chunk mode draws tiles in grouped chunks; Individual mode draws each tile on its own so that it can sort among other sprites, for example characters walking behind trees. Rule-based autotiling comes from the Rule Tile in the separate 2D Tilemap Extras package, where each rule matches a pattern of neighbours.

Try it

Click or touch an empty cell and drag to paint ground; start on ground to erase. With the keyboard, click the map or tab to it, move the cursor with the arrow keys, and press Space to flip a cell. Turn on Show tile indices and watch the numbers of the neighbours change as you paint next to them. Then turn autotiling off. Finally paint along a thick chunk border and compare how many chunks one edit rebuilds.

The code

A LÖVE 11 program with the demo's numbers: a 24 by 16 map, 8 by 8 chunks, the same starting islands and the same mask (north 1, east 2, south 4, west 8). Each chunk is cached in a canvas and redrawn only when it is dirty. Left mouse paints, right mouse erases, A toggles autotiling, and the bottom line counts chunk rebuilds.

-- main.lua for LÖVE 11. Left mouse paints ground, right mouse erases,
-- A toggles autotiling. The map is 24 by 16 cells, cached in 8 by 8 chunks.
local COLS, ROWS, CHUNK, CELL = 24, 16, 8, 32
local map = {}       -- map[y][x]: 1 is ground, 0 is empty. This is the whole level.
local chunks = {}    -- chunks[cy][cx] = { canvas = ..., dirty = true or false }
local autotile = true
local rebuilds = 0

local function ground(x, y)
  if x < 1 or y < 1 or x > COLS or y > ROWS then return false end
  return map[y][x] == 1
end

-- four neighbour bits: north 1, east 2, south 4, west 8
local function tileIndex(x, y)
  if not autotile then return 15 end
  local index = 0
  if ground(x, y - 1) then index = index + 1 end
  if ground(x + 1, y) then index = index + 2 end
  if ground(x, y + 1) then index = index + 4 end
  if ground(x - 1, y) then index = index + 8 end
  return index
end

local function has(index, bit)   -- is that neighbour ground?
  return math.floor(index / bit) % 2 == 1
end

local function drawTile(index, px, py)
  love.graphics.setColor(0.35, 0.6, 0.3)
  love.graphics.rectangle("fill", px, py, CELL, CELL)
  love.graphics.setColor(0.15, 0.3, 0.12)   -- an edge on each side with no ground
  if not has(index, 1) then love.graphics.rectangle("fill", px, py, CELL, 4) end
  if not has(index, 2) then love.graphics.rectangle("fill", px + CELL - 4, py, 4, CELL) end
  if not has(index, 4) then love.graphics.rectangle("fill", px, py + CELL - 4, CELL, 4) end
  if not has(index, 8) then love.graphics.rectangle("fill", px, py, 4, CELL) end
end

local function markDirty(x, y)
  if x < 1 or y < 1 or x > COLS or y > ROWS then return end
  local cx = math.floor((x - 1) / CHUNK) + 1
  local cy = math.floor((y - 1) / CHUNK) + 1
  chunks[cy][cx].dirty = true
end

local function setCell(x, y, value)
  if x < 1 or y < 1 or x > COLS or y > ROWS or map[y][x] == value then return end
  map[y][x] = value
  markDirty(x, y)
  if autotile then   -- the four neighbours may need a different tile now
    markDirty(x, y - 1)
    markDirty(x + 1, y)
    markDirty(x, y + 1)
    markDirty(x - 1, y)
  end
end

local function rebuildChunk(chunk, cx, cy)
  love.graphics.setCanvas(chunk.canvas)
  love.graphics.clear(0, 0, 0, 0)
  for y = (cy - 1) * CHUNK + 1, cy * CHUNK do
    for x = (cx - 1) * CHUNK + 1, cx * CHUNK do
      if map[y][x] == 1 then
        drawTile(tileIndex(x, y), (x - 1) % CHUNK * CELL, (y - 1) % CHUNK * CELL)
      end
    end
  end
  love.graphics.setCanvas()
  chunk.dirty = false
  rebuilds = rebuilds + 1
end

local function startTile(x, y)   -- two islands, a bridge and a pond
  local a = x >= 4 and x <= 11 and y >= 4 and y <= 10
  local b = x >= 14 and x <= 20 and y >= 7 and y <= 13
  local bridge = x >= 12 and x <= 13 and y >= 8 and y <= 9
  local pond = x >= 7 and x <= 8 and y >= 6 and y <= 7
  if (a or b or bridge) and not pond then return 1 end
  return 0
end

function love.load()
  for y = 1, ROWS do
    map[y] = {}
    for x = 1, COLS do map[y][x] = startTile(x, y) end
  end
  for cy = 1, ROWS / CHUNK do
    chunks[cy] = {}
    for cx = 1, COLS / CHUNK do
      chunks[cy][cx] = { canvas = love.graphics.newCanvas(CHUNK * CELL, CHUNK * CELL), dirty = true }
    end
  end
end

function love.keypressed(key)
  if key == "a" then
    autotile = not autotile
    for cy = 1, #chunks do
      for cx = 1, #chunks[cy] do chunks[cy][cx].dirty = true end
    end
  end
end

function love.update(dt)
  local x = math.floor(love.mouse.getX() / CELL) + 1
  local y = math.floor(love.mouse.getY() / CELL) + 1
  if love.mouse.isDown(1) then setCell(x, y, 1) end
  if love.mouse.isDown(2) then setCell(x, y, 0) end
end

function love.draw()
  for cy = 1, #chunks do
    for cx = 1, #chunks[cy] do
      local chunk = chunks[cy][cx]
      if chunk.dirty then rebuildChunk(chunk, cx, cy) end
      love.graphics.setColor(1, 1, 1)
      love.graphics.draw(chunk.canvas, (cx - 1) * CHUNK * CELL, (cy - 1) * CHUNK * CELL)
    end
  end
  love.graphics.setColor(1, 1, 1)
  love.graphics.print("autotile " .. tostring(autotile) .. "   chunk rebuilds " .. rebuilds, 10, 530)
end
# autotile_layer.gd for Godot 4.3 or later (TileMapLayer arrived in 4.3).
# Add a TileMapLayer node to a new 2D scene, attach this script and run.
# Left mouse paints ground, right mouse erases. The tileset is generated in code.
extends TileMapLayer

const COLS := 24
const ROWS := 16
const CELL := 32
# north, east, south, west give bits 1, 2, 4, 8. Godot's y axis points down.
const NEIGHBOURS := [Vector2i(0, -1), Vector2i(1, 0), Vector2i(0, 1), Vector2i(-1, 0)]
var source_id := 0

func _ready() -> void:
    var img := Image.create(CELL * 16, CELL, false, Image.FORMAT_RGBA8)
    for index in 16:
        for x in CELL:
            for y in CELL:
                var edge := ((index & 1) == 0 and y < 4) or ((index & 2) == 0 and x >= CELL - 4) \
                    or ((index & 4) == 0 and y >= CELL - 4) or ((index & 8) == 0 and x < 4)
                img.set_pixel(index * CELL + x, y, Color(0.15, 0.3, 0.12) if edge else Color(0.35, 0.6, 0.3))
    var source := TileSetAtlasSource.new()
    source.texture = ImageTexture.create_from_image(img)
    source.texture_region_size = Vector2i(CELL, CELL)
    for index in 16:
        source.create_tile(Vector2i(index, 0))   # tile index = x in the atlas
    tile_set = TileSet.new()
    tile_set.tile_size = Vector2i(CELL, CELL)
    source_id = tile_set.add_source(source)

func is_ground(cell: Vector2i) -> bool:
    return get_cell_source_id(cell) != -1

func refresh(cell: Vector2i) -> void:
    if not is_ground(cell):
        return
    var index := 0
    for i in 4:
        if is_ground(cell + NEIGHBOURS[i]):
            index += 1 << i
    set_cell(cell, source_id, Vector2i(index, 0))

func paint(cell: Vector2i, ground: bool) -> void:
    if cell.x < 0 or cell.y < 0 or cell.x >= COLS or cell.y >= ROWS or is_ground(cell) == ground:
        return
    if ground:
        set_cell(cell, source_id, Vector2i(15, 0))   # corrected by refresh below
    else:
        erase_cell(cell)
    refresh(cell)
    for offset in NEIGHBOURS:
        refresh(cell + offset)

func _process(_delta: float) -> void:
    var cell := local_to_map(get_local_mouse_position())
    if Input.is_mouse_button_pressed(MOUSE_BUTTON_LEFT):
        paint(cell, true)
    elif Input.is_mouse_button_pressed(MOUSE_BUTTON_RIGHT):
        paint(cell, false)
// AutotileMap.cs. Unity 2022 LTS or Unity 6, 2D template (it includes the Tilemap package).
// Add to an empty GameObject at the origin and press Play. Left mouse paints, right erases.
// Uses the Input Manager; if Active Input Handling is the Input System package only,
// switch it to Both.
using UnityEngine;
using UnityEngine.Tilemaps;

public class AutotileMap : MonoBehaviour
{
    const int Cols = 24, Rows = 16, Cell = 32;
    // north, east, south, west give bits 1, 2, 4, 8. Unity's y axis points up.
    static readonly Vector3Int[] neighbours = {
        Vector3Int.up, Vector3Int.right, Vector3Int.down, Vector3Int.left };
    readonly Tile[] tiles = new Tile[16];
    Grid grid;
    Tilemap map;

    void Start()
    {
        var tex = new Texture2D(Cell * 16, Cell);
        tex.filterMode = FilterMode.Point;
        var grass = new Color(0.35f, 0.6f, 0.3f);
        var edge = new Color(0.15f, 0.3f, 0.12f);
        for (int i = 0; i < 16; i++)
            for (int x = 0; x < Cell; x++)
                for (int y = 0; y < Cell; y++)   // y = 0 is the bottom row of a texture
                {
                    bool e = ((i & 1) == 0 && y >= Cell - 4) || ((i & 2) == 0 && x >= Cell - 4)
                          || ((i & 4) == 0 && y < 4) || ((i & 8) == 0 && x < 4);
                    tex.SetPixel(i * Cell + x, y, e ? edge : grass);
                }
        tex.Apply();
        for (int i = 0; i < 16; i++)
        {
            tiles[i] = ScriptableObject.CreateInstance<Tile>();
            tiles[i].sprite = Sprite.Create(tex, new Rect(i * Cell, 0, Cell, Cell), new Vector2(0.5f, 0.5f), Cell);
        }
        grid = gameObject.AddComponent<Grid>();          // cells are 1 by 1 world units
        var layer = new GameObject("Ground");
        layer.transform.SetParent(transform, false);
        map = layer.AddComponent<Tilemap>();
        var tilemapRenderer = layer.AddComponent<TilemapRenderer>();
        tilemapRenderer.mode = TilemapRenderer.Mode.Chunk;  // draw tiles in grouped chunks
        Camera.main.orthographicSize = 9f;
        Camera.main.transform.position = new Vector3(Cols / 2f, Rows / 2f, -10f);
    }

    bool IsGround(Vector3Int c) => map.HasTile(c);

    void Refresh(Vector3Int c)
    {
        if (!IsGround(c)) return;
        int index = 0;
        for (int i = 0; i < 4; i++)
            if (IsGround(c + neighbours[i])) index |= 1 << i;
        map.SetTile(c, tiles[index]);
    }

    void Paint(Vector3Int c, bool ground)
    {
        if (c.x < 0 || c.y < 0 || c.x >= Cols || c.y >= Rows || IsGround(c) == ground) return;
        map.SetTile(c, ground ? tiles[15] : null);   // null erases the cell
        Refresh(c);
        foreach (var n in neighbours) Refresh(c + n);
    }

    void Update()
    {
        var world = Camera.main.ScreenToWorldPoint(Input.mousePosition);
        var cell = grid.WorldToCell(world);
        cell.z = 0;
        if (Input.GetMouseButton(0)) Paint(cell, true);
        else if (Input.GetMouseButton(1)) Paint(cell, false);
    }
}

In all three, an edit recomputes the cell and its four neighbours and nothing else. Only the Lua version caches chunks by hand; Godot and Unity already do that for you. In real projects you would usually let terrains or Rule Tiles pick the tiles instead of writing the mask yourself.

Pitfalls

  • Forgetting the neighbours. Updating only the edited cell leaves its neighbours showing stale edges. Any rule-based tile must refresh the cells around it too.
  • Mixing up the y axis. Godot and LÖVE count y downwards, Unity counts it upwards. If north and south edges are swapped, your neighbour table points the wrong way.
  • Tiles with their own state. A chest that remembers being opened fights the tilemap. Keep tiles for terrain; spawn nodes or GameObjects for things that move or remember.
  • Seams between tiles. Thin lines that flicker between tiles while the camera moves usually come from texture filtering sampling the neighbouring tile in the atlas, or from positions that are not whole pixels. Padding tiles in the atlas and using point filtering for pixel art are the usual fixes.
  • Animating by rewriting cells. Setting thousands of cells every frame, for example to animate water, dirties every chunk. Use the engine's animated tiles instead.
  • Collision follows the same grid. Each solid tile can produce its own collision shape, and many small shapes can snag a sliding character on the seams. In Unity, a TilemapCollider2D with a CompositeCollider2D merges them into larger shapes.

In real games

Tilemaps are older than game engines. The Nintendo Entertainment System drew its backgrounds from a name table, a grid of one-byte tile numbers that pointed into a table of 8 by 8 pixel patterns, because there was not enough memory to store the screen as pixels.

Standalone level editors such as Tiled and LDtk store maps as tile layers plus object layers: terrain in the grid, things with state as objects. Both also offer rule-based automatic tiling.

Robert Nystrom's Game Programming Patterns uses a terrain grid to explain the flyweight pattern: many cells share a few tile types instead of each owning a full object.

Takeaways

  • A tilemap stores a level as a grid of small tile indices; the images live once in a shared tileset.
  • Point to cell is floor(position / cell_size), which is why lookups in a tilemap are instant.
  • Autotiling computes a tile from the neighbours. One edit changes up to five cells.
  • Engines build chunks of cells and rebuild only the dirty ones; chunk size trades draw calls against edit cost.
  • Godot 4.3+ uses TileMapLayer with terrains; Unity uses Tilemap with Rule Tiles from 2D Tilemap Extras.
