Input action maps: InputMap in Godot, the Input System in Unity

Why game code should ask for named actions such as jump instead of keys, and how Godot's InputMap and Unity's Input System bind, rebind and save them.

One player has a French keyboard, another plugs in a gamepad, a third wants jump on another key. If your code says "if Space is down, jump", every one of those requests means editing gameplay code. The fix is to stop naming keys in gameplay code at all.

Name what the player wants, not what they pressed

An action is a name for something the player wants to do: jump, move_left, pause. A binding connects one physical input, such as the Space key or the bottom face button of a gamepad, to an action. An action can have several bindings. The table of all actions and their bindings is the action map (Godot calls it the InputMap).

Gameplay code only asks about actions, such as "was jump just pressed?", and never learns which key did it.

Who owns what, and in what order

The engine owns the action map and the state of every action. Your code owns only the names. Each frame, in this order:

  1. The engine reads the queued device events (see the previous lesson on events).
  2. It matches each event against the bindings and updates the action it belongs to: held or not, just pressed, and a strength from 0 to 1 for triggers and sticks.
  3. Your update or input callback reads the actions.

Rebinding means changing a row of that table while the game runs. Nothing else has to change. A settings screen edits data and saves it for the next launch.

Godot 4: InputMap

You define actions in Project Settings, Input Map, and they are stored in project.godot. Gameplay code reads them through Input: Input.is_action_pressed("jump"), Input.is_action_just_pressed("jump"), and helpers that combine actions into axes, Input.get_axis("move_left", "move_right") and Input.get_vector(...). An input event can be tested with event.is_action_pressed("jump").

The InputMap singleton edits the table at run time: add_action, action_add_event, action_erase_event, action_get_events and has_action. A binding is just an InputEvent object, such as an InputEventKey or an InputEventJoypadButton. Godot has one flat list of actions for the whole game. Each action also has its own dead zone, which the next lesson is about.

Unity 6 and 2022 LTS: the Input System package

Actions live in an Input Action Asset, edited in the Actions Editor. Inside it, actions are grouped into action maps, such as Player and UI, that you enable and disable as a group. Bindings are text paths such as <Keyboard>/space or <Gamepad>/buttonSouth, and a composite binding such as 1DAxis or 2DVector turns several buttons into one axis. From Input System 1.8 an asset can be made project-wide and read with InputSystem.actions.FindAction("Jump").

Rebinding does not overwrite the asset. It sets an override on top of the binding, so "reset to default" means removing the override. PerformInteractiveRebinding() waits for the player's next input. SaveBindingOverridesAsJson() and LoadBindingOverridesFromJson() store the overrides. The older Input Manager also has named buttons and axes, such as Input.GetButton("Jump"), but no built-in way to change them while the game runs.

The trade-off

Godot's single list is quick to set up. Unity's maps and overrides take longer to learn but give you context switching and reset to defaults for free. Both are the same table.

Try it

Click the canvas, then move with the arrow keys and jump with Space. On a touch screen, hold the pad buttons under the table. Now press Rebind jump and press any key, for example W, or tap Pad B. Jump moves to the new input straight away, and nothing else changed.

Then switch on Game code reads raw keys. The game now asks about the arrow keys and Space directly. Your rebinding still sits in the table, but the game ignores it, and the pad stops working completely. Binding a key that is already in use takes it away from its old action.

The code

The same system in LÖVE, with the demo's names and numbers. LÖVE has no action map, so the table is a plain Lua table. F1, F2 and F3 start rebinding move_left, move_right and jump, standing in for the demo's buttons. The pad names (dpleft, a) are LÖVE's standard gamepad buttons.

local SPEED, JUMP_SPEED, GRAVITY, GROUND = 160, 420, 1200, 300

-- The action map: data, not code. Rebinding edits only this table.
local bindings = {
  move_left  = { key = "left",  pad = "dpleft" },
  move_right = { key = "right", pad = "dpright" },
  jump       = { key = "space", pad = "a" },
}
local REBIND_KEYS = { f1 = "move_left", f2 = "move_right", f3 = "jump" }
local waitingFor = nil      -- the action being rebound, or nil
local player = { x = 400, y = GROUND, vy = 0 }

local function actionDown(name)       -- polled, for held actions
  local b = bindings[name]
  if b.key and love.keyboard.isDown(b.key) then return true end
  for _, stick in ipairs(love.joystick.getJoysticks()) do
    if b.pad and stick:isGamepad() and stick:isGamepadDown(b.pad) then return true end
  end
  return false
end

local function onInput(field, value)  -- every press event comes through here
  if waitingFor then
    for _, b in pairs(bindings) do      -- one input, one action
      if b[field] == value then b[field] = nil end
    end
    bindings[waitingFor][field] = value
    waitingFor = nil
    return
  end
  if bindings.jump[field] == value and player.y >= GROUND then
    player.vy = -JUMP_SPEED
  end
end

function love.keypressed(key, scancode, isrepeat)
  if isrepeat then return end
  if REBIND_KEYS[key] and not waitingFor then waitingFor = REBIND_KEYS[key] return end
  onInput("key", key)
end

function love.gamepadpressed(joystick, button) onInput("pad", button) end

function love.update(dt)
  local move = 0
  if actionDown("move_left") then move = move - 1 end
  if actionDown("move_right") then move = move + 1 end
  player.x = player.x + move * SPEED * dt
  player.vy = player.vy + GRAVITY * dt
  player.y = math.min(player.y + player.vy * dt, GROUND)
  if player.y >= GROUND then player.vy = 0 end
end

function love.draw()
  love.graphics.rectangle("fill", player.x - 12, player.y - 28, 24, 28)
  love.graphics.print(waitingFor and ("press an input for " .. waitingFor) or "F1-F3: rebind", 20, 20)
end
# action_player.gd on a Node2D. Godot 4. F3 rebinds jump.
extends Node2D

const SPEED := 160.0
const JUMP_SPEED := 420.0
const GRAVITY := 1200.0
const GROUND := 300.0
var vy := 0.0
var waiting_for := ""

func _ready() -> void:
    position = Vector2(400, GROUND)
    # Usually made in Project Settings > Input Map. Made here so the script runs alone.
    _add_default("move_left", KEY_LEFT, JOY_BUTTON_DPAD_LEFT)
    _add_default("move_right", KEY_RIGHT, JOY_BUTTON_DPAD_RIGHT)
    _add_default("jump", KEY_SPACE, JOY_BUTTON_A)

func _add_default(action: StringName, key: Key, button: JoyButton) -> void:
    if InputMap.has_action(action):
        return
    InputMap.add_action(action)
    var k := InputEventKey.new()
    k.physical_keycode = key
    InputMap.action_add_event(action, k)
    var j := InputEventJoypadButton.new()
    j.button_index = button
    InputMap.action_add_event(action, j)

func _unhandled_input(event: InputEvent) -> void:
    if waiting_for != "" and event is InputEventKey and event.pressed:
        # Replace the keyboard binding, keep the pad one.
        for old in InputMap.action_get_events(waiting_for):
            if old is InputEventKey:
                InputMap.action_erase_event(waiting_for, old)
        var k := InputEventKey.new()
        k.physical_keycode = event.physical_keycode
        InputMap.action_add_event(waiting_for, k)
        waiting_for = ""
        get_viewport().set_input_as_handled()
    elif event is InputEventKey and event.pressed and event.keycode == KEY_F3:
        waiting_for = "jump"

func _process(delta: float) -> void:
    position.x += Input.get_axis("move_left", "move_right") * SPEED * delta
    if Input.is_action_just_pressed("jump") and position.y >= GROUND:
        vy = -JUMP_SPEED
    vy += GRAVITY * delta
    position.y = minf(position.y + vy * delta, GROUND)
    if position.y >= GROUND:
        vy = 0.0
    queue_redraw()

func _draw() -> void:
    draw_rect(Rect2(-12, -28, 24, 28), Color.WHITE)
// ActionPlayer.cs. Unity 6 or 2022 LTS with the Input System package. F3 rebinds jump.
// Put it on a Cube. Units are metres, so 160 px/s becomes 1.6 m/s.
using UnityEngine;
using UnityEngine.InputSystem;

public class ActionPlayer : MonoBehaviour
{
    const float Speed = 1.6f, JumpSpeed = 4.2f, Gravity = 12f;
    InputAction move, jump;
    float vy;

    void Awake()
    {
        move = new InputAction("Move", InputActionType.Value);
        move.AddCompositeBinding("1DAxis")
            .With("Negative", "<Keyboard>/leftArrow")
            .With("Positive", "<Keyboard>/rightArrow");
        move.AddCompositeBinding("1DAxis")
            .With("Negative", "<Gamepad>/dpad/left")
            .With("Positive", "<Gamepad>/dpad/right");
        jump = new InputAction("Jump", InputActionType.Button);
        jump.AddBinding("<Keyboard>/space");      // binding index 0
        jump.AddBinding("<Gamepad>/buttonSouth"); // binding index 1
        jump.performed += ctx => { if (transform.position.y <= 0f) vy = JumpSpeed; };
    }

    void OnEnable()  { move.Enable(); jump.Enable(); }
    void OnDisable() { move.Disable(); jump.Disable(); }

    void Update()
    {
        if (Keyboard.current != null && Keyboard.current.f3Key.wasPressedThisFrame) RebindJump();
        Vector3 p = transform.position;
        p.x += move.ReadValue<float>() * Speed * Time.deltaTime;
        vy -= Gravity * Time.deltaTime;
        p.y = Mathf.Max(p.y + vy * Time.deltaTime, 0f);
        if (p.y <= 0f) vy = 0f;
        transform.position = p;
    }

    void RebindJump()
    {
        jump.Disable();   // rebinding an enabled action throws an exception
        jump.PerformInteractiveRebinding(0)
            .WithControlsExcluding("<Mouse>")
            .WithCancelingThrough("<Keyboard>/escape")
            .OnComplete(op => { op.Dispose(); jump.Enable(); Save(); })
            .OnCancel(op => { op.Dispose(); jump.Enable(); })
            .Start();
    }

    void Save() { PlayerPrefs.SetString("jump", jump.SaveBindingOverridesAsJson()); }
}

In every tab, key names appear only in the table or the code that builds it. The movement and jump lines name actions.

Pitfalls

  • Binding by character instead of position. W, A, S and D are in different places on an AZERTY keyboard. Godot's physical_keycode binds by position on a US layout, and keycode by the printed label. Unity's Input System also names keyboard controls by their US layout position. Bind movement by position and show the local label.
  • The press that rebinds also triggers the action. If the action stays live while you wait, the key the player presses to bind it fires it too. Unity forces the issue: PerformInteractiveRebinding throws if the action is enabled. In Godot, call set_input_as_handled() so other input callbacks skip that press.
  • Silent conflicts. Nothing in the code above stops one key from being bound to two actions. Decide on a rule, such as taking it away from the old action like the demo does, or refusing and warning, and apply it in your settings screen.
  • Forgetting to save. Changes made through Godot's InputMap at run time are not written back to project.godot, so they are gone on the next launch. Save the events yourself, for example as key codes in a ConfigFile. In Unity, save with SaveBindingOverridesAsJson and load before gameplay starts.
  • Hard-coded button prompts. A tutorial that says "Press Space" is wrong after a rebind. Build prompts from the bindings: GetBindingDisplayString() in Unity, as_text() on the bound event in Godot.

In real games

The same idea appears one layer down, in SDL, which LÖVE is built on. Its game controller mapping database turns many different pads into one standard layout, which is why "a" in the Lua code means the bottom face button on almost any controller. Steam Input does it one layer up, outside the game: players remap controllers per game, and its API lets games declare their own actions grouped into action sets.

Your turn (15 minutes)

Search your project for raw key checks: KEY_ or is_key_pressed in Godot, Keyboard.current or Input.GetKey in Unity. Replace each one in gameplay code with a named action, and add a gamepad binding for every action. Then add one rebind key, as in the code tabs, that rebinds jump and saves it. You are done when you can rebind jump, quit, relaunch, and still jump with the new key, and no gameplay script names a key.

Takeaways

  • An action is a name for what the player wants. A binding connects one physical input to it. Gameplay code asks only about actions.
  • Rebinding and new devices then change data in one table, never gameplay code.
  • Godot keeps one flat InputMap edited in Project Settings or with the InputMap singleton. Unity groups actions into maps in an asset and rebinds with overrides on top of it.
  • When you build rebinding, handle the triggering press, conflicts, saving and on-screen prompts yourself.
