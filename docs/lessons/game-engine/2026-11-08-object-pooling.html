Object pooling: borrow, return, never destroy

How reusing a fixed set of objects avoids creation costs and collector pauses, who owns a pooled object, and how Godot and Unity code express it.

Your shooter runs smoothly until the boss fight. Then, every few seconds, the whole game stops for a moment while hundreds of bullets are on screen. The pause comes from memory: thousands of bullets created, thrown away, and cleaned up by the runtime.

What creating and destroying really costs

Spawning a bullet looks like one line, but the engine reserves memory for the object, builds its components or child nodes, registers it with the renderer and the physics world, and calls your setup code. In Unity, Instantiate copies a prefab and then runs Awake and OnEnable. In Godot, instantiate() builds the nodes of a packed scene and add_child puts them in the tree, which calls _enter_tree and _ready.

Destroying undoes all of that. In languages with a garbage collector, a part of the runtime that finds memory no longer used and reclaims it, there is a second bill. The dead object becomes garbage: memory that nothing points to but that is not yet free. When enough garbage piles up, the collector runs, and while it works your frame waits. Unity's C# scripts, Godot's C# scripts and Lua all use a garbage collector.

GDScript is different. Nodes are freed when you call queue_free or free, and other objects are reference counted, so memory is returned at once and there is no collector pause. In Godot with GDScript, a pool saves the cost of building nodes and entering the tree, not a collection. The saving is smaller.

The pool: create once, then lend

An object pool is a collection of ready-made objects that you borrow and give back instead of creating and destroying them. All of them are created once, usually while the level loads. A list called the free list holds the ones not in use.

  • Acquire: take an object off the free list, reset every field it has, and switch it on.
  • Release: switch it off and put it back on the free list. Nothing is freed, so nothing becomes garbage.

This answers the ownership question. The pool owns every object for the whole life of the pool. Game code only borrows one, and the borrow ends at release. After release, any reference you still hold points at an object that someone else may already be using for something new.

How big, and what happens when it runs dry

The size you need is roughly the spawn rate times the lifetime. Sixty shots per second that each live 1.2 seconds means about 72 bullets in the air, so a pool of 80 leaves some room. Sooner or later the pool will be empty anyway, and you must choose what acquire does then:

  • Skip. Refuse the request. Fine for sparks and debris, bad for the player's own gun.
  • Grow. Create a new object and keep it in the pool afterwards. Nothing is lost, but you pay the creation cost in the middle of play.
  • Recycle the oldest. Take the active object that has lived longest and reuse it. It vanishes early, which players rarely notice for bullet holes.

Reset everything on acquire

A pooled object keeps whatever state it had when it was released. If acquire does not reset age, velocity, health, colour and any running timers, the new bullet starts life with the old one's leftovers. This is the most common pooling bug.

The code

The Lua version is a whole LÖVE program with the demo's numbers and the "skip" policy. The free list is a stack, so acquire and release never move other entries. The update loop walks the whole pool, so releasing during the loop is safe.

local POOL_SIZE, FIRE_RATE, LIFE = 80, 60, 1.2
local SPEED, GRAVITY = 300, 500
local pool, freeList = {}, {}
local fireTimer, clock = 0, 0

for i = 1, POOL_SIZE do                   -- created once, at load
  local b = { active = false, x = 0, y = 0, vx = 0, vy = 0, age = 0 }
  pool[i] = b
  freeList[#freeList + 1] = b
end

local function acquire()
  local b = freeList[#freeList]
  if b == nil then return nil end         -- empty: skip the shot
  freeList[#freeList] = nil
  b.active = true
  return b
end

local function release(b)
  b.active = false
  freeList[#freeList + 1] = b
end

local function fire()
  local b = acquire()
  if b == nil then return end
  b.x, b.y, b.age = 400, 500, 0           -- reset every field
  b.vx, b.vy = 140 * math.sin(clock * 2.3), -SPEED
end

function love.update(dt)
  clock = clock + dt
  fireTimer = fireTimer + dt
  while fireTimer >= 1 / FIRE_RATE do
    fireTimer = fireTimer - 1 / FIRE_RATE
    fire()
  end
  for i = 1, #pool do
    local b = pool[i]
    if b.active then
      b.vy = b.vy + GRAVITY * dt
      b.x, b.y = b.x + b.vx * dt, b.y + b.vy * dt
      b.age = b.age + dt
      if b.age >= LIFE then release(b) end
    end
  end
end

function love.draw()
  for i = 1, #pool do
    local b = pool[i]
    if b.active then love.graphics.circle("fill", b.x, b.y, 3) end
  end
end
# Godot 4. Attach to a Node2D in a new scene and run.
# Godot has no built-in node pool, so the pool is this script.
extends Node2D

const POOL_SIZE := 80
const FIRE_RATE := 60.0
const LIFE := 1.2
const SPEED := 300.0
const GRAVITY := 500.0

class Bullet extends Sprite2D:
    var active := false
    var velocity := Vector2.ZERO
    var age := 0.0

var pool: Array = []
var free_list: Array = []   # not "free": that is a Node method
var fire_timer := 0.0
var clock := 0.0

func _ready() -> void:
    position = get_viewport_rect().size * Vector2(0.5, 0.8)
    var tex := preload("res://icon.svg")
    for i in POOL_SIZE:
        var b := Bullet.new()
        b.texture = tex
        b.scale = Vector2(0.1, 0.1)
        add_child(b)            # enters the tree once and stays
        pool.append(b)
        release(b)

func acquire() -> Bullet:
    if free_list.is_empty():
        return null             # empty: skip the shot
    var b: Bullet = free_list.pop_back()
    b.active = true
    b.visible = true
    return b

func release(b: Bullet) -> void:
    b.active = false
    b.visible = false
    free_list.push_back(b)

func fire() -> void:
    var b := acquire()
    if b == null:
        return
    b.position = Vector2.ZERO   # reset every field
    b.age = 0.0
    b.velocity = Vector2(140.0 * sin(clock * 2.3), -SPEED)

func _process(delta: float) -> void:
    clock += delta
    fire_timer += delta
    while fire_timer >= 1.0 / FIRE_RATE:
        fire_timer -= 1.0 / FIRE_RATE
        fire()
    for b in pool:
        if b.active:
            b.velocity.y += GRAVITY * delta
            b.position += b.velocity * delta
            b.age += delta
            if b.age >= LIFE:
                release(b)
// BulletFountain.cs. Unity 2021.1 or later, including Unity 6.
// Add to an empty GameObject in a new scene and press Play.
using UnityEngine;
using UnityEngine.Pool;

public class BulletFountain : MonoBehaviour
{
    public const float FireRate = 60f, Life = 1.2f, Speed = 6f, Gravity = 10f;
    const int PoolSize = 80;

    ObjectPool<Bullet> pool;
    float fireTimer, clock;

    void Awake()
    {
        pool = new ObjectPool<Bullet>(
            createFunc: CreateBullet,
            actionOnGet: b => b.gameObject.SetActive(true),
            actionOnRelease: b => b.gameObject.SetActive(false),
            actionOnDestroy: b => Destroy(b.gameObject),
            collectionCheck: true,       // error if released twice
            defaultCapacity: PoolSize,
            maxSize: PoolSize);          // extra returns are destroyed

        // Prewarm: the pool creates nothing until it is asked.
        var warm = new Bullet[PoolSize];
        for (int i = 0; i < PoolSize; i++) warm[i] = pool.Get();
        for (int i = 0; i < PoolSize; i++) pool.Release(warm[i]);
    }

    Bullet CreateBullet()
    {
        var go = GameObject.CreatePrimitive(PrimitiveType.Sphere);
        go.transform.localScale = Vector3.one * 0.1f;
        var b = go.AddComponent<Bullet>();
        b.pool = pool;
        return b;
    }

    void Update()
    {
        clock += Time.deltaTime;
        fireTimer += Time.deltaTime;
        while (fireTimer >= 1f / FireRate)
        {
            fireTimer -= 1f / FireRate;
            Bullet b = pool.Get();       // creates one if the pool is empty
            b.transform.position = transform.position;   // reset every field
            b.velocity = new Vector3(3f * Mathf.Sin(clock * 2.3f), Speed, 0f);
            b.age = 0f;
        }
    }
}

// Bullet.cs, in its own file.
using UnityEngine;
using UnityEngine.Pool;

public class Bullet : MonoBehaviour
{
    public IObjectPool<Bullet> pool;
    public Vector3 velocity;
    public float age;

    void Update()
    {
        velocity.y -= BulletFountain.Gravity * Time.deltaTime;
        transform.position += velocity * Time.deltaTime;
        age += Time.deltaTime;
        if (age >= BulletFountain.Life) pool.Release(this);
    }
}

The two engines differ in what they hand you. Godot has no general pool class for nodes, so you write the free list yourself, as in the Lua. Unity has had ObjectPool<T> in the UnityEngine.Pool namespace since 2021.1. You give it functions for create, get, release and destroy, and it keeps the free list. Its policy for an empty pool is "grow": Get calls your create function. maxSize limits how many inactive objects it keeps. A release beyond that destroys the object instead. Note that defaultCapacity does not create anything, which is why the code warms the pool by hand.

Pitfalls

  • Setup code that runs only once. In Unity, Awake and Start run once per object, not once per borrow. Put per-use setup in OnEnable, which runs every time SetActive(true) is called, or in the get callback. In Godot, _ready runs only the first time a node enters the tree, so it is no place for per-use setup either.
  • Holding a reference after release. A homing missile that remembers its target bullet will happily follow that object after it has been recycled into a different bullet. Clear references on release, or give each object a counter that goes up on every acquire and compare it before use.
  • Releasing twice. The object ends up on the free list twice, and two later acquires get the same object. Unity's pool reports this when collectionCheck is on. In your own pool, check the active flag in release.
  • Hidden is not switched off. In Godot, visible = false only stops drawing. If a pooled node has its own script, also set process_mode to Node.PROCESS_MODE_DISABLED, and turn off its collision shapes. Changing a collision shape inside a physics callback must be deferred, for example with set_deferred("disabled", true).
  • Pooling everything. A pool holds its memory as long as it exists, and every pooled type adds reset code that can go wrong. Pool what a profiler shows is costly.

In real games

Particle systems are pools by design. A Unity Particle System has a Max Particles setting, and Godot's GPUParticles2D has an amount property. Both work with a fixed number of particle slots that are reused as particles die, instead of creating an object for every particle.

Unity's UnityEngine.Pool namespace also contains pools for plain collections, such as ListPool<T>. They exist for the same reason: to avoid making a new list and throwing it away every frame in code that runs often.

Your turn (15 minutes)

Find the object your game creates most often: bullets, hit effects or damage numbers. Count how many are alive at the busiest moment by printing the count every second. Build a pool that size plus a quarter, using the code above, and replace the create and destroy calls with acquire and release.

Then fire a burst larger than the pool. You are done when you have decided, on purpose, whether that object should skip, grow or recycle the oldest, and the profiler no longer shows creation calls during the burst.

Takeaways

  • Creating and destroying objects costs engine work now and, with a garbage collector, a collection pause later.
  • A pool creates objects once and lends them out. The pool owns them; game code only borrows.
  • Size the pool from spawn rate times lifetime, and choose skip, grow or recycle for when it runs out.
  • Reset every field on acquire, and drop every reference on release.
  • Godot gives you the pieces to build a pool; Unity 2021.1 and later ship ObjectPool<T>. Measure first, especially in GDScript, where there is no collector to avoid.
