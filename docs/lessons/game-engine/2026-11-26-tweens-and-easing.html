Tweens and easing: moving values along a curve

How a tween turns elapsed time into a value with an easing curve, who owns and advances it, and how Godot's Tween and Unity coroutines do it.

A menu panel slides in at constant speed and stops dead. A coin simply appears at full size. Nothing is broken, yet both feel cheap. Real objects speed up and slow down, and a small curve applied to time is the fix.

A tween is a value driven by time

A tween (from "in-between") changes one value from a start a to an end b over a fixed duration. It simulates nothing: given the time passed, it says where the value should be. Every tween runs the same four steps each frame:

  1. Add the frame's delta time to elapsed.
  2. Turn that into progress: t = elapsed / duration, clamped to 0..1.
  3. Bend progress with an easing function: e = ease(t).
  4. Blend between the ends: value = a + (b - a) * e. This blend is called lerp, short for linear interpolation.

Without step 3 the value moves at constant speed: linear motion, the mechanical menu panel.

Easing functions

An easing function takes progress from 0 to 1 and returns a new number, with ease(0) = 0 and ease(1) = 1. What happens in between is the feel. The common families are named by their shape:

  • Quad, cubic, sine: smooth power curves. inQuad(t) = t * t starts slow; outQuad(t) = 1 - (1 - t)² ends slow.
  • In, out, in-out: in eases the start, out eases the end, in-out both. Things arriving on screen usually want out; things leaving want in.
  • Back and elastic: overshoot past 1 and come back, so e can be 1.1 or more. Good for pops and bounces.
  • Bounce: hits 1 several times, like a dropped ball.

Most of these come from Robert Penner's easing equations, written for Flash in the early 2000s and copied into nearly every engine and tween library since. The names you see in Godot and in tween libraries for Unity follow his families.

Who owns the tween, and when does it run

A tween owns three things: its start and end values, its duration, and its elapsed clock. It does not own the property it writes. The node or GameObject owns that, and anything else that writes the same property every frame will fight the tween. Whichever writes last in the frame wins.

Godot 4 has a built-in Tween object. You make one with create_tween() on any node and add steps with tween_property(object, "property", final_value, duration). Steps run one after another by default; set_parallel(true) makes them run together. The curve is chosen with two settings: set_trans() picks the family (Tween.TRANS_QUAD, TRANS_BACK, TRANS_ELASTIC, TRANS_BOUNCE and others) and set_ease() picks EASE_IN, EASE_OUT or EASE_IN_OUT. The SceneTree, not your node, advances every tween once per process frame. A tween made with create_tween() is bound to that node: it stops while the node is outside the tree and is killed when the node is freed.

Unity (2022 LTS and Unity 6) has no general tween class for GameObjects. You write the four steps yourself, usually in a coroutine, or use a third-party library such as DOTween. A coroutine that does yield return null resumes once per frame after all Update calls and before LateUpdate. It belongs to the MonoBehaviour that started it and stops when that GameObject is destroyed or deactivated. For the curve you can write the formula, or expose an AnimationCurve field and call Evaluate(t), so a designer can draw the easing in the Inspector.

The trade-off: Godot gives you sequences, parallel steps and named curves for free, from fixed families. Unity makes you write the loop, but it is plain code you can debug, and an AnimationCurve can be any shape.

The code

A LÖVE 11 program with the demo's numbers: one second, x from 60 to 460, scale 0.5 to 1.5, opacity 0.15 to 1, all from one eased value. Space replays; Left and Right pick the easing.

-- main.lua for LÖVE 11. Space replays, Left/Right change the easing.
local ease = {}
function ease.linear(t) return t end
function ease.inQuad(t) return t * t end
function ease.outQuad(t) return 1 - (1 - t) * (1 - t) end
function ease.inOutQuad(t)
  if t < 0.5 then return 2 * t * t end
  return 1 - (2 - 2 * t) ^ 2 / 2
end
function ease.outCubic(t) return 1 - (1 - t) ^ 3 end
function ease.inOutSine(t) return (1 - math.cos(math.pi * t)) / 2 end
function ease.outBack(t)
  local c1 = 1.70158
  return 1 + (c1 + 1) * (t - 1) ^ 3 + c1 * (t - 1) ^ 2
end
function ease.outElastic(t)
  if t == 0 or t == 1 then return t end
  return 2 ^ (-10 * t) * math.sin((t * 10 - 0.75) * (2 * math.pi / 3)) + 1
end
function ease.outBounce(t)
  local n, d = 7.5625, 2.75
  if t < 1 / d then return n * t * t end
  if t < 2 / d then t = t - 1.5 / d; return n * t * t + 0.75 end
  if t < 2.5 / d then t = t - 2.25 / d; return n * t * t + 0.9375 end
  t = t - 2.625 / d
  return n * t * t + 0.984375
end

local NAMES = { "linear", "inQuad", "outQuad", "inOutQuad", "outCubic",
                "inOutSine", "outBack", "outElastic", "outBounce" }
local choice = 3                         -- outQuad
local DURATION = 1.0
local FROM_X, TO_X = 60, 460
local elapsed = 0
local x, scale, alpha = FROM_X, 0.5, 0.15

local function lerp(a, b, e) return a + (b - a) * e end

function love.update(dt)
  elapsed = math.min(elapsed + dt, DURATION)    -- 1. advance the clock
  local t = elapsed / DURATION                   -- 2. progress 0..1
  local e = ease[NAMES[choice]](t)               -- 3. bend it
  x = lerp(FROM_X, TO_X, e)                      -- 4. blend each value
  scale = lerp(0.5, 1.5, e)
  alpha = math.max(0, math.min(1, lerp(0.15, 1, e)))  -- overshoot must not break colour
end

function love.keypressed(key)
  if key == "space" then elapsed = 0 end
  if key == "right" then choice = choice % #NAMES + 1; elapsed = 0 end
  if key == "left" then choice = (choice - 2) % #NAMES + 1; elapsed = 0 end
end

function love.draw()
  local size = 36 * scale
  love.graphics.setColor(0.2, 0.45, 0.85, alpha)
  love.graphics.rectangle("fill", x - size / 2, 200 - size / 2, size, size)
  love.graphics.setColor(0.5, 0.5, 0.5)
  love.graphics.line(FROM_X, 240, FROM_X, 250)
  love.graphics.line(TO_X, 240, TO_X, 250)
  love.graphics.setColor(1, 1, 1)
  love.graphics.print(NAMES[choice] .. string.format("   t = %.2f", elapsed / DURATION), 20, 20)
end
# tween_box.gd for Godot 4. Attach to a Sprite2D with any texture (icon.svg works)
# in a new 2D scene. ui_accept (Space or Enter by default) replays the tween.
extends Sprite2D

const FROM_X := 60.0
const TO_X := 460.0
const DURATION := 1.0

var tween: Tween

func _ready() -> void:
    play_tween()

func play_tween() -> void:
    if tween:
        tween.kill()                   # never let two tweens fight over one property
    position = Vector2(FROM_X, 200)
    scale = Vector2(0.5, 0.5)
    modulate.a = 0.15
    tween = create_tween().set_parallel(true)
    tween.set_trans(Tween.TRANS_QUAD).set_ease(Tween.EASE_OUT)   # outQuad
    tween.tween_property(self, "position:x", TO_X, DURATION)
    tween.tween_property(self, "scale", Vector2(1.5, 1.5), DURATION)
    tween.tween_property(self, "modulate:a", 1.0, DURATION)
    tween.finished.connect(func(): print("tween finished"))

func _unhandled_input(event: InputEvent) -> void:
    if event.is_action_pressed("ui_accept"):
        play_tween()

# Other curves from the demo: TRANS_BACK, TRANS_ELASTIC or TRANS_BOUNCE with EASE_OUT,
# TRANS_SINE with EASE_IN_OUT. Godot's constants may differ slightly from the Lua ones.
// TweenBox.cs for Unity 2022 LTS or Unity 6. Add to a GameObject with a SpriteRenderer.
// Positions are in world units, so the track is -4 to 4 instead of 60 to 460 pixels.
// Right-click the component header and choose Replay to run it again.
using System.Collections;
using UnityEngine;

[RequireComponent(typeof(SpriteRenderer))]
public class TweenBox : MonoBehaviour
{
    public float fromX = -4f, toX = 4f, duration = 1f;
    public bool useCurve = false;   // tick to use the curve drawn in the Inspector
    public AnimationCurve curve = AnimationCurve.EaseInOut(0f, 0f, 1f, 1f);

    SpriteRenderer spriteRenderer;
    Coroutine running;

    static float OutQuad(float t) => 1f - (1f - t) * (1f - t);

    void Awake() => spriteRenderer = GetComponent<SpriteRenderer>();
    void Start() => Replay();

    [ContextMenu("Replay")]
    void Replay()
    {
        if (running != null) StopCoroutine(running);   // one tween per property
        running = StartCoroutine(Tween());
    }

    IEnumerator Tween()
    {
        float elapsed = 0f;
        while (true)
        {
            elapsed = Mathf.Min(elapsed + Time.deltaTime, duration);
            float t = elapsed / Mathf.Max(duration, 0.0001f);
            float e = useCurve ? curve.Evaluate(t) : OutQuad(t);
            transform.position = new Vector3(Mathf.LerpUnclamped(fromX, toX, e), 0f, 0f);
            transform.localScale = Vector3.one * Mathf.LerpUnclamped(0.5f, 1.5f, e);
            Color c = spriteRenderer.color;
            c.a = Mathf.Clamp01(Mathf.LerpUnclamped(0.15f, 1f, e));
            spriteRenderer.color = c;
            if (elapsed >= duration) yield break;
            yield return null;          // resume next frame, after Update
        }
    }
}

Pitfalls

  • Starting a second tween on the same property. Press a button twice and two tweens write position every frame; the result jitters or ends in the wrong place. Keep a reference and kill the old tween first (tween.kill() in Godot, StopCoroutine in Unity).
  • A clamped lerp eats the overshoot. Unity's Mathf.Lerp and Vector3.Lerp clamp their third argument to 0..1, so a back or elastic curve loses its overshoot. Use LerpUnclamped. Do clamp values that must stay in range, such as alpha.
  • Lerping toward the target every frame is not a tween. x = lerp(x, target, 0.1) is exponential smoothing: it depends on frame rate unless scaled by delta time, and never quite arrives.
  • Pausing and time scale. A tween that reads scaled time freezes when the game pauses. In Unity use Time.unscaledDeltaTime for menus that animate during a pause. In Godot a bound tween follows its node's pause behaviour, which you set on the node.
  • Tweening a physics body. If the physics engine also moves the object, the two fight. Tween a kinematic body, and in Godot consider set_process_mode(Tween.TWEEN_PROCESS_PHYSICS) so the tween runs in the physics step.
  • Performance. The maths is a few multiplications. Allocation is the real cost: a new tween object per hit on hundreds of enemies makes garbage, which is why tween libraries pool them.

In real games

Easing is everywhere in game interfaces: menus that slide and settle, damage numbers that pop with an overshoot and fade, health bars that drain smoothly instead of jumping. The talk Juice it or lose it by Martin Jonasson and Petri Purho (2012) turned a plain block-breaker lively step by step, and many of its steps were tweens of position, scale and rotation.

CSS transitions have ease-in, ease-out and ease-in-out timing functions, and Unity tween libraries such as DOTween offer an Ease setting with names like OutQuad and OutBack from Penner's families.

Your turn (15 minutes)

Find a pickup, button or popup in your project that appears instantly. Make it pop: tween its scale from 0 to 1 over 0.3 seconds with an out back curve (TRANS_BACK with EASE_OUT in Godot, or the outBack formula with LerpUnclamped in Unity). Then trigger it again while it is still playing. You are done when a rapid second trigger restarts the pop cleanly, with no flicker from two tweens fighting.

Takeaways

  • Every tween is four steps: advance elapsed, compute t = elapsed / duration, apply e = ease(t), then lerp(a, b, e).
  • The easing curve keeps time steps equal and changes how far the value moves in each one.
  • Use out for things arriving, in for things leaving, and back or elastic for overshoot.
  • The tween owns its clock, not the property: kill the old tween before starting a new one on the same value.
  • Godot gives you a built-in Tween advanced by the SceneTree; in Unity you write a coroutine (or use a library) and an AnimationCurve for custom shapes.
