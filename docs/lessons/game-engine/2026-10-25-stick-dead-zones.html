Analogue sticks and dead zones

Why raw stick values drift and snap, and how axial, radial and scaled radial dead zones clean them up in LÖVE, Godot and Unity.

You put the controller down and your character slowly walks off a ledge. Or you try to creep forward at a slight angle and the character keeps snapping to straight up. Both bugs live in the few lines of code between the stick and your movement code.

What a stick really reports

An analogue stick has one sensor per axis, and the engine reports each as a number from -1 to 1: the raw x and y. In LÖVE and Godot positive y is down; in Unity it is up. The raw numbers have two flaws:

  • The centre is not zero. A released stick rests slightly off centre and jitters. On a worn controller this drift is enough to move a character.
  • The edge is not exactly one. Some sticks never quite reach full tilt, so the player never reaches full speed.

A dead zone is a range of raw values that the game treats as zero. The inner dead zone covers the centre and hides drift. An outer dead zone treats anything near the rim as full tilt. What matters most is the shape of the inner one.

Three ways to cut out the middle

Axial. Test each axis on its own: if x is below the dead zone, set it to zero, then the same for y. This hides drift, but push the stick mostly right and slightly up and the small y is thrown away. The character snaps to the axis, so shallow angles are impossible.

Radial. Judge the whole vector by its length: below the dead zone return zero, otherwise return it unchanged. Direction is kept, but output jumps: with a dead zone of 0.2, a length of 0.19 gives nothing and 0.21 gives 0.21. Moving at 5% speed is impossible.

Scaled radial. Judge the length, then stretch what is left back to the full range. With an inner zone of 0.2 and an outer edge of 0.95, the output length is (length - 0.2) / (0.95 - 0.2), capped at 1, in the raw direction. Output starts at zero at the edge of the dead zone and reaches 1 just before the rim.

local len = math.sqrt(x * x + y * y)
if len < INNER then return 0, 0 end
local scaled = math.min((len - INNER) / (OUTER - INNER), 1)
return x / len * scaled, y / len * scaled

Rule of thumb

Use scaled radial for walking, aiming and steering. Keep axial thresholds for treating a stick as four buttons, as menus do.

Who does it, and in what order

The controller owns the raw value. The engine applies its dead zone between the device and your code, so the value your update reads has usually been processed already. Both engines also let you read the raw value.

Godot 4. Every InputMap action has its own dead zone. Input.get_action_strength and Input.get_axis apply it per action, which on a stick is a scaled axial dead zone. Input.get_vector combines the raw strengths of four actions into one vector and applies a scaled radial dead zone; the optional fifth argument sets its size. Input.get_joy_axis returns one raw axis. The default for new actions was 0.5 up to Godot 4.3 and is 0.2 from 4.4.

Unity 6 and 2022 LTS, Input System package. Values pass through processors, small functions that run in order on the device control, then the binding, then the action. A gamepad's sticks already carry a stickDeadzone processor, scaled radial with a min and max that default to the Input System settings defaultDeadzoneMin and defaultDeadzoneMax, 0.125 and 0.925. ReadValue() gives the processed value, ReadUnprocessedValue() the raw one. An axisDeadzone processor handles single axes and triggers.

The trade-off

Godot's dead zones are per-action settings, but the shape depends on which function you call. Unity applies a good default on the device, but processors you add stack on top of it instead of replacing it.

Try it

The stick starts worn: released, it rests at (0.09, -0.12), and with no dead zone the character crawls away. Pick Axial and the drift stops. Now hold the stick to the right and slowly move it up: "Game reads" stays flat, then jumps.

Switch on Trace a full circle to see every direction at the current tilt. Axial leaves flat notches on the axes, radial passes the circle unchanged, scaled radial shrinks it evenly. In the graph, look for the jump in radial and the ramp in scaled radial. Finally, set the inner dead zone to 0.1 and the drift comes back.

The code

LÖVE gives you raw axes through Joystick:getGamepadAxis, so the dead zone is yours to write. The numbers match the demo. Swap in axial to feel the snapping.

local INNER = 0.2      -- below this length the stick counts as centred
local OUTER = 0.95     -- beyond this length it counts as full tilt
local SPEED = 120      -- pixels per second at full tilt
local player = { x = 400, y = 300 }

-- Scaled radial: judge the whole vector by its length,
-- then stretch the live range INNER..OUTER back to 0..1.
local function scaledRadial(x, y)
  local len = math.sqrt(x * x + y * y)
  if len < INNER or len == 0 then return 0, 0 end
  local scaled = math.min((len - INNER) / (OUTER - INNER), 1)
  return x / len * scaled, y / len * scaled
end

-- Axial, for comparison: hides drift but snaps to the axes.
local function axial(x, y)
  if math.abs(x) < INNER then x = 0 end
  if math.abs(y) < INNER then y = 0 end
  return x, y
end

local function readStick()
  local stick = love.joystick.getJoysticks()[1]
  if stick == nil or not stick:isGamepad() then return 0, 0 end
  return stick:getGamepadAxis("leftx"), stick:getGamepadAxis("lefty")
end

function love.update(dt)
  local rawX, rawY = readStick()
  local x, y = scaledRadial(rawX, rawY)   -- try axial(rawX, rawY)
  player.x = player.x + x * SPEED * dt
  player.y = player.y + y * SPEED * dt
end

function love.draw()
  love.graphics.circle("fill", player.x, player.y, 8)
end
# stick_mover.gd on a Node2D. Godot 4. Uses the left stick of the first pad.
extends Node2D

const INNER := 0.2
const SPEED := 120.0
var raw := Vector2.ZERO

func _ready() -> void:
    position = Vector2(400, 300)
    # Usually made in Project Settings > Input Map. Made here so the script runs alone.
    _add_axis_action("move_left", JOY_AXIS_LEFT_X, -1.0)
    _add_axis_action("move_right", JOY_AXIS_LEFT_X, 1.0)
    _add_axis_action("move_up", JOY_AXIS_LEFT_Y, -1.0)
    _add_axis_action("move_down", JOY_AXIS_LEFT_Y, 1.0)

func _add_axis_action(action: StringName, axis: JoyAxis, direction: float) -> void:
    if InputMap.has_action(action):
        return
    InputMap.add_action(action, INNER)   # the per-action dead zone
    var motion := InputEventJoypadMotion.new()
    motion.axis = axis
    motion.axis_value = direction
    InputMap.action_add_event(action, motion)

func _process(delta: float) -> void:
    # Raw value, no dead zone. Drawn as a red line so you can see your drift.
    raw = Vector2(Input.get_joy_axis(0, JOY_AXIS_LEFT_X), Input.get_joy_axis(0, JOY_AXIS_LEFT_Y))
    # Scaled radial on the whole stick.
    var move := Input.get_vector("move_left", "move_right", "move_up", "move_down", INNER)
    # Axial, for comparison: Vector2(Input.get_axis("move_left", "move_right"),
    #                                Input.get_axis("move_up", "move_down"))
    position += move * SPEED * delta
    queue_redraw()

func _draw() -> void:
    draw_line(Vector2.ZERO, raw * 40.0, Color.RED)
    draw_circle(Vector2.ZERO, 8.0, Color.WHITE)
// StickMover.cs. Unity 6 or 2022 LTS with the Input System package.
// Put it on a Cube. Units are metres, so 120 px/s becomes 1.2 m/s. Here y is up.
using UnityEngine;
using UnityEngine.InputSystem;

public class StickMover : MonoBehaviour
{
    const float Inner = 0.2f, Outer = 0.95f, Speed = 1.2f;

    static Vector2 ScaledRadial(Vector2 v, float inner, float outer)
    {
        float len = v.magnitude;
        if (len < inner || len == 0f) return Vector2.zero;
        float scaled = Mathf.Min((len - inner) / (outer - inner), 1f);
        return v / len * scaled;
    }

    void Update()
    {
        Gamepad pad = Gamepad.current;
        if (pad == null) return;
        // The value before any processor runs: this is where drift shows.
        Vector2 raw = pad.leftStick.ReadUnprocessedValue();
        // After the stick's own stickDeadzone processor (defaults 0.125 and 0.925).
        Vector2 builtIn = pad.leftStick.ReadValue();
        // The same maths with this lesson's numbers.
        Vector2 move = ScaledRadial(raw, Inner, Outer);
        transform.position += (Vector3)(move * Speed * Time.deltaTime);
        Debug.DrawRay(transform.position, raw, Color.red);
        Debug.DrawRay(transform.position, builtIn, Color.green);
    }
}

The Unity script runs its own function on the unprocessed value. Running it on ReadValue() would apply two dead zones in a row.

Pitfalls

  • Building a vector from two separate axis reads. Vector2(get_axis(...), get_axis(...)) in Godot, or two single-axis checks of your own, give an axial dead zone and its snapping. Read the stick as one vector.
  • Stacking dead zones. In Unity, a stickDeadzone added to a binding on <Gamepad>/leftStick runs on a value the control has already processed, so the stick feels sluggish. Change the project defaults instead, or start from the unprocessed value.
  • Normalising stick input. normalized() throws away how far the stick is pushed, and turns any drift that slips past the dead zone into full speed. Only cap the length at 1.
  • One size for every player. The right inner size depends on the controller and how worn it is. Put a slider in your settings screen.
  • Menus and movement sharing one threshold. A stick used as a button needs a larger threshold than movement, or a resting thumb moves the menu cursor. Godot keeps 0.5 for its built-in ui_ actions, even though new actions now default to 0.2.

In real games

Both engines here default to scaled radial for sticks: Unity puts a stickDeadzone processor on every gamepad stick, and Godot's get_vector applies one to the whole vector. Many games, shooters in particular, offer inner and outer dead zone sliders in their controller settings. Aiming often adds a response curve after the dead zone, such as squaring the length so small movements are finer.

Takeaways

  • Raw stick values never rest at exactly zero and may not reach exactly one. A dead zone hides the centre and an outer edge fixes the rim.
  • Axial dead zones judge each axis alone and snap movement to the axes. Radial ones keep direction but jump from zero.
  • Scaled radial judges the length, then stretches the rest of the range back to 0 to 1. Use it for movement and aiming.
  • The engine usually applies a dead zone before your code runs: per action or in get_vector in Godot, as a processor on the stick in Unity. Know which one you are reading so you never apply two.
