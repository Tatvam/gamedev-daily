Service locator: autoloads in Godot, singletons in Unity

How to make audio and saving reachable from anywhere through a service locator, and keep them swappable with null and logging services.

Every script in your game calls AudioManager.play("jump"). Run the player scene on its own and it fails with a null-reference error, because the audio manager lives in the menu scene. Muting everything for a test means editing forty scripts.

Global access, the quick way

Some systems are needed everywhere and should exist once: audio, saving, settings. Passing them through every constructor is tedious, so we make them global.

A singleton is a class that makes sure only one instance of itself exists and gives every caller global access to that instance. Godot builds this in as the autoload: a script or scene you list in Project Settings, which Godot creates when the game starts, adds under the root of the scene tree, and makes reachable by name from any script. In Unity you usually write it yourself: a MonoBehaviour stores itself in a static Instance field in Awake, destroys any second copy, and calls DontDestroyOnLoad so it survives scene changes.

Both solve reachability, and both share a weakness: the caller names the concrete class. To mute the game or log every sound, you must edit the callers or the class.

A locator: ask for the role, not the class

A service is a role described by a small set of methods, for example "something with play(id)". A service locator is one global object with a slot for each role. At startup, some code provides (registers) an implementation for each slot. Game code then asks the locator for the role and never learns which class answered:

RealAudio:play("jump")        -- names the class: hard to swap
services.audio:play("jump")   -- names the role: swap the slot instead

Two small helpers make the locator pleasant to use:

  • A null service has the right methods and does nothing. Fill every slot with one by default, and callers never need to check for an empty slot. A scene opened on its own is silent instead of broken.
  • A decorator is a service that wraps another one with the same methods. LoggingAudio writes each call to a log, then hands it to the real audio service. You add logging without touching either the callers or the real service.

Who owns what

The locator owns references, one per slot. Whoever provides a service creates it, usually a startup script or a test. The service owns its own resources, such as audio players. In Godot, an autoload node is a child of the tree's root, so changing scenes, which replaces only the current scene, leaves it alone. In Unity, a static field lives as long as the scripting domain does, and a DontDestroyOnLoad object is moved to a special scene that loading a new scene does not unload.

Order: register before anyone asks

If a caller asks before the slot is filled, it gets the null service at best and a crash at worst.

Godot creates autoloads before the main scene, in the order of the Autoload list, so any scene node can rely on them in _ready. Unity's classic singleton fills its Instance in Awake, but Unity does not promise which object's Awake runs first, so another script's Awake may see null. The usual fixes are to read services in Start, to set the Script Execution Order, or to register from a static method marked [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSceneLoad)], which runs before any Awake in the first scene.

Godot's autoload is built in and ordered, but a script that writes Audio.play() is tied to that autoload's name and class. Unity has nothing built in, so you write more, but a static C# property gives you a typed interface and compile errors when a slot is renamed.

Rule of thumb

Put a locator in front of services that really are global, and fill every slot with a null service before the first scene runs. For anything a single object needs, pass it in directly instead; that is dependency injection, and it keeps the dependency visible in the code.

Try it

The square hops every 1.2 seconds and calls services.audio:play("jump"); every third hop grabs the coin and also plays "coin". Use Audio service (or tap a box) to swap what fills the slot. Watch the game code panel: its two lines flash on every call and never change.

Try NullAudio: calls keep coming, sounds stop, nothing breaks. Try LoggingAudio: the log fills and each call still reaches Real. Then pick nil, an empty slot with no null service, and watch the next hop.

The code

The Lua is the demo as a LÖVE 11 program: the same services, hop timing and coin rule, with keys 1 to 4 for the four choices. It runs silently in an empty folder; add sounds/jump.wav and sounds/coin.wav to hear RealAudio. The Godot and Unity tabs build the same locator, registered before any scene script runs.

-- main.lua for LÖVE 11. Keys: 1 real, 2 null, 3 logging, 4 nothing registered.
local clock, played = 0, 0
local log = {}

-- Three services with the same method: play(id).
local NullAudio = { name = "NullAudio" }
function NullAudio:play(id) end              -- accepts the call, does nothing

local RealAudio = { name = "RealAudio", sources = {} }
function RealAudio:play(id)
  played = played + 1
  local path = "sounds/" .. id .. ".wav"
  if self.sources[id] == nil and love.filesystem.getInfo(path) then
    self.sources[id] = love.audio.newSource(path, "static")
  end
  local source = self.sources[id]
  if source then
    source:stop()                            -- restart if still playing
    source:play()
  end
end

local LoggingAudio = { name = "LoggingAudio", inner = RealAudio }
function LoggingAudio:play(id)
  log[#log + 1] = string.format("%.1fs  play(%q)", clock, id)
  self.inner:play(id)                        -- then do the real work
end

-- The locator: one slot per role.
local services = { audio = NullAudio }

function services.provideAudio(service)
  services.audio = service or NullAudio      -- nil falls back to the null service
end

-- Game code. It names the role, never the class.
local HOP_EVERY = 1.2
local timer, hops = 0, 0

function love.load()
  services.provideAudio(RealAudio)           -- register before anyone asks
end

function love.update(dt)
  clock = clock + dt
  timer = timer + dt
  if timer >= HOP_EVERY then
    timer = timer - HOP_EVERY
    hops = hops + 1
    services.audio:play("jump")
    if hops % 3 == 0 then
      services.audio:play("coin")            -- every third hop grabs the coin
    end
  end
end

function love.keypressed(key)
  if key == "1" then services.provideAudio(RealAudio) end
  if key == "2" then services.provideAudio(NullAudio) end
  if key == "3" then services.provideAudio(LoggingAudio) end
  if key == "4" then services.audio = nil end  -- skips provideAudio: next hop crashes
end

function love.draw()
  local name = services.audio and services.audio.name or "nil"
  love.graphics.print("audio: " .. name .. "   hops " .. hops .. "   sounds played " .. played, 10, 10)
  local first = math.max(1, #log - 9)
  for i = first, #log do
    love.graphics.print(log[i], 10, 40 + (i - first) * 16)
  end
end
# Godot 4. Six small files. Optional: res://sounds/jump.wav and coin.wav.

# audio_service.gd: the role. Every audio service extends it.
class_name AudioService
extends RefCounted

func play(_id: String) -> void:
    pass


# null_audio.gd
class_name NullAudio
extends AudioService

func play(_id: String) -> void:
    pass  # accepts the call, does nothing


# real_audio.gd
class_name RealAudio
extends AudioService

var _player: AudioStreamPlayer

func _init(player: AudioStreamPlayer) -> void:
    _player = player

func play(id: String) -> void:
    var path := "res://sounds/%s.wav" % id
    if ResourceLoader.exists(path):
        _player.stream = load(path)
        _player.play()


# logging_audio.gd: wraps another service.
class_name LoggingAudio
extends AudioService

var _inner: AudioService

func _init(inner: AudioService) -> void:
    _inner = inner

func play(id: String) -> void:
    print("[audio] play ", id)
    _inner.play(id)


# services.gd: add it to the Autoload list in Project Settings as "Services".
# Godot creates it before the main scene, so it is ready first.
extends Node

var audio: AudioService = NullAudio.new()

func _ready() -> void:
    var player := AudioStreamPlayer.new()
    add_child(player)  # the autoload owns the player node
    provide_audio(LoggingAudio.new(RealAudio.new(player)))

func provide_audio(service: AudioService) -> void:
    audio = service if service != null else NullAudio.new()


# hopper.gd: on any Node in the main scene.
extends Node

const HOP_EVERY := 1.2
var _timer := 0.0
var _hops := 0

func _process(delta: float) -> void:
    _timer += delta
    if _timer < HOP_EVERY:
        return
    _timer -= HOP_EVERY
    _hops += 1
    Services.audio.play("jump")
    if _hops % 3 == 0:
        Services.audio.play("coin")
// Services.cs. Unity 2022 LTS or Unity 6. Needs no GameObject in the scene.
// Optional: Assets/Resources/Sounds/jump.wav and coin.wav.
using UnityEngine;

public interface IAudioService { void Play(string id); }

public class NullAudio : IAudioService
{
    public void Play(string id) { }          // accepts the call, does nothing
}

public class RealAudio : IAudioService
{
    readonly AudioSource source;
    public RealAudio(AudioSource source) { this.source = source; }

    public void Play(string id)
    {
        var clip = Resources.Load<AudioClip>("Sounds/" + id);
        if (clip != null) source.PlayOneShot(clip);
    }
}

public class LoggingAudio : IAudioService
{
    readonly IAudioService inner;
    public LoggingAudio(IAudioService inner) { this.inner = inner; }

    public void Play(string id)
    {
        Debug.Log("[audio] play " + id);
        inner.Play(id);
    }
}

public static class Services
{
    public static IAudioService Audio { get; private set; } = new NullAudio();

    public static void ProvideAudio(IAudioService service) =>
        Audio = service ?? new NullAudio();

    // Runs before any Awake in the first scene, every time Play starts.
    [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSceneLoad)]
    static void Boot()
    {
        var go = new GameObject("Audio");
        Object.DontDestroyOnLoad(go);
        ProvideAudio(new LoggingAudio(new RealAudio(go.AddComponent<AudioSource>())));
    }
}


// Hopper.cs, in its own file. Add to any GameObject and press Play.
using UnityEngine;

public class Hopper : MonoBehaviour
{
    const float HopEvery = 1.2f;
    float timer;
    int hops;

    void Update()
    {
        timer += Time.deltaTime;
        if (timer < HopEvery) return;
        timer -= HopEvery;
        hops++;
        Services.Audio.Play("jump");
        if (hops % 3 == 0) Services.Audio.Play("coin");
    }
}

Pitfalls

  • Empty slots. An empty slot turns every early call into a crash, as the nil option shows. Start each slot with a null service, and make provide fall back to it.
  • Swapping without cleaning up. Replacing a service in the slot does not stop its music or close its files. Give services a shutdown method and call it before you swap.
  • Unity statics that survive Play mode. With domain reload turned off in the Enter Play Mode options, static fields keep their values from the previous run, including a service whose AudioSource was destroyed. Re-provide every service in a BeforeSceneLoad method, or reset statics in one marked RuntimeInitializeLoadType.SubsystemRegistration.
  • The locator as a junk drawer. A class that reaches into the locator for six services hides six dependencies. Keep the locator for a few truly global services.
  • Holding a cached reference. A script that copies Services.audio into a field at startup keeps the old service after a swap. Ask the locator at the moment of the call.

In real games

Godot's own documentation presents autoloads as the way to keep data and systems alive across scene changes, and the engine's editor shows them under the root in the Remote scene tree while the game runs.

In Unity projects, a bootstrap that registers services before the first scene, through a static initialiser or a dedicated startup scene, is a common community pattern.

Robert Nystrom's Game Programming Patterns uses audio as its main example of the Service Locator pattern, including the null service and the logging decorator, and has a separate chapter arguing against overusing singletons.

Your turn (15 minutes)

Find the global object in your project that the most scripts call directly, often audio or saving. Write a small interface for the methods they actually use, a null version, and a locator slot that starts with the null version. Change the callers to go through the slot.

You are done when the scene that uses it most runs on its own, with the real service never registered, without a single error, and when registering a logging wrapper prints every call without any caller being edited.

Takeaways

  • Autoloads and singletons make a system reachable from anywhere, but callers that name the concrete class cannot swap it.
  • A service locator has one slot per role. Callers ask for the role; one place decides which class fills it.
  • Fill every slot with a null service by default, and wrap services with decorators such as logging instead of editing them.
  • Register before anyone asks: Godot autoloads come before the main scene, and Unity's BeforeSceneLoad comes before any Awake.
  • Keep the locator small. For dependencies that belong to one object, pass them in directly.
