Culling: drawing only what the camera sees

How engines skip objects outside the camera with a bounding box test, why that test has its own cost, and how a grid makes it cheaper.

Your level has two thousand props, and the camera shows about two hundred of them at a time. If the engine sent all two thousand to the graphics card every frame, ninety percent of that work would produce pixels nobody sees. It does not, and knowing how it avoids that work tells you when the shortcut breaks: a sprite that pops in late at the edge of the screen, or an enemy that is invisible yet still eats frame time.

Culling is a cheap question asked before an expensive job

Culling means removing objects from the draw list before they are drawn. The most common kind is frustum culling: skip anything outside the camera's view. In 3D the view is a pyramid with its tip cut off, called the frustum. In 2D it is simply a rectangle. The idea is the same in both, so this lesson stays in 2D.

Testing an object's exact shape against the view would cost almost as much as drawing it. Instead every object carries a bounding box: the smallest axis-aligned rectangle that contains everything it could draw. The engine compares boxes, not shapes.

Two boxes do not overlap when one of them is entirely to one side of the other. That gives four comparisons per object, and no square roots or loops:

visible = box.right > view.left and box.left < view.right
      and box.bottom > view.top and box.top < view.bottom

The test is not free

Four comparisons are cheap, but they still run for every object in the scene, every frame, for every camera. With a few thousand sprites that is nothing. With hundreds of thousands of objects in a large open world, the loop over all of them shows up in a profiler before the drawing does. Culling turns "draw everything" into "test everything", and testing everything is the next bottleneck.

The fix is a spatial partition: a structure that sorts objects by where they are, so you can ask "what is near this rectangle?" without looking at everything. The simplest is a uniform grid. Each cell keeps a list of the objects whose boxes touch it. To cull, find the cells the view overlaps and test only the objects in those lists.

What the engines do for you

Both engines frustum-cull automatically. You do not write the loop above in Godot or Unity; you only need to know it is there, because it shapes what you should and should not do.

Godot 4 culls 2D canvas items against the viewport using each item's bounding rectangle, and culls 3D geometry against the camera frustum. To react to visibility in your own code, add a VisibleOnScreenNotifier2D (or the 3D version) with a rect you choose; it emits screen_entered and screen_exited and answers is_on_screen(). Its sibling VisibleOnScreenEnabler2D goes one step further and switches a target node's processing off while it is off screen.

Unity (2022 LTS and Unity 6) culls every Renderer by its bounds, once per camera. A script on the same GameObject receives OnBecameVisible and OnBecameInvisible, and Renderer.isVisible reports the current state. For many objects that have no renderer of their own, the CullingGroup API lets you register bounding spheres and be told when they change visibility.

Culled is not paused

Culling skips the drawing. An off-screen object's scripts, animation and physics keep running unless you, or an option such as Unity's Animator culling mode or Godot's enabler node, stop them. Who owns that decision is you.

The code

A LÖVE 11 program with the demo's numbers: a 2000 by 1200 pixel world, a thousand circles with half-sizes from 4 to 20 pixels, 200 pixel grid cells and an 800 by 600 camera, the size of LÖVE's default window. The random positions differ from the demo's because the generators differ. Press M to cycle between off, every and grid and watch the counters in the corner.

-- main.lua for LÖVE 11. Arrow keys move the camera, M cycles the culling mode.
local WORLD_W, WORLD_H, CELL = 2000, 1200, 200
local COLS, ROWS = WORLD_W / CELL, WORLD_H / CELL     -- 10 by 6 cells
local SPEED = 600
local cam = { x = 1000, y = 600, w = 800, h = 600 }  -- x, y is the centre
local objects, grid = {}, {}
local modes = { "off", "every", "grid" }
local mode = 2
local frame, tested, drawn = 0, 0, 0

local function cellOf(v, cells)
  return math.max(0, math.min(math.floor(v / CELL), cells - 1))
end

function love.load()
  local rng = love.math.newRandomGenerator(7)
  for i = 0, COLS * ROWS - 1 do grid[i] = {} end
  for i = 1, 1000 do
    local o = { x = rng:random() * WORLD_W, y = rng:random() * WORLD_H,
                r = 4 + rng:random() * 16, seen = 0 }
    objects[i] = o
    -- file it in every cell its box touches, not just the cell of its centre
    for cy = cellOf(o.y - o.r, ROWS), cellOf(o.y + o.r, ROWS) do
      for cx = cellOf(o.x - o.r, COLS), cellOf(o.x + o.r, COLS) do
        table.insert(grid[cy * COLS + cx], o)
      end
    end
  end
end

function love.update(dt)
  local k = love.keyboard.isDown
  if k("left") then cam.x = cam.x - SPEED * dt end
  if k("right") then cam.x = cam.x + SPEED * dt end
  if k("up") then cam.y = cam.y - SPEED * dt end
  if k("down") then cam.y = cam.y + SPEED * dt end
  cam.x = math.max(cam.w / 2, math.min(cam.x, WORLD_W - cam.w / 2))
  cam.y = math.max(cam.h / 2, math.min(cam.y, WORLD_H - cam.h / 2))
end

function love.keypressed(key)
  if key == "m" then mode = mode % 3 + 1 end
end

local function visible(o, left, top)
  return o.x + o.r > left and o.x - o.r < left + cam.w
     and o.y + o.r > top and o.y - o.r < top + cam.h
end

local function consider(o, left, top)
  tested = tested + 1
  if visible(o, left, top) then
    drawn = drawn + 1
    love.graphics.circle("fill", o.x, o.y, o.r)
  end
end

function love.draw()
  frame = frame + 1
  tested, drawn = 0, 0
  local left, top = cam.x - cam.w / 2, cam.y - cam.h / 2
  love.graphics.push()
  love.graphics.translate(-left, -top)
  if modes[mode] == "off" then
    for _, o in ipairs(objects) do
      drawn = drawn + 1
      love.graphics.circle("fill", o.x, o.y, o.r)
    end
  elseif modes[mode] == "every" then
    for _, o in ipairs(objects) do consider(o, left, top) end
  else
    for cy = cellOf(top, ROWS), cellOf(top + cam.h, ROWS) do
      for cx = cellOf(left, COLS), cellOf(left + cam.w, COLS) do
        for _, o in ipairs(grid[cy * COLS + cx]) do
          if o.seen ~= frame then          -- in two cells, still tested once
            o.seen = frame
            consider(o, left, top)
          end
        end
      end
    end
  end
  love.graphics.pop()
  love.graphics.print(modes[mode] .. "  tested " .. tested .. "  drawn " .. drawn, 10, 10)
end
# culling_field.gd for Godot 4. Attach to a Node2D in a new scene and run.
# Godot already skips drawing items whose bounds are off screen. The notifiers
# let this script read the same answer. Arrow keys move the camera.
extends Node2D

const WORLD := Vector2(2000, 1200)
const SPEED := 600.0
var camera := Camera2D.new()
var notifiers: Array[VisibleOnScreenNotifier2D] = []
var label := Label.new()

func _ready() -> void:
    var rng := RandomNumberGenerator.new()
    rng.seed = 7
    for i in 1000:
        var r := rng.randf_range(4.0, 20.0)
        var dot := Polygon2D.new()
        dot.polygon = PackedVector2Array([Vector2(-r, -r), Vector2(r, -r), Vector2(r, r), Vector2(-r, r)])
        dot.position = Vector2(rng.randf_range(0.0, WORLD.x), rng.randf_range(0.0, WORLD.y))
        var notifier := VisibleOnScreenNotifier2D.new()
        notifier.rect = Rect2(-r, -r, 2.0 * r, 2.0 * r)   # the box used for the test
        dot.add_child(notifier)
        notifiers.append(notifier)
        add_child(dot)
    camera.position = WORLD / 2.0
    add_child(camera)
    camera.make_current()
    var hud := CanvasLayer.new()
    hud.add_child(label)
    add_child(hud)

func _process(delta: float) -> void:
    camera.position += Input.get_vector("ui_left", "ui_right", "ui_up", "ui_down") * SPEED * delta
    var on_screen := 0
    for n in notifiers:
        if n.is_on_screen():
            on_screen += 1
    label.text = "on screen: %d of %d" % [on_screen, notifiers.size()]
// CullingField.cs. Unity 2022 LTS or Unity 6, 2D template.
// Add it to any GameObject and press Play. Unity culls every Renderer by its
// bounds on its own; isVisible lets the script read the result.
// Uses the Input Manager ("Horizontal" and "Vertical"); if Active Input Handling is
// set to the Input System package only, switch it to Both.
using UnityEngine;

public class CullingField : MonoBehaviour
{
    public int count = 1000;
    public Vector2 worldSize = new Vector2(20f, 12f);   // 100 pixels per unit
    public float cameraSpeed = 6f;
    SpriteRenderer[] renderers;

    void Start()
    {
        // A 1 by 1 unit white square made from Unity's built-in 4 by 4 white texture.
        var sprite = Sprite.Create(Texture2D.whiteTexture, new Rect(0, 0, 4, 4),
                                   new Vector2(0.5f, 0.5f), 4f);
        Random.InitState(7);
        renderers = new SpriteRenderer[count];
        for (int i = 0; i < count; i++)
        {
            var go = new GameObject("Object " + i);
            go.transform.position = new Vector3(Random.Range(0f, worldSize.x),
                                                Random.Range(0f, worldSize.y), 0f);
            go.transform.localScale = Vector3.one * Random.Range(0.08f, 0.4f);
            renderers[i] = go.AddComponent<SpriteRenderer>();
            renderers[i].sprite = sprite;
        }
    }

    void Update()
    {
        var move = new Vector3(Input.GetAxisRaw("Horizontal"), Input.GetAxisRaw("Vertical"), 0f);
        Camera.main.transform.position += move * cameraSpeed * Time.deltaTime;

        int visible = 0;
        foreach (var r in renderers)
            if (r.isVisible) visible++;   // any camera, including the Scene view
        if (Time.frameCount % 30 == 0) Debug.Log($"visible {visible} of {count}");
    }
}

The Godot and Unity versions contain no culling code, only code that reads the engine's answer: there is no loop over boxes of your own. The Godot camera shows the window's size in pixels, so with an 800 by 600 window it matches the Lua camera. Unity's default 2D camera is 10 units tall (1000 pixels at this scale) and starts at the world's corner, so its counts will differ from the Lua program's.

Pitfalls

  • Bounds that are too small. If something draws outside its box, the test can skip it while part of it is on screen. Common causes are shaders that move vertices (wind on grass, a wobble effect), particles that drift far from their emitter, and a hand-sized notifier rect on a large sprite. Make the box cover everything the object can draw. Godot's 3D geometry has an extra_cull_margin for this.
  • Testing points instead of boxes. The "centre only" toggle in the demo shows the result: objects pop in at the edges. Always test the full box.
  • Expecting culling to save update time. A thousand off-screen enemies still run their scripts. If their updates are expensive, pause them with visibility callbacks, but keep anything the player can notice (a timer, a patrol that should arrive on cue) running or simulated cheaply.
  • Visibility in the Unity editor. OnBecameVisible and isVisible count every camera, and in the editor the Scene view is a camera. An object can look "visible" in Play mode only because the Scene view shows it. Test with the Scene view closed or pointed elsewhere.
  • Grids and moving objects. Anything that moves must be taken out of its old cells and filed in new ones when it crosses a border. Engines do this for their own structures; your own grid needs the same bookkeeping.
  • Cell size. Cells much smaller than the view mean many cells to visit and objects listed in several of them. Cells much larger than the view mean testing nearly everything again. A cell somewhere around a quarter of the view, as in the demo, is a reasonable start; measure rather than guess.

In real games

Frustum culling is always on in Godot and Unity. The variations are the extra kinds layered on top.

Occlusion culling skips objects that are inside the view but hidden behind something else, such as rooms behind a wall. Unity can bake occlusion data for a scene, and Godot 4 supports occlusion culling with OccluderInstance3D nodes. Quake precomputed a potentially visible set for each area of a level, a list of which other areas could ever be seen from it, which is the same idea solved ahead of time.

Distance culling drops small objects far from the camera: Godot 4's visibility ranges on 3D geometry and Unity's per-layer cull distances on the camera both do this.

Tile-based 2D games often skip per-object tests completely. Because tiles sit on a grid, the range of visible tiles can be computed directly from the camera rectangle, which is the grid idea from this lesson with one object per cell.

Your turn (15 minutes)

Pick an object in your project that does work every frame, such as an animated enemy or a particle emitter. Give it a visibility check: a VisibleOnScreenNotifier2D in Godot, or OnBecameVisible and OnBecameInvisible in Unity. Print a line each time it enters or leaves the screen, then make its update return early while it is off screen. You are done when the log shows the switch at the moment it crosses the edge, with no visible pop. If it pops, its bounds are too small.

Takeaways

  • Frustum culling skips objects whose bounding box does not overlap the camera view. In 2D the test is four comparisons.
  • Test boxes, not centres, and make each box cover everything the object can draw, or it will pop at the edges.
  • The test itself runs for every object every frame. A spatial partition such as a grid limits it to objects near the view.
  • Godot and Unity cull automatically; you read their answer through VisibleOnScreenNotifier2D or OnBecameVisible and Renderer.isVisible.
  • Culling saves drawing, not updating. Pausing off-screen logic is a separate decision you own.
