Length, distance and scaling: is the enemy in range?

How Pythagoras gives the length of a vector and the distance between two points, what multiplying by a number does, and how to test range without a square root.

Your tower can shoot anything within 5 squares. An enemy walks up and stands 3 squares right and 4 squares down from it. Is it in range? Nothing in the pair (3, 4) says "5", yet that is the answer.

Length: a right-angled triangle in disguise

As in the last two lessons, a vector is a pair of components (x, y), drawn as an arrow, and y grows downwards, as on a screen.

Draw the arrow v = (3, 4). Walk the long way round instead, 3 squares across and then 4 down, and those two walks plus the arrow form a right-angled triangle. The arrow is its longest side.

Pythagoras' theorem says that for a right-angled triangle, the two short sides squared add up to the long side squared. So the length of a vector, also called its magnitude and written |v| ("the length of v"), is:

-- |v| = square root of (x squared + y squared)
local len = math.sqrt(v.x * v.x + v.y * v.y)
-- sqrt(3*3 + 4*4) = sqrt(9 + 16) = sqrt(25) = 5

Negative components do no harm: squaring removes the sign. (−3, 4) has length √(9 + 16) = 5 as well. A length is never negative, and it is zero only for the zero vector (0, 0).

Distance: the length of end minus start

Two lessons ago, end minus start gave the move from one point to another. The distance between two points is simply the length of that move. Tower at (3, 3), enemy at (6, 7):

  1. offset = enemy − tower = (6 − 3, 7 − 3) = (3, 4).
  2. distance = |offset| = √(3² + 4²) = 5.

The order of the subtraction does not matter here: tower − enemy is (−3, −4), which has the same length. Distance has no direction.

Scaling: multiplying by a number

A plain number like 2 or 0.5, as opposed to a vector, is called a scalar, because what it does is scale. To multiply a vector by a scalar k, multiply both components by k:

-- k * v = (k * v.x, k * v.y)
local scaled = { x = 2 * v.x, y = 2 * v.y }
-- 2 * (3, 4) = (6, 8), length sqrt(36 + 64) = sqrt(100) = 10

The length went from 5 to 10: it is multiplied by k too. With k = 0.5 you get (1.5, 2), length 2.5, halfway to the enemy. With k = −1 you get (−3, −4): same length, opposite way. In general the length is multiplied by |k|, the size of k with its sign dropped, and a negative k also reverses the direction. With k = 0 everything collapses to (0, 0).

You already used this. velocity * dt scales a move per second down to a move for this frame.

Range checks without the square root

Back to the tower. "Is the distance at most 5?" can be asked another way: "is the distance squared at most 5 squared?" Both sides are never negative, so squaring them keeps their order. A bigger distance always has a bigger square.

So the test needs only multiplications, no square root:

local dx, dy = enemy.x - tower.x, enemy.y - tower.y
local inRange = dx * dx + dy * dy <= range * range
-- 3*3 + 4*4 = 25 <= 5*5 = 25, so true

The quantity x² + y² is the squared length. Use it whenever you only compare distances: in range or not, which enemy is closest. Take the square root only when you need the real number, for example to show "5 m away" or to move exactly 5 squares.

Rule of thumb

Comparing? Use squared lengths, and square the other side too. Need the actual distance? Take the square root.

The code

Vectors are small tables with x and y, as before. The tower, range and enemies are the same as in the demo, so four of the six enemies are drawn red. The first enemy is the one at (6, 7).

-- Vectors are tables { x = ..., y = ... }. y grows downwards, like LÖVE's screen.
local function sub(a, b)            -- the way from b to a
  return { x = a.x - b.x, y = a.y - b.y }
end

local function scale(v, k)          -- k times v
  return { x = v.x * k, y = v.y * k }
end

local function lengthSquared(v)
  return v.x * v.x + v.y * v.y
end

local function length(v)
  return math.sqrt(lengthSquared(v))
end

local function distance(a, b)
  return length(sub(b, a))
end

local function inRange(a, b, r)     -- no square root needed
  return lengthSquared(sub(b, a)) <= r * r
end

local UNIT = 40                     -- pixels per grid square
local tower = { x = 3, y = 3 }
local range = 5                     -- in squares
local enemies = {
  { x = 6, y = 7 }, { x = 8, y = 2 }, { x = 6, y = 1 },
  { x = 1, y = 7 }, { x = 9, y = 7 }, { x = 1, y = 5 },
}

function love.update(dt)
  for i = 1, #enemies do
    local e = enemies[i]
    e.inRange = inRange(tower, e, range)
  end
end

function love.draw()
  love.graphics.setColor(1, 1, 1)
  love.graphics.circle("line", tower.x * UNIT, tower.y * UNIT, range * UNIT)
  for i = 1, #enemies do
    local e = enemies[i]
    if e.inRange then
      love.graphics.setColor(0.9, 0.25, 0.2)
    else
      love.graphics.setColor(0.5, 0.5, 0.5)
    end
    love.graphics.circle("fill", e.x * UNIT, e.y * UNIT, 8)
  end
  local first = enemies[1]
  local half = scale(sub(first, tower), 0.5)
  love.graphics.setColor(1, 1, 1)
  love.graphics.print(string.format("distance = %.2f, half = (%g, %g), length %.2f",
    distance(tower, first), half.x, half.y, length(half)), 10, 10)
end

The top line should read distance = 5.00, half = (1.5, 2), length 2.50. The circle is drawn in pixels, so its radius is range * UNIT; the test works in squares, so it uses range. Each comparison must use one unit on both sides.

Built-in versions: Godot's Vector2 has length(), length_squared() and distance_to(); Unity's Vector2 has magnitude, sqrMagnitude and Vector2.Distance. Both engines let you write v * 2 to scale.

Pitfalls

  • Squaring one side only. dx * dx + dy * dy <= range compares 25 with 5, and the tower's real reach shrinks to √5, about 2.2 squares. Square both sides, or neither.
  • Squared values do not scale like distances. Twice as far is four times the squared length: 10 squares away is 100, not 50. Never average squared lengths, or add them to normal distances.
  • Adding the components instead. |3| + |4| = 7, not 5. That number is a different kind of distance (it draws a diamond, not a circle) and gets its own lesson later.
  • Negative scale factors. Scaling by −2 doubles the length and flips the arrow. The length is 2 × 5 = 10, never −10, so take the size of k when working out the new length.
  • The zero vector. (0, 0) has length 0 and stays (0, 0) whatever you scale it by. When the enemy stands on the tower, the offset has no direction. That is harmless here, but dividing by this length, which the next lesson does, needs a guard.
  • Performance. A square root costs more than a multiplication, but on modern hardware one call is cheap. The squared test is worth it in tight loops, such as every bullet against every enemy, and it is no harder to write.

In real games

Distance checks are everywhere a game asks "near enough?": tower and turret range, the radius at which an enemy notices you, pickups that fly towards a player within a few metres, and doors or prompts that appear when you walk close. Unity's documentation for sqrMagnitude and Godot's for length_squared() both point out that the squared version is the cheaper one to use when you only compare.

Scaling shows up as soon as anything moves: velocity times delta time, a dash that moves twice the walk speed, a knockback scaled by damage, or a sprite drawn at half size.

Takeaways

  • The length of (x, y) is √(x² + y²), from Pythagoras. (3, 4) has length 5.
  • The distance between two points is the length of end minus start, and the order does not matter.
  • k × v multiplies each component by k. The length is multiplied by |k|, and a negative k flips the direction.
  • To compare distances, compare squared lengths with squared limits: dx² + dy² ≤ r². No square root needed.
