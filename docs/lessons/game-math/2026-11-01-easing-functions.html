Easing functions: why does my menu slide in like a robot?

How ease-in, ease-out, back and bounce curves reshape the 0 to 1 fraction of a timed move so that menus, pickups and cameras move with character.

The pause menu slides in from the left in half a second. It arrives on time, but it moves like a machine part: full speed on the first frame, a dead stop on the last. Yesterday smoothstep fixed one kind of move. Today we open the toolbox: curves that start slow, end slow, overshoot, or bounce.

One slot, many curves

A timed move has a fraction of time passed, t, from 0 to 1, and lerp turns it into a position: lerp(a, b, t) = a + (b - a) * t, where a is the start and b is the end.

An easing function is any function that sits between the timer and lerp. It takes t and returns a new fraction, e. 0 must go to 0 and 1 to 1, so the move still starts at a and ends at b on time. In between, anything goes:

x = lerp(a, b, ease(t))

On a graph with t across and e upwards, a flat stretch means slow movement and a steep stretch means fast movement. The straight diagonal is plain lerp, called linear.

Ease-in: slow start

The simplest curve is t times t, written t². In words, multiply the fraction by itself. Worked example at t = 0.5, half the time: e = 0.5 × 0.5 = 0.25. Halfway through the time the object has covered only a quarter of the way, so it starts gently and finishes fast. This is ease-in: "in" names the start of the motion. Multiplying three times, t³, gives a stronger ease-in called cubic: at t = 0.5 it gives 0.125.

Ease-out: the mirror

To get a slow finish, run ease-in backwards. Turn the time around with 1 − t, apply ease-in, and turn the result around again with 1 minus it:

easeOut(t) = 1 - easeIn(1 - t)       -- so for t²:  1 - (1 - t) * (1 - t)

Worked example at t = 0.5: 1 − t = 0.5, squared is 0.25, and 1 − 0.25 = 0.75. A fast start that settles softly. This is ease-out, the usual choice for things that arrive, such as menus and pop-ups.

Ease-in-out: both halves

Ease-in-out runs ease-in, squashed into the first half of the time and the way, then ease-out for the rest. For the square curve:

if t < 0.5 then e = 2 * t * t else e = 1 - 2 * (1 - t) * (1 - t) end

Worked example at t = 0.25: 2 × 0.25 × 0.25 = 0.125. At t = 0.5 both halves give 0.5, so they join without a jump.

Back: overshoot and return

A curve may leave the 0 to 1 band in the middle, as long as it ends at 1. Back shoots past the end and returns, like a panel that slides slightly too far. The common version uses a strength s and the shifted time u = t − 1:

e = 1 + (s + 1) * u * u * u + s * u * u

Worked example with s = 2 and t = 0.5, so u = −0.5: u³ = −0.125 and u² = 0.25, so e = 1 + 3 × (−0.125) + 2 × 0.25 = 1 − 0.375 + 0.5 = 1.125. Halfway through, the panel is 12.5 percent past its target. With s = 0 the curve is exactly ease-out cubic, 1 − (1 − t)³. The usual value is s = 1.70158, which peaks at 1.1, a 10 percent overshoot, at about t = 0.58.

Bounce: landing on the floor

Bounce treats e = 1 as the floor: the object falls onto it, hops, lands, hops smaller, and settles. The floor is at the top of the graph, so each hop is a dip below 1. The curve is four pieces of the U-shaped parabola t². The first rises from 0 to 1; each later one dips, to 0.75, then 0.9375, then 0.984375, and returns to 1. Each piece is 7.5625 × (t − c)² + h, where c is the middle of the piece and h its lowest value.

Worked example at t = 0.5, which falls in the second arc. Its middle is c = 1.5 / 2.75, about 0.545, and h = 0.75. So t − c is about −0.045, squared is about 0.00207, times 7.5625 is 0.015625, and e = 0.75 + 0.015625 = 0.765625: in the air after the first bounce.

Clamp t, not e

Clamp t to 0 to 1 before calling any easing function: outside that range the formulas run off. Ease-in at t = 1.5 gives 2.25, and bounce at t = 1.5 gives about 3.23. But do not clamp the result of back: going above 1 is the whole point.

The code

A small easing library in plain Lua with the same names and numbers as the demo, then a pause menu in LÖVE that slides in with outBack when you press Escape. Swap the easing name to try the others.

-- Each easing takes t in 0..1 and returns the shaped fraction.
local ease = {}
function ease.linear(t)    return t end
function ease.inQuad(t)    return t * t end
function ease.outQuad(t)   return 1 - (1 - t) * (1 - t) end
function ease.inCubic(t)   return t * t * t end
function ease.outCubic(t)  return 1 - (1 - t) * (1 - t) * (1 - t) end
function ease.inOutQuad(t)
  if t < 0.5 then return 2 * t * t end
  return 1 - 2 * (1 - t) * (1 - t)
end

local BACK = 1.70158                -- overshoot of about 10 percent
function ease.outBack(t)
  local u = t - 1
  return 1 + (BACK + 1) * u * u * u + BACK * u * u
end

function ease.outBounce(t)
  local n, d = 7.5625, 2.75
  if t < 1 / d then return n * t * t end
  if t < 2 / d then t = t - 1.5 / d; return n * t * t + 0.75 end
  if t < 2.5 / d then t = t - 2.25 / d; return n * t * t + 0.9375 end
  t = t - 2.625 / d
  return n * t * t + 0.984375
end

-- Clamp t (never the result), then lerp with the eased fraction.
local function tween(from, to, elapsed, duration, easing)
  if duration <= 0 then return to end                -- avoid dividing by 0
  local t = math.max(0, math.min(1, elapsed / duration))
  return from + (to - from) * easing(t)
end

print(ease.outQuad(0.5), ease.outBack(0.5), ease.outBounce(0.5))
-- 0.75   about 1.0877   0.765625

-- Screen coordinates: x grows right, y grows down, as in LÖVE.
local menuX, elapsed, open = -200, 0, false
function love.keypressed(key)
  if key == "escape" then open = not open; elapsed = 0 end
end
function love.update(dt)
  elapsed = elapsed + dt
  if open then
    menuX = tween(-200, 40, elapsed, 0.5, ease.outBack)
  else
    menuX = tween(40, -200, elapsed, 0.3, ease.inQuad)
  end
end
function love.draw()
  love.graphics.rectangle("fill", menuX, 100, 180, 240)
end

Built-in versions: Godot's Tween takes a curve family and a direction, for example set_trans(Tween.TRANS_BACK) with set_ease(Tween.EASE_OUT). Unity has no easing list in Mathf apart from Mathf.SmoothStep; an AnimationCurve lets you draw your own curve and read it with Evaluate(t).

Pitfalls

  • Mixing up "in" and "out". Ease-in is slow at the start, ease-out is slow at the end. Check with t = 0.5: ease-in gives less than 0.5, ease-out gives more.
  • Not clamping t. When the timer runs past the duration, ease-in and bounce shoot far past 1, and the menu flies off screen. Clamp t to 0 to 1 first, as tween does.
  • Clamping the result of back. Clamping e to 1 cuts off the overshoot. For values that cannot exceed 1, such as opacity, choose a curve that stays in range instead.
  • A duration of zero. elapsed / duration divides by zero. The guard in tween jumps straight to the end instead.
  • Interrupted moves. If the player closes the menu halfway through opening, the code above starts the closing tween from 40 and the menu jumps. Start from the current position instead.
  • Easing a position every frame. Easing shapes the fraction of a timed move. Following a moving target needs exponential smoothing, the next lesson.

In real games

Easing is everywhere in game interfaces: menus that slide and settle, buttons that grow when selected, damage numbers that pop up and fade. Back suits things that pop into place, bounce suits things that drop and land.

The names come from Robert Penner's easing equations, published for Flash animation and followed by most tweening libraries since. Godot's Tween includes back, bounce, elastic and more. On the web, CSS has the keywords ease-in, ease-out and ease-in-out, which are defined as cubic Bezier curves, a curve type later in this track.

You are done when the object still arrives exactly on time with every curve, and letting the timer run long past the duration leaves it resting at its target. For a bonus, make a pickup pop in by using tween(0, 1, elapsed, 0.4, ease.outBack) as its scale, and check that it peaks at about 1.1 times full size.

Takeaways

  • An easing function reshapes the fraction t: lerp(a, b, ease(t)). It keeps 0 at 0 and 1 at 1.
  • Ease-in (t × t) starts slow, ease-out (1 − (1 − t)²) ends slow, and ease-out is ease-in run backwards.
  • Ease-in-out uses ease-in for the first half of the time and ease-out for the second.
  • Back overshoots on purpose; with s = 1.70158 it peaks at 1.1. Bounce is four arcs that each touch 1.
  • Clamp t before easing, never the result, and guard against a zero duration.
