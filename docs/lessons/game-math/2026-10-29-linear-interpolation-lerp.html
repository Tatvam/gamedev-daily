Linear interpolation: how does a door slide open in exactly one second?

How lerp(a, b, t) = a + (b − a) × t blends a position, a size and a colour between two values with one number t from 0 to 1.

A sliding door is closed at x = 2 and open at x = 10, and it should take exactly one second to open. A pickup should grow as it flies to the player. A screen should fade from blue to orange as the sun sets. Three different jobs, but each one is the same question: where are you between a start and an end?

One tiny function answers all three. It is called linear interpolation, nearly always shortened to lerp.

One number that says how far along

Describe progress with a single number called t. At the start, t = 0. At the end, t = 1. Halfway, t = 0.5, and a quarter of the way, t = 0.25. The name t comes from "time", because t is very often a fraction of a duration, but it can be any fraction of the way.

The same t can drive many things at once. The picture shows one t moving a number, a size and a colour together.

The formula

Call the start value a and the end value b. The distance from one to the other is the gap, b − a. To go a fraction t of the way, take that fraction of the gap and add it to the start:

lerp(a, b, t) = a + (b - a) * t

Worked example, the door from a = 2 to b = 10 at t = 0.25:

  1. The gap: 10 − 2 = 8.
  2. A quarter of the gap: 8 × 0.25 = 2.
  3. Add it to the start: 2 + 2 = 4.

Check the ends. At t = 0 the gap is multiplied by zero, so the answer is a, which is 2. At t = 1 you add the whole gap and get b, which is 10.

The same formula is often written as a * (1 - t) + b * t. It gives the same answer, and reads as a mix: with t = 0.25 you take 75 percent of a and 25 percent of b.

Positions: lerp each component

A position has two numbers, so lerp them one at a time with the same t. From A = (2, 6) to B = (10, 2) at t = 0.25:

  • x: 2 + (10 − 2) × 0.25 = 2 + 2 = 4
  • y: 6 + (2 − 6) × 0.25 = 6 − 1 = 5

So the point is (4, 5). This is the vector subtraction from earlier lessons in disguise: B − A is the arrow from A to B, and A + (B − A) × t walks a fraction t along that arrow. Every point you get for t between 0 and 1 lies on the straight segment from A to B, which is why the method is called linear. As in the earlier lessons, this lesson and its demo use y pointing down, as on a screen and in LÖVE.

Sizes and colours

A size is one number, so it is one lerp: a radius from 0.4 to 1.2 at t = 0.5 is 0.4 + 0.8 × 0.5 = 0.8. A colour is three numbers, red, green and blue, each from 0 to 1 as LÖVE uses them. Lerp each channel separately. From blue (0.2, 0.4, 1.0) to orange (1.0, 0.6, 0.0) at t = 0.5 gives (0.6, 0.5, 0.5).

Where t comes from

To make something take a fixed time, count the seconds since it started and divide by the duration: t = elapsed / duration. The door that takes one second is at t = 0.25 after a quarter of a second, wherever it is and whatever the frame rate. Once elapsed passes the duration, t goes above 1, so you clamp it: limit it to the range 0 to 1.

local t = math.min(elapsed / DURATION, 1)
door.x = lerp(CLOSED_X, OPEN_X, t)

t outside 0 to 1

Nothing in the formula stops at the ends. At t = 1.5 the door from 2 to 10 is at 2 + 8 × 1.5 = 14, past the open position. At t = −0.5 it is at −2. Going beyond the ends is called extrapolation. Sometimes you want it, for an overshoot; usually you want a clamp.

The code

The same dot as the demo, with the same numbers. It travels from A to B in two seconds, waits one second, and starts again. lerp is the line that matters; everything else is lerp applied to more numbers.

-- Positions are in grid units. y grows downwards, as on LÖVE's screen.
local UNIT = 40                            -- pixels per grid unit

-- Blend from a to b. t = 0 gives a, t = 1 gives b, t = 0.5 is halfway.
local function lerp(a, b, t)
  return a + (b - a) * t
end

-- Keep t between 0 and 1.
local function clamp01(t)
  return math.max(0, math.min(1, t))
end

-- Blend two points one component at a time.
local function lerpPoint(p, q, t)
  return { x = lerp(p.x, q.x, t), y = lerp(p.y, q.y, t) }
end

-- Blend two colours { r, g, b }, each channel from 0 to 1.
local function lerpColor(c1, c2, t)
  return { lerp(c1[1], c2[1], t), lerp(c1[2], c2[2], t), lerp(c1[3], c2[3], t) }
end

local A, B = { x = 2, y = 6 }, { x = 10, y = 2 }
local SIZE_A, SIZE_B = 0.4, 1.2            -- radius in grid units
local COLOR_A, COLOR_B = { 0.2, 0.4, 1.0 }, { 1.0, 0.6, 0.0 }
local DURATION = 2                         -- seconds from A to B
local elapsed = 0

-- Check: prints 4  5, then 0.6  0.5  0.5
local check = lerpPoint(A, B, 0.25)
print(check.x, check.y)
local mid = lerpColor(COLOR_A, COLOR_B, 0.5)
print(mid[1], mid[2], mid[3])

function love.update(dt)
  elapsed = elapsed + dt
  if elapsed > DURATION + 1 then           -- wait 1 s at B, then start again
    elapsed = 0
  end
end

function love.draw()
  local t = clamp01(elapsed / DURATION)
  local pos = lerpPoint(A, B, t)
  local size = lerp(SIZE_A, SIZE_B, t)
  local col = lerpColor(COLOR_A, COLOR_B, t)
  love.graphics.setColor(col[1], col[2], col[3])   -- LÖVE 11 and later: 0 to 1
  love.graphics.circle("fill", pos.x * UNIT, pos.y * UNIT, size * UNIT)
  love.graphics.setColor(1, 1, 1)
  love.graphics.print(string.format("t = %.2f", t), 10, 10)
end

Built-in versions: Godot has lerp(from, to, weight), Vector2.lerp and Color.lerp, which do not clamp. Unity has Mathf.Lerp, Vector2.Lerp and Color.Lerp, which clamp t to 0 to 1, and Mathf.LerpUnclamped when you want extrapolation.

Pitfalls

  • Forgetting to clamp. elapsed / duration keeps growing after the end, so the door slides through the wall. Clamp t, or stop updating once t reaches 1. Watch for the other end too: a size lerped with t = −1 gives 0.4 − 0.8 = −0.4, a negative radius, and colour channels outside 0 to 1, such as 1.4 red at t = 1.5.
  • Dividing by a zero duration. lerp itself never divides, so A equal to B is safe: every t gives A. But elapsed / duration with a duration of 0 divides by zero. Treat a zero duration as "already finished" and use t = 1.
  • Lerping towards a moving target with a fixed t every frame. x = lerp(x, target, 0.1) is a different tool. It never quite arrives, and it moves faster at higher frame rates. It is exponential smoothing, and it gets its own lesson soon.
  • Lerping angles. Blending 170 degrees towards −170 by plain lerp passes through 0, the far side of the circle. Use a + angleDiff(a, b) * t from the angle wrapping lesson, so the blend goes the short way.
  • A muddy middle. Lerping red, green and blue separately between two very different colours can pass through a dull grey, as blue to orange does at t = 0.5 here. If that looks wrong, add a third colour in the middle and lerp in two halves.
  • Not landing exactly on b. With decimals, a + (b - a) * t at t = 1 can be off by a rounding error when a and b are very different in size: lerp(-1e10, 0.1, 1) gives about 0.1000004. The form a * (1 - t) + b * t gives exactly b at t = 1. For ordinary game numbers either is fine.

In real games

Lerp is everywhere. Doors, lifts and moving platforms slide between two positions with t from a timer. Health bars draw their width as a lerp from empty to full. Fades to black lerp an alpha value, the opacity, from 0 to 1, and cross-fading music lerps two volumes in opposite directions. Tweening libraries, which animate a value from one number to another over time, are typically built on lerp with an easing curve applied to t.

It also hides inside engines. The physics topic's fixed timestep lesson draws objects at previous + (current - previous) * alpha, a lerp between the last two physics states. Shaders have it built in as mix(x, y, a) in GLSL.

Your turn (15 minutes)

Give a health bar in your own project a smooth drain. When the player takes damage, remember the old health, the new health and set a timer to 0. Each frame, add dt to the timer, compute t = clamp01(timer / 0.3) and draw the bar with width lerp(oldHealth, newHealth, t) * PIXELS_PER_POINT.

You are done when a hit from 100 to 60 health shows the bar at 100 points at 0 s, 80 at 0.15 s, and 60 at 0.3 s and after. For a bonus, make a second hit during the drain start from the value currently shown, lerp(oldHealth, newHealth, t), so the bar never jumps.

Takeaways

  • lerp(a, b, t) = a + (b - a) * t: start at a and add the fraction t of the gap.
  • t = 0 gives a and t = 1 gives b. Always check those two cases.
  • Positions, sizes and colours are lerped one number at a time with the same t.
  • For a fixed duration, use t = elapsed / duration and clamp it to 0 to 1.
  • t outside 0 to 1 extrapolates past the ends; clamp unless you want an overshoot.
