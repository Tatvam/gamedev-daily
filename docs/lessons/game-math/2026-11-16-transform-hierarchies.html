Transform hierarchies: how does the hand follow the elbow?

How storing each part relative to its parent makes a whole robot arm follow its shoulder, and how one multiply per part turns that into world positions.

You rotate a robot's shoulder and the upper arm swings round, but the forearm and the hand stay floating in mid-air. Or you drive a tank forward and its turret stays behind on the road. Every part has its own position and angle, and nothing tells the hand that it belongs to the arm.

This lesson fixes that by storing each part relative to the part it hangs from.

Each part remembers where it sits on its parent

As in the last two lessons, y points down, as on a screen and in LÖVE, so a positive angle turns clockwise. One grid square is one unit.

Our robot arm has four parts: a base, an upper arm, a forearm and a hand. The forearm hangs from the upper arm: the upper arm is its parent, the forearm its child. A part with no parent, here the base, is a root. Parents, children and children's children form a family tree, called a transform hierarchy or scene graph.

Instead of storing where the forearm is in the world, we store where it is on the upper arm: "4 units along its x arrow, turned 90 degrees from it". That is the forearm's local transform: a position and angle measured with the parent's arrows, from the parent's origin. Where the part ends up on the screen is its world transform.

The local transform never changes when the shoulder turns: the elbow is always at the end of the upper arm, wherever it points.

From local to world: one multiply per part

To place a child, first put it on its parent as if the parent sat at the origin (the local transform), then carry it wherever the parent went (the parent's world transform). "B first, then A" is the product A × B, so:

child world = parent world × child local

Here "×" is the matrix multiply from last lesson, and each local transform is built the usual way, Move × Rotate. Apply this from the root downwards and the hand's world transform becomes the whole chain:

hand world = base local × upper local × forearm local × hand local

Read it right to left, as always: the hand is placed on the forearm, the forearm (carrying the hand) on the upper arm, and so on out to the world.

Worked example

The numbers from the diagram. The base sits at (3, 8) and does not turn.

  • Upper arm: no move, turn −90°. Its world angle is −90°, so its x arrow points straight up, (0, −1). Its origin is the base, (3, 8).
  • Forearm: 4 along the upper arm's x arrow is 4 × (0, −1) = (0, −4), added to (3, 8): the elbow is at (3, 4). It turns 90° from its parent, so its world angle is −90 + 90 = 0°: it points right.
  • Hand: 3 along the forearm's x arrow (1, 0) from (3, 4) puts the wrist at (6, 4). World angle 0 + 45 = 45°, so a hand 1.5 long ends at (6 + 1.5 × 0.707, 4 + 1.5 × 0.707) ≈ (7.06, 5.06).

Check the forearm with the matrices. Upper arm world has a = cos(−90°) = 0, b = sin(−90°) = −1, c = 1, d = 0, tx = 3, ty = 8. Forearm local, move (4, 0) then turn 90°, has a = 0, b = 1, c = −1, d = 0, tx = 4, ty = 0. Multiplying gives a = 0 × 0 + 1 × 1 = 1, b = 0, c = 0, d = 1, tx = 0 × 4 + 1 × 0 + 3 = 3, ty = −1 × 4 + 0 × 0 + 8 = 4. No rotation, origin at (3, 4): the same answer.

Shortcut without scale

When nothing in the chain is scaled, the world angle of a part is just the sum of the local angles above it: −90 + 90 + 45 = 45 for the hand. Its position is the parent's position plus the local position turned by the parent's world angle. The matrix version does the same work and also handles scale.

Now turn the shoulder by 30°. Only the upper arm's local angle changes, yet the elbow, wrist and hand all swing with it, because each is built on top of the upper arm.

The code

Each part is a table with a parent, a local position, angle and length. Parts are listed parents first, so one loop updates them all. The matrix helpers are from the last two lessons; the numbers are the demo's starting values.

-- y grows downwards, so a positive angle turns clockwise.
local function makeMove(tx, ty) return { a = 1, b = 0, c = 0, d = 1, tx = tx, ty = ty } end
local function makeRotate(angle)
  local cosA, sinA = math.cos(angle), math.sin(angle)
  return { a = cosA, b = sinA, c = -sinA, d = cosA, tx = 0, ty = 0 }
end

-- multiply(A, B) means "B first, then A".
local function multiply(A, B)
  return {
    a = A.a * B.a + A.c * B.b,  c = A.a * B.c + A.c * B.d,
    b = A.b * B.a + A.d * B.b,  d = A.b * B.c + A.d * B.d,
    tx = A.a * B.tx + A.c * B.ty + A.tx,
    ty = A.b * B.tx + A.d * B.ty + A.ty,
  }
end

local function transformPoint(m, x, y)
  return m.a * x + m.c * y + m.tx, m.b * x + m.d * y + m.ty
end

-- x, y and angle are measured on the parent, not in the world.
local base     = { x = 3, y = 8, angle = 0, length = 0 }
local upperArm = { parent = base,     x = 0, y = 0, angle = math.rad(-90), length = 4 }
local forearm  = { parent = upperArm, x = 4, y = 0, angle = math.rad(90),  length = 3 }
local hand     = { parent = forearm,  x = 3, y = 0, angle = math.rad(45),  length = 1.5 }
local parts = { base, upperArm, forearm, hand }   -- parents before children

local function updateWorld(part)
  local localMatrix = multiply(makeMove(part.x, part.y), makeRotate(part.angle))
  if part.parent then
    part.world = multiply(part.parent.world, localMatrix)
  else
    part.world = localMatrix                     -- a root: local is world
  end
end

local function updateAll()
  for _, part in ipairs(parts) do updateWorld(part) end
end

function love.load()
  updateAll()
end

local TURN_SPEED = math.rad(90)                  -- radians per second
local function turn(part, minusKey, plusKey, dt)
  if love.keyboard.isDown(minusKey) then part.angle = part.angle - TURN_SPEED * dt end
  if love.keyboard.isDown(plusKey) then part.angle = part.angle + TURN_SPEED * dt end
end

function love.update(dt)
  turn(upperArm, "q", "a", dt)
  turn(forearm, "w", "s", dt)
  turn(hand, "e", "d", dt)
  updateAll()
end

local UNIT = 40                                  -- pixels per unit
function love.draw()
  for i = 2, #parts do                           -- skip the base, it has no length
    local part = parts[i]
    local x1, y1 = transformPoint(part.world, 0, 0)
    local x2, y2 = transformPoint(part.world, part.length, 0)
    love.graphics.line(x1 * UNIT, y1 * UNIT, x2 * UNIT, y2 * UNIT)
  end
end

With these numbers the hand's end, transformPoint(hand.world, 1.5, 0), is (7.06, 5.06), as in the worked example.

LÖVE can also do the chain for you while drawing. Each love.graphics.push() remembers the current transform, so nesting push, translate and rotate calls follows the tree, and pop() climbs back up to the parent:

love.graphics.push()
love.graphics.translate(upperArm.length * UNIT, 0)   -- inside the upper arm: go to the elbow
love.graphics.rotate(forearm.angle)
drawForearmAtOrigin()                                -- your own function
love.graphics.pop()

Built-in versions: in Godot, a Node2D's position and rotation are local and global_position, global_rotation and global_transform are world. In Unity, transform.localPosition and transform.localRotation are local, transform.position and transform.rotation are world.

Pitfalls

  • Updating a child before its parent. The child is built on last frame's parent transform and trails one frame behind. Keep the list ordered parents first, or update recursively from the root.
  • Angle sums run past 180 degrees. Shoulder 150 + elbow 120 + wrist 90 is a world angle of 360, which is the same as 0. The matrices do not care, but if you compare or display world angles, wrap them first, as in the angle wrapping lesson. The demo shows wrapped world angles.
  • Non-uniform scale on a parent. Stretch the upper arm by (2, 1) and a turned forearm comes out slanted (sheared), as in the last lesson. Scale the drawing of a part, not the part that carries children, or keep parent scales uniform.
  • Zero length and zero scale. A part of length 0, like our base, is fine. A scale of 0 collapses every child into one point and cannot be undone.
  • Reparenting makes things jump. The gem's old position is a world position; used as a local position on the hand it lands somewhere else. The demo snaps the gem into the claw. Keeping it in place needs the inverse transform, next lesson.

In real games

Godot's scene tree and Unity's Hierarchy window are transform hierarchies: drag one object onto another and it becomes a child, and the inspector shows its local position.

Skeletal animation works the same way: a skeleton is a tree of bones, and an animation mostly stores local angles per bone. The 2D tool Spine and the skeletons in Godot and Unity are built on this. You will also meet it in a turret on a tank, a sword in a hand, or a moon orbiting a planet that orbits a sun.

Your turn (15 minutes)

Build a tank from the code above. Make a hull root that you move with the arrow keys, a turret child at local (0, 0) that turns with Q and E, and a barrel child of the turret at local (0.5, 0) with length 2.

When you press space, spawn a bullet at the barrel's end, transformPoint(barrel.world, 2, 0), flying along the barrel's world x arrow, (barrel.world.a, barrel.world.b). You are done when bullets leave the barrel tip in the right direction while the hull drives and the turret turns at the same time.

Takeaways

  • A hierarchy stores each part relative to its parent: a local position and angle, measured with the parent's arrows.
  • Child world = parent world × child local. Down a chain, the matrices multiply from the root to the part.
  • Change one local value and everything below it follows, without touching the children.
  • Update parents before children, and wrap world angles before comparing them.
