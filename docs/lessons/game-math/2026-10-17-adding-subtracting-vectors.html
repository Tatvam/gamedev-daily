Adding and subtracting vectors: paddling across a river

How adding vectors tip to tail combines two movements, and how subtracting them tells you what to add to get the movement you want.

A boat in your game paddles to the right. The river pushes it down the screen at the same time. Where does it actually go? And if there is an island upstream, which way should it paddle so that the river carries it there instead of past it?

Both questions have a one-line answer. The first is an addition, the second a subtraction.

Adding: one movement, then the other

Last lesson, a vector was a pair of components (x, y), pictured as an arrow, and a displacement was an arrow meaning "move this far, this way". Here, as before, y grows downwards: positive y moves down the screen.

Our boat has two velocities, displacements per second:

  • paddle = (3, 0): the paddling moves it 3 squares right each second.
  • current = (1, 2): the river carries it 1 right and 2 down each second.

Picture one move, then the other. Draw the paddle arrow, then draw the current arrow with its tail on the paddle's tip. This is adding tip to tail. The arrow from the first tail to the last tip is the sum, the total movement.

In numbers, add the components separately: x with x, y with y. For two vectors a and b:

-- a + b = (a.x + b.x, a.y + b.y)
local total = { x = paddle.x + current.x, y = paddle.y + current.y }
-- (3 + 1, 0 + 2) = (4, 2)

Every second the boat moves 4 right and 2 down. Start it at (2, 4) and after one second it is at (6, 4 + 2) = (6, 6).

The order does not matter: current + paddle is (1 + 3, 2 + 0), the same (4, 2). In the picture, the two orders trace two sides of a parallelogram and meet at the same corner. Adding the zero vector (0, 0) changes nothing.

Subtracting: what do I need to add?

The negative of a vector, written −b, has every component's sign flipped: same length, opposite way. The negative of the current (1, 2) is (−1, −2), 1 left and 2 up. Paddle with that and you cancel the river.

Subtraction is adding the negative:

-- a - b = a + (-b) = (a.x - b.x, a.y - b.y)
local diff = { x = paddle.x - current.x, y = paddle.y - current.y }
-- (3 - 1, 0 - 2) = (2, -2)

Read a − b as a question: what do I add to b to get a? Check: current + (2, −2) = (1 + 2, 2 − 2) = (3, 0), the paddle. In a picture, draw a and b from the same point; a − b is the arrow from the tip of b to the tip of a.

That is last lesson's "end minus start" again. A position is an arrow from the origin, so island − boat is the arrow from the boat's tip to the island's tip: the move from boat to island.

The boat question, answered

The boat is at (2, 4) and the island at (7, 2). We want to arrive in one second.

  1. The movement we want: wanted = island − boat = (7 − 2, 2 − 4) = (5, −2).
  2. The river gives us the current for free. What must we add to it to get wanted? paddle = wanted − current = (5 − 1, −2 − 2) = (4, −4).
  3. Check by adding: current + paddle = (1 + 4, 2 − 4) = (5, −2). That is wanted, so the boat lands on the island.

The boat aims far more "up" than the island seems to need, because the river keeps dragging it down.

Rule of thumb

Adding answers "where do these movements take me together?" Subtracting answers "what is missing?" Say it as "a minus b is the way from b to a".

The code

LÖVE has no vector type, so vectors are small tables with x and y, using the numbers from the diagram. At the start the boat works out its paddle with two subtractions. Each frame it adds paddle and current to get its velocity, and after one second it lands on the island.

-- Vectors are tables { x = ..., y = ... }. y grows downwards, like LÖVE's screen.
local function add(a, b)
  return { x = a.x + b.x, y = a.y + b.y }
end

local function sub(a, b)                 -- the way from b to a
  return { x = a.x - b.x, y = a.y - b.y }
end

local function neg(v)                    -- same length, opposite way
  return { x = -v.x, y = -v.y }
end

local UNIT = 40                          -- pixels per grid square
local boat     = { x = 2, y = 4 }        -- position, in squares
local island   = { x = 7, y = 2 }        -- position, in squares
local current  = { x = 1, y = 2 }        -- squares per second
local paddle   = { x = 3, y = 0 }        -- replaced in love.load
local timeLeft = 1                       -- sail for one second

function love.load()
  local wanted = sub(island, boat)       -- (5, -2)
  paddle = sub(wanted, current)          -- (4, -4)
end

function love.update(dt)
  if timeLeft <= 0 then return end
  local step = math.min(dt, timeLeft)
  timeLeft = timeLeft - step
  local velocity = add(paddle, current)  -- (5, -2)
  boat.x = boat.x + velocity.x * step
  boat.y = boat.y + velocity.y * step
end

function love.draw()
  love.graphics.circle("line", island.x * UNIT, island.y * UNIT, 12)
  love.graphics.circle("fill", boat.x * UNIT, boat.y * UNIT, 6)
  love.graphics.print(string.format("paddle = (%g, %g)", paddle.x, paddle.y), 10, 10)
end

add(a, neg(b)) gives the same result as sub(a, b), a handy check. Multiplying by step scales a per-second velocity down to one frame; scaling is next lesson's topic.

In Godot and Unity, Vector2 (and Unity's Vector3) already support +, - and unary -, so you write island - boat directly.

Pitfalls

  • Subtracting in the wrong order. current - wanted is (−4, 4), the opposite of the paddle you need. Addition ignores order; subtraction does not: b − a is always −(a − b).
  • Adding different units. Squares per second plus pixels means nothing. Convert first, and add a velocity to a position only after multiplying it by a time, as velocity.x * step does.
  • Mixing y-up and y-down. Gravity is (0, 9.8) with y down and (0, −9.8) with y up. Copy the wrong one and things fall upwards.
  • Lua tables are shared, not copied. local start = boat does not save the start: both names point at one table, so moving the boat moves start. Copy it with { x = boat.x, y = boat.y }. That is why add and sub return new tables.
  • The zero vector is a normal answer. With the island on the boat, wanted is (0, 0) and the paddle is (−1, −2), against the river to stay put. A zero result is not an error, but it has no direction to take.
  • Many small tables. Each add makes garbage to collect. Fine for a few objects; for thousands of bullets per frame, work on the x and y numbers directly.

In real games

Adding velocities combines movements that happen at once: walk speed plus a conveyor belt, wind or a moving platform, with knockback added on top. A camera that follows at a fixed offset sits at player position + offset.

Subtraction shows up as "what I want minus what I have". Craig Reynolds' steering behaviours (1999) are built on it: steering is desired velocity minus current velocity, the same calculation as wanted − current for the boat.

Takeaways

  • Add vectors component by component: (a.x + b.x, a.y + b.y). In a picture, put the second arrow's tail on the first arrow's tip.
  • The order of an addition does not matter, a + b = b + a. The order of a subtraction does.
  • a − b = a + (−b), and it answers "what do I add to b to get a?": the paddle against a current, or a steering force.
  • Drawn from one point, a − b is the arrow from the tip of b to the tip of a, which is why end minus start gives the move between positions.
