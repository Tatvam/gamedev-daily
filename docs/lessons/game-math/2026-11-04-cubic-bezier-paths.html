Cubic Bezier curves: how do I build a smooth flight path?

How four points and six lerps make a curve you shape at both ends, and how to join curves into one path with no kink at the joint.

An enemy fighter should swoop in from the left, climb, dive and climb again before leaving the screen. Yesterday's quadratic curve can only bend one way, so you join several. Wherever two pieces meet, the fighter's nose snaps to a new direction, and players notice.

Two control points per curve, plus one rule at each joint, fix both problems.

Choose how the curve leaves and how it arrives

A quadratic curve has one control point that decides both how the curve leaves the start and how it arrives at the end. A cubic Bezier curve splits that job between two control points, usually called handles:

  • P0 is the start and P3 is the end.
  • P1 is the start handle. The curve leaves P0 heading straight towards it.
  • P2 is the end handle. The curve arrives at P3 coming straight from it.

With both ends steered separately, one cubic can make an S-bend or a loop.

The same lerps, one more round

As before, pick t from 0 (start) to 1 (end). Joining the four points in order gives three straight legs. Then:

  1. Walk t of the way along each of the three legs. That gives three points, A, B and C.
  2. Join A to B and B to C, and walk t of the way along those two lines. That gives D and E.
  3. Walk t of the way from D to E. That point is on the curve.

Four points become three, then two, then one.

Positions are in grid squares and y grows downwards, as in LÖVE, so a smaller y is higher on screen. The example curve starts at P0 = (0, 6), has handles P1 = (2, 0) and P2 = (6, 0), and ends at P3 = (8, 4).

A worked example

Lerp is lerp(a, b, t) = a + (b − a) × t, done for x and y separately. With t = 0.5 every lerp is simply the midpoint:

  • A = midpoint of (0, 6) and (2, 0) = (1, 3); B = midpoint of (2, 0) and (6, 0) = (4, 0); C = midpoint of (6, 0) and (8, 4) = (7, 2)
  • D = midpoint of (1, 3) and (4, 0) = (2.5, 1.5); E = midpoint of (4, 0) and (7, 2) = (5.5, 1)
  • point = midpoint of (2.5, 1.5) and (5.5, 1) = (4, 1.25)

The same thing as one formula

Written out and tidied up, the six lerps become:

point(t) = (1 − t)³ P0 + 3(1 − t)² t P1 + 3(1 − t) t² P2 + t³ P3

Each point gets a weight, and the weights always add up to 1. At t = 0.5 they are 1/8, 3/8, 3/8 and 1/8. For x: (1 × 0 + 3 × 2 + 3 × 6 + 1 × 8) / 8 = 32 / 8 = 4. For y: (1 × 6 + 3 × 0 + 3 × 0 + 1 × 4) / 8 = 10 / 8 = 1.25. The same (4, 1.25). The handle weights never pass 4/9, so the curve leans towards the handles without reaching them.

Which way is the curve heading?

The last orange line, from D to E, touches the curve at the point. So E − D points in the direction of travel. Multiply it by 3 and you get the velocity: how far the point moves per unit of t. At t = 0.5, E − D = (3, −0.5), so the velocity is (9, −1.5): moving right and slightly up.

At t = 0 the velocity is 3 × (P1 − P0), and at t = 1 it is 3 × (P3 − P2). For the example the curve arrives at P3 with velocity 3 × ((8, 4) − (6, 0)) = (6, 12), heading down and to the right.

Joining curves without a kink

A path is several curves where each one starts where the previous one ended. Call the second curve Q0 to Q3, with Q0 = P3, the joint. The first curve arrives along P2 → P3; the second leaves along Q0 → Q1. If those two directions differ, the path has a corner.

The fix is to put Q1 on the far side of the joint, in line with P2. There are two strengths of this rule:

  • Aligned handles point in exactly opposite directions from the joint but may have different lengths. The direction is continuous, so there is no corner, but the speed changes suddenly at the joint.
  • Mirrored handles are also the same length. Then the velocity is the same on both sides, so a ship moving at a steady rate of t keeps its speed too.

Rule of thumb

For a mirrored joint: Q1 = P3 + (P3 − P2) = 2 × P3 − P2. With the example, 2 × (8, 4) − (6, 0) = (10, 8).

The code

The fighter from the demo: two curves, a mirrored joint, 1.5 seconds per curve and 40 pixels per grid square. bezier3 returns the point and the velocity, and the velocity gives the nose direction.

-- Points are tables { x, y }. y grows downwards, like LÖVE's screen.
local function vec(x, y) return { x = x, y = y } end

local function lerpPoint(p, q, t)
  return vec(p.x + (q.x - p.x) * t, p.y + (q.y - p.y) * t)
end

-- Cubic Bezier: three lerps, then two, then one.
-- Returns the point and the velocity (movement per unit of t).
local function bezier3(p0, p1, p2, p3, t)
  local a = lerpPoint(p0, p1, t)
  local b = lerpPoint(p1, p2, t)
  local c = lerpPoint(p2, p3, t)
  local d = lerpPoint(a, b, t)
  local e = lerpPoint(b, c, t)
  return lerpPoint(d, e, t), vec(3 * (e.x - d.x), 3 * (e.y - d.y))
end

-- The handle that makes the next curve leave the joint smoothly.
local function mirrorHandle(handle, joint)
  return vec(2 * joint.x - handle.x, 2 * joint.y - handle.y)
end

local UNIT = 40                                 -- pixels per grid square
local function grid(x, y) return vec(x * UNIT, y * UNIT) end
local c1 = { grid(0, 6), grid(2, 0), grid(6, 0), grid(8, 4) }
local c2 = { c1[4], mirrorHandle(c1[3], c1[4]), grid(14, 8), grid(16, 3) }
local SECONDS_PER_CURVE = 1.5
local s = 0                                     -- 0..1 first curve, 1..2 second
local heading = 0

-- Point and velocity for a path position pos between 0 and 2.
local function pathPoint(pos)
  if pos < 1 then
    return bezier3(c1[1], c1[2], c1[3], c1[4], pos)
  end
  local t = math.min(pos - 1, 1)                -- never past the end
  return bezier3(c2[1], c2[2], c2[3], c2[4], t)
end

function love.update(dt)
  s = s + dt / SECONDS_PER_CURVE
  if s > 2 then s = 0 end
end

function love.draw()
  love.graphics.push()
  love.graphics.translate(40, 60)
  local points = {}
  for i = 0, 64 do                              -- 32 pieces per curve
    local p = pathPoint(i / 32)
    points[#points + 1] = p.x
    points[#points + 1] = p.y
  end
  love.graphics.line(points)
  local p, v = pathPoint(s)
  if v.x ~= 0 or v.y ~= 0 then                  -- keep the old heading if v is zero
    heading = math.atan2(v.y, v.x)
  end
  love.graphics.translate(p.x, p.y)
  love.graphics.rotate(heading)
  love.graphics.polygon("fill", 12, 0, -8, -7, -8, 7)
  love.graphics.pop()
  local speed = math.sqrt(v.x * v.x + v.y * v.y) / UNIT / SECONDS_PER_CURVE
  love.graphics.print(string.format("s = %.2f  (%.2f, %.2f)  speed %.2f squares/s",
    s, p.x / UNIT, p.y / UNIT, speed), 10, 10)
end

At s = 0.5 the printed position is (4.00, 1.25), the worked example. Just before and after the joint the speed is 8.94 squares per second on both sides, because the handles are mirrored.

Built-in versions: Godot 4 has Vector2.bezier_interpolate and a Curve2D resource whose points have in and out handles. LÖVE's love.math.newBezierCurve takes any number of points, so four points make a cubic. We know of no general cubic Bezier function in Unity's core API; nest Vector2.Lerp as above.

Pitfalls

  • Handles lined up by eye. A few degrees off still twitches the nose. Compute the second handle with mirrorHandle.
  • Aligned is not mirrored. With Q1 = (9, 6), half as far from the joint as P2, there is no corner, but the speed drops from 8.94 to 4.47 squares per second the moment the fighter crosses the joint.
  • A handle on top of its end point. If P2 = P3, the velocity at t = 1 is 3 × (P3 − P2) = (0, 0), so there is no direction to point the nose along. Normalising it divides by zero; keep the previous heading, as the code does.
  • Letting t leave 0 to 1. The formula carries on. For the example curve, t = 1.5 gives (9, 12.75), far below the end point. Clamp t, and make sure the path position picks the right curve: in the code, s = 1 is t = 0 on the second curve, which is the same point as t = 1 on the first.
  • Every curve gets the same time. A short curve and a long curve both take 1.5 seconds, so the fighter is slower on the short one. Within one curve, equal steps of t are not equal distances either. The arc length lesson fixes both.
  • Performance. Six lerps per point is cheap, but sample the drawn path once when it changes, not every frame.

In real games

Paths made of joined cubic curves are a common way to script enemy flight in shooters, camera moves along a rail, and the route of a moving platform. Godot's Path2D and Path3D nodes store their shape as a Curve2D or Curve3D with in and out handles on each point, which is the same idea as this lesson.

Outside games, the pen tool in vector programs such as Inkscape edits joined cubic curves with handles, SVG draws them with the C path command, and CSS animation timing uses cubic-bezier(). PostScript and CFF fonts outline letters with cubic curves, where TrueType uses quadratic ones.

Your turn (15 minutes)

Paste the code into a LÖVE project. Check your bezier3 first: with the grid points (0, 6), (2, 0), (6, 0), (8, 4) and t = 0.25 it should give (1.8125, 2.59375). Then add a third curve after the second, starting at (16, 3), whose first handle is mirrorHandle(c2[3], c2[4]) and which ends back at (0, 6), and extend pathPoint to a range of 0 to 3.

You are done when the fighter flies a closed loop, its nose never snaps at either joint, and the printed speed is the same just before and just after each joint. (The end of the third curve meets the start of the first: make that joint smooth too.)

Takeaways

  • A cubic Bezier has a start, an end and two handles: it leaves towards the first handle and arrives from the second.
  • For a given t: three lerps along the legs, two between those points, and one more for the curve point.
  • 3 × (E − D) is the velocity; at the ends it is 3 × (P1 − P0) and 3 × (P3 − P2).
  • Two curves join without a corner when the handles on either side of the joint are in line, and without a speed jump when they are also equal: Q1 = 2P3 − P2.
  • Guard against zero-length handles and t outside 0 to 1.
