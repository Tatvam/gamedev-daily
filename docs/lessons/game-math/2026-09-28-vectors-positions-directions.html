Vectors: a place or a movement?

How one pair of numbers can mean either a place or a movement, how to tell the two apart, and how "end minus start" gives the move from one point to another.

Your level file has a line chest = (6, 2). Your enemy file has a line knockback = (6, 2). Same two numbers. One says where something is, the other says how far something moves.

Mix them up and a hit teleports the player to the corner of the map instead of pushing them back.

One pair of numbers, two meanings

A vector in a 2D game is a pair of numbers written (x, y). The two numbers are its components: x says how far across, y says how far down or up. Picture it as an arrow: x steps across, then y steps along the other axis.

This lesson uses the screen convention from last time: the origin is the top-left, x grows to the right and y grows downwards, as in LÖVE and Godot's 2D. So a negative y means "up the screen".

The arrow can mean two different things:

  • A position is a place. It is the arrow that starts at the origin, (0, 0), and the place is where its tip lands. The chest at (6, 2) is 6 across and 2 down from the origin.
  • A displacement is a movement: how far and which way, with no starting point attached. A knockback of (6, 2) means "6 to the right and 2 down from wherever you are now". Velocities, offsets and directions are all displacements.

The difference is whether the arrow is pinned to the origin. A position always is. A displacement can start anywhere and is still the same vector.

From one place to another: end minus start

The most common question in game code is "how do I get from here to there?": an enemy walking to the player, a bullet flying at a target.

Look at the left of the diagram. The player stands at (2, 5) and the chest is at (6, 2). Count across: from 2 to 6 is 4 steps right. Count down: from 5 to 2 is 3 steps up, and up is negative when y grows downwards, so that part is −3. The move from player to chest is (4, −3).

Each count was "end minus start". Name the pieces: A is the start position, B is the end position, and v is the displacement from A to B. Then, one component at a time:

v.x = B.x - A.x      -- 6 - 2 = 4
v.y = B.y - A.y      -- 2 - 5 = -3

Written as one line, v = B - A. Say it as "the vector from A to B is B minus A". The order matters: A - B gives (−4, 3), the move from the chest back to the player.

Check it by walking it: start at the player and add the move. 2 + 4 = 6 and 5 + (−3) = 2. You land on the chest.

Which combinations make sense

CalculationGivesExample
position − positiona displacementchest − player = the move between them
position + displacementa positionplayer + knockback = where the player lands
displacement + displacementa displacementwalk speed + wind = total velocity
position + positionnothing usefulplayer + chest = a place with no meaning

The last row is the bug from the start of the lesson. One exception comes later: averaging, such as the midpoint (A + B) / 2, is fine.

Rule of thumb

Engines use the same type, such as Vector2, for both meanings, so let the variable name carry the meaning. pos, spawnPoint and target are places. velocity, offset, toTarget and knockback are movements.

The code

LÖVE has no vector type, so a small table with x and y does the job. The numbers are the ones from the diagram and the demo, and 40 pixels are drawn per grid square.

-- Positions: places on the grid (y grows downwards, like LÖVE's screen)
local player = { x = 2, y = 5 }
local chest  = { x = 6, y = 2 }
local UNIT = 40                    -- pixels per grid square

-- The displacement from position a to position b: end minus start
local function vectorFromTo(a, b)
  return { x = b.x - a.x, y = b.y - a.y }
end

-- A zero vector has no direction; check before you rely on one
local function isZero(v)
  return v.x == 0 and v.y == 0
end

function love.draw()
  local move = vectorFromTo(player, chest)          -- (4, -3)

  local ax, ay = player.x * UNIT, player.y * UNIT
  local bx, by = chest.x * UNIT, chest.y * UNIT
  love.graphics.circle("fill", ax, ay, 6)
  love.graphics.circle("fill", bx, by, 6)
  if not isZero(move) then
    love.graphics.line(ax, ay, bx, by)
  end
  love.graphics.print(string.format("move = (%g, %g)", move.x, move.y), 10, 10)
end

In Godot and Unity the vector types already subtract component by component, so the line is simply chest_pos - player_pos in GDScript and chestPos - playerPos in C#, both giving a Vector2.

Pitfalls

  • Subtracting in the wrong order. A - B points from B back to A. If an enemy runs away from the player instead of towards them, check the order first. Say it out loud: end minus start.
  • Forgetting which way y points. With y down, a move of (4, −3) goes up and right. In a y-up world the same numbers go down and right. Copying a direction such as "up is (0, 1)" from a tutorial that uses the other convention flips your game.
  • Adding two positions. The result depends on where the origin is, so it means nothing in the game world.
  • The zero vector. When A and B are the same point, B − A is (0, 0): no distance and no direction. Code that later turns a displacement into a pure direction will divide by its length, which is zero here, and produce nonsense. Check for it, as isZero does.
  • Transforming a direction as if it were a place. Moving an object moves its positions but must not change its directions. Engines have separate functions for each, shown below.

In real games

Chase, aim and camera-follow code all start with end minus start, such as player - enemy or target - turret.

Engines keep one vector type but treat the two meanings differently when converting between spaces. Unity's Transform has TransformPoint for positions and TransformDirection for directions: the first applies the object's position, rotation and scale, the second only its rotation. In Godot, multiplying a Transform2D by a vector treats it as a position, while basis_xform leaves out the translation, which is what a direction needs.

3D graphics writes the difference into the numbers: vectors get a fourth component, w, which is 1 for a position and 0 for a direction, so a 4 by 4 transform matrix moves positions but leaves directions alone.

Your turn (15 minutes)

Paste the code into a new LÖVE project and run it: it should print move = (4, -3). Now make the chest follow the mouse, snapped to whole grid squares like the demo:

function love.update(dt)
  local mx, my = love.mouse.getPosition()
  chest.x = math.floor(mx / UNIT + 0.5)
  chest.y = math.floor(my / UNIT + 0.5)
end

Move the mouse around the player and predict the sign of each component before you read it. Then put the mouse on the player and check that no line is drawn. You are done when your predictions are always right.

Takeaways

  • A vector is a pair of components, (x, y), best pictured as an arrow.
  • A position is an arrow from the origin. A displacement is the same kind of arrow with no fixed start: a movement, velocity or offset.
  • The move from A to B is B − A, one component at a time: end minus start.
  • Position − position gives a displacement; position + displacement gives a position; position + position is almost always a bug.
  • Know which way y points: with y down, negative y means up the screen.
