Sine waves for motion: how do I make a pickup float?

How amplitude, frequency and phase turn math.sin and the clock into bobbing pickups, pulsing gems and swaying plants, with one small Lua function.

You want a coin pickup to float gently, so you write coin.y = baseY + math.sin(time). You run the game and the coin looks frozen. Look very closely and it drifts one pixel up and down, once every six seconds.

Nothing is broken. math.sin needs three numbers from you: how far, how fast, and when. This lesson is about those three numbers.

From a circle to a wave

In the last lesson, the sine of an angle was the y of the point at that angle on the unit circle (the circle of radius 1). Now let the angle grow steadily, write down the sine at every moment, and plot it against the angle. The point going round the circle draws a wave.

Two facts make this wave perfect for motion:

  • It stays between −1 and 1. Whatever it drives never wanders off.
  • It repeats every 2π radians. It loops forever with no seam, and it slows down smoothly at the top and bottom, like a float on water.

Three numbers shape the wave

Here is the formula. Each part is explained below it.

offset = A × sin(2π × f × t + φ)
  • t is the time in seconds, for example since the level started.
  • A, the amplitude, is how far it goes. sin gives −1 to 1, so A × sin gives −A to A.
  • f, the frequency, is how many full waves happen per second. Its unit is the hertz (Hz): 2 Hz means twice a second. The time for one wave is the period, and period = 1 / f.
  • φ (the Greek letter phi), the phase, is an angle in radians added inside. It slides the wave sideways in time without changing its shape.

Why the 2π? One full wave is one trip round the circle, which is 2π radians. To make f trips per second, the angle must grow by 2π × f every second.

Worked example

Take A = 10 pixels, f = 0.5 Hz and φ = 0. The period is 1 / 0.5 = 2 seconds. At t = 0.5 the angle is 2π × 0.5 × 0.5 = π/2, and sin(π/2) = 1, so the offset is 10.

Look at t = 0.25: halfway through the rise in time, the coin has already covered 71 percent of the distance. It moves fastest through the middle and slows near the top. That easing is why a sine float looks soft and a constant-speed bounce looks mechanical.

Now the hook makes sense. math.sin(time) is A = 1 and 2π × f = 1, so f = 1 / 2π ≈ 0.16 Hz: one pixel each way, once every 6.28 seconds.

Up is minus on a screen

The graphs draw up as positive, like a maths book. On a screen, and in LÖVE, y grows downwards. So to make a positive offset lift the coin, subtract it: y = baseY - offset. The demo uses y pointing down for its scene, and this minus sign, so up on the graph is up on the screen.

Not only position

The wave is just a number that swings smoothly. Feed it into anything:

  • Bob: y = baseY - offset, with A in pixels.
  • Pulse: scale = 1 + offset, with A = 0.1 for 10 percent bigger and smaller.
  • Sway: rotation = offset, with A = math.rad(10) for 10 degrees each way.

For a row of identical pickups, give each one its own phase, such as φ = (i − 1) × π/4 for pickup number i. They stop moving in lockstep, and a ripple runs along the row.

Rule of thumb

Choose the period first, in seconds, because that is what you feel when you watch. Then set f = 1 / period. Choose A in the units of the thing you are moving.

The code

A small wave object, used three times: five coins that bob with a ripple, a pulse that changes their size, and a plant that sways. The numbers are the demo's defaults: A = 10 (pixels, percent or degrees), f = 0.5 Hz.

-- offset = amplitude * sin(2 pi * frequency * t + phase)
local TWO_PI = 2 * math.pi

local function newWave(amplitude, frequency, phase)
  return { amplitude = amplitude, frequency = frequency,
           phase = phase or 0, angle = 0 }
end

-- The angle grows by 2 pi * frequency every second. While the frequency stays
-- the same this equals 2 pi * f * t; % keeps the number between 0 and 2 pi.
local function updateWave(w, dt)
  w.angle = (w.angle + TWO_PI * w.frequency * dt) % TWO_PI
end

local function waveValue(w, extraPhase)
  return w.amplitude * math.sin(w.angle + w.phase + (extraPhase or 0))
end

local bob   = newWave(10, 0.5)             -- 10 pixels each way, every 2 seconds
local pulse = newWave(0.10, 0.5)           -- 10 percent bigger and smaller
local sway  = newWave(math.rad(10), 0.5)   -- 10 degrees each way

local coins = {}
for i = 1, 5 do
  coins[i] = { x = 100 + (i - 1) * 60, baseY = 200, radius = 12 }
end

function love.update(dt)
  updateWave(bob, dt)
  updateWave(pulse, dt)
  updateWave(sway, dt)
end

function love.draw()
  for i, c in ipairs(coins) do
    local ripple = (i - 1) * math.pi / 4      -- each coin 45 degrees further along
    local y = c.baseY - waveValue(bob, ripple) -- minus: y grows downwards
    local r = c.radius * (1 + waveValue(pulse, ripple))
    love.graphics.circle("fill", c.x, y, r)
  end

  -- A plant, 70 pixels tall, rocking about its root at (500, 300).
  love.graphics.push()
  love.graphics.translate(500, 300)
  love.graphics.rotate(waveValue(sway))      -- radians, positive is clockwise
  love.graphics.line(0, 0, 0, -70)
  love.graphics.pop()
end

The code adds to the angle every frame instead of computing 2π × f × t from the total time. The result is the same while f stays fixed, and the wave stays smooth when f changes; see the pitfalls. The demo works the same way.

Built-in versions: Godot has sin() and the constant TAU, which equals 2π. Unity has Mathf.Sin and Mathf.PI. Both sine functions take radians.

Pitfalls

  • Forgetting the 2π. math.sin(time * 2) does not mean 2 waves per second. Its period is 2π / 2 ≈ 3.14 seconds. Write 2 * math.pi * f and f really is waves per second.
  • Phase in degrees. math.sin(angle + 90) adds 90 radians, about 14 full turns plus a bit. Use math.pi / 2 or math.rad(90). Phases of −180 and 180 degrees give exactly the same wave.
  • Counting frames instead of seconds. angle = angle + 0.05 every frame runs twice as fast at 120 frames per second as at 60. Always multiply by dt.
  • Changing f with the total-time formula. With sin(2π × f × t), a change in f moves the angle by 2π × (change) × t. At t = 100 seconds, going from 0.5 to 0.505 Hz moves it by π: a coin at the top snaps to the bottom. Adding 2π × f × dt each frame, as in the code, avoids the jump.
  • Frequency zero is not "off". With f = 0 the offset is stuck at A × sin(φ), which is only 0 when φ is 0. Set A to 0 to switch the motion off.
  • Scales through zero. 1 + A × sin goes to 0 and turns negative when A reaches 1. Keep a pulse amplitude below 1. For a value from 0 to 1, such as brightness, use (sin(angle) + 1) / 2.
  • Forgetting the minus. baseY + offset is not wrong, but on a screen with y pointing down the coin starts by moving down.
  • Cost. One math.sin per object per frame is cheap. A few hundred bobbing pickups are not a performance concern.

In real games

Floating collectibles, hovering power-ups and "press a button" prompts that gently grow and shrink are common uses of a sine wave over time. So are idle "breathing" motions on characters and glowing items that brighten and dim.

Foliage that sways in the wind is often done in a vertex shader with the same idea. The time goes into sin, and the world position goes into the phase, so neighbouring plants do not move in lockstep. Exact methods differ from engine to engine and game to game.

Takeaways

  • A sine wave is the height of a point going round a circle. It stays between −1 and 1 and repeats every 2π.
  • offset = A × sin(2π × f × t + φ). A is how far, f is waves per second, φ slides the wave in time.
  • period = 1 / f. Pick the period you want to feel, then work out f.
  • The same wave can drive position, size, rotation or brightness. Give copies different phases so they do not move in lockstep.
  • With y pointing down, subtract the offset to move up. Add 2π × f × dt each frame so frequency changes stay smooth.
