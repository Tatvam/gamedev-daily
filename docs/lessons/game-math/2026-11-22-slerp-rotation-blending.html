Slerp: why does my camera tumble on its way to the new angle?

How slerp blends two quaternion rotations along the shortest arc at a steady speed, and why blending Euler angles or raw numbers wobbles.

A cutscene camera should swing from one shot to the next in two seconds. You lerp its yaw, pitch and roll, and on the way it rolls over and dips its nose before settling. You need a blend that turns the shortest way, at a steady speed.

Three ways to blend two rotations

We have a start pose A, a target pose B, and a number t that goes from 0 to 1 over time, as in the lerp lesson. We want a pose for every t in between. Axes are the same as in the last two lessons: x right, y up, z forward.

1. Lerp the Euler angles

Lerp yaw, pitch and roll one by one. The three turns are stacked in order, so the object does not turn about one steady axis. It wanders.

The worst case: yaw 180°, pitch 180°, roll 180° is the same pose as 0°, 0°, 0°. Each 180° turn flips the sign of two of x, y and z, and together they flip every one twice. Lerping the numbers from (0, 0, 0) to (180, 180, 180) makes the plane tumble through about 233° of turning only to end where it started.

2. Lerp the four quaternion numbers

Yesterday we saw that a rotation quaternion always has length 1. Picture all such quaternions as points on a sphere. It is a sphere in four dimensions, so the diagram uses a circle, which behaves the same way.

Plain lerp walks the straight line, the chord, between the two points. Points on the chord are shorter than 1, so they are not proper rotations. Nlerp (normalised lerp) fixes the length by dividing by it, which pushes each point straight out to the circle. The pose is now valid, but the steps are uneven: short near the ends, long in the middle.

3. Slerp: walk along the arc

Slerp (spherical linear interpolation) moves along the arc itself, so equal steps in t give equal steps of turning. First find how far apart the two points are on the sphere. Call that angle Ω (the Greek capital omega). The dot product from the vectors lessons gives it, now with four numbers:

cos Ω = a.w·b.w + a.x·b.x + a.y·b.y + a.z·b.z

Then mix a and b with two weights that come from sines instead of plain 1 − t and t:

slerp(a, b, t) = a × sin((1 − t)·Ω) / sin Ω  +  b × sin(t·Ω) / sin Ω

Worked example on a circle. a = (1, 0), b = (0, 1), so Ω = 90° and sin Ω = 1. At t = 0.25 the weights are sin 67.5° ≈ 0.924 and sin 22.5° ≈ 0.383, giving (0.924, 0.383): exactly 22.5° round, a quarter of the way. Lerp gives (0.75, 0.25), which has length 0.79 and, once normalised, sits at only 18.4°. Nlerp lags at the start and catches up in the middle.

Worked example with quaternions. A is no turn, (1, 0, 0, 0). B is 90° about up, (0.707, 0, 0.707, 0). The dot product is 0.707, so Ω = 45°. That is half of the 90° turn, because quaternions store half angles. At t = 0.5 both weights are sin 22.5° / sin 45° ≈ 0.383 / 0.707 = 0.541:

w = 0.541 × 1 + 0.541 × 0.707 = 0.924
y = 0.541 × 0 + 0.541 × 0.707 = 0.383

(0.924, 0, 0.383, 0) is cos 22.5° and sin 22.5°: a 45° turn about up. Halfway in time, halfway round.

The short way round

Yesterday's lesson showed that q and −q (every number negated) are the same pose. On the sphere they are opposite points, and slerp only knows about points. Yaw 270° gives B = (−0.707, 0, 0.707, 0), and the dot product with A is −0.707. Slerping straight to it turns 270° to the right. Flip B to (0.707, 0, −0.707, 0), which is −90°, the same pose, and the dot becomes +0.707: now slerp turns 90° to the left.

Rule of thumb

If the dot product is negative, negate B before you slerp. If it is very close to 1, the poses are almost equal and sin Ω is almost 0, so use nlerp instead of dividing by nearly nothing.

The code

Slerp with the sign check and the near-equal fallback, turning from A to the demo's default B in two seconds. Space restarts it.

-- Quaternions are tables { w, x, y, z }. x right, y up, z forward. Degrees.
local function fromAxisAngle(ax, ay, az, degrees)   -- axis of length 1
  local half = math.rad(degrees) / 2
  local s = math.sin(half)
  return { w = math.cos(half), x = ax * s, y = ay * s, z = az * s }
end

local function multiply(a, b)                       -- b first, then a
  return {
    w = a.w * b.w - a.x * b.x - a.y * b.y - a.z * b.z,
    x = a.w * b.x + a.x * b.w + a.y * b.z - a.z * b.y,
    y = a.w * b.y - a.x * b.z + a.y * b.w + a.z * b.x,
    z = a.w * b.z + a.x * b.y - a.y * b.x + a.z * b.w }
end

local function fromEuler(yaw, pitch, roll)          -- roll, then pitch, then yaw
  local q = multiply(fromAxisAngle(0, 1, 0, yaw), fromAxisAngle(1, 0, 0, pitch))
  return multiply(q, fromAxisAngle(0, 0, 1, roll))
end

local function slerp(a, b, t)
  local d = a.w * b.w + a.x * b.x + a.y * b.y + a.z * b.z   -- cos of omega
  if d < 0 then                     -- -b is the same pose: go the short way
    b = { w = -b.w, x = -b.x, y = -b.y, z = -b.z }
    d = -d
  end
  local wa, wb = 1 - t, t            -- almost equal: plain lerp weights
  if d < 0.9995 then
    local omega = math.acos(d)
    local s = math.sin(omega)
    wa = math.sin((1 - t) * omega) / s
    wb = math.sin(t * omega) / s
  end
  local q = { w = wa * a.w + wb * b.w, x = wa * a.x + wb * b.x,
              y = wa * a.y + wb * b.y, z = wa * a.z + wb * b.z }
  local len = math.sqrt(q.w * q.w + q.x * q.x + q.y * q.y + q.z * q.z)
  return { w = q.w / len, x = q.x / len, y = q.y / len, z = q.z / len }
end

local A = fromEuler(0, 0, 0)
local B = fromEuler(150, -60, 120)
local DURATION = 2                    -- seconds for the whole turn
local time = 0
local orientation = A

function love.update(dt)
  time = time + dt
  local t = math.min(time / DURATION, 1)   -- stop at B, do not overshoot
  orientation = slerp(A, B, t)
end

function love.keypressed(key)
  if key == "space" then time = 0 end
end

function love.draw()
  local o = orientation
  love.graphics.print(string.format("q = (%.3f, %.3f, %.3f, %.3f)", o.w, o.x, o.y, o.z), 10, 10)
end

After one second it prints (0.808, −0.408, −0.328, −0.270); at the end (0.306, −0.660, −0.530, −0.436). That is B with every sign flipped, because B's w is negative and the sign check took the short way. Same pose. To draw the dart, rotate its points with yesterday's rotate(q, p).

Built-in versions: Unity has Quaternion.Slerp(a, b, t), which clamps t to 0 to 1. In Godot 4 it is a.slerp(b, t), and both quaternions must be normalised.

Pitfalls

  • No sign check. When the dot product is negative, the turn as stored is more than 180° (yaw 270° is one example), and slerp without the check takes the long way round. The demo's toggle shows it.
  • Dividing by sin Ω near zero. When A and B are almost the same, Ω and sin Ω are almost 0. The fallback to lerp weights avoids it. The same branch catches B = −A: after the flip they are equal, which is correct, because they are the same pose.
  • t outside 0 to 1. The formula keeps going: slerping a 90° turn with t = 1.5 gives a 135° turn. That can be useful for overshoot, but usually you want to clamp t, as the code does. Unity's Slerp clamps; SlerpUnclamped does not.
  • Inputs that are not length 1. The dot product is then not cos Ω, and math.acos of a number above 1 gives NaN (not a number). Normalise A and B first.
  • Slerping towards a moving target each frame. current = slerp(current, target, 0.1) depends on the frame rate. Use 1 - math.exp(-speed * dt) as t, as in the exponential smoothing lesson.
  • Slerp is not always needed. For a 30° turn, nlerp is never more than 0.03° away from slerp; for 90°, under 1°; for 180°, about 8°. Nlerp is cheaper, so small blends often use it.

In real games

Unity offers both Quaternion.Slerp and Quaternion.Lerp; its documentation describes Lerp as interpolating and then normalising, which is nlerp. Godot's Quaternion has slerp, and Unreal Engine's FQuat has a Slerp function.

Typical uses: turning a camera between two shots, turning a turret or ship to a new heading, and blending animation poses bone by bone.

Your turn (15 minutes)

Build a security camera that sweeps between two poses. Set A = fromEuler(-60, 20, 0) and B = fromEuler(60, 20, 0): looking left and right, tipped 20° down. Every 3 seconds swap which one is the start. Feed smoothstep(t) from the smoothstep lesson into slerp so the camera eases in and out at each end.

You are done when the camera sweeps back and forth without rolling. Check by hand: at t = 0.5, slerp(A, B, 0.5) should print (0.985, 0.174, 0, 0), which is fromEuler(0, 20, 0): straight ahead and 20° down.

Takeaways

  • Lerping Euler angles makes the object wander and can tumble it a long way, even between equal poses.
  • Lerping the four quaternion numbers cuts across the sphere; normalising (nlerp) fixes the length but not the uneven speed.
  • Slerp walks the arc: find Ω from the 4D dot product, then weight a and b by sin((1 − t)·Ω) and sin(t·Ω), divided by sin Ω.
  • Negate B when the dot product is negative, so the turn goes the short way.
  • When the dot product is almost 1, use lerp weights to avoid dividing by nearly zero, and clamp t to stop at B.
