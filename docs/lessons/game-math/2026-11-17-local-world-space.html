Local space and world space: where is the click, as seen by the ship?

How the inverse transform turns a world position into an object's own coordinates, so a rotated ship can tell ahead from behind and test clicks on its hull.

Your ship is turned 37 degrees and the player clicks near it. Did the click land on the hull? In world coordinates the hull is a tilted rectangle, which is awkward to test. From the ship's own point of view it is a straight box, and the test is two comparisons.

One point, two descriptions

As in the last three lessons, y points down, as on a screen and in LÖVE, so a positive angle turns clockwise. One grid square is one unit.

World space is the shared grid every object lives on. Local space (or object space) is a grid that belongs to one object: its origin is the object's centre, and its arrows turn and stretch with the object. Our ship carries a local x arrow that points out of its nose and a local y arrow that points out of its right side.

The point P below has two addresses: world (5, 7), and for the ship "4 along my x arrow, then 2 along my y arrow", local (4, 2).

Local to world: you already know this

The ship's transform matrix M stores its position, angle and scale. Multiplying a local point by M gives the world point: start at the ship and walk along its arrows, (0.8, 0.6) for x and (−0.6, 0.8) for y:

world = (3, 3) + 4 × (0.8, 0.6) + 2 × (−0.6, 0.8)
      = (3 + 3.2 − 1.2, 3 + 2.4 + 1.6) = (5, 7)

World to local: undo the steps in reverse

The ship's matrix was built as Move × Rotate × Scale: scale first, then rotate, then move. To go back, undo each step, last one first. You take off your shoes before your socks.

  1. Undo the move. Subtract the ship's position: (5, 7) − (3, 3) = (2, 4). This is the arrow from the ship to P, still measured on the world grid.
  2. Undo the turn. Ask how far that arrow reaches along each of the ship's arrows. That question is the dot product from the dot product lesson: with an arrow of length 1, the dot product measures "how far along it".
    local x = (2, 4) · (0.8, 0.6) = 1.6 + 2.4 = 4
    local y = (2, 4) · (−0.6, 0.8) = −1.2 + 3.2 = 2
  3. Undo the scale. Divide both by the ship's scale. Here it is 1, so P is at local (4, 2). For a ship scaled by 2 it would be (2, 1).

Now the questions get easy. Local x is positive, so P is ahead of the ship. Local y is positive, so P is on its right (with y pointing down; flip that for y-up). On the hull means local x between −1.5 and 1.5 and local y between −1 and 1.

The general tool: the inverse matrix

The matrix that undoes M is its inverse, written M⁻¹ and read "M inverse". Multiply them together, in either order, and you get the identity, the matrix that changes nothing. For our six-number 2D matrix it takes one number first, the determinant, which says how much the matrix scales areas:

det = a × d − b × c

a' =  d / det     c' = −c / det     tx' = −(a' × tx + c' × ty)
b' = −b / det     d' =  a / det     ty' = −(b' × tx + d' × ty)

Worked example: the ship's M has a = 0.8, b = 0.6, c = −0.6, d = 0.8, tx = 3, ty = 3. Then det = 0.64 + 0.36 = 1, so a' = 0.8, b' = −0.6, c' = 0.6, d' = 0.8, tx' = −(2.4 + 1.8) = −4.2 and ty' = −(−1.8 + 2.4) = −0.6. Apply it to (5, 7):

local x = 0.8 × 5 + 0.6 × 7 − 4.2 = 4
local y = −0.6 × 5 + 0.8 × 7 − 0.6 = 2

The same (4, 2). The recipe is easier to picture; the inverse also handles stretched scale and chains of parents, so it is what goes in code.

Rule of thumb

Many questions are easy in one space and messy in the other. Move the point into the space where the question is easy, answer it, and move the answer back out if you need it.

The code

The ship's matrix, its inverse, and a mouse test against the hull. The numbers are the demo's starting values. transformPoint is the one from the last lessons.

-- y grows downwards, so a positive angle turns clockwise.
-- Move × Rotate × Scale, built in one go.
local function makeTransform(x, y, angle, scale)
  local cosA, sinA = math.cos(angle), math.sin(angle)
  return { a = cosA * scale, b = sinA * scale, c = -sinA * scale, d = cosA * scale,
           tx = x, ty = y }
end

local function transformPoint(m, x, y)
  return m.a * x + m.c * y + m.tx, m.b * x + m.d * y + m.ty
end

local function invert(m)
  local det = m.a * m.d - m.b * m.c
  if math.abs(det) < 1e-9 then return nil end   -- scale 0: no way back
  local a, b, c, d = m.d / det, -m.b / det, -m.c / det, m.a / det
  return { a = a, b = b, c = c, d = d,
           tx = -(a * m.tx + c * m.ty), ty = -(b * m.tx + d * m.ty) }
end

local UNIT = 40                                   -- pixels per world unit
local HALF_LENGTH, HALF_WIDTH = 1.5, 1            -- hull box, in local units
local ship = { x = 3, y = 3, angle = math.rad(37), scale = 1 }
local localX, localY, onHull = 0, 0, false

function love.update(dt)
  if love.keyboard.isDown("q") then ship.angle = ship.angle - math.rad(90) * dt end
  if love.keyboard.isDown("e") then ship.angle = ship.angle + math.rad(90) * dt end
  local shipWorld = makeTransform(ship.x, ship.y, ship.angle, ship.scale)
  local worldToShip = invert(shipWorld)
  if worldToShip then
    local mx, my = love.mouse.getPosition()
    localX, localY = transformPoint(worldToShip, mx / UNIT, my / UNIT)
    onHull = math.abs(localX) <= HALF_LENGTH and math.abs(localY) <= HALF_WIDTH
  end
end

function love.draw()
  local ahead = localX > 0 and "ahead" or "behind"
  local side = localY > 0 and "right" or "left"
  love.graphics.print(string.format("local (%.1f, %.1f): %s, %s",
    localX, localY, ahead, side), 10, 10)
  if onHull then love.graphics.print("on the hull", 10, 30) end
end

With the mouse at pixel (200, 280), which is world (5, 7), this prints local (4.0, 2.0): ahead, right. It is not exact because 37° only approximates the diagram's 36.87°.

Built-in versions: in Godot, Node2D.to_local(point) and to_global(point), or Transform2D.affine_inverse() for the matrix. In Unity, transform.InverseTransformPoint(point) and transform.TransformPoint(point).

Pitfalls

  • Converting a direction as if it were a point. A velocity or an aim direction has no position, so it must skip the move: use only a', b', c', d' and leave out tx' and ty'. Otherwise the ship's position leaks into the direction. Unity has InverseTransformDirection for this.
  • Turning back by −angle and forgetting the scale. The dot product shortcut (or rotating by minus the angle) only undoes a turn. On a ship scaled by 2 the answer comes out twice too large. Divide by the scale, or use the full inverse.
  • Zero scale. A scale of 0 squashes every point onto the origin, the determinant is 0, and there is no way back. invert returns nil; check for it before using the result.
  • Worrying about angles past 180 degrees. No wrapping is needed here: 217° and −143° are the same turn, and sine and cosine give the same matrix and the same local point for both.
  • Inverting per point. Compute the inverse once per object per frame and reuse it. Note too that a point exactly on the centre line (local y = 0) counts as "left" in the code above.

In real games

Clicking a rotated unit, button or card is commonly done this way: convert the mouse into the object's local space and test a straight rectangle. The same trick tests a bullet against a rotated box, an oriented bounding box.

Steering code reads "ahead, and on which side?" from the signs of a target's local position. It also fixes last lesson's jumping gem: to reparent without moving, set the new local transform to the parent's world inverse × the object's world transform.

Takeaways

  • A point has a world address and, for each object, a local address along that object's arrows.
  • Local to world: multiply by the object's matrix M. World to local: multiply by its inverse M⁻¹.
  • The inverse undoes the steps in reverse order: subtract the position, turn back, divide by the scale.
  • In local space, "ahead?", "which side?" and "inside my box?" become simple comparisons.
  • Directions skip the move, and a scale of 0 cannot be undone.
