Random seeds: how does the same seed build the same dungeon?

How a pseudo-random generator turns one starting number, the seed, into a repeatable sequence, and how to use it to rebuild the same level every time.

A player posts "seed 12345 has a great first floor", and everyone who types 12345 gets the same rooms. A tester reports a bug in a randomly built level, and you want that exact level on your machine. Both need randomness you can replay.

Random numbers from a formula

A computer follows instructions exactly, so it cannot make truly random numbers out of nothing. Instead it uses a pseudo-random number generator (PRNG): a small formula that takes the current number and produces the next one. The numbers look random, but each one is fixed by the one before it.

The number the generator is holding right now is its state. The number you put in before the first step is the seed. Same seed, same steps, same numbers, every time.

A toy generator you can run by hand

Here is one rule: multiply the current number by 5, add 3, and keep only the remainder after dividing by 16. "Keep the remainder" is called mod: 38 mod 16 is 6, because 38 is two 16s with 6 left over.

next = (5 * now + 3) mod 16

Start from the seed 7: 5 × 7 + 3 = 38, and 38 mod 16 = 6. From 6: 5 × 6 + 3 = 33, which gives 1. Then 8, 11, 10, and so on.

The sequence is a loop. The number of steps before it repeats is the period, here 16. The seed does not change the loop, only where you start on it.

This kind of rule, "multiply, add, keep the remainder", is a linear congruential generator (LCG). Real ones use the same rule with bigger numbers. A well known set is multiply by 1,664,525, add 1,013,904,223, mod 232 (4,294,967,296). With these, the loop visits every one of the 4,294,967,296 states before it repeats.

From a state to a useful number

Games rarely want a number up to four billion. Divide the state by the modulus to get a fraction r from 0 up to, but never reaching, 1. In the toy generator, state 6 gives 6 / 16 = 0.375.

To get a whole number from lo to hi, both included, stretch the fraction over the number of choices and round down:

value = lo + floor(r * (hi - lo + 1))

For a room width from 3 to 7 there are 5 choices. With r = 0.375: 3 + floor(0.375 × 5) = 3 + floor(1.875) = 3 + 1 = 4. Because r never reaches 1, the result never goes past 7.

From numbers to a dungeon

A level generator is just a long list of questions answered by the next number: how wide is this room, how tall, where does it go, which way does the corridor bend. With seed 12345 the first four numbers are 0.020, 0.017, 0.543 and 0.635, so the first room is 3 wide, 3 tall, at column 16, row 11. Ask the same questions in the same order and you get the same answers.

Rule of thumb

Same seed, same generator, same calls in the same order: same result. Change any one of the three and everything after that point changes.

Try it

Type a seed and the dungeon is built from it. The grid uses screen directions: x grows to the right, y grows downwards, and cell (0, 0) is the top-left corner. Rooms are numbered in the order they were placed.

Press Build again as often as you like and check the comparison line. Then switch on Sparks share the generator: a particle effect now takes a few numbers from the same generator before the dungeon does, a different count each time, and the same seed stops giving the same dungeon.

The code

Each generator is a table holding its own state, so the level, the loot and the particles can each have one without disturbing the others. The dungeon builder uses the same numbers, in the same order, as the demo.

-- A linear congruential generator. Every step is exact in Lua numbers.
local M = 4294967296          -- 2^32, the number of states
local A = 1664525             -- multiplier
local C = 1013904223          -- increment

local function newRng(seed)
  return { state = math.floor(seed) % M }
end

local function nextFloat(rng) -- from 0 up to, never reaching, 1
  rng.state = (A * rng.state + C) % M
  return rng.state / M
end

local function nextInt(rng, lo, hi) -- lo to hi, both included
  return lo + math.floor(nextFloat(rng) * (hi - lo + 1))
end

local COLS, ROWS = 32, 20

local function overlaps(a, b) -- closer than one empty cell?
  return a.x <= b.x + b.w and b.x <= a.x + a.w
     and a.y <= b.y + b.h and b.y <= a.y + a.h
end

local function makeDungeon(seed)
  local rng = newRng(seed)    -- its own generator, used by nothing else
  local rooms = {}
  for attempt = 1, 30 do
    local room = {}
    room.w = nextInt(rng, 3, 7)
    room.h = nextInt(rng, 3, 6)
    room.x = nextInt(rng, 1, COLS - room.w - 1)
    room.y = nextInt(rng, 1, ROWS - room.h - 1)
    local free = true
    for i = 1, #rooms do
      if overlaps(room, rooms[i]) then free = false end
    end
    if free then
      if #rooms > 0 then room.sideFirst = nextFloat(rng) < 0.5 end
      rooms[#rooms + 1] = room
    end
  end
  return rooms
end

function love.load()
  rooms = makeDungeon(12345)  -- 8 rooms, the first 3 by 3 at (16, 11)
end
# Godot's own seeded generator
var rng := RandomNumberGenerator.new()
rng.seed = 12345
var w := rng.randi_range(3, 7)   # both ends included
// .NET's seeded generator works in Unity
var rng = new System.Random(12345);
int w = rng.Next(3, 8);   // the upper end is NOT included

The demo also draws a corridor from each room to the one placed before it, going sideways first when sideFirst is true. LÖVE has a built-in seeded generator too: love.math.newRandomGenerator(seed), with rng:random(3, 7). Godot and Unity give you RandomNumberGenerator and System.Random, shown in the other tabs. They use different algorithms, so seed 12345 gives different numbers in each.

Pitfalls

  • One shared generator for everything. If particles and the level draw from one generator, one extra spark shifts every number after it, as the demo's toggle shows. Give each system its own generator.
  • Neighbouring seeds that start alike. In an LCG, seeds 1, 2 and 3 give first numbers of 0.236, 0.237 and 0.237, and later numbers move in step too. If players will type small seeds, scramble the seed first. The next lesson builds the hash that does it.
  • Using state % n for a range. The low bits of an LCG are weak: the lowest one simply alternates, as the ring diagram shows. state % 2 gives heads, tails, heads, tails. Always go through the fraction and multiply, as nextInt does.
  • Off by one at the top of the range. nextInt includes both ends. Unity's Random.Range for whole numbers and System.Random.Next leave the top one out. Check which kind you are calling.
  • Trusting math.random to stay the same. math.randomseed makes it repeatable on one setup, but Lua 5.4 and LuaJIT use different algorithms, so a saved seed can mean a different level elsewhere. For seeds that players share, use a generator whose code you own, like the one above.
  • Seed edge cases. Seed 0 is fine here because the increment is odd; some other generator types get stuck when every bit of the state is 0. Negative seeds work because Lua's % always returns a value from 0 to M − 1. Fractions are rounded down first.

In real games

Minecraft lets players type a world seed, and the same seed in the same game version builds the same world. Slay the Spire and Spelunky 2 both offer seeded runs, so players can race through identical maps.

A daily challenge mode can be built the same way: turn the date into a seed, and everyone plays the same level that day. Replays and lockstep multiplayer often rely on the same idea: store the seed and the player inputs, and the game can rebuild everything else.

Takeaways

  • A pseudo-random generator is a formula that turns its state into the next state. The seed is the first state.
  • Same seed, same generator and the same calls in the same order give the same results on every run.
  • Divide the state by the modulus to get a fraction from 0 to just under 1, then stretch it to the range you need.
  • Give each system its own generator so that one extra call elsewhere cannot change your level.
  • Simple generators have weak low bits and similar neighbouring seeds. Use the fraction, and scramble small seeds.
