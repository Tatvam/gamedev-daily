Quadratic Bezier curves: how does the grenade arc over the wall?

How three points and three lerps make a smooth curve you shape by dragging one control point, and how to aim it so a grenade clears a wall.

Your soldier throws a grenade at a target behind a low wall. A straight line from hand to target goes through the wall. You want a smooth arc, and you want to shape it by moving a single point, not by tuning gravity and launch speed until it happens to land in the right place.

Three points and the lerp you already know are enough.

Three points and a slider

Start with the picture below. There is a start point (the thrower's hand), an end point (the target), and a third point floating above them, the control point. The curve leaves the start heading towards the control point, arrives at the end coming from it, and bends smoothly in between. It leans towards the control point but never touches it.

We name the points P0 (start), P1 (control) and P2 (end). Joining them gives two straight legs. Now pick a number t from 0 to 1, as in the lerp lesson: 0 means "at the start", 1 means "at the end". To find the curve's point for that t:

  1. Walk t of the way along the first leg. Call that point A.
  2. Walk t of the way along the second leg. Call that point B.
  3. Walk t of the way from A to B. That point is on the curve.

Do this for every t from 0 to 1 and the points trace a quadratic Bezier curve, "quadratic" because t ends up squared in the formula.

Positions are in grid squares and y grows downwards, as in LÖVE, so "up" means a smaller y. The thrower is at P0 = (0, 4), the control point at P1 = (2, 0) and the target at P2 = (8, 4).

A worked example

Lerp is lerp(a, b, t) = a + (b − a) × t, done separately for x and y. With t = 0.5:

  • A = lerp((0, 4), (2, 0), 0.5) = (0 + 2 × 0.5, 4 − 4 × 0.5) = (1, 2)
  • B = lerp((2, 0), (8, 4), 0.5) = (2 + 6 × 0.5, 0 + 4 × 0.5) = (5, 2)
  • point = lerp((1, 2), (5, 2), 0.5) = (1 + 4 × 0.5, 2 + 0 × 0.5) = (3, 2)

Halfway through its flight the grenade is 2 squares above the floor, while the control point is 4 above it. The curve went only half the way towards P1.

The same thing as one formula

Write the three lerps out with letters, tidy up, and you get:

point(t)  =  (1 − t)² × P0  +  2 × (1 − t) × t × P1  +  t² × P2

Each point is multiplied by a weight, saying how much of it goes into the mix: (1 − t)² for the start, 2(1 − t)t for the control point, t² for the end. The weights always add up to 1. At t = 0.5 they are 0.25, 0.5 and 0.25, so the point is 0.25 × (0, 4) + 0.5 × (2, 0) + 0.25 × (8, 4) = (0, 1) + (1, 0) + (2, 1) = (3, 2). The same answer.

The weights explain the shape. At t = 0 the start has weight 1, so the curve begins exactly at P0; at t = 1 it ends exactly at P2. The control point's weight peaks in the middle, so the curve leans towards it, but never above 0.5, so the curve never reaches it.

Aiming the arc

When the start and end are at the same height, the top of the arc is at t = 0.5, and it sits exactly halfway between the control point and the midpoint of P0 and P2. In the example the midpoint is (4, 4) and the control point is (2, 0); halfway between them is (3, 2), the peak we computed.

Rule of thumb

To make an arc rise h squares above a start and end at the same height, put the control point 2h above their midpoint. With y down that is: control = (midpoint.x, midpoint.y − 2h).

A bonus: if the control point is halfway across, the grenade moves sideways by the same amount for each step of t while its height curves, which is how a thrown object moves under steady gravity. Every quadratic Bezier is a piece of a parabola, possibly tilted.

The code

A grenade that flies from the thrower to the target along the curve every 1.5 seconds, using the worked example's points at 40 pixels per grid square.

-- Points are tables { x, y }. y grows downwards, like LÖVE's screen.
local function vec(x, y) return { x = x, y = y } end

local function lerp(a, b, t)
  return a + (b - a) * t
end

local function lerpPoint(p, q, t)
  return vec(lerp(p.x, q.x, t), lerp(p.y, q.y, t))
end

-- Quadratic Bezier: lerp along both legs, then lerp between the results.
local function bezier2(p0, p1, p2, t)
  local a = lerpPoint(p0, p1, t)   -- along the first leg
  local b = lerpPoint(p1, p2, t)   -- along the second leg
  return lerpPoint(a, b, t)        -- t of the way from a to b
end

-- Control point that makes the arc rise height h above the start and end.
local function controlForPeak(p0, p2, h)
  return vec((p0.x + p2.x) / 2, (p0.y + p2.y) / 2 - 2 * h)
end

local UNIT = 40                       -- pixels per grid square
local p0 = vec(0 * UNIT, 4 * UNIT)    -- thrower
local p2 = vec(8 * UNIT, 4 * UNIT)    -- target
local p1 = vec(2 * UNIT, 0 * UNIT)    -- control point
local FLIGHT_TIME = 1.5               -- seconds per throw
local timer = 0

function love.update(dt)
  timer = timer + dt
  if timer > FLIGHT_TIME then timer = 0 end
end

function love.draw()
  love.graphics.push()
  love.graphics.translate(60, 200)    -- leave room above for the arc
  local points = {}
  local steps = 32                    -- the curve as 32 straight pieces
  for i = 0, steps do
    local p = bezier2(p0, p1, p2, i / steps)
    points[#points + 1] = p.x
    points[#points + 1] = p.y
  end
  love.graphics.line(points)
  local t = timer / FLIGHT_TIME
  local g = bezier2(p0, p1, p2, t)
  love.graphics.circle("fill", g.x, g.y, 6)
  love.graphics.pop()
  love.graphics.print(string.format("t = %.2f  grenade = (%.2f, %.2f)",
    t, g.x / UNIT, g.y / UNIT), 10, 10)
end

To aim over the wall, replace the control point with local p1 = controlForPeak(p0, p2, 3 * UNIT), which gives (4, −2) in grid squares. With t = 0.5 the printed position is (3.00, 2.00) for the original control point, as in the worked example.

Built-in versions: LÖVE has love.math.newBezierCurve, whose evaluate(t) method returns the point for a given t. We know of no quadratic Bezier function built into Godot or Unity, but you can nest their lerps the same way: Vector2.lerp in Godot 4, Vector2.Lerp in Unity.

Pitfalls

  • Expecting the curve to pass through the control point. With level ends it gets only half way. If your arc is too low, move the control point twice as far as you think.
  • Letting t leave 0 to 1. The curve just keeps going. With the example points, t = 1.5 gives A = (3, −2), B = (11, 6) and a point at (15, 10): past the target and 6 squares under the floor. If t comes from a timer, clamp it, or stop the throw when it reaches 1. Unity's Vector2.Lerp clamps t for you; plain Lua does not.
  • Assuming equal steps of t mean equal distances. The demo's dots bunch up in places. Fine for a throw, wrong for a train that should move steadily; a later lesson on arc length fixes this.
  • Control point in line with the ends. The curve becomes a straight line, but the speed along it is uneven unless the control point is exactly in the middle. If the control point lies beyond an end, the path overshoots and comes back: with P0 = (0, 4), P1 = (10, 4) and P2 = (4, 4), the point reaches x = 6.25 at t = 0.625 before returning to 4.
  • All three points in one place. The "curve" is a single point. Nothing breaks, since there is no division, but nothing moves.
  • Too few pieces when drawing. 4 straight segments look like a bent wire; 16 to 32 is usually smooth for a small arc.

In real games

Quadratic Bezier curves are a common way to lob things to a chosen spot and to draw the aiming arc before a throw. They also suit curved motion that is not physical at all, such as a coin flying to the score counter or a card swooping into the player's hand.

Outside games, the outlines of TrueType fonts are made of quadratic Bezier curves, and both SVG paths (the Q command) and the HTML canvas (quadraticCurveTo) draw them directly. The curves are named after Pierre Bézier, an engineer at Renault who used them to design car bodies. The repeated-lerp method in this lesson is called de Casteljau's algorithm, after Paul de Casteljau, who worked on the same problem at Citroën.

Takeaways

  • A start, an end and one control point define a quadratic Bezier curve; it bends towards the control point without touching it.
  • For a given t: lerp along both legs to get A and B, then lerp from A to B.
  • The same point is (1 − t)² P0 + 2(1 − t)t P1 + t² P2; the weights add up to 1.
  • With level ends, put the control point 2h above the midpoint to make the arc rise h.
  • Keep t between 0 and 1, and do not expect equal steps of t to cover equal distances.
