Shuffle bags: why did my 1 in 5 gem not drop for 20 rocks?

How drawing from a shuffled bag keeps a drop's odds exact while putting a hard limit on how long a player can go without it.

In your mining game every rock has a 1 in 5 chance to hold a gem. A tester breaks twenty rocks in a row, gets nothing but coins, and reports that gems are broken. Your code is correct. Pure randomness allows long dry spells, and players feel them more than the average.

Why pure random makes long streaks

Call the chance of a gem on one draw p, a number from 0 to 1. Here p = 1/5 = 0.2, so a coin has chance 1 − p = 0.8. With pure random each draw ignores earlier draws. Such draws are independent.

The chance of k coins in a row is the coin chance multiplied by itself k times:

chance of k misses in a row = (1 - p) ^ k

Worked example: the chance that the next 2 rocks both give coins is 0.8 × 0.8 = 0.64. For longer waits:

Rocks in a row without a gem (k)0.8 ^ kAbout
50.3281 in 3
100.1071 in 9
150.0351 in 28
200.0121 in 87

1 in 87 sounds rare, but among ten thousand players, hundreds will hit a 20-rock drought.

Put the odds in a bag

A shuffle bag works like a deck of cards. Put in the items in the ratio you want: for a 1 in 5 gem, one Gem and four Coins. Shuffle. Each draw takes the next item out without putting it back. When the bag is empty, refill it and shuffle again.

Every full bag gives exactly one gem in five draws, so the long-run chance is still 1/5. What changes is the streaks: once four coins are out, the last draw is certainly the gem.

The longest possible wait

Call the number of items in a full bag N, with one gem among them. The worst case is a gem drawn first in one bag and last in the next. Between them sit the N − 1 coins of the first bag and the N − 1 coins of the second:

longest wait = (N - 1) + (N - 1) = 2N - 2

The same picture caps the lucky streaks: for N of 2 or more, gems can come at most twice in a row, last in one bag and first in the next.

Shuffling fairly

Every order of the bag must be equally likely. The standard method is the Fisher-Yates shuffle: start at the last position, swap it with a random position from 1 up to itself (it may stay put), then do the same for the position before it, and so on down to position 2.

Worked example with four different items, starting from {Gem, Coin, Potion, Key}:

  • Position 4: pick a random spot from 1 to 4, say 1. Swap Key and Gem: {Key, Coin, Potion, Gem}.
  • Position 3: pick from 1 to 3, say 3. It stays: {Key, Coin, Potion, Gem}.
  • Position 2: pick from 1 to 2, say 1. Swap: {Coin, Key, Potion, Gem}.

There were 4 × 3 × 2 = 24 possible sets of picks, and there are exactly 24 orders of four items, so each order comes up once: the shuffle is fair. Drawing from the end of the list then gives Gem, Potion, Key, Coin.

Rule of thumb

A bag of N items with one rare item keeps its chance at exactly 1 in N and promises the player never waits more than 2N − 2 draws for it.

The code

The same bag as the demo with N = 5. shuffle is Fisher-Yates, and drawFromBag refills and reshuffles only when the bag is empty.

-- One Gem and (bagSize - 1) Coins: a 1 in bagSize chance
local function makeContents(bagSize)
  local items = { "Gem" }
  for i = 2, bagSize do
    items[i] = "Coin"
  end
  return items
end

-- Fisher-Yates: every order is equally likely
local function shuffle(t)
  for i = #t, 2, -1 do
    local j = love.math.random(1, i)  -- 1 up to i, including i
    t[i], t[j] = t[j], t[i]
  end
end

local function newBag(contents)
  return { contents = contents, items = {} }
end

local function drawFromBag(bag)
  if #bag.contents == 0 then
    return nil  -- nothing to put in the bag
  end
  if #bag.items == 0 then
    for i = 1, #bag.contents do
      bag.items[i] = bag.contents[i]
    end
    shuffle(bag.items)
  end
  return table.remove(bag.items)  -- take from the end
end

local function pureRandom(bagSize)
  if love.math.random(1, bagSize) == 1 then
    return "Gem"
  end
  return "Coin"
end

local rockBag = newBag(makeContents(5))

function love.keypressed(key)
  if key == "d" then
    print("Bag: " .. drawFromBag(rockBag) .. "   Pure: " .. pureRandom(5))
  end
end
var contents := ["Gem", "Coin", "Coin", "Coin", "Coin"]
var bag: Array = []

func draw_from_bag() -> String:
    if contents.is_empty():
        return ""
    if bag.is_empty():
        bag = contents.duplicate()
        bag.shuffle()
    return bag.pop_back()

Godot arrays have a built-in Array.shuffle(). For Unity I know of no built-in list shuffle; port shuffle with 0-based indices and Random.Range(0, i + 1), whose integer form excludes the upper end.

Any loot table with whole-number weights becomes a bag: yesterday's chest with weights 50, 25, 15, 8 and 2 is a bag of 100 items holding 50 coins, 25 potions and so on.

Pitfalls

  • The almost-right shuffle. Swapping every position with a spot picked from the whole list, 1 to n, is biased: for four items it has 4 × 4 × 4 × 4 = 256 sets of picks, which cannot split evenly over 24 orders. Pick from 1 to i.
  • Sorting with a random comparison. table.sort(t, function () return love.math.random() < 0.5 end) is not a shuffle. It is biased, and Lua may stop with an "invalid order function" error.
  • Empty contents. A bag with nothing in it refills to nothing, so drawFromBag returns nil. The love.keypressed example assumes a non-empty bag; in a real game check for nil before using the result.
  • Players can count. Near the end of a bag the next draw is known: after four coins the gem is certain. For combat crits that may feel scripted. Two copies of everything, 2 gems and 8 coins, keeps the 1 in 5 rate but makes draws harder to predict, at the cost of raising the longest wait from 8 to 16.
  • Changing the bag mid-way. If the odds change, throw the current bag away and refill with the new contents, or both the ratio and the limit break.

In real games

Modern official Tetris games deal pieces from a shuffled bag of all seven pieces, the "7-bag". With N = 7 the longest wait for any one piece is 2 × 7 − 2 = 12.

In deck-builders such as Slay the Spire the draw pile is a shuffled bag, refilled from the discard pile when it runs out.

Takeaways

  • Pure random draws have no memory, so the chance of k misses in a row, (1 − p) ^ k, never reaches zero.
  • A shuffle bag holds the items in the exact ratio you want and is refilled and reshuffled only when empty.
  • The long-run odds stay the same; with one rare item in a bag of N, the longest wait is 2N − 2.
  • Shuffle with Fisher-Yates: swap position i with a random position from 1 to i, from the end down to 2.
