From vector to angle with atan2: why does my turret aim backwards?

How math.atan2(dy, dx) turns a direction such as "towards the mouse" into an angle in all four quadrants, and why plain atan(dy / dx) aims backwards.

Your turret should face the mouse. You work out the direction from the turret to the mouse, turn it into an angle with math.atan(dy / dx), and it works perfectly while the mouse is on the right. Move the mouse to the left and the barrel points exactly the wrong way.

The fix is one function, math.atan2. This lesson shows what it does and why the simpler version cannot work.

Going backwards from a direction to an angle

So far we went from an angle a to a direction, the point (cos a, sin a). Aiming needs the opposite trip: you know a direction and want its angle.

The direction comes from subtraction. With the turret at (400, 300) and the mouse at (430, 340), the vector from turret to mouse is d = (430 − 400, 340 − 300) = (30, 40). Call its parts dx, how far across, and dy, how far down. This lesson and its demo use y pointing down, as on a screen and in LÖVE, so angles grow clockwise: 0 points right and 90 degrees points straight down.

The slope is not enough

The first idea most people have is the tangent. For an angle a, tan a is sin a divided by cos a, which is dy divided by dx: how steep the direction is. Its inverse, arctangent (atan), takes a steepness and gives back an angle. For (30, 40) the steepness is 40 / 30 = 1.333, and atan(1.333) is 53.1 degrees. Correct.

Now put the mouse at (370, 260), up and to the left. The direction is e = (−30, −40). Divide: −40 / −30 = 1.333. The two minus signs cancelled. atan gets exactly the same number as before, so it gives exactly the same answer, 53.1 degrees, which points down and to the right. The true direction is the opposite one.

atan only ever returns angles between −90 and 90 degrees: the right half of the circle. Every direction on the left shares its steepness with one on the right, and atan always picks the right one. Straight up and down add a second problem: dx is 0, and you divide by zero.

atan2 keeps both numbers

atan2 is the arctangent that takes dy and dx as two separate numbers instead of their ratio. Because it still sees both signs, it knows which quadrant the direction is in and answers anywhere round the full circle. In Lua:

local angle = math.atan2(dy, dx)   -- radians, from -pi to pi

Note the order: dy comes first, then dx. It matches "steepness = dy / dx", with the top of the fraction first.

Worked examples, using the small numbers from the diagram:

  • atan2(4, 3) = 0.927 radians = 53.1 degrees: down and to the right.
  • atan2(−4, −3) = −2.214 radians = −126.9 degrees: up and to the left.
  • atan2(5, 0) = 90 degrees and atan2(−5, 0) = −90 degrees: straight down and straight up, with no division anywhere.

−126.9 degrees is 53.1 degrees minus half a turn: the other end of the same line. In effect atan2 works out atan(dy / dx) and, if dx is negative, moves the answer 180 degrees onto the left half.

What the answer looks like

The answer runs from −180 to 180 degrees (−π to π radians). For 0 to 360, wrap it: in Lua, angle % (2 * math.pi) turns −2.214 into 4.069 radians, 233.1 degrees. Both name the same direction.

Bonus: the angle between two directions

The dot product lesson used the cosine to find the angle between two vectors, which never tells you which side. The 2D cross product told you the side but not the size. Feed both into atan2 and you get both: math.atan2(cross, dot) is the signed angle from a to b. For a = (2, 0) and b = (−1, 1): cross = 2 × 1 − 0 × (−1) = 2, dot = 2 × (−1) + 0 × 1 = −2, and atan2(2, −2) = 135 degrees, clockwise on screen.

The code

A turret that faces the mouse and fires with Space. With the turret at (400, 300), a mouse at (430, 340) gives 53.1 degrees, and a mouse at (370, 260) gives −126.9 degrees, as in the worked examples.

-- y grows downwards, as on LÖVE's screen, so angles grow clockwise:
-- 0 is right, pi/2 (90 degrees) is down, -pi/2 (-90 degrees) is up.
local turret = { x = 400, y = 300, angle = 0, barrel = 24 }
local bullets = {}
local BULLET_SPEED = 300   -- pixels per second

-- The angle of the direction (dx, dy) in radians, from -pi to pi.
-- LÖVE runs LuaJIT (Lua 5.1 rules), which has math.atan2.
-- In Lua 5.3 and later, write math.atan(dy, dx) instead.
local function angleOf(dx, dy)
  return math.atan2(dy, dx)   -- y first, then x
end

local function aimAt(t, targetX, targetY)
  local dx, dy = targetX - t.x, targetY - t.y
  if dx == 0 and dy == 0 then return end   -- no direction: keep the old angle
  t.angle = angleOf(dx, dy)
end

function love.keypressed(key)
  if key == "space" then
    local dirX, dirY = math.cos(turret.angle), math.sin(turret.angle)
    table.insert(bullets, {
      x = turret.x + dirX * turret.barrel, y = turret.y + dirY * turret.barrel,
      vx = dirX * BULLET_SPEED, vy = dirY * BULLET_SPEED })
  end
end

function love.update(dt)
  local mouseX, mouseY = love.mouse.getPosition()
  aimAt(turret, mouseX, mouseY)
  for _, b in ipairs(bullets) do
    b.x = b.x + b.vx * dt
    b.y = b.y + b.vy * dt
  end
end

function love.draw()
  local tipX = turret.x + math.cos(turret.angle) * turret.barrel
  local tipY = turret.y + math.sin(turret.angle) * turret.barrel
  love.graphics.circle("line", turret.x, turret.y, 12)
  love.graphics.line(turret.x, turret.y, tipX, tipY)
  for _, b in ipairs(bullets) do
    love.graphics.circle("fill", b.x, b.y, 3)
  end
  local degrees = math.deg(turret.angle)   -- from -180 to 180
  love.graphics.print(string.format("%.1f deg (%.1f on a 0 to 360 scale)",
    degrees, degrees % 360), 10, 10)
end

If you draw a sprite instead of a line, pass the angle straight to love.graphics.draw as its rotation, and draw the sprite facing right, where angle 0 points.

Built-in versions: Godot has atan2(y, x) and Vector2.angle(). Unity has Mathf.Atan2(y, x). All three return radians.

Pitfalls

  • Swapping the arguments. math.atan2(dx, dy) runs without an error but measures the angle from the y axis in the opposite turning direction. (3, 4) comes out as 36.9 degrees instead of 53.1. If aiming is mirrored across the diagonal, check the order.
  • The zero-length vector. When the target sits exactly on the turret, there is no direction. atan2(0, 0) usually returns 0 instead of an error, so the turret silently snaps to face right. Check for a zero vector and keep the old angle, as aimAt does. Plain atan is worse: 0 / 0 gives NaN ("not a number"), which spreads into everything it touches.
  • The jump at 180 degrees. Cross the left side and the angle leaps from 180 to −180. The direction barely changed, but code that eases from one value to the other spins almost a full turn the long way. A later lesson in this track fixes that.
  • The y direction. With y up, as in Unity and maths books, the same call gives the same numbers, but positive angles turn anticlockwise. The answer is in radians either way.
  • Sprites drawn facing up. atan2 measures from the right, so a sprite drawn pointing up needs π / 2 added (with y down) or it aims 90 degrees off.

In real games

Mouse aiming in top-down shooters is atan2 of the vector from the player to the cursor. Twin-stick aiming is the same call on the right stick's two axes. Arrows, missiles and thrown knives point along their flight by taking atan2 of their velocity each frame, so they tip over naturally as gravity bends their path.

Games with sprites drawn in eight directions use the angle to pick one: eight 45 degree slices of the full turn. You will build that in the exercise.

Your turn (15 minutes)

Give a character eight facing sprites (or eight coloured rectangles with a number on them). Each frame, take the angle from the character to the mouse with math.atan2 and turn it into a slice number from 0 to 7:

local turn = angle % (2 * math.pi)                       -- 0 to 2 pi
local slice = math.floor((turn + math.pi / 8) / (math.pi / 4)) % 8

Adding π / 8 (half a slice) centres each slice on its direction, so slice 0 covers right from −22.5 to 22.5 degrees. You are done when slice 0 shows with the mouse to the right, slice 2 with it below (y down), slice 4 to the left, slice 6 above, and nothing flickers when the mouse crosses the left side where atan2 jumps.

Takeaways

  • To aim, subtract positions to get the direction (dx, dy), then turn it into an angle with math.atan2(dy, dx), y first.
  • Plain atan(dy / dx) loses the signs, so it can only answer for the right half and aims backwards on the left.
  • atan2 returns radians from −π to π. With y down, positive means below the x axis; wrap with % (2 * math.pi) for 0 to 2π.
  • A zero vector has no angle: check for it before calling atan2.
  • math.atan2(cross, dot) gives the signed angle between two directions.
