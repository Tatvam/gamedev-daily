Projection and reflection: which way does the ball bounce?

How the dot product splits a movement into the part going into a wall and the part along it, and how flipping or dropping one part gives bounce and slide.

Your ball bounces off the screen edges by flipping the x speed at the sides and the y speed at the floor. Then you add a slanted bumper, and there is nothing to flip: neither x nor y is "the part that hits the wall" any more.

A character that stops dead against a slanted wall instead of sliding along it has the same problem. Both are fixed by splitting the movement into the part that goes into the wall and the part that runs along it.

Two parts of one movement

Every wall has a normal: an arrow of length 1 sticking straight out of the wall's front face, at a right angle to it. Collision code usually hands you this arrow. We call it n.

Call the ball's movement per second (its velocity) d. Any d is the sum of two arrows:

  • along: the part in line with n, straight into or out of the wall.
  • across: the part parallel to the wall.

A bounce keeps across and flips along. A slide keeps across and throws along away.

Positions are in grid squares and y grows downwards, as on a screen and in LÖVE. Here is a ball falling onto a flat floor:

Projection: the shadow of one arrow on another

From the dot product lesson: when n has length 1, d · n says how far d reaches in n's direction. Here it is −4, negative because d goes into the floor while n points out.

Multiply n by that number to get the along arrow: (d · n) n = −4 × (0, −1) = (0, 4). This is the projection of d onto n: d's shadow on the line of n, with the light shining at a right angle to that line.

The across part is what is left: (3, 4) − (0, 4) = (3, 0). Check: across · n = 3 × 0 + 0 × (−1) = 0, so it has nothing in n's direction.

To project v onto an arrow a that is not length 1, divide by a's length squared:

projection of v onto a  =  (v · a ÷ a · a) × a

Read it as "v dot a, divided by a dot a, times a". For v = (3, 4) and a = (2, 0): v · a = 6, a · a = 4, so the projection is 1.5 × (2, 0) = (3, 0). With a unit arrow, a · a is 1 and the division disappears.

Reflection: flip the part that hits

The bounced movement is r = across − along. Since across = d − along, that is d − 2 × along, which gives the usual formula:

r  =  d − 2 (d · n) n

Read it as "d, minus twice the projection of d onto n". Subtracting the along part once cancels it: a slide. Twice flips it: a bounce. This is a reflection, the path out mirroring the path in.

Now a slanted wall with direction (4, −3). Its normal is n = (−0.6, −0.8), pointing up and left. (Swap the parts and negate one, (x, y) to (y, −x), then divide by the length 5; the next lesson explains why.) The ball moves right, d = (5, 0):

  • d · n = 5 × (−0.6) + 0 × (−0.8) = −3
  • along = −3 × (−0.6, −0.8) = (1.8, 2.4)
  • across = (5, 0) − (1.8, 2.4) = (3.2, −2.4)
  • r = (3.2, −2.4) − (1.8, 2.4) = (1.4, −4.8)

The ball leaves steeply up and right, with length √(1.4² + 4.8²) = √25 = 5: the same speed it came in with.

Bounciness

Between flipping and dropping there is a dial: multiply the flipped part by a bounciness e from 0 to 1, so r = across − e × along. e = 1 is the mirror bounce; e = 0 is the slide, (3.2, −2.4) on the slanted wall. On the floor with e = 0.5, r = (3, −2): same sideways speed, half the upward speed.

Rule of thumb

Project onto the normal to get the part that hits. Keep the rest. Flip the hitting part to bounce, drop it to slide, scale it for anything in between. Only do this when d · n is negative.

Nothing here depends on which way y points: the same formulas work in a y-up world.

The code

The slanted wall and ball from the worked example, named as in the demo. bounce uses project, so it still works if the normal is not length 1.

-- Vectors are tables { x, y }. y grows downwards, like LÖVE's screen.
local function vec(x, y) return { x = x, y = y } end
local function dot(a, b) return a.x * b.x + a.y * b.y end
local function scale(v, s) return vec(v.x * s, v.y * s) end
local function sub(a, b) return vec(a.x - b.x, a.y - b.y) end

-- The part of v that points along a. a can be any length.
local function project(v, a)
  local aa = dot(a, a)
  if aa == 0 then
    return vec(0, 0)                  -- a has no direction
  end
  return scale(a, dot(v, a) / aa)
end

-- n: the wall's normal, out of its front face.
-- e: bounciness. 1 = mirror bounce, 0 = slide.
local function bounce(d, n, e)
  if dot(d, n) >= 0 then
    return d                          -- not moving into the front face
  end
  local along = project(d, n)
  local across = sub(d, along)
  return sub(across, scale(along, e))
end

local function reflect(d, n) return bounce(d, n, 1) end
local function slide(d, n) return bounce(d, n, 0) end

local wall = vec(4, -3)               -- the wall's direction
local n = scale(vec(wall.y, -wall.x), 1 / math.sqrt(dot(wall, wall)))
local d = vec(5, 0)                   -- n is (-0.6, -0.8)

function love.draw()
  local r = reflect(d, n)             -- (1.4, -4.8)
  local s = slide(d, n)               -- (3.2, -2.4)
  love.graphics.print(string.format("reflect: (%.1f, %.1f)", r.x, r.y), 10, 10)
  love.graphics.print(string.format("slide:   (%.1f, %.1f)", s.x, s.y), 10, 30)
end

In a game, call bounce on the ball's velocity in love.update(dt) on the frame it touches the wall, with the normal your collision check found.

Built-in versions: Unity has Vector2.Reflect(inDirection, inNormal), matching reflect here. Godot has Vector2.project, slide and bounce; bounce(n) is this lesson's reflect, while Godot 4's own reflect mirrors across a line and gives the opposite sign.

Pitfalls

  • A normal that is not length 1. d − 2(d · n)n assumes it. With n = (0, −2) on the floor, d = (3, 4) becomes (3, −12), four times too fast. Normalise n, or use project, which divides by n · n.
  • Bouncing when moving away. If d · n is positive, the ball is already leaving, and reflecting sends it back into the wall. A ball still overlapping the wall next frame then bounces in, out, in, and looks stuck. Only bounce when d · n is negative, and push the ball out of the wall on a hit.
  • A normal facing the wrong way. Flipping n does not change the reflection (the two minus signs cancel), but it flips the "moving into the wall?" test, so balls pass through. Check which side your normals face.
  • Zero-length vectors. Projecting onto (0, 0) would divide by zero; project returns (0, 0) instead. A ball with d = (0, 0) has d · n = 0 and does not bounce. A grazing ball moving exactly along the wall also has d · n = 0 and keeps going.
  • Sliding loses speed. On the slanted wall the slide has length 4, down from 5. That usually feels right for a character walking into a wall at an angle. For full speed, normalise the slide and multiply by the old speed, but guard against a slide of (0, 0) when walking straight in.

In real games

Balls, bullets and pucks that ricochet off angled walls use this reflection; "flip the x speed" is the same formula with the normal (1, 0) or (−1, 0). Character controllers slide along walls by removing the along part; Godot's CharacterBody2D.move_and_slide, for example, slides a character along the surfaces it touches. Physics engines expose bounciness as a material setting, often called restitution, which plays the role of e here.

Takeaways

  • With a unit normal n, the projection (d · n) n is the part of d going into the wall; the rest runs along it.
  • Bounce: r = d − 2(d · n)n. Slide: d − (d · n)n. Bounciness e scales the flipped part.
  • Only respond when d · n is negative, and normalise n or divide by n · n.
  • A mirror bounce keeps the speed; a slide usually loses some.
