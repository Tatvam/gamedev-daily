Smoothstep: why does my camera jolt when it starts and stops?

How smoothstep bends the straight 0 to 1 ramp of lerp into an S-shaped curve, so a camera or door starts gently, speeds up, and settles softly.

The player walks through a doorway and the camera pans to the next room in exactly one second, using lerp. It works, but it feels mechanical: the camera leaps to full speed on the first frame and stops dead on the last, with a small jolt at each end.

Real things speed up and slow down. Today we keep lerp and change only the number we feed it.

Bend t before you use it

Recall the lerp lesson: lerp(a, b, t) = a + (b - a) * t. The start is a, the end is b, and t is the fraction of the way from 0 to 1. For a timed move, t is the time so far divided by the duration, so it grows at a steady rate.

That steady rate is the problem. The speed is the same on the first frame as in the middle, and then it drops to zero in one frame. Your eye reads a sudden change of speed as a jolt.

The fix is to pass t through a curve first. A curve that turns 0 to 1 into 0 to 1, but changes slowly near both ends and quickly in the middle, is called an easing curve. The simplest useful one is smoothstep, named for its S shape.

The formula

Smoothstep takes t from 0 to 1 and returns a new fraction s, also from 0 to 1:

s = t * t * (3 - 2 * t)

In words: t squared, times three minus twice t. You will also see it written as 3t² − 2t³, which is the same thing multiplied out. Worked example with t = 0.25, a quarter of the time:

  1. t × t = 0.25 × 0.25 = 0.0625.
  2. 3 − 2 × 0.25 = 3 − 0.5 = 2.5.
  3. s = 0.0625 × 2.5 = 0.15625.

After a quarter of the time the object has covered about 16 percent of the way instead of 25 percent. Check the other key points. At t = 0, s = 0. At t = 1, s = 1 × 1 × (3 − 2) = 1. At t = 0.5, s = 0.25 × 2 = 0.5, so the middle is the same as lerp. At t = 0.75, s = 0.84375, which mirrors the quarter: 1 − 0.15625.

To use it, feed s to lerp instead of t: x = lerp(a, b, smoothstep(t)). Smoothstep does not replace lerp. It only reshapes the fraction.

Where the speed goes

Compare how far each version moves in one tenth of the time. With lerp every tenth moves 0.1 of the way. With smoothstep, t from 0 to 0.1 moves s from 0 to 0.028, almost nothing, while t from 0.4 to 0.5 moves s from 0.352 to 0.5, which is 0.148. The time saved at the ends is spent in the middle. If you know calculus: the speed of s compared with lerp is 6t(1 − t), which is 0 at both ends and peaks at 1.5 in the middle.

The shader form: smoothstep between two edges

Shading languages define smoothstep with two edges: smoothstep(edge0, edge1, x). It is yesterday's clamped inverse lerp followed by the S curve: t = clamp((x − edge0) / (edge1 − edge0), 0, 1), then t × t × (3 − 2t). A fog that starts at 20 metres and is complete at 60 metres, seen at 30 metres: t = (30 − 20) / (60 − 20) = 0.25, so the fog amount is 0.15625.

Always clamp t first

The S curve only behaves between 0 and 1. Outside it the formula turns back: t = 1.25 gives 0.78, t = 1.5 gives 0, and t = 2 gives −4. A camera whose timer runs past the duration would slide back towards the start and then shoot off the other way. Clamp t to 0 to 1 before applying the curve.

The code

A crate in LÖVE that moves between two pads in one second, the same move as the demo. Press space to send it to the other pad. smooth01 holds the line that matters.

-- Screen coordinates: x grows right, y grows down, as in LÖVE.
local A, B = 40, 360           -- the two pads, in pixels
local DURATION = 1.0           -- seconds per move

local function lerp(a, b, t)
  return a + (b - a) * t
end

local function clamp01(t)
  return math.max(0, math.min(1, t))
end

-- The S curve on 0..1. Clamp first: outside 0..1 the curve turns back.
local function smooth01(t)
  t = clamp01(t)
  return t * t * (3 - 2 * t)
end

-- Shader style: 0 below edge0, 1 above edge1, S-shaped in between.
local function smoothstep(edge0, edge1, x)
  if edge0 == edge1 then return x < edge0 and 0 or 1 end   -- avoid dividing by 0
  return smooth01((x - edge0) / (edge1 - edge0))
end

print(smooth01(0.25))          -- 0.15625
print(smooth01(1.5))           -- 1, thanks to the clamp
print(smoothstep(20, 60, 30))  -- 0.15625, fog at 30 m

local crateX, from, to, elapsed = A, A, B, 0

function love.keypressed(key)
  if key == "space" then
    if to == B then to = A else to = B end
    from, elapsed = crateX, 0
  end
end

function love.update(dt)
  elapsed = elapsed + dt
  crateX = lerp(from, to, smooth01(elapsed / DURATION))
end

function love.draw()
  love.graphics.rectangle("fill", crateX - 20, 200, 40, 40)
end

Built-in versions: Godot's smoothstep(from, to, x) is the shader form with two edges and returns 0 to 1. Unity's Mathf.SmoothStep(from, to, t) is different: it returns a value between from and to, like a lerp that eases, so it plays the role of lerp(from, to, smooth01(t)). GLSL has smoothstep(edge0, edge1, x).

Pitfalls

  • Not clamping t. When the timer runs past the duration, t goes above 1 and the plain formula runs backwards: 0 at t = 1.5 and −4 at t = 2. Below 0 it climbs again: t = −0.5 gives 1. Clamp before the curve, as smooth01 does.
  • Mixing up the two signatures. The shader form and Godot take two edges and a value and return a fraction. Unity takes a start, an end and a fraction and returns a position. Test with t = 0.25 and expect 0.15625 of the way.
  • Equal edges. If edge0 equals edge1 the inverse lerp divides by zero; guard it as above, which turns it into a hard step. The GLSL specification also leaves the result undefined when edge0 is greater than edge1, so in shaders do not rely on a reversed range.
  • Smoothing the position instead of t. Smoothstep shapes the fraction of a timed move. Applying it to a position every frame does not ease anything. Chasing a moving target is a different problem, covered by exponential smoothing.
  • Interrupted moves. If a new move starts halfway, start it from the current position, as the code does with from = crateX, or the crate jumps.

In real games

Smoothstep is one of the most common functions in shaders. The usual trick is to use it as a soft threshold: smoothstep(0.4, 0.6, value) instead of a hard cut-off gives soft edges to circles, outlines, fog bands and dissolve effects. GLSL and HLSL both have it built in.

The same curve is the fade function in Ken Perlin's original noise. His later improved noise replaced it with a smoother cousin, 6t⁵ − 15t⁴ + 10t³, often called smootherstep, which also starts and ends with no change in acceleration. In gameplay code it is a common default for camera pans, doors and sliding menus.

Takeaways

  • Smoothstep reshapes the fraction t: s = t * t * (3 - 2 * t), then lerp(a, b, s).
  • It starts and ends with zero speed and moves fastest in the middle, at 1.5 times the average speed.
  • At t = 0.25 it gives 0.15625, at 0.5 it gives 0.5, and it is symmetric about the middle.
  • Clamp t to 0 to 1 first. Outside that range the curve turns back.
  • The shader form smoothstep(edge0, edge1, x) is a clamped inverse lerp followed by the same curve. Unity's version takes different arguments.
