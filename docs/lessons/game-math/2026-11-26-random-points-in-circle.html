Random points in a circle: why do my flowers clump in the middle?

Why a random angle and a random distance bunch points at the centre of a circle, and how one square root spreads them evenly.

You plant 400 flowers in a round meadow, each at a random direction and a random distance from the centre. The result looks wrong: a thick carpet in the middle and bare grass near the edge. Every number was fair. The picture is not.

Fair numbers, unfair picture

A random point is uniform in a shape when every patch of the same area is equally likely to get it. Scatter many uniform points and they look evenly sprinkled, with no thick or thin regions.

For a rectangle this is easy. Pick x and y separately:

x = left + random() * width
y = top  + random() * height

Every column and every row get the same share, so every patch does too. A circle is the trap, because the obvious recipe uses an angle and a distance, which is polar coordinates:

angle = random() * 2 * pi
dist  = R * random()          -- R is the circle's radius

Why the middle gets too many

Think of the circle as a set of thin rings, like the rings of a tree. The naive recipe gives every distance the same chance, so every ring gets the same number of points. But the rings are not the same size. A ring's length is its circumference, 2 × pi × its distance from the centre, so a ring at distance 8 is four times longer than a ring at distance 2.

A worked example

Take a meadow of radius 10 and draw a smaller circle of radius 5 inside it. Area is pi × radius², so the small circle has pi × 25 and the whole meadow pi × 100. The small circle is a quarter of the area, so a fair scatter should put a quarter of the flowers in it.

The naive recipe puts a flower within distance 5 whenever its random number is below 0.5. That happens half the time. Half the flowers in a quarter of the space: twice as crowded as it should be.

The fix: a square root

Area grows with the square of the distance. To undo that, take the square root of the random number before scaling it. The square root of a number is the value that, multiplied by itself, gives that number: √0.25 = 0.5, because 0.5 × 0.5 = 0.25.

u    = random()          -- a fair fraction from 0 to 1
dist = R * sqrt(u)

Here u is the random fraction going in, and dist is the distance from the centre coming out. Check it against the worked example: a flower lands within distance 5 when √u is below 0.5, which means u below 0.25. That is a quarter of the time, exactly the share of the area. Two more: u = 0.64 gives dist = 10 × 0.8 = 8, and u = 0.81 gives 9.

Another way: throw and retry

A second fix needs no square root. Pick a uniform point in the square around the circle and, if it falls outside the circle, throw it away and pick again. This is called rejection sampling. The points you keep are uniform in the circle, because the square was uniform and you only removed the corners.

The circle fills pi / 4, about 78.5%, of its square, so on average you need about 1.27 tries per point. The same idea works for any shape you can test a point against, such as a star or a level's walkable area.

Rule of thumb

For a random distance in a circle, use R * sqrt(random()), never R * random(). For an odd shape, pick in a box around it and retry until the point is inside.

The code

Three ways to scatter in a circle, one for a ring, and the meadow from the hook. randomInCircle is what the right side of the demo does.

local TAU = 2 * math.pi

-- Uniform point inside a circle of radius R around (cx, cy)
local function randomInCircle(cx, cy, R)
  local angle = love.math.random() * TAU
  local dist = R * math.sqrt(love.math.random())
  return cx + math.cos(angle) * dist, cy + math.sin(angle) * dist
end

-- The clumping version, only for comparison
local function randomInCircleNaive(cx, cy, R)
  local angle = love.math.random() * TAU
  local dist = R * love.math.random()
  return cx + math.cos(angle) * dist, cy + math.sin(angle) * dist
end

-- Rejection sampling: pick in the square, retry outside the circle
local function randomInCircleRejection(cx, cy, R)
  while true do
    local x = (love.math.random() * 2 - 1) * R
    local y = (love.math.random() * 2 - 1) * R
    if x * x + y * y <= R * R then
      return cx + x, cy + y
    end
  end
end

-- Uniform point in a ring between rMin and rMax: blend the SQUARES
local function randomInRing(cx, cy, rMin, rMax)
  local angle = love.math.random() * TAU
  local u = love.math.random()
  local dist = math.sqrt(rMin * rMin + (rMax * rMax - rMin * rMin) * u)
  return cx + math.cos(angle) * dist, cy + math.sin(angle) * dist
end

local flowers = {}

function love.load()
  for i = 1, 400 do
    local x, y = randomInCircle(400, 300, 150)
    flowers[i] = { x = x, y = y }
  end
end

function love.draw()
  for i, f in ipairs(flowers) do
    love.graphics.circle("fill", f.x, f.y, 3)
  end
end
func random_in_circle(center: Vector2, r: float) -> Vector2:
    var angle := randf() * TAU
    var dist := r * sqrt(randf())
    return center + Vector2.from_angle(angle) * dist

With rMin = 0, randomInRing is the same as randomInCircle. Worked example for a ring from 5 to 10: u = 0.5 gives √(25 + 75 × 0.5) = √62.5, about 7.9, not the halfway mark 7.5, because the outer part of the ring holds more area.

For an ellipse, take a point in a circle of radius 1 and multiply its x by the half-width and its y by the half-height. Stretching keeps an even scatter even.

Pitfalls

  • Forgetting the square root. The clump is easy to miss with 20 points and obvious with 400. Scatter a few thousand and look.
  • Blending the distances of a ring. rMin + (rMax - rMin) * sqrt(u) still crowds the inner edge. Blend the squared radii, then take the root, as randomInRing does. Swapped rMin and rMax still work.
  • Normalising a point from the square to get a direction. Pick x and y from −1 to 1, divide by the length, and you get a direction biased towards the diagonals: about 1.7 times more directions near 45 degrees than near the axes. Use a random angle, or reject points outside the circle before normalising. A point at exactly (0, 0) has length zero and cannot be normalised at all.
  • Rejection in a tiny shape. A circle wastes about 21% of tries; a thin ring in a big box wastes most. Use a tight box, and cap the tries if the shape could be empty. Never pull outside points onto the edge instead: they pile up on the rim.
  • Using a square root in 3D. In a ball, volume grows with the cube of the distance, so the distance is R * u ^ (1/3). With a square root, points still crowd the middle.
  • Radius zero. Every function returns the centre; the rejection loop accepts its first try because 0 ≤ 0.

In real games

Unity's Random.insideUnitCircle and Random.insideUnitSphere are documented as returning points inside a circle and a sphere of radius 1, so you do not need the square root there; Godot has no direct equivalent that I am sure of, so write the four-line function above.

When you also want points that never sit too close together, such as trees in a forest, the usual next step is Poisson disc sampling, described by Robert Bridson in 2007.

Takeaways

  • A uniform scatter gives every patch of equal area the same chance of a point.
  • A random angle with R * random() crowds the centre, because inner rings are shorter but get as many points.
  • R * sqrt(random()) fixes it: within half the radius you get a quarter of the points, matching a quarter of the area.
  • Rejection sampling, picking in a box and retrying outside the shape, works for any shape you can test, at about 1.27 tries per point for a circle.
  • For a ring, blend the squared radii and take the root; for a ball, use a cube root.
