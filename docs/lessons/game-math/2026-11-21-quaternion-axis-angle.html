Quaternion intuition: how does my ship loop without locking?

How a quaternion stores any 3D rotation as one turn about one axis, in four numbers, and how to build one, combine two and rotate a point.

Yesterday's plane stopped turning sideways when it dived straight down, because yaw, pitch and roll are three turns about fixed axes, and two of those axes lined up. A space ship has to loop, barrel roll and dive in any order without ever locking. Engines solve this by storing rotations in a different form: the quaternion.

Every rotation is one turn about one axis

Pick up a book and turn it any way you like, as many times as you like, keeping its centre in place. There is always a single line through the book, and a single turn about that line, that takes it from where it started to where it is now. This fact is called Euler's rotation theorem.

So a rotation can be stored as two things:

  • an axis: a direction of length 1, the line the object turns around;
  • an angle: how far it turns, written θ (the Greek letter theta).

In this lesson's axes (x right, y up, z forward, away from you, as in Unity and in yesterday's lesson) a positive turn about the up axis swings the nose from forward (+z) towards the right (+x). There are no rings and no order of turns, so nothing can line up and lock.

The four numbers

A quaternion is that axis and angle packed into four numbers, called w, x, y and z. The packing uses half the angle:

w = cos(θ / 2)
x = axis.x × sin(θ / 2)
y = axis.y × sin(θ / 2)
z = axis.z × sin(θ / 2)

Worked example. Turn 90° about the up axis (0, 1, 0). Half of 90° is 45°, and cos 45° = sin 45° ≈ 0.707:

w = 0.707            x = 0 × 0.707 = 0
y = 1 × 0.707 = 0.707    z = 0 × 0.707 = 0

A few more, all about the up axis, so you can see the pattern:

Turn about upwxyz
0° (no turn)1000
90°0.70700.7070
180°0010
360° (back home)−1000

w near 1 means "hardly turned", w near 0 means "half a turn". Because cos² + sin² = 1, the four numbers always have length 1: √(w² + x² + y² + z²) = 1. A quaternion of length 1 is a unit quaternion, and only those are rotations.

Why half the angle? It makes the next two formulas work; the full reason needs more algebra than this lesson. One side effect is in the table: a full 360° turn gives w = −1, not 1, yet the object is back where it started. The numbers q and −q (every number negated) always mean the same rotation.

Combining two turns: multiply

To do one rotation and then another, you multiply the quaternions. For a × b (turn by b first, then by a):

w = a.w·b.w − a.x·b.x − a.y·b.y − a.z·b.z
x = a.w·b.x + a.x·b.w + a.y·b.z − a.z·b.y
y = a.w·b.y − a.x·b.z + a.y·b.w + a.z·b.x
z = a.w·b.z + a.x·b.y − a.y·b.x + a.z·b.w

Check with two 90° turns about up, a = b = (0.707, 0, 0.707, 0). Then w = 0.5 − 0.5 = 0, y = 0.5 + 0.5 = 1 and x = z = 0. The result (0, 0, 1, 0) is the 180° row of the table. The order matters: a × b and b × a are usually different, just like turning then rolling is different from rolling then turning.

This is what fixes the dive. To turn a ship about its own nose or wing, multiply its orientation on the right by a small turn: orientation = orientation × turn. Each small turn is about whichever way the ship points right now, so it never runs out of directions.

Rotating a point

To move a point p, written u for the quaternion's (x, y, z) part and × for the cross product:

t  = 2 × (u × p)
p' = p + w·t + u × t

Rotate the nose (0, 0, 1) by the 90° quaternion, where u = (0, 0.707, 0). The cross product u × p = (0.707, 0, 0), so t = (1.414, 0, 0) and w·t = (1, 0, 0). Then u × t = (0, 0, −1). Adding: p' = (0, 0, 1) + (1, 0, 0) + (0, 0, −1) = (1, 0, 0). The nose now points right, the same answer yesterday's yaw formula gives.

The code

The three functions from the concept, plus a ship steered with local turns. A quaternion is a table { w, x, y, z }.

-- x right, y up, z forward. Angles in degrees.
local function fromAxisAngle(ax, ay, az, degrees)
  local len = math.sqrt(ax * ax + ay * ay + az * az)
  if len < 1e-9 then return { w = 1, x = 0, y = 0, z = 0 } end   -- no axis: no turn
  local half = math.rad(degrees) / 2
  local s = math.sin(half) / len                                   -- divide: unit axis
  return { w = math.cos(half), x = ax * s, y = ay * s, z = az * s }
end

-- a * b: turn by b first, then by a
local function multiply(a, b)
  return {
    w = a.w * b.w - a.x * b.x - a.y * b.y - a.z * b.z,
    x = a.w * b.x + a.x * b.w + a.y * b.z - a.z * b.y,
    y = a.w * b.y - a.x * b.z + a.y * b.w + a.z * b.x,
    z = a.w * b.z + a.x * b.y - a.y * b.x + a.z * b.w }
end

local function normalise(q)
  local len = math.sqrt(q.w * q.w + q.x * q.x + q.y * q.y + q.z * q.z)
  return { w = q.w / len, x = q.x / len, y = q.y / len, z = q.z / len }
end

local function rotate(q, p)
  local tx = 2 * (q.y * p.z - q.z * p.y)      -- t = 2 * (u x p)
  local ty = 2 * (q.z * p.x - q.x * p.z)
  local tz = 2 * (q.x * p.y - q.y * p.x)
  return { x = p.x + q.w * tx + (q.y * tz - q.z * ty),   -- p + w*t + u x t
           y = p.y + q.w * ty + (q.z * tx - q.x * tz),
           z = p.z + q.w * tz + (q.x * ty - q.y * tx) }
end

local orientation = { w = 1, x = 0, y = 0, z = 0 }

local function turnLocal(ax, ay, az, degrees)    -- about the ship's own axis
  orientation = normalise(multiply(orientation, fromAxisAngle(ax, ay, az, degrees)))
end

function love.update(dt)
  local step = 60 * dt
  if love.keyboard.isDown("d") then turnLocal(0, 1, 0,  step) end   -- yaw right
  if love.keyboard.isDown("a") then turnLocal(0, 1, 0, -step) end
  if love.keyboard.isDown("s") then turnLocal(1, 0, 0,  step) end   -- pitch down
  if love.keyboard.isDown("w") then turnLocal(1, 0, 0, -step) end
  if love.keyboard.isDown("e") then turnLocal(0, 0, 1,  step) end   -- roll
  if love.keyboard.isDown("q") then turnLocal(0, 0, 1, -step) end
end

function love.draw()
  local o = orientation
  local nose = rotate(o, { x = 0, y = 0, z = 1 })
  love.graphics.print(string.format("q = (%.3f, %.3f, %.3f, %.3f)", o.w, o.x, o.y, o.z), 10, 10)
  love.graphics.print(string.format("nose = (%.2f, %.2f, %.2f)", nose.x, nose.y, nose.z), 10, 30)
end

Hold S for 1.5 seconds: the nose reads (0, −1, 0), straight down. Now hold D: the nose swings sideways, which the Euler version could not do.

Built-in versions: in Unity, Quaternion.AngleAxis(degrees, axis) builds one and q * v rotates a vector. In Godot 4, Quaternion(axis, radians) builds one (the axis must have length 1) and q * v rotates a vector.

Pitfalls

  • A zero-length axis. (0, 0, 0) has no direction, and dividing by its length divides by zero. fromAxisAngle returns "no turn" instead.
  • Forgetting the half angle. Putting cos θ instead of cos(θ / 2) into w makes every rotation turn twice as far. If 90° turns your object 180°, look here first.
  • Angles past 180°, and q versus −q. 270° about up gives (−0.707, 0, 0.707, 0), which is exactly −1 times the quaternion for −90° about up, and the object ends up in the same pose. So two quaternions can look different and still be equal rotations. When you compare them, also check whether one is the negative of the other.
  • Reading the axis back near 0°. The axis is (x, y, z) ÷ sin(θ / 2), and that sine is 0 when there is no turn. Check for it, just as the demo does.
  • Drift. Each multiply adds a tiny rounding error, so after many frames the length creeps away from 1 and the object starts to stretch. Normalising after each multiply, as turnLocal does, is cheap.
  • Number order. This lesson writes (w, x, y, z). Unity and Godot construct quaternions as (x, y, z, w). Mixing them up fails silently.
  • Multiply order. orientation × turn turns about the object's own axes. turn × orientation turns about the world's axes. Both are useful; pick on purpose.

In real games

Unity's Transform.rotation is a quaternion, even though the Inspector shows Euler angles. Godot has a Quaternion type next to its Basis matrix, and Unreal Engine has FQuat next to FRotator. The glTF 2.0 model format stores node rotations as unit quaternions in x, y, z, w order.

Typical uses: space and flight games, freely orbiting cameras, and skeletal animation, where bone rotations are commonly stored as quaternions so they blend smoothly.

Takeaways

  • Any 3D rotation is a single turn by an angle about one axis.
  • A quaternion stores it as w = cos(θ / 2) and (x, y, z) = axis × sin(θ / 2), four numbers of total length 1.
  • Multiply quaternions to chain turns; order matters. orientation × turn turns about the object's own axes and never locks.
  • Rotate a point with t = 2 (u × p), p' = p + w·t + u × t.
  • q and −q are the same rotation; normalise to stop drift.
