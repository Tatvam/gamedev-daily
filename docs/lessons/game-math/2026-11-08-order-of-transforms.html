The order of transforms: why does my ship orbit the corner of the screen?

Why rotating then moving puts a ship somewhere else than moving then rotating, and how multiplying matrices in the right order fixes it.

You press the turn key and, instead of spinning on the spot, your ship swings in a huge circle around the top-left corner of the screen. Or you make it twice as big and it also jumps twice as far from the corner. The numbers are right. The order is wrong.

This lesson shows why the order of the steps decides where the ship lands.

Every step happens around the origin

As in the last lesson, y points down, as on a screen and in LÖVE, so a positive angle turns clockwise. The origin is the point (0, 0) of the world.

We have three kinds of step. Each one is a small transform of its own:

  • Scale multiplies every x by sx and every y by sy. It stretches away from the origin.
  • Rotate turns every point by an angle. It turns around the origin.
  • Move adds (tx, ty) to every point. It does not care where the origin is.

So scale and rotate only act "on the spot" while the ship sits on the origin. Once it has moved away, a rotation swings it around the origin like a stone on a string, and a scale pushes it further out.

One point, two orders

Take the nose of the ship, (1, 0). Turn it 90 degrees and move it by (4, 0). A 90 degree turn with y down sends (x, y) to (−y, x).

  • Rotate, then move: (1, 0) turns to (0, 1), then moves to (4, 1). The ship's centre (0, 0) stays put while turning, then moves to (4, 0).
  • Move, then rotate: (1, 0) moves to (5, 0), then turns around the origin to (0, 5). The centre goes (0, 0) to (4, 0) to (0, 4): it has swung a quarter circle.

Scale behaves the same: scale by 2 after moving to (4, 0) and the centre lands on (8, 0). And stretching by (2, 1) before turning makes the ship long along its nose; turning first stretches it along the world x, so it comes out fat.

Combining steps is matrix multiplication

Each step is a matrix, like the ones from last time. Doing one step after another is one new matrix, their product. The rule from last lesson does the work: the columns of a matrix are where the x arrow, the y arrow and the origin land. So to do B first and then A, push B's three columns through A. The first two are arrows (directions, no move), the third is a position:

A × B:   a  = A.a × B.a + A.c × B.b        c  = A.a × B.c + A.c × B.d
         b  = A.b × B.a + A.d × B.b        d  = A.b × B.c + A.d × B.d
         tx = A.a × B.tx + A.c × B.ty + A.tx
         ty = A.b × B.tx + A.d × B.ty + A.ty

Notice the direction: A × B means B first, then A. The point sits on the right, A × B × p, so the matrix next to it touches it first. Matrices are read from right to left.

Worked example. Rotate 90°, R, has columns (0, 1), (−1, 0) and (0, 0). Move (4, 0), T, has columns (1, 0), (0, 1) and (4, 0).

  • T × R, rotate first: push R's columns through T. The arrows are not moved: (0, 1) and (−1, 0). The origin (0, 0) moves to (4, 0). Nose: 0 × 1 + (−1) × 0 + 4 = 4 and 1 × 1 + 0 × 0 + 0 = 1, so (4, 1).
  • R × T, move first: push T's columns through R. The arrows turn to (0, 1) and (−1, 0). The origin column (4, 0) turns to (0, 4). Nose: 0 + 0 + 0 = 0 and 1 + 0 + 4 = 5, so (0, 5).

Same answers as the step-by-step version. So T × R is not R × T: matrix multiplication does not let you swap the two sides.

The usual order

For placing an object, scale, then rotate, then move. Scale and rotate while the ship still sits on the origin, so they happen on the spot. Move last, so the position you asked for is exactly where it ends up.

Two moves, two rotations, or a rotation and a uniform scale (same number for x and y) can swap safely. A move paired with anything else cannot. Sometimes you want the "wrong" order on purpose. To turn a door around its hinge at (2, 1), move the hinge to the origin, rotate, and move it back: T(2, 1) × R × T(−2, −1). That is the pivot trick from the rotation lesson, written as matrices.

The code

Three small functions make the steps, multiply combines two, and combine takes a list of steps in the order they happen. Note that each new step goes on the left. The numbers match the demo's starting values: the usual order puts the nose at (4, 2), the swapped order at (0, 5).

-- y grows downwards, so a positive angle turns clockwise.
-- A transform keeps the top two rows of the matrix: a c tx / b d ty.
local function makeScale(sx, sy) return { a = sx, b = 0, c = 0, d = sy, tx = 0, ty = 0 } end
local function makeMove(tx, ty)  return { a = 1, b = 0, c = 0, d = 1, tx = tx, ty = ty } end
local function makeRotate(angle)
  local cosA, sinA = math.cos(angle), math.sin(angle)
  return { a = cosA, b = sinA, c = -sinA, d = cosA, tx = 0, ty = 0 }
end

-- multiply(A, B) means "B first, then A".
local function multiply(A, B)
  return {
    a = A.a * B.a + A.c * B.b,  c = A.a * B.c + A.c * B.d,
    b = A.b * B.a + A.d * B.b,  d = A.b * B.c + A.d * B.d,
    tx = A.a * B.tx + A.c * B.ty + A.tx,
    ty = A.b * B.tx + A.d * B.ty + A.ty,
  }
end

-- steps are listed in the order they happen to the ship
local function combine(steps)
  local m = makeScale(1, 1)                  -- identity: changes nothing
  for _, step in ipairs(steps) do
    m = multiply(step, m)                    -- the newest step goes on the left
  end
  return m
end

local function transformPoint(m, x, y)
  return m.a * x + m.c * y + m.tx, m.b * x + m.d * y + m.ty
end

local scale, rotate, move = makeScale(2, 1), makeRotate(math.rad(90)), makeMove(4, 0)
local usual   = combine({ scale, rotate, move })   -- nose lands on (4, 2)
local swapped = combine({ move, rotate, scale })   -- nose lands on (0, 5)

local UNIT, ORIGIN_X, ORIGIN_Y = 40, 200, 150
local SHIP = { {1, 0}, {-1, 1}, {-0.5, 0}, {-1, -1} }   -- nose, wing, notch, wing

local function drawShip(m)
  local points = {}
  for _, p in ipairs(SHIP) do
    local x, y = transformPoint(m, p[1], p[2])
    table.insert(points, ORIGIN_X + x * UNIT)
    table.insert(points, ORIGIN_Y + y * UNIT)
  end
  love.graphics.polygon("line", points)
end

function love.draw()
  drawShip(usual)
  drawShip(swapped)
end

LÖVE's own drawing transform works the same way, which surprises many people: the calls are written move, rotate, scale, but the shape feels them in the reverse order, because each call goes on the right of the current transform.

love.graphics.push()
love.graphics.translate(x, y)   -- happens to the shape last
love.graphics.rotate(angle)
love.graphics.scale(2, 1)       -- happens to the shape first
drawShipAtOrigin()              -- your own function that draws around (0, 0)
love.graphics.pop()

Built-in versions: Godot's Transform2D and Unity's Matrix4x4 both multiply with *, and in both A * B applies B first. Unity's Matrix4x4.TRS builds the usual order, scale then rotate then move, in one call.

Pitfalls

  • Reading the product left to right. Move × Rotate × Scale scales first. When an engine call surprises you, test it on (1, 0) with a 90 degree turn and a move of (4, 0).
  • Rotating or scaling after the move. The ship orbits the corner of the screen, or jumps away when it grows. Put the move last, or use move, rotate, move back for a pivot.
  • Non-uniform scale after a rotation slants the shape. Set the order to Rotate → Scale → Move, the angle to 45 and scale x to 2: the ship comes out slanted (sheared). That shape cannot be described by one scale, one angle and one position any more, so reading them back from the matrix gives nonsense.
  • Wrapping angles is safe. Rotations of 450 and −270 degrees give the same matrix as 90, so wrapping the angle never changes the result, apart from rounding.
  • Combining per point. Multiplying is associative: (A × B) × C equals A × (B × C). So combine the steps once per object per frame, then apply the one matrix to every point, not three matrices to each point.

In real games

Godot and Unity, like most engines, store an object's transform in the usual order, scale then rotate then move, which is why the position you type into the editor is exactly where the object's origin appears. Unity's Matrix4x4.TRS is named after that order, written right to left as translate, rotate, scale.

You meet the order yourself when drawing with love.graphics.translate and rotate, turning a door or turret around a hinge, zooming a camera around the mouse instead of the screen corner, and making orbits, which the swapped order gives for free.

Your turn (15 minutes)

Make a sign that swings on a hinge. Draw a rectangle from (−1, 0) to (1, 2) around its own origin, and hang it from a hinge at local (0, 0). Build its matrix with combine({ rotate, move }), where the angle is 0.4 * math.sin(time) and the move puts the hinge at the screen point you want.

Then move the hinge to the sign's top-left corner, (−1, 0), using the pivot trick: combine({ makeMove(1, 0), rotate, makeMove(-1, 0), move }). You are done when the first version swings from its top middle, the second from its corner, and swapping rotate and move makes the sign fly in a wide arc instead.

Takeaways

  • Scale and rotate always work around the origin, so they only act "on the spot" while the object is still at (0, 0).
  • The usual order for placing an object is scale, then rotate, then move.
  • Combining steps is matrix multiplication, and A × B means B first, then A. Written as matrices, the usual order is Move × Rotate × Scale.
  • Swapping the order of a move with anything else changes the result. Use that on purpose to rotate around a pivot or to orbit.
