The dot product: is the player in front of the guard?

How multiplying two vectors component by component and adding gives one number that says whether they point the same way, and how far apart they are.

A guard in a stealth game should spot you when you walk up to its face, and not when you sneak up behind it. You know which way the guard is looking and where you are. Which single number tells "in front" from "behind"?

That number is the dot product: two multiplications and one addition, no angles needed.

Two arrows from the guard

As in the earlier lessons, positions are in grid squares and y grows downwards, as on a screen. Draw two arrows starting at the guard:

  • a, the facing: the way the guard looks. In our example a = (3, 1).
  • b, guard to player: player position minus guard position, as in the subtraction lesson.

Now look at the three pictures below before reading any formula. When b leans the same way as a, the player is in front. When it leans the opposite way, the player is behind. The dashed line through the guard, at a right angle to the facing, is the border between the two.

The recipe

In words: multiply the two x numbers, multiply the two y numbers, and add the results. The answer is the dot product, written with a raised dot and read "a dot b":

a · b = ax × bx + ay × by

Here ax means "the x part of a", by means "the y part of b", and so on.

Worked through for the three panels, with a = (3, 1):

  • b = (2, 4): 3 × 2 + 1 × 4 = 6 + 4 = 10. Positive: in front.
  • b = (−1, 3): 3 × (−1) + 1 × 3 = −3 + 3 = 0. Zero: exactly to the side.
  • b = (−2, 1): 3 × (−2) + 1 × 1 = −6 + 1 = −5. Negative: behind.

Why does it work? Try the easiest facing, a = (1, 0), straight along x. Then a · b = 1 × bx + 0 × by = bx. The dot product is just "how far along the facing the player is": positive ahead, negative behind. Turning the guard and the player together does not change the dot product, so the same reading holds for any facing. That is why the sign is all you need for "in front or behind".

The angle hiding inside

The dot product also equals the two lengths multiplied together, times the cosine of the angle between the arrows:

a · b = |a| × |b| × cos θ

|a| is the length of a, from the length lesson. θ (the Greek letter theta) is the angle between the two arrows. The cosine, cos, turns an angle into a number: 1 at 0°, 0 at 90°, −1 at 180°, and in between it slides smoothly. A later lesson builds it from a circle; for now the picture below is enough.

Lengths are never negative, so the sign of the dot product is always the sign of cos θ: positive below 90°, zero at exactly 90°, negative above it. The dashed line in the first diagram is the line of 90° angles.

Turn the formula around and you get the angle itself. Check it on the first panel. |a| = √(3² + 1²) = √10 and |b| = √(2² + 4²) = √20, so |a| × |b| = √200 ≈ 14.14. Then cos θ = 10 ÷ 14.14 ≈ 0.71, and the angle whose cosine is 0.71 is 45°. The inverse of cosine is called arccos, math.acos in Lua, and it gives radians, which math.deg turns into degrees.

Rule of thumb

For "same side or not", use the sign of a · b and skip everything else. For "how close in direction", normalise both vectors first: then a · b is cos θ, a number from −1 to 1.

One more note on y. The demo and the code use y down, like LÖVE. Flipping y flips both arrows, so the dot product and the angle come out the same in a y-up world.

The code

The same guard and the same numbers. A square is 40 pixels. The player starts at guard + (2, 4), so the first frame prints 10 and 45 degrees; then it follows the mouse.

-- Positions are in grid squares. y grows downwards, like LÖVE's screen.
local UNIT = 40                     -- pixels per grid square
local guard = { x = 5, y = 5 }
local facing = { x = 3, y = 1 }     -- a: the way the guard looks
local player = { x = 7, y = 9 }     -- guard + (2, 4)

local function dot(a, b)
  return a.x * b.x + a.y * b.y
end

local function length(v)
  return math.sqrt(v.x * v.x + v.y * v.y)
end

-- Angle between two vectors in degrees, always from 0 to 180.
local function angleBetween(a, b)
  local lengths = length(a) * length(b)
  if lengths == 0 then
    return nil                      -- a zero vector has no direction
  end
  local c = dot(a, b) / lengths     -- this is cos(theta)
  c = math.max(-1, math.min(1, c))  -- rounding can push it past 1
  return math.deg(math.acos(c))
end

function love.mousemoved(x, y)
  player = { x = x / UNIT, y = y / UNIT }
end

function love.draw()
  local toPlayer = { x = player.x - guard.x, y = player.y - guard.y }  -- b
  local d = dot(facing, toPlayer)
  local status = "exactly to the side"
  if d > 0 then
    status = "in front"
  elseif d < 0 then
    status = "behind"
  end
  local angle = angleBetween(facing, toPlayer)
  local angleText = "none"
  if angle then
    angleText = string.format("%.0f degrees", angle)
  end

  local gx, gy = guard.x * UNIT, guard.y * UNIT
  love.graphics.line(gx, gy, gx + facing.x * UNIT, gy + facing.y * UNIT)
  love.graphics.circle("fill", gx, gy, 12)
  love.graphics.circle("line", player.x * UNIT, player.y * UNIT, 8)
  love.graphics.print(string.format("a . b = %.2f, %s", d, status), 10, 10)
  love.graphics.print("angle: " .. angleText, 10, 30)
end

Check it by hand: dot({ x = 3, y = 1 }, { x = 2, y = 4 }) is 10, and angleBetween of the same two is 45. Built-in versions: Godot has Vector2.dot, Unity has Vector2.Dot, and Unity's Vector2.Angle gives the angle between two vectors in degrees.

Pitfalls

  • Comparing with a number other than 0 without normalising. The sign of a · b never depends on length, but its size does. With a = (3, 1) and b = (2, 4) the dot product is 10; move the player twice as far in the same direction and it is 20. A test such as d > 0.5 only means "within 60°" (cos 60° = 0.5) when both vectors have length 1, and then you never need acos at all.
  • Zero-length vectors. If the player stands exactly on the guard, b = (0, 0) and a · b = 0, which reads as "exactly to the side". That is meaningless, not 90°, and the angle would divide by 0, so angleBetween returns nil. Decide what your game does then.
  • arccos of 1.0000000000000002. Computer arithmetic rounds. For a = (0.1, 0.3) and b = (0.3, 0.9), which point exactly the same way, a · b ÷ (|a| × |b|) comes out slightly above 1, and math.acos returns NaN (not a number). Clamp to the range −1 to 1 first, as the code does.
  • The angle never passes 180°. Walk the player all the way round the guard and θ climbs to 180° directly behind, then falls back to 0°. The dot product cannot tell left from right: (−1, 3) and (1, −3) both give 0. That needs the cross product, which comes later in this track.
  • Using positions instead of directions. dot(facing, player) measures the player from the corner of the map, not from the guard. Subtract the guard's position first.

In real games

"Is that thing in front of me?" sits behind enemy sight checks, backstab bonuses, and AI that only reacts to targets ahead of it.

In graphics, Lambert's diffuse lighting sets the brightness of a surface from the dot product of its unit normal (the arrow pointing straight out of it) and the unit direction towards the light: 1 facing the light, 0 or less facing away.

The dot product also measures how much of one vector lies along another, which is how sliding along walls and bouncing off them is calculated. That is the projection lesson, two steps from here.

Takeaways

  • a · b = ax × bx + ay × by: multiply matching parts and add. Two vectors in, one number out.
  • Positive means the vectors lean the same way, zero means a right angle, negative means they lean apart.
  • a · b = |a| × |b| × cos θ, so with two unit vectors the dot product is cos θ, from −1 to 1.
  • For "in front or behind" use only the sign. Normalise before comparing with any other number.
  • Guard against zero-length vectors and clamp before calling acos.
