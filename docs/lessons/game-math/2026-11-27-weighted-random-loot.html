Weighted random choice: how does a loot table make a crown rare?

How to give every item in a loot table its own chance with weights, one random roll and a short walk along a line, so coins drop often and crowns rarely.

A chest should usually hold coins, sometimes a potion, now and then a shield or a sword, and only very rarely a crown. Picking a random item from a list of five gives each one a 20% chance, so crowns rain from every chest and stop feeling special. You need a way to say "this one is common, that one is rare" and have the dice respect it.

Give every item a weight

A loot table is a list of things that can drop, each with a number called its weight. A bigger weight means a bigger share of the drops. The weights do not have to add up to anything special. What matters is each weight compared with the total weight, the sum of all of them:

chance of an item = its weight / total weight

Here is the chest from the hook. The weights happen to add up to 100, so each weight reads directly as a percentage.

Lay the weights end to end

Picture a ruler as long as the total weight. Give each item a stretch as long as its weight, one after another. Drop a pin at a random spot. Every spot is equally likely, so the pin lands in long stretches more often than short ones, in exactly the proportion of their lengths. The stretch it lands in is the item you drop.

Finding the stretch: walk and subtract

In code, the pin is a roll: a random number from 0 up to (but not including) the total weight. You get it by multiplying a random fraction from 0 to 1 by the total. Then walk along the items in order:

  1. If the roll is smaller than this item's weight, the pin is inside this item's stretch. Pick it.
  2. Otherwise subtract this item's weight from the roll and move to the next item.

Subtracting slides the ruler along, so each item's stretch starts at 0 when you reach it. Worked example with a roll of 82:

  • 82 is not below Coin's 50. Subtract: 82 − 50 = 32.
  • 32 is not below Potion's 25. Subtract: 32 − 25 = 7.
  • 7 is below Shield's 15. The chest holds a shield.

Two more to check: a roll of 49.9 stops at Coin straight away, and a roll of 98.5 goes 48.5, 23.5, 8.5, 0.5 and then lands on Crown, because 0.5 is below 2.

Changing one weight changes every chance

Raising one weight makes all the others a little rarer. Set the crown's weight to 0 and the total becomes 98: a coin is now 50 / 98, about 51.0%, and the crown can never drop. Double every weight and nothing changes at all, because the ratios stay the same. So you can add a new item without rewriting every other number.

Rule of thumb

Roll a number from 0 to the total weight, then subtract weights one by one until the roll is smaller than the current weight. That item is your pick, and its chance is its weight divided by the total.

The code

The same chest as the demo, with the same names and weights. weightedPick is the walk from above.

local lootTable = {
  { name = "Coin",   weight = 50 },
  { name = "Potion", weight = 25 },
  { name = "Shield", weight = 15 },
  { name = "Sword",  weight = 8 },
  { name = "Crown",  weight = 2 },
}

local function totalWeight(items)
  local total = 0
  for i = 1, #items do
    total = total + items[i].weight
  end
  return total
end

-- Each item's chance is its weight / total weight
local function weightedPick(items)
  local total = totalWeight(items)
  if total <= 0 then
    return nil  -- nothing can drop
  end
  local roll = love.math.random() * total  -- 0 up to, not including, total
  for i = 1, #items do
    local w = items[i].weight
    if roll < w then
      return items[i]
    end
    roll = roll - w
  end
  -- Rounding can leave roll a hair past the end: give the last item that can drop
  for i = #items, 1, -1 do
    if items[i].weight > 0 then
      return items[i]
    end
  end
end

function love.keypressed(key)
  if key == "r" then
    local item = weightedPick(lootTable)
    print("The chest holds: " .. (item and item.name or "nothing"))
  end
end
# Godot 4.3 and later: rand_weighted returns the index of the picked weight
var rng := RandomNumberGenerator.new()
var names := ["Coin", "Potion", "Shield", "Sword", "Crown"]
var weights := PackedFloat32Array([50, 25, 15, 8, 2])

func open_chest() -> String:
    return names[rng.rand_weighted(weights)]

Unity has no built-in weighted pick that I am sure of; port weightedPick directly, using Random.value for the random fraction.

If you prefer whole numbers, roll love.math.random(1, total) and test roll <= w instead of roll < w. With the chest, rolls 1 to 50 give a coin, which is 50 of the 100 possible rolls.

Pitfalls

  • Mixing up < and <=. With a fractional roll from 0, use <; with a whole-number roll from 1, use <=. Mixing them gives the first item one extra slot and the last item one fewer, and a weight of 0 can suddenly drop.
  • A total weight of 0. Every weight is 0, or the table is empty. The roll is always 0, nothing is ever smaller than 0, and the loop falls off the end. Check for it and return nil, then decide what an empty chest means in your game.
  • Negative weights. A negative weight shrinks the total and steals from its neighbours. Treat it as a bug: clamp it to 0 or report it when you load the table.
  • Rounding at the very end. With fractional weights such as 0.1 and 0.2, the subtractions can leave a tiny leftover so the loop finishes without a pick. The fallback at the end of weightedPick catches that.
  • Huge tables picked very often. The walk checks items one by one, which is fine for 5 or 50. For thousands of entries picked every frame, store the running totals (50, 75, 90, 98, 100) once and search them by halving the range each step, a binary search.
  • 2% does not mean once in 50 chests. Each roll is independent, so a player can open 150 chests without a crown. The demo shows how noisy rare items are. The next lessons deal with this.

In real games

Minecraft's data-driven loot tables give each entry a weight, and its wiki describes the chance of an entry as its weight divided by the total of the weights in its pool, which is exactly the rule above. Godot 4.3 added RandomNumberGenerator.rand_weighted, which takes an array of weights and returns the index of the pick.

For a fixed table picked from millions of times, the alias method, published by Alastair Walker in the 1970s, makes every pick equally cheap however many items there are. Games rarely need it.

Takeaways

  • A weight is a share, not a percentage: each item's chance is its weight divided by the total weight.
  • Lay the weights end to end on a line, drop one random roll from 0 to the total, and pick the stretch it lands in.
  • In code, subtract weights one by one until the roll is smaller than the current weight.
  • Changing one weight changes every chance; scaling all weights changes none.
  • Guard against a total of 0, negative weights and rounding at the end of the walk.
