Catmull-Rom splines: how do I make a path through every waypoint?

How a Catmull-Rom spline works out Bezier handles from neighbouring points, so a smooth path passes through every waypoint you place.

You place six waypoints for a patrol drone. Straight lines between them make it snap to a new heading at every waypoint. Yesterday's Bezier curves are smooth, but now every waypoint needs two handles placed by hand, and moving one waypoint means fixing its handles again.

What you want is to place only the waypoints and have the handles worked out for you. That is what a Catmull-Rom spline does.

Let the neighbours choose the direction

A spline is a path made of curve pieces joined end to end. Each piece, called a segment, runs from one waypoint to the next. A Catmull-Rom spline is a spline that passes through every waypoint, and it decides the direction at each waypoint with one simple rule:

The rule

At each waypoint, head in the direction from the previous waypoint to the next one.

A cubic Bezier segment leaves towards its first handle and arrives from its second, so the rule only has to place the two handles of each segment. For the segment from P1 to P2, with P0 the waypoint before and P3 the one after:

handle out of P1 = P1 + (P2 − P0) / 6
handle into  P2 = P2 − (P3 − P1) / 6

In words: take the neighbour line, the arrow from the waypoint before to the waypoint after, and shrink it to one sixth. Add it to the waypoint for the handle out; subtract it for the handle in.

One sixth makes the velocity through each waypoint half the neighbour line, the choice usually called Catmull-Rom. Other fractions are smooth too; that is what tension changes.

A worked example

Positions are in grid squares and y grows downwards, as in LÖVE, so a smaller y is higher on screen. Four waypoints: P0 = (0, 8), P1 = (2, 2), P2 = (6, 2) and P3 = (8, 8). We build the middle segment, from P1 to P2.

  • The neighbour line at P1 is P2 − P0 = (6 − 0, 2 − 8) = (6, −6). One sixth of it is (1, −1), so the handle out of P1 is (2, 2) + (1, −1) = (3, 1).
  • The neighbour line at P2 is P3 − P1 = (6, 6). One sixth is (1, 1), so the handle into P2 is (6, 2) − (1, 1) = (5, 1).
  • Feed (2, 2), (3, 1), (5, 1), (6, 2) into yesterday's cubic Bezier. At t = 0.5 the weights are 1/8, 3/8, 3/8, 1/8. For x: (2 + 9 + 15 + 6) / 8 = 4. For y: (2 + 3 + 3 + 2) / 8 = 1.25. The halfway point is (4, 1.25).

The curve rises to y = 1.25, above the straight line at y = 2, because it still carries the upward movement from P0.

Why there is never a kink

The segment after P1 leaves towards P1 + (P2 − P0) / 6; the segment before arrives from P1 − (P2 − P0) / 6, the hollow square at (1, 3). The two handles are mirrored through P1: yesterday's rule for a smooth joint with no speed jump, for free at every waypoint.

The velocity through P1 is 3 × (handle − P1) = 3 × (1, −1) = (3, −3), which is half of the neighbour line (6, −6).

The ends and closed loops

The first waypoint has no previous neighbour and the last has no next one. A simple fix lets an end waypoint stand in for its missing neighbour, so the path starts heading straight at P1. On a closed path, such as a race track, the neighbours wrap round: after the last waypoint comes the first.

Tension

With a tension number c, the handle offset becomes (1 − c) / 6 of the neighbour line:

  • c = 0 is the Catmull-Rom spline: one sixth. The middle segment peaks at y = 1.25.
  • c = 0.5 halves the handles to one twelfth: (2.5, 1.5) and (5.5, 1.5). The peak is y = 1.625, closer to the straight line.
  • c = 1 puts the handles on the waypoints themselves. The path becomes straight lines, and the drone comes to a complete stop at every waypoint.

Splines with this tension number are often called cardinal splines; Catmull-Rom is the one with tension 0.

The code

The drone from the demo: six waypoints, 1.5 seconds per segment, 40 pixels per grid square. catmullRom computes the two handles and hands them to yesterday's bezier3. Click in the window to add a waypoint.

-- Points are tables { x, y }. y grows downwards, like LÖVE's screen.
local function vec(x, y) return { x = x, y = y } end

local function lerpPoint(p, q, t)
  return vec(p.x + (q.x - p.x) * t, p.y + (q.y - p.y) * t)
end

-- Yesterday's cubic Bezier. Returns the point and the velocity.
local function bezier3(p0, p1, p2, p3, t)
  local a = lerpPoint(p0, p1, t)
  local b = lerpPoint(p1, p2, t)
  local c = lerpPoint(p2, p3, t)
  local d = lerpPoint(a, b, t)
  local e = lerpPoint(b, c, t)
  return lerpPoint(d, e, t), vec(3 * (e.x - d.x), 3 * (e.y - d.y))
end

-- Waypoint number i. Open paths repeat their end points; closed paths wrap.
local function pointAt(points, i, closed)
  local n = #points
  if closed then return points[(i - 1) % n + 1] end
  return points[math.max(1, math.min(i, n))]
end

-- Segment i runs from points[i] to points[i + 1].
local function catmullRom(points, i, t, tension, closed)
  local p0 = pointAt(points, i - 1, closed)
  local p1 = pointAt(points, i, closed)
  local p2 = pointAt(points, i + 1, closed)
  local p3 = pointAt(points, i + 2, closed)
  local k = (1 - tension) / 6
  local h1 = vec(p1.x + (p2.x - p0.x) * k, p1.y + (p2.y - p0.y) * k)
  local h2 = vec(p2.x - (p3.x - p1.x) * k, p2.y - (p3.y - p1.y) * k)
  return bezier3(p1, h1, h2, p2, t)
end

local UNIT = 40                                 -- pixels per grid square
local function grid(x, y) return vec(x * UNIT, y * UNIT) end
local points = { grid(0, 8), grid(2, 2), grid(6, 2), grid(8, 8), grid(12, 7), grid(15, 2) }
local TENSION = 0
local CLOSED = false
local SECONDS_PER_SEGMENT = 1.5
local u = 0                                     -- 0 = start of path, 1 = end
local heading = 0

local function segmentCount()
  if CLOSED then return #points end
  return #points - 1
end

-- Point and velocity at a position pos from 0 to 1 along the whole path.
local function pathPoint(pos)
  local count = segmentCount()
  local s = math.max(0, math.min(pos, 1)) * count
  local i = math.min(math.floor(s), count - 1)  -- pos = 1 is the end of the last segment
  return catmullRom(points, i + 1, s - i, TENSION, CLOSED)
end

function love.mousepressed(x, y, button)
  if button == 1 and #points < 12 then
    points[#points + 1] = vec(x - 40, y - 40)  -- undo the translate in love.draw
  end
end

function love.update(dt)
  u = u + dt / (segmentCount() * SECONDS_PER_SEGMENT)
  if u > 1 then u = 0 end
end

function love.draw()
  love.graphics.push()
  love.graphics.translate(40, 40)
  local coords = {}
  local steps = segmentCount() * 24
  for j = 0, steps do
    local p = pathPoint(j / steps)
    coords[#coords + 1] = p.x
    coords[#coords + 1] = p.y
  end
  love.graphics.line(coords)
  for _, w in ipairs(points) do
    love.graphics.circle("fill", w.x, w.y, 5)
  end
  local p, v = pathPoint(u)
  if v.x ~= 0 or v.y ~= 0 then                  -- keep the old heading if v is zero
    heading = math.atan2(v.y, v.x)
  end
  love.graphics.translate(p.x, p.y)
  love.graphics.rotate(heading)
  love.graphics.polygon("fill", 12, 0, -8, -7, -8, 7)
  love.graphics.pop()
  local speed = math.sqrt(v.x * v.x + v.y * v.y) / UNIT / SECONDS_PER_SEGMENT
  love.graphics.print(string.format("u = %.2f  (%.2f, %.2f)  speed %.2f squares/s",
    u, p.x / UNIT, p.y / UNIT, speed), 10, 10)
end

With six waypoints there are five segments, so u = 0.3 is segment 2 at t = 0.5, and the printed position is (4.00, 1.25), the worked example. The speed there is 3.00 squares per second.

Built-in versions: Godot 4's Vector2.cubic_interpolate(b, pre_a, post_b, weight) takes the same four points and gives this tension 0 curve. MonoGame has Vector2.CatmullRom. We know of no Catmull-Rom function in Unity's core API; use the code above.

Pitfalls

  • The path swings outside the waypoints. Between P1 and P2 the example curve rises 0.75 squares above the straight line. A patrol path next to a wall can cut through it. Add a waypoint there or raise the tension.
  • Uneven spacing makes loops. Two close waypoints with distant neighbours get big handles on a short segment, and the curve can loop. Try it in the demo. The centripetal variant, which spaces t by the distance between waypoints, avoids these loops; it is beyond this lesson.
  • Zero velocity. With tension 1, or with two waypoints on the same spot, the velocity at a waypoint is (0, 0). There is no direction to point the drone along, and normalising it divides by zero. Keep the previous heading, as the code does.
  • t outside 0 to 1. The formula keeps going: t = 1.5 on the example segment gives (6.5, 4.25), well below P2 and not on the next segment. Clamp the position and pick the segment from it, as pathPoint does; its math.min stops pos = 1 asking for a segment that does not exist.
  • Segment count. An open path of n waypoints has n − 1 segments; a closed one has n.
  • Speed is not constant. Every segment takes 1.5 seconds whatever its length, and equal steps of t are not equal distances. The next lesson fixes this.

In real games

Catmull-Rom splines are a common choice whenever a path must pass through placed points: camera rails, racing lines for AI cars, patrol routes, and smoothing the corners off a path found on a grid. The waypoints a designer sees in the editor are exactly where the object goes.

Engines and libraries include them: Godot's cubic_interpolate functions, MonoGame's Vector2.CatmullRom (inherited from Microsoft's XNA), and Microsoft's DirectXMath, which has XMVectorCatmullRom. The curve is named after Edwin Catmull and Raphael Rom, who described a family of curves of this kind in 1974.

Paste the code into a LÖVE project. First check your catmullRom: with the grid points before multiplying by UNIT, segment 2 at t = 0.25 and tension 0 should give (2.90625, 1.4375). Then set CLOSED = true and move the waypoints until they form a lap of a race track.

You are done when the drone loops round forever with no snap at any waypoint, including the one where the lap starts. Bonus: change TENSION to 0.5 and watch the corners pull in closer to the straight lines between waypoints.

Takeaways

  • A Catmull-Rom spline passes through every waypoint and needs no hand-placed handles.
  • At each waypoint it heads along the neighbour line, from the previous waypoint to the next.
  • Handles: P1 + (P2 − P0) / 6 out of a waypoint and P2 − (P3 − P1) / 6 into the next; they are mirrored, so the path never kinks.
  • Tension c scales the handles by (1 − c): 0 is Catmull-Rom, 1 gives straight lines that stop at each waypoint.
  • Handle the ends, clamp the position, and keep the old heading when the velocity is zero.
