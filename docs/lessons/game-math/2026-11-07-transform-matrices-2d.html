2D transform matrices: how does one object store move, turn and size?

How six numbers in a 3 by 3 matrix hold a position, a rotation and a scale, and how one multiply puts every point of a ship in the right place.

Your ship is a list of points drawn around (0, 0). To put it in the level you scale every point, then rotate it, then move it: three separate steps, for every point, every frame. Then a turret is bolted onto the ship and needs the same three steps, plus its own.

Every engine packs those three steps into one small table of numbers, a transform matrix. This lesson shows what each number in it means.

Follow the two arrows and the origin

This lesson and its demo use y pointing down, as on a screen and in LÖVE, so a positive angle turns clockwise.

The rotation lesson had one key idea. A point such as (3, 1) is a recipe: "3 steps along the x arrow (1, 0), then 1 step along the y arrow (0, 1), starting from the origin". Rotating keeps the recipe and only turns the arrows. The same trick works for scale and for moving too. Ask three questions:

  1. Where does the x arrow (1, 0) end up? Scaling by sx stretches it, rotating by a turns it: (sx cos a, sx sin a).
  2. Where does the y arrow (0, 1) end up? It is stretched by sy and turned a quarter turn ahead: (−sy sin a, sy cos a).
  3. Where does the origin (0, 0) end up? Scaling and turning leave it alone, and moving puts it at the translation (tx, ty), the object's position.

Here sx and sy are the scale along x and y, a is the angle in radians, and tx and ty are how far the object is moved. A transform is the whole package of "scale, then rotate, then move". Write the three answers as three columns and you have the transform matrix, a grid of numbers usually called M:

So the matrix is three columns:

    | a  c  tx |     a = sx × cos A     c = −sy × sin A
M = | b  d  ty |     b = sx × sin A     d =  sy × cos A
    | 0  0  1  |

(Here the angle is a capital A so it does not clash with the entry a.) The first column (a, b) is where the x arrow lands, the second (c, d) where the y arrow lands, the third (tx, ty) where the origin lands. The bottom row, 0 0 1, never changes in 2D. It is there so that two matrices can be multiplied into one, which is the next lesson.

Using the matrix on a point

To transform a point (x, y), follow the recipe with the new arrows: start at the new origin, take x steps along the first column and y steps along the second:

x′ = a × x + c × y + tx
y′ = b × x + d × y + ty

Mathematicians write this as M times the column (x, y, 1). The extra 1 is the number that multiplies the third column: one lot of translation.

Worked example, the one in the diagram: scale 2, angle 90 degrees, move (4, 1). cos 90° = 0 and sin 90° = 1, so a = 2 × 0 = 0, b = 2 × 1 = 2, c = −2 × 1 = −2, d = 2 × 0 = 0. Take the wing tip (−1, 1):

  • x′ = 0 × (−1) + (−2) × 1 + 4 = 2
  • y′ = 2 × (−1) + 0 × 1 + 1 = −1

The wing lands on (2, −1). Check it the long way. Scale by 2: (−2, 2). Rotate by 90 degrees: (−2 × 0 − 2 × 1, −2 × 1 + 2 × 0) = (−2, −2). Move by (4, 1): (2, −1). Same answer, but the sines and cosines were worked out once for the whole ship, not once per point.

Positions get a 1, directions get a 0

Remember that a vector can be a place or a movement. A movement, such as the ship's "forward" (1, 0), should be turned and scaled but not moved: moving a direction makes no sense. Give it a 0 instead of the 1 and the third column drops out. Forward becomes (a, b) = (0, 2): pointing down the screen, which is where the nose now faces.

Reading the matrix back

Because the columns are the arrows, you can read a matrix by eye. The position is the third column. The angle is atan2(b, a), the direction of the first column. Scale x is the length of the first column and scale y the length of the second. The identity matrix, with 1 and 0 on the diagonal and nothing else, is the transform that changes nothing.

The code

One function builds the matrix, one applies it. The ship is the one from the demo. When it starts, the nose (1, 0) prints as (4.00, 3.00) and the wing (−1, 1) is drawn at (2, −1), as in the worked example. Hold Q or E to turn it.

-- y grows downwards, as on LÖVE's screen, so a positive angle turns clockwise.
-- Only the top two rows are stored: the bottom row is always 0, 0, 1.
local function makeTransform(tx, ty, angle, sx, sy)
  local cosA, sinA = math.cos(angle), math.sin(angle)
  return {
    a = sx * cosA,  c = -sy * sinA,  tx = tx,   -- row 1
    b = sx * sinA,  d =  sy * cosA,  ty = ty,   -- row 2
  }
end

-- A position: w = 1 (moves). A direction: w = 0 (turns and scales only).
local function transformPoint(m, x, y, w)
  w = w or 1
  return m.a * x + m.c * y + m.tx * w,
         m.b * x + m.d * y + m.ty * w
end

local UNIT = 40                       -- pixels per grid square
local ORIGIN_X, ORIGIN_Y = 200, 200   -- where (0, 0) is on screen
local ship = { {1, 0}, {-1, 1}, {-0.5, 0}, {-1, -1} }   -- nose, wing, notch, wing
local pos = { x = 4, y = 1 }
local angle = math.rad(90)
local scale = 2
local TURN_SPEED = math.rad(90)       -- radians per second

function love.update(dt)
  if love.keyboard.isDown("e") then angle = angle + TURN_SPEED * dt end
  if love.keyboard.isDown("q") then angle = angle - TURN_SPEED * dt end
end

function love.draw()
  local m = makeTransform(pos.x, pos.y, angle, scale, scale)   -- once per frame
  local points = {}
  for _, p in ipairs(ship) do
    local x, y = transformPoint(m, p[1], p[2])
    table.insert(points, ORIGIN_X + x * UNIT)
    table.insert(points, ORIGIN_Y + y * UNIT)
  end
  love.graphics.polygon("line", points)
  local noseX, noseY = transformPoint(m, 1, 0)
  local fwdX, fwdY = transformPoint(m, 1, 0, 0)                -- forward, a direction
  love.graphics.print(string.format("nose (%.2f, %.2f)  forward (%.2f, %.2f)",
    noseX, noseY, fwdX, fwdY), 10, 10)
end

Built-in versions: LÖVE has love.math.newTransform(x, y, angle, sx, sy) with a transformPoint method. In Godot, a Transform2D stores exactly these columns as x, y and origin. Unity works in 3D with Matrix4x4.TRS(position, rotation, scale) and MultiplyPoint3x4.

Pitfalls

  • Rows and columns swapped. Some books and engines write the matrix on its side, with the arrows as rows. When copying a formula, check where the translation sits: last column or bottom row.
  • Moving a direction. Transform a velocity or a "forward" vector as a position and it gets the translation added. A ship at (400, 300) then "faces" a point 400 pixels away. Use w = 0 for directions.
  • Degrees in the cosine. As always, math.cos wants radians. Angles past 180 degrees or below 0 are fine: 450 and −270 degrees give the same matrix as 90, apart from rounding.
  • Scale 0. Both arrows shrink to nothing and every point lands on the position. That cannot be undone, and reading the angle back with atan2(0, 0) gives a meaningless 0. Keep scales away from 0, or store angle and scale separately as well.
  • Negative scale mirrors. sx = −1 flips the ship. That is a handy mirror for a sprite facing left, but atan2(b, a) then reads back an angle 180 degrees off.
  • Expecting exact zeros. cos 90° comes out as about 0.00000000000000006, not 0. Round for display and never compare transformed points with ==.

In real games

Every 2D engine keeps a transform like this for each object. Godot's Node2D exposes its Transform2D directly, and LÖVE's love.graphics keeps a current transform that translate, rotate and scale change and that applies to everything drawn after them.

You will use the maths yourself when you need where something is, not just how it looks: the world position of a gun's muzzle on a turned and scaled ship, the corners of a rotated hitbox for a collision test, or the "forward" direction of an enemy for a dot product field of view check.

Your turn (15 minutes)

Give a ship in your own project a muzzle at local (1.2, 0), just in front of the nose. Each frame, build the ship's matrix once with makeTransform, then use it twice: transformPoint(m, 1.2, 0) for where bullets spawn, and transformPoint(m, 1, 0, 0) for the direction they fly. Normalise that direction before multiplying by bullet speed, because the scale stretched it.

You are done when bullets leave the tip of the nose and fly straight ahead at any angle and at scale 0.5, 1 and 3, and their speed stays the same when the ship grows.

Takeaways

  • A 2D transform matrix is three columns: where the x arrow lands, where the y arrow lands, and where the origin lands.
  • For scale sx, sy, angle A and position (tx, ty): a = sx cos A, b = sx sin A, c = −sy sin A, d = sy cos A.
  • Apply it with x′ = a x + c y + tx and y′ = b x + d y + ty. Directions use 0 instead of 1 and skip the translation.
  • You can read position, angle and scale back from the columns, unless a scale is 0 or negative.
