AABB overlap tests

How to test two axis-aligned boxes for overlap by comparing their intervals on each axis, and why checking corners misses some hits.

A long sword swing passes straight through a tall, thin enemy and nothing happens. Neither box has a corner inside the other, so the hit check says they never met. Somewhere else in the same game, a crate resting flat on the floor counts as "colliding" every single frame.

Both bugs come from the simplest collision test in games. This lesson shows the version that has neither.

A box is two intervals

An axis-aligned bounding box, or AABB, is a rectangle whose sides are parallel to the x and y axes. It never rotates. That is what makes it cheap: it is fully described by where it starts and ends on each axis.

In LÖVE, and in these lessons, a box is stored as its top-left corner x, y and its size w, h, with y growing downwards. So box A covers x from a.x to a.x + a.w, and y from a.y to a.y + a.h.

A stretch of numbers from a minimum to a maximum is an interval. Think of it as the box's shadow on that axis.

When do two intervals overlap?

Two intervals on a line are apart only if one ends before the other begins. So they overlap when each one starts before the other ends:

a.x < b.x + b.w  and  b.x < a.x + a.w

In words: A starts before B ends, and B starts before A ends.

When do two boxes overlap?

Two boxes overlap when their shadows overlap on both axes. If either axis shows a gap, a straight line fits through that gap and the boxes are apart. That is the whole test: four comparisons joined by and.

One check by hand

Take A at x = 100, y = 50, w = 60, h = 40 and B at x = 140, y = 100, w = 80, h = 30, the boxes in the diagram. On x, A covers 100 to 160 and B covers 140 to 220. Is 100 < 220? Yes. Is 140 < 160? Yes. The x shadows overlap.

On y, A covers 50 to 90 and B covers 100 to 130. Is 50 < 130? Yes. Is 100 < 90? No. The y shadows have a gap, so the boxes do not overlap.

It is often useful to know how much two intervals overlap, not just whether they do:

overlap = math.min(maxA, maxB) - math.max(minA, minB)

This is the smaller of the two ends minus the larger of the two starts. A positive result is the overlap in pixels, zero means the edges just touch, and a negative result is the size of the gap. For the example: on x, 160 − 140 = 20. On y, 90 − 100 = −10, a gap of 10. Later lessons use this number to push boxes apart.

The bug: checking corners

A test that many people write first is "is any corner of A inside B?", sometimes checked both ways round. It fails when the boxes cross like a plus sign: a tall thin box over a wide flat one. They clearly overlap in the middle, but every corner lies outside the other box.

Touching is a choice

With <, boxes whose edges meet exactly do not count as overlapping. With <=, they do.

A collision response usually pushes a box out until it is exactly touching the wall or floor. If touching counts as overlapping, that box is "still colliding" on the next step, and the next, so your code keeps reporting hits of zero depth. That is a common source of characters that stick to walls or crates that never stop firing landing sounds. The usual choice is strict < for overlap. If you need "is something right next to me", ask that separately, for example by testing a box moved one pixel down.

Another way to write it

Some code stores a box as a centre and a half extent, half its width and half its height. Then the x test reads math.abs(a.cx - b.cx) < a.hw + b.hw: the centres are closer than the two half widths added together. It is the same test, so pick whichever matches how you store boxes.

The code

A complete LÖVE program with the same two boxes and numbers as the demo's starting layout. Drag box A with the mouse; both boxes turn red when they overlap, and the two interval overlaps are printed at the top.

-- x, y is the top-left corner, y grows downwards, w and h are the size.
local boxA = { x = 150, y = 90,  w = 120, h = 80 }
local boxB = { x = 320, y = 140, w = 160, h = 100 }

-- Positive: overlap in pixels. Zero: touching. Negative: size of the gap.
local function intervalOverlap(minA, maxA, minB, maxB)
  return math.min(maxA, maxB) - math.max(minA, minB)
end

-- Strict < : boxes that only touch do not count as overlapping.
local function overlaps(a, b)
  return a.x < b.x + b.w and b.x < a.x + a.w
     and a.y < b.y + b.h and b.y < a.y + a.h
end

local dragging = false
local grabX, grabY = 0, 0

function love.mousepressed(mx, my, button)
  if button == 1 and mx >= boxA.x and mx <= boxA.x + boxA.w
     and my >= boxA.y and my <= boxA.y + boxA.h then
    dragging = true
    grabX, grabY = mx - boxA.x, my - boxA.y
  end
end

function love.mousereleased(mx, my, button)
  if button == 1 then dragging = false end
end

function love.update(dt)
  if dragging then
    local mx, my = love.mouse.getPosition()
    boxA.x, boxA.y = mx - grabX, my - grabY
  end
end

function love.draw()
  if overlaps(boxA, boxB) then
    love.graphics.setColor(1, 0.3, 0.3)
  else
    love.graphics.setColor(1, 1, 1)
  end
  love.graphics.rectangle("line", boxA.x, boxA.y, boxA.w, boxA.h)
  love.graphics.rectangle("line", boxB.x, boxB.y, boxB.w, boxB.h)

  local ox = intervalOverlap(boxA.x, boxA.x + boxA.w, boxB.x, boxB.x + boxB.w)
  local oy = intervalOverlap(boxA.y, boxA.y + boxA.h, boxB.y, boxB.y + boxB.h)
  love.graphics.setColor(1, 1, 1)
  love.graphics.print("x overlap " .. ox .. "   y overlap " .. oy, 10, 10)
end
# Godot's Rect2 is the same idea: a top-left position and a size.
var box_a := Rect2(150, 90, 120, 80)
var box_b := Rect2(320, 140, 160, 100)

func _physics_process(_delta: float) -> void:
    var hit := box_a.intersects(box_b)         # touching edges do not count
    var hit_or_touch := box_a.intersects(box_b, true)  # include_borders
    var shared := box_a.intersection(box_b)    # the overlapping rectangle
// Rect stores x, y, width and height.
Rect boxA = new Rect(150, 90, 120, 80);
Rect boxB = new Rect(320, 140, 160, 100);
public Collider2D other;   // another collider, set in the Inspector

void FixedUpdate()
{
    bool hit = boxA.Overlaps(boxB);

    // Colliders expose their AABB as a Bounds (centre and extents).
    bool roughHit = GetComponent<Collider2D>().bounds.Intersects(other.bounds);
}

In both engines you rarely write this test for physics bodies yourself: the physics engine runs it, and you ask it questions, for example with Physics2D.OverlapBox in Unity. Writing it by hand is still the right tool for hitboxes, UI and tile games with their own collision.

Pitfalls

  • Testing corners instead of intervals. Misses the plus-sign case, and checking only the corners of A also misses B sitting entirely inside A. Use the four comparisons.
  • Mixing centre and corner positions. If a sprite's position is its centre but the test treats it as the top-left corner, every hitbox is shifted by half its size. Hits register too early on one side and too late on the other. Decide on one convention and convert in one place.
  • Counting touching as overlap by accident. <= makes resting objects report zero-depth hits forever. Choose on purpose, and use the same rule everywhere.
  • Forgetting rotation. An AABB cannot rotate. For a spinning sprite, recompute a larger box around it each step, or use a rotated-shape test from later in this track.
  • Testing every pair. The test is cheap, but 1000 boxes make about half a million pairs. Fine for a few dozen objects; beyond that, a broad phase (Track 6) skips pairs that are far apart.

In real games

Many 2D games use AABBs as their only collision shape: tile-based platformers, top-down shooters and bullet-hell games, where hitboxes are deliberately simple rectangles. The LÖVE library bump.lua by Enrique García Cota is built entirely around axis-aligned boxes.

Full physics engines use AABBs too, as a first filter. Box2D keeps an AABB around every shape in a tree, and only shapes whose boxes overlap go on to the exact, more expensive test. Godot's Rect2 and Unity's Rect and Bounds types all offer the overlap test shown here.

Takeaways

  • An axis-aligned box is two intervals, one on x and one on y.
  • Two intervals overlap when each starts before the other ends. Two boxes overlap when their intervals overlap on both axes.
  • The overlap amount is the smaller end minus the larger start: positive for overlap, zero for touching, negative for a gap.
  • Checking corners misses boxes that cross like a plus sign. Compare intervals instead.
  • Whether touching counts is a design decision. Strict < stops resting objects reporting endless zero-depth hits.
