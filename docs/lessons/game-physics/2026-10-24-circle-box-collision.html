Circle against box

How clamping a circle's centre to a box gives the closest point, the overlap test, the depth and the normal, even when the centre is inside the box.

A round player walks past a crate's corner and stops dead, with a clear gap between them. Or a fast ball ends up inside a wall and, a frame later, disappears. Both are bugs in one small test: a circle against a box.

Find the point of the box closest to the circle

The box is an AABB, an axis-aligned bounding box: a rectangle that never rotates. As in the AABB lesson it is stored as its top-left corner x, y and its size w, h, with y growing downwards. The circle is a centre x, y and a radius r.

The circle touches the box when some point of the box is closer to the centre than r. Only one point needs checking: the point of the box closest to the centre. If that one is too far away, every other point is further still.

Clamping finds the closest point

To clamp a number is to force it into a range: values below the range become its minimum, values above become its maximum, and values inside stay as they are.

qx = clamp(c.x, b.x, b.x + b.w)
qy = clamp(c.y, b.y, b.y + b.h)

In words: left of the box, use the left edge; right of it, use the right edge; in between, keep the centre's own x. Then the same for y. The result is the closest point, Q. The axes can be handled separately only because the box's edges line up with them.

The overlap test

With dx = c.x - qx and dy = c.y - qy, compare squared lengths as last lesson:

dx * dx + dy * dy < c.r * c.r

In words: the closest point of the box is nearer to the centre than the radius.

One check by hand

The box x = 180, y = 80, w = 200, h = 120 spans 180 to 380 across and 80 to 200 down. The circle, as at the start of the demo, is at (420, 230) with r = 60. 420 is past the right edge, so qx = 380; 230 is below the bottom, so qy = 200. Then dx = 40, dy = 30, and 1600 + 900 = 2500 < 3600, so they overlap.

Depth and normal

The penetration depth is how far the circle has sunk in: depth = c.r - distance, here 60 − 50 = 10 pixels. The contact normal is the direction, of length 1, that pushes the circle out of the box: (dx / distance, dy / distance), here (0.8, 0.6). Moving the circle 10 pixels along it leaves the two exactly touching.

Beside a face, only one coordinate is clamped, so the normal points straight out of that face. Near a corner both are clamped, and the normal turns smoothly as the circle moves around it.

Good game answer

That smooth turn is why a circle is a forgiving shape for a character. A box player that clips a crate's corner by one pixel stops dead; a circle player gets a slanted normal and slides around it. Neither shape is physically "right" for a person, but the circle feels better against boxy levels.

The two bugs

Testing the circle's bounding square. Reusing the box test on a square around the circle asks whether the centre is inside the box grown by r on every side. The correct region has rounded corners. In the four corner pieces between them, the square test reports hits across a visible gap: the snag in the hook.

The centre inside the box. Then clamping changes nothing, Q is the centre and the distance is 0. The overlap test still says yes, correctly, but the normal is 0 / 0, which is "not a number" (NaN). Push the circle by NaN and its position becomes NaN, and it vanishes. Fast objects that sink deep into a wall in one step, and objects spawned inside boxes, both hit this.

The fix: when the distance is 0, measure the distance from the centre to each face and leave through the nearest. The normal points straight out of that face, and depth = c.r + distance to that face, because the whole radius must clear it too.

Check: centre (350, 140), r = 40, same box. The faces are 170 away on the left, 30 right, 60 up and 60 down. Right wins, so the normal is (1, 0) and the depth 40 + 30 = 70. Pushed 70 right, the centre is at x = 420 and the circle's left edge at 380, exactly on the right face.

The code

A complete LÖVE program with the demo's starting shapes. Drag the circle; the shapes turn red on overlap, Q is a dot, and the depth and normal are printed at the top.

-- Box: x, y is the top-left corner, w and h the size. y grows downwards.
local box = { x = 180, y = 80, w = 200, h = 120 }
-- Circle: x, y is the centre, r the radius.
local circle = { x = 420, y = 230, r = 60 }

local function clamp(v, lo, hi)
  return math.max(lo, math.min(hi, v))
end

-- The point of the box closest to (px, py). Inside the box it is (px, py).
local function closestPoint(b, px, py)
  return clamp(px, b.x, b.x + b.w), clamp(py, b.y, b.y + b.h)
end

-- Strict < : a circle that only touches the box does not count.
local function circleBoxOverlap(c, b)
  local qx, qy = closestPoint(b, c.x, c.y)
  local dx, dy = c.x - qx, c.y - qy
  return dx * dx + dy * dy < c.r * c.r
end

-- Only call after circleBoxOverlap says yes. Returns depth, normal x, normal y.
-- The normal points from the box to the circle: the way to push the circle out.
local function contact(c, b)
  local qx, qy = closestPoint(b, c.x, c.y)
  local dx, dy = c.x - qx, c.y - qy
  local dist = math.sqrt(dx * dx + dy * dy)
  if dist > 0 then
    return c.r - dist, dx / dist, dy / dist
  end
  -- The centre is inside the box: leave through the nearest face.
  local left = c.x - b.x
  local right = b.x + b.w - c.x
  local top = c.y - b.y
  local bottom = b.y + b.h - c.y
  local best = math.min(left, right, top, bottom)
  if best == left then return c.r + left, -1, 0 end
  if best == right then return c.r + right, 1, 0 end
  if best == top then return c.r + top, 0, -1 end
  return c.r + bottom, 0, 1
end

local dragging = false
local grabX, grabY = 0, 0

function love.mousepressed(mx, my, button)
  local dx, dy = mx - circle.x, my - circle.y
  if button == 1 and dx * dx + dy * dy <= circle.r * circle.r then
    dragging = true
    grabX, grabY = dx, dy
  end
end

function love.mousereleased(mx, my, button)
  if button == 1 then dragging = false end
end

function love.update(dt)
  if dragging then
    local mx, my = love.mouse.getPosition()
    circle.x, circle.y = mx - grabX, my - grabY
  end
end

function love.draw()
  local hit = circleBoxOverlap(circle, box)
  if hit then
    love.graphics.setColor(1, 0.3, 0.3)
  else
    love.graphics.setColor(1, 1, 1)
  end
  love.graphics.rectangle("line", box.x, box.y, box.w, box.h)
  love.graphics.circle("line", circle.x, circle.y, circle.r)
  local qx, qy = closestPoint(box, circle.x, circle.y)
  love.graphics.circle("fill", qx, qy, 4)
  love.graphics.line(qx, qy, circle.x, circle.y)
  if hit then
    local depth, nx, ny = contact(circle, box)
    love.graphics.print(string.format("depth %.1f   normal (%.2f, %.2f)", depth, nx, ny), 10, 10)
  end
end
# Rect2 stores the top-left corner in position, and end is the bottom-right.
var box := Rect2(180, 80, 200, 120)
var centre := Vector2(420, 230)
var radius := 60.0

func _physics_process(_delta: float) -> void:
    var closest := centre.clamp(box.position, box.end)
    var hit := centre.distance_squared_to(closest) < radius * radius
    if hit and centre != closest:
        var depth := radius - centre.distance_to(closest)
        var normal := closest.direction_to(centre)   # from box to circle
    # centre == closest means the centre is inside: use the nearest face.
// Rect(x, y, width, height). Unity's y points up, which does not change the clamp.
Rect box = new Rect(180, 80, 200, 120);
Vector2 centre = new Vector2(420, 230);
float radius = 60f;

void FixedUpdate()
{
    Vector2 closest = new Vector2(
        Mathf.Clamp(centre.x, box.xMin, box.xMax),
        Mathf.Clamp(centre.y, box.yMin, box.yMax));
    bool hit = (centre - closest).sqrMagnitude < radius * radius;

    // Or ask the physics engine for a 2D collider overlapping a circle.
    Collider2D other = Physics2D.OverlapCircle(centre, radius);
}

For physics bodies the engine does this for you: CircleShape2D against RectangleShape2D in Godot, CircleCollider2D against BoxCollider2D in Unity. Writing it yourself suits hitboxes and simple custom movement.

Pitfalls

  • No inside case. 0 / 0 gives NaN, which spreads to every number it touches. Objects vanishing after a hard hit point here.
  • Using the width as the right edge. The range for x is b.x to b.x + b.w, not b.x to b.w. It only works for boxes at the origin.
  • Mixing box conventions. Storing some boxes by centre and half-size and others by top-left corner puts every clamp off by half a box. Pick one.
  • A flipped normal. This normal points from the box to the circle. If you push the box instead of the circle, push it along the negative normal.
  • Rotated boxes. Clamping needs axis-aligned edges. Rotate the centre into the box's own frame first, or use the separating axis test from a later lesson.

In real games

A round ball, bullet or player against walls, crates and tiles is a common 2D pairing. Breakout-style games need it for ball and bricks, and top-down games often give the player a circle so it slides around wall corners.

Engines have a dedicated routine for it. Box2D has a circle against polygon function, and a box is a four-sided polygon. Godot and Unity report the same normal and depth for contacts between these shapes.

Takeaways

  • Clamp the centre to the box on each axis to get the closest point of the box.
  • The circle overlaps the box when that point is closer than the radius. Compare squared lengths.
  • Depth is the radius minus the distance; the normal points from the closest point to the centre.
  • A centre inside the box gives distance zero: push out through the nearest face, depth = radius + distance to that face.
  • A circle's bounding square reports false hits at box corners.
