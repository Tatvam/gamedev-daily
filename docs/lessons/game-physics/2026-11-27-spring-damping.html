Damping: making springs settle

How a force against the velocity lets a spring settle, and how one damping ratio picks under-damped, critically damped or over-damped motion.

Yesterday's lantern on a spring never stops bouncing. Put that spring behind a follow camera and the screen bobs for the whole level. Guess a "friction" number and the camera either still wobbles or drags behind the player as if through syrup.

Damping is the dial between those two failures, and one number, the damping ratio, tells you where on the dial you are.

A force against the velocity

Damping is anything that takes energy out of motion. For a spring, the simplest damping is a force that pushes against the velocity:

Fdamp = -c * v

In words: the faster the body moves, the harder the damper pushes back, always in the opposite direction. A body standing still feels nothing. The number c is the damping coefficient. It is force per unit of speed, so with mass in kilograms and distance in pixels it is in kg/s.

A real version is a dashpot: a piston in oil, as in a car's shock absorber.

Add it to the spring from yesterday:

F = -k * x - c * v

In words: the spring pulls the body back towards rest in proportion to the stretch x, and the damper resists any movement at all, in either direction. Gravity is added on top as before.

One step by hand

Use the demo's numbers: mass 1 kg, stiffness k = 40, damping c = 2.53 kg/s (where that comes from is below). The weight passes its hanging point moving down at 200 px/s. Screen y points down.

  • At the hanging point the spring and gravity cancel, so only the damper acts: -2.53 * 200 = -506, that is 506 upward.
  • Acceleration: -506 / 1 = -506 px/s².
  • One step of 1/60 s, velocity first: 200 - 506/60 = 191.6 px/s. Then position moves 191.6/60 = 3.19 px.
  • Without damping it would have moved 3.33 px.

One number instead of c: the damping ratio

Alone, c means nothing: 10 nearly stops a light, soft spring and barely touches a heavy, stiff one. What matters is how it compares with the critical damping:

cCritical = 2 * sqrt(k * m)

In words: stiffer springs and heavier bodies need more damping to stop overshooting. For k = 40 and 1 kg that is 2 * sqrt(40) = 12.65 kg/s.

The damping ratio, written with the Greek letter zeta (ζ), is how much damping you have compared with that:

c = 2 * zeta * sqrt(k * m)

In words: choose the ratio, then compute c from it. A ratio of 0.2 gives 2 * 0.2 * 6.325 = 2.53, the value used in the step above. Change the stiffness or mass and the motion keeps its character.

The ratio splits the motion into three kinds:

  • Under-damped, 0 < ζ < 1: the body overshoots and swings, and each swing is smaller than the last by the same fraction. Zero means no damping at all: it swings forever.
  • Critically damped, ζ = 1: the body comes back as fast as it can without ever passing the rest point.
  • Over-damped, ζ > 1: no overshoot, but the body creeps the last part of the way. The larger the ratio, the slower.

Real physics versus game physics

Critical damping is the fastest return that never overshoots, which is why it is the usual answer for cameras and anything that must not wobble. It is not always the fastest to look still. In the demo, a ratio of 0.8 overshoots by less than a pixel and is within 1 px of rest after 0.72 s, while critical damping takes 1.07 s. Games also pick ratios well below 1 on purpose for menus and squashy characters, because a small overshoot reads as life. Choose by feel.

Try it

The demo starts with no damping, yesterday's bug: the left weight never stops, while the grey, critically damped one settles in about a second. Try the presets. Watch the settle time readout: it falls as you raise the ratio to about 0.8, then climbs again through 1 and keeps climbing as you go over-damped. Try 0.8 and compare it with critical. Then change the stiffness: the motion keeps its shape.

The code

The demo's spring with the same numbers, a fixed step of 1/60 s and semi-implicit Euler. The weight starts 80 px below where it hangs still.

local STEP = 1 / 60
local mass = 1
local stiffness = 40        -- kg/s^2
local dampingRatio = 0.2    -- 0 = none, 1 = critical
local restLength = 120      -- pixels
local gravity = 600         -- pixels per second squared, down
local anchorY = 40
-- hangs still at restLength + mass * gravity / stiffness = 135 px below
local weight = { y = anchorY + 135 + 80, vy = 0 }
local accumulator = 0

-- Turn the ratio into a damping coefficient c (kg/s)
local function dampingCoefficient()
  return 2 * dampingRatio * math.sqrt(stiffness * mass)
end

local function step(dt)
  local stretch = (weight.y - anchorY) - restLength
  local springForce = -stiffness * stretch
  -- the anchor never moves, so weight.vy is how fast the stretch changes
  local dampingForce = -dampingCoefficient() * weight.vy
  local force = springForce + dampingForce + mass * gravity
  weight.vy = weight.vy + force / mass * dt   -- velocity first
  weight.y = weight.y + weight.vy * dt        -- then position
end

function love.update(dt)
  accumulator = accumulator + math.min(dt, 0.25)
  while accumulator >= STEP do
    step(STEP)
    accumulator = accumulator - STEP
  end
end

function love.draw()
  love.graphics.line(200, anchorY, 200, weight.y)
  love.graphics.circle("fill", 200, weight.y, 14)
end
# On a RigidBody2D hanging from a fixed point. Godot applies gravity.
extends RigidBody2D

@export var anchor := Vector2(200, 40)   # global position
@export var stiffness := 40.0
@export var rest_length := 120.0
@export var damping_ratio := 0.2

func _physics_process(_delta: float) -> void:
    var d := global_position - anchor
    var length := d.length()
    if length < 0.0001:
        return
    var dir := d / length
    var c := 2.0 * damping_ratio * sqrt(stiffness * mass)
    var stretch_speed := linear_velocity.dot(dir)
    var f := -stiffness * (length - rest_length) - c * stretch_speed
    apply_central_force(f * dir)
// On a GameObject with a Rigidbody2D. Unity works in metres.
using UnityEngine;

public class DampedSpring2D : MonoBehaviour
{
    public Vector2 anchor = new Vector2(0f, 4f);
    public float stiffness = 40f;
    public float restLength = 1.2f;
    public float dampingRatio = 0.2f;
    Rigidbody2D body;

    void Awake() { body = GetComponent<Rigidbody2D>(); }

    void FixedUpdate()
    {
        Vector2 d = body.position - anchor;
        float length = d.magnitude;
        if (length < 0.0001f) return;
        Vector2 dir = d / length;
        float c = 2f * dampingRatio * Mathf.Sqrt(stiffness * body.mass);
        // linearVelocity is called velocity before Unity 6
        float stretchSpeed = Vector2.Dot(body.linearVelocity, dir);
        float f = -stiffness * (length - restLength) - c * stretchSpeed;
        body.AddForce(f * dir);
    }
}

In 2D the engine versions damp only the velocity along the spring, so the weight still swings sideways freely. Ready-made versions: Godot's DampedSpringJoint2D has a damping property, and Unity's SpringJoint2D takes a dampingRatio next to its frequency.

Body damping is different: Godot's linear_damp and Unity's linearDamping (drag before Unity 6) slow the whole velocity all the time, like air. Godot also applies a small default linear damping from the project settings, so an undamped spring may still settle slowly there.

Pitfalls

  • Damping the world velocity instead of the stretch speed. With a fixed anchor they are the same. On a moving cart they are not: the lantern resists the cart's motion and trails behind as if in syrup. Damp the difference between the two ends' velocities.
  • Multiplying the velocity by 0.98 every frame. The amount then depends on the frame rate, and on nothing about the spring.
  • Tuning c by hand and then changing the spring. A camera that was smooth at k = 40 wobbles at k = 160 with the same c, because the ratio has halved. Store the ratio and compute c.
  • Too much damping explodes. With semi-implicit Euler, once c * dt / m passes about 2, each step reverses the velocity and makes it bigger. At 60 steps per second and 1 kg that is near c = 120, which a very stiff spring with a high ratio can reach. Use substeps, or apply the damping as v = v / (1 + c * dt / m), the stable form from the drag lesson.
  • Treating over-damping as "safe". A ratio of 3 takes about four times as long as critical damping to settle in the demo. Sluggish is a bug too.

In real games

Engines expose the ratio because designers can reason about it. Unity's SpringJoint2D uses a damping ratio and a frequency, and Box2D tunes its spring joints the same way in its version 3 API. Unity's WheelCollider suspension has a spring value and a separate damper value.

Damped springs also drive cameras that settle and UI that pops into place. Unity's Mathf.SmoothDamp eases a value to a target without overshooting, as a critically damped spring does.

Takeaways

  • Damping is a force against the velocity, -c * v.
  • The coefficient c means little alone. Choose a damping ratio and compute c = 2 * ζ * sqrt(k * m).
  • Below 1 the body overshoots and swings; at 1 it returns fastest without overshoot; above 1 it creeps.
  • For a spring between two moving things, damp the speed at which the stretch changes, not the world velocity.
  • Very large damping can explode. Keep c * dt / m well below 2.
