Slopes

How to walk a character along an angled floor at a steady speed, stop it creeping downhill, and refuse slopes steeper than a maximum angle.

You let go of the stick on a gentle hill and the hero slowly slides down it. Hold right instead and the same hero runs up a cliff that was meant to block the way, faster than on flat ground, then skips back down in little hops.

All of this comes from treating a slope as flat ground or as a wall. It is neither, and it needs two rules of its own.

Two common ways to get slopes wrong

Move on x, push up. The character moves sideways at its run speed and any overlap with the ground is fixed by lifting it straight up. On a slope every step sideways also becomes a lift, so the character climbs anything, and the steeper the slope, the faster it goes. On the way down it walks off the surface and falls back onto it: the hopping.

Gravity, then slide. This is the method from sliding along walls: push out along the contact normal and remove the velocity that points into the surface. That is right for a box on an icy ramp. For a character it is wrong: gravity has a part that runs along the slope, the slide keeps exactly that part, and a standing character creeps downhill.

The floor normal tells you the angle

When the character touches the ground, the collision test gives you a contact normal: a vector of length 1 that points out of the surface. Everything we need comes from it.

The angle of a slope is the angle between its normal and straight up. The dot product of two unit vectors is the cosine of the angle between them, so:

cos(slopeAngle) = n · up

In words: the more the normal points up, the flatter the floor. In LÖVE y points down the screen, so up is (0, -1) and the dot product is just -n.y. A flat floor, n = (0, -1), gives 1: the cosine of 0 degrees.

To decide if a surface is a floor, compare it with the steepest slope you want the character to walk on, the maximum walkable angle:

isFloor = -n.y >= cos(maxAngle)

In words: the surface is a floor if its normal lies inside a cone around up. Comparing cosines saves an inverse cosine per contact, but note the flip: a bigger cosine means a flatter slope.

Rule 1: on a floor, walk along the tangent

The tangent is the direction along the surface. In 2D you get it by turning the normal a quarter turn:

t = (-n.y, n.x)

In words: swap the two parts and negate one, and the vector lies along the floor, pointing right. On flat ground n = (0, -1) gives t = (1, 0). On a 30 degree hill rising to the right, n = (-0.5, -0.866) gives t = (0.866, -0.5): right and up.

Set the velocity to t * input * SPEED. One step of 1/60 s moves the character 2.31 pixels right and 1.33 up: 2.67 pixels along the slope, exactly 160 pixels per second. The push-up method moves 2.67 right and 1.54 up, 3.08 pixels per step, which is the 185 in the table.

Real people slow down uphill. Most games do not, because a run speed that changes with the ground feels like slipping controls. If you want hills to slow the player, scale the speed on purpose instead of getting it as a side effect.

Rule 2: on a floor, switch gravity off

The part of gravity along the slope is what made the slide method creep. A real person is held in place by friction, which you could model as in contact friction. For a character there is a simpler, exact answer: while it stands on a floor its velocity comes only from the input, and gravity is not added at all. Gravity starts again the moment the floor is gone.

This is where the physically correct answer and the good game answer part ways. A character is not a box. It should stand where the player left it.

Steep slopes act as walls

A surface that fails the floor test is too steep to stand on, so gravity stays on. But a push out along its real normal has an upward part, and a player holding right could still inch up. So treat a steep slope as a vertical wall: push out sideways only and remove only the sideways velocity into it. Gravity then wins, and the character slides to the foot.

Rule of thumb

Start with a maximum walkable angle of 45 degrees, the default in both Godot and Unity, then tune it while playing. Draw the normal and the cone while you tune.

The code

The right-hand panel as a LÖVE program, with the demo's numbers. The character is a circle of radius 10 and the ground is a list of segments. findContacts is the closest-point test from circle against box, done for segments, and also reports surfaces up to 2 pixels away so a character resting exactly on the floor stays grounded.

local SPEED, GRAVITY, MAX_FALL = 160, 1800, 540   -- px/s, px/s², px/s (y points down)
local R, SKIN = 10, 2                              -- circle radius, contact margin
local COS_MAX = math.cos(math.rad(45))             -- steepest walkable slope
local STEP, accumulator = 1 / 60, 0
local ground = {}   -- your level: segments { ax = , ay = , bx = , by = }
local player = { x = 40, y = 240, vx = 0, vy = 0, grounded = false, gnx = 0, gny = -1 }

local function isFloor(nx, ny)
  return -ny >= COS_MAX                    -- n . up, with up = (0, -1)
end

local function findContacts(p)
  local list = {}
  for _, s in ipairs(ground) do
    local dx, dy = s.bx - s.ax, s.by - s.ay
    local t = ((p.x - s.ax) * dx + (p.y - s.ay) * dy) / (dx * dx + dy * dy)
    t = math.max(0, math.min(1, t))
    local ex, ey = p.x - (s.ax + t * dx), p.y - (s.ay + t * dy)
    local d = math.sqrt(ex * ex + ey * ey)
    if d > 0 and d < R + SKIN then
      list[#list + 1] = { nx = ex / d, ny = ey / d, depth = R - d }
    end
  end
  return list
end

local function stepPlayer(p, input, dt)    -- input is -1, 0 or 1
  if p.grounded then                       -- rules 1 and 2: along the floor, no gravity
    p.vx = -p.gny * input * SPEED
    p.vy =  p.gnx * input * SPEED
  else
    p.vx = input * SPEED
    p.vy = math.min(p.vy + GRAVITY * dt, MAX_FALL)
  end
  p.x, p.y = p.x + p.vx * dt, p.y + p.vy * dt

  p.grounded = false
  local best = -math.huge
  for _, c in ipairs(findContacts(p)) do
    local nx, ny, depth = c.nx, c.ny, c.depth
    if isFloor(nx, ny) then
      p.grounded = true
      if depth > best then                 -- keep the floor we press into most
        best, p.gnx, p.gny = depth, nx, ny
      end
    elseif ny < 0 then                     -- too steep: act like a vertical wall
      depth = depth / math.abs(nx)
      nx, ny = (nx > 0) and 1 or -1, 0
    end
    if depth > 0 then                      -- push out of the surface
      p.x, p.y = p.x + nx * depth, p.y + ny * depth
    end
    local into = p.vx * nx + p.vy * ny     -- remove velocity into the surface
    if into < 0 then
      p.vx, p.vy = p.vx - into * nx, p.vy - into * ny
    end
  end
end

function love.update(dt)
  local input = 0
  if love.keyboard.isDown("left") then input = input - 1 end
  if love.keyboard.isDown("right") then input = input + 1 end
  accumulator = accumulator + math.min(dt, 0.25)
  while accumulator >= STEP do
    stepPlayer(player, input, STEP)
    accumulator = accumulator - STEP
  end
end
# Godot 4: CharacterBody2D has both rules built into move_and_slide().
extends CharacterBody2D

const SPEED := 160.0
const GRAVITY := 1800.0

func _ready() -> void:
    floor_max_angle = deg_to_rad(45.0)   # steepest walkable slope (45 is the default)
    floor_stop_on_slope = true           # rule 2: no creeping down when idle
    floor_constant_speed = true          # rule 1: same speed up and down hills

func _physics_process(delta: float) -> void:
    velocity.x = Input.get_axis("ui_left", "ui_right") * SPEED
    if not is_on_floor():
        velocity.y += GRAVITY * delta
    move_and_slide()
    # After the move: is_on_floor(), get_floor_normal() and
    # rad_to_deg(get_floor_angle()) tell you what you are standing on.
// Unity's CharacterController (3D) has a slope limit in degrees.
using UnityEngine;

public class SlopeWalker : MonoBehaviour
{
    public float speed = 5f;
    public float gravity = 20f;
    CharacterController controller;
    float fallSpeed;

    void Start()
    {
        controller = GetComponent<CharacterController>();
        controller.slopeLimit = 45f;   // steepest walkable slope
    }

    void Update()
    {
        Vector3 move = transform.forward * Input.GetAxis("Vertical") * speed;
        if (controller.isGrounded) fallSpeed = -1f;   // small push keeps contact
        else fallSpeed -= gravity * Time.deltaTime;
        move.y = fallSpeed;
        controller.Move(move * Time.deltaTime);
    }

    void OnControllerColliderHit(ControllerColliderHit hit)
    {
        float slopeAngle = Vector3.Angle(hit.normal, Vector3.up);   // same test as isFloor
    }
}

In Godot, floor_stop_on_slope is on by default and floor_constant_speed is off. Unity's CharacterController is not a Rigidbody and is usually moved from Update. A Rigidbody character has no slope limit; you write the floor test yourself from the contact normals.

Pitfalls

  • Grounded for one frame, airborne the next. A character moving exactly along the floor never overlaps it, so an overlap test says "in the air" every other step. Count contacts within a small margin, like SKIN.
  • Mixing up the y axis. With y pointing up (Unity, most maths books) the test is n.y >= cos(maxAngle). Get the sign wrong and ceilings become floors. Writing <= instead of >= makes only steep slopes walkable.
  • Launching off the top of a slope. Over the crest of a steep hill the floor drops away faster than gravity can follow, and the character flies for a moment. The right panel still does this. Ground snapping, later in this series, fixes it.
  • Picking the wrong floor in a corner. Where two floors meet, the character touches both. Keep the one it presses into most; taking the first in the list makes the speed stutter at the corner.

In real games

Both engines expose the two rules as settings. Godot's CharacterBody2D and CharacterBody3D have floor_max_angle, 45 degrees by default, along with floor_stop_on_slope and floor_constant_speed. Unity's CharacterController has slopeLimit, also 45 degrees by default.

Some games make slopes change the speed on purpose. Fans who have studied the classic Sonic the Hedgehog games describe one speed along the ground plus a slope factor that adds speed downhill and removes it uphill: a design choice built on top of rule 1, not a side effect of collision code.

Takeaways

  • The contact normal holds the slope angle: cos(angle) = n · up, which is -n.y when y points down.
  • A surface is a floor when -n.y >= cos(maxAngle). Compare cosines, and remember that bigger means flatter.
  • On a floor, set the velocity along the tangent (-n.y, n.x) and do not add gravity. The character keeps its speed and stands still when idle.
  • Treat slopes steeper than the limit as vertical walls, so gravity slides the character down instead of input pushing it up.
