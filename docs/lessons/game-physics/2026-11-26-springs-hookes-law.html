Springs and the law of Hooke

How a spring pulls back in proportion to its stretch, why that makes every wobble take the same time, and how to pick a stiffness from the feel you want.

You hang a lantern from the ceiling on a spring. The first version says "if the lantern is below its spot, push it up; if it is above, push it down", always with the same force. A small nudge makes the lantern buzz like an insect. A hard yank makes it swing lazily. Neither one looks like a spring.

A real spring pushes harder the further you pull it. That one change, a force in proportion to the stretch, is the whole of this lesson.

Stretch, not position

A spring joins an anchor that does not move to a body. Left alone it has its rest length L0. Its length right now, the distance between its ends, is L.

x = L - L0

In words: the stretch x is how much longer the spring is than it wants to be. Positive means stretched, negative means squashed, zero means at rest.

The law of Hooke

F = -k * x

In words: the spring force is the stretch multiplied by a stiffness k, and it points the opposite way to the stretch. Twice the stretch, twice the pull. The minus sign is what makes it pull back.

The stiffness is force per pixel of stretch. With mass in kilograms and force in kg·px/s², as in the forces lesson, k is in kg/s².

Direction in 2D

A spring only pushes or pulls along its own length. Take the vector d from the anchor to the body, divide it by L to get a direction one unit long, and multiply by the force.

One step by hand

The demo starts with the numbers below. Screen y points down, so "up" is negative.

  • Anchor at height 0, weight 170 px below it. Rest length 120 px, so the stretch is 170 - 120 = 50 px.
  • Spring force: -40 * 50 = -2000, that is 2000 upward.
  • Gravity on a 1 kg weight at 600 px/s²: 600 downward. Total: 1400 upward.
  • Acceleration: -1400 / 1 = -1400 px/s².
  • One step of 1/60 s with semi-implicit Euler: velocity 0 - 1400/60 = -23.3 px/s, then position moves by -23.3/60 = -0.39 px.

Where it hangs

Under gravity the weight does not settle at the rest length. It settles where the spring's pull matches its weight, k * x = m * g:

x = m * g / k

In words: a heavier body or a softer spring sags further. With the numbers above, 1 * 600 / 40 = 15 px below the rest length.

Why proportional feels right: the period

The time for one full wobble, there and back, is the period:

T = 2 * pi * sqrt(m / k)

In words: heavier is slower, stiffer is faster, and the size of the swing does not appear at all. A nudge and a yank take the same time, and players read that steady rhythm as "spring". The constant pull from the start has no such rule: smaller swings get faster, which is the buzz.

Nobody can feel "40 kg/s²", but anyone can feel "one wobble per second". So pick the period and solve for the stiffness:

k = m * (2 * pi / T)^2

For a 1 kg weight and T = 1 s that gives k = 39.5, which is why the demo starts at 40.

Real physics versus game physics

A real spring's stiffness is set by its metal, and it loses energy as heat. A game spring gets whatever stiffness gives the timing you want, and today's spring loses no energy: it wobbles forever. That is a missing ingredient, not a bug, and the next lesson adds it.

Try it

Drag the weight and let go, or press the pull button. With Hooke's rule, pull short and pull long: the measured period stays the same. Switch to "constant pull" and repeat: short pulls buzz, long pulls swing slowly. With "ignores rest length", the rest length slider stops doing anything.

The code

The same spring as the demo, with the same numbers, stepped with a fixed timestep and semi-implicit Euler: velocity first, then position.

local STEP = 1 / 60
local stiffness = 40       -- force per pixel of stretch (kg/s^2)
local restLength = 120     -- pixels
local gravity = 600        -- pixels per second squared, down
local anchor = { x = 200, y = 40 }
local weight = { x = 200, y = 210, vx = 0, vy = 0, mass = 1 }
local accumulator = 0

-- Spring force on the body at (bx, by), anchored at (ax, ay)
local function springForce(ax, ay, bx, by)
  local dx, dy = bx - ax, by - ay
  local length = math.sqrt(dx * dx + dy * dy)
  if length < 0.0001 then return 0, 0 end    -- no direction
  local stretch = length - restLength
  local f = -stiffness * stretch               -- Hooke
  return f * dx / length, f * dy / length
end

local function step(dt)
  local fx, fy = springForce(anchor.x, anchor.y, weight.x, weight.y)
  fy = fy + weight.mass * gravity
  weight.vx = weight.vx + fx / weight.mass * dt
  weight.vy = weight.vy + fy / weight.mass * dt
  weight.x = weight.x + weight.vx * dt
  weight.y = weight.y + weight.vy * dt
end

function love.update(dt)
  accumulator = accumulator + math.min(dt, 0.25)
  while accumulator >= STEP do
    step(STEP)
    accumulator = accumulator - STEP
  end
end

function love.draw()
  love.graphics.line(anchor.x, anchor.y, weight.x, weight.y)
  love.graphics.circle("fill", weight.x, weight.y, 14)
end
# On a RigidBody2D. Godot already applies gravity to it.
extends RigidBody2D

@export var anchor := Vector2(200, 40)   # global position
@export var stiffness := 40.0
@export var rest_length := 120.0

func _physics_process(_delta: float) -> void:
    var d := global_position - anchor
    var length := d.length()
    if length < 0.0001:
        return
    var stretch := length - rest_length
    apply_central_force(-stiffness * stretch * d / length)
// On a GameObject with a Rigidbody2D. Unity works in metres,
// so the rest length is in metres and the stiffness in N/m.
using UnityEngine;

public class Spring2D : MonoBehaviour
{
    public Vector2 anchor = new Vector2(0f, 4f);
    public float stiffness = 40f;
    public float restLength = 1.2f;
    Rigidbody2D body;

    void Awake() { body = GetComponent<Rigidbody2D>(); }

    void FixedUpdate()
    {
        Vector2 d = body.position - anchor;
        float length = d.magnitude;
        if (length < 0.0001f) return;
        float stretch = length - restLength;
        body.AddForce(-stiffness * stretch * d / length);
    }
}

Both engines also have ready-made springs. Godot has the DampedSpringJoint2D node, with stiffness, damping and rest_length properties. Unity has the SpringJoint2D component, which is set by a frequency and a dampingRatio instead of a stiffness: the "choose the wobble, not the number" idea from above, built in.

Pitfalls

  • Using the length instead of the stretch. F = -k * L is a spring with a rest length of zero. It drags the body into the anchor, as the demo's "ignores rest length" rule shows.
  • The wrong sign. Writing d = anchor - body but keeping the minus in -k * x pushes the body away. The push grows with the stretch and the body flies off screen.
  • Dividing by a zero length. When both ends sit on the same point the direction is undefined. Skip the force for that step.
  • Forgetting the other end. If both ends are bodies, each needs the force: one gets F, the other -F. Giving it to only one end creates momentum from nothing.
  • Stiffness too high for the step. With semi-implicit Euler an undamped spring stays stable only while sqrt(k / m) * dt is below 2. A later lesson covers stiff springs.

In real games

Springs are a common way to build effects that do not look like springs: cameras that lag and settle, icons that wobble into place, tails, hanging signs and vehicle suspension. Unity's WheelCollider, for example, describes its suspension with a spring and a damper value.

Physics engines expose springs as joints. Box2D, which Unity's 2D physics is built on, has a distance joint that can act as a spring; in its version 3 API it is tuned by a frequency in hertz and a damping ratio. The names have changed between versions, so check the one you use.

Takeaways

  • A spring force depends on the stretch, x = L - L0, not on the length or the position.
  • Hooke's law, F = -k * x, pulls back harder the further you pull, along the line between the ends.
  • Under gravity a body hangs m * g / k below the rest length.
  • The period 2 * pi * sqrt(m / k) does not depend on the size of the swing. Choose the period you want and compute k from it.
  • An undamped spring never stops. That is the next thing to fix.
