Impulse resolution in 2D

How to apply a collision impulse along the contact normal so circles bounce off each other at the right angle, not straight back along their path.

You aim the cue ball at the edge of a ball on your pool table. The target should slide off to the side. Instead it rolls straight ahead, in the direction the cue ball was going, as if you had hit it dead centre. The cue ball stops dead. Every shot is a straight shot, and the game cannot be played.

Momentum and energy both add up. The bug is the direction of the push.

From a line to a plane

The previous lesson solved a collision on a line. Two carts closed at a speed vn = vB - vA. They swapped one impulse, -j for A and +j for B, with:

j = -(1 + e) * vn / (1 / mA + 1 / mB)

In 2D, velocities are vectors. The obvious upgrade is to put the whole relative velocity vector in place of vn, so the balls leave at -e times the velocity they arrived with. That is the bug from the hook. Momentum is kept, because the impulses are still equal and opposite, and with e = 1 so is energy. Only the direction is wrong.

A smooth contact can only push along the normal

When two smooth balls touch, each one can push the other only straight out from its surface. That direction is the contact normal, written n: a vector of length 1. For two circles it lies along the line between their centres, from A to B:

n = (centreB - centreA) / distance

In words: point from A's centre to B's centre, then scale the arrow to length 1.

Split the relative velocity in two. The normal part runs along n: how fast the balls are closing. The tangent part runs along the surface, at right angles to n: how fast they slide past each other. A frictionless contact leaves the tangent part alone and reverses only the normal part.

The 2D rule, one equation at a time

vn = dot(vB - vA, n)

In words: the closing speed is how much of the relative velocity points along the normal. Negative means closing, positive means separating. The dot product is a.x * b.x + a.y * b.y.

j = -(1 + e) * vn / (1 / mA + 1 / mB)

In words: the same impulse size as on the line. The normal fixes its direction.

vA = vA - (j / mA) * n
vB = vB + (j / mB) * n

In words: push B along the normal, push A the other way, each by the impulse divided by its own mass. The tangent part of each velocity passes through unchanged.

Check one step by hand

Both balls have mass 1, e = 1, and y grows downwards, as on screen. A rolls right at (400, 0) pixels per second. B is still and sits 30 degrees up and to the right, so n = (0.866, −0.5).

  • vB − vA = (−400, 0), so vn = −400 × 0.866 = −346.4. They are closing at 346 pixels per second.
  • j = 2 × 346.4 ÷ (1 + 1) = 346.4.
  • vB = 346.4 × (0.866, −0.5) = (300, −173.2): up and to the right, along the normal.
  • vA = (400, 0) − (300, −173.2) = (100, 173.2): down and to the right.
  • The dot product of the two new velocities is 100 × 300 − 173.2 × 173.2 = 0, so they are at right angles. Energy check: 200² + 346.4² = 400².

The buggy rule gives vA = (0, 0) and vB = (400, 0). That is the right answer for a dead-centre hit, applied to a hit that was not dead centre.

The game answer

Equal masses and e = 1 always split at 90 degrees, the pool rule for a hit without spin. Real balls spin and rub, so a real cue ball curves after the hit. The frictionless version is simpler and predictable, which is what lets a player aim.

The code

The demo's rule, set up as the cut shot. The cushions use the wall bounce from the restitution lesson and are left out here. Each step is split into 8 substeps so balls overlap by under a pixel when the normal is measured.

local STEP, SUBSTEPS = 1 / 60, 8
local RESTITUTION    = 1
local ROLL           = 60      -- rolling slowdown, px/s^2
local RADIUS         = 10
local balls = {}

local function newBall(x, y, m)
  local b = { x = x, y = y, vx = 0, vy = 0, r = RADIUS, inv = 1 / m }
  balls[#balls + 1] = b
  return b
end

local cue = newBall(100, 150, 1)
newBall(300, 150 - RADIUS, 1)  -- target, half a ball above the line
cue.vx = 400                   -- shoot right at 400 px/s

local function collide(a, b, e)
  local dx, dy = b.x - a.x, b.y - a.y
  local rs = a.r + b.r
  local d2 = dx * dx + dy * dy
  if d2 >= rs * rs then return end          -- not touching
  local d = math.sqrt(d2)
  local nx, ny = 1, 0                         -- any normal if centres coincide
  if d > 0 then nx, ny = dx / d, dy / d end   -- normal from a to b
  local invSum = a.inv + b.inv
  local push = (rs - d) / invSum              -- separate, split by inverse mass
  a.x, a.y = a.x - nx * push * a.inv, a.y - ny * push * a.inv
  b.x, b.y = b.x + nx * push * b.inv, b.y + ny * push * b.inv
  local vn = (b.vx - a.vx) * nx + (b.vy - a.vy) * ny
  if vn >= 0 then return end                  -- already separating
  local j = -(1 + e) * vn / invSum
  a.vx, a.vy = a.vx - j * nx * a.inv, a.vy - j * ny * a.inv
  b.vx, b.vy = b.vx + j * nx * b.inv, b.vy + j * ny * b.inv
end

local function move(b, dt)
  b.x, b.y = b.x + b.vx * dt, b.y + b.vy * dt
  local speed = math.sqrt(b.vx * b.vx + b.vy * b.vy)
  if speed > 0 then
    local k = math.max(0, speed - ROLL * dt) / speed
    b.vx, b.vy = b.vx * k, b.vy * k
  end
end

local accumulator = 0
function love.update(dt)
  accumulator = accumulator + math.min(dt, 0.25)
  while accumulator >= STEP do
    local h = STEP / SUBSTEPS
    for _ = 1, SUBSTEPS do
      for i = 1, #balls do move(balls[i], h) end
      for i = 1, #balls - 1 do
        for k = i + 1, #balls do collide(balls[i], balls[k], RESTITUTION) end
      end
    end
    accumulator = accumulator - STEP
  end
end

function love.draw()
  for _, b in ipairs(balls) do love.graphics.circle("line", b.x, b.y, b.r) end
end
# Godot's RigidBody2D does the normal impulse for you.
# You choose the mass, the bounce and the slowdown.
extends RigidBody2D

func _ready() -> void:
    var material := PhysicsMaterial.new()
    material.bounce = 1.0       # restitution
    material.friction = 0.0     # smooth contact: normal impulse only
    physics_material_override = material
    mass = 1.0
    gravity_scale = 0.0         # top-down table, no gravity
    linear_damp = 0.5           # stands in for rolling slowdown
// Unity's Rigidbody2D does the normal impulse for you.
// You choose the mass, the bounce and the collision mode.
void Start()
{
    var body = GetComponent<Rigidbody2D>();
    var material = new PhysicsMaterial2D("Ball");
    material.bounciness = 1f;   // restitution
    material.friction = 0f;     // smooth contact: normal impulse only
    body.sharedMaterial = material;
    body.mass = 1f;
    body.gravityScale = 0f;     // top-down table, no gravity
    body.collisionDetectionMode = CollisionDetectionMode2D.Continuous;
}

The engines also add rotation. A frictionless push on a circle points through its centre, so it cannot make it spin. Each engine combines the materials of two touching bodies in its own way, so check its documentation before relying on exact numbers.

Pitfalls

  • Reversing the whole relative velocity. It keeps momentum, so a momentum check will not catch it. Test a glancing hit: if the target leaves along the shooter's line, the impulse is not along the normal.
  • Normal and relative velocity disagree. If n points from A to B, the relative velocity must be vB - vA. Swap only one of them and the impulse pulls the balls into each other.
  • Centres in the same place. The distance is 0 and dividing by it gives NaN, which then spreads to every ball it touches. Pick any fixed normal in that case, as the code does.
  • Measuring the normal too late. The normal comes from overlapping positions, a little after the true contact, when the line of centres has already turned. Fast balls leave at a slightly wrong angle. Substeps keep the error small.
  • Packed racks depend on order. In a break one ball touches several at once, and resolving pairs in a different order gives slightly different results. Solver iterations, in a later lesson, reduce this.

In real games

Box2D, the open source engine by Erin Catto that Unity's 2D physics is built on, applies contact impulses along the contact normal from the relative velocity and the inverse masses, as here. It also adds rotation and friction. Godot's RigidBody2D and Unity's Rigidbody2D both resolve contacts this way, and expose restitution as PhysicsMaterial.bounce and PhysicsMaterial2D.bounciness.

Pool games show it most clearly, because players read the angle of every hit.

Takeaways

  • A smooth contact can only push along the contact normal, the line between the circle centres.
  • Project the relative velocity onto the normal to get vn, and skip the impulse if vn >= 0.
  • The impulse size is the same as on a line, j = -(1 + e) * vn / (1/mA + 1/mB), and it is applied as j * n.
  • The tangent part of the velocity passes through unchanged. That is what makes glancing hits glance.
  • Momentum and energy checks cannot catch an impulse that points the wrong way. Look at a glancing hit.
