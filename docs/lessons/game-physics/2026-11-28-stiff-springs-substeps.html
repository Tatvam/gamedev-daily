Stiff springs and substeps

Why a spring that is too stiff for its timestep explodes, how to predict the limit from one number, and how substeps make it stable again.

The car's suspension feels soft, so you double the spring stiffness. Then you double it again, and the car buzzes and shoots off the screen with a position of NaN. The spring is fine. It is too stiff for your timestep, and one formula says exactly where that line is.

Watch it break, one step at a time

Take the spring from the last two lessons, lying flat with no gravity or damping, with a 1 kg block on the end. Its offset from rest is x pixels and the force is -k * x. Step it with semi-implicit Euler at 60 steps per second. Set k = 20000, pull the block 10 px right, and do one step by hand:

  • Force: -20000 * 10 = -200000. Acceleration: -200000 px/s².
  • Velocity: 0 - 200000 / 60 = -3333 px/s.
  • Position: 10 - 3333 / 60 = 10 - 55.6 = -45.6 px.

The block started 10 px right of rest and landed 45.6 px left of it: further away than it started. The next force is four and a half times bigger, and so is the next jump:

Each step multiplies the offset by about −3.25. That is what "the spring exploded" means: the error of one step feeds a bigger error in the next.

The one number that predicts it

A spring has a natural speed. Its angular frequency, written with the Greek letter omega, is

omega = sqrt(k / m)

In words: stiffer springs and lighter bodies swing faster. It is in radians per second; one full swing takes 2 * pi / omega seconds. For k = 20000 and 1 kg, omega is 141.4, or 22.5 swings per second.

Omega times the timestep says how far through its swing the spring moves in one step. For semi-implicit Euler without damping:

stable when  omega * dt < 2

In words: a step must be shorter than about a third of a swing (2 / 2π = 0.32). Ours is 141.4 / 60 = 2.36, over the line. Turned around, it gives the stiffest spring a timestep allows:

kMax = 4 * m / (dt * dt)

In words: halve the timestep and you may use four times the stiffness. At 60 steps per second and 1 kg the limit is 14400. At 30 steps per second it is only 3600. Explicit Euler is worse: on an undamped spring it gains energy at every step size.

At omega * dt = 1.9 the block in a quick test swings about three times too far and 30% too fast. Aim for 1 or less.

The fix: substeps

A substep is a smaller step taken several times inside one fixed step. The game still ticks 60 times per second; only the spring takes n steps of h = dt / n.

n = ceil(omega * dt / 1)

In words: the fewest substeps that bring omega * h down to 1. For k = 20000 that is ceil(2.36) = 3, so omega * h = 0.79, and the 10 px pull now swings at most 10.9 px. The cost is n times the spring work, which is cheap next to raising the tick rate of the whole game.

Real physics versus game physics

A spring swinging 22.5 times per second is close to the most a 60 Hz screen can show (30), so players see a blur or a rigid rod. If a spring should look rigid, do not fight the timestep: soften it until it looks right, or use a rigid constraint, the next lesson.

Try it

Both blocks have the same spring and pull. The top one takes one step per tick; the bottom one splits each tick into substeps. Raise the stiffness past 14400 and the top block blows up while the bottom one keeps swinging. Drop the physics rate to 30 and the top fails at 3600. Use slow motion to see each jump past rest, and set substeps to 1 to see both fail.

The code

The demo's bottom block with "Auto substeps" on: 1 kg, a fixed tick of 1/60 s, released 40 px from rest.

local STEP = 1 / 60
local MAX_OMEGA_H = 1       -- stay well under the hard limit of 2
local mass = 1
local stiffness = 20000     -- kg/s^2: over the limit of 14400 at 60 Hz
local block = { x = 40, v = 0 }   -- offset from rest, pixels
local accumulator = 0

-- Fewest substeps that keep omega * h at or below MAX_OMEGA_H
local function substepsFor(k, m, dt)
  local omega = math.sqrt(k / m)
  return math.max(1, math.ceil(omega * dt / MAX_OMEGA_H))
end

local function springStep(h)
  local force = -stiffness * block.x
  block.v = block.v + force / mass * h    -- velocity first
  block.x = block.x + block.v * h         -- then position
end

local function step(dt)
  local n = substepsFor(stiffness, mass, dt)   -- 3 for these numbers
  local h = dt / n
  for i = 1, n do
    springStep(h)
  end
end

function love.update(dt)
  accumulator = accumulator + math.min(dt, 0.25)
  while accumulator >= STEP do
    step(STEP)
    accumulator = accumulator - STEP
  end
end

function love.draw()
  love.graphics.line(40, 100, 200 + block.x, 100)
  love.graphics.rectangle("fill", 200 + block.x - 14, 86, 28, 28)
end
# A spring you integrate yourself, such as a camera or UI offset.
extends Node2D

@export var stiffness := 20000.0
@export var mass := 1.0
var offset := 40.0
var speed := 0.0

func _physics_process(delta: float) -> void:
    var omega := sqrt(stiffness / mass)
    var n := maxi(1, ceili(omega * delta))
    var h := delta / n
    for i in n:
        speed += -stiffness * offset / mass * h
        offset += speed * h
    position.x = 200.0 + offset
// The same hand-made spring in FixedUpdate.
using UnityEngine;

public class SubsteppedSpring : MonoBehaviour
{
    public float stiffness = 20000f;
    public float mass = 1f;
    float offset = 0.4f;   // metres
    float speed;

    void FixedUpdate()
    {
        float dt = Time.fixedDeltaTime;
        float omega = Mathf.Sqrt(stiffness / mass);
        int n = Mathf.Max(1, Mathf.CeilToInt(omega * dt));
        float h = dt / n;
        for (int i = 0; i < n; i++)
        {
            speed += -stiffness * offset / mass * h;
            offset += speed * h;
        }
        transform.localPosition = new Vector3(offset, 0f, 0f);
    }
}

The limit depends only on k / m and dt, so it is the same in pixels and in metres. A spring force on an engine body cannot be substepped this way, because the engine integrates the body once per tick. Then the options are a higher tick rate (Godot: Project Settings > Physics > Common > Physics Ticks per Second; Unity: Project Settings > Time > Fixed Timestep) or the engine's own joints, such as DampedSpringJoint2D in Godot and SpringJoint2D in Unity. I have not measured how they cope with extreme stiffness, so test them at your tick rate.

Pitfalls

  • Forgetting mass. A spring fine on a 10 kg crate explodes on a 0.1 kg coin: omega is ten times larger.
  • Hoping damping saves it. It tightens the limit. With the damping ratio zeta from the last lesson, semi-implicit Euler needs (omega * dt)² + 4 * zeta * omega * dt < 4. At zeta = 1 that is omega * dt < 0.83.
  • A variable timestep. A spring tuned at 144 frames per second has omega * dt 2.4 times bigger at 60, and one slow frame can push it over 2.
  • Substepping everything. Collision detection and game logic inside the loop cost n times as much. Substep only the stiff forces.
  • Many springs on one point. Their stiffnesses add up. Use the sum for omega, or the point explodes although each spring passes alone.

In real games

Substepping is built into some physics engines. Version 3 of Box2D takes a substep count as an argument of its world step function, b2World_Step(worldId, timeStep, subStepCount), and its author, Erin Catto, has written about choosing a substepping solver because it handles stiff joints and stacks better. The research paper Small Steps in Physics Simulation from NVIDIA makes the same argument for position-based solvers.

The default ticks of Unity (50 per second) and Godot (60) set a ceiling on how stiff a hand-written spring can be, and a spring that "randomly" explodes usually has a frame-rate-driven timestep or a light body.

Raise k until it explodes and check that this happens where the number passes 2 (or the damped limit). Then add the substepsFor loop. You are done when the printed omega * h stays at 1 or less for every stiffness the game allows.

Takeaways

  • A spring explodes when one step carries the body past rest by more than it started with, so each error feeds a bigger one.
  • The number that matters is omega * dt with omega = sqrt(k / m). Semi-implicit Euler without damping is stable below 2 and accurate around 1 or less.
  • The stiffest spring a timestep allows is 4 * m / dt². Halving the step allows four times the stiffness.
  • Substeps shrink the step only for the stiff part. Pick n = ceil(omega * dt).
  • Damping, light bodies and several springs on one point all lower the limit.
