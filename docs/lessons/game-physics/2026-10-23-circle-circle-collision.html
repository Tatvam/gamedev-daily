Circle against circle

How to test two circles for overlap by comparing the distance between centres with the sum of the radii, using squared distances and no square root.

A coin is drawn with a visible gap from the player and is collected anyway. Or the opposite: two balls sink halfway into each other before the game notices. Both bugs come from testing round things with the wrong maths.

The correct test is a single comparison. Here it is, with the two common ways it goes wrong.

Two circles touch when their centres are close enough

A circle is stored as its centre x, y and its radius r, the distance from the centre to the edge. Every point on the edge is exactly r from the centre, which is what makes circles easy.

Walk the straight line from the centre of A to the centre of B. You leave A after a.r pixels and enter B b.r pixels before its centre. If the whole line is shorter than a.r + b.r, those two stretches overlap, and so do the circles:

distance < a.r + b.r

In words: the centres are closer together than the two radii laid end to end.

Measuring the distance

The distance comes from the Pythagorean theorem. Take the difference on each axis, dx = b.x - a.x and dy = b.y - a.y. These are the two short sides of a right-angled triangle, and the distance is its long side:

distance = math.sqrt(dx * dx + dy * dy)

In words: square each difference, add them, and take the square root.

Skip the square root

A yes or no answer does not need the distance itself. Both sides of distance < a.r + b.r are zero or positive, and for numbers like that, squaring both sides keeps the order the same. So compare the squares instead:

dx * dx + dy * dy < (a.r + b.r) * (a.r + b.r)

In words: the squared distance is smaller than the squared sum of the radii. No square root anywhere. A square root is not very slow on modern hardware, so do not expect a big speed-up, but this form costs nothing and you will see it in almost every engine.

One check by hand

Take A at x = 180, y = 130, r = 70 and B at x = 300, y = 220, r = 90, the start of the demo below. Then dx = 120 and dy = 90, so the squared distance is 14400 + 8100 = 22500. The radii add to 160, and 160 × 160 = 25600. Since 22500 < 25600, the circles overlap.

How deep, and which way

When they overlap, later lessons need two more numbers, and these do need the square root. The penetration depth is how far the circles sink into each other: depth = a.r + b.r - distance. Here that is 160 − 150 = 10 pixels.

The contact normal is the direction to push B away from A, as a vector of length 1: (dx / distance, dy / distance). Here that is (120 / 150, 90 / 150) = (0.8, 0.6). Pushing B 10 pixels along it leaves the circles exactly touching. Compute these only after the cheap test says yes, and guard against distance = 0.

The two bugs

Forgetting to square the radii. Writing dx * dx + dy * dy < a.r + b.r compares a squared distance with a plain one. For the circles above that asks whether 22500 < 160, which is false. The test only fires once the centres are within about 12.6 pixels, the square root of 160, so the circles sink deep into each other first.

Testing the bounding boxes instead. Putting a square around each circle and using last lesson's box test feels close enough. It is exact side by side, but on a diagonal the corners of the boxes meet while the round edges are still apart: the coin collected across a gap.

Good game answer

Physically, a hitbox should match the shape you see. In games it is often better to make it a little smaller. A player circle a few pixels smaller than the sprite makes near misses feel fair, which is why bullet-hell shooters often give the player a hitbox much smaller than the sprite. Use the exact test, then tune the radius for feel.

The code

A complete LÖVE program with the same two circles as the demo's start. Drag circle A with the mouse. Both circles turn red when they overlap, and the depth and normal are printed at the top.

-- x, y is the centre, r is the radius. y grows downwards.
local circleA = { x = 180, y = 130, r = 70 }
local circleB = { x = 300, y = 220, r = 90 }

-- Strict < : circles that only touch do not count as overlapping.
local function circlesOverlap(a, b)
  local dx = b.x - a.x
  local dy = b.y - a.y
  local radii = a.r + b.r
  return dx * dx + dy * dy < radii * radii
end

-- Only call after circlesOverlap says yes. Returns depth, normal x, normal y.
local function contact(a, b)
  local dx = b.x - a.x
  local dy = b.y - a.y
  local dist = math.sqrt(dx * dx + dy * dy)
  if dist == 0 then
    return a.r + b.r, 1, 0   -- same centre: any direction will do
  end
  return a.r + b.r - dist, dx / dist, dy / dist
end

local dragging = false
local grabX, grabY = 0, 0

function love.mousepressed(mx, my, button)
  local dx, dy = mx - circleA.x, my - circleA.y
  if button == 1 and dx * dx + dy * dy <= circleA.r * circleA.r then
    dragging = true
    grabX, grabY = dx, dy
  end
end

function love.mousereleased(mx, my, button)
  if button == 1 then dragging = false end
end

function love.update(dt)
  if dragging then
    local mx, my = love.mouse.getPosition()
    circleA.x, circleA.y = mx - grabX, my - grabY
  end
end

function love.draw()
  local hit = circlesOverlap(circleA, circleB)
  if hit then
    love.graphics.setColor(1, 0.3, 0.3)
  else
    love.graphics.setColor(1, 1, 1)
  end
  love.graphics.circle("line", circleA.x, circleA.y, circleA.r)
  love.graphics.circle("line", circleB.x, circleB.y, circleB.r)
  love.graphics.line(circleA.x, circleA.y, circleB.x, circleB.y)
  if hit then
    local depth, nx, ny = contact(circleA, circleB)
    love.graphics.print(string.format("depth %.1f   normal (%.2f, %.2f)", depth, nx, ny), 10, 10)
  end
end
# A circle as a centre and a radius.
var a_pos := Vector2(180, 130)
var a_r := 70.0
var b_pos := Vector2(300, 220)
var b_r := 90.0

func _physics_process(_delta: float) -> void:
    var radii := a_r + b_r
    var hit := a_pos.distance_squared_to(b_pos) < radii * radii
    if hit:
        var depth := radii - a_pos.distance_to(b_pos)
        var normal := a_pos.direction_to(b_pos)   # length 1, from A to B
// A circle as a centre and a radius.
Vector2 aPos = new Vector2(180, 130); float aR = 70f;
Vector2 bPos = new Vector2(300, 220); float bR = 90f;

void FixedUpdate()
{
    float radii = aR + bR;
    Vector2 d = bPos - aPos;
    bool hit = d.sqrMagnitude < radii * radii;

    // Or ask the physics engine for every 2D collider inside a circle.
    Collider2D[] inside = Physics2D.OverlapCircleAll(aPos, aR);
}

For physics bodies the engine runs this test for you: give a body a CircleShape2D in Godot or a CircleCollider2D in Unity. Writing it yourself suits hitboxes and pickups that need no physics body.

Pitfalls

  • Squaring one side only. dx * dx + dy * dy < a.r + b.r runs, gives no error, and is wrong almost everywhere. If you drop the square root on one side, square the other side too.
  • Using bounding boxes for round things. Fine as a quick first filter, but on diagonals the corners report hits across a visible gap. Follow a box hit with the circle test.
  • Dividing by zero distance. Two circles spawned at the same point give distance = 0, and the normal becomes "not a number", which then spreads to every position it touches. Check for zero and pick a fixed direction.
  • Mixing radius and diameter. A sprite 64 pixels wide has a radius of 32. Passing the width doubles the hitbox.

In real games

Circles are a common choice for bullets, pickups, round enemies and the player in top-down and bullet-hell games, because the test does not change when the object rotates. Pool and marble games are built almost entirely on it.

Engines expose circles as a basic shape: Godot has CircleShape2D, Unity has CircleCollider2D, and Box2D has a circle shape with its own circle against circle routine. All of them report a depth and normal like the ones here.

Your turn (15 minutes)

Take the Lua program above and add a "push apart" step to love.update: when the circles overlap, move B along the normal by the depth, so circleB.x = circleB.x + nx * depth and the same for y. Now drag A into B. B should slide away and stay exactly touching, never overlapping.

You are done when B can be pushed around the screen by A and never visibly sinks into it. Print the depth too: after the push it should be zero or a tiny number such as 0.00001, left over from rounding. That is why engines often ignore depths below a small tolerance.

Takeaways

  • Two circles overlap when the distance between their centres is less than the sum of their radii.
  • Compare squared distance with the squared sum of the radii. It gives the same answer with no square root.
  • If you square one side, square the other. Forgetting to is a silent bug.
  • Bounding boxes around circles report false hits on diagonals.
  • The depth is the radii minus the distance, and the normal is the centre-to-centre direction divided by the distance. Guard against zero distance.
