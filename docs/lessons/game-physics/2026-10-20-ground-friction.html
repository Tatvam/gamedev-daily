Ground friction

How friction slows a sliding object, and how to bring it to a clean stop at zero instead of jittering back and forth around it.

You let go of the controls and the hero slides to a halt. Then the sprite flickers between facing left and right, the walk animation never switches to idle, and the hero slowly creeps. Nothing is pushing it. The friction code is.

Friction is a deceleration towards zero

Ground friction is the push from the floor that resists sliding. It always points against the direction of motion, so its only job is to take speed away.

For a box sliding across a floor, real friction is close to constant: it does not grow or shrink with speed. The deceleration it causes is

deceleration = mu * gravity

In words: the box loses the same amount of speed every second, gravity scaled by mu, the friction coefficient (how grippy the surfaces are, near 0 for ice). Mass cancels out: a heavier box presses harder on the floor but is also harder to slow.

With the gravity of 1800 px/s² from earlier lessons and mu = 0.5, that is 900 px/s². At 60 steps per second each step removes 900 / 60 = 15 px/s of speed.

The obvious code, and the bug

The first version most people write subtracts the drop in the direction of motion:

local drop = FRICTION * dt
if vx > 0 then
  vx = vx - drop
elseif vx < 0 then
  vx = vx + drop
end

Flick a box at 640 px/s and follow the speed: 640, 625, 610, down to 25, then 10. The next step subtracts 15 from 10 and gets minus 5. Now the box moves backwards, so the next step adds 15 and gets 10 again. It never escapes:

Three symptoms follow. The facing, read from the sign of the speed, flips every step. A check for vx == 0, such as "play the idle animation", is never true. And since 10 and -5 average to 2.5, the box creeps at 2.5 px/s forever.

The bug hides in testing: if the speed is an exact multiple of the drop, such as 600 with a drop of 15, it lands exactly on zero.

The fix: never cross zero

If the speed left is no bigger than the drop, the box would stop during this step. So stop it:

if math.abs(vx) <= drop then
  vx = 0
end

This matches reality too. Friction can bring a box to rest but never push it backwards, and once it rests, static friction holds it still. The clamp is the game version of that.

How far it slides

Constant deceleration gives the same formulas as a ball thrown upward under gravity:

stop_time     = speed / FRICTION
stop_distance = speed * speed / (2 * FRICTION)

In words: the distance grows with the square of the speed, so a box flicked twice as fast slides four times as far. From 640 px/s at 900 px/s², that is 0.71 s and 227.6 px. With a 1/60 s step the box stops after 43 steps (0.72 s) at about 222 px, a little short, for the same reason the stepped jump in the last lesson was.

Turn it around to design friction from feel: to stop from 640 px/s in 200 px, use FRICTION = 640 * 640 / (2 * 200) = 1024 px/s².

The other kind: proportional deceleration

Many games instead remove a fraction of the speed each second, called damping:

vx = vx - DAMPING * vx * dt

In words: the faster the box goes, the harder it is slowed. With DAMPING = 3 per second at 60 steps per second, each step keeps 95 percent of the speed. It falls fast, then crawls, and never reaches zero: after four seconds the box still moves at about 0.003 px/s.

So damping needs a stop speed below which the speed is set to zero. With 5 px/s, the same flick stops after 1.58 s and 201 px.

Real answer and game answer

Real sliding friction is the constant kind; damping is closer to air resistance. Games use both because they feel different: constant friction gives a firm stop, like a crate on carpet, and damping a soft glide, like a ship in space. Pick by feel, and clamp either way.

The code

The bottom lane of the demo in LÖVE, same names and numbers, on the fixed timestep from the first lesson. Swap applyFriction for applyDamping in step for the gliding version.

local STEP = 1 / 60
local FRICTION = 900       -- px/s², 0.5 times a gravity of 1800
local DAMPING = 3          -- per second, for the proportional version
local STOP_SPEED = 5       -- px/s, a damped box slower than this stops
local FLICK_SPEED = 640    -- px/s

local box = { x = 40, vx = 0, facing = 1 }
local accumulator = 0

local function applyFriction(body, dt)
  local drop = FRICTION * dt
  if math.abs(body.vx) <= drop then
    body.vx = 0              -- would cross zero, so stop instead
  elseif body.vx > 0 then
    body.vx = body.vx - drop
  else
    body.vx = body.vx + drop
  end
end

local function applyDamping(body, dt)
  body.vx = body.vx - DAMPING * body.vx * dt
  if math.abs(body.vx) < STOP_SPEED then
    body.vx = 0
  end
end

local function step(body, dt)
  applyFriction(body, dt)    -- or applyDamping(body, dt)
  body.x = body.x + body.vx * dt
  if body.vx > 0 then
    body.facing = 1
  elseif body.vx < 0 then
    body.facing = -1
  end                        -- at exactly 0, keep the old facing
end

function love.keypressed(key)
  if key == "space" then
    box.x = 40
    box.vx = FLICK_SPEED
  end
end

function love.update(dt)
  accumulator = accumulator + math.min(dt, 0.25)
  while accumulator >= STEP do
    step(box, STEP)
    accumulator = accumulator - STEP
  end
end

function love.draw()
  love.graphics.rectangle("fill", box.x, 300, 30, 30)
end
# On a CharacterBody2D. move_toward never steps past its target,
# so it is the clamped version in one call.
const FRICTION := 900.0

func _physics_process(delta: float) -> void:
    var direction := Input.get_axis("ui_left", "ui_right")
    if is_on_floor() and direction == 0.0:
        velocity.x = move_toward(velocity.x, 0.0, FRICTION * delta)
    move_and_slide()
// On a Rigidbody2D. Unity works in metres, so 9 m/s² instead of 900 px/s².
// Mathf.MoveTowards never steps past its target either.
const float Friction = 9f;
Rigidbody2D body;

void Awake() { body = GetComponent<Rigidbody2D>(); }

void FixedUpdate()
{
    Vector2 v = body.linearVelocity;   // body.velocity before Unity 6
    v.x = Mathf.MoveTowards(v.x, 0f, Friction * Time.fixedDeltaTime);
    body.linearVelocity = v;
}

Damping is built into both engines' rigid bodies: linear_damp on a Godot RigidBody2D, and linear damping on a Unity Rigidbody2D (Linear Drag before Unity 6). Physics-material friction is different: it acts where two bodies touch, and gets its own lesson later.

Pitfalls

  • Subtracting without a clamp. The speed hops over zero and back forever. Clamp, or use move_toward or Mathf.MoveTowards, which clamp for you.
  • Damping as a per-frame multiply. vx = vx * 0.9 once per drawn frame stops a box faster at 120 frames per second than at 60. Multiply by dt inside the fixed step.
  • Damping too strong for the step. If DAMPING * dt is above 1, one step reverses the speed. In the demo, set damping to 15 and the physics rate to 10.
  • Fighting the player. Apply ground friction when the player is not pushing, or pushes against the motion. Otherwise tuning friction also changes top speed.
  • Friction in the air. Use a separate, usually smaller, value in the air, or the hero stops dead mid-jump.

In real games

The basic movement template Godot 4 offers for a new CharacterBody2D script stops the character with move_toward(velocity.x, 0, SPEED) when no direction is held: the clamped constant version, strong enough to stop almost at once.

Rigid body engines such as Box2D, Godot physics and Unity physics offer linear damping per body, separate from the contact friction worked out at each touching point. Platformers commonly give ice floors a lower deceleration than normal ground.

Your turn (15 minutes)

In a project where something slides to a stop, print the horizontal speed every physics step after input is released. If the sign changes before it settles, you have the bug; replace the subtraction with the clamp or move_toward.

Then design the stop: choose how far the character should slide from full speed, set FRICTION = speed * speed / (2 * distance), and print the real stopping distance. You are done when the speed reaches exactly zero within a few pixels of your target.

Takeaways

  • Ground friction removes a fixed amount of speed per second, mu * gravity, whatever the mass.
  • Without a clamp the speed hops over zero forever: facing flickers, idle never plays, the body creeps.
  • Clamp: if the speed left is no bigger than the drop, set it to zero.
  • Damping removes a fraction of the speed, feels like a glide, and needs a stop speed.
  • Stopping distance is speed² / (2 * FRICTION), so choose friction from the slide you want.
