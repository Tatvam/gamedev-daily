Collision layers and masks

How a layer bit and a mask on every body decide, with two AND operations, which pairs are tested at all, and how a layer matrix shows the same rule.

You add shooting to your game. The first bullet spawns at the centre of the ship, overlaps the ship, and explodes on the spot. Every shot after it does the same, and the ship shakes from its own fire.

The collision code is not wrong. It tests everything against everything, as asked. This lesson shows how to tell it which pairs should never meet.

Most pairs should never meet

Physically, a bullet that starts inside a ship touches the ship. In a game it must not. Here the realistic answer and the good answer differ, and the game wins: your bullets pass through you, and enemies do not shove the coins around.

Deciding which pairs of objects are allowed to collide is called collision filtering. Almost every engine does it the same way, with two numbers on each body:

  • The layer says what the body is. Each kind of object gets its own bit.
  • The mask says what the body collides with. It has a bit set for every layer it wants to touch.

Box2D calls the same two numbers the category bits and the mask bits.

One bit per layer

A bit is one binary digit. Giving each layer its own power of two means each layer owns one bit, and a set of layers fits in one number:

LayerValueBinary
Player10001
Enemy20010
Bullet40100
Pickup81000

To build a mask, combine the layers with a bitwise OR, which keeps every bit that is set in either number:

player.mask = ENEMY | PICKUP   -- 0010 | 1000 = 1010, which is 10

In words: the player touches enemies and pickups, and nothing else. Since no two layers share a bit, this OR is the same as adding: 2 + 8 = 10.

The test: two ANDs

A bitwise AND keeps only the bits set in both numbers. If the result is not zero, the two numbers share at least one bit. The filter asks that question twice:

canCollide = (a.layer & b.mask) ~= 0  and  (b.layer & a.mask) ~= 0

In words: A is something B wants to touch, and B is something A wants to touch. Only then does the pair go on to the real shape test.

Now check one pair by hand that should pass. An enemy has layer 2 and mask Player, Enemy and Bullet, which is 1 + 2 + 4 = 7. A bullet has layer 4 and mask 2. Then 4 & 7 = 4 and 2 & 2 = 2. Both are non-zero, so bullets hit enemies.

The layer matrix is the same rule as a table

A layer matrix is a grid with one row and one column per layer, and a tick wherever two layers collide. Read across one row and the ticks are that layer's mask. Unity sets 2D filtering mainly this way, in the Physics 2D project settings.

A matrix is always symmetric: Player against Bullet is the same tick as Bullet against Player. Separate masks can disagree. Under the double AND, a disagreement just means no collision. Godot stores a layer and a mask on every object and describes the mask as the layers it scans, so one-sided setups there can behave one-sided. The safe habit everywhere is to keep both sides in agreement.

Filter first, shape test second

Two ANDs cost almost nothing next to a shape test, so the filter runs first. When bullets ignore each other, most bullet pairs are rejected before any distance is measured.

Rule of thumb

Name your layers after what objects are (Player, Enemy, Bullet), never after what they hit. Then write the matrix once, in one place, and give every object its mask from it.

The code

This is the demo's filter and pair loop in Lua. LÖVE runs LuaJIT, which has a built-in bit library for bitwise operations. The mask values are the suggested matrix from the demo. resolve is the push-apart and bounce from the circle lesson; the next lesson looks at it closely.

local bit = require("bit")

local PLAYER = 1   -- 0001
local ENEMY  = 2   -- 0010
local BULLET = 4   -- 0100
local PICKUP = 8   -- 1000

-- layer: what I am. mask: what I collide with.
local MASK = {
  [PLAYER] = bit.bor(ENEMY, PICKUP),           -- 10
  [ENEMY]  = bit.bor(PLAYER, ENEMY, BULLET),   -- 7
  [BULLET] = ENEMY,                            -- 2
  [PICKUP] = bit.bor(PLAYER, PICKUP),          -- 9
}

local function newBody(x, y, r, layer)
  return { x = x, y = y, vx = 0, vy = 0, r = r, layer = layer, mask = MASK[layer] }
end

local function canCollide(a, b)
  return bit.band(a.layer, b.mask) ~= 0
     and bit.band(b.layer, a.mask) ~= 0
end

local function circlesOverlap(a, b)
  local dx, dy, rr = b.x - a.x, b.y - a.y, a.r + b.r
  return dx * dx + dy * dy < rr * rr
end

local function collidePairs(bodies)
  for i = 1, #bodies - 1 do
    for j = i + 1, #bodies do
      local a, b = bodies[i], bodies[j]
      if canCollide(a, b) and circlesOverlap(a, b) then
        resolve(a, b)   -- push apart and bounce, as in the circle lesson
      end
    end
  end
end
# Godot 4: every CollisionObject2D has collision_layer and collision_mask.
# The Inspector numbers layers 1 to 32. Layer n is the bit value 2^(n - 1).
# Name them in Project Settings > Layer Names > 2D Physics.
# Here: 1 Player, 2 Enemy, 3 Bullet, 4 Pickup.

func _ready() -> void:
    collision_layer = 1        # I am a Player (layer 1)
    collision_mask = 2 | 8     # I scan Enemy (layer 2) and Pickup (layer 4)

    # The same thing by layer number instead of bit value:
    collision_layer = 0
    collision_mask = 0
    set_collision_layer_value(1, true)
    set_collision_mask_value(2, true)
    set_collision_mask_value(4, true)
// Unity: each GameObject is on exactly one layer, numbered 0 to 31.
// Which layers collide is the matrix in Project Settings > Physics 2D.

void Awake()
{
    int player = LayerMask.NameToLayer("Player");   // a layer index, not a mask
    int bullet = LayerMask.NameToLayer("Bullet");
    Physics2D.IgnoreLayerCollision(player, bullet, true);   // untick one cell

    // Queries take a mask, built from layer names:
    int solid = LayerMask.GetMask("Enemy", "Pickup");
    RaycastHit2D hit = Physics2D.Raycast(transform.position, Vector2.right, 10f, solid);
}

Pitfalls

  • Mixing up a layer number and a bit value. Godot's layer 3 is the value 4. Unity's LayerMask.NameToLayer returns an index such as 8, and passing that 8 straight into a raycast as a mask means "layer 3", not "layer 8". Convert with 1 << index in C#, or use LayerMask.GetMask.
  • A new layer that nothing touches. Under the double-AND rule, adding a layer to one body's mask is only half the job. The other side must list it too, or the pair is still skipped.
  • Forgetting the queries. Raycasts and overlap checks take their own mask. A line-of-sight ray with the default mask may stop on a coin or on the shooter itself.
  • Switching a pair on while bodies overlap. The solver sees a deep overlap and pushes the bodies apart in a single step. You can reproduce it in the demo. Switch filters on only when the bodies are apart.
  • The LÖVE physics module counts differently. As far as I know, Fixture:setMask in love.physics takes the categories a fixture should not collide with, which is the opposite of the mask in this lesson. Check the LÖVE wiki for your version before relying on it.
  • Running out of bits. Both engines offer 32 layers. Use them for broad kinds of object, not for every enemy type.

In real games

Box2D, the 2D physics library inside many games and inside LÖVE's physics module, filters with category bits and mask bits and requires both checks to pass, exactly like the canCollide above. It also has a group index that can override the bits for groups of shapes, such as the limbs of one ragdoll.

Godot gives every physics object a 32-bit collision layer and collision mask. Unity puts each GameObject on one of 32 layers and filters pairs with a layer collision matrix, with separate matrices for 3D physics and 2D physics. In both engines the default is that new objects collide with each other, so a fresh project behaves like the demo before you untick anything.

Takeaways

  • A layer says what a body is. A mask says what it collides with. Each layer owns one bit.
  • A pair is tested only if each body's layer shares a bit with the other's mask: two ANDs, both non-zero.
  • A layer matrix is the same data as a table. Each row is a mask, and the table is symmetric.
  • Run the filter before the shape test. It is nearly free and skips most pairs.
  • Keep layer numbers and bit values apart, and give queries such as raycasts a mask too.
