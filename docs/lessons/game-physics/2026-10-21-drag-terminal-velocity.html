Drag and terminal velocity

How air drag grows with speed until it cancels gravity, how to pick drag from the top speed you want, and how to stop strong drag from exploding.

The hero steps off a tall ledge. By the bottom the camera lags behind, the landing looks like a teleport, and now and then they drop straight through a thin floor. Gravity keeps adding speed, and nothing takes it away.

Gravity alone never stops adding speed

With the gravity of 1800 px/s² from earlier lessons, a body gains 1800 px/s every second. After two seconds it moves 60 pixels per step at 60 steps per second, more than a 32 pixel tile.

In the real world, air pushes back. Drag is a force against the direction of motion that grows with speed. Here it is written as an acceleration in px/s², next to gravity.

Two shapes of drag

Linear drag is proportional to the speed:

drag = k * speed

In words: twice as fast, twice the drag. k is "per second": per second times px/s gives px/s².

Quadratic drag is proportional to the speed squared:

drag = c * speed * speed

In words: twice as fast, four times the drag. c is "per pixel": per pixel times px²/s² gives px/s².

Mass hides inside k and c: a stone and a feather of the same shape feel the same air force, but the stone has more mass to slow. Give each kind of object its own constant.

Terminal velocity

Drop a body from rest. At first drag is zero. As the body speeds up, drag grows and the net acceleration (gravity minus drag) shrinks. When drag equals gravity, the speed stops changing. That speed is the terminal velocity.

Setting drag equal to gravity and solving gives the useful version for a designer: choose the top speed, then compute the constant.

k = GRAVITY / TERMINAL                -- linear
c = GRAVITY / (TERMINAL * TERMINAL)   -- quadratic

In words: the lower the top speed you want, the bigger the constant. For a top speed of 600 px/s, k = 1800 / 600 = 3 per second, or c = 1800 / 360000 = 0.005 per pixel.

Same top speed, different feel

Quadratic drag is weak at low speed and strong at high speed, so it barely touches the start of a fall and then bites: it reaches 95 percent of top speed in about 0.61 s. Linear drag already slows a body at low speed and takes about 1.0 s.

Real answer and game answer

For a falling person or a thrown ball, real drag is close to quadratic; linear drag fits slow, tiny things such as settling dust. Games use both: linear drag makes everything feel soft, quadratic drag leaves short hops alone and reins in long falls. Pick by feel.

The bug: drag stronger than the step

The obvious code adds gravity minus drag, as in every lesson so far:

local strength = c * math.abs(vy)       -- or k, for linear drag
vy = vy + (GRAVITY - strength * vy) * dt

Now the hero, falling at 600 px/s, opens a parachute with a top speed of 80 px/s, so c = 1800 / 6400 = 0.28125. At 600 px/s the drag is 0.28125 × 600 × 600 = 101,250 px/s², and one step of 1/60 s removes 1687 px/s. The hero only had 630.

The first step removes more speed than there is, so the hero shoots upward. Now drag points down, and since it grows with the square of the speed, each overshoot is bigger.

The rule: if strength * dt is more than 1, one step of drag removes more speed than the body has.

The fix: divide instead of subtract

vy = (vy + GRAVITY * dt) / (1 + strength * dt)

In words: add gravity, then divide by a number that is always bigger than 1. The drag part can only shrink the speed towards zero. It can never flip its sign or make it grow, however strong the drag is. This is a small piece of implicit integration: the drag is worked out for the end of the step instead of the start.

It keeps the same top speed. Run one step at terminal velocity: (600 + 30) / (1 + 0.005 * 600 / 60) = 630 / 1.05 = 600. Linear drag gives the same: (600 + 30) / (1 + 3 / 60) = 600.

Many platformers skip drag and clamp instead: vy = math.min(vy, MAX_FALL). That works too; the speed just hits its ceiling with a sharp corner instead of easing in.

Watch the red drag arrow grow to match the grey gravity arrow as the graph levels off. Then open the parachute at full speed: the middle body blows up. With linear drag the obvious code survives at 60 steps per second but fails at 10. With quadratic drag, a terminal speed of 100 and 10 steps per second, it fails even without the parachute.

The code

The right-hand lane of the demo in LÖVE, with the same names and numbers, on the fixed timestep from the first lesson. Set QUADRATIC to false for linear drag.

local STEP = 1 / 60
local GRAVITY = 1800       -- px/s², y points down in LÖVE
local TERMINAL = 600       -- px/s, the top fall speed you want
local PARACHUTE = 80       -- px/s, top speed with the parachute open
local QUADRATIC = true     -- false for linear drag

local body = { y = 0, vy = 0, terminal = TERMINAL }
local accumulator = 0

local function dragConstant(terminal)
  if QUADRATIC then
    return GRAVITY / (terminal * terminal)   -- c, per pixel
  end
  return GRAVITY / terminal                  -- k, per second
end

local function step(b, dt)
  local strength = dragConstant(b.terminal)
  if QUADRATIC then
    strength = strength * math.abs(b.vy)     -- grows with speed
  end
  b.vy = (b.vy + GRAVITY * dt) / (1 + strength * dt)
  b.y = b.y + b.vy * dt
end

function love.keypressed(key)
  if key == "p" then
    body.terminal = PARACHUTE
  elseif key == "space" then
    body.y = 0
    body.vy = 0
    body.terminal = TERMINAL
  end
end

function love.update(dt)
  accumulator = accumulator + math.min(dt, 0.25)
  while accumulator >= STEP do
    step(body, STEP)
    accumulator = accumulator - STEP
  end
end

function love.draw()
  local h = love.graphics.getHeight()
  love.graphics.circle("fill", 200, body.y % h, 12)   -- wraps around the screen
  love.graphics.print(string.format("%.1f px/s", body.vy), 10, 10)
end
# On a CharacterBody2D. y points down in Godot too.
# Uses the full speed, so drag works in any direction.
const GRAVITY := 1800.0
const TERMINAL := 600.0
const DRAG := GRAVITY / (TERMINAL * TERMINAL)   # quadratic c

func _physics_process(delta: float) -> void:
    var speed := velocity.length()
    velocity = (velocity + Vector2(0.0, GRAVITY) * delta) / (1.0 + DRAG * speed * delta)
    move_and_slide()
// On a Rigidbody2D with Gravity Scale set to 0, so this code owns gravity.
// Unity works in metres and y points up: 18 m/s² and 6 m/s at 100 px per metre.
const float Gravity = 18f;
const float Terminal = 6f;
const float Drag = Gravity / (Terminal * Terminal);   // quadratic c, per metre
Rigidbody2D body;

void Awake() { body = GetComponent<Rigidbody2D>(); }

void FixedUpdate()
{
    Vector2 v = body.linearVelocity;   // body.velocity before Unity 6
    float dt = Time.fixedDeltaTime;
    v = (v + Vector2.down * Gravity * dt) / (1f + Drag * v.magnitude * dt);
    body.linearVelocity = v;
}

Both engines also have a damping value on rigid bodies: linear_damp on a Godot RigidBody2D, Linear Damping on a Unity Rigidbody2D (Linear Drag before Unity 6). These act like linear drag, but their exact formulas differ, so measure the top speed instead of computing it.

Pitfalls

  • Subtracting strong drag. Once strength * dt passes 1, the speed flips and explodes. Divide instead.
  • Quadratic drag per axis in 2D. Separate c * vx * vx and c * vy * vy treat diagonals differently. Use the length of the whole velocity, as in the GDScript tab.
  • Forgetting that drag also acts on the way up. While rising, drag adds to gravity, so jumps designed in the jump arc lesson come out lower. Leave drag off while rising, or retune.
  • The same drag on the run. Horizontal drag lowers top running speed. To limit only falls, apply it to vertical speed.
  • Drag per drawn frame. Drag applied per frame changes with the frame rate. Keep it in the fixed step.

In real games

Physics engines give every body a damping setting: linearDamping on a Box2D body definition, linear_damp in Godot, Linear Damping in Unity. It is the quickest way to make debris settle.

Many 2D platformers cap fall speed instead of simulating air, which keeps long falls readable. Smoke and spark particles commonly use strong drag so they burst outward and then hang.

For scale, the figure usually quoted for a skydiver falling belly-down is roughly 55 m/s, about 200 km/h.

Takeaways

  • Drag pushes against motion and grows with speed: linear drag is k * speed, quadratic drag is c * speed².
  • Terminal velocity is the speed at which drag cancels gravity and the speed stops changing.
  • Design from the top speed: k = GRAVITY / TERMINAL, c = GRAVITY / TERMINAL².
  • Quadratic drag reaches top speed sooner and leaves slow motion almost untouched; linear drag feels softer all the time.
  • Subtracting strong drag explodes. (v + GRAVITY * dt) / (1 + strength * dt) never reverses and keeps the same top speed.
