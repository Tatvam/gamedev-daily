Gravity and free fall

How constant gravity turns a throw into a parabola, and how to choose a gravity value in pixels per second squared from the fall you want.

You type in 9.81 because that is real gravity, and your character hangs in the air like a balloon. So you convert it properly to pixels, and now every fall looks like it was filmed on the Moon. The number was right both times. It was the wrong question.

This lesson shows what gravity does to a falling body, and how to pick the number from the fall you want.

Gravity is one constant acceleration

A body in free fall is moved by gravity alone. Near the ground, gravity is the same acceleration everywhere and for every object. Call it g, measured in pixels per second squared (px/s²).

So the speed grows by the same amount every second:

speed = g * t

In words: after t seconds of falling from rest, the body moves at g times t pixels per second. With g = 1800, that is 900 px/s after half a second.

The distance fallen grows with the square of the time:

distance = 0.5 * g * t * t

In words: twice the time means four times the distance. The units check out: px/s² times s² is px.

Mass appears in neither line. Gravity is a force of mass * g, and dividing a force by the mass, as in the forces lesson, leaves g. Without air pushing back, a rock and a feather fall together.

Throwing is falling plus sliding

Gravity only touches the vertical speed. A ball thrown sideways keeps its sideways speed, so it moves the same distance sideways in each tick while falling faster and faster. That draws a parabola, the curve of y = x². A dropped ball and a thrown ball released at the same height land at the same moment.

One step by hand

The game does not use the formulas. It runs the two lines from earlier lessons, velocity first, at a fixed step of 1/60 s. With g = 1800, gravity adds 1800 / 60 = 30 px/s per step:

  • Step 1: speed 0 + 30 = 30 px/s, so the ball moves 30 / 60 = 0.5 px.
  • Step 2: speed 60 px/s, it moves 1.0 px more, 1.5 px in total.

The formula says 0.5 × 1800 × (1/30)² = 1.0 px after two steps. The stepped ball is slightly ahead, as if it had started falling half a step early, and it can only land on a whole step. For a 250 pixel drop the formula says 0.527 s and the game lands on step 32, at 0.533 s. Close enough to plan with.

From metres to pixels

Real gravity is 9.81 metres per second squared. Your game measures in pixels, so you need a scale: how many pixels make one metre. Then:

g_pixels = 9.81 * pixels_per_metre

In words: the same acceleration, written in your units. If a character 87.5 px tall is meant to be 1.75 m, the scale is 50 px per metre and real gravity is 490.5 px/s². Typing 9.81 straight into a pixel game is 50 times too weak here.

Mind the sign. In LÖVE and in Godot 2D, y grows downwards, so gravity is positive. In Unity, y grows upwards and gravity is negative.

Correct is not the same as good

At 490.5 px/s² a 250 px drop, five metres at this scale, takes a full second. That is physically right and usually feels slow on screen, partly because game characters jump several times their own height. Choosing a stronger gravity than your scale implies is a design decision, not a mistake.

Choose gravity from the fall you want

Turn the distance formula around. Decide how far a body should fall and how long that should take, then:

g = 2 * height / (time * time)

In words: twice the drop, divided by the fall time squared. Want a 250 px drop to take half a second? Then g = 2 × 250 / 0.25 = 2000 px/s². The table shows the same drop under a few choices, using time = √(2 × height / g) and landing speed = √(2 × g × height).

The code

The demo as a LÖVE program, with the same numbers: a 250 px drop from y = 80 to a floor at y = 330, gravity 1800 px/s², and a throw at 250 px/s. It prints the fall time and landing speed of each ball.

local GRAVITY = 1800      -- px/s^2, positive: screen y grows downward
local STEP = 1 / 60       -- fixed step, seconds
local FLOOR_Y = 330       -- y of a ball's centre when it rests on the floor
local accumulator = 0

-- Pick gravity from a fall you want: drop height in px, time in s.
local function gravityFor(height, seconds)
  return 2 * height / (seconds * seconds)
end

local function newBall(vx)
  return { x = 70, y = 80, vx = vx, vy = 0, time = 0, landed = false }
end

local dropped = newBall(0)
local thrown = newBall(250)

local function fall(ball, dt)
  if ball.landed then return end
  ball.vy = ball.vy + GRAVITY * dt   -- gravity changes only vertical speed
  ball.x = ball.x + ball.vx * dt     -- sideways speed never changes
  ball.y = ball.y + ball.vy * dt
  ball.time = ball.time + dt
  if ball.y >= FLOOR_Y then
    ball.y = FLOOR_Y
    ball.landed = true
    print(string.format("landed after %.2f s at %.0f px/s", ball.time, ball.vy))
    ball.vx, ball.vy = 0, 0          -- stop, or gravity keeps piling up
  end
end

function love.update(dt)
  accumulator = accumulator + math.min(dt, 0.25)
  while accumulator >= STEP do
    fall(dropped, STEP)
    fall(thrown, STEP)
    accumulator = accumulator - STEP
  end
end

function love.draw()
  love.graphics.line(0, FLOOR_Y + 8, love.graphics.getWidth(), FLOOR_Y + 8)
  love.graphics.circle("fill", dropped.x, dropped.y, 8)
  love.graphics.circle("fill", thrown.x, thrown.y, 8)
end
# Godot 4. 2D gravity is set in Project Settings > Physics > 2D >
# Default Gravity, 980 px/s^2 by default. +y is down.
extends CharacterBody2D

var gravity: float = ProjectSettings.get_setting("physics/2d/default_gravity")

func _physics_process(delta: float) -> void:
    if not is_on_floor():
        velocity.y += gravity * delta
    move_and_slide()

# A RigidBody2D falls by itself. Its gravity_scale property
# multiplies the project gravity for that one body.
// Unity: gravity is in Project Settings > Physics 2D > Gravity,
// (0, -9.81) by default. +y is up, and one unit is meant to be one metre.
using UnityEngine;

public class StrongerGravity : MonoBehaviour
{
    void Start()
    {
        Physics2D.gravity = new Vector2(0f, -30f);       // the whole game
        GetComponent<Rigidbody2D>().gravityScale = 1.5f; // or one body
    }
}

Pitfalls

  • Using 9.81 in a pixel world. It is in metres per second squared. Multiply by your pixels per metre, or choose from the fall time.
  • Gravity piling up on the floor. If you keep adding gravity while a character stands still, its vertical speed grows every step. When it walks off a ledge, it drops instantly at a huge speed. Set the vertical speed to zero on landing, as the code above does.
  • No limit on fall speed. Under constant gravity speed grows forever, and a long fall soon moves more pixels per step than a thin floor is thick. Many games clamp it, for example ball.vy = math.min(ball.vy, MAX_FALL). That is a game rule, not physics; the drag lesson shows the physical version.
  • Making heavy things fall faster. If you add gravity as a force, add mass * g, so that dividing by the mass gives g back. Adding the same force to every body makes light ones fall faster.

In real games

Both engines from these lessons start you with one global gravity and let each body scale it. Godot 4 uses 980 px/s² for 2D by default, and RigidBody2D has a gravity_scale. Unity uses (0, −9.81) for 2D physics by default, and Rigidbody2D has a gravityScale.

Player characters are often not moved by the engine's gravity at all. Godot's CharacterBody2D does not fall by itself: its script adds gravity to its velocity in _physics_process, as in the GDScript tab. Doing it yourself gives the designer full control of the numbers, which is how the next lesson will tune jumps.

Your turn (15 minutes)

In your game, drop something from a known height in pixels and print how long it takes to land. Check the gravity you are really using with 2 * height / (time * time).

Now decide how long that fall should take, calculate the new gravity with gravityFor, and set it. Add a maximum fall speed. You are done when the printed time matches your target to within a step, about 0.02 s.

Takeaways

  • Gravity is a constant acceleration: speed grows with time, distance with time squared.
  • It acts only on vertical speed, so a sideways throw becomes a parabola and lands at the same moment as a drop.
  • Real gravity in pixels is 9.81 times your pixels per metre, and it often feels too slow on screen.
  • Choose gravity from the fall you want: g = 2 × height / time².
  • Reset vertical speed on landing, and cap fall speed if long falls are possible.
