Restitution and bouncing

How one restitution number decides how much speed a bounce keeps, why the height kept is its square, and how to stop balls sinking or buzzing.

You write vy = -vy * 0.5 when the ball hits the floor. It bounces twice, then slowly sinks into the ground and falls out of the level. You fix that, and now the resting ball plays its bounce sound sixty times a second.

One number for bounciness

The restitution of a collision, usually written e, is the speed the bodies separate with divided by the speed they approached with, measured along the contact normal. The normal is the unit vector pointing out of the surface, towards the ball.

  • e = 0: no bounce. The ball stops moving into the surface and stays on it. That is what the previous lesson did.
  • e = 1: a perfect bounce. The ball leaves as fast as it arrived.
  • In between: the ball keeps that fraction of its speed into the surface.

Only the part into the surface bounces

A ball hitting the floor at an angle should keep moving sideways, so split the velocity in two. The normal speed is how fast the ball moves along the normal:

vn = vx * nx + vy * ny

In words: a dot product. When vn is negative, the ball is moving into the surface. The rest of the velocity, the tangent part, slides along the surface and is not touched here (friction is a later lesson).

The bounce replaces the normal part vn with -e * vn. Taking away vn and adding -e * vn is one subtraction:

vx = vx - (1 + e) * vn * nx
vy = vy - (1 + e) * vn * ny

In words: remove the speed into the surface once to stop the ball, and remove it e more times to send it back out.

Check one step by hand

Screen coordinates, so +y is down and the floor normal is (0, -1). A ball arrives with velocity (120, 780) pixels per second and e = 0.6.

  • vn = 120 × 0 + 780 × (−1) = −780. Negative, so it is moving into the floor.
  • vx = 120 − 1.6 × (−780) × 0 = 120. The sideways speed is kept.
  • vy = 780 − 1.6 × (−780) × (−1) = 780 − 1248 = −468. Up at 0.6 × 780.

Speed keeps e, height keeps e squared

A ball thrown up at speed v under gravity g rises to h = v² / (2g). In words: height grows with the square of the launch speed. The bounce multiplies the speed by e, so it multiplies the height by e².

Designers usually think in heights: "it should come back to half the height". Then pick e = sqrt(0.5) ≈ 0.71, not 0.5.

The game answer

Real restitution changes with impact speed and material, and an ideal ball makes endless ever-smaller bounces. Games use one constant per material and cancel the tiny bounces, as the next section shows.

The two bugs

Flipping without pushing out. A ball moves in steps, so it ends the impact step a little inside the floor. vy = -e * vy sends it up, but once the bounces are small, one step up is not enough to leave the floor. The next step it is still "colliding", so the code flips the velocity again, back down. It flips every step and gravity wins, so the ball sinks. The fix: push the ball out to the surface, and bounce only when vn is negative.

Bouncing forever at rest. With gravity at 1500 pixels per second squared and steps of 1/60 s, a resting ball gains 1500 × 1/60 = 25 pixels per second each step and touches the floor again. Every step looks like a new tiny impact, so a sound or dust puff fires 60 times a second. The fix is a rest threshold: if the ball hits slower than, say, 60 pixels per second, use e = 0 and do not count it as a bounce. A 60 pixel per second bounce would rise only 60² / 3000 = 1.2 pixels, so nothing visible is lost.

The code

This is one lane of the demo with Push out, then bounce, e = 0.5 and a 60 pixel per second threshold. It peaks near 41 pixels, a little under the 45 that e² × 180 predicts, because the ball is snapped to the floor and the peak is sampled once per step.

local GRAVITY     = 1500    -- pixels per second squared, +y is down
local STEP        = 1 / 60  -- fixed timestep in seconds
local RESTITUTION = 0.5     -- 0 = no bounce, 1 = keeps all its speed
local REST_SPEED  = 60      -- pixels per second: slower hits do not bounce
local FLOOR, LEFT, RIGHT = 312, 0, 160

local ball = { x = 80, y = 120, vx = 0, vy = 0, r = 12, bounces = 0 }

-- (nx, ny) is the surface normal, pointing out of the surface towards the ball.
local function bounce(b, nx, ny)
  local vn = b.vx * nx + b.vy * ny        -- speed along the normal
  if vn >= 0 then return end              -- already leaving: leave it alone
  local e = RESTITUTION
  if -vn < REST_SPEED then
    e = 0                                 -- too slow: just stop, no event
  else
    b.bounces = b.bounces + 1             -- play a sound here
  end
  b.vx = b.vx - (1 + e) * vn * nx
  b.vy = b.vy - (1 + e) * vn * ny
end

local function step(dt)
  ball.vy = ball.vy + GRAVITY * dt
  ball.x = ball.x + ball.vx * dt
  ball.y = ball.y + ball.vy * dt
  -- Push out first, then bounce.
  if ball.y + ball.r > FLOOR then ball.y = FLOOR - ball.r; bounce(ball, 0, -1) end
  if ball.x - ball.r < LEFT then ball.x = LEFT + ball.r; bounce(ball, 1, 0) end
  if ball.x + ball.r > RIGHT then ball.x = RIGHT - ball.r; bounce(ball, -1, 0) end
end

local accumulator = 0
function love.update(dt)
  accumulator = accumulator + math.min(dt, 0.25)
  while accumulator >= STEP do
    step(STEP)
    accumulator = accumulator - STEP
  end
end

function love.draw()
  love.graphics.circle("fill", ball.x, ball.y, ball.r)
end
# A CharacterBody2D that bounces by itself. Godot's +y is down too.
const GRAVITY := 1500.0
const RESTITUTION := 0.5
const REST_SPEED := 60.0

func _physics_process(delta: float) -> void:
    velocity.y += GRAVITY * delta
    var hit := move_and_collide(velocity * delta)
    if hit:
        var n := hit.get_normal()
        var vn := velocity.dot(n)
        if vn < 0.0:
            var e := RESTITUTION if -vn >= REST_SPEED else 0.0
            velocity -= (1.0 + e) * vn * n
// Let the Rigidbody2D bounce: give it a material with bounciness.
void Start()
{
    var mat = new PhysicsMaterial2D("Ball");
    mat.bounciness = 0.5f;   // the restitution
    mat.friction = 0f;
    GetComponent<Rigidbody2D>().sharedMaterial = mat;
}
// The rest threshold is a project setting: Physics2D.velocityThreshold.
// Unity measures it in world units (metres) per second, not pixels.

In Godot, a RigidBody2D takes its bounciness from the bounce property of a PhysicsMaterial set as its physics material override. In Unity, PhysicsMaterial2D.bounciness plays the same role. When two materials meet, each engine combines their values by its own rule; check your version's manual.

Pitfalls

  • Impact damage without a threshold. The rest threshold matters for gameplay too: a resting crate that "lands" every step deals fall damage every step.
  • Scaling the whole velocity. v = reflect(v) * e also slows the sideways motion, so a ball skimming the floor brakes hard. If you want that, call it friction and give it its own number.
  • Restitution above 1. Each bounce adds energy, and the ball climbs higher until it flies out of the level. For a bumper or a spring pad, set the outgoing speed directly instead.
  • Expecting e² exactly. With 60 steps per second the measured height ratio is a few hundredths lower, for example 0.23 instead of 0.25. The speed ratio is exact. More steps per second shrink the gap.

In real games

The engines from these lessons all expose restitution as a material setting: bounce on Godot's PhysicsMaterial, bounciness on Unity's PhysicsMaterial2D. Box2D, the open source engine by Erin Catto that Unity's 2D physics is built on, treats collisions slower than a velocity threshold as having no bounce, the same idea as REST_SPEED. Unity exposes it as Physics2D.velocityThreshold, and as Physics.bounceThreshold for 3D.

Bumpers and spring pads are where the game answer wins outright: they launch at a designed speed, which no real material does.

Takeaways

  • Restitution e is the fraction of the speed into the surface that comes back out.
  • Bounce with v = v - (1 + e) * vn * n; it changes only the normal part.
  • Height kept is e², so for a target height ratio use its square root.
  • Push out first, and bounce only when vn is negative, or the ball sinks.
  • A rest threshold turns tiny bounces into a clean stop and stops event spam.
