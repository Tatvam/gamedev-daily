The minimum translation vector

How the axis of smallest overlap in a separating axis test gives the direction and distance that push two overlapping shapes apart.

Your player walks into a tilted crate. The collision test says "overlap", so you push the player back up by the overlap on y, and now they climb the crate's side like a ladder. Or you push them along the line between the two centres, and they slide off sideways. Knowing that two shapes overlap is not enough: you need to know which way out is shortest, and how far.

The shortest way out

The minimum translation vector (MTV) is the smallest move you can apply to one shape so that it stops overlapping another. It has a direction, a unit vector called the normal, and a length called the depth or penetration.

The separating axis test from the last lesson does most of the work. When no edge normal shows a gap, every axis reports an overlap instead, and the MTV lies along the axis with the smallest one.

Two ways out on every axis

On one axis, shape A's shadow runs from aLo to aHi and B's from bLo to bHi. B can leave A's shadow in two directions:

local pushPlus  = aHi - bLo   -- move B this far along +axis
local pushMinus = bHi - aLo   -- or this far along -axis

In words: to clear A on the plus side, B's low end must move up to A's high end. To clear it on the minus side, B's high end must move down to A's low end. The overlap on this axis is the smaller of the two, and the smaller one also tells you which way to go.

If either number is negative, the shadows have a gap and the shapes are apart.

local depth = math.min(pushPlus, pushMinus)

Do this for every axis and keep the one with the smallest depth. That axis, pointed the right way, times that depth is the MTV.

The numbers

Take the triangle from the last lesson, corners (100, 100), (200, 100) and (100, 200), and a 60 pixel box from (140, 140) to (200, 200). Its top-left corner is inside the triangle.

  • Axis A1, (0, 1), the normal of the top edge. A covers 100 to 200 and B covers 140 to 200. pushPlus = 200 - 140 = 60, pushMinus = 200 - 100 = 100. Overlap 60.
  • Axis A2, (-0.707, -0.707), the normal of the long edge. A covers -212.1 to -141.4 and B covers -282.8 to -198.0. pushPlus = 141.4, pushMinus = -198.0 + 212.1 = 14.1. Overlap 14.1.
  • Axis A3, (1, 0), the normal of the left edge. The same as A1: overlap 60.

The box's own edge normals are x and y again and also give 60. The smallest overlap is 14.1 on A2, and it was pushMinus that won, so B moves along minus the axis: (0.707, 0.707) times 14.1, which is (10, 10). The box's corner moves from (140, 140) to (150, 150), exactly onto the long edge, where x + y = 300.

Bug one: the push points the wrong way

An edge normal can point either way; the separating axis test did not care, because a gap is a gap from either side. The MTV does care. If you take the axis as it comes and push B by depth along it, half the time you push B into A. In the example the raw normal is (-0.707, -0.707), and pushing along it moves the box by (-10, -10): the overlap doubles to 28.3.

The fix is the comparison above: if pushPlus is smaller, push along the axis, otherwise along its negative. A common alternative that agrees for shallow overlaps: flip the normal if it points from B's centre towards A's.

Bug two: out the far side

The MTV knows nothing about where B came from, only where it is now. If a fast box falls into a thin platform and ends a step with its centre below the platform's centre, the shortest way out is downwards. The box tunnels even though the overlap was detected.

Here the physically correct answer and the good game answer part ways. Correct would be to rewind to the moment of first contact, as the swept tests did. Cheaper, and good enough for most games, is to keep overlaps shallow: a fixed timestep, sensible top speeds and colliders thicker than one step of movement.

Rule of thumb

The MTV is trustworthy while the depth is small compared with the shapes. When the depth gets close to half the thickness of either shape, expect it to pick the wrong side.

The code

The separating axis test from the last lesson, now keeping the smallest overlap and its direction. With the example shapes it prints push B by (10.0, 10.0), depth 14.1; press Space to apply it.

-- Convex polygons as flat lists of corners: x1, y1, x2, y2, ...
local triangle = { 100, 100,  200, 100,  100, 200 }
local box      = { 140, 140,  200, 140,  200, 200,  140, 200 }

local function project(poly, ax, ay)
  local lo, hi = math.huge, -math.huge
  for i = 1, #poly, 2 do
    local d = poly[i] * ax + poly[i + 1] * ay
    lo = math.min(lo, d)
    hi = math.max(hi, d)
  end
  return lo, hi
end

-- Tests the normal of every edge of shape. Keeps the smallest overlap in best.
-- Returns false as soon as an axis shows a gap.
local function smallestOverlap(shape, a, b, best)
  for i = 1, #shape, 2 do
    local j = i + 2
    if j > #shape then j = 1 end
    local ex, ey = shape[j] - shape[i], shape[j + 1] - shape[i + 1]
    local len = math.sqrt(ex * ex + ey * ey)
    local ax, ay = -ey / len, ex / len
    local aLo, aHi = project(a, ax, ay)
    local bLo, bHi = project(b, ax, ay)
    local pushPlus  = aHi - bLo                 -- move B this far along +axis
    local pushMinus = bHi - aLo                 -- or this far along -axis
    local depth = math.min(pushPlus, pushMinus)
    if depth < 0 then return false end          -- a gap: the shapes are apart
    if depth < best.depth then
      best.depth = depth
      if pushPlus < pushMinus then best.nx, best.ny = ax, ay
      else best.nx, best.ny = -ax, -ay end      -- point the push from A to B
    end
  end
  return true
end

-- The minimum translation vector: how far and which way to move B out of A.
local function mtv(a, b)
  local best = { depth = math.huge, nx = 0, ny = 0 }
  if not smallestOverlap(a, a, b, best) then return nil end
  if not smallestOverlap(b, a, b, best) then return nil end
  return best.depth, best.nx, best.ny
end

local function move(poly, dx, dy)
  for i = 1, #poly, 2 do
    poly[i] = poly[i] + dx
    poly[i + 1] = poly[i + 1] + dy
  end
end

function love.keypressed(key)
  if key == "space" then
    local depth, nx, ny = mtv(triangle, box)
    if depth then move(box, nx * depth, ny * depth) end
  end
end

function love.draw()
  love.graphics.polygon("line", triangle)
  love.graphics.polygon("line", box)
  local depth, nx, ny = mtv(triangle, box)
  if depth then
    love.graphics.print(string.format("push B by (%.1f, %.1f), depth %.1f",
      nx * depth, ny * depth, depth), 10, 10)
  else
    love.graphics.print("apart", 10, 10)
  end
end
# player.gd: a CharacterBody2D with a collision shape.
# Godot works out the normal and depth for you and reports them.
extends CharacterBody2D

func _physics_process(delta: float) -> void:
    var hit := move_and_collide(velocity * delta)
    if hit:
        print("normal ", hit.get_normal(), " depth ", hit.get_depth())
// PushOut.cs: moves this object's collider out of another one.
using UnityEngine;

public class PushOut : MonoBehaviour
{
    public Collider2D other;
    Collider2D self;

    void Awake() { self = GetComponent<Collider2D>(); }

    void FixedUpdate()
    {
        ColliderDistance2D d = Physics2D.Distance(other, self);
        if (d.isValid && d.isOverlapped)
        {
            transform.position += (Vector3)(d.pointA - d.pointB);
        }
    }
}

In both engines you seldom write this. Godot's move_and_collide reports a KinematicCollision2D holding the normal and depth. Unity's Physics2D.Distance returns a negative distance for overlapping colliders, with a normal and a point on each. Neither documents its algorithm inside.

Pitfalls

  • Unnormalised axes. Without dividing by the edge length, overlaps on different axes are scaled differently and the "smallest" is meaningless.
  • Stopping early. The yes or no test may stop at the first gap. The MTV needs every axis, since any of them might hold the smallest overlap.
  • Ties and flicker. Two nearly equal overlaps can swap winners from step to step, so the push flickers between two directions. Prefer last step's normal when they are close.
  • Moving both bodies. If both are free to move, split the push between them. How to split it by mass is a later lesson.
  • Pushing velocity too. Moving the position fixes the overlap, but a body still moving into the wall comes straight back next step. Remove the part of the velocity along the normal as well; sliding along walls covers that.

In real games

Box2D version 2 uses the separating axis search on polygon pairs (b2FindMaxSeparation in b2_collide_polygon.cpp) to find the axis of least penetration, which becomes the contact normal. Godot's KinematicCollision2D exposes the depth of an overlap through get_depth, and Unity's ColliderDistance2D exposes it as a negative distance.

Metanet Software's tutorial on collision for their game N describes projecting shapes onto axes and pushing the player out along the axis of smallest overlap, the same idea as this lesson.

Takeaways

  • The minimum translation vector is the shortest move that separates two overlapping shapes: a unit normal times a depth.
  • On each axis, B can leave A in two directions, aHi - bLo and bHi - aLo. The smaller is the overlap and gives the direction.
  • The MTV lies along the axis with the smallest overlap, so every axis must be tested.
  • Always point the push from A to B; the raw edge normal pushes the wrong way half the time.
  • The MTV only sees the present. Deep overlaps get pushed out the wrong side, so keep them shallow.
