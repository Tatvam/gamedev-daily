Swept AABB tests

How to calculate when a moving box first touches another box during a step, stop it there, and find which face it hit, so it cannot tunnel.

Your character dashes at a wall. On a fast dash it ends up on the other side. On a slower one the game sees the overlap, cancels the move, and the character stops several body lengths short. Both bugs come from checking only where the box ends the step. The fix is to ask "when during the step do they first touch?"

Ask when, not whether

The last lesson said: test the path, not the point. For a box, the path is a straight slide by the step's motion d = (dx, dy), the velocity times the step. Every position along it is described by one number, t:

position(t) = start + d * t

In words: at t = 0 the box is at the start, at t = 1 at the end, at t = 0.5 halfway. The smallest t at which it touches the other box is the time of impact. Stop the box there and it touches exactly, with no gap and no overlap. A test that finds this time for two axis-aligned boxes is a swept AABB test.

One axis at a time

Two boxes overlap only when they overlap on x and on y, so take each axis alone. Call the moving box A and the wall B. Moving right, A's x span starts to overlap when its right edge reaches B's left edge, and stops when its left edge passes B's right edge:

xEnter = (B.left - A.right) / dx
xExit  = (B.right - A.left) / dx

In words: the gap still to close, divided by the distance moved in a whole step, is the fraction of the step needed to close it.

With the demo's starting numbers: A is 40 by 40 with its top-left corner at (80, 140), the wall spans x from 320 to 370, and the step moves 400 pixels right. So xEnter = (320 - 120) / 400 = 0.5 and xExit = (370 - 80) / 400 = 0.725.

Moving left, the edges swap roles, and dividing by a negative dx keeps the times positive. When dx is zero, the axis overlaps for the whole step or never, which you check by comparing the spans directly.

The y axis works the same way. The demo moves 60 pixels up, so dy = -60 (y grows downwards), and A enters when its top reaches the wall's bottom at 240: yEnter = (240 - 140) / -60 = -1.67 and yExit = (90 - 180) / -60 = 1.5. A negative entry means y was already overlapping before the step began.

Both axes: the later entry, the earlier exit

The boxes touch only while both axes overlap:

enter = max(xEnter, yEnter)
exit  = min(xExit, yExit)

In words: wait for the later of the two entries, and stop at the earlier of the two exits.

There is a hit this step only when enter < exit and enter is between 0 and 1. Otherwise the axes overlap at different moments (the box slips past a corner), the contact is in a later step, or the boxes overlapped before the step began. For the demo: enter = max(0.5, -1.67) = 0.5, exit = min(0.725, 1.5) = 0.725, a hit at t = 0.5.

Where to stop, and which way the wall faces

Stop at the start plus the motion times enter: (80 + 400 * 0.5, 140 - 60 * 0.5) = (280, 110). A's right edge is now at 320, exactly on the wall's left edge.

The contact normal, the direction pointing out of the surface that was hit, comes from the axis that entered last, the one still keeping the boxes apart. Here that is x with A moving right, so the normal is (-1, 0), opposite to the motion on that axis.

It is a raycast in disguise

Shrink A to its centre point and grow B by half of A's size on every side. A ray from A's centre along d hits the grown box at the same t: the slab test from the raycasts lesson. Check: (300 - 100) / 400 = 0.5.

Correct, but not always what you want

Stopping dead throws away the rest of the step. Games usually spend the leftover 1 - enter sliding along the surface, a later lesson. With several walls, test each and keep the smallest enter.

The code

A LÖVE program with the demo's starting numbers; space takes one step. The first press prints hit at t = 0.500, normal (-1, 0), stopped at (280, 110), later presses a hit at t = 0, so the box rests against the wall. In a game, call sweptAABB from your fixed step with vx * STEP, vy * STEP.

-- Boxes are { x, y, w, h } with x, y the top-left corner. y grows downwards.
local mover = { x = 80, y = 140, w = 40, h = 40 }
local wall  = { x = 320, y = 90, w = 50, h = 150 }
local move  = { x = 400, y = -60 }   -- pixels moved in one step (velocity * STEP)

-- When A's span enters and leaves B's span on one axis, as fractions of the move.
local function axisTimes(aMin, aSize, bMin, bSize, d)
  if d > 0 then
    return (bMin - (aMin + aSize)) / d, (bMin + bSize - aMin) / d
  elseif d < 0 then
    return (bMin + bSize - aMin) / d, (bMin - (aMin + aSize)) / d
  elseif aMin + aSize > bMin and aMin < bMin + bSize then
    return -math.huge, math.huge   -- not moving, always overlapping on this axis
  else
    return math.huge, -math.huge   -- not moving, never overlapping on this axis
  end
end

-- Returns t, nx, ny for the first contact during the move, or nil for no hit.
local function sweptAABB(a, dx, dy, b)
  local xEnter, xExit = axisTimes(a.x, a.w, b.x, b.w, dx)
  local yEnter, yExit = axisTimes(a.y, a.h, b.y, b.h, dy)
  local enter = math.max(xEnter, yEnter)   -- both overlap after the later entry
  local exit = math.min(xExit, yExit)      -- and until the earlier exit
  if enter >= exit or enter < 0 or enter > 1 then
    return nil
  end
  if xEnter > yEnter then
    return enter, (dx > 0) and -1 or 1, 0   -- x entered last: left or right face
  end
  return enter, 0, (dy > 0) and -1 or 1     -- y entered last, or a tie: top or bottom
end

local message = "press space to take one step"

function love.keypressed(key)
  if key ~= "space" then return end
  local t, nx, ny = sweptAABB(mover, move.x, move.y, wall)
  if t then
    mover.x = mover.x + move.x * t   -- stop at first contact
    mover.y = mover.y + move.y * t
    message = string.format("hit at t = %.3f, normal (%d, %d), stopped at (%g, %g)",
      t, nx, ny, mover.x, mover.y)
  else
    mover.x = mover.x + move.x
    mover.y = mover.y + move.y
    message = "no hit"
  end
end

function love.draw()
  love.graphics.rectangle("fill", wall.x, wall.y, wall.w, wall.h)
  love.graphics.rectangle("line", mover.x, mover.y, mover.w, mover.h)
  love.graphics.print(message, 10, 10)
end
# mover.gd: a CharacterBody2D with a rectangle collision shape.
extends CharacterBody2D

func _ready() -> void:
    velocity = Vector2(24000, -3600)   # 400 and -60 pixels per step at 60 steps per second

func _physics_process(delta: float) -> void:
    # Sweeps the body's shape along the motion and stops it at first contact.
    var collision := move_and_collide(velocity * delta)
    if collision:
        print("hit, normal ", collision.get_normal())
        velocity = Vector2.ZERO
// Mover.cs: on an object with a BoxCollider2D and a kinematic Rigidbody2D.
// Assumes the collider has no offset and the object is not scaled.
using UnityEngine;

public class Mover : MonoBehaviour
{
    public Vector2 velocity = new Vector2(40f, -6f);   // units per second
    public LayerMask wallMask;                          // must not include this object's layer
    BoxCollider2D box;
    Rigidbody2D body;

    void Awake()
    {
        box = GetComponent<BoxCollider2D>();
        body = GetComponent<Rigidbody2D>();
    }

    void FixedUpdate()
    {
        Vector2 move = velocity * Time.fixedDeltaTime;
        if (move == Vector2.zero) return;
        RaycastHit2D hit = Physics2D.BoxCast(body.position, box.size, 0f,
                                             move.normalized, move.magnitude, wallMask);
        if (hit.collider != null)
        {
            // hit.fraction is t, hit.normal the normal, hit.centroid the box centre at contact
            body.MovePosition(hit.centroid);
            velocity = Vector2.zero;
        }
        else
        {
            body.MovePosition(body.position + move);
        }
    }
}

Godot's move_and_collide keeps a small safe margin, so the body stops a hair before the surface. PhysicsDirectSpaceState2D.cast_motion answers the same question without moving anything, as safe and unsafe fractions of the motion.

Pitfalls

  • Dividing by zero motion. A falling box has dx = 0. Dividing gives infinities, or not-a-number when the gap is also zero, and every comparison with not-a-number is false. Handle zero explicitly, as axisTimes does.
  • Taking the earlier entry. The box then stops as soon as its x span lines up with the wall, even far below it, as at t = 0.4 in the diagram.
  • Trusting a box around the whole path. In "Just misses the corner" it overlaps the wall, yet the path never touches it. A fine cheap first check, not the answer.
  • Starting inside. If the boxes already overlap, enter is negative, the test reports nothing, and the box walks through. Push it out first; that is a later lesson.
  • Rounding after stopping. Floating point can leave the box a sliver inside the wall, so the next enter is slightly negative and counts as no hit. If resting boxes creep into walls, accept a small negative tolerance and treat it as 0.
  • Exact corner hits. When the entries are equal, either face is defensible. The code picks y, so a character falling onto a ledge corner lands instead of being stopped sideways. That is a game choice, not physics.

In real games

Engines expose this as a shape cast: move a shape along a path and report the first hit. Godot's move_and_collide returns a KinematicCollision2D with the normal; Unity has Physics2D.BoxCast and Rigidbody2D.Cast. Box2D computes a time of impact for fast bodies during continuous collision detection, with a more general algorithm because its shapes rotate, but the result is the same idea: the fraction of the step at which contact begins.

Takeaways

  • Write the step's motion as start + d * t and look for the smallest t at which the boxes touch.
  • Each axis gives an entry and exit time: the gap to close divided by the motion on that axis.
  • The boxes touch from the later entry to the earlier exit. A hit needs enter < exit and enter between 0 and 1.
  • The axis that entered last gives the contact normal, pointing against the motion.
  • Zero motion on an axis, a start inside the wall, and rounding at rest are the cases that break naive versions.
