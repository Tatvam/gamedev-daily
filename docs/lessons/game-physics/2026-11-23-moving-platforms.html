Moving platforms

How to carry a character on a moving platform by giving it the platform's step first, and how to keep the platform's speed when it jumps off.

The player steps onto a sliding raft, and it slides away under their feet. On a lift going down, the character stutters and the jump button works only now and then. Jump off a moving platform, and you land in the gap behind it. Two small rules fix all three.

Why the floor leaves without you

A moving platform is a kinematic body: your code moves it. The character controller's collision code only stops the character moving into a solid. It never drags the character along, so the floor can move away freely.

  • Sideways: the platform slides out from under the character, and the character drops.
  • Down: a lift at 120 px/s drops 2 pixels per 1/60 second step. Gravity of 1800 px/s² moves the character only half a pixel in its first step. It is in the air for about 7 steps, lands for 1, and repeats. Jump presses in those 7 steps do nothing.
  • Up: the platform rises into the character's feet. The demo pushes the character back out, so this works by luck. Code that ignores overlapping bodies lets it fall through the lift.

Rule 1: the rider takes the platform's step

A rider is a body whose ground, at the end of the last step, was the platform. Every step now runs in this order:

  1. Move every platform, and remember how far it went this step: dx and dy.
  2. Move each rider by the same dx and dy, using the normal move functions so walls still stop it.
  3. Then do the rider's own move: walking, gravity, jumping.
moveY(player, ground.dy)
moveX(player, ground.dx)

In words: whatever the floor did this step, the rider does too. Give every static block dx = 0 and dy = 0, and the same lines work on solid ground: a static floor is a platform that does not move.

The order matters. If the rider moves before the platform, it always works with last step's floor and the ground check flickers.

Rule 2: keep the platform's velocity when you leave

A rider moves at the platform's speed even when its own velocity is zero. When it jumps, that speed must not vanish. Store the floor's velocity every grounded step and use it in the air:

airVx = ground.vx                  -- every step on the ground
vy = -JUMP + ground.vy             -- on the step you jump
vx = input * RUN + airVx           -- every step in the air

In words: in the air, the character keeps the sideways speed of the floor it left, and a rising lift adds its speed to the jump. Here y grows downwards, so a rising lift has a negative vy.

How much does it matter? A jump at 520 px/s under 1800 px/s² lasts 2 × 520 / 1800 = 0.58 seconds, about 34 steps. A platform at 120 px/s moves about 68 pixels meanwhile. It is 90 pixels wide, so a character near its middle comes down beside it.

Measure the platform's velocity from the step it took, vx = dx / STEP, so carry and jump agree even on the step where it turns round.

One step by hand

The sliding platform's left edge is at x = 200, moving right at 120 px/s. The character stands on it at x = 245, with no input.

  • Platform: 120 × 1/60 = 2 pixels, so its left edge goes to 202. dx = 2, vx = 2 × 60 = 120.
  • Carry: the character moves by dx, from 245 to 247.
  • Own move: no input. Gravity gives vy = 1800 / 60 = 30 px/s, a 0.5 pixel move down, which the platform's top stops at 0. Grounded, airVx = 120.
  • Next step it jumps: carried to 249, vy = −520 + 0 + 30 = −490. One step later, in the air, airVx moves it 2 pixels to 251, and the platform reaches 206. Still 45 pixels from its left edge.

Correct versus good

The demo's platforms turn round instantly. A real passenger would be thrown off. A game rider stays glued, because being flung off your own lift feels unfair: carrying is a game rule, not friction. For the same reason, some games ignore a platform's downward speed on a jump.

Try it

Both fixes start off. The character stands on the sliding platform, and the platform leaves without it. Press Reset, switch on Carry the rider, and it rides along. Now press Jump while standing still: it comes down behind the platform. Switch on Keep platform velocity and jump again.

Then set Start on to the lift with carrying off. As it goes down, "Grounded in the last second" falls to about 12 percent, and most Jump presses are lost. Keyboard: click the scene, then arrows or A and D walk, Space jumps. On touch, hold beside the character to walk and tap above it to jump.

The code

The demo's step in Lua, with the same level and numbers. The move functions are the per-axis ones from earlier lessons, but they return the block that stopped the move, so the character knows what it stands on.

local STEP, GRAVITY, JUMP, RUN = 1 / 60, 1800, 520, 240
local W, H, EPS = 20, 36, 0.001
local SPEED = 120                    -- platform speed, px/s
local carry, inherit = true, true    -- set to false to see the bugs

-- Every block has a step (dx, dy) and a velocity. Static blocks keep 0.
local function block(x, y, w, h)
  return { x = x, y = y, w = w, h = h, dx = 0, dy = 0, vx = 0, vy = 0 }
end
local blocks = {
  block(0, 290, 640, 10), block(0, 0, 10, 290), block(630, 0, 10, 290),
  block(10, 200, 90, 90), block(100, 250, 40, 40), block(540, 120, 90, 170),
}
local slider = block(110, 200, 90, 12)
slider.axis, slider.min, slider.max, slider.dir = "x", 110, 330, 1
local lift = block(450, 220, 80, 12)
lift.axis, lift.min, lift.max, lift.dir = "y", 120, 220, -1
local platforms = { slider, lift }
blocks[#blocks + 1] = slider
blocks[#blocks + 1] = lift
local player = { x = 145, y = 164, vy = 0, airVx = 0, ground = slider }
local accumulator = 0

-- Move along one axis, stopping at the first solid face.
-- Returns the block that stopped the move, or nil.
local function moveX(b, dx)
  local allowed, hit = dx, nil
  for _, s in ipairs(blocks) do
    if b.y < s.y + s.h - EPS and b.y + H > s.y + EPS then
      if dx > 0 and b.x + W <= s.x + EPS and s.x - b.x - W < allowed then
        allowed, hit = s.x - b.x - W, s
      elseif dx < 0 and b.x >= s.x + s.w - EPS and s.x + s.w - b.x > allowed then
        allowed, hit = s.x + s.w - b.x, s
      end
    end
  end
  b.x = b.x + allowed
  return hit
end

local function moveY(b, dy)
  local allowed, hit = dy, nil
  for _, s in ipairs(blocks) do
    if b.x < s.x + s.w - EPS and b.x + W > s.x + EPS then
      if dy > 0 and b.y + H <= s.y + EPS and s.y - b.y - H < allowed then
        allowed, hit = s.y - b.y - H, s
      elseif dy < 0 and b.y >= s.y + s.h - EPS and s.y + s.h - b.y > allowed then
        allowed, hit = s.y + s.h - b.y, s
      end
    end
  end
  b.y = b.y + allowed
  return hit
end

local function movePlatform(p)
  local old = p[p.axis]
  local nextPos = old + p.dir * SPEED * STEP
  if nextPos < p.min or nextPos > p.max then      -- turn round at the ends
    nextPos = math.max(p.min, math.min(p.max, nextPos))
    p.dir = -p.dir
  end
  p[p.axis] = nextPos
  if p.axis == "x" then p.dx = nextPos - old else p.dy = nextPos - old end
  p.vx, p.vy = p.dx / STEP, p.dy / STEP          -- velocity from the step taken
end

-- A platform that moves into a body shoves it out the shortest way.
local function pushOut(b, s)
  local left, right = b.x + W - s.x, s.x + s.w - b.x
  local up, down = b.y + H - s.y, s.y + s.h - b.y
  local m = math.min(left, right, up, down)
  if m <= EPS then return end                    -- not overlapping
  if m == up then b.y = b.y - up
  elseif m == down then b.y = b.y + down
  elseif m == left then b.x = b.x - left
  else b.x = b.x + right end
end

local function physicsStep(b, ix, jump)
  for _, p in ipairs(platforms) do movePlatform(p) end  -- 1. platforms first
  local g = b.ground                                    -- what we stood on last step
  if g and carry then                                   -- 2. take the floor's step
    moveY(b, g.dy)
    moveX(b, g.dx)
  end
  for _, p in ipairs(platforms) do pushOut(b, p) end
  if g then b.airVx = inherit and g.vx or 0 end         -- keep the floor's speed
  local vx = ix * RUN                                   -- 3. our own move
  if not g then vx = vx + b.airVx end
  if g and jump then
    b.vy = -JUMP + (inherit and g.vy or 0)
  end
  b.vy = b.vy + GRAVITY * STEP
  if moveX(b, vx * STEP) and not g then b.airVx = 0 end -- hit a wall
  local hit = moveY(b, b.vy * STEP)
  if hit and b.vy > 0 then b.ground = hit else b.ground = nil end
  if hit then b.vy = 0 end
end

local jumpPressed = false
function love.keypressed(key)
  if key == "space" or key == "w" or key == "up" then jumpPressed = true end
end

function love.update(dt)
  accumulator = accumulator + math.min(dt, 0.25)
  while accumulator >= STEP do
    local ix = 0
    if love.keyboard.isDown("left", "a") then ix = ix - 1 end
    if love.keyboard.isDown("right", "d") then ix = ix + 1 end
    physicsStep(player, ix, jumpPressed)
    jumpPressed = false                  -- a press counts for one step
    accumulator = accumulator - STEP
  end
end

function love.draw()
  for _, s in ipairs(blocks) do love.graphics.rectangle("line", s.x, s.y, s.w, s.h) end
  love.graphics.rectangle("fill", player.x, player.y, W, H)
end
# Godot 4: move_and_slide() already carries a CharacterBody2D on a moving
# floor (an AnimatableBody2D, for example). Here we keep the platform's
# speed ourselves, as in the Lua. A sketch; check it in your own project.
extends CharacterBody2D

const RUN := 240.0
const GRAVITY := 1800.0
const JUMP := 520.0
var air_vx := 0.0

func _ready() -> void:
    platform_on_leave = PLATFORM_ON_LEAVE_DO_NOTHING

func _physics_process(delta: float) -> void:
    var on_floor := is_on_floor()               # from the last move_and_slide
    var input := Input.get_axis("ui_left", "ui_right")
    if on_floor:
        air_vx = get_platform_velocity().x      # zero on static ground
        velocity.x = input * RUN
    else:
        velocity.x = input * RUN + air_vx
    velocity.y += GRAVITY * delta
    if on_floor and Input.is_action_just_pressed("ui_accept"):
        velocity.y = -JUMP + get_platform_velocity().y
    move_and_slide()
    if not on_floor and is_on_wall():
        air_vx = 0.0
// Unity: CharacterController does not ride platforms by itself.
// Remember what is under the feet and add its movement each frame.
using UnityEngine;

[RequireComponent(typeof(CharacterController))]
public class PlatformRider : MonoBehaviour
{
    public float run = 4f, jump = 6f;      // metres per second
    CharacterController controller;
    Transform platform;                    // what we stood on last frame
    Vector3 platformLast;                  // where it was then
    Vector3 velocity;
    float airVx;

    void Awake() { controller = GetComponent<CharacterController>(); }

    void Update()
    {
        float dt = Time.deltaTime;
        if (dt <= 0f) return;
        bool grounded = controller.isGrounded;
        Vector3 platformVelocity = Vector3.zero;
        if (platform != null)
        {
            Vector3 step = platform.position - platformLast;
            controller.Move(step);                     // take the floor's step
            platformVelocity = step / dt;
        }
        if (grounded) airVx = platformVelocity.x;
        velocity.x = Input.GetAxis("Horizontal") * run + (grounded ? 0f : airVx);
        velocity.y += Physics.gravity.y * dt;
        if (grounded && Input.GetButtonDown("Jump"))
            velocity.y = jump + platformVelocity.y;
        controller.Move(velocity * dt);
        if (controller.isGrounded && velocity.y < 0f) velocity.y = -1f;

        platform = null;                           // what is under us now?
        if (controller.isGrounded && Physics.Raycast(transform.position,
                Vector3.down, out RaycastHit hit, controller.height * 0.5f + 0.1f))
        {
            platform = hit.transform;
            platformLast = platform.position;
        }
    }
}

In Godot, move_and_slide does rule 1, and platform_on_leave chooses rule 2: add the platform's velocity on leaving (the default), add only its upward part, or do nothing. The default adds it once, so code that sets velocity.x from input every frame wipes it out; the sketch keeps air_vx itself. In Unity, if platforms move in FixedUpdate, ride them there too.

Pitfalls

  • Riders before platforms. The rider runs one step behind its floor, sinking into rising lifts and floating above falling ones. Move all platforms first.
  • Wiping the inherited speed. vx = input * RUN in the air throws away the platform's speed on the very next step. Keep the inherited part in its own variable.
  • Carrying through walls. Adding dx straight to the position drags the rider into the wall at the end of the track. Carry with the same move functions you use for walking.
  • Crushing. A lift that pushes a rider into a ceiling has nowhere to put it. Decide: stop the lift, hurt the player, or let it pass through. The demo leaves room under every platform.
  • Parenting to the platform. Making the character a child of the platform's transform carries it for free, but a scaled platform scales its children too, and you still need rule 2.

Cost: one extra move per rider per step.

In real games

Godot 4's CharacterBody2D and CharacterBody3D follow a moving floor inside move_and_slide, report its speed with get_platform_velocity(), and offer the platform_on_leave choices above. AnimatableBody2D is the body type meant for platforms moved by code or animation. A StaticBody2D can set a constant_linear_velocity without moving, and touching bodies are carried as if it moved: a conveyor belt, which is rule 1 with a platform that only pretends to move.

Unity's CharacterController has no platform setting, so Unity projects add the platform's movement themselves or parent the character to the platform.

Your turn (15 minutes)

Add a platform that moves left and right and one that moves up and down. Store each one's dx, dy, vx and vy every step, with zeros for static blocks. Make the character remember the block it landed on, then add the carry and the inherited air speed.

You are done when the character can stand still on both platforms without drifting or flickering in and out of "grounded", and a standing jump from the sliding platform lands back on it.

Takeaways

  • Collision code never drags a character along, so a moving floor leaves without it.
  • Move platforms first, then move each rider by its platform's step, then do the rider's own move.
  • Give static blocks a step and velocity of zero, and the same code handles every floor.
  • Keep the platform's velocity, in its own variable, when leaving it.
  • Measure platform velocity from the step it took, so carrying and jumping always agree.
