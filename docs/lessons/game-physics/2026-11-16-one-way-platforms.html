One-way platforms

How to let a body jump up through a platform, land on it from above and drop through on demand, by checking where its feet were before the step.

You jump at a ledge from underneath. Either your head bumps into it, or you pass into it and, at the top of the jump, the game yanks you up onto it as if a hand grabbed you. Then you press down to hop off, and nothing happens.

All three bugs come from asking the wrong question. This lesson asks the right one, and it is one line of code.

A platform that only has a top

A one-way platform (also called a jump-through or pass-through platform) blocks a body from above but lets it pass from below and from the sides. Nothing in the real world behaves like this. It is a game rule, so the goal is not realism: the goal is a rule that feels fair and never surprises the player.

The easiest way to think about it: a one-way platform is not a box. It is a single line, its top, and only the body's feet, the bottom edge of its box, can collide with that line. In the code below y points down the screen, as in LÖVE, so a larger y is lower.

First try: make it solid

Give the platform an ordinary box collider. Landing works, but jumping from below hits the underside and stops. That is the head bump.

Second try: only collide while falling

Ignore the platform while the body moves up (vy < 0), and while it falls, push any overlap out through the top. Now the body passes up through. But if the jump peaks while the body is still inside the platform, the next step is a falling step with an overlap, and the push-out lifts the body to the top: about 20 pixels in one step with the demo's numbers. That is the pop.

The same rule also breaks dropping through. Move the body down into the platform and it is falling and overlapping, so it snaps straight back up.

The rule: where were the feet before this step?

Overlap tells you where the body is. You need to know whether it came from above, so remember the feet before you move and test three things.

box.vy >= 0

In words: the body is moving down or standing still. Rising bodies never land.

oldBottom <= top

In words: before this step the feet were on or above the top of the platform.

newBottom >= top

In words: after this step the feet are on or below the top. Together with the line before, the feet crossed the top during this step.

If all three hold and the body overlaps the platform on x, it lands: put the feet on the top and set vy to 0. In every other case the platform does nothing at all. It never pushes sideways and never pushes down.

Because the test is "did the feet cross the line during the step", not "do they overlap now", it also cannot tunnel: a fast fall that moves the feet 30 pixels past a 10 pixel thick platform still crossed its top.

One step by hand

The demo uses gravity 1800 px/s² and 60 steps per second. A box 24 pixels tall stands on platform B, whose top is at y = 175, so the box's y is 151 and vy is 0.

  1. Gravity: vy = 0 + 1800 × (1/60) = 30 px/s, downwards.
  2. oldBottom = 151 + 24 = 175. Move: y = 151 + 30 × (1/60) = 151.5, so newBottom = 175.5.
  3. 30 ≥ 0, 175 ≤ 175 and 175.5 ≥ 175: land. y goes back to 151 and vy to 0.

So standing on a one-way platform is simply landing on it again every step.

Dropping through

Now the drop-through is free. When the player presses down while standing on a one-way platform, move the body down by one pixel. The feet are at 176, below the top at 175, so on the next step oldBottom <= top is false and the platform ignores the body, which falls away under gravity. The same rule that stops the pop also makes the drop work.

Rule of thumb

Decide a one-way collision with where the body was, never with where it is. Overlap is the symptom; the previous position is the cause.

The code

The right-hand panel as a LÖVE program, in the demo's 400 by 300 world with the same platforms and numbers. landsOn is the whole rule; everything else is the usual fixed-step platformer loop.

local STEP = 1 / 60
local GRAVITY, RUN = 1800, 150               -- px/s² and px/s
local JUMP = math.sqrt(2 * GRAVITY * 90)     -- launch speed for a 90 px jump
local FLOOR = 280                            -- y of the solid ground; y points down
local platforms = {                          -- one-way: only the top counts
  { x = 30,  w = 120, top = 210 },           -- A
  { x = 230, w = 140, top = 175 },           -- B
  { x = 120, w = 160, top = 105 },           -- C
}
local box = { x = 40, y = FLOOR - 24, w = 16, h = 24, vy = 0, on = nil }
local accumulator = 0
local jumpPressed, dropPressed = false, false

function love.keypressed(key)
  if key == "space" or key == "up" then jumpPressed = true end
  if key == "down" then dropPressed = true end
end

-- Falling, feet were on or above the top, feet are now on or below it.
local function landsOn(p, oldBottom, newBottom)
  local overX = box.x < p.x + p.w and box.x + box.w > p.x
  return overX and box.vy >= 0 and oldBottom <= p.top and newBottom >= p.top
end

local function step(dt)
  local dir = 0
  if love.keyboard.isDown("left") then dir = dir - 1 end
  if love.keyboard.isDown("right") then dir = dir + 1 end
  -- one-way platforms never block sideways
  box.x = math.max(0, math.min(box.x + dir * RUN * dt, 400 - box.w))

  if jumpPressed and box.on then
    box.vy = -JUMP
  elseif dropPressed and box.on and box.on ~= "floor" then
    box.y = box.y + 1                        -- feet 1 px below the top: the rule lets go
  end
  jumpPressed, dropPressed = false, false

  box.vy = box.vy + GRAVITY * dt
  local oldBottom = box.y + box.h            -- remember the feet before moving
  box.y = box.y + box.vy * dt
  local newBottom = box.y + box.h

  local landing = nil                        -- highest platform crossed this step
  for _, p in ipairs(platforms) do
    if landsOn(p, oldBottom, newBottom) and (landing == nil or p.top < landing.top) then
      landing = p
    end
  end
  box.on = nil
  if landing then
    box.y, box.vy, box.on = landing.top - box.h, 0, landing
  elseif newBottom >= FLOOR then
    box.y, box.vy, box.on = FLOOR - box.h, 0, "floor"
  end
end

function love.update(dt)
  accumulator = accumulator + math.min(dt, 0.25)
  while accumulator >= STEP do
    step(STEP)
    accumulator = accumulator - STEP
  end
end

function love.draw()
  love.graphics.rectangle("fill", 0, FLOOR, 400, 300 - FLOOR)
  for _, p in ipairs(platforms) do
    love.graphics.rectangle("fill", p.x, p.top, p.w, 10)
  end
  love.graphics.rectangle("line", box.x, box.y, box.w, box.h)
end
# Platforms: StaticBody2D nodes on collision layer 2, each with a
# CollisionShape2D that has One Way Collision ticked. Godot applies the
# landing rule itself. Keep the solid ground on a different layer.
extends CharacterBody2D

const RUN := 150.0
const GRAVITY := 1800.0
var jump_speed := sqrt(2.0 * GRAVITY * 90.0)

func _physics_process(delta: float) -> void:
    velocity.x = Input.get_axis("ui_left", "ui_right") * RUN
    velocity.y += GRAVITY * delta
    if is_on_floor() and Input.is_action_just_pressed("ui_accept"):
        velocity.y = -jump_speed
    elif is_on_floor() and Input.is_action_just_pressed("ui_down"):
        drop_through()
    move_and_slide()

func drop_through() -> void:
    set_collision_mask_value(2, false)   # stop seeing every platform
    await get_tree().create_timer(0.25).timeout
    set_collision_mask_value(2, true)
// Platforms: a Collider2D with "Used By Effector" ticked, plus a
// PlatformEffector2D with "Use One Way" ticked. The effector applies
// the landing rule. This script adds dropping through.
using System.Collections;
using UnityEngine;

public class DropThrough : MonoBehaviour
{
    public Collider2D body;      // the player's own collider
    Collider2D platform;         // the one-way platform under the player

    void OnCollisionEnter2D(Collision2D hit)
    {
        if (hit.collider.GetComponent<PlatformEffector2D>() != null) platform = hit.collider;
    }

    void OnCollisionExit2D(Collision2D hit)
    {
        if (hit.collider == platform) platform = null;
    }

    void Update()
    {
        if (platform != null && Input.GetKeyDown(KeyCode.DownArrow))
            StartCoroutine(Drop(platform));
    }

    IEnumerator Drop(Collider2D p)
    {
        Physics2D.IgnoreCollision(body, p, true);    // only this platform
        yield return new WaitForSeconds(0.25f);
        Physics2D.IgnoreCollision(body, p, false);
    }
}

Both engines run the landing rule for you, so the engine code is about the drop. The Godot version switches off a whole layer for a quarter of a second, which has the timer problem from the pitfalls. The Unity version ignores only the platform the player stood on.

Pitfalls

  • Deciding with the current overlap. Any rule that looks only at where the body is now pops bodies onto platforms they never cleared, whatever direction check you add.
  • Testing the centre instead of the feet. Comparing the box's centre or top with the platform's top lets the box land with its legs inside the platform. Compare the bottom edge.
  • Drop-through by timer. Ignoring all platforms for a fixed time is easy, but a body falling from rest covers ½ × 1800 × 0.25² ≈ 56 pixels in a quarter of a second, so it also falls through a platform 40 pixels lower. Ignore only the platform the body stood on, or use the one-pixel nudge.
  • Rounding. The rule compares oldBottom <= top exactly, which is safe with whole-number positions. If snapping can leave the feet a hair below the top, a standing body falls through. Add a tolerance such as 0.01 pixels and keep the drop nudge larger. Some games use a few pixels on purpose, so a jump that nearly made it still lands: a feel decision, not physics.
  • Moving platforms. If the platform moves, compare the feet with where its top was before the step as well. A rising platform otherwise passes up over the feet and the body falls through it.

In real games

Godot has the rule built in: CollisionShape2D and CollisionPolygon2D have a one_way_collision property, plus a one_way_collision_margin that makes the shape count as thicker, which helps fast bodies. Unity has PlatformEffector2D: tick "Use One Way" on the effector and "Used By Effector" on the collider. Its surface arc sets how wide the blocking side is.

Many platformers use these platforms. Fans of Super Mario World call them semisolid platforms. In the Super Smash Bros. series, fighters can drop through the floating platforms by pressing down, and in Terraria the player can drop through placed platforms the same way.

Your turn (15 minutes)

Put a one-way platform in your project 100 pixels above the ground, with a jump that peaks about 85 pixels up. Jump straight up into it twenty times from different spots. Every jump must fall back to the ground: if the character ever ends up on top, you have the pop. Then stand on the platform, press down, and check that the character drops through it but still lands on a second platform 40 pixels lower. You are done when both checks pass.

Takeaways

  • A one-way platform is a line, its top, and only the body's feet test against it.
  • Land when the body is falling and the feet crossed the top this step: oldBottom <= top and newBottom >= top.
  • Checking only the direction of motion pops bodies onto platforms they never cleared and breaks dropping through.
  • Drop through by moving the feet one pixel below the top, or by ignoring only that one platform for a moment.
