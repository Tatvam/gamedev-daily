Tile collisions one axis at a time

Why a box snags on the seams between tiles when you resolve both axes at once, and how moving on x and then on y makes tile collisions reliable.

Your character falls beside a tall wall while you hold towards it, and halfway down it stops, hanging on a flat wall. Press jump and it jumps off the wall as if it were a floor, again and again, until it has climbed the whole level.

The wall is a stack of separate tiles, and the collision code found an edge between two of them that should not exist.

The bug: pushing out of a seam

A tile map is a grid of squares, each either empty or solid. Here a tile is 32 pixels wide. Every solid tile is its own box, so a tall wall is a stack of boxes. Where two solid tiles meet there is a seam: an edge buried inside the wall that nothing should ever touch.

A common first attempt moves the player on both axes, then pushes it out of every tile it overlaps, along the axis with the smaller overlap. That is the minimum translation vector from earlier lessons, applied one tile at a time:

box.x = box.x + box.vx * dt            -- move on both axes at once
box.y = box.y + box.vy * dt
for _, tile in ipairs(overlappingTiles(box)) do
  local ox, oy = overlapX(box, tile), overlapY(box, tile)
  if ox < oy then pushOutX(box, tile) else pushOutY(box, tile) end
end

In words: whichever way the box sticks in least, push it back that way. For one lone box this is right. For a wall of tiles it goes wrong at the seams.

One step by hand

The player is a 22 by 22 pixel box, and screen y grows downwards. Its right edge is against a wall face at x = 352. Its bottom edge is at 126, just above the seam at 128 between two wall tiles. This step it moves 3 pixels right (180 pixels per second at 60 steps per second) and 4 pixels down (falling at 240 pixels per second).

  1. After the move, the right edge is at 355 and the bottom at 130. The box overlaps both wall tiles.
  2. The lower tile: the box sticks into it 3 pixels on x but only 2 pixels on y (130 − 128). The y overlap is smaller, so the box is pushed up by 2, its fall speed is set to 0, and it counts as standing on the ground.
  3. The upper tile: 3 pixels on x, 22 on y. The box is pushed left by 3.

The box ends the step standing on the seam. Next step gravity gives it 30 pixels per second, it sinks half a pixel into the lower tile, half a pixel is less than 3, and it is pushed up again. It hangs there as long as you hold towards the wall.

The overlap test was right; the response picked a face that is buried. Looking at one tile at a time, it cannot know another tile sits on top.

The fix: one axis at a time

Split every step into two moves:

  1. Move on x only. If the box now overlaps a solid tile, push it back on x only, to the side it came from, and set vx to 0.
  2. Then move on y only. If it overlaps a solid tile, push it back on y only and set vy to 0. If it was moving down, it has landed.

Now there is no axis to choose wrongly. During the x move the box can only enter a tile through a side face, and the box was just on that side, so that face is never buried. The same holds for the y move.

Run the same numbers. Move x: the right edge goes to 355 while the box still spans 104 to 126 on y, so it overlaps only the upper tile. Push it back to 352. Move y: the bottom goes to 130, but the box now spans 330 to 352 on x, which is the empty column next to the wall. Nothing to hit. It keeps falling.

Correct physics, wrong game

For two separate boxes, the smallest overlap is the physically sensible push. A tile wall is one shape stored in pieces. Per-axis movement is not more realistic; it is a rule that only works on a grid, which is exactly why it suits tile games.

Changing the loop order is not a fix

The step by hand checked the bottom row of tiles first. Check the top row first and the fall above happens to work, but now a jump beside a wall stops dead when the top of the box reaches a seam, as if it had hit a ceiling. A different order moves the bug instead of removing it.

Try it

Switch to Hold right and jump and watch the left box climb the wall. Then change the run speed: a faster run gives a bigger x overlap, so more seams catch. To steer, use the arrow keys on a panel (up or space jumps), or hold a finger or the mouse where the box should go.

The code

The right-hand panel as a LÖVE program, with the demo's map and numbers. hitTile returns the first solid tile the box overlaps; touching a tile is not overlapping it, which is what the math.ceil(...) - 1 takes care of.

local TILE, STEP = 32, 1 / 60
local GRAVITY, JUMP, RUN, MAX_FALL = 1800, 600, 180, 900   -- px/s² and px/s
local MAP = {
  "############", "#..........#", "#..........#",
  "#..........#", "#....###...#", "#..........#",
  "#..........#", "#..........#", "############",
}
local box = { x = 300, y = 40, w = 22, h = 22, vx = 0, vy = 0, grounded = false }
local accumulator = 0

local function solid(col, row)          -- col and row start at 0
  local line = MAP[row + 1]
  return line ~= nil and line:sub(col + 1, col + 1) == "#"
end

local function hitTile()                -- first solid tile the box overlaps
  for row = math.floor(box.y / TILE), math.ceil((box.y + box.h) / TILE) - 1 do
    for col = math.floor(box.x / TILE), math.ceil((box.x + box.w) / TILE) - 1 do
      if solid(col, row) then return col, row end
    end
  end
  return nil
end

local function step(dt)
  local dir = 0
  if love.keyboard.isDown("left") then dir = dir - 1 end
  if love.keyboard.isDown("right") then dir = dir + 1 end
  box.vx = dir * RUN
  if love.keyboard.isDown("space") and box.grounded then box.vy = -JUMP end
  box.vy = math.min(box.vy + GRAVITY * dt, MAX_FALL)

  box.x = box.x + box.vx * dt            -- 1. move on x only
  local col = hitTile()
  if col then                            --    push out on x only
    if box.vx > 0 then box.x = col * TILE - box.w else box.x = (col + 1) * TILE end
    box.vx = 0
  end

  box.y = box.y + box.vy * dt            -- 2. then move on y only
  box.grounded = false
  local _, row = hitTile()
  if row then                            --    push out on y only
    if box.vy > 0 then
      box.y = row * TILE - box.h
      box.grounded = true
    else
      box.y = (row + 1) * TILE
    end
    box.vy = 0
  end
end

function love.update(dt)
  accumulator = accumulator + math.min(dt, 0.25)
  while accumulator >= STEP do
    step(STEP)
    accumulator = accumulator - STEP
  end
end

function love.draw()
  for row = 0, #MAP - 1 do
    for col = 0, #MAP[1] - 1 do
      if solid(col, row) then love.graphics.rectangle("fill", col * TILE, row * TILE, TILE, TILE) end
    end
  end
  love.graphics.rectangle("line", box.x, box.y, box.w, box.h)
end
# The same split with a CharacterBody2D: one move_and_collide call per axis.
extends CharacterBody2D

const RUN := 180.0
const JUMP := 600.0
const GRAVITY := 1800.0
var grounded := false

func _physics_process(delta: float) -> void:
    velocity.x = Input.get_axis("ui_left", "ui_right") * RUN
    if Input.is_action_pressed("ui_accept") and grounded:
        velocity.y = -JUMP
    velocity.y = minf(velocity.y + GRAVITY * delta, 900.0)

    if move_and_collide(Vector2(velocity.x * delta, 0.0)):   # 1. x only
        velocity.x = 0.0
    grounded = false
    var hit := move_and_collide(Vector2(0.0, velocity.y * delta))   # 2. y only
    if hit:
        grounded = hit.get_normal().y < 0.0
        velocity.y = 0.0

In Unity the usual route is different: a TilemapCollider2D combined with a CompositeCollider2D merges the tile shapes into one outline, so the seams are gone before any body touches them. The option that links the two has been renamed between Unity versions; look for "composite" on the tile map collider.

Pitfalls

  • Moving more than a tile per step. Each axis move must be smaller than a tile, or the box can skip a tile: tunnelling again. The demo caps the fall at 900 pixels per second, 15 pixels per step. For more speed, split the move into smaller pieces.
  • Counting touching as overlapping. A box on the floor has its bottom exactly on the tile top. If that counts as a hit, the x move pushes it sideways out of the floor. The ceil(...) - 1 keeps the test strict.
  • Pushing on the wrong side. Take the push direction from the velocity on that axis. A box that moved right came from the left, so it goes back to the tile's left face.
  • Forgetting to clear grounded. Clear it before the y move and set it only when the y move lands, or the player can jump in mid-air after walking off a ledge.
  • Corners depend on the order. Moving diagonally into an outer corner, x-first and y-first can disagree: one lands on the ledge, the other is stopped by its side. Pick one order and keep it.

In real games

Maddy Thorson's article on the physics of TowerFall and Celeste describes moving actors on x and on y separately, in whole pixels, stopping each axis on its own when it meets something solid. That is this lesson with a step of one pixel.

General physics engines meet the same seams as ghost collisions: a body sliding over a floor of separate boxes catches on the edges between them. Box2D offers chain shapes, which join a surface's segments so their inner corners cannot push. Unity's composite collider merges the tiles into one shape instead.

Build a wall five tiles tall in your tile map and let your character fall beside it while holding towards it, from several heights. If it ever stops mid-air, your code resolves both axes together.

Takeaways

  • A wall made of tiles has hidden seams between the tiles. Pushing a box out along the smallest overlap can push it out of a seam.
  • The symptom is a player that hangs on flat walls, can jump off them, and so climbs them.
  • Moving on x, resolving on x, then moving on y, resolving on y means a box can only meet faces it approached from open space.
  • Keep each axis move under one tile, and treat touching as not overlapping.
  • Changing the order of the tile loop moves the bug; it does not fix it.
