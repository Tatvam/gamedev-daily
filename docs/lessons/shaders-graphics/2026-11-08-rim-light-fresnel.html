Rim light and Fresnel: edges that glow

1 − N·V is near 0 where a surface faces you and near 1 at its edges. Raise it to a power for a rim light, or use Schlick's formula for Fresnel.

A dark character in a dark cave disappears into the background. A selected unit needs to stand out without a box drawn around it. A shield bubble should be almost clear in the middle but shine at its edges. One number fixes all three: how much the surface is turned away from the camera.

How much does this pixel face the eye?

A fragment shader is a small function that runs once per pixel and returns a colour. Rim lighting needs two inputs: the surface normal N, and V, the unit vector from the surface towards the eye. It ignores the light.

Both vectors have length 1, so their dot product N·V is the cosine of the angle between them. That gives the facing ratio:

  • In the middle of a ball, N points straight at you: N·V = 1.
  • Halfway out, the surface is tilted: N·V is somewhere between 0 and 1.
  • At the outline, the silhouette, the surface is side-on: N·V = 0.

Flip it with 1 − N·V and you have a mask that is 0 in the middle and 1 at the edges.

Shaping the rim with a power

On its own, 1 − N·V is a wide haze. As with shininess, a power squeezes it: only values near 1 survive. The exponent is the rim power. A small power gives a broad glow and a large one gives a thin line along the outline.

Four lines on top of the diffuse shader, each a stage in the demo:

ndotv  = clamp(N·V, 0, 1)                      -- 1. how much the pixel faces the eye
edge   = 1 - ndotv                             -- 2. flip it: 0 in the middle, 1 at the outline
rim    = pow(edge, power)                      -- 3. squeeze it into a thin band
colour = albedo * (diffuse + ambient)
       + rimColour * strength * rim            -- 4. add it on top

The rim is added and ignores L, so it glows even where the light cannot reach. It reads as a light behind the character, outlining it against the dark.

Fresnel: the physics behind the trick

Rim light is an artistic fake. It copies something real. Look straight down into a lake and you see the bottom; look across it and you see the sky reflected. Every smooth surface reflects more light as you view it at a lower angle. This is the Fresnel effect, named after the physicist Augustin-Jean Fresnel.

The exact Fresnel equations are expensive. Real-time shaders use Schlick's approximation, published by Christophe Schlick in 1994:

F = F0 + (1 - F0) * pow(1 - N·V, 5)

F0 is how much the surface reflects when you look at it head-on. It is about 0.02 for water and 0.04 for glass and most plastics, and between about 0.5 and 1 for metals. At the silhouette F reaches 1 for every material. So Schlick is a rim with the power fixed at 5 and a floor of F0. In a full shader F scales the reflected surroundings; the demo uses the rim colour instead.

Axes, the eye and colour space

The demo uses x right, y up, z out of the screen, with gl_FragCoord's (0, 0) at the bottom-left, and V = (0, 0, 1). LÖVE's screen_coords start at the top-left with y down, so the LÖVE code flips y. Godot's NORMAL and VIEW are in view space; the Unity example uses world space. Either works if both vectors share one space. The demo adds colours without gamma conversion; engines convert colour pickers from sRGB to linear first, so the same numbers look slightly different there.

Try it

Step through the Stage menu. On stage 4, slide Rim power and watch the band thin; the graph shows the same curve. Then drag the sun (or use the arrow keys) and set Light height below 0. The diffuse light goes; the rim stays.

Turn on Bumps: the rim appears inside the ball too, wherever a bump turns away from you. Rim light is about facing, not outlines. Finally, switch to Schlick and try F0 = 0.04 (glass), then 0.9 (metal).

The code

In LÖVE the shader is a string with the effect entry point, drawn over the whole window. The mouse moves the light. Hold up or down to raise or lower it. Press [ or ] to change the rim power, f to switch to Schlick Fresnel, and b for bumps.

local RADIUS = 0.38                  -- sphere radius, as a fraction of the window height
local rimColor = { 0.25, 0.75, 1.0 }
local rimPower = 3.0
local rimStrength = 1.0
local f0 = 0.04                      -- reflectance head-on, used by Schlick
local mode = 0                       -- 0 = rim light, 1 = Schlick Fresnel
local bumps = 0
local height = 1.0                   -- light height above the screen, in sphere radii
local shader

local pixelcode = [[
uniform vec2 u_resolution;
uniform vec3 u_light;
uniform vec3 u_rimColor;
uniform float u_rimPower;
uniform float u_rimStrength;
uniform float u_f0;
uniform float u_mode;
uniform float u_bumps;
const float RADIUS = 0.38;
const vec3 ALBEDO = vec3(0.8, 0.25, 0.2);
const float AMBIENT = 0.1;

vec4 effect(vec4 color, Image tex, vec2 texture_coords, vec2 screen_coords)
{
  vec2 p = (screen_coords - 0.5 * u_resolution) / u_resolution.y / RADIUS;
  p.y = -p.y;                                  // LÖVE's y grows downwards: make it grow up
  float aa = 1.5 / (u_resolution.y * RADIUS);
  float mask = 1.0 - smoothstep(1.0 - aa, 1.0, length(p));
  vec3 n = vec3(p, sqrt(max(1.0 - dot(p, p), 0.0)));
  vec2 tilt = vec2(cos(9.0 * p.x) * sin(9.0 * p.y), sin(9.0 * p.x) * cos(9.0 * p.y));
  n = normalize(n - u_bumps * 0.6 * vec3(tilt, 0.0));
  float diffuse = max(dot(n, u_light), 0.0);

  float ndotv = clamp(dot(n, vec3(0.0, 0.0, 1.0)), 0.0, 1.0);
  float edge = 1.0 - ndotv;
  float rim = pow(edge, u_rimPower);
  float schlick = u_f0 + (1.0 - u_f0) * pow(edge, 5.0);
  float amount = mix(rim, schlick, u_mode);

  vec3 col = ALBEDO * (diffuse + AMBIENT) + u_rimColor * u_rimStrength * amount;
  vec3 bg = vec3(0.1, 0.11, 0.14);
  return vec4(mix(bg, col, mask), 1.0) * color;
}
]]

local function normalize(x, y, z)
  local len = math.sqrt(x * x + y * y + z * z)
  if len < 1e-6 then return 0, 0, 1 end
  return x / len, y / len, z / len
end

function love.load()
  shader = love.graphics.newShader(pixelcode)
end

function love.keypressed(key)
  if key == "]" then rimPower = math.min(rimPower + 0.5, 8) end
  if key == "[" then rimPower = math.max(rimPower - 0.5, 0.5) end
  if key == "f" then mode = 1 - mode end
  if key == "b" then bumps = 1 - bumps end
end

function love.update(dt)
  if love.keyboard.isDown("up") then height = height + dt end
  if love.keyboard.isDown("down") then height = height - dt end
end

function love.draw()
  local w, h = love.graphics.getDimensions()
  local mx, my = love.mouse.getPosition()
  local lightX = (mx - 0.5 * w) / h / RADIUS
  local lightY = -(my - 0.5 * h) / h / RADIUS  -- flip: screen y goes down
  local lx, ly, lz = normalize(lightX, lightY, height)
  shader:send("u_light", { lx, ly, lz })
  shader:send("u_resolution", { love.graphics.getPixelDimensions() })
  shader:send("u_rimColor", rimColor)
  shader:send("u_rimPower", rimPower)
  shader:send("u_rimStrength", rimStrength)
  shader:send("u_f0", f0)
  shader:send("u_mode", mode)
  shader:send("u_bumps", bumps)
  love.graphics.setShader(shader)
  love.graphics.rectangle("fill", 0, 0, w, h)
  love.graphics.setShader()
  love.graphics.print("rim power " .. rimPower, 10, 10)
end
precision mediump float;

uniform vec2 u_resolution;
uniform vec3 u_light;        // unit vector from the surface towards the light
uniform vec2 u_lightPos;     // where the sun marker is drawn, device pixels, origin bottom-left
uniform vec3 u_rimColor;     // colour of the rim
uniform float u_rimPower;    // bigger means a thinner rim
uniform float u_rimStrength; // how bright the rim is at the outline
uniform float u_f0;          // Schlick: reflectance when the surface faces the eye
uniform float u_mode;        // 0 = rim light, 1 = Schlick Fresnel
uniform float u_stage;       // 0 normals ... 4 final colour
uniform float u_bumps;       // 1 = tilt the normals with a bump pattern

const float RADIUS = 0.38;               // sphere radius, as a fraction of the canvas height
const vec3 ALBEDO = vec3(0.8, 0.25, 0.2); // surface colour
const float AMBIENT = 0.1;
const vec3 V = vec3(0.0, 0.0, 1.0);      // towards the eye: the camera looks straight at the screen

void main() {
  // the sphere, its normal and its Lambert diffuse, as in the earlier lessons
  vec2 p = (gl_FragCoord.xy - 0.5 * u_resolution) / u_resolution.y / RADIUS;
  float aa = 1.5 / (u_resolution.y * RADIUS);
  float mask = 1.0 - smoothstep(1.0 - aa, 1.0, length(p));
  vec3 n = vec3(p, sqrt(max(1.0 - dot(p, p), 0.0)));
  vec2 tilt = vec2(cos(9.0 * p.x) * sin(9.0 * p.y), sin(9.0 * p.x) * cos(9.0 * p.y));
  n = normalize(n - u_bumps * 0.6 * vec3(tilt, 0.0));
  float diffuse = max(dot(n, u_light), 0.0);

  // 1. how much the pixel faces the eye
  float ndotv = clamp(dot(n, V), 0.0, 1.0);
  // 2. flip it: 0 in the middle, 1 at the outline
  float edge = 1.0 - ndotv;
  // 3. squeeze it with a power (rim light) or use Schlick's Fresnel
  float rim = pow(edge, u_rimPower);
  float schlick = u_f0 + (1.0 - u_f0) * pow(edge, 5.0);
  float amount = mix(rim, schlick, u_mode);
  // 4. add it on top of the diffuse colour
  vec3 col = ALBEDO * (diffuse + AMBIENT) + u_rimColor * u_rimStrength * amount;

  vec3 bg = vec3(0.1, 0.11, 0.14);
  if (u_stage < 3.5) col = vec3(amount);
  if (u_stage < 2.5) col = vec3(edge);
  if (u_stage < 1.5) col = vec3(ndotv);
  if (u_stage < 0.5) col = n * 0.5 + 0.5;
  col = mix(bg, col, mask);

  // the sun marker: filled when the light is in front, hollow when it is behind
  float lw = max(1.0, u_resolution.y / 300.0);
  float front = step(0.0, u_light.z);
  float d = length(gl_FragCoord.xy - u_lightPos);
  vec3 sun = vec3(1.0, 0.82, 0.25);
  col = mix(col, vec3(0.0), 1.0 - smoothstep(lw, 2.0 * lw, abs(d - 8.5 * lw)));
  col = mix(col, sun, 1.0 - smoothstep(0.7 * lw, 1.5 * lw, abs(d - 6.5 * lw)));
  col = mix(col, sun, front * (1.0 - smoothstep(4.5 * lw, 5.5 * lw, d)));
  gl_FragColor = vec4(col, 1.0);
}
// Godot 4, a ShaderMaterial on a MeshInstance3D (try a SphereMesh). Lit by the scene's lights.
shader_type spatial;

uniform vec3 albedo : source_color = vec3(0.8, 0.25, 0.2);
uniform vec3 rim_color : source_color = vec3(0.25, 0.75, 1.0);
uniform float rim_power : hint_range(0.5, 8.0) = 3.0;
uniform float rim_strength : hint_range(0.0, 2.0) = 1.0;

void fragment() {
    ALBEDO = albedo;
    // NORMAL and VIEW are both in view space; VIEW points from the surface to the camera
    float ndotv = clamp(dot(normalize(NORMAL), VIEW), 0.0, 1.0);
    EMISSION = rim_color * rim_strength * pow(1.0 - ndotv, rim_power);
}
// Built-in render pipeline, on any mesh with smooth normals. Uses the main directional light.
Shader "GameDevDaily/RimLight"
{
    Properties
    {
        _Albedo ("Albedo", Color) = (0.8, 0.25, 0.2, 1)
        _RimColor ("Rim colour", Color) = (0.25, 0.75, 1, 1)
        _RimPower ("Rim power", Range(0.5, 8)) = 3
        _RimStrength ("Rim strength", Range(0, 2)) = 1
    }
    SubShader
    {
        Tags { "RenderType" = "Opaque" }
        Pass
        {
            Tags { "LightMode" = "ForwardBase" }
            CGPROGRAM
            #pragma vertex vert
            #pragma fragment frag
            #include "UnityCG.cginc"

            fixed4 _Albedo;
            fixed4 _RimColor;
            float _RimPower;
            float _RimStrength;

            struct v2f
            {
                float4 pos : SV_POSITION;
                float3 worldNormal : TEXCOORD0;
                float3 worldPos : TEXCOORD1;
            };

            v2f vert (appdata_base v)
            {
                v2f o;
                o.pos = UnityObjectToClipPos(v.vertex);
                o.worldNormal = UnityObjectToWorldNormal(v.normal);
                o.worldPos = mul(unity_ObjectToWorld, v.vertex).xyz;
                return o;
            }

            fixed4 frag (v2f i) : SV_Target
            {
                float3 n = normalize(i.worldNormal);                     // re-normalise after interpolation
                float3 v = normalize(_WorldSpaceCameraPos - i.worldPos); // towards the camera, per pixel
                float diffuse = max(dot(n, normalize(_WorldSpaceLightPos0.xyz)), 0.0);
                float rim = pow(1.0 - saturate(dot(n, v)), _RimPower);
                float3 col = _Albedo.rgb * (diffuse + 0.1) + _RimColor.rgb * _RimStrength * rim;
                return fixed4(col, 1.0);
            }
            ENDCG
        }
    }
}

Godot's EMISSION is added on top of the engine's lighting, the same job as the + in the demo. In URP Shader Graph, multiply a Fresnel Effect node (its Power input is the rim power) by a colour and plug it into Emission.

Pitfalls

  • Using the camera's forward vector as V. With a perspective camera the direction to the eye differs per pixel. One forward vector makes the rim lopsided on objects away from the screen centre. Compute V per pixel, as the Unity tab does.
  • Forgetting to re-normalise N. Interpolated normals are shorter than 1 inside a triangle, so the rim shows the mesh's triangles. Normalise in the fragment shader.
  • Flat faces. A cube face has one normal, so the whole face gets one rim value and pops on and off as it turns. A rim needs smooth normals.
  • N and V in different spaces. A world-space N with a view-space V gives nonsense. Pick one space.
  • pow of a negative number. Rounding can push N·V a hair above 1, which makes 1 − N·V negative, and back faces give N·V below 0. Clamp N·V to 0 to 1 first; GLSL leaves pow(x, y) undefined for x < 0.

What it costs

One dot product, one subtraction and one pow. That is among the cheapest effects in this course and fine on any phone. With a fixed power of 5, as in Schlick, you can drop the pow for three multiplies: e2 = e * e; e5 = e2 * e2 * e. For a transparent shield the cost is the blending, not the rim: a big bubble shades every pixel it covers on top of what is behind it.

In real games

Rim light is a common way to pick out characters and selected objects against dark backgrounds, and to make shields shine at their edges. Godot's StandardMaterial3D has a Rim setting built in. Unity's manual uses rim lighting as an example surface shader, and Shader Graph has the Fresnel Effect node. Physically based materials, such as Unity's Standard shader and Godot's StandardMaterial3D, apply a Fresnel term to reflections for you, so water and polished floors reflect more as you look across them.

Your turn (15 minutes)

Start from the LÖVE program.

  1. Make a shield: change the last lines so that the ball is transparent except for the rim. Return the rim colour with alpha amount * mask, and draw something behind it first.
  2. Make the rim pulse: send love.timer.getTime() as a uniform and multiply the strength by 0.75 + 0.25 * sin(3.0 * u_time).
  3. Make the rim appear only on the lit side by multiplying it by smoothstep(-0.2, 0.4, dot(n, u_light)).

You are done when the shield is see-through in the middle, glows at its edge, pulses, and its glow follows the mouse.

Takeaways

  • N·V says how much a pixel faces the eye: 1 head-on, 0 side-on. 1 − N·V is a mask that is bright at the edges.
  • pow(1 − N·V, power) is a rim light. A bigger power gives a thinner rim.
  • The rim ignores the light direction, so it outlines objects even on their dark side.
  • Schlick's Fresnel, F0 + (1 − F0) × pow(1 − N·V, 5), is the physical version: every smooth surface reflects more at grazing angles.
  • V must point to the camera from each pixel, and N and V must be unit vectors in the same space.
