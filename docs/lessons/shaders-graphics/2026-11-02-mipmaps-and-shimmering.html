Mipmaps: why distant textures shimmer

A pixel that covers many texels can only sample a few. Mipmaps store pre-shrunk copies so each pixel reads the level that matches its size.

Walk across a tiled floor in a 3D game with mipmaps switched off and the distant tiles crawl: curved bands sweep across them and single pixels flicker between light and dark every frame. Zoom a 2D camera out over a detailed tilemap and the same sparkle appears. Nothing is wrong with the texture. Each pixel now covers far more texels than it reads.

One pixel, many texels

A fragment shader is a small function that runs once per pixel and returns a colour. When it samples a texture it gets the colour at one point. The last lesson covered magnification, where one texel covers many pixels. This one covers the opposite, minification: the texture is drawn smaller than it is, so one pixel covers many texels.

The patch of texture that one pixel covers is its footprint. On a floor seen at an angle, footprints near the camera are a fraction of a texel. Near the horizon a single footprint can cover the whole texture.

Linear filtering still reads only the four texels around the sample point. If a footprint covers 10 by 10 texels, 96 of them are ignored, and which four get read depends on exactly where the point lands. Move the camera slightly and it lands elsewhere: light one frame, dark the next. That is aliasing: detail finer than the pixel grid turning into false patterns and flicker.

Shrink the texture ahead of time

The right colour for that pixel is the average of every texel in its footprint. Averaging 100 texels for every pixel, every frame, is far too slow. A mipmap does the averaging once, when the texture is loaded, and keeps the results.

The original texture is level 0. Level 1 is half as wide and half as tall, and each of its texels is the average of a 2 by 2 block of level 0. Level 2 halves level 1, and so on down to a single texel holding the average colour of the whole texture. The whole set is the mip chain. The name comes from the Latin multum in parvo, "much in a small space", and from Lance Williams's 1983 paper that introduced the idea.

Which level a pixel reads

The GPU measures how far the texture coordinate moves from one pixel to the next. It works in texel units, t = uv * size. GPUs shade pixels in 2 by 2 blocks, so the neighbour to the right and the neighbour above are always at hand; the shader functions dFdx and dFdy expose those differences. The longer of the two steps is called ρ (rho): roughly, texels per pixel.

The level to read is the one where a texel is about one pixel wide again. Each level doubles the texel width, so that level is λ = log2(ρ) (lambda). At ρ = 4, λ = 2, and level 2 texels are 4 level-0 texels wide. When ρ is 1 or less the texture is magnified, and level 0 is used with the magnification filter.

local function mipLevel(dxu, dxv, dyu, dyv, size, bias)   -- uv change per pixel
  local rho = math.max(math.sqrt(dxu^2 + dxv^2), math.sqrt(dyu^2 + dyv^2)) * size
  local lambda = math.log(rho) / math.log(2) + bias
  return math.min(math.max(lambda, 0), math.log(size) / math.log(2))
end

Between two levels

λ is rarely a whole number. Rounding it and reading one level is cheap, but the floor shows a visible seam wherever the level jumps. Trilinear filtering reads the two levels on either side with linear filtering, eight texels in all, and blends them by the fraction of λ. OpenGL calls the two options LINEAR_MIPMAP_NEAREST and LINEAR_MIPMAP_LINEAR.

A bias is a number added to λ before the level is chosen. A positive bias reads smaller levels sooner and looks blurrier; a negative bias reads bigger levels and lets the shimmer back in.

Up, down and colour

The demo puts (0, 0) at the bottom-left with y up, like WebGL's gl_FragCoord. LÖVE's screen_coords start at the top-left with y down, and so do Godot's UVs. The level does not care: it uses the lengths of the steps, which are the same either way. The demo averages the stored numbers directly; for sRGB textures a good mip generator converts to linear light first, or mixed light and dark areas come out too dark.

Try it

The floor texture is a 32 by 32 checker with a faint one-texel grain, generated in the shader. Every mip level is worked out exactly, as the average of the level-0 texels it covers. Start with Filter on Linear, no mipmaps and watch the far half of the floor: bands and flicker. Turn on Big pixels to see each sample on its own.

Then walk the Stage menu. Stage 2 shows λ: black is magnified, the cyan line is exactly one texel per pixel, white is 32 texels per pixel. Stage 3 colours each pixel by the level it reads. Switch between nearest level and blend two levels and compare the hard and soft borders. Drag on the floor, or use the arrow keys, to move the probe. Last, drag Bias both ways.

The code

In LÖVE you ask for mipmaps when you create the image, love.graphics.newImage(data, { mipmaps = true }), and the GPU builds and picks the levels itself. This program draws the same floor, with the same texture and numbers as the demo, using a shader with LÖVE's effect entry point. M toggles mipmaps, up and down change the bias.

local SIZE = 32          -- the texture is 32 by 32 texels
local REPEAT = 2         -- texture repeats per metre, as in the shader
local SPEED = 0.5        -- camera speed, metres per second
local bias, useMips, offset = 0, true, 0
local imgPlain, imgMips, shader

local pixelcode = [[
uniform vec2 u_size;      // window size in pixels
uniform float u_offset;   // how far the camera has moved, in texture repeats
const float REPEAT = 2.0;
const float HEIGHT = 0.5; // camera height above the floor

vec4 effect(vec4 color, Image tex, vec2 texture_coords, vec2 screen_coords)
{
  // LÖVE puts (0, 0) at the top-left, so y grows downwards
  float horizon = 0.2 * u_size.y;
  float focal = 0.9 * u_size.y;
  float below = max(screen_coords.y - horizon, 0.5);
  float z = HEIGHT * focal / below;
  float x = (screen_coords.x - 0.5 * u_size.x) * z / focal;
  vec2 uv = vec2(x, z) * REPEAT + vec2(0.0, u_offset);
  vec4 floorColour = Texel(tex, uv);       // the GPU picks the mip level
  vec4 sky = vec4(0.6, 0.74, 0.9, 1.0);
  return mix(floorColour, sky, step(screen_coords.y, horizon)) * color;
}
]]

local function mix(a, b, t) return a + (b - a) * t end

-- Big 8-texel checker plus a faint 1-texel grain, 0 to 1.
local function texel(i, j)
  local big = (math.floor(i / 8) + math.floor(j / 8)) % 2 == 0 and 1 or -1
  local grain = (i + j) % 2 == 0 and 1 or -1
  return 0.5 + 0.35 * big + 0.15 * grain
end

function love.load()
  local data = love.image.newImageData(SIZE, SIZE)
  for j = 0, SIZE - 1 do
    for i = 0, SIZE - 1 do
      local v = texel(i, j)
      data:setPixel(i, j, mix(0.16, 0.88, v), mix(0.18, 0.82, v), mix(0.28, 0.7, v), 1)
    end
  end
  imgPlain = love.graphics.newImage(data)                       -- level 0 only
  imgMips = love.graphics.newImage(data, { mipmaps = true })    -- levels 0 to 5
  imgMips:setMipmapFilter("linear")                             -- blend two levels
  for _, img in ipairs({ imgPlain, imgMips }) do
    img:setFilter("linear", "linear")
    img:setWrap("repeat", "repeat")
  end
  shader = love.graphics.newShader(pixelcode)
end

function love.keypressed(key)
  if key == "m" then useMips = not useMips end
  if key == "up" then bias = bias + 0.5 end
  if key == "down" then bias = bias - 0.5 end
  -- LÖVE calls it sharpness: positive means more detail, so it is minus the bias
  imgMips:setMipmapFilter("linear", -bias)
end

function love.update(dt)
  offset = (offset + SPEED * REPEAT * dt) % 1
end

function love.draw()
  local w, h = love.graphics.getDimensions()
  shader:send("u_size", { love.graphics.getPixelDimensions() })
  shader:send("u_offset", offset)
  love.graphics.setShader(shader)
  love.graphics.draw(useMips and imgMips or imgPlain, 0, 0, 0, w / SIZE, h / SIZE)
  love.graphics.setShader()
  love.graphics.print("mipmaps: " .. tostring(useMips) .. "   bias: " .. bias, 10, 10)
end
#ifdef GL_FRAGMENT_PRECISION_HIGH
precision highp float;
#else
precision mediump float;
#endif

uniform vec2 u_resolution;
uniform float u_offset;   // how far the camera has moved, in texture repeats
uniform float u_mode;     // 0 no mipmaps, 1 nearest level, 2 blend two levels
uniform float u_bias;     // added to the level
uniform float u_stage;    // 0 floor uv ... 3 final colour
uniform float u_pix;      // size of one shown pixel, in device pixels
uniform vec2 u_probe;     // probe position in device pixels, origin bottom-left

const float SIZE = 32.0;      // the texture is 32 by 32 texels
const float MAX_LEVEL = 5.0;  // levels are 32, 16, 8, 4, 2 and 1 texels wide
const float REPEAT = 2.0;     // texture repeats per metre of floor
const float HEIGHT = 0.5;     // camera height above the floor, metres

// The floor uv seen through the pixel at px. Origin bottom-left, y up.
vec2 floorUV(vec2 px) {
  float horizon = 0.8 * u_resolution.y;
  float focal = 0.9 * u_resolution.y;
  float below = max(horizon - px.y, 0.5);             // pixels below the horizon
  float z = HEIGHT * focal / below;                   // distance along the floor
  float x = (px.x - 0.5 * u_resolution.x) * z / focal;
  return vec2(x, z) * REPEAT + vec2(0.0, u_offset);
}

// A checker of +1 and -1 with squares s texels wide, averaged over blocks b texels wide.
// A block wider than a square holds as much +1 as -1, so its average is 0.
float checker(vec2 k, float b, float s) {
  vec2 c = 1.0 - 2.0 * mod(floor(k * b / s), 2.0);
  return c.x * c.y * step(b, s);
}

// Texel k of the level whose texels are b level-0 texels wide: the average of that block.
float mipTexel(vec2 k, float b) {
  k = mod(k, SIZE / b);                                // repeat wrap
  return 0.5 + 0.35 * checker(k, b, 8.0) + 0.15 * checker(k, b, 1.0);
}

// Linear (bilinear) sample of one level, as in the filtering lesson.
float sampleLevel(vec2 uv, float level) {
  float b = floor(exp2(level) + 0.5);                 // 1, 2, 4, 8, 16 or 32
  vec2 p = fract(uv) * SIZE / b - 0.5;                // texel space of this level
  vec2 i0 = floor(p);
  vec2 f = p - i0;
  float v0 = mix(mipTexel(i0, b), mipTexel(i0 + vec2(1.0, 0.0), b), f.x);
  float v1 = mix(mipTexel(i0 + vec2(0.0, 1.0), b), mipTexel(i0 + vec2(1.0, 1.0), b), f.x);
  return mix(v0, v1, f.y);
}

vec3 levelColour(float level) {
  vec3 c = vec3(0.25, 0.45, 1.0);                         // 0 blue
  c = mix(c, vec3(0.2, 0.8, 0.35), step(0.5, level));     // 1 green
  c = mix(c, vec3(0.95, 0.85, 0.2), step(1.5, level));    // 2 yellow
  c = mix(c, vec3(1.0, 0.5, 0.15), step(2.5, level));     // 3 orange
  c = mix(c, vec3(0.9, 0.2, 0.25), step(3.5, level));     // 4 red
  c = mix(c, vec3(0.65, 0.3, 0.9), step(4.5, level));     // 5 purple
  return c;
}

void main() {
  vec2 px = (floor(gl_FragCoord.xy / u_pix) + 0.5) * u_pix;   // centre of the shown pixel
  vec2 uv = floorUV(px);
  vec2 dx = floorUV(px + vec2(u_pix, 0.0)) - uv;      // uv step to the next pixel across
  vec2 dy = uv - floorUV(px - vec2(0.0, u_pix));      // uv step to the next pixel up

  float rho = max(length(dx), length(dy)) * SIZE;     // texels per pixel
  float lambda = log2(rho);                           // the level where that is one texel
  float lod = clamp(lambda + u_bias, 0.0, MAX_LEVEL);
  float level0 = floor(lod);
  float level1 = min(level0 + 1.0, MAX_LEVEL);
  float t = lod - level0;                             // how far towards the next level
  if (u_mode < 1.5) { level0 = floor(lod + 0.5); level1 = level0; t = 0.0; }  // nearest level
  if (u_mode < 0.5) { level0 = 0.0; level1 = 0.0; t = 0.0; }                  // no mipmaps

  float v = mix(sampleLevel(uv, level0), sampleLevel(uv, level1), t);
  vec3 col = mix(vec3(0.16, 0.18, 0.28), vec3(0.88, 0.82, 0.7), v);

  if (u_stage < 2.5) col = mix(mix(levelColour(level0), levelColour(level1), t), col, 0.3);
  if (u_stage < 1.5) {
    col = vec3(clamp(lambda / MAX_LEVEL, 0.0, 1.0));  // black: magnified, white: 32 texels
    col = mix(col, vec3(0.3, 0.9, 1.0), 1.0 - smoothstep(0.02, 0.05, abs(lambda)));
  }
  if (u_stage < 0.5) col = vec3(fract(uv), 0.0);

  float horizon = 0.8 * u_resolution.y;
  float h = clamp((px.y - horizon) / (u_resolution.y - horizon), 0.0, 1.0);
  vec3 sky = mix(vec3(0.6, 0.74, 0.9), vec3(0.3, 0.45, 0.75), h);
  col = mix(col, sky, step(horizon, px.y));

  float lw = max(1.0, u_resolution.y / 300.0);         // line width, device pixels
  float d = abs(length(gl_FragCoord.xy - u_probe) - 7.0 * lw);
  col = mix(col, vec3(0.0), 1.0 - smoothstep(lw, 2.0 * lw, d));
  col = mix(col, vec3(1.0), 1.0 - smoothstep(0.3 * lw, lw, d));
  gl_FragColor = vec4(col, 1.0);
}
// Godot 4, a ShaderMaterial on a large PlaneMesh. In the Import dock,
// turn on Mipmaps > Generate for the texture and reimport it.
shader_type spatial;
render_mode unshaded;

uniform sampler2D floor_tex : source_color, filter_linear_mipmap, repeat_enable;
uniform float tiles = 20.0;        // texture repeats across the plane
uniform float bias = 0.0;          // added to the level
uniform bool show_level = false;   // show lambda as grey, like stage 2

void fragment() {
    vec2 uv = UV * tiles;            // UV (0, 0) is the top-left in Godot
    vec2 t = uv * vec2(textureSize(floor_tex, 0));     // texel units
    float rho = max(length(dFdx(t)), length(dFdy(t))); // texels per pixel
    float lambda = log2(rho) + bias;
    vec3 col = texture(floor_tex, uv, bias).rgb;       // the third argument is the bias
    if (show_level) {
        col = vec3(clamp(lambda / 5.0, 0.0, 1.0));
    }
    ALBEDO = col;
}
// Built-in render pipeline, unlit, on a large plane. In the texture's
// import settings keep Generate Mip Maps on and set Filter Mode to Trilinear.
Shader "GameDevDaily/MipFloor"
{
    Properties
    {
        _MainTex ("Texture", 2D) = "white" {}
        _Tiles ("Repeats", Float) = 20
        _Bias ("Mip bias", Float) = 0
        _ShowLevel ("Show level (0 or 1)", Range(0, 1)) = 0
    }
    SubShader
    {
        Tags { "RenderType" = "Opaque" }
        Pass
        {
            CGPROGRAM
            #pragma vertex vert_img
            #pragma fragment frag
            #include "UnityCG.cginc"

            sampler2D _MainTex;
            float4 _MainTex_TexelSize;   // (1 / width, 1 / height, width, height)
            float _Tiles, _Bias, _ShowLevel;

            fixed4 frag (v2f_img i) : SV_Target
            {
                float2 uv = i.uv * _Tiles;              // (0, 0) is the bottom-left
                float2 t = uv * _MainTex_TexelSize.zw;  // texel units
                float rho = max(length(ddx(t)), length(ddy(t)));
                float lambda = log2(rho) + _Bias;
                fixed4 col = tex2Dbias(_MainTex, float4(uv, 0, _Bias));   // bias in w
                if (_ShowLevel > 0.5)
                {
                    float g = saturate(lambda / 5.0);
                    col = fixed4(g, g, g, 1);
                }
                return col;
            }
            ENDCG
        }
    }
}

In URP or Shader Graph the same import settings apply. The Sample Texture 2D LOD node reads one chosen level, which is useful for testing. Without the bias, a plain texture or tex2D call already does everything the demo does by hand.

Pitfalls

  • A blurry floor in the distance. ρ takes the longer of the two steps. On a floor seen at a low angle, the step up the screen is much longer than the step across, so the level suits the long direction and the short one gets blurred. Anisotropic filtering takes several samples along the long direction instead. It is a texture setting in every engine.
  • Sprites bleeding into each other in an atlas. At level 3, each texel averages an 8 by 8 block, which can straddle two sprites. Leave padding between sprites of at least 2 to the power of the deepest level you expect, or limit the number of levels.
  • Leaves and fences that vanish in the distance. Cut-out textures use an alpha test. Averaging shrinks thin opaque parts into half-transparent texels, which then fail the test. Engines offer fixes, such as Unity's Mip Maps Preserve Coverage import option.
  • Sampling inside an if. The level comes from neighbouring pixels in the 2 by 2 block. If those neighbours took a different branch, the difference is meaningless. Compute the UV and sample outside the branch, as the LÖVE shader does for the sky.
  • WebGL 1 and odd sizes. WebGL 1 can only build mipmaps for textures whose width and height are powers of two.

What it costs

The mip chain adds a third to the memory of each texture. Reading is usually faster with mipmaps, not slower: neighbouring pixels read neighbouring texels of a small level, which stay in the texture cache, while without mipmaps they jump all over a big texture. Trilinear reads two levels, and on many GPUs, phones especially, it can take longer than bilinear; nearest level is the cheap option on weak hardware. Anisotropic filtering costs the most, so on phones keep it low and use it on floors and roads, where it shows.

In real games

Nearly every 3D game mipmaps its surface textures. Minecraft exposes a Mipmap Levels slider in its video settings, so players can see the trade-off between distant blocks that shimmer and distant blocks that blur.

Engines also use the chain to save memory: Unity's mipmap streaming and Unreal's texture streaming keep only the levels the camera currently needs. Temporal upscalers, which render at a lower resolution and rebuild a sharper image, generally recommend a negative mip bias so textures keep their detail at the final resolution.

Your turn (15 minutes)

Use the LÖVE program to see the levels it picks.

  1. Run it and press M a few times while the floor moves. Find the distance where the shimmer starts.
  2. Copy the floor maths from the shader into a Lua function floorUV(x, y) that returns u and v for a screen pixel. Call it for the pixel under the mouse, one pixel to the right and one pixel down, and pass the differences to mipLevel from the explanation above. Print the result.
  3. Move the mouse from the bottom of the window to the horizon and note where λ passes 1, 2 and 3. Then press up and down and see how the bias shifts those places.

You are done when you can predict, before pressing the key, whether a bias of +1 moves the point where level 2 starts closer to the camera or further away.

Takeaways

  • When a texture is drawn small, one pixel covers many texels but reads only a few, so it shimmers.
  • A mipmap stores copies at half, quarter and smaller sizes, each texel the average of 2 by 2 from the level above. Cost: a third more memory.
  • The level is λ = log2(ρ), where ρ is the texels covered by one pixel step, measured from neighbouring pixels.
  • Trilinear filtering blends the two nearest levels so there is no seam; bias shifts the choice towards sharp or smooth.
  • Distant blur at grazing angles is the job of anisotropic filtering, not of a negative bias.
