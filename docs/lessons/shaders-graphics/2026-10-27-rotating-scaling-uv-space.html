Rotating and scaling UV space: spin and zoom around a pivot

Move the pivot to zero, turn the coordinates back by the angle, divide by the zoom, move back: four lines spin and zoom any pattern around any point.

A magic circle that turns slowly under the player. A radar screen that zooms in on a blip. A portal whose swirl spins around its own centre, not around the corner of the screen. None of these move any geometry. The quad stays still and the shader turns and stretches the coordinates it reads the pattern with.

Transform the question, not the answer

A fragment shader is a small function that runs once per pixel and returns a colour. For a pattern shader the input is the pixel's UV and the output is pattern(uv). Last lesson showed that a pixel cannot move; it can only change which point of the pattern it asks about. Scrolling changed that point with a subtraction. Rotating and zooming change it with a little more maths.

The point the pixel finally asks about is the sample point, written q here. Everything in this lesson is a recipe for turning uv into q.

Rotation turns around (0, 0)

Rotating a 2D point by an angle a counter-clockwise uses one cosine and one sine:

vec2 rotate(vec2 p, float a) {
  float c = cos(a);
  float s = sin(a);
  return vec2(c * p.x - s * p.y, s * p.x + c * p.y);
}

That formula always turns around the origin, the point (0, 0). In this series the UV is centred, so (0, 0) is the middle of the picture, with y pointing up. GLSL can write the same thing as a matrix, mat2(c, s, -s, c) * p. Matrices in GLSL are filled column by column, so the first two numbers are the first column; reading them as a row turns the pattern the wrong way.

Why the angle has a minus sign

Suppose you want the pattern to appear turned 30 degrees counter-clockwise. A feature that used to sit at pattern point P should now show up at rotate(P, a). The pixel at that new spot must therefore ask for P, which means each pixel undoes the turn: q = rotate(uv, -a).

Zoom works the same way backwards. To make the pattern look twice as big, each pixel must ask about a point half as far out, so you divide by the zoom. Multiplying the UV by 2 does the opposite: it fits twice as many repeats into the same space, and the pattern looks smaller.

Turning around a pivot

A pivot is the point the pattern should spin and zoom around: the centre of the magic circle, the blip on the radar. Since rotate and division only work around (0, 0), you move the pivot there first, transform, then move it back:

vec2 p = uv - u_pivot;      // 1. the pivot is now at (0, 0)
p = rotate(p, -u_angle);    // 2. turn the coordinates back
p = p / u_zoom;             // 3. divide to zoom in
vec2 q = p + u_pivot;       // 4. put the pivot back
vec3 col = tiles(q);

Check it with the pixel that sits exactly on the pivot. Step 1 gives (0, 0). Turning and dividing (0, 0) leaves it at (0, 0). Step 4 gives back the pivot. So that pixel always reads the same pattern point, whatever the angle and zoom: the pivot never moves, and everything else turns and grows around it.

Rule of thumb

To do something to the pattern, do the opposite to the coordinates: turn them by -a, divide by the zoom, subtract the offset. And do it around the pivot, never around a corner by accident.

Try it

Each tile has an orange hand pointing along its +x axis, so you can see which way the pattern is turned. Drag Angle and Zoom, then drag on the picture (or use the Pivot sliders) to move the white ring. Notice that the tile under the ring never moves.

Now switch on Ignore the pivot: the pattern swings around the middle of the picture and slides out from under the ring. Then walk the Stage menu from 1 to 6. Each stage shows the coordinates after one line of the recipe as red and green gradient squares, fract(p * 4.0), one square per tile.

The code

The Lua version runs the demo's shader in LÖVE, whose pixel shaders use the entry point effect instead of main. Click to set the pivot. Left and right turn by 15 degrees, up and down zoom, space toggles the spin, P toggles Ignore the pivot and S cycles the stage.

-- The demo's starting values. Centred uv: (0, 0) in the middle, y up.
local angle = 30            -- degrees, counter-clockwise
local zoom = 1.5            -- above 1 zooms in
local pivot = { 0.2, 0.1 }  -- in uv units
local usePivot = 1          -- 0 turns around the centre instead
local spin = false          -- when on, the angle grows 45 degrees per second
local stage = 5             -- 0 uv, 1 minus pivot, 2 turned, 3 zoomed, 4 q, 5 final
local rect = { 20, 20, 640, 360 }   -- x, y, width, height in pixels
local shader

local pixelcode = [[
uniform float u_angle;      // radians, counter-clockwise
uniform float u_zoom;       // above 1 zooms in
uniform vec2 u_pivot;       // centred uv units
uniform float u_usepivot;   // 1.0 uses the pivot, 0.0 turns around the centre
uniform float u_stage;
uniform vec4 u_rect;

vec2 rotate(vec2 p, float a) {             // turns p counter-clockwise by a
    float c = cos(a);
    float s = sin(a);
    return vec2(c * p.x - s * p.y, s * p.x + c * p.y);
}

vec3 tiles(vec2 q, float w) {              // w is one pixel, in cell units
    vec2 g = q * 4.0;                      // 4 tiles per uv unit
    vec2 id = floor(g);
    vec2 f = fract(g);
    float checker = mod(id.x + id.y, 2.0);
    vec3 col = mix(vec3(0.15, 0.2, 0.36), vec3(0.24, 0.33, 0.56), checker);
    vec2 e = min(f, 1.0 - f);              // distance to the tile edge on each axis
    float grid = 1.0 - smoothstep(0.03 - w, 0.03 + w, min(e.x, e.y));
    col = mix(col, vec3(0.88, 0.91, 0.96), grid);
    vec2 h = vec2(f.x - clamp(f.x, 0.5, 0.8), f.y - 0.5);   // a hand pointing +x
    float d = min(length(h) - 0.06, length(f - 0.5) - 0.13);
    float hand = 1.0 - smoothstep(-w, w, d);
    return mix(col, vec3(1.0, 0.62, 0.2), hand);
}

vec3 shade(vec2 uv, float aa) {
    vec2 pivot = u_pivot * u_usepivot;
    vec2 p0 = uv - pivot;                  // 1. move the pivot to (0, 0)
    vec2 p1 = rotate(p0, -u_angle);        // 2. turn the coordinates back
    vec2 p2 = p1 / u_zoom;                 // 3. divide to zoom in
    vec2 q = p2 + pivot;                   // 4. move the pivot back
    vec3 col = tiles(q, aa / u_zoom * 4.0);
    if (u_stage < 4.5) col = vec3(fract(q * 4.0), 0.0);
    if (u_stage < 3.5) col = vec3(fract(p2 * 4.0), 0.0);
    if (u_stage < 2.5) col = vec3(fract(p1 * 4.0), 0.0);
    if (u_stage < 1.5) col = vec3(fract(p0 * 4.0), 0.0);
    if (u_stage < 0.5) col = vec3(fract(uv * 4.0), 0.0);
    float ring = abs(length(uv - u_pivot) - 0.03);         // mark the pivot
    col = mix(col, vec3(0.0), 1.0 - smoothstep(2.0 * aa, 3.5 * aa, ring));
    col = mix(col, vec3(1.0), 1.0 - smoothstep(0.5 * aa, 1.5 * aa, ring));
    return col;
}

vec4 effect(vec4 color, Image tex, vec2 texture_coords, vec2 screen_coords)
{
    vec2 uv = (screen_coords - u_rect.xy - 0.5 * u_rect.zw) / u_rect.w;
    uv.y = -uv.y;                     // y points down here; make it point up
    float aa = 1.0 / u_rect.w;        // one pixel, in uv units
    return vec4(shade(uv, aa), 1.0);
}
]]

function love.load()
  shader = love.graphics.newShader(pixelcode)
end

function love.update(dt)
  if spin then
    angle = (angle + 45 * dt) % 360
  end
end

function love.keypressed(key)
  if key == "left" then angle = (angle + 15) % 360 end
  if key == "right" then angle = (angle - 15) % 360 end
  if key == "up" then zoom = math.min(4, zoom * 1.25) end
  if key == "down" then zoom = math.max(0.25, zoom / 1.25) end
  if key == "space" then spin = not spin end
  if key == "p" then usePivot = 1 - usePivot end
  if key == "s" then stage = (stage + 1) % 6 end
end

function love.mousepressed(x, y, button)
  -- screen pixels to centred uv with y up: the same maths as the shader
  pivot[1] = (x - rect[1] - 0.5 * rect[3]) / rect[4]
  pivot[2] = -(y - rect[2] - 0.5 * rect[4]) / rect[4]
end

function love.draw()
  shader:send("u_angle", math.rad(angle))
  shader:send("u_zoom", zoom)
  shader:send("u_pivot", pivot)
  shader:send("u_usepivot", usePivot)
  shader:send("u_stage", stage)
  shader:send("u_rect", rect)
  love.graphics.setShader(shader)
  love.graphics.rectangle("fill", rect[1], rect[2], rect[3], rect[4])
  love.graphics.setShader()
end

  float hand = 1.0 - smoothstep(-w, w, d);
  return mix(col, vec3(1.0, 0.62, 0.2), hand);

vec3 shade(vec2 uv, float aa) {
  vec2 pivot = u_pivot * u_usepivot;
  vec2 p0 = uv - pivot;                    // 1. move the pivot to (0, 0)
  vec2 p1 = rotate(p0, -u_angle);          // 2. turn the coordinates back
  vec2 p2 = p1 / u_zoom;                   // 3. divide to zoom in
  vec2 q = p2 + pivot;                     // 4. move the pivot back
  vec3 col = tiles(q, aa / u_zoom * 4.0);
  if (u_stage < 4.5) col = vec3(fract(q * 4.0), 0.0);
  if (u_stage < 3.5) col = vec3(fract(p2 * 4.0), 0.0);
  if (u_stage < 2.5) col = vec3(fract(p1 * 4.0), 0.0);
  if (u_stage < 1.5) col = vec3(fract(p0 * 4.0), 0.0);
  if (u_stage < 0.5) col = vec3(fract(uv * 4.0), 0.0);
  float ring = abs(length(uv - u_pivot) - 0.03);         // mark the pivot
  col = mix(col, vec3(0.0), 1.0 - smoothstep(2.0 * aa, 3.5 * aa, ring));
  col = mix(col, vec3(1.0), 1.0 - smoothstep(0.5 * aa, 1.5 * aa, ring));
  return col;
}

void main() {
  vec2 px = gl_FragCoord.xy;                             // pixels, origin bottom-left
  vec2 uv = (px - 0.5 * u_resolution) / u_resolution.y;  // centred, y up
  float aa = 1.0 / u_resolution.y;                       // one pixel, in uv units
  gl_FragColor = vec4(shade(uv, aa), 1.0);
}

shader_type canvas_item;

uniform float angle_degrees = 30.0;          // counter-clockwise, after the y flip below
uniform float zoom : hint_range(0.25, 4.0) = 1.5;
uniform vec2 pivot = vec2(0.2, 0.1);         // centred uv units, y up
uniform float aspect = 1.0;                  // set to the ColorRect's width / height

vec2 rotate(vec2 p, float a) {
    float c = cos(a);
    float s = sin(a);
    return vec2(c * p.x - s * p.y, s * p.x + c * p.y);
}

vec3 tiles(vec2 q, float w) {
    vec2 g = q * 4.0;
    vec2 id = floor(g);
    vec2 f = fract(g);
    float checker = mod(id.x + id.y, 2.0);
    vec3 col = mix(vec3(0.15, 0.2, 0.36), vec3(0.24, 0.33, 0.56), checker);
    vec2 e = min(f, 1.0 - f);
    float grid = 1.0 - smoothstep(0.03 - w, 0.03 + w, min(e.x, e.y));
    col = mix(col, vec3(0.88, 0.91, 0.96), grid);
    vec2 h = vec2(f.x - clamp(f.x, 0.5, 0.8), f.y - 0.5);
    float d = min(length(h) - 0.06, length(f - 0.5) - 0.13);
    float hand = 1.0 - smoothstep(-w, w, d);
    return mix(col, vec3(1.0, 0.62, 0.2), hand);
}

void fragment() {
    vec2 uv = (UV - 0.5) * vec2(aspect, 1.0);  // centred
    uv.y = -uv.y;                              // UV.y points down in Godot; make it point up
    vec2 p = rotate(uv - pivot, -radians(angle_degrees)) / zoom;
    vec2 q = p + pivot;
    float w = fwidth(q.y) * 4.0;               // one pixel, in cell units
    COLOR = vec4(tiles(q, w), 1.0);
}

// Put it on a material and apply it to a Quad.
Shader "GameDevDaily/RotateZoomUV"
{
    Properties
    {
        _Angle ("Angle (degrees, counter-clockwise)", Float) = 30
        _Zoom ("Zoom", Range(0.25, 4)) = 1.5
        _Pivot ("Pivot (centred uv, xy)", Vector) = (0.2, 0.1, 0, 0)
        _Aspect ("Aspect (width / height)", Float) = 1
    }
    SubShader
    {
        Tags { "RenderType" = "Opaque" }
        Pass
        {
            CGPROGRAM
            #pragma vertex vert
            #pragma fragment frag
            #pragma target 3.0
            #include "UnityCG.cginc"

            float _Angle, _Zoom, _Aspect;
            float4 _Pivot;

            struct v2f
            {
                float4 pos : SV_POSITION;
                float2 uv : TEXCOORD0;
            };

            v2f vert (appdata_base v)
            {
                v2f o;
                o.pos = UnityObjectToClipPos(v.vertex);
                o.uv = v.texcoord.xy;
                return o;
            }

            float2 rotate (float2 p, float a)
            {
                float c = cos(a);
                float s = sin(a);
                return float2(c * p.x - s * p.y, s * p.x + c * p.y);
            }

            float3 tiles (float2 q, float w)
            {
                float2 g = q * 4.0;
                float2 id = floor(g);
                float2 f = frac(g);
                float checker = frac((id.x + id.y) * 0.5) * 2.0;  // 0 or 1; HLSL fmod differs from GLSL mod
                float3 col = lerp(float3(0.15, 0.2, 0.36), float3(0.24, 0.33, 0.56), checker);
                float2 e = min(f, 1.0 - f);
                float grid = 1.0 - smoothstep(0.03 - w, 0.03 + w, min(e.x, e.y));
                col = lerp(col, float3(0.88, 0.91, 0.96), grid);
                float2 h = float2(f.x - clamp(f.x, 0.5, 0.8), f.y - 0.5);
                float d = min(length(h) - 0.06, length(f - 0.5) - 0.13);
                float hand = 1.0 - smoothstep(-w, w, d);
                return lerp(col, float3(1.0, 0.62, 0.2), hand);
            }

            fixed4 frag (v2f i) : SV_Target
            {
                float2 uv = (i.uv - 0.5) * float2(_Aspect, 1.0);  // centred, y up
                float2 p = rotate(uv - _Pivot.xy, -radians(_Angle)) / _Zoom;
                float2 q = p + _Pivot.xy;
                float w = fwidth(q.y) * 4.0;
                return fixed4(tiles(q, w), 1.0);
            }
            ENDCG
        }
    }
}

WebGL's gl_FragCoord and a Unity Quad's uv start at the bottom-left with y up, so a positive angle turns the pattern counter-clockwise. Godot's canvas_item UV and LÖVE's screen_coords start at the top-left with y down, where the same formula turns it clockwise; both versions above flip y so that all four agree with the demo. In URP Shader Graph, the Rotate node takes a UV, a Center and a Rotation, so it does steps 1, 2 and 4 for you; check its direction in your project with an asymmetric test pattern. In a Unity project set to Linear colour space, the hard-coded colours are treated as linear values and look lighter than on this page.

Pitfalls

  • Everything goes the opposite way. Rotating the coordinates by +a turns the pattern by -a, and multiplying by the zoom zooms out. That is not a bug in your maths; it is what transforming the coordinates means. Keep the minus sign and the division, so that the uniforms mean what their names say.
  • The pattern swings around a corner. Without steps 1 and 4 everything turns around (0, 0). With UVs that run 0 to 1, that is the bottom-left or top-left corner, depending on the engine. The Ignore the pivot toggle shows this.
  • The pattern squashes as it turns. On a quad that is wider than it is tall, a 0 to 1 UV has short units across and long units down. Rotate in it and squares become rhombuses partway through the turn. Correct the aspect ratio before rotating, as all four versions do.
  • Degrees fed into sin and cos. GLSL's sin and cos take radians. A slider in degrees needs radians() in the shader or math.rad in Lua.
  • Order matters once the zoom is not the same on both axes. With a single zoom, rotating then dividing gives the same result as dividing then rotating. With a vec2 stretch it does not: stretch after rotating and the pattern stretches along the pattern's own axes; stretch before and it stretches along the screen's axes.
  • Zooming far out shimmers. At a zoom of 0.25, each tile is only a few pixels wide and fine lines flicker as the pattern turns. The demo widens its soft edges by one pixel measured in pattern space (aa / u_zoom) to hide this. Textures need mipmaps, a later lesson.

What it costs

The transform is a subtraction, four multiplies and two adds for the rotation, one divide, and an add, per pixel. That is nothing, even on a phone. The only notable cost is cos and sin, and the angle is the same for every pixel. In a real game, work them out once on the CPU and send the two numbers, or send 1.0 / zoom as well and multiply instead of dividing. The demo keeps them in the shader so it stays readable.

In real games

Scaling the UV is built into almost every material editor. A Unity material's Tiling setting and Godot's StandardMaterial3D UV1 Scale multiply the UV, so a value of 2 repeats the texture twice across the surface and makes it look smaller: the same "opposite" effect as in this lesson. Shader Graph's Tiling And Offset node does the same multiply in a graph.

Rotated UVs are how spinning effects are usually drawn on a flat quad: rotating magic circles and portals, radar sweeps, loading spinners, and spinning pickups in 2D games. Unity's built-in cubemap skybox shader has a Rotation property in degrees, which turns the direction it samples with rather than the sky itself.

Your turn (15 minutes)

Start from the LÖVE example:

  1. Make the zoom breathe: keep a time variable that grows in love.update(dt), and send zoom * (1 + 0.2 * math.sin(time * 2)) instead of zoom. Click somewhere and check that the tile under the pivot ring stays still while everything else pulses.
  2. Change u_zoom to a vec2 called u_stretch and send { 2, 1 }. Swap lines 2 and 3 of the recipe and compare the two results with the spin on.

You are done when you can say which order keeps the stretch along the orange hands, and which keeps it along the screen.

Takeaways

  • A shader turns and zooms a pattern by transforming the point each pixel reads, q, not by moving the pattern.
  • Do the opposite to the coordinates: rotate by -a and divide by the zoom to turn by a and grow by the zoom.
  • Rotation and division work around (0, 0), so subtract the pivot first and add it back after.
  • Correct the aspect ratio before rotating, and pass radians to sin and cos.
  • The transform is cheap; compute cos and sin of a shared angle once on the CPU.
