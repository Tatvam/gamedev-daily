Texture sampling: from a UV to a texel

A sampler turns a UV into a colour: wrap it, multiply by the texture size, floor to find the texel, read it. Scale and offset pick the texels.

You set a crate material's Tiling to 2 and the planks repeat twice. You raise Offset and the planks slide the other way. Both come from one call nearly every shader makes: "give me the texture's colour at this UV". This lesson opens that call up.

A texture is a grid of colours you look up by UV

A fragment shader is a small function that runs once per pixel and returns a colour. So far ours made that colour from maths. Most real shaders read it from a texture.

A texture is an image stored on the GPU: a grid of colours. Each cell is a texel (texture element), a separate word so it is not mixed up with the screen's pixels. A sampler is the shader's handle to a texture together with the rules for reading it. You give the sampler a UV and it gives back a colour:

vec4 c = texture2D(u_tex, uv);   // GLSL ES 1.0, as in WebGL 1

The same call is texture() in newer GLSL and in Godot, Texel() in LÖVE and tex2D() in Unity's Built-in pipeline.

The UV is in texture space: (0, 0) is one corner of the image and (1, 1) the opposite corner, whatever the image's size. An 8 by 8 texture and a 1024 by 1024 texture both run from 0 to 1. That is why you can swap in a bigger texture without touching the shader.

The four steps of a sample

For a texture W texels wide and H high, with the simplest settings (repeat wrapping and nearest filtering), the sampler does this:

  1. Wrap. Bring the UV into 0 to 1. Repeat wrapping keeps only the part after the point: fract(uv), so 1.3 becomes 0.3.
  2. Scale to texels. Multiply by the size: uv * vec2(W, H). In a 4 texel wide texture, u = 0.6 becomes 2.4, which means "40 percent of the way through texel 2".
  3. Pick. floor drops the fraction and leaves the texel index, here 2.
  4. Read. Return that texel's colour.

Texel i covers u from i / W to (i + 1) / W, with its centre at (i + 0.5) / W. To read one particular texel, aim at its centre: at the edge, rounding can tip you into the neighbour.

The demo below has no texture file, so its shader does the four steps itself, and a function texel(i, j) computes each texel of an 8 by 8 slime sprite with maths. A real sampler does the same steps in hardware. With linear filtering it also blends neighbouring texels; that is a later lesson.

Scale and offset pick which texels

A surface, such as a quad or a sprite, has its own UV that runs from 0 to 1 across it. Before sampling, a shader can transform it:

vec2 uv = surfaceUv * u_scale + u_offset;
  • Scale 2. The UV now runs from 0 to 2 across the surface, so the texture fits twice, each copy half as big. A bigger scale means a smaller picture.
  • Offset 0.25. Every pixel reads a quarter of a texture further along, so the picture slides a quarter of a copy the opposite way.

This is exactly Unity's Tiling and Offset fields on a material, and the UV1 Scale and Offset of Godot's StandardMaterial3D.

Which corner is (0, 0)

  • WebGL and OpenGL: v = 0 is the first row of texel data in memory. Image files store the top row first, so unless you flip the image on upload (WebGL's UNPACK_FLIP_Y_WEBGL), the picture's top row sits at v = 0 and looks upside down when v points up.
  • Unity: UV (0, 0) is the bottom-left of the texture as it appears in the editor, with v up.
  • Godot and LÖVE: (0, 0) is the top-left, with v down.

The demo uses v up, like Unity, and marks texel (0, 0) in red so you can always see where the origin is.

Rule of thumb

A sample is wrap, multiply by the size, floor, read. When a texture looks shifted by one texel or flipped, write those four steps out by hand for one pixel.

Try it

The left panel is the texture itself, UV 0 to 1. The right panel is a surface that samples it. Drag on the right panel, or use the Probe sliders, to move the white ring: that is one pixel. The yellow square on the left is the texel it reads.

Set Scale to 2 and the slime appears four times. Set Offset u to 0.25 and it slides left. Then walk the Stage menu from 1 to 5 to watch the UV become a texel index and then a colour.

The code

In LÖVE you can build the 8 by 8 texture for real, with the same texel rule as the demo, and let the GPU's sampler do the four steps. The pixel shader uses LÖVE's entry point effect instead of main. Click the right panel to place the probe; - and = change the scale, the arrow keys change the offset.

local SIZE = 8                 -- the texture is 8 by 8 texels
local PANEL = 256              -- each panel is 256 by 256 pixels
local T = PANEL / SIZE         -- one texel is 32 pixels on screen
local scale = 1                -- copies of the texture across the surface
local offset = { 0, 0 }        -- in texture widths
local probe = { 0.3, 0.35 }    -- the demo's (0.3, 0.65), with v pointing down
local image, shader

local pixelcode = [[
uniform float u_scale;
uniform vec2 u_offset;

vec4 effect(vec4 color, Image tex, vec2 texture_coords, vec2 screen_coords)
{
  vec2 uv = texture_coords * u_scale + u_offset;  // surface uv to texture uv
  return Texel(tex, uv) * color;                  // wrap, scale, floor, read
}
]]

-- The texture's colour rule: texel (i, j), i to the right, j up, both 0 to 7.
local function isTexel(i, j, ti, tj)
  return i == ti and j == tj
end

local function texel(i, j)
  if isTexel(i, j, 0, 0) then return 0.9, 0.2, 0.2 end            -- origin marker
  if isTexel(i, j, 2, 5) or isTexel(i, j, 5, 5) or isTexel(i, j, 2, 3)
    or isTexel(i, j, 5, 3) or isTexel(i, j, 3, 2) or isTexel(i, j, 4, 2) then
    return 0.08, 0.1, 0.08                                      -- eyes and smile
  end
  if isTexel(i, j, 3, 6) then return 0.7, 0.95, 0.6 end           -- highlight
  local dx, dy = i + 0.5 - 4, j + 0.5 - 4
  if math.sqrt(dx * dx + dy * dy) < 3.3 then return 0.35, 0.75, 0.35 end
  if (i + j) % 2 == 0 then return 0.12, 0.14, 0.24 end
  return 0.2, 0.23, 0.36
end

-- The same four steps the sampler does, on the CPU, for the readout.
local function probeTexel()
  local u = probe[1] * scale + offset[1]
  local v = probe[2] * scale + offset[2]
  u = u - math.floor(u)                          -- 1. wrap (repeat)
  v = v - math.floor(v)
  local i = math.min(math.floor(u * SIZE), SIZE - 1)   -- 2 and 3. scale, floor
  local row = math.min(math.floor(v * SIZE), SIZE - 1)
  return i, SIZE - 1 - row                       -- rows count down in LÖVE; j counts up
end

function love.load()
  local data = love.image.newImageData(SIZE, SIZE)
  for j = 0, SIZE - 1 do
    for i = 0, SIZE - 1 do
      local r, g, b = texel(i, j)
      data:setPixel(i, SIZE - 1 - j, r, g, b, 1)   -- image rows go down
    end
  end
  image = love.graphics.newImage(data)
  image:setFilter("nearest", "nearest")   -- no blending between texels
  image:setWrap("repeat", "repeat")       -- uv outside 0 to 1 repeats
  shader = love.graphics.newShader(pixelcode)
end

function love.keypressed(key)
  if key == "=" then scale = math.min(4, scale + 0.25) end
  if key == "-" then scale = math.max(0.25, scale - 0.25) end
  if key == "right" then offset[1] = offset[1] + 0.05 end
  if key == "left" then offset[1] = offset[1] - 0.05 end
  if key == "down" then offset[2] = offset[2] + 0.05 end
  if key == "up" then offset[2] = offset[2] - 0.05 end
end

function love.mousepressed(x, y)
  local u, v = (x - 300) / PANEL, (y - 20) / PANEL
  if u >= 0 and u <= 1 and v >= 0 and v <= 1 then
    probe[1], probe[2] = u, v
  end
end

function love.draw()
  love.graphics.setColor(1, 1, 1)
  love.graphics.draw(image, 20, 20, 0, T)        -- left: the texture as it is
  shader:send("u_scale", scale)
  shader:send("u_offset", offset)
  love.graphics.setShader(shader)
  love.graphics.draw(image, 300, 20, 0, T)       -- right: the sampled surface
  love.graphics.setShader()

  local i, j = probeTexel()
  love.graphics.circle("line", 300 + probe[1] * PANEL, 20 + probe[2] * PANEL, 6)
  love.graphics.setColor(1, 0.85, 0.2)
  love.graphics.rectangle("line", 20 + i * T, 20 + (SIZE - 1 - j) * T, T, T)
  love.graphics.print("probe reads texel (" .. i .. ", " .. j .. ")", 20, 290)
end
#ifdef GL_FRAGMENT_PRECISION_HIGH
precision highp float;
#else
precision mediump float;
#endif

uniform vec2 u_resolution;
uniform float u_scale;    // uv scale: copies of the texture across the surface
uniform vec2 u_offset;    // uv offset, in texture widths
uniform vec2 u_probe;     // surface uv of the probe, 0 to 1, y up
uniform float u_stage;    // 0 surface uv ... 4 final colour
uniform float u_grid;     // 1.0 draws texel edges and tile edges

const float SIZE = 8.0;   // the texture is 8 by 8 texels

float isTexel(vec2 ij, vec2 t) {
  return 1.0 - step(0.5, length(ij - t));
}

// The texture, made with maths: the colour of texel (i, j), i to the right, j up.
vec3 texel(vec2 ij) {
  vec3 col = mix(vec3(0.12, 0.14, 0.24), vec3(0.2, 0.23, 0.36), mod(ij.x + ij.y, 2.0));
  float body = 1.0 - step(3.3, length(ij + 0.5 - vec2(4.0)));
  col = mix(col, vec3(0.35, 0.75, 0.35), body);
  col = mix(col, vec3(0.7, 0.95, 0.6), isTexel(ij, vec2(3.0, 6.0)));
  float face = isTexel(ij, vec2(2.0, 5.0)) + isTexel(ij, vec2(5.0, 5.0))
             + isTexel(ij, vec2(2.0, 3.0)) + isTexel(ij, vec2(5.0, 3.0))
             + isTexel(ij, vec2(3.0, 2.0)) + isTexel(ij, vec2(4.0, 2.0));
  col = mix(col, vec3(0.08, 0.1, 0.08), face);
  col = mix(col, vec3(0.9, 0.2, 0.2), isTexel(ij, vec2(0.0)));
  return col;
}

// What texture2D does with repeat wrapping and nearest filtering.
vec2 texelIndex(vec2 uv) {
  vec2 wrapped = fract(uv);                         // repeat: keep the part after the point
  return min(floor(wrapped * SIZE), SIZE - 1.0);    // which texel, 0 to 7
}

vec3 sampleTexture(vec2 uv) {
  return texel(texelIndex(uv));
}

float boxEdge(vec2 p, vec2 lo, vec2 hi) {           // distance to the outline of a box
  vec2 q = abs(p - 0.5 * (lo + hi)) - 0.5 * (hi - lo);
  return abs(length(max(q, 0.0)) + min(max(q.x, q.y), 0.0));
}

vec3 drawLine(vec3 col, float d, float lw, vec3 ink) {  // d and lw in pixels
  col = mix(col, vec3(0.0), 1.0 - smoothstep(lw, 2.0 * lw, d));
  return mix(col, ink, 1.0 - smoothstep(0.3 * lw, lw, d));
}

float gridShade(vec2 p, float texelPx, float lw) {   // 1.0 on a texel edge
  vec2 f = fract(p);
  vec2 e = min(f, 1.0 - f) * texelPx;                // to the nearest edge, pixels
  return 1.0 - smoothstep(0.0, lw, min(e.x, e.y));
}

void main() {
  vec2 res = u_resolution;
  float m = 0.06 * res.y;                                       // margin, pixels
  float S = min(res.y - 2.0 * m, 0.5 * (res.x - 3.0 * m));      // panel size, pixels
  vec2 a0 = vec2(0.5 * (res.x - 2.0 * S - m), 0.5 * (res.y - S)); // texture panel
  vec2 b0 = a0 + vec2(S + m, 0.0);                              // surface panel
  float lw = max(1.0, res.y / 300.0);                           // line width, pixels
  vec2 px = gl_FragCoord.xy;                                    // origin bottom-left, y up
  vec3 col = vec3(0.1, 0.11, 0.13);
  vec3 yellow = vec3(1.0, 0.85, 0.2);

  vec2 probeUv = u_probe * u_scale + u_offset;   // the uv the probe pixel asks for
  vec2 pij = texelIndex(probeUv);                // the texel it gets
  vec2 puv = fract(probeUv);                     // where that is in the texture

  // Left panel: the texture itself, uv 0 to 1 on both axes.
  vec2 t = (px - a0) / S;
  if (t.x >= 0.0 && t.x <= 1.0 && t.y >= 0.0 && t.y <= 1.0) {
    col = texel(min(floor(t * SIZE), SIZE - 1.0));
    if (u_grid > 0.5) col = mix(col, vec3(0.0), 0.5 * gridShade(t * SIZE, S / SIZE, lw));
    col = drawLine(col, boxEdge(t, pij / SIZE, (pij + 1.0) / SIZE) * S, lw, yellow);
    col = drawLine(col, abs(length(t - puv) * S - 3.0 * lw), lw, yellow);
  }

  // Right panel: the surface. Every pixel samples the texture at its own uv.
  vec2 s = (px - b0) / S;
  if (s.x >= 0.0 && s.x <= 1.0 && s.y >= 0.0 && s.y <= 1.0) {
    vec2 uv = s * u_scale + u_offset;
    vec2 ij = texelIndex(uv);
    vec3 c = sampleTexture(uv);
    if (u_stage < 3.5) c = vec3(ij / (SIZE - 1.0), 0.0);
    if (u_stage < 2.5) c = vec3(fract(fract(uv) * SIZE), 0.0);
    if (u_stage < 1.5) c = vec3(fract(uv), 0.0);
    if (u_stage < 0.5) c = vec3(s, 0.0);
    col = c;
    if (u_grid > 0.5) {
      col = mix(col, vec3(0.0), 0.5 * gridShade(uv * SIZE, S / (SIZE * u_scale), lw));
      col = mix(col, vec3(1.0), gridShade(uv, S / u_scale, 0.7 * lw));   // tile edges
    }
    col = drawLine(col, abs(length(s - u_probe) * S - 3.0 * lw), lw, vec3(1.0));
  }

  col = mix(col, vec3(0.45), 1.0 - smoothstep(0.0, lw, boxEdge(px, a0, a0 + S)));
  col = mix(col, vec3(0.45), 1.0 - smoothstep(0.0, lw, boxEdge(px, b0, b0 + S)));
  gl_FragColor = vec4(col, 1.0);
}
// Godot 4. Put this in a ShaderMaterial on a Sprite2D. In the Inspector, set
// CanvasItem > Texture > Filter to Nearest and Repeat to Enabled.
shader_type canvas_item;

uniform float uv_scale = 1.0;         // copies of the texture across the sprite
uniform vec2 uv_offset = vec2(0.0);   // in texture widths

void fragment() {
    vec2 uv = UV * uv_scale + uv_offset;   // UV (0, 0) is the top-left in Godot
    COLOR = texture(TEXTURE, uv);
}
// Built-in render pipeline, unlit. On the texture's import settings,
// set Filter Mode to Point and Wrap Mode to Repeat.
Shader "GameDevDaily/SampleScaleOffset"
{
    Properties
    {
        _MainTex ("Texture", 2D) = "white" {}
    }
    SubShader
    {
        Tags { "RenderType" = "Opaque" }
        Pass
        {
            CGPROGRAM
            #pragma vertex vert
            #pragma fragment frag
            #include "UnityCG.cginc"

            sampler2D _MainTex;
            float4 _MainTex_ST;   // the material's Tiling in xy and Offset in zw

            struct v2f
            {
                float4 pos : SV_POSITION;
                float2 uv : TEXCOORD0;
            };

            v2f vert (appdata_base v)
            {
                v2f o;
                o.pos = UnityObjectToClipPos(v.vertex);
                o.uv = v.texcoord.xy * _MainTex_ST.xy + _MainTex_ST.zw;   // what TRANSFORM_TEX does
                return o;
            }

            fixed4 frag (v2f i) : SV_Target
            {
                return tex2D(_MainTex, i.uv);   // UV (0, 0) is the bottom-left in Unity
            }
            ENDCG
        }
    }
}

The Unity version scales the UV in the vertex shader, which gives the same result as per pixel because the GPU interpolates UVs in straight lines. In URP the read is SAMPLE_TEXTURE2D(_BaseMap, sampler_BaseMap, uv); in Shader Graph, a Tiling And Offset node feeds the UV input of Sample Texture 2D.

Because Godot and LÖVE put v = 0 at the top, a positive v offset there makes the picture move up, while in the demo and in Unity it moves down.

Pitfalls

  • The edge at exactly 1.0. u = 1.0 times 8 is 8.0, and there is no texel 8. The wrap mode decides what happens: repeat reads texel 0, which shows up as a thin line of the opposite edge along a sprite's border. The next lesson is about exactly this.
  • Aiming at texel edges. To read one texel on purpose, for example from a lookup strip, use (i + 0.5) / W. i / W sits on the boundary, and a tiny rounding error picks the neighbour.
  • Upside-down textures. A WebGL texture uploaded without the flip, or UV maths copied from Godot into Unity, flips the image. Test with an asymmetric image like the demo's.
  • Colour space. Colour textures are usually stored in sRGB. In Unity's Linear colour space, and in Godot 3D shaders for a sampler with the source_color hint, the colour is converted from sRGB to linear as it is read. Data textures, such as normal maps or noise, must not be converted: untick sRGB (Color Texture) in Unity and leave out source_color in Godot.

What it costs

The sampler's maths runs in dedicated hardware, so the cost is mostly memory. GPUs keep recently read texels in a small texture cache, so when neighbouring pixels read neighbouring texels, as at scale 1, reads are cheap. On phones memory bandwidth is usually the tightest budget: smaller textures and compressed formats such as ETC2 or ASTC help. A very large scale makes neighbouring pixels read texels far apart, which defeats the cache and makes the picture shimmer; mipmaps, later in this track, fix both.

In real games

Every textured surface in a game is sampled this way. Scale and offset have their own fields in engine materials: Unity's Tiling and Offset are passed to the shader as _MainTex_ST and applied with the TRANSFORM_TEX macro, and Godot's StandardMaterial3D has UV1 Scale and UV1 Offset.

Sprite sheet animation is the same idea: with four frames in a row, a scale of 0.25 across shows one frame and an offset of frame * 0.25 picks it. Godot's Sprite2D exposes this as Hframes and Frame; Unity particles have a Texture Sheet Animation module.

Your turn (15 minutes)

Turn the LÖVE example into a sprite sheet player.

  1. Make the image 32 by 8: four 8 by 8 frames side by side. Fill frame f with texel, but move the eyes one texel left or right depending on f.
  2. Change u_scale to a vec2 and send { 0.25, 1 }.
  3. In love.update(dt), step a frame number every 0.15 seconds and send u_offset = { frame * 0.25, 0 }.

You are done when the slime glances left and right, and no column of the neighbouring frame ever shows at the edge. If one does, check your offsets against the four steps.

Takeaways

  • A texture is a grid of texels, addressed by a UV from 0 to 1 whatever its size.
  • With nearest filtering a sample is: wrap, multiply by the size, floor, read.
  • Texel i spans i / W to (i + 1) / W; aim at (i + 0.5) / W to hit it.
  • uv * scale + offset is Tiling and Offset: bigger scale, smaller picture; positive offset, picture moves back.
  • WebGL, Unity, Godot and LÖVE do not agree on where (0, 0) is. Test with an asymmetric image.
