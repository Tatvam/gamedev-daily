Texture filtering: nearest and linear

Nearest takes the one texel a UV falls in. Linear blends the four nearest texel centres, weighted by how close each one is.

You import a 16 by 16 pixel-art hero, scale it up four times, and it comes out as a soft blur. Or a low-resolution wall texture in a 3D game turns into crisp blocks when you walk up to it. Both come from one sampler setting: the filter, which decides what colour lies between texels.

What lies between two texels

A fragment shader is a small function that runs once per pixel and returns a colour. When it reads a texture, the sampler turns a UV into a colour: wrap, multiply by the size, floor, read. That floor is one choice of filter: the rule that decides which texels, and how much of each, make up the colour.

Filtering matters most under magnification, when one texel covers many screen pixels. Stretch an 8 by 8 texture over 300 pixels and each texel covers about 37 by 37 of them, but the texture only stores 64 colours.

Where the texel centres are

Texel i covers u from i / 8 to (i + 1) / 8, so its centre is at (i + 0.5) / 8. The stored colour belongs to that centre. This half-texel offset is the source of most filtering bugs.

Nearest: one texel

Nearest filtering (Unity calls it Point) returns the texel the UV falls in: floor(uv * 8.0). Every pixel inside one texel gets exactly the same colour, so the texture turns into blocks with hard edges.

Linear: four texels, weighted

Linear filtering (bilinear, in two dimensions) blends the four texel centres around the UV. Move into texel space so the centres land on whole numbers, then split the position into a whole part and a fraction:

local p = u * 8 - 0.5         -- texel space, centres on whole numbers
local i0 = math.floor(p)      -- the texel to the left
local f = p - i0              -- how far towards the next texel, 0 to 1

That is one axis, in Lua; the shader does the same for u and v at once with vec2, floor and fract. The four texels are i0, one to the right, one up, and one diagonal. Blend the bottom pair by f.x, the top pair by f.x, then the two results by f.y. That is three mix calls. The weights always add up to 1.

A worked example: a uv of about (0.516, 0.531) gives p = (3.625, 3.75), so i0 = (3, 3) and f = (0.625, 0.75). Texel (4, 4) is nearest and gets 0.625 × 0.75 = 0.47 of the colour. Texel (3, 3) is furthest and gets 0.375 × 0.25 = 0.09.

Nearest is linear with the weights rounded

Round the weights to 0 or 1 with step(0.5, f) and the same four-texel blend picks exactly one texel: i0 + step(0.5, f) equals floor(uv * 8.0). The demo draws both filters this way so their intermediate values can be compared; hardware does a single read.

What gets blended, and which way is up

Linear filtering averages the numbers the texture stores. In the demo those are gamma-encoded screen values. For a texture marked as sRGB, the GPU converts texels to linear light as it reads them, and the specifications recommend doing so before filtering. The gamma lesson later covers why that matters.

The demo puts (0, 0) at the bottom-left with v up, as WebGL's gl_FragCoord and Unity's UVs do. Godot and LÖVE put (0, 0) at the top-left with v down. The formulas do not change; only "below and to the left" becomes "above and to the left".

Rule of thumb

Pixel art and anything meant to look blocky: nearest. Painted textures, photos, 3D surfaces, fonts and UI with smooth edges: linear.

The code

In LÖVE the filter belongs to the image: Image:setFilter(min, mag), where min is used when the image is drawn smaller and mag when it is drawn larger. This example draws the texture three times: nearest by the GPU, linear by the GPU, and linear by hand in a shader (entry point effect, as LÖVE requires) that reads the nearest image at texel centres. The third panel should match the second; space drops the half-texel shift.

local SIZE = 8                 -- the texture is 8 by 8 texels
local T = 24                   -- one texel is 24 pixels on screen
local shift = 0.5              -- 0.5 is correct; space toggles the bug (0)
local imgNearest, imgLinear, shader

local pixelcode = [[
uniform vec2 u_size;     // texture size in texels
uniform float u_shift;   // 0.5 puts the texel centres on whole numbers

vec4 effect(vec4 color, Image tex, vec2 texture_coords, vec2 screen_coords)
{
  vec2 p = texture_coords * u_size - u_shift;
  vec2 i0 = floor(p);                        // the texel up and to the left
  vec2 f = p - i0;                           // the weights, 0 to 1
  vec2 lo = (clamp(i0, vec2(0.0), u_size - 1.0) + 0.5) / u_size;
  vec2 hi = (clamp(i0 + 1.0, vec2(0.0), u_size - 1.0) + 0.5) / u_size;
  vec4 top = mix(Texel(tex, lo), Texel(tex, vec2(hi.x, lo.y)), f.x);
  vec4 bottom = mix(Texel(tex, vec2(lo.x, hi.y)), Texel(tex, hi), f.x);
  return mix(top, bottom, f.y) * color;
}
]]

-- The texture: texel (i, j), i to the right, j up, both 0 to 7.
local function texel(i, j)
  if i == 0 and j == 0 then return 0.3, 0.75, 0.4 end         -- origin marker
  if i == 6 and j == 1 then return 1, 1, 1 end                -- sparkle
  if j == 7 and i % 2 == 1 then return 0.9, 0.9, 0.9 end      -- top stripes
  local d = math.abs(i - 3.5) + math.abs(j - 3.5)
  if d < 1.5 then return 1, 0.85, 0.25 end                   -- diamond core
  if d < 2.5 then return 0.95, 0.55, 0.2 end
  if d < 3.5 then return 0.85, 0.25, 0.3 end
  return 0.12, 0.14, 0.24                                     -- background
end

-- The same maths on the CPU: the four texels and how much of each.
local function weights(u, v)
  local px, py = u * SIZE - shift, v * SIZE - shift
  local x0, y0 = math.floor(px), math.floor(py)
  local fx, fy = px - x0, py - y0
  return x0, y0, (1 - fx) * (1 - fy), fx * (1 - fy), (1 - fx) * fy, fx * fy
end

function love.load()
  local data = love.image.newImageData(SIZE, SIZE)
  for j = 0, SIZE - 1 do
    for i = 0, SIZE - 1 do
      local r, g, b = texel(i, j)
      data:setPixel(i, SIZE - 1 - j, r, g, b, 1)   -- image rows go down
    end
  end
  imgNearest = love.graphics.newImage(data)
  imgNearest:setFilter("nearest", "nearest")
  imgLinear = love.graphics.newImage(data)
  imgLinear:setFilter("linear", "linear")
  shader = love.graphics.newShader(pixelcode)
end

function love.keypressed(key)
  if key == "space" then shift = 0.5 - shift end
end

function love.draw()
  love.graphics.setColor(1, 1, 1)
  love.graphics.draw(imgNearest, 20, 20, 0, T)    -- nearest, by the GPU
  love.graphics.draw(imgLinear, 232, 20, 0, T)    -- linear, by the GPU
  shader:send("u_size", { SIZE, SIZE })
  shader:send("u_shift", shift)
  love.graphics.setShader(shader)
  love.graphics.draw(imgNearest, 444, 20, 0, T)   -- linear, by hand
  love.graphics.setShader()
  love.graphics.print("nearest       linear       by hand, shift " .. shift, 20, 222)

  local mx, my = love.mouse.getPosition()
  local u, v = (mx - 444) / (SIZE * T), (my - 20) / (SIZE * T)
  if u >= 0 and u <= 1 and v >= 0 and v <= 1 then   -- v counts down here
    local x0, y0, a, b, c, d = weights(u, v)
    love.graphics.print(string.format("texels from (%d, %d): %.2f %.2f %.2f %.2f",
      x0, y0, a, b, c, d), 20, 250)
  end
end
#ifdef GL_FRAGMENT_PRECISION_HIGH
precision highp float;
#else
precision mediump float;
#endif

uniform vec2 u_resolution;
uniform vec2 u_centre;    // texture uv at the middle of the view, y up
uniform float u_zoom;     // 1.0 fits all 8 texels across the shorter side
uniform float u_filter;   // 0 nearest, 1 linear, 2 linear without the -0.5
uniform float u_stage;    // 0 raw uv ... 3 final colour
uniform float u_grid;     // 1.0 draws texel edges and centres

const float SIZE = 8.0;   // the texture is 8 by 8 texels

float inRange(float x, float a, float b) {   // 1.0 when a <= x <= b, for whole numbers
  return step(a - 0.5, x) * step(x, b + 0.5);
}

// The texture, made with maths: the colour of texel (i, j), i to the right, j up.
vec3 texel(vec2 ij) {
  ij = clamp(ij, 0.0, SIZE - 1.0);                        // clamp to edge
  vec2 c = abs(ij - 3.5);
  float d = c.x + c.y;                                    // diamond rings: 1, 2, 3
  vec3 col = vec3(0.12, 0.14, 0.24);
  col = mix(col, vec3(0.85, 0.25, 0.3), step(d, 3.5));
  col = mix(col, vec3(0.95, 0.55, 0.2), step(d, 2.5));
  col = mix(col, vec3(1.0, 0.85, 0.25), step(d, 1.5));
  col = mix(col, vec3(0.9), inRange(ij.y, 7.0, 7.0) * mod(ij.x, 2.0));          // top stripes
  col = mix(col, vec3(1.0), inRange(ij.x, 6.0, 6.0) * inRange(ij.y, 1.0, 1.0)); // sparkle
  col = mix(col, vec3(0.3, 0.75, 0.4), inRange(ij.x, 0.0, 0.0) * inRange(ij.y, 0.0, 0.0));
  return col;
}

vec3 drawLine(vec3 col, float d, float lw, vec3 ink) {  // d and lw in pixels
  col = mix(col, vec3(0.0), 1.0 - smoothstep(lw, 2.0 * lw, d));
  return mix(col, ink, 1.0 - smoothstep(0.3 * lw, lw, d));
}

float gridShade(vec2 p, float cellPx, float lw) {   // 1.0 on a cell edge
  vec2 f = fract(p);
  vec2 e = min(f, 1.0 - f) * cellPx;                // to the nearest edge, pixels
  return 1.0 - smoothstep(0.0, lw, min(e.x, e.y));
}

void main() {
  vec2 res = u_resolution;
  float side = min(res.x, res.y);
  float lw = max(1.0, side / 300.0);                      // line width, pixels
  float tpx = side * u_zoom / SIZE;                       // pixels per texel
  vec2 px = gl_FragCoord.xy;                              // origin bottom-left, y up
  vec2 uv = u_centre + (px - 0.5 * res) / (side * u_zoom);

  vec2 p = uv * SIZE - 0.5;              // texel space: centres on whole numbers
  if (u_filter > 1.5) p = uv * SIZE;     // the bug: centres treated as corners
  vec2 i0 = floor(p);                    // the texel below and to the left
  vec2 f = p - i0;                       // how far towards the next texel, 0 to 1
  if (u_filter < 0.5) f = step(0.5, f);  // nearest: round the weights to 0 or 1

  vec3 a = texel(i0);
  vec3 b = texel(i0 + vec2(1.0, 0.0));
  vec3 c = texel(i0 + vec2(0.0, 1.0));
  vec3 d = texel(i0 + vec2(1.0, 1.0));
  vec3 col = mix(mix(a, b, f.x), mix(c, d, f.x), f.y);   // bottom pair, top pair, then up

  if (u_stage < 2.5) col = vec3(f, 0.0);
  if (u_stage < 1.5) col = vec3(i0 / (SIZE - 1.0), 0.0);
  if (u_stage < 0.5) col = vec3(uv, 0.0);

  if (u_grid > 0.5) {
    col = mix(col, vec3(0.0), 0.45 * gridShade(uv * SIZE, tpx, lw));     // texel edges
    float r = length(fract(uv * SIZE) - 0.5) * tpx;                      // to the centre
    col = drawLine(col, max(r - 1.5 * lw, 0.0), lw, vec3(1.0));          // centre dots
  }
  col = drawLine(col, abs(length(px - 0.5 * res) - 6.0 * lw), lw, vec3(0.3, 0.9, 1.0));
  gl_FragColor = vec4(col, 1.0);
}
// Godot 4, in a ShaderMaterial on a Sprite2D. The easy way is the node's
// CanvasItem > Texture > Filter property (Nearest or Linear), or a hint such
// as filter_nearest on a sampler uniform. This version filters by hand.
shader_type canvas_item;

uniform float shift = 0.5;   // 0.5 is correct, 0.0 shows the half-texel bug

void fragment() {
    vec2 size = vec2(textureSize(TEXTURE, 0));
    vec2 p = UV * size - shift;          // UV (0, 0) is the top-left in Godot
    vec2 i0 = floor(p);
    vec2 f = p - i0;
    ivec2 a = ivec2(clamp(i0, vec2(0.0), size - 1.0));
    ivec2 b = ivec2(clamp(i0 + 1.0, vec2(0.0), size - 1.0));
    // texelFetch reads one texel by index, with no filtering at all
    vec4 top = mix(texelFetch(TEXTURE, a, 0), texelFetch(TEXTURE, ivec2(b.x, a.y), 0), f.x);
    vec4 bottom = mix(texelFetch(TEXTURE, ivec2(a.x, b.y), 0), texelFetch(TEXTURE, b, 0), f.x);
    COLOR = mix(top, bottom, f.y);
}
// Built-in render pipeline, unlit. The easy way is the texture's import
// setting Filter Mode: Point (no filter), Bilinear or Trilinear.
// This version filters by hand. Set the texture to Point.
Shader "GameDevDaily/HandFilter"
{
    Properties
    {
        _MainTex ("Texture", 2D) = "white" {}
        _Shift ("Shift (0.5 correct, 0 the bug)", Float) = 0.5
    }
    SubShader
    {
        Tags { "RenderType" = "Opaque" }
        Pass
        {
            CGPROGRAM
            #pragma vertex vert_img
            #pragma fragment frag
            #include "UnityCG.cginc"

            sampler2D _MainTex;
            float4 _MainTex_TexelSize;   // (1 / width, 1 / height, width, height)
            float _Shift;

            fixed4 frag (v2f_img i) : SV_Target
            {
                float2 size = _MainTex_TexelSize.zw;
                float2 p = i.uv * size - _Shift;   // (0, 0) is the bottom-left
                float2 i0 = floor(p);
                float2 f = p - i0;
                float2 lo = (clamp(i0, 0.0, size - 1.0) + 0.5) / size;         // texel centres
                float2 hi = (clamp(i0 + 1.0, 0.0, size - 1.0) + 0.5) / size;
                fixed4 bottom = lerp(tex2D(_MainTex, lo), tex2D(_MainTex, float2(hi.x, lo.y)), f.x);
                fixed4 top = lerp(tex2D(_MainTex, float2(lo.x, hi.y)), tex2D(_MainTex, hi), f.x);
                return lerp(bottom, top, f.y);
            }
            ENDCG
        }
    }
}

Unity fills _MainTex_TexelSize because its name is the texture's name plus _TexelSize. In URP or Shader Graph, set Filter Mode on the texture asset, or connect a Sampler State node (Filter: Point, Linear or Trilinear) to Sample Texture 2D.

Pitfalls

  • Blurry pixel art. LÖVE, Godot 4 (for 2D) and Unity all default to linear filtering. Switch it off for pixel art: love.graphics.setDefaultFilter("nearest", "nearest") before loading images, Godot's project setting Rendering > Textures > Canvas Textures > Default Texture Filter, or Unity's Filter Mode Point. See the pixel-art lesson Nearest neighbour scaling for the artist's side.
  • Nearest at a scale that is not a whole number. At 2.5 times, some texels cover 2 pixels and some cover 3, so a moving sprite shimmers. Draw pixel art at whole-number scales, or soften only the edges with the exercise below.
  • Forgetting the −0.5 when filtering by hand. The result is smooth, so it looks right, but the image is shifted by half a texel. The demo's right panel can show it.
  • Neighbours bleeding in from an atlas. Linear reads one texel past each sprite's edge. In a texture atlas that texel belongs to the next sprite, so a faint line of its colour appears. Pad sprites with copies of their edge texels.
  • Dark fringes. Linear blends colour and alpha separately. Blending an opaque red texel with a transparent black one gives a half-transparent dark red. Premultiplied alpha, from the alpha lesson, fixes it.

What it costs

The texture unit fetches and blends the four texels in one operation, so for ordinary 8-bit textures linear costs about the same as nearest on most GPUs, phones included. Float textures are the exception: WebGL 1 can linear-filter 32-bit float textures only with the OES_texture_float_linear extension, which many phones lack. Filtering by hand costs four reads instead of one, and reads are expensive on a phone, so do it only when the hardware cannot.

In real games

Retro-style 2D games draw with nearest so every art pixel stays a sharp square, and so do 3D games built around a blocky look, such as Minecraft. Most other 3D games use linear filtering, plus the mipmap and anisotropic modes that the next lesson starts on.

The original PlayStation had no texture filtering, which is part of why its textures look blocky up close. The Nintendo 64 filtered, but blended three texels instead of four to save work. Retro shaders imitate both on purpose.

Your turn (15 minutes)

Use the LÖVE example to build your own filters by changing only the weights f.

  1. Add f = step(vec2(0.5), f); after the line that computes f. Predict first: which panel should the third panel now match?
  2. Replace it with f = smoothstep(0.0, 1.0, f);. Colours still pass through every centre, but the blends ease in and out.
  3. Replace it with f = clamp((f - 0.5) * 4.0 + 0.5, 0.0, 1.0);. This keeps texels flat in the middle and blends only near their edges. Scale the image by a number that is not whole, such as T = 23.5, and compare it with the nearest panel.

You are done when you can say, for each version, what colour you get exactly halfway between two texel centres and exactly on a centre.

Takeaways

  • A texel's colour belongs to its centre, at (i + 0.5) / size.
  • Nearest returns the texel the UV falls in: floor(uv * size).
  • Linear works from p = uv * size - 0.5: floor(p) picks four texels, fract(p) weights them, and three mix calls blend them.
  • Nearest is the same blend with the weights rounded to 0 or 1.
  • Hardware linear filtering is nearly free; hand-made filtering costs four reads.
