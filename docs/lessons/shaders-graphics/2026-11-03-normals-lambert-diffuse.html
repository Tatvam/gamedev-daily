Normals and Lambert diffuse: shading a sphere with one dot product

Each pixel of a lit surface needs its normal and the direction to the light. Their dot product, clamped at zero, is how bright that pixel is.

Draw a planet as a flat orange circle and it reads as a coin. Darken the side turned away from the sun and it becomes a ball. Move the sun and the dark side has to follow. That shading is one dot product per pixel, and every lit surface in a 3D game starts from it.

Which way does this pixel face?

A fragment shader is a small function that runs once per pixel and returns a colour. Lighting needs one more input than before: which way the surface under the pixel faces.

That direction is the surface normal, written N: a vector of length 1 that points straight out of the surface. A floor's normal points up. On a ball, each point's normal points away from the centre.

The light needs a direction too. L is a unit vector from the surface towards the light. This lesson uses a directional light, like the sun, which has the same L for every pixel. (Point lights, where L changes across the surface, come next lesson.)

Lambert's cosine law

A beam hitting a surface straight on lights a small patch. Tilt the surface and the same beam spreads over a bigger patch, so each bit gets less. Brightness drops off with the cosine of the angle θ between N and L. That rule is Lambert's cosine law, from Johann Heinrich Lambert's Photometria of 1760.

The cosine costs nothing to get. For two unit vectors, the dot product N·L = Nx·Lx + Ny·Ly + Nz·Lz is cos θ. It is 1 when the surface faces the light, 0 when the light skims along it, and negative when the surface faces away. A surface facing away gets no light, not negative light, so we clamp it:

local diffuse = math.max(nx * lx + ny * ly + nz * lz, 0)

That number is the diffuse term: light that a matte surface scatters equally in all directions, so it looks the same from any viewing angle. Multiply it by the surface colour, the albedo, and you have a lit pixel.

A sphere without any triangles

In a 3D engine each vertex of the mesh stores a normal, and the rasteriser blends them across each triangle. To hide nothing, the demo draws a sphere straight in the fragment shader, where the normal is easy to work out.

Take p, the pixel's position measured from the centre of the disc, with the disc's edge at length 1. A point on a sphere of radius 1 obeys x² + y² + z² = 1, so the height of the surface towards the viewer is z = sqrt(1 − x² − y²). On a sphere the normal is just the point itself, N = (p.x, p.y, z). It already has length 1, so it needs no normalising.

Six lines build the whole effect, and the demo's Stage menu shows each one:

p       = centred position / RADIUS      -- 1. where am I on the disc?
mask    = 1 inside length(p) < 1         -- 2. am I on the sphere at all?
N       = (p.x, p.y, sqrt(1 - p·p))      -- 3. which way does the surface face?
ndotl   = N·L                            -- 4. how much does it face the light?
diffuse = max(ndotl, 0)                  -- 5. no negative light
colour  = albedo * (diffuse + ambient)   -- 6. tint, and lift the shadow a little

The ambient term in line 6 is a small constant added so the dark half is not pure black. It is a cheap stand-in for light bounced off everything else.

Axes and colour space

The demo uses x right, y up, and z out of the screen towards you, with (0, 0) of gl_FragCoord at the bottom-left. LÖVE's screen_coords and Godot's UV start at the top-left with y down, so the code tabs flip y. Get this wrong and the light comes from below when you point above. The maths assumes linear light, but this page sends the numbers to the screen unconverted; a gamma-correct pipeline shows a softer falloff. A later lesson on gamma explains why.

Try it

Drag anywhere on the canvas, or use the arrow keys, to move the sun marker. The light shines from above that point, at the height set by Light height. Then step through the Stage menu from 1. Stage 3 shows N as colour, each axis mapped from −1…1 to 0…1: red is x, green is y, blue is z. Stage 4 shows N·L before the clamp; red marks the negative values that stage 5 throws away.

Drag Light height below zero to put the light behind the ball (the marker turns hollow): only a crescent stays lit.

The code

In LÖVE, the shader goes in a string with the effect entry point and is drawn over a full-window rectangle. Lua works out L from the mouse, normalises it and sends it each frame. The numbers match the demo. Hold up or down to raise or lower the light.

local RADIUS = 0.38                  -- sphere radius, as a fraction of the window height
local albedo = { 0.9, 0.45, 0.25 }   -- surface colour
local ambient = 0.1                  -- lifts the dark half above black
local height = 1.0                   -- light height above the screen, in sphere radii
local lightX, lightY = 0.6, 0.6      -- light position over the screen, in sphere radii, y up
local shader

local pixelcode = [[
uniform vec2 u_resolution;   // window size in pixels
uniform vec3 u_light;        // unit vector towards the light
uniform vec3 u_albedo;
uniform float u_ambient;
const float RADIUS = 0.38;

vec4 effect(vec4 color, Image tex, vec2 texture_coords, vec2 screen_coords)
{
  vec2 p = (screen_coords - 0.5 * u_resolution) / u_resolution.y / RADIUS;
  p.y = -p.y;                                  // LÖVE's y grows downwards: make it grow up
  float aa = 1.5 / (u_resolution.y * RADIUS);  // 1.5 pixels, in sphere units
  float mask = 1.0 - smoothstep(1.0 - aa, 1.0, length(p));
  vec3 n = vec3(p, sqrt(max(1.0 - dot(p, p), 0.0)));
  float ndotl = dot(n, u_light);
  float diffuse = max(ndotl, 0.0);
  vec3 col = u_albedo * (diffuse + u_ambient);
  vec3 bg = vec3(0.1, 0.11, 0.14);
  return vec4(mix(bg, col, mask), 1.0) * color;
}
]]

local function normalize(x, y, z)
  local len = math.sqrt(x * x + y * y + z * z)
  if len < 1e-6 then return 0, 0, 1 end      -- no direction: light from the front
  return x / len, y / len, z / len
end

function love.load()
  shader = love.graphics.newShader(pixelcode)
end

function love.update(dt)
  local w, h = love.graphics.getDimensions()
  local mx, my = love.mouse.getPosition()
  lightX = (mx - 0.5 * w) / h / RADIUS
  lightY = -(my - 0.5 * h) / h / RADIUS       -- flip: screen y goes down
  if love.keyboard.isDown("up") then height = height + dt end
  if love.keyboard.isDown("down") then height = height - dt end
end

function love.draw()
  local lx, ly, lz = normalize(lightX, lightY, height)
  shader:send("u_light", { lx, ly, lz })
  shader:send("u_resolution", { love.graphics.getPixelDimensions() })
  shader:send("u_albedo", albedo)
  shader:send("u_ambient", ambient)
  love.graphics.setShader(shader)
  love.graphics.rectangle("fill", 0, 0, love.graphics.getDimensions())
  love.graphics.setShader()
  love.graphics.print(string.format("L = (%.2f, %.2f, %.2f)", lx, ly, lz), 10, 10)
end
precision mediump float;

uniform vec2 u_resolution;
uniform vec3 u_light;      // unit vector from the surface towards the light
uniform vec2 u_lightPos;   // where the sun marker is drawn, device pixels, origin bottom-left
uniform vec3 u_albedo;     // surface colour
uniform float u_ambient;   // lifts the dark half above black
uniform float u_stage;     // 0 centred position ... 5 final colour

const float RADIUS = 0.38; // sphere radius, as a fraction of the canvas height

void main() {
  // 1. position from the centre in sphere units: 1 at the edge, y up
  vec2 p = (gl_FragCoord.xy - 0.5 * u_resolution) / u_resolution.y / RADIUS;
  // 2. 1 inside the disc, 0 outside, with a 1.5 pixel soft edge
  float aa = 1.5 / (u_resolution.y * RADIUS);
  float mask = 1.0 - smoothstep(1.0 - aa, 1.0, length(p));
  // 3. the normal: on a unit sphere it is the surface point itself
  vec3 n = vec3(p, sqrt(max(1.0 - dot(p, p), 0.0)));
  // 4. cosine of the angle between the normal and the light
  float ndotl = dot(n, u_light);
  // 5. Lambert: surfaces facing away get no light
  float diffuse = max(ndotl, 0.0);
  // 6. tint by the albedo and add a little ambient
  vec3 col = u_albedo * (diffuse + u_ambient);

  vec3 bg = vec3(0.1, 0.11, 0.14);
  if (u_stage < 4.5) col = vec3(diffuse);
  if (u_stage < 3.5) col = vec3(max(ndotl, 0.0)) + vec3(0.9, 0.2, 0.15) * max(-ndotl, 0.0);
  if (u_stage < 2.5) col = n * 0.5 + 0.5;
  col = mix(bg, col, mask);
  if (u_stage < 1.5) col = vec3(mask);
  if (u_stage < 0.5) {
    col = vec3(clamp(p * 0.5 + 0.5, 0.0, 1.0), 0.0);
    col = mix(col, vec3(1.0), 0.6 * (1.0 - smoothstep(0.0, 2.0 * aa, abs(length(p) - 1.0))));
  }

  // the sun marker: filled when the light is in front, hollow when it is behind
  float lw = max(1.0, u_resolution.y / 300.0);
  float d = length(gl_FragCoord.xy - u_lightPos);
  float front = step(0.0, u_light.z);
  vec3 sun = vec3(1.0, 0.82, 0.25);
  col = mix(col, vec3(0.0), 1.0 - smoothstep(lw, 2.0 * lw, abs(d - 8.5 * lw)));
  col = mix(col, sun, 1.0 - smoothstep(0.7 * lw, 1.5 * lw, abs(d - 6.5 * lw)));
  col = mix(col, sun, front * (1.0 - smoothstep(4.5 * lw, 5.5 * lw, d)));
  gl_FragColor = vec4(col, 1.0);
}
// Godot 4, a ShaderMaterial on a square ColorRect. The sphere fills the rect.
shader_type canvas_item;

uniform vec3 albedo : source_color = vec3(0.9, 0.45, 0.25);
uniform vec3 light_dir = vec3(0.6, 0.6, 1.0);   // towards the light, x right, y up, z out
uniform float ambient : hint_range(0.0, 0.5) = 0.1;

void fragment() {
    vec2 p = UV * 2.0 - 1.0;
    p.y = -p.y;                     // Godot's UV (0, 0) is the top-left, y grows down
    float aa = fwidth(length(p));
    float mask = 1.0 - smoothstep(1.0 - aa, 1.0, length(p));
    vec3 n = vec3(p, sqrt(max(1.0 - dot(p, p), 0.0)));
    float diffuse = max(dot(n, normalize(light_dir)), 0.0);
    vec3 col = albedo * (diffuse + ambient);
    COLOR = vec4(col, mask);        // transparent outside the disc
}
// Built-in render pipeline, unlit, on a Quad facing the camera. The sphere fills the quad.
// The light direction is in the quad's own 2D convention (x right, y up, z out of the
// quad towards the viewer), not in Unity's world space.
Shader "GameDevDaily/LambertSphere"
{
    Properties
    {
        _Albedo ("Albedo", Color) = (0.9, 0.45, 0.25, 1)
        _LightDir ("Direction to light", Vector) = (0.6, 0.6, 1, 0)
        _Ambient ("Ambient", Range(0, 0.5)) = 0.1
    }
    SubShader
    {
        Tags { "RenderType" = "Opaque" }
        Pass
        {
            CGPROGRAM
            #pragma vertex vert_img
            #pragma fragment frag
            #include "UnityCG.cginc"

            fixed4 _Albedo;
            float4 _LightDir;
            float _Ambient;

            fixed4 frag (v2f_img i) : SV_Target
            {
                float2 p = i.uv * 2.0 - 1.0;    // uv (0, 0) is the bottom-left: y is already up
                float aa = fwidth(length(p));
                float mask = 1.0 - smoothstep(1.0 - aa, 1.0, length(p));
                float3 n = float3(p, sqrt(max(1.0 - dot(p, p), 0.0)));
                float diffuse = max(dot(n, normalize(_LightDir.xyz)), 0.0);
                float3 col = _Albedo.rgb * (diffuse + _Ambient);
                float3 bg = float3(0.1, 0.11, 0.14);
                return fixed4(lerp(bg, col, mask), 1.0);
            }
            ENDCG
        }
    }
}

In the engine tabs the sphere fills its rectangle, and fwidth gives the soft edge. On real meshes you rarely write this yourself: in Unity's Built-in pipeline, #pragma surface surf Lambert asks for exactly this model, and in Godot a spatial shader's custom light() function receives NORMAL and LIGHT and adds to DIFFUSE_LIGHT. In a Unity project set to Linear colour space, the output is converted for the screen, so the shadowed side looks brighter than on this page.

Pitfalls

  • L pointing the wrong way. The formula wants the direction towards the light. A sun object usually stores the direction its light travels. Used as it is, light and dark swap. Negate it.
  • Forgetting to normalise. N·L is cos θ only when both vectors have length 1. Unnormalised, (0.6, 0.6, 1.0) has length 1.31 and the front of the ball clips to flat colour. Normals blended across a triangle come out shorter than 1, so normalise them again in the fragment shader.
  • Mixing spaces. N and L must both be in world space, or both in view space. An object-space normal with a world-space light gives lighting that turns with the model.
  • Non-uniform scale. Transform normals like positions on a stretched mesh and they stop standing straight out of the surface. Engines use a separate normal matrix (the inverse transpose); use the engine's normal rather than your own.
  • Pitch black shadows. Lambert gives exactly 0 past the terminator. Ambient, a fill light or a "wrap" variant keeps the shadow side readable.

What it costs

One dot product and one max is about the cheapest maths a shader can do, fine on any phone; the demo's sqrt is a little dearer. What adds up is the number of lights, each one another N·L per pixel. Early 3D hardware lit only at vertices and blended the colours (Gouraud shading) to save work. Per-pixel lighting is standard now, but on low-end phones keep few lights per object.

In real games

The fixed-function lighting of OpenGL and Direct3D, used before programmable shaders, computed diffuse as max(N·L, 0) per vertex. Unity's built-in surface shaders offer Lambert as a named lighting model, and its legacy Diffuse shader uses it. Godot's StandardMaterial3D has a Diffuse Mode setting where Lambert sits beside Lambert Wrap, Burley and Toon. Physically based shaders still multiply their diffuse and specular parts by the same clamped N·L.

Takeaways

  • The surface normal N says which way a pixel's surface faces. L is the unit direction from the surface towards the light.
  • For unit vectors, N·L is the cosine of the angle between them, which is Lambert's cosine law for diffuse brightness.
  • Clamp with max(N·L, 0): a surface facing away gets no light, not negative light.
  • On a unit sphere drawn in a shader, N = (p.x, p.y, sqrt(1 − p·p)). On meshes the normal comes from the vertices and must be normalised again.
  • Diffuse lighting is cheap. The cost grows with the number of lights, not with the maths of one.
