Alpha and blending: over, add, multiply and the dark fringe

How the GPU combines a shader's colour with what is already on screen, and why premultiplied alpha removes the dark fringe around filtered sprites.

You scale up a pixel-art coin, put it on a pale sky, and a thin dirty-brown outline appears around it that is not in the image file. On the dark cave level nobody notices. On the snow level everyone does.

The outline comes from how alpha is stored and blended. One change to the blend fixes it.

The fourth number

A fragment shader is a small function that runs once per pixel and returns a colour. So far every lesson returned vec4(col, 1.0) and ignored the last number. That number is alpha: how much of the pixel this fragment covers, from 0.0 (not at all) to 1.0 (fully).

The shader does not decide what happens with alpha. After it returns, a fixed piece of GPU hardware, the blend unit, reads the colour already stored at that pixel, called the destination or dst, and combines it with the shader's output, the source or src. You do not program the blend unit. You configure it by choosing two factors.

Normal blending is mix

The usual transparency, often called over, uses the factors SrcAlpha and OneMinusSrcAlpha:

result = src.rgb * src.a + dst * (1.0 - src.a)

That is exactly mix(dst, src.rgb, src.a) from the mix lesson, with alpha as the mask. At a = 1.0 you see only the sprite; at a = 0.5 you see half of each. Order matters: drawing A over B is not the same as B over A, which is why transparent objects are sorted back to front.

Additive and multiply

Two other modes come up constantly. Additive blending adds the source to what is there: it can only brighten, which suits fire, sparks and lasers. Multiply multiplies by what is there: it can only darken, which suits shadows and tinted glass. Both give the same result in any order, so they need no sorting.

ModeResultFactors (F1, F2)
Normal, straightsrc.rgb * a + dst * (1 - a)SrcAlpha, OneMinusSrcAlpha
Normal, premultipliedsrc.rgb + dst * (1 - a)One, OneMinusSrcAlpha
Additivesrc.rgb * a + dstSrcAlpha, One
Multiply, premultiplieddst * (src.rgb + 1 - a)DstColor, OneMinusSrcAlpha

Additive vanishes on white and multiply vanishes on black, so the demo has a dark half and a light half.

Where the dark fringe comes from

A texture with straight alpha stores the plain colour in rgb and the coverage in a. A fully transparent texel still stores some rgb, and many tools save it as black. Nobody sees it, until the sprite is drawn larger than its texture and linear filtering blends each pixel from the four nearest texels.

Follow the demo's orange, (1.0, 0.5, 0.1), at that halfway sample, drawn on a white background:

StepStraightPremultiplied
Filtered sample(0.5, 0.25, 0.05), a = 0.5(0.5, 0.25, 0.05), a = 0.5
Blend onto white0.5 × sample + 0.5 × whitesample + 0.5 × white
Result(0.75, 0.63, 0.53)(1.0, 0.75, 0.55)

The right answer is half orange and half white: (1.0, 0.75, 0.55). The straight blend gives a muddy (0.75, 0.63, 0.53). It multiplies by alpha twice: once when filtering mixed in the black, and again in src.rgb * a.

Premultiplied alpha

Premultiplied alpha stores rgb * a in the texture instead of plain rgb. A transparent texel is then always (0, 0, 0, 0), whatever colour the artist left there, and filtering averages colour already weighted by coverage, which is correct. The blend uses One instead of SrcAlpha, so it does not multiply a second time.

A bonus: with the premultiplied blend, a fragment with alpha 0.0 and a bright rgb adds light without hiding anything, so one blend setting draws normal sprites and additive glows in the same batch.

Rule of thumb

Straight alpha is easy to edit; premultiplied alpha is correct to filter and blend. If a texture is filtered, scaled or mipmapped, premultiply it before it reaches the GPU and blend with One, OneMinusSrcAlpha.

Try it

Two 16 by 16 sprites are generated in the shader: an orange disc and a blue diamond, each with a one-texel soft edge at alpha 0.5. The shader filters them by hand and blends them over a background that is dark on the left and light on the right. Drag on the picture (or focus it and press the arrow keys) to move the diamond.

Start with what is on screen: a brown rim on the light half, invisible on the dark half. Switch Stage to 1 to see the stored texels, black around each shape. Now tick Premultiplied alpha and the rim is gone. Untick it, set Hidden colour to White, and a pale halo appears on the dark half instead. Try Sprite colour, then untick Linear filtering: with no filtering there is no fringe in any mode.

The code

The Lua version runs the demo's shader in LÖVE, whose pixel shaders use effect instead of main. Drag with the left mouse button to move the diamond. P toggles premultiplied alpha, 1, 2 and 3 pick normal, additive or multiply, F toggles linear filtering, H cycles the hidden colour, S cycles the stage, and up and down change the opacity.

-- The demo's starting values. Centred uv: (0, 0) in the middle, y up.
local posA = { -0.12, 0.04 }   -- orange disc, drawn first
local posB = { 0.14, -0.06 }   -- blue diamond, drawn on top
local size = 0.56              -- sprite quad size in uv units (16 texels)
local premul = 0               -- 0 straight, 1 premultiplied
local blend = 0                -- 0 normal, 1 additive, 2 multiply
local filter = 1               -- 0 nearest, 1 linear
local hidden = 0               -- rgb of a = 0 texels: 0 black, 1 white, 2 sprite colour
local opacity = 1
local stage = 3                -- 0 texels, 1 alpha, 2 rgb, 3 final
local rect = { 20, 20, 640, 360 }   -- x, y, width, height in pixels

local pixelcode = [[
uniform vec2 u_posA;
uniform vec2 u_posB;
uniform float u_size;
uniform float u_premul;
uniform float u_blend;
uniform float u_filter;
uniform float u_hidden;
uniform float u_opacity;
uniform float u_stage;
uniform vec4 u_rect;

float inQuad(vec2 uv, vec2 pos) {
    vec2 t = abs(uv - pos) / u_size;
    return step(t.x, 0.5) * step(t.y, 0.5);
}

// One texel of a 16 x 16 sprite, made with maths instead of an image file.
vec4 spriteTexel(vec2 ij, float shape, vec3 tint) {
    ij = clamp(ij, 0.0, 15.0);                       // clamp to edge
    vec2 c = ij + 0.5 - 8.0;                         // texel centre, from the middle
    float d = length(c);                             // disc
    if (shape > 0.5) d = abs(c.x) + abs(c.y) - 0.5;  // diamond
    float a = 0.0;
    if (d < 7.5) a = 0.5;                            // soft edge drawn by the artist
    if (d < 6.5) a = 1.0;
    vec3 rgb = tint;
    if (length(c - vec2(-2.0, 2.0)) < 2.5) rgb = mix(tint, vec3(1.0), 0.5);
    vec3 hiddenCol = vec3(0.0);                      // what a = 0 texels store
    if (u_hidden > 0.5) hiddenCol = vec3(1.0);
    if (u_hidden > 1.5) hiddenCol = tint;
    if (a < 0.25) rgb = hiddenCol;
    if (u_premul > 0.5) rgb = rgb * a;              // premultiplied: store rgb * a
    return vec4(rgb, a);
}

vec4 spriteAt(vec2 uv, vec2 pos, float shape, vec3 tint, float useLinear) {
    if (inQuad(uv, pos) < 0.5) return vec4(0.0);   // outside the quad: no fragment
    vec2 t = (uv - pos) / u_size * 16.0 + 8.0;       // texel units, 0 to 16
    if (useLinear < 0.5) return spriteTexel(floor(t), shape, tint); // nearest
    vec2 f = t - 0.5;
    vec2 i = floor(f);
    vec2 w = f - i;
    vec4 s00 = spriteTexel(i, shape, tint);
    vec4 s10 = spriteTexel(i + vec2(1.0, 0.0), shape, tint);
    vec4 s01 = spriteTexel(i + vec2(0.0, 1.0), shape, tint);
    vec4 s11 = spriteTexel(i + vec2(1.0, 1.0), shape, tint);
    return mix(mix(s00, s10, w.x), mix(s01, s11, w.x), w.y); // bilinear
}

// What the GPU's blend unit does.
vec3 blendOver(vec3 dst, vec4 s) {
    if (u_premul > 0.5) s = s * u_opacity;          // premultiplied: scale all four
    else s.a = s.a * u_opacity;                      // straight: scale alpha only
    vec3 src = s.rgb * s.a;                          // straight: factor SrcAlpha
    if (u_premul > 0.5) src = s.rgb;                // premultiplied: factor One
    if (u_blend > 1.5) return dst * (src + 1.0 - s.a); // multiply
    if (u_blend > 0.5) return dst + src;               // additive
    return src + dst * (1.0 - s.a);                     // normal
}

vec3 shade(vec2 uv) {
    vec3 dst = mix(vec3(0.08, 0.09, 0.16), vec3(0.95, 0.93, 0.88), step(0.0, uv.x));
    vec3 tintA = vec3(1.0, 0.5, 0.1);
    vec3 tintB = vec3(0.1, 0.6, 0.95);
    vec4 sA = spriteAt(uv, u_posA, 0.0, tintA, u_filter);
    vec4 sB = spriteAt(uv, u_posB, 1.0, tintB, u_filter);
    vec3 col = blendOver(blendOver(dst, sA), sB);   // draw A, then B
    if (u_stage < 2.5) {
        if (u_stage < 0.5) {                        // stored texels, no filtering
            sA = spriteAt(uv, u_posA, 0.0, tintA, 0.0);
            sB = spriteAt(uv, u_posB, 1.0, tintB, 0.0);
        }
        vec3 vA = sA.rgb;
        vec3 vB = sB.rgb;
        if (u_stage > 0.5 && u_stage < 1.5) { vA = vec3(sA.a); vB = vec3(sB.a); }
        float ch = mod(floor(uv.x * 25.0) + floor(uv.y * 25.0), 2.0);
        col = vec3(0.3 + 0.1 * ch);
        if (inQuad(uv, u_posA) > 0.5) col = vA;
        if (inQuad(uv, u_posB) > 0.5) col = vB;
    }
    return col;
}

vec4 effect(vec4 color, Image tex, vec2 texture_coords, vec2 screen_coords)
{
    vec2 uv = (screen_coords - u_rect.xy - 0.5 * u_rect.zw) / u_rect.w;
    uv.y = -uv.y;                   // y points down here; make it point up
    return vec4(shade(uv), 1.0);
}

local function toUV(x, y)
  local u = (x - rect[1] - rect[3] / 2) / rect[4]
  local v = -(y - rect[2] - rect[4] / 2) / rect[4]
  return u, v
end

function love.load()
  shader = love.graphics.newShader(pixelcode)
end

function love.keypressed(key)
  if key == "p" then premul = 1 - premul end
  if key == "1" then blend = 0 end
  if key == "2" then blend = 1 end
  if key == "3" then blend = 2 end
  if key == "f" then filter = 1 - filter end
  if key == "h" then hidden = (hidden + 1) % 3 end
  if key == "s" then stage = (stage + 1) % 4 end
  if key == "up" then opacity = math.min(1, opacity + 0.05) end
  if key == "down" then opacity = math.max(0, opacity - 0.05) end
end

function love.mousepressed(x, y, button)
  if button == 1 then posB[1], posB[2] = toUV(x, y) end
end

function love.mousemoved(x, y)
  if love.mouse.isDown(1) then posB[1], posB[2] = toUV(x, y) end
end

function love.draw()
  shader:send("u_posA", posA)
  shader:send("u_posB", posB)
  shader:send("u_size", size)
  shader:send("u_premul", premul)
  shader:send("u_blend", blend)
  shader:send("u_filter", filter)
  shader:send("u_hidden", hidden)
  shader:send("u_opacity", opacity)
  shader:send("u_stage", stage)
  shader:send("u_rect", rect)
  love.graphics.setShader(shader)
  love.graphics.rectangle("fill", rect[1], rect[2], rect[3], rect[4])
  love.graphics.setShader()
end

In a real LÖVE game the GPU does the blend; you choose it with love.graphics.setBlendMode, and the second argument says whether your colours are straight or premultiplied. To premultiply a texture you built or loaded as image data, multiply each pixel before making the image:

-- data is an ImageData; do this once, before love.graphics.newImage(data)
data:mapPixel(function(x, y, r, g, b, a)
  return r * a, g * a, b * a, a
end)

-- straight "over", LÖVE's default
love.graphics.setBlendMode("alpha", "alphamultiply")
-- premultiplied "over", for the image above
love.graphics.setBlendMode("alpha", "premultiplied")
-- additive glow from a straight-alpha image
love.graphics.setBlendMode("add", "alphamultiply")

The Godot and Unity tabs set the real blend state instead of blending by hand. The Unity shader is for the Built-in pipeline; in URP Shader Graph, set Surface Type to Transparent and pick the Blending Mode (Alpha, Premultiply, Additive or Multiply).

WebGL's gl_FragCoord has (0, 0) at the bottom-left; LÖVE's screen_coords has it at the top-left with y down, so the Lua version flips y. The demo blends the stored numbers directly. A Unity project in Linear colour space decodes sRGB render targets before blending, so a half-transparent edge looks lighter there than on this page.

Pitfalls

  • Mixing up the two kinds. Straight data with the premultiplied blend adds the full colour at the edge and leaves a bright halo. Premultiplied data with the straight blend multiplies by alpha twice and leaves a dark one. Decide once per texture and label it.
  • Fading a premultiplied sprite by alpha only. If you lower a but not rgb, the sprite turns into an additive glow as it fades. Multiply all four channels by the opacity, as the demo and the engine snippets do.
  • Edge colour bleeding is the other fix. To keep straight alpha, fill transparent texels with the nearest opaque colour, as Sprite colour does in the demo. It fixes filtering but not the additive trick.
  • Unsorted transparency. Normal blending depends on order, and transparent objects usually do not write depth. Sort them back to front. Additive and multiply do not need sorting.

What it costs

The blend itself is fixed-function hardware and nearly free; premultiplied alpha costs nothing at run time once the texture is prepared. The expense of transparency is overdraw: every layer runs the fragment shader again for every pixel it covers, and nothing behind a transparent sprite can be skipped. On a phone, ten big overlapping smoke particles can cost more than the rest of the frame. Keep transparent quads tight around their visible pixels.

In real games

Particle effects lean on these modes: additive for fire, sparks, lasers and magic; normal for smoke and dust; multiply for shadows and dark decals. Unity's older built-in particle shaders came as separate Additive, Alpha Blended and Multiply versions for that reason.

Premultiplied alpha is supported as a blend mode in Unity's ShaderLab (Blend One OneMinusSrcAlpha), in Godot (blend_premul_alpha) and in LÖVE (the "premultiplied" alpha mode). Microsoft's XNA Game Studio 4.0 made it the default for sprites. Texture importers often fix fringes by bleeding colour into transparent texels instead: Unity's Alpha Is Transparency option does this, and Godot's importer has a Fix Alpha Border option.

Your turn (15 minutes)

Make the fringe and then fix it in a real LÖVE project, without a shader:

  1. In love.load, create love.image.newImageData(16, 16). New image data starts as transparent black. Use setPixel to paint an orange disc of radius 6 at full alpha.
  2. Make an image from it and draw it scaled by 16 on a white background (love.graphics.setBackgroundColor(1, 1, 1)). Images use linear filtering by default. Look for the brown rim.
  3. Premultiply the data with the mapPixel snippet above before making the image, and draw it with setBlendMode("alpha", "premultiplied").

You are done when the rim is gone, and when fading the sprite with love.graphics.setColor(o, o, o, o) makes it fade evenly instead of glowing.

Takeaways

  • The shader returns rgb and alpha; the blend unit combines them with the colour already on screen using two factors you choose.
  • Normal blending is mix(dst, src.rgb, src.a). Additive only brightens, multiply only darkens, and neither needs sorting.
  • Filtering a straight-alpha texture pulls the hidden colour of transparent texels into the edge, which shows as a dark or light fringe.
  • Premultiplied alpha stores rgb * a and blends with One, OneMinusSrcAlpha: filtering is then correct, and fading must scale all four channels.
  • Blending is cheap; overdraw from large transparent layers is what costs, especially on phones.
