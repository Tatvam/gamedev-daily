Repeating space with fract: one motif, many tiles

Multiply UV by a tile count, then floor gives each cell a number and fract gives it its own 0 to 1 coordinates, so one shape repeats everywhere.

A floor covered in tiles, a wall of polka dots, the placement grid in a build mode. Drawing each tile as its own sprite means hundreds of objects to place and track.

A shader can draw the whole surface with one shape, written once. The trick is to fold space so that every pixel thinks it is in the first tile.

Two questions about every pixel

A fragment shader is a small function that runs once per pixel and returns a colour. So far the input has been the pixel's UV, a position that runs from 0.0 to 1.0 up the picture. Today we ask two new questions about that position: which tile am I in, and where am I inside that tile?

Start by scaling. If we want 4 tiles, multiply the UV by 4. Call the result st; it now runs from 0.0 to 4.0. Each whole-number step of st is one tile, or cell.

Two built-in functions split st into its two answers:

  • floor(x) rounds down to the whole number below. floor(2.4) is 2.0. That is the cell id: which cell the pixel is in, counting from 0.
  • fract(x) keeps only the part after the decimal point, defined as x - floor(x). fract(2.4) is 0.4. That is the pixel's local coordinate: where it sits inside its own cell, from 0.0 up to (but never reaching) 1.0.

Add them back together and you get st again: the position has only been split in two.

Draw once, appear everywhere

The useful part is the local coordinate. It runs from 0.0 to 1.0 in every cell. Any shape you draw using local instead of uv therefore appears in every cell at once. You write a dot centred on (0.5, 0.5), and you get a whole grid of dots.

Here is the demo's shader, one line per stage. The Stage menu in the demo shows each result:

vec2 uv = px / u_resolution.y;         // 1. input: y from 0.0 to 1.0
vec2 st = uv * u_tiles;                // 2. scaled: 0.0 to tiles
vec2 id = floor(st);                   // 3. which cell: 0, 1, 2 ...
vec2 local = fract(st);                // 4. where in the cell: 0.0 to 1.0
float m = motif(local, aa);            // 5. the mask, from the local position
vec3 col = mix(bg, ink, m);            // 6. final colour

As in the UV lesson, the first line divides both axes by the height, so cells stay square on a wide screen. Tiles sets how many rows there are; the width gets as many columns as fit.

The cell id is the second gift. Every pixel in a cell gets the same id, so you can use it to make cells differ. The demo's Vary by cell id toggle uses mod(id.x + id.y, 2.0), which is 0.0 and 1.0 in alternating cells, to swap the colour on every other dot. Next lesson builds a whole checkerboard from that line.

Rule of thumb

Scale, then split. fract says where you are in the tile, floor says which tile. Draw the shape with the first; vary it with the second.

Try it

Set Stage to 2. st = uv * tiles first: most of the picture turns flat yellow, because red and green cannot go above 1.0 and st passes that after the first cell. Step to stage 3 and the picture becomes a staircase of flat colours, one per cell id. Stage 4 shows the same red-green ramp as stage 1, repeated in every cell.

Then go back to 6. Final, drag Tiles, and tap or drag on the picture. The yellow outline marks the probe's cell, and the readouts show the numbers. Try Tiles at 3.5 to see half a row of cells at the top, and push Motif size past 0.5 to see the shape get cut at the cell border.

The code

The Lua version runs the same motif and shade functions in LÖVE, whose pixel shaders use the entry point effect instead of main. Up and down change the tile count, left and right the motif size, M cycles the motif, V and G switch the variation and the grid, and S cycles the stage. Clicking prints the cell under the mouse, using the same split in plain Lua.

-- The demo's starting values.
local tiles = 4          -- rows of cells
local size = 0.32        -- motif radius, in cell units
local motifKind = 0      -- 0 dot, 1 ring, 2 diamond
local vary = 0           -- 1 swaps the colour on every other cell
local grid = 1           -- 1 draws the cell borders
local stage = 5          -- 0 UV, 1 st, 2 id, 3 local, 4 mask, 5 final
local rect = { 20, 20, 640, 360 }   -- x, y, width, height in pixels
local shader

local pixelcode = [[
uniform float u_tiles;
uniform float u_size;
uniform float u_motif;
uniform float u_vary;
uniform float u_grid;
uniform float u_stage;
uniform vec4 u_rect;

float motif(vec2 local, float aa)
{
    vec2 p = local - 0.5;                          // (0, 0) is the cell centre
    float d = length(p);                           // 0. dot, 1. ring
    if (u_motif > 1.5) d = abs(p.x) + abs(p.y);    // 2. diamond
    float m = 1.0 - smoothstep(u_size - aa, u_size + aa, d);
    if (u_motif > 0.5 && u_motif < 1.5)
        m = 1.0 - smoothstep(0.05 - aa, 0.05 + aa, abs(d - u_size));
    return m;
}

vec3 shade(vec2 uv, float aspect, float aa)
{
    vec2 st = uv * u_tiles;                        // 2. scaled
    vec2 id = floor(st);                           // 3. which cell
    vec2 local = fract(st);                        // 4. where in the cell
    float m = motif(local, aa);                    // 5. mask
    float odd = mod(id.x + id.y, 2.0);
    vec3 ink = mix(vec3(1.0, 0.62, 0.2), vec3(0.3, 0.8, 1.0), odd * u_vary);
    vec3 col = mix(vec3(0.1, 0.12, 0.22), ink, m); // 6. final
    vec2 count = ceil(vec2(u_tiles * aspect, u_tiles));
    if (u_stage < 4.5) col = vec3(m);
    if (u_stage < 3.5) col = vec3(local, 0.0);
    if (u_stage < 2.5) col = vec3(id / count, 0.0);
    if (u_stage < 1.5) col = vec3(st, 0.0);
    if (u_stage < 0.5) col = vec3(uv, 0.0);
    return col;
}

vec4 effect(vec4 color, Image tex, vec2 texture_coords, vec2 screen_coords)
{
    vec2 uv = (screen_coords - u_rect.xy) / u_rect.w;   // (0, 0) is top-left here
    float aspect = u_rect.z / u_rect.w;
    float aa = u_tiles / u_rect.w;                      // one pixel, in cell units
    vec3 col = shade(uv, aspect, aa);
    vec2 local = fract(uv * u_tiles);
    vec2 edge = min(local, 1.0 - local) / aa;           // pixels to the cell border
    float e = min(edge.x, edge.y);
    col = mix(col, vec3(1.0), 0.55 * u_grid * (1.0 - step(1.0, e)));
    return vec4(col, 1.0);
}
]]

function love.load()
  shader = love.graphics.newShader(pixelcode)
end

function love.keypressed(key)
  if key == "up" then tiles = math.min(12, tiles + 0.5) end
  if key == "down" then tiles = math.max(1, tiles - 0.5) end
  if key == "right" then size = math.min(0.7, size + 0.02) end
  if key == "left" then size = math.max(0.05, size - 0.02) end
  if key == "m" then motifKind = (motifKind + 1) % 3 end
  if key == "v" then vary = 1 - vary end
  if key == "g" then grid = 1 - grid end
  if key == "s" then stage = (stage + 1) % 6 end
end

function love.mousepressed(x, y)
  -- The same split on the CPU: floor for the cell, x - floor(x) for fract.
  local stx = (x - rect[1]) / rect[4] * tiles
  local sty = (y - rect[2]) / rect[4] * tiles
  local idx, idy = math.floor(stx), math.floor(sty)
  print("cell", idx, idy, "local", stx - idx, sty - idy)
end

function love.draw()
  shader:send("u_tiles", tiles)
  shader:send("u_size", size)
  shader:send("u_motif", motifKind)
  shader:send("u_vary", vary)
  shader:send("u_grid", grid)
  shader:send("u_stage", stage)
  shader:send("u_rect", rect)
  love.graphics.setShader(shader)
  love.graphics.rectangle("fill", rect[1], rect[2], rect[3], rect[4])
  love.graphics.setShader()
end

uniform vec2 u_resolution;
uniform float u_dpr;
uniform float u_tiles;
uniform float u_size;
uniform float u_motif;
uniform float u_vary;
uniform float u_grid;
uniform float u_stage;
uniform vec2 u_probe;

// The motif: drawn once, in local coordinates from 0.0 to 1.0.
float motif(vec2 local, float aa) {
  vec2 p = local - 0.5;                          // (0, 0) is the cell centre
  float d = length(p);                           // 0. dot, 1. ring
  if (u_motif > 1.5) d = abs(p.x) + abs(p.y);    // 2. diamond
  float m = 1.0 - smoothstep(u_size - aa, u_size + aa, d);
  if (u_motif > 0.5 && u_motif < 1.5)
    m = 1.0 - smoothstep(0.05 - aa, 0.05 + aa, abs(d - u_size));
  return m;
}

// The lesson: repeat space, then draw the motif in every cell.
vec3 shade(vec2 uv, float aspect, float aa) {
  vec2 st = uv * u_tiles;                        // 2. scaled: 0.0 to tiles
  vec2 id = floor(st);                           // 3. which cell: 0, 1, 2 ...
  vec2 local = fract(st);                        // 4. where in the cell: 0.0 to 1.0
  float m = motif(local, aa);                    // 5. the mask
  float odd = mod(id.x + id.y, 2.0);             // 1.0 on every other cell
  vec3 ink = mix(vec3(1.0, 0.62, 0.2), vec3(0.3, 0.8, 1.0), odd * u_vary);
  vec3 col = mix(vec3(0.1, 0.12, 0.22), ink, m); // 6. final
  vec2 count = ceil(vec2(u_tiles * aspect, u_tiles));
  if (u_stage < 4.5) col = vec3(m);
  if (u_stage < 3.5) col = vec3(local, 0.0);
  if (u_stage < 2.5) col = vec3(id / count, 0.0);
  if (u_stage < 1.5) col = vec3(st, 0.0);
  if (u_stage < 0.5) col = vec3(uv, 0.0);
  return col;
}

void main() {
  vec2 px = gl_FragCoord.xy;                     // pixels, origin bottom-left
  float aspect = u_resolution.x / u_resolution.y;
  vec2 uv = px / u_resolution.y;                 // 1. y 0.0 to 1.0, x 0.0 to aspect
  float aa = u_tiles / u_resolution.y;           // one pixel, in cell units
  vec3 col = shade(uv, aspect, aa);

  // Demo only: grid lines on the cell borders.
  vec2 st = uv * u_tiles;
  vec2 local = fract(st);
  vec2 edge = min(local, 1.0 - local) / aa;      // pixels to the cell border
  float e = min(edge.x, edge.y);
  col = mix(col, vec3(1.0), 0.55 * u_grid * (1.0 - step(u_dpr, e)));

  // Demo only: a yellow outline around the probe's cell.
  vec2 pid = floor(u_probe * u_tiles);
  float same = 1.0 - step(0.5, length(floor(st) - pid));
  col = mix(col, vec3(1.0, 0.85, 0.2), same * (1.0 - step(2.0 * u_dpr, e)));

  // Demo only: the probe ring, dark outline then white.
  float d = length(px - u_probe * u_resolution.y);
  col = mix(col, vec3(0.0), step(abs(d - 8.0 * u_dpr), 2.5 * u_dpr));
  col = mix(col, vec3(1.0), step(abs(d - 8.0 * u_dpr), 1.0 * u_dpr));

  gl_FragColor = vec4(col, 1.0);
}
// Godot 4. Put this in a ShaderMaterial on a ColorRect.
shader_type canvas_item;

uniform float tiles = 4.0;
uniform float size : hint_range(0.05, 0.7) = 0.32;
uniform float motif_kind = 0.0;  // 0 dot, 1 ring, 2 diamond
uniform float vary = 0.0;        // 1.0 swaps the colour on every other cell
uniform float aspect = 1.0;      // set to the ColorRect's width / height

float motif(vec2 local, float aa) {
    vec2 p = local - 0.5;
    float d = length(p);
    if (motif_kind > 1.5) d = abs(p.x) + abs(p.y);
    float m = 1.0 - smoothstep(size - aa, size + aa, d);
    if (motif_kind > 0.5 && motif_kind < 1.5)
        m = 1.0 - smoothstep(0.05 - aa, 0.05 + aa, abs(d - size));
    return m;
}

void fragment() {
    vec2 st = UV * vec2(aspect, 1.0) * tiles;   // UV (0, 0) is the top-left
    vec2 id = floor(st);
    vec2 local = fract(st);
    float aa = fwidth(st.y);                    // one pixel, in cell units
    float m = motif(local, aa);
    float odd = mod(id.x + id.y, 2.0);
    vec3 ink = mix(vec3(1.0, 0.62, 0.2), vec3(0.3, 0.8, 1.0), odd * vary);
    COLOR = vec4(mix(vec3(0.1, 0.12, 0.22), ink, m), 1.0);
}

Shader "GameDevDaily/FractTiles"
{
    Properties
    {
        _Tiles ("Tiles", Float) = 4
        _Size ("Motif size", Range(0.05, 0.7)) = 0.32
        _Motif ("Motif (0 dot, 1 ring, 2 diamond)", Float) = 0
        _Vary ("Vary by cell id (0 or 1)", Float) = 0
        _Aspect ("Aspect (width / height)", Float) = 1
    }
    SubShader
    {
        Tags { "RenderType" = "Opaque" }
        Pass
        {
            CGPROGRAM
            #pragma vertex vert
            #pragma fragment frag
            #pragma target 3.0
            #include "UnityCG.cginc"

            float _Tiles, _Size, _Motif, _Vary, _Aspect;

            struct v2f
            {
                float4 pos : SV_POSITION;
                float2 uv : TEXCOORD0;
            };

            v2f vert (appdata_base v)
            {
                v2f o;
                o.pos = UnityObjectToClipPos(v.vertex);
                o.uv = v.texcoord.xy;
                return o;
            }

            float motif (float2 local, float aa)
            {
                float2 p = local - 0.5;
                float d = length(p);
                if (_Motif > 1.5) d = abs(p.x) + abs(p.y);
                float m = 1.0 - smoothstep(_Size - aa, _Size + aa, d);
                if (_Motif > 0.5 && _Motif < 1.5)
                    m = 1.0 - smoothstep(0.05 - aa, 0.05 + aa, abs(d - _Size));
                return m;
            }

            fixed4 frag (v2f i) : SV_Target
            {
                float2 st = i.uv * float2(_Aspect, 1.0) * _Tiles;  // uv (0, 0) is the bottom-left
                float2 id = floor(st);
                float2 local = frac(st);
                float aa = fwidth(st.y);
                float m = motif(local, aa);
                float odd = fmod(id.x + id.y, 2.0);   // fine here: id is never negative
                float3 ink = lerp(float3(1.0, 0.62, 0.2), float3(0.3, 0.8, 1.0), odd * _Vary);
                return fixed4(lerp(float3(0.1, 0.12, 0.22), ink, m), 1.0);
            }
            ENDCG
        }
    }
}

HLSL spells fract as frac. In URP Shader Graph, the Tiling And Offset node does the scaling, and the Fraction and Floor nodes do the split. The Godot and Unity versions use fwidth to measure one pixel; WebGL 1 only has it through an extension, so the demo works it out from the resolution instead. They also leave out the stage menu and the grid.

Which corner is cell (0, 0) depends on where UV starts. WebGL's gl_FragCoord and a Unity Quad's uv start at the bottom-left; Godot's canvas_item UV and LÖVE's screen_coords start at the top-left. With a fractional tile count, the cut-off row lands at the top in WebGL and Unity and at the bottom in Godot and LÖVE. The colours are hard-coded numbers, so a Unity project in Linear colour space treats them as linear values, and they will look lighter there than on this page.

Pitfalls

  • Shapes that leave their cell. Each pixel only ever looks at its own cell, so a motif that reaches past local 0.0 or 1.0 is cut off with a hard straight edge. Push Motif size above 0.5 in the demo to see it. To let shapes overlap their neighbours, each pixel has to check the cells next to it too; the cellular patterns lesson in Track 4 does this.
  • Negative coordinates. Centre the UV and half the picture becomes negative. floor(-0.25) is -1.0 and fract(-0.25) is 0.75, which is exactly what tiling needs. But HLSL's fmod keeps the sign of the first number, so fmod(-1.0, 2.0) is -1.0 where GLSL's mod gives 1.0. Lua's % works like GLSL's mod; math.fmod works like HLSL's fmod.
  • Edge softness that ignores the tile count. A soft edge of 0.02 in local units gets twice as wide on screen when the cells get twice as big. Measure softness in pixels, as the demo does with aa = u_tiles / u_resolution.y, so edges stay crisp at any tile count.
  • Large values and precision. fract of a big number loses detail, because a float has only so many digits to share between the whole part and the fraction. Medium precision on phones runs out quickly; Track 6 returns to this.

What it costs

floor and fract are among the cheapest operations a GPU has, even on a phone. Better still, tiling costs nothing per tile: each pixel still runs the motif once, whether there are 4 cells or 400. The cost that does grow is visual: when cells shrink to a few pixels, thin rings shimmer and break up, the same problem that mipmaps solve for textures later in Track 2.

In real games

Repeating a texture across a surface is the same idea done by the texture hardware. In Unity, the Tiling and Offset fields on a material scale and shift the UV before the texture is read. Godot's materials have a matching UV1 Scale setting. A texture set to repeat then wraps the coordinates back into 0 to 1, much as fract does; the wrap modes lesson covers that.

Grid overlays, tiled backgrounds and patterned UI panels can be drawn this way with no texture at all. Giving each cell its own look from its id is where the hash and cellular noise lessons in Track 4 begin.

Your turn (15 minutes)

Turn the LÖVE example into a level-select grid:

  1. Add a uniform u_selected of type vec2, sent from Lua, holding the id of one cell.
  2. In shade, compute float on = 1.0 - step(0.5, length(id - u_selected));. It is 1.0 only in that one cell.
  3. Use it to make the selected cell's motif bigger and brighter: for example change u_size to u_size + 0.1 * on inside motif, by passing on in.
  4. In love.mousepressed, send the clicked idx, idy as u_selected.

You are done when clicking any cell makes exactly that one stand out, while the shader still draws only one motif.

Takeaways

  • Multiply UV by a tile count to make each whole number one cell.
  • floor(st) is the cell id; fract(st), which equals st - floor(st), is the position inside the cell from 0.0 to 1.0.
  • Draw a shape with the local position and it repeats in every cell. Use the id to make cells differ.
  • Shapes must stay inside their cell, and edge softness should be measured in pixels.
  • Tiling is almost free: one motif per pixel, no matter how many cells.
