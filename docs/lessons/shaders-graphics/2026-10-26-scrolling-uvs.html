Scrolling UVs: conveyors, clouds and parallax layers

Subtract time times a velocity from the UV and any repeating pattern slides across the surface. Two layers at different speeds give depth.

A conveyor belt whose treads roll forward. A waterfall that keeps falling. Clouds drifting behind a title screen. In each case the object never moves; only the pattern painted on it does, and the shader needs one subtraction to slide it.

Move the coordinates, not the picture

A fragment shader is a small function that runs once per pixel and returns a colour. For a pattern shader, the input is the pixel's UV and the output is pattern(uv). The pixel cannot move. What it can change is which point of the pattern it asks about.

vec2 p = uv - offset;     // the point of the pattern this pixel reads
vec3 col = pattern(p);

The offset is a vec2 in UV units, the same for every pixel. Follow one feature of the pattern, say a dot that sits at pattern point 0.1. Before, it showed up where uv = 0.1. Now a pixel sees it when uv - offset = 0.1, so at uv = 0.1 + offset. The whole pattern has moved by +offset.

Make the offset grow

To animate, let the offset grow with time: offset = u_time * velocity. The velocity is a vec2 in UV units per second. Build it from an angle and a speed, speed * vec2(cos(a), sin(a)), so angle 0 moves right and 90 degrees moves up (when y points up, as it does in this demo).

A speed of 0.1 means a feature takes 10 seconds to cross the quad's height. The speed is relative to the quad: on a quad twice as tall, the same material moves twice as many pixels per second.

The pattern has to repeat

The offset keeps growing, so after a while every pixel reads a point far from where the pattern started. That only works if the pattern exists everywhere. A pattern built with fract, as in the tiling lesson, repeats forever, so any offset is fine. A texture repeats only if its wrap mode is set to repeat; that setting gets its own lesson soon.

Two layers, two speeds

From a train window, nearby fences rush past while distant hills barely move. That difference is parallax, the cheapest way to fake depth in 2D. Give each layer its own offset, grow the near one faster, and combine them with mix.

vec2 pf = uv - u_far;     // far layer: slow
vec2 pn = uv - u_near;    // near layer: same direction, 3 times faster
float stars = dots(pf, aa);
float clouds = puffs(pn);

Rule of thumb

To move a pattern by v UV units per second, read it at uv - time * v. A plus sign moves it backwards.

Try it

The night sky has two layers: distant stars and nearby clouds. Turn Direction and both change course together. Set Near layer rate to 1 and the sky looks flat; push it to 3 or 4 and the clouds float in front of the stars.

Set Stage to 1. Grid before scrolling, then 2. Grid after scrolling. The red and green gradient squares are the near layer's cell coordinates, fract(p * 3.0). In stage 2 the coordinates themselves slide, and every later stage is built on them.

The code

The Lua version runs the demo's shader in LÖVE, whose pixel shaders use the entry point effect instead of main. The offsets are added up in love.update(dt), so turning the direction never makes the pattern jump (see the pitfalls). Left and right turn the direction by 15 degrees, up and down change the speed, Q and E change the near layer rate, S cycles the stage and space pauses.

-- The demo's starting values. Centred uv: (0, 0) in the middle, y up.
local angle = 0        -- degrees: 0 moves right, 90 moves up
local speed = 0.1      -- far layer, uv units per second
local rate = 3         -- the near layer moves this many times faster
local stage = 4        -- 0 grid, 1 scrolled grid, 2 far, 3 near, 4 final
local paused = false
local far = { 0, 0 }   -- offsets in uv units
local near = { 0, 0 }
local rect = { 20, 20, 640, 360 }   -- x, y, width, height in pixels
local shader

local pixelcode = [[
uniform vec2 u_far;
uniform vec2 u_near;
uniform float u_stage;
uniform vec4 u_rect;

float dots(vec2 p, float aa) {           // far layer: 6 small dots per uv unit
    vec2 cell = fract(p * 6.0) - 0.5;
    float d = length(cell) - 0.12;
    return 1.0 - smoothstep(-6.0 * aa, 6.0 * aa, d);  // aa in cell units
}

float puffs(vec2 p) {                    // near layer: 3 soft clouds per uv unit
    vec2 q = p * 3.0;
    q.x += 0.5 * mod(floor(q.y), 2.0);   // shift every other row by half a cell
    vec2 cell = fract(q) - 0.5;
    float d = length(cell * vec2(1.0, 1.6)) - 0.3;
    return 1.0 - smoothstep(-0.05, 0.1, d);
}

vec3 shade(vec2 uv, float aa) {
    vec2 pf = uv - u_far;                // 1. scroll: subtract the offset
    vec2 pn = uv - u_near;
    float stars = dots(pf, aa);          // 2. one mask per layer
    float clouds = puffs(pn);
    vec3 sky = mix(vec3(0.2, 0.33, 0.6), vec3(0.07, 0.1, 0.22), uv.y + 0.5);
    vec3 col = sky + vec3(0.5, 0.6, 0.85) * stars * 0.6;   // 3. far first
    col = mix(col, vec3(0.95, 0.97, 1.0), clouds * 0.8);   //    near on top
    if (u_stage < 3.5) col = vec3(clouds);
    if (u_stage < 2.5) col = vec3(stars);
    if (u_stage < 1.5) col = vec3(fract(pn * 3.0), 0.0);
    if (u_stage < 0.5) col = vec3(fract(uv * 3.0), 0.0);
    return col;
}

vec4 effect(vec4 color, Image tex, vec2 texture_coords, vec2 screen_coords)
{
    vec2 uv = (screen_coords - u_rect.xy - 0.5 * u_rect.zw) / u_rect.w;
    uv.y = -uv.y;                     // y points down here; make it point up
    float aa = 1.0 / u_rect.w;        // one pixel, in uv units
    return vec4(shade(uv, aa), 1.0);
}
]]

local function scroll(offset, vx, vy, dt)
  offset[1] = (offset[1] + vx * dt) % 2   -- both patterns repeat every 2 uv units
  offset[2] = (offset[2] + vy * dt) % 2
end

function love.load()
  shader = love.graphics.newShader(pixelcode)
end

function love.update(dt)
  if paused then return end
  local a = math.rad(angle)
  local vx = speed * math.cos(a)
  local vy = speed * math.sin(a)
  scroll(far, vx, vy, dt)
  scroll(near, vx * rate, vy * rate, dt)
end

function love.keypressed(key)
  if key == "left" then angle = (angle + 15) % 360 end
  if key == "right" then angle = (angle - 15) % 360 end
  if key == "up" then speed = math.min(0.5, speed + 0.02) end
  if key == "down" then speed = math.max(0, speed - 0.02) end
  if key == "e" then rate = math.min(4, rate + 0.5) end
  if key == "q" then rate = math.max(0, rate - 0.5) end
  if key == "s" then stage = (stage + 1) % 5 end
  if key == "space" then paused = not paused end
end

function love.draw()
  shader:send("u_far", far)
  shader:send("u_near", near)
  shader:send("u_stage", stage)
  shader:send("u_rect", rect)
  love.graphics.setShader(shader)
  love.graphics.rectangle("fill", rect[1], rect[2], rect[3], rect[4])
  love.graphics.setShader()
end
#ifdef GL_FRAGMENT_PRECISION_HIGH
precision highp float;
#else
precision mediump float;
#endif

uniform vec2 u_resolution;
uniform vec2 u_far;    // far layer offset, uv units, sent each frame
uniform vec2 u_near;   // near layer offset
uniform float u_stage;

float dots(vec2 p, float aa) {           // far layer: 6 small dots per uv unit
  vec2 cell = fract(p * 6.0) - 0.5;
  float d = length(cell) - 0.12;
  return 1.0 - smoothstep(-6.0 * aa, 6.0 * aa, d);  // aa in cell units
}

float puffs(vec2 p) {                    // near layer: 3 soft clouds per uv unit
  vec2 q = p * 3.0;
  q.x += 0.5 * mod(floor(q.y), 2.0);     // shift every other row by half a cell
  vec2 cell = fract(q) - 0.5;
  float d = length(cell * vec2(1.0, 1.6)) - 0.3;
  return 1.0 - smoothstep(-0.05, 0.1, d);
}

vec3 shade(vec2 uv, float aa) {
  vec2 pf = uv - u_far;                  // 1. scroll: subtract the offset
  vec2 pn = uv - u_near;
  float stars = dots(pf, aa);            // 2. one mask per layer
  float clouds = puffs(pn);
  vec3 sky = mix(vec3(0.2, 0.33, 0.6), vec3(0.07, 0.1, 0.22), uv.y + 0.5);
  vec3 col = sky + vec3(0.5, 0.6, 0.85) * stars * 0.6;   // 3. far first
  col = mix(col, vec3(0.95, 0.97, 1.0), clouds * 0.8);   //    near on top
  if (u_stage < 3.5) col = vec3(clouds);
  if (u_stage < 2.5) col = vec3(stars);
  if (u_stage < 1.5) col = vec3(fract(pn * 3.0), 0.0);
  if (u_stage < 0.5) col = vec3(fract(uv * 3.0), 0.0);
  return col;
}

void main() {
  vec2 px = gl_FragCoord.xy;                             // pixels, origin bottom-left
  vec2 uv = (px - 0.5 * u_resolution) / u_resolution.y;  // centred, y up
  float aa = 1.0 / u_resolution.y;                       // one pixel, in uv units
  gl_FragColor = vec4(shade(uv, aa), 1.0);
}
// Godot 4. Two layers scrolled with the built-in TIME.
// Put this in a ShaderMaterial on a ColorRect.
shader_type canvas_item;

uniform vec2 velocity = vec2(0.1, 0.0); // far layer, uv units per second
uniform float rate = 3.0;               // near layer moves this many times faster
uniform float aspect = 1.0;             // set to the ColorRect's width / height

float dots(vec2 p, float aa) {
    vec2 cell = fract(p * 6.0) - 0.5;
    float d = length(cell) - 0.12;
    return 1.0 - smoothstep(-6.0 * aa, 6.0 * aa, d);
}

float puffs(vec2 p) {
    vec2 q = p * 3.0;
    q.x += 0.5 * mod(floor(q.y), 2.0);
    vec2 cell = fract(q) - 0.5;
    float d = length(cell * vec2(1.0, 1.6)) - 0.3;
    return 1.0 - smoothstep(-0.05, 0.1, d);
}

void fragment() {
    vec2 uv = (UV - 0.5) * vec2(aspect, 1.0);  // centred; y points DOWN
    float aa = fwidth(uv.y);                   // one pixel, in uv units
    float stars = dots(uv - TIME * velocity, aa);
    float clouds = puffs(uv - TIME * velocity * rate);
    vec3 sky = mix(vec3(0.07, 0.1, 0.22), vec3(0.2, 0.33, 0.6), UV.y);
    vec3 col = sky + vec3(0.5, 0.6, 0.85) * stars * 0.6;
    col = mix(col, vec3(0.95, 0.97, 1.0), clouds * 0.8);
    COLOR = vec4(col, 1.0);
}

// Put it on a material and apply it to a Quad.
Shader "GameDevDaily/ScrollingLayers"
{
    Properties
    {
        _Velocity ("Velocity (uv per second, xy)", Vector) = (0.1, 0, 0, 0)
        _Rate ("Near layer rate", Float) = 3
        _Aspect ("Aspect (width / height)", Float) = 1
    }
    SubShader
    {
        Tags { "RenderType" = "Opaque" }
        Pass
        {
            CGPROGRAM
            #pragma vertex vert
            #pragma fragment frag
            #pragma target 3.0
            #include "UnityCG.cginc"

            float4 _Velocity;
            float _Rate, _Aspect;

            struct v2f
            {
                float4 pos : SV_POSITION;
                float2 uv : TEXCOORD0;
            };

            v2f vert (appdata_base v)
            {
                v2f o;
                o.pos = UnityObjectToClipPos(v.vertex);
                o.uv = v.texcoord.xy;
                return o;
            }

            float dots (float2 p, float aa)
            {
                float2 cell = frac(p * 6.0) - 0.5;
                float d = length(cell) - 0.12;
                return 1.0 - smoothstep(-6.0 * aa, 6.0 * aa, d);
            }

            float puffs (float2 p)
            {
                float2 q = p * 3.0;
                q.x += frac(floor(q.y) * 0.5);  // 0 or 0.5; HLSL fmod differs from GLSL mod
                float2 cell = frac(q) - 0.5;
                float d = length(cell * float2(1.0, 1.6)) - 0.3;
                return 1.0 - smoothstep(-0.05, 0.1, d);
            }

            fixed4 frag (v2f i) : SV_Target
            {
                float2 uv = (i.uv - 0.5) * float2(_Aspect, 1.0);  // y points up
                float aa = fwidth(uv.y);
                float2 offset = _Time.y * _Velocity.xy;           // _Time.y is seconds
                float stars = dots(uv - offset, aa);
                float clouds = puffs(uv - offset * _Rate);
                float3 sky = lerp(float3(0.2, 0.33, 0.6), float3(0.07, 0.1, 0.22), i.uv.y);
                float3 col = sky + float3(0.5, 0.6, 0.85) * stars * 0.6;
                col = lerp(col, float3(0.95, 0.97, 1.0), clouds * 0.8);
                return fixed4(col, 1.0);
            }
            ENDCG
        }
    }
}

The Godot and Unity versions use time times velocity, which is fine while the velocity is fixed. In URP Shader Graph, multiply a Time node by a velocity and feed it into the Offset input of a Tiling And Offset node. That node adds the offset to the UV, so a positive offset moves the picture towards negative x and y.

WebGL's gl_FragCoord and a Unity Quad's uv start at the bottom-left with y up, so a positive y velocity scrolls up. Godot's canvas_item UV and LÖVE's screen_coords start at the top-left with y down, so in Godot a positive y velocity scrolls down; the LÖVE version flips y to match the demo. In a Unity project set to Linear colour space, the hard-coded colours are treated as linear values and look lighter than on this page.

Pitfalls

  • The pattern moves the wrong way. uv + offset moves the pattern by -offset. If a conveyor runs backwards, flip the sign rather than the velocity, so the velocity keeps meaning "this way, this fast".
  • Turning the direction makes the pattern jump. With offset = u_time * velocity, the whole history is recomputed each frame. At 100 seconds, turning a 0.1 speed velocity by 90 degrees moves the offset by about 14 UV units at once. If velocity can change during play, add up the offset on the CPU, offset = offset + velocity * dt, and send it, as the demo and the Lua do.
  • Offsets grow until precision runs out. An offset of several thousand UV units leaves too few bits for the fraction, and on phones with mediump the pattern starts to wobble and step. Wrap the offset by a distance after which the pattern looks the same. Here both layers repeat every 2 UV units, so % 2 is seamless. Wrapping by anything else causes a visible jump.
  • Pixel art shimmers. A slow scroll moves by a fraction of a pixel each frame, so edges crawl. Snap the offset to whole texels: floor(offset * size) / size, with size the texture size in texels.
  • Seams at the edge of a texture. A texture that does not tile shows a hard line each time it repeats, and one set to clamp smears its edge pixels across the quad. The art must tile, and the wrap mode must repeat.

What it costs

The scroll itself is two subtractions per pixel, as close to free as GPU work gets. The cost is in the layers: each one evaluates its pattern again, or samples its texture again, for every pixel. Two or three full-screen layers are fine on a phone; ten blended full-screen layers is a lot of fill work for a mobile GPU.

In real games

Scrolling UVs are built into the engines' standard tools. Unity's built-in materials expose a texture offset, which scripts can change through Material.SetTextureOffset or mainTextureOffset, and Shader Graph has the Tiling And Offset node. Godot's StandardMaterial3D has a UV1 Offset property, and its shaders can use TIME directly as above.

It shows up wherever something flows over a fixed surface: rivers, lava, waterfalls, conveyor belts, and the layered scrolling backgrounds of 2D shooters and runners.

Your turn (15 minutes)

Turn the LÖVE example into a waterfall:

  1. Set angle to 270 so both layers fall, and the speed to 0.3.
  2. In puffs, stretch the clouds into streaks: change vec2(1.0, 1.6) to vec2(2.5, 0.4), which makes them narrow and tall.
  3. Recolour: make the sky a deep blue-green and the cloud colour a pale aqua.
  4. Add a third layer: call puffs again with its own offset, scrolled at rate * 1.7, at half strength, so the streaks do not all fall in lock-step.

You are done when the water falls with three visibly different speeds, and pressing left or right still turns it smoothly without a jump.

Takeaways

  • A shader cannot move pixels; it scrolls by changing where each pixel reads the pattern: pattern(uv - offset).
  • Subtracting the offset moves the pattern by the offset; adding it moves the pattern the other way.
  • offset = time * velocity is enough for a fixed velocity; add up velocity * dt on the CPU when the velocity can change.
  • The pattern must repeat, and the offset should wrap by a whole number of repeats to stay precise.
  • Layers with their own offsets and speeds give parallax; each layer costs one more pattern evaluation or texture sample per pixel.
