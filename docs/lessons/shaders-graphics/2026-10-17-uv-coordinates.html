UV coordinates: one shader for every screen size

Three lines turn pixel positions into UVs: divide by the resolution, move the origin to the centre, and fix the aspect ratio so circles stay round.

You write a shader that draws a glowing circle in the middle of the screen. On your monitor it looks right. On a phone it is a squashed oval, on a 4K screen it is a dot in the corner, and when the player resizes the window it slides off the edge.

The circle was measured in the wrong unit.

Pixels are the wrong unit

A fragment shader is a small function that runs once per pixel and returns a colour. What goes in is the pixel's position, gl_FragCoord.xy, in pixels from the bottom-left corner in WebGL. A rule like "inside if closer than 200 pixels to (400, 300)" means something different on every screen.

The fix is to stop measuring in pixels and measure in fractions of the screen instead. Coordinates measured that way are called UV coordinates, or UVs. By convention the letters u and v are used because x, y and z already name positions in the world. Meshes use the same name for the coordinates that pick which part of a texture to show.

Three lines, three steps

1. Divide by the resolution. vec2 uv = gl_FragCoord.xy / u_resolution; Now the left edge is 0.0 and the right edge is 1.0, and the same for bottom and top, on any screen. A shader written in these units works at any resolution.

2. Move the origin to the centre. uv = uv - 0.5; Now the range is -0.5 to 0.5 and (0, 0) is the middle of the screen. Distance from the middle is now just length(uv).

3. Correct the aspect ratio. After step 1 a horizontal unit is the screen's width and a vertical unit is its height. On a 16:9 screen one step in x covers 1.78 times as many pixels as one step in y, so a circle of radius 0.3 comes out as a wide oval. The aspect ratio is width divided by height. Multiply x by it, uv.x = uv.x * u_resolution.x / u_resolution.y;, and one unit now covers the same number of pixels in both directions. On a 16:9 screen y still runs from -0.5 to 0.5, and x runs from about -0.89 to 0.89.

Steps 1 to 3 are often written as one line, which you will see in many shared shaders. It gives exactly the same numbers:

vec2 uv = (gl_FragCoord.xy - 0.5 * u_resolution) / u_resolution.y;

Which corner is zero, and which way is up

This is where ported shaders go upside down. Each system picks its own origin:

Value(0, 0) isy grows
WebGL gl_FragCoordbottom-leftup
LÖVE screen_coordstop-leftdown
Godot canvas_item UVtop-leftdown
Unity mesh UVs on the built-in Quadbottom-leftup

When the origin is at the top, add uv.y = 1.0 - uv.y; right after step 1 and everything else in this lesson works unchanged.

Rule of thumb

Decide which axis is "1 unit" and say so in a comment. Dividing by the height, as here, means a radius of 0.3 is always 30% of the screen height, however wide the screen is.

Try it

Both fixes start switched off: the circle is a stretched quarter oval in the corner. Switch on Centre the origin, then Correct the aspect ratio, and watch the grid cells (0.1 uv each) become squares. Then shrink the pretend screen with the width and height sliders: with both fixes on, the circle stays round and keeps the same share of the screen height.

The Stage menu shows the values the shader works with. Click or tap the canvas, or focus it and use the arrow keys, to probe one pixel. On stage 1 with centring on, the bottom-left quarter is black: uv is negative there, and negative colours display as zero. The numbers are right; the screen just cannot show them.

The code

The Lua version draws the final stage of the demo across the whole LÖVE window. LÖVE's screen_coords are in pixels from the top-left, so the shader flips y after dividing. A centred circle looks the same either way, but anything above or below the centre would otherwise land on the wrong side.

local radius = 0.3   -- in screen heights, like the Radius slider
local shader

local pixelcode = [[
uniform vec2 u_resolution;
uniform float u_radius;

vec4 effect(vec4 color, Image tex, vec2 texture_coords, vec2 screen_coords)
{
    vec2 uv = screen_coords / u_resolution;            // 1. 0 to 1 at any size
    uv.y = 1.0 - uv.y;                                  // LÖVE counts y from the top
    uv = uv - 0.5;                                      // 2. origin in the middle
    uv.x = uv.x * u_resolution.x / u_resolution.y;      // 3. square units

    float d = length(uv);
    float mask = 1.0 - step(u_radius, d);
    vec3 col = mix(vec3(0.10, 0.12, 0.20), vec3(1.0, 0.55, 0.15), mask);
    return vec4(col, 1.0);
}
]]

function love.load()
  shader = love.graphics.newShader(pixelcode)
end

function love.draw()
  local w, h = love.graphics.getPixelDimensions()   -- screen_coords are in pixels
  shader:send("u_resolution", { w, h })
  shader:send("u_radius", radius)
  love.graphics.setShader(shader)
  love.graphics.rectangle("fill", 0, 0, love.graphics.getDimensions())
  love.graphics.setShader()
end
#ifdef GL_FRAGMENT_PRECISION_HIGH
precision highp float;
#else
precision mediump float;
#endif

uniform vec2 u_resolution;
uniform float u_stage;
uniform float u_centre;
uniform float u_aspect;
uniform float u_radius;
uniform float u_grid;
uniform vec2 u_view;
uniform vec2 u_probe;
uniform float u_dpr;

void main() {
  // Demo only: a pretend screen of any size in the middle of the canvas.
  vec2 size = floor(u_resolution * u_view);
  vec2 corner = floor((u_resolution - size) * 0.5);
  vec2 p = gl_FragCoord.xy - corner;   // pixels from the screen's bottom-left

  // What goes in: a pixel position. Three lines turn it into UVs.
  vec2 uv = p / size;                                  // 1. 0 to 1 at any size
  if (u_centre > 0.5) uv = uv - 0.5;                   // 2. origin in the middle
  if (u_aspect > 0.5) uv.x = uv.x * size.x / size.y;   // 3. square units

  // What comes out: one colour. The Stage menu picks which value to show.
  float d = length(uv);
  float mask = 1.0 - step(u_radius, d);
  vec3 col = vec3(uv, 0.0);
  if (u_stage > 1.5) col = vec3(d);
  if (u_stage > 2.5) col = vec3(mask);
  if (u_stage > 3.5) col = mix(vec3(0.10, 0.12, 0.20), vec3(1.0, 0.55, 0.15), mask);

  // Demo only: grid lines every 0.1 uv units, with the axes stronger.
  vec2 perPx = 1.0 / size;
  if (u_aspect > 0.5) perPx.x = perPx.x * size.x / size.y;
  vec2 halfW = perPx * 0.75 * u_dpr;
  vec2 toLine = abs(fract(uv * 10.0 + 0.5) - 0.5) / 10.0;
  float lines = max(1.0 - step(halfW.x, toLine.x), 1.0 - step(halfW.y, toLine.y));
  float axes = max(1.0 - step(halfW.x * 2.0, abs(uv.x)), 1.0 - step(halfW.y * 2.0, abs(uv.y)));
  float lum = dot(clamp(col, 0.0, 1.0), vec3(0.299, 0.587, 0.114));
  vec3 ink = vec3(1.0 - step(0.5, lum));
  col = mix(col, ink, u_grid * max(lines * 0.35, axes * 0.85));

  // Demo only: hatching outside the pretend screen, and the probe ring.
  vec2 inside = step(vec2(0.0), p) * step(p, size);
  float hatch = step(0.5, fract((gl_FragCoord.x + gl_FragCoord.y) / (12.0 * u_dpr)));
  col = mix(vec3(0.42 + 0.08 * hatch), col, inside.x * inside.y);
  float r = length(gl_FragCoord.xy - u_probe);
  col = mix(col, vec3(0.0), 1.0 - step(1.5 * u_dpr, abs(r - 9.0 * u_dpr)));
  col = mix(col, vec3(1.0), 1.0 - step(1.0 * u_dpr, abs(r - 7.0 * u_dpr)));

  gl_FragColor = vec4(col, 1.0);
}
// Godot 4. Put this in a ShaderMaterial on a ColorRect.
shader_type canvas_item;

uniform float u_radius : hint_range(0.05, 0.5) = 0.3;
// The rect's size in pixels. From GDScript:
// material.set_shader_parameter("rect_size", size)
uniform vec2 rect_size = vec2(640.0, 360.0);

void fragment() {
    vec2 uv = UV;                                   // 1. already 0 to 1 across the rect
    uv.y = 1.0 - uv.y;                              // Godot's UV starts at the top-left
    uv = uv - 0.5;                                  // 2. origin in the middle
    uv.x = uv.x * rect_size.x / rect_size.y;        // 3. square units

    float mask = 1.0 - step(u_radius, length(uv));
    COLOR = vec4(mix(vec3(0.10, 0.12, 0.20), vec3(1.0, 0.55, 0.15), mask), 1.0);
}
// Built-in render pipeline, unlit. Put it on a material and apply it to a Quad.
Shader "GameDevDaily/UVCircle"
{
    Properties
    {
        _Radius ("Radius", Range(0.05, 0.5)) = 0.3
        _Aspect ("Aspect (quad width / height)", Float) = 1.7778
    }
    SubShader
    {
        Tags { "RenderType" = "Opaque" }
        Pass
        {
            CGPROGRAM
            #pragma vertex vert
            #pragma fragment frag
            #include "UnityCG.cginc"

            float _Radius, _Aspect;

            struct v2f
            {
                float4 pos : SV_POSITION;
                float2 uv : TEXCOORD0;
            };

            v2f vert (appdata_base v)
            {
                v2f o;
                o.pos = UnityObjectToClipPos(v.vertex);
                o.uv = v.texcoord.xy;   // 0 to 1 across the Quad, 0,0 at the bottom-left
                return o;
            }

            fixed4 frag (v2f i) : SV_Target
            {
                float2 uv = i.uv - 0.5;          // 2. origin in the middle
                uv.x *= _Aspect;                 // 3. square units
                float mask = 1.0 - step(_Radius, length(uv));
                return fixed4(lerp(float3(0.10, 0.12, 0.20), float3(1.0, 0.55, 0.15), mask), 1.0);
            }
            ENDCG
        }
    }
}

The engine versions start from the mesh's UVs, already 0 to 1 across the rectangle, so step 1 is done. They still need the aspect ratio from outside, because a UV of 1 means "the far edge" at any size. In URP, the same idea in an Unlit Shader Graph is: UV node, Subtract 0.5, Multiply by a Vector2 of (aspect, 1), Length, then Step against a Radius property, and use the result as the T input of a Lerp between two colours going into Base Color.

Pitfalls

  • Correcting the wrong axis for portrait screens. Dividing by the height keeps y from -0.5 to 0.5. On a phone held upright the width is smaller than the height, so x only reaches about ±0.28 and a circle of radius 0.3 is cut off at the sides. Divide by min(u_resolution.x, u_resolution.y) instead if the shape must always fit.
  • Assuming a sprite's UVs run from 0 to 1. When a sprite comes from a texture atlas, its UVs cover only its own small rectangle of the atlas. Centring by subtracting 0.5 then puts the centre somewhere else entirely.
  • Forgetting the flip when porting. Check the origin table above before blaming your maths. An effect that is mirrored top to bottom almost always comes from a missing or extra 1.0 - uv.y.

What it costs

The three lines are a divide, a subtract and a multiply per pixel: next to nothing, even on a phone. To skip the divide, send 1.0 / u_resolution from the CPU and multiply instead.

On phones, watch precision. Pixel coordinates reach several thousand, and mediump floats on many mobile GPUs keep only about three significant digits. The #ifdef at the top of the demo's shader asks for high precision where the device supports it. Precision gets its own lesson later.

In real games

Engines hand shaders UVs from the mesh: UV in Godot, TEXCOORD0 in Unity. Effects on rectangles, such as a cooldown sweep over an ability icon or the fill of a health bar, are written in those 0 to 1 units so they work at any size.

On Shadertoy, where every shader covers the whole canvas, the one-line form above is one of the most common first lines you will read.

Your turn (15 minutes)

Run the Lua version in LÖVE with a resizable window (add function love.conf(t) t.window.resizable = true end to conf.lua). Then:

  1. Delete step 3, resize the window to be very wide, and watch the circle stretch. Put it back.
  2. Make the window taller than it is wide and watch the circle get cut off at the sides. Change step 3 so it divides by the smaller of the two sides.
  3. Add a second, smaller circle at uv (0.0, 0.3), using length(uv - vec2(0.0, 0.3)). Check that it is above the first one, not below.

You are done when both circles stay round, stay inside the window and keep their places at any window shape.

Takeaways

  • UVs measure position as a fraction of the screen or rectangle, so a shader written in them works at any resolution.
  • Subtracting 0.5 puts the origin in the middle, where distance from the centre is just length(uv).
  • Multiplying x by width over height makes one unit the same number of pixels both ways, so circles stay round.
  • WebGL and Unity mesh UVs start at the bottom-left; LÖVE's screen coordinates and Godot's canvas UV start at the top-left.
  • When something looks wrong, show uv as colour. Seeing the numbers is the fastest debugger a shader has.
