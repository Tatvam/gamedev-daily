Blinn-Phong specular: the half vector and the shiny highlight

A highlight appears where the normal lines up with the half vector, halfway between light and eye. A shininess exponent sets how small it is.

With only Lambert diffuse, a billiard ball looks like chalk. A real ball has a small bright spot where it mirrors the lamp, and the spot slides when you walk around the table. That specular highlight costs one more dot product and a power function.

Light that bounces towards the eye

A fragment shader is a small function that runs once per pixel and returns a colour. So far its lighting inputs were the surface normal N and the direction to the light L, whose dot product gave the diffuse term.

Shiny surfaces also reflect light like a blurry mirror. That is the specular term, and it needs a third input: V, the unit vector from the surface towards the eye. Diffuse ignores V, so it stays put when the camera moves. Specular depends on V, so the highlight moves.

Phong: compare the mirror ray with the eye

Bui Tuong Phong's 1975 idea: reflect the light about the normal to get the mirror ray R. The closer R points to the eye, the brighter the pixel. In GLSL that is R = reflect(-L, N) and then R·V.

Blinn: compare the normal with the half vector

Jim Blinn, in 1977, asked instead: which normal would mirror the light exactly into the eye? A mirror sends light out at the angle it came in, so that normal sits halfway between L and V:

H = normalize(L + V)        -- the half vector

H is the half vector, and N·H measures how close each pixel's normal comes to it. Phong's model with this swap is called Blinn-Phong.

Both put the highlight's centre in the same place, because R = V exactly when N = H. But the angle between N and H is half the angle between R and V, so N·H falls off more slowly. A Blinn-Phong exponent must be about four times the Phong one for a highlight of similar size.

Shininess: an exponent that squeezes

N·H alone is a broad glow over half the ball. Raise it to a power s, the shininess. Only values very near 1 survive a large power, so a big s keeps only pixels whose normal is almost exactly H.

Four lines on top of the diffuse shader, each a stage in the demo:

diffuse = max(N·L, 0)                         -- from the Lambert lesson
H       = normalize(L + V)                    -- 1. halfway between light and eye
base    = max(N·H, 0)                         -- 2. how close is N to H?
spec    = pow(base, s) * step(0, N·L)         -- 3. squeeze it; no light, no highlight
colour  = albedo * (diffuse + ambient)
        + strength * spec                     -- 4. add it, uncoloured, on top

step(0, N·L) keeps highlights off the side the light cannot reach. The highlight is not multiplied by the albedo: red plastic shows a white highlight, because its surface reflects the light's own colour. Only metals tint their highlights.

Axes, the eye and colour space

The demo uses x right, y up and z out of the screen, with gl_FragCoord's (0, 0) at the bottom-left. The camera looks straight in, so V = (0, 0, 1) everywhere; in a 3D engine V is the normalised vector from each surface point to the camera. LÖVE's screen_coords and Godot's UV start at the top-left with y down, so the code tabs flip y. Colours go to the screen without gamma conversion, and values over 1 clip to white.

Try it

Drag on the canvas, or use the arrow keys, to move the sun. The white cross marks where N = V, the white square where N = L, and the blue ring where N = H. The ring stays halfway between them, and the highlight stays on the ring.

On stage 3 you see the broad N·H glow; on stage 4, what the exponent keeps of it as you slide Shininess. Switch Model to Phong and the highlight shrinks to about half its width; a quarter of the shininess matches it again. At shininess 1 with the sun low, Blinn-Phong's glow ends at a hard edge, cut by step(0, N·L), while Phong's fades out.

The code

In LÖVE the shader is a string with the effect entry point, drawn over the window. The mouse sets L. Hold space for Phong, press [ or ] to halve or double the shininess, and hold up or down to move the light.

local RADIUS = 0.38                  -- sphere radius, as a fraction of the window height
local albedo = { 0.8, 0.25, 0.2 }    -- surface colour
local ambient = 0.1
local shininess = 32                 -- the exponent s
local strength = 0.6                 -- highlight brightness
local height = 1.0                   -- light height above the screen, in sphere radii
local shader

local pixelcode = [[
uniform vec2 u_resolution;
uniform vec3 u_light;        // unit vector towards the light
uniform vec3 u_albedo;
uniform float u_ambient;
uniform float u_shininess;
uniform float u_strength;
uniform float u_phong;       // 0 = Blinn-Phong, 1 = Phong
const float RADIUS = 0.38;

vec4 effect(vec4 color, Image tex, vec2 texture_coords, vec2 screen_coords)
{
  vec2 p = (screen_coords - 0.5 * u_resolution) / u_resolution.y / RADIUS;
  p.y = -p.y;                                  // LÖVE's y grows downwards: make it grow up
  float aa = 1.5 / (u_resolution.y * RADIUS);
  float mask = 1.0 - smoothstep(1.0 - aa, 1.0, length(p));
  vec3 n = vec3(p, sqrt(max(1.0 - dot(p, p), 0.0)));
  float ndotl = dot(n, u_light);
  float diffuse = max(ndotl, 0.0);

  vec3 v = vec3(0.0, 0.0, 1.0);                // towards the eye
  vec3 hv = u_light + v;
  vec3 h = hv / max(length(hv), 0.0001);       // the half vector
  float blinn = max(dot(n, h), 0.0);
  float phong = max(dot(reflect(-u_light, n), v), 0.0);
  float spec = pow(mix(blinn, phong, u_phong), u_shininess) * step(0.0, ndotl);

  vec3 col = u_albedo * (diffuse + u_ambient) + vec3(u_strength * spec);
  vec3 bg = vec3(0.1, 0.11, 0.14);
  return vec4(mix(bg, col, mask), 1.0) * color;
}
]]

local function normalize(x, y, z)
  local len = math.sqrt(x * x + y * y + z * z)
  if len < 1e-6 then return 0, 0, 1 end
  return x / len, y / len, z / len
end

function love.load()
  shader = love.graphics.newShader(pixelcode)
end

function love.keypressed(key)
  if key == "]" then shininess = math.min(shininess * 2, 256) end
  if key == "[" then shininess = math.max(shininess / 2, 1) end
end

function love.update(dt)
  if love.keyboard.isDown("up") then height = height + dt end
  if love.keyboard.isDown("down") then height = height - dt end
end

function love.draw()
  local w, h = love.graphics.getDimensions()
  local mx, my = love.mouse.getPosition()
  local lightX = (mx - 0.5 * w) / h / RADIUS
  local lightY = -(my - 0.5 * h) / h / RADIUS  -- flip: screen y goes down
  local lx, ly, lz = normalize(lightX, lightY, height)
  shader:send("u_light", { lx, ly, lz })
  shader:send("u_resolution", { love.graphics.getPixelDimensions() })
  shader:send("u_albedo", albedo)
  shader:send("u_ambient", ambient)
  shader:send("u_shininess", shininess)
  shader:send("u_strength", strength)
  shader:send("u_phong", love.keyboard.isDown("space") and 1 or 0)
  love.graphics.setShader(shader)
  love.graphics.rectangle("fill", 0, 0, w, h)
  love.graphics.setShader()
  love.graphics.print("shininess " .. shininess, 10, 10)
end
precision mediump float;

uniform vec2 u_resolution;
uniform vec3 u_light;       // unit vector from the surface towards the light
uniform vec2 u_lightPos;    // where the sun marker is drawn, device pixels, origin bottom-left
uniform float u_shininess;  // the exponent s: bigger means a smaller, tighter highlight
uniform float u_strength;   // how bright the highlight is at its centre
uniform float u_phong;      // 0 = Blinn-Phong (N.H), 1 = Phong (R.V)
uniform float u_stage;      // 0 normals ... 4 final colour
uniform float u_marks;      // 1 = draw the N = V, N = L and N = H markers

const float RADIUS = 0.38;               // sphere radius, as a fraction of the canvas height
const vec3 ALBEDO = vec3(0.8, 0.25, 0.2); // surface colour
const float AMBIENT = 0.1;
const vec3 V = vec3(0.0, 0.0, 1.0);      // towards the eye: the camera looks straight at the screen

void main() {
  // the sphere and its Lambert diffuse, as in the last two lessons
  vec2 p = (gl_FragCoord.xy - 0.5 * u_resolution) / u_resolution.y / RADIUS;
  float aa = 1.5 / (u_resolution.y * RADIUS);
  float mask = 1.0 - smoothstep(1.0 - aa, 1.0, length(p));
  vec3 n = vec3(p, sqrt(max(1.0 - dot(p, p), 0.0)));
  float ndotl = dot(n, u_light);
  float diffuse = max(ndotl, 0.0);

  // 1. the half vector: halfway between the light and the eye
  vec3 hv = u_light + V;
  vec3 h = hv / max(length(hv), 0.0001);
  // 2. how closely the normal lines up with it (Blinn), or the mirror ray with the eye (Phong)
  float blinn = max(dot(n, h), 0.0);
  float phong = max(dot(reflect(-u_light, n), V), 0.0);
  float base = mix(blinn, phong, u_phong);
  // 3. the exponent squeezes the broad glow into a small highlight; no light, no highlight
  float spec = pow(base, u_shininess) * step(0.0, ndotl);
  // 4. add it, uncoloured, on top of the diffuse colour
  vec3 col = ALBEDO * (diffuse + AMBIENT) + vec3(u_strength * spec);

  vec3 bg = vec3(0.1, 0.11, 0.14);
  if (u_stage < 3.5) col = vec3(spec);
  if (u_stage < 2.5) col = vec3(base);
  if (u_stage < 1.5) col = vec3(diffuse);
  if (u_stage < 0.5) col = n * 0.5 + 0.5;
  col = mix(bg, col, mask);

  // markers: a cross where N = V, a square where N = L, a ring where N = H
  float lw = max(1.0, u_resolution.y / 300.0);
  vec2 dv = gl_FragCoord.xy - 0.5 * u_resolution;
  float crossLine = 1.0 - smoothstep(0.5 * lw, 1.2 * lw, min(abs(dv.x), abs(dv.y)));
  float crossMark = crossLine * (1.0 - step(6.0 * lw, max(abs(dv.x), abs(dv.y))));
  vec2 dl = gl_FragCoord.xy - (0.5 * u_resolution + u_light.xy * RADIUS * u_resolution.y);
  float square = 1.0 - smoothstep(0.7 * lw, 1.5 * lw, abs(max(abs(dl.x), abs(dl.y)) - 5.0 * lw));
  float front = step(0.0, u_light.z);
  vec2 dh = gl_FragCoord.xy - (0.5 * u_resolution + h.xy * RADIUS * u_resolution.y);
  float ring = 1.0 - smoothstep(0.7 * lw, 1.5 * lw, abs(length(dh) - 6.0 * lw));
  col = mix(col, vec3(1.0), u_marks * crossMark);
  col = mix(col, vec3(1.0), u_marks * front * square);
  col = mix(col, vec3(0.2, 0.85, 1.0), u_marks * ring);

  // the sun marker: filled when the light is in front, hollow when it is behind
  float d = length(gl_FragCoord.xy - u_lightPos);
  vec3 sun = vec3(1.0, 0.82, 0.25);
  col = mix(col, vec3(0.0), 1.0 - smoothstep(lw, 2.0 * lw, abs(d - 8.5 * lw)));
  col = mix(col, sun, 1.0 - smoothstep(0.7 * lw, 1.5 * lw, abs(d - 6.5 * lw)));
  col = mix(col, sun, front * (1.0 - smoothstep(4.5 * lw, 5.5 * lw, d)));
  gl_FragColor = vec4(col, 1.0);
}
// Godot 4, a ShaderMaterial on a square ColorRect. The sphere fills the rect.
shader_type canvas_item;

uniform vec3 albedo : source_color = vec3(0.8, 0.25, 0.2);
uniform vec3 light_dir = vec3(0.6, 0.6, 1.0);   // towards the light, x right, y up, z out
uniform float shininess : hint_range(1.0, 256.0) = 32.0;
uniform float strength : hint_range(0.0, 1.0) = 0.6;
uniform float ambient : hint_range(0.0, 0.5) = 0.1;

void fragment() {
    vec2 p = UV * 2.0 - 1.0;
    p.y = -p.y;                     // Godot's UV (0, 0) is the top-left, y grows down
    float aa = fwidth(length(p));
    float mask = 1.0 - smoothstep(1.0 - aa, 1.0, length(p));
    vec3 n = vec3(p, sqrt(max(1.0 - dot(p, p), 0.0)));
    vec3 l = normalize(light_dir);
    float ndotl = dot(n, l);
    vec3 h = normalize(l + vec3(0.0, 0.0, 1.0));
    float spec = pow(max(dot(n, h), 0.0), shininess) * step(0.0, ndotl);
    vec3 col = albedo * (max(ndotl, 0.0) + ambient) + vec3(strength * spec);
    COLOR = vec4(col, mask);        // transparent outside the disc
}

// The light direction is in the quad's own 2D convention (x right, y up, z out of the
// quad towards the viewer), not in Unity's world space.
Shader "GameDevDaily/BlinnPhongSphere"
{
    Properties
    {
        _Albedo ("Albedo", Color) = (0.8, 0.25, 0.2, 1)
        _LightDir ("Direction to light", Vector) = (0.6, 0.6, 1, 0)
        _Shininess ("Shininess", Range(1, 256)) = 32
        _Strength ("Specular strength", Range(0, 1)) = 0.6
        _Ambient ("Ambient", Range(0, 0.5)) = 0.1
    }
    SubShader
    {
        Tags { "RenderType" = "Opaque" }
        Pass
        {
            CGPROGRAM
            #pragma vertex vert_img
            #pragma fragment frag
            #include "UnityCG.cginc"

            fixed4 _Albedo;
            float4 _LightDir;
            float _Shininess;
            float _Strength;
            float _Ambient;

            fixed4 frag (v2f_img i) : SV_Target
            {
                float2 p = i.uv * 2.0 - 1.0;    // uv (0, 0) is the bottom-left: y is already up
                float aa = fwidth(length(p));
                float mask = 1.0 - smoothstep(1.0 - aa, 1.0, length(p));
                float3 n = float3(p, sqrt(max(1.0 - dot(p, p), 0.0)));
                float3 l = normalize(_LightDir.xyz);
                float ndotl = dot(n, l);
                float3 h = normalize(l + float3(0.0, 0.0, 1.0));
                float spec = pow(max(dot(n, h), 0.0), _Shininess) * step(0.0, ndotl);
                float3 col = _Albedo.rgb * (max(ndotl, 0.0) + _Ambient) + _Strength * spec;
                float3 bg = float3(0.1, 0.11, 0.14);
                return fixed4(lerp(bg, col, mask), 1.0);
            }
            ENDCG
        }
    }
}

On real meshes V comes from the camera. In a Godot spatial shader's light() function it is the built-in VIEW, from the fragment to the camera, and the result goes into SPECULAR_LIGHT. In Unity's Built-in pipeline, #pragma surface surf BlinnPhong gives this model, coloured by a _SpecColor property.

Pitfalls

  • Using the wrong V. V points from the surface to the eye. The camera's forward vector points the other way. With a perspective camera, work V out per pixel.
  • A highlight on the dark side. N·H can be positive where N·L is negative. Multiply by step(0.0, N·L), or by N·L itself, which avoids a hard edge at low shininess.
  • Reusing a Phong exponent. At the same s, Blinn-Phong highlights are much bigger. Multiply s by about 4.
  • Shininess that dims the material. A higher s makes the highlight smaller but not brighter. Real-Time Rendering describes a normalisation factor of about (s + 8) / 8π that brightens tight highlights, a first step towards physically based shading.
  • pow of a negative number. GLSL leaves pow(x, y) undefined for x < 0, so clamp the base first.

What it costs

Per light, Blinn-Phong adds a normalise, a dot product and a pow (usually a log and an exponent on the GPU). That is cheap on a phone, but paid per light per pixel. Precision matters more. On phones mediump is often a 16-bit float, which steps by about 0.0005 near 1; at s = 256 one step dims the highlight by about 12%, so tight highlights band. Use highp for N·H if you see rings. With a directional light and a distant viewer, as here, H is the same for every pixel, so you can compute it once on the CPU.

In real games

The fixed-function lighting in OpenGL, used before programmable shaders, computed specular from the half vector raised to the material's GL_SHININESS, which could go up to 128. Unity's Built-in surface shaders still offer BlinnPhong as a named lighting model beside Lambert. Godot 3's SpatialMaterial had Blinn and Phong specular modes.

Your turn (15 minutes)

Start from the LÖVE program.

  1. Add a u_specColor uniform that multiplies the highlight. Try gold (1.0, 0.8, 0.4) with a near-black albedo: the ball should read as metal.
  2. Hold space and find the Phong shininess that best matches Blinn-Phong at s = 64. It should be near 16.
  3. Compute H once per frame in Lua from L and (0, 0, 1), send it as a uniform, and delete the half vector lines from the shader.

You are done when the picture with H computed in Lua matches the one computed in the shader.

Takeaways

  • Specular light depends on the view direction V, so highlights move with the camera and diffuse shading does not.
  • The half vector H = normalize(L + V) is the normal that would mirror the light into the eye. N·H says how close each pixel comes.
  • pow(max(N·H, 0), s) turns that into a highlight. Bigger s, smaller highlight.
  • Phong's R·V puts the highlight in the same place, but needs about a quarter of the exponent for the same size.
