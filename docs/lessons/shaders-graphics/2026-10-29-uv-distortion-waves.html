UV distortion: bending a pattern with a wave

Add a sine wave to the UV before drawing and everything drawn with it bends: sways, wobbles and ripples from one line, plus the limit where it folds.

Air shimmers above a campfire. The level wobbles when the hero dives underwater. A banner sways in the wind although it is a single flat quad. None of these needs to move a vertex. Each one can bend the picture inside the shader, and the bend is one line long.

Move where the pixel reads, not the pixel

A fragment shader is a small function that runs once per pixel and returns a colour. It cannot move its pixel, but it can change the question it asks. Normally a pixel at uv asks "what does the pattern look like here?". With UV distortion it asks about a slightly different point:

vec2 q = uv + off;     // read the pattern from here instead

Everything drawn afterwards uses q: the checkerboard, the circle, a texture lookup. If off is the same everywhere the picture just slides, as in the scrolling lesson. If it changes from place to place, the picture bends.

The offset is a wave

The usual choice is a sine wave of the other coordinate. To make each row slide sideways by a different amount:

float wave(float x) {
  return u_amp * sin(TWO_PI * (u_freq * x - u_phase));
}
vec2 off = vec2(wave(uv.y), 0.0);   // the shift depends on the height

The amplitude u_amp is the largest shift in UV units; 0.03 is three percent of the screen height. The frequency u_freq is how many waves fit into one UV unit. The phase u_phase slides the wave along, so increasing it makes the bend travel. The 2π turns waves into the radians sin expects.

That surprises everyone once: a pixel that reads from its right shows what was to its right, so the picture moves the opposite way to the offset. Flip the sign of u_amp for the other direction.

Three shapes of wave

  • Sway. vec2(wave(uv.y), 0.0): rows slide sideways. Flags, banners, heat haze.
  • Both axes. vec2(wave(uv.y), wave(uv.x)): rows slide sideways and columns slide up and down. An underwater wobble.
  • Ripple. Push along the direction away from the centre by a wave of the radius: normalize(uv) * wave(length(uv)). Rings spread out, like a stone dropped in a pond. Guard the centre, where the direction is undefined. Within one amplitude of the centre the ripple can also pull pixels right through it, so keep the amplitude small or fade it in with the radius.

Keep the phase on the CPU

The tempting version is u_phase = u_time * speed. It works until the speed changes: after 65 seconds at speed 0.5, nudging the speed to 0.6 adds 6.5 waves to the phase at once, and that half wave shows as a sudden jump. Instead, add speed * dt to the phase every frame and wrap it back into 0 to 1. The sine repeats every wave, so wrapping changes nothing on screen, and the shader never sees a huge number that low-precision phone GPUs would round.

Rule of thumb

Keep 2π × frequency × amplitude below 1. Past that, the both-axes and ripple waves push neighbouring pixels past each other and the pattern folds into mirrored creases. A sway only shears rows sideways, so it never folds, but steep slopes still look smeared.

The code

The Lua version runs the demo's shader in LÖVE, whose pixel shaders use the entry point effect instead of main. Click to place the probe. Left and right change the frequency, up and down the amplitude, M cycles the wave, G toggles the grid and S cycles the stage.

-- The demo's starting values. Centred uv: (0, 0) in the middle, y up.
local amp = 0.03            -- largest shift, in uv units
local freq = 3              -- waves per uv unit
local speed = 0.5           -- waves per second
local phase = 0             -- waves travelled, kept between 0 and 1
local mode = 0              -- 0 sway, 1 both axes, 2 ripple
local stage = 4             -- 0 uv, 1 offset, 2 bent uv, 3 mask, 4 final
local grid = 0              -- 1 draws the undistorted grid on top
local probe = { 0.3, 0.15 } -- in uv units
local rect = { 20, 20, 640, 360 }   -- x, y, width, height in pixels
local shader

local pixelcode = [[
uniform float u_amp;      // largest shift, in uv units
uniform float u_freq;     // waves per uv unit
uniform float u_phase;    // waves travelled, 0 to 1
uniform float u_mode;     // 0 sway, 1 both axes, 2 ripple
uniform float u_stage;
uniform float u_grid;     // 1.0 draws the undistorted grid on top
uniform vec2 u_probe;     // centred uv of the probe
uniform vec4 u_rect;      // x, y, width, height in pixels

const float TWO_PI = 6.2831853;
const float CELLS = 6.0;  // checker cells per uv unit

float wave(float x) {
  return u_amp * sin(TWO_PI * (u_freq * x - u_phase));
}

vec2 offsetAt(vec2 uv) {
  if (u_mode > 1.5) {                                // ripple: push along the radius
    float r = length(uv);
    vec2 dir = r > 0.0001 ? uv / r : vec2(0.0);      // no direction at the centre
    return dir * wave(r);
  }
  if (u_mode > 0.5) return vec2(wave(uv.y), wave(uv.x));   // both axes
  return vec2(wave(uv.y), 0.0);                      // sway: rows slide sideways
}

float checker(vec2 q, float aa) {
  vec2 c = abs(fract(q * CELLS * 0.5 + 0.25) - 0.5) * 2.0 - 0.5;  // signed, cell units
  float d = min(abs(c.x), abs(c.y)) / CELLS;        // to the nearest cell edge, uv units
  return smoothstep(-aa, aa, sign(c.x * c.y) * d);
}

vec3 shade(vec2 uv, float aa) {
  vec2 off = offsetAt(uv);
  vec2 q = uv + off;                                 // read the pattern from here instead
  float mask = checker(q, aa);
  float d = length(q) - 0.2;                         // a disc, drawn with q too
  vec3 col = mix(vec3(0.16, 0.2, 0.3), vec3(0.84, 0.86, 0.9), mask);
  col = mix(col, vec3(0.1, 0.08, 0.06), 1.0 - smoothstep(-aa, aa, d - 0.012));
  col = mix(col, vec3(1.0, 0.62, 0.2), 1.0 - smoothstep(-aa, aa, d));

  if (u_stage < 3.5) col = vec3(mask);
  if (u_stage < 2.5) col = vec3(fract(q * 4.0), 0.0);
  if (u_stage < 1.5) col = vec3(0.5 + 0.5 * off / max(abs(u_amp), 0.0001), 0.5);
  if (u_stage < 0.5) col = vec3(uv + 0.5, 0.0);

  if (u_grid > 0.5) {
    vec2 g = abs(fract(uv * CELLS + 0.5) - 0.5) / CELLS;   // to the nearest straight line
    float gd = min(g.x, g.y);
    col = mix(col, vec3(0.2, 0.85, 1.0), 1.0 - smoothstep(0.5 * aa, 1.5 * aa, gd));
  }

  vec2 a = u_probe;                                  // the probe pixel
  vec2 ba = offsetAt(u_probe);                       // from it to where it reads
  float bb = dot(ba, ba);
  float h = bb > 0.0 ? clamp(dot(uv - a, ba) / bb, 0.0, 1.0) : 0.0;
  float seg = length(uv - a - ba * h);
  col = mix(col, vec3(0.0), 1.0 - smoothstep(1.5 * aa, 3.0 * aa, seg));
  col = mix(col, vec3(1.0), 1.0 - smoothstep(0.5 * aa, 1.5 * aa, seg));
  float pd = length(uv - a) - 0.012;
  col = mix(col, vec3(0.0), 1.0 - smoothstep(aa, 2.5 * aa, pd));
  col = mix(col, vec3(1.0), 1.0 - smoothstep(-aa, aa, pd));
  float rd = abs(length(uv - a - ba) - 0.016);
  col = mix(col, vec3(0.0), 1.0 - smoothstep(1.5 * aa, 3.0 * aa, rd));
  col = mix(col, vec3(1.0, 0.85, 0.2), 1.0 - smoothstep(0.5 * aa, 1.5 * aa, rd));
  return col;
}

vec4 effect(vec4 color, Image tex, vec2 texture_coords, vec2 screen_coords)
{
  vec2 uv = (screen_coords - u_rect.xy - 0.5 * u_rect.zw) / u_rect.w;
  uv.y = -uv.y;                      // y points down here; make it point up
  float aa = 1.0 / u_rect.w;         // one pixel, in uv units
  return vec4(shade(uv, aa), 1.0);
}
]]

function love.load()
  shader = love.graphics.newShader(pixelcode)
end

function love.update(dt)
  phase = phase + speed * dt
  phase = phase - math.floor(phase)   -- wrap into 0 to 1; the sine does not notice
end

function love.keypressed(key)
  if key == "right" then freq = math.min(10, freq + 0.5) end
  if key == "left" then freq = math.max(0.5, freq - 0.5) end
  if key == "up" then amp = math.min(0.1, amp + 0.005) end
  if key == "down" then amp = math.max(0, amp - 0.005) end
  if key == "m" then mode = (mode + 1) % 3 end
  if key == "g" then grid = 1 - grid end
  if key == "s" then stage = (stage + 1) % 5 end
end

function love.mousepressed(x, y, button)
  -- screen pixels to centred uv with y up: the same maths as the shader
  probe[1] = (x - rect[1] - 0.5 * rect[3]) / rect[4]
  probe[2] = -(y - rect[2] - 0.5 * rect[4]) / rect[4]
end

function love.draw()
  shader:send("u_amp", amp)
  shader:send("u_freq", freq)
  shader:send("u_phase", phase)
  shader:send("u_mode", mode)
  shader:send("u_stage", stage)
  shader:send("u_grid", grid)
  shader:send("u_probe", probe)
  shader:send("u_rect", rect)
  love.graphics.setShader(shader)
  love.graphics.rectangle("fill", rect[1], rect[2], rect[3], rect[4])
  love.graphics.setShader()
end

void main() {
  vec2 px = gl_FragCoord.xy;                             // pixels, origin bottom-left
  vec2 uv = (px - 0.5 * u_resolution) / u_resolution.y;  // centred, y up
  float aa = 1.0 / u_resolution.y;                       // one pixel, in uv units
  gl_FragColor = vec4(shade(uv, aa), 1.0);

// Godot 4. Sways a sprite's own texture, the "Sway" wave from the demo.
// Put this in a ShaderMaterial on a Sprite2D.
shader_type canvas_item;

uniform float amplitude = 0.03;   // largest shift, in UV units (fraction of the sprite)
uniform float frequency = 3.0;    // waves per UV unit
uniform float speed = 0.5;        // waves per second

void fragment() {
    float phase = speed * TIME;   // fine while speed stays constant
    float shift = amplitude * sin(6.2831853 * (frequency * UV.y - phase));
    COLOR = texture(TEXTURE, UV + vec2(shift, 0.0));
}
// Built-in render pipeline, unlit. Sways the texture on a Quad, the "Sway" wave from the demo.
Shader "GameDevDaily/WaveSway"
{
    Properties
    {
        _MainTex ("Texture", 2D) = "white" {}
        _Amplitude ("Amplitude (uv units)", Float) = 0.03
        _Frequency ("Frequency (waves per uv unit)", Float) = 3
        _Speed ("Speed (waves per second)", Float) = 0.5
    }
    SubShader
    {
        Tags { "RenderType" = "Opaque" }
        Pass
        {
            CGPROGRAM
            #pragma vertex vert
            #pragma fragment frag
            #include "UnityCG.cginc"

            sampler2D _MainTex;
            float4 _MainTex_ST;
            float _Amplitude, _Frequency, _Speed;

            struct v2f
            {
                float4 pos : SV_POSITION;
                float2 uv : TEXCOORD0;
            };

            v2f vert (appdata_base v)
            {
                v2f o;
                o.pos = UnityObjectToClipPos(v.vertex);
                o.uv = TRANSFORM_TEX(v.texcoord, _MainTex);
                return o;
            }

            fixed4 frag (v2f i) : SV_Target
            {
                float phase = _Speed * _Time.y;   // _Time.y is seconds since load
                float shift = _Amplitude * sin(6.2831853 * (_Frequency * i.uv.y - phase));
                return tex2D(_MainTex, i.uv + float2(shift, 0.0));
            }
            ENDCG
        }
    }
}

The engine versions bend a texture instead of a pattern made from maths, which is what you will do most often. In LÖVE that is Texel(tex, texture_coords + off).

Which way is up matters. WebGL's gl_FragCoord and a Unity Quad's uv start at the bottom-left with y up, so a wave of y - phase travels upwards. Godot's canvas_item UV and LÖVE's screen_coords start at the top-left with y down, so the same formula travels downwards unless you flip y, as the Lua version does. In URP Shader Graph, build the same thing from a Time, a Sine and an Add into the UV input of Sample Texture 2D.

Pitfalls

  • Reading past the edge. Near the border of a sprite, UV + offset lands outside 0 to 1, and depending on the wrap mode you see the opposite edge or a smeared stripe. Leave a transparent margin at least as wide as the amplitude.
  • Amplitude in the wrong units. In a sprite shader, UV units are fractions of the sprite, so the same amplitude wobbles a small sprite less.
  • Folding. In the both-axes and ripple waves, past 2π × frequency × amplitude = 1, two neighbouring pixels read from points that have crossed over, and the image mirrors itself. The demo's readout shows that number.
  • Phase from raw time. speed * time jumps when the speed changes and loses precision after a long session. Accumulate and wrap the phase on the CPU.

What it costs

The wave itself is cheap: one sin and a few multiply-adds per pixel, fine on any phone. Sampling a texture at a UV the fragment shader computed is a dependent texture read: the GPU cannot fetch the texel ahead of time. Apple's older OpenGL ES guidance for iOS warned that this was slower on the GPUs of that time; on recent hardware the difference is usually small. Distorting the whole screen also means drawing the scene to a texture first, a full-screen pass covered in the post-processing track.

In real games

Wave distortion of UVs is a standard building block: heat shimmer, underwater wobble, swaying flags and grass on flat quads, magic portals. Many games use scrolling noise as the offset instead of a sine wave, which hides the regular pattern.

In Godot, a hint_screen_texture sampler reads what has already been drawn, and offsetting its UV distorts the scene behind an object, such as the air behind a heat haze sprite. Unity's Shader Graph has ready-made distortion nodes such as Twirl, Spherize and Radial Shear.

Your turn (15 minutes)

Start from the LÖVE example and turn the sway into heat haze over a campfire:

  1. Make the shimmer strongest at the bottom and gone at the top: multiply the sway by 1.0 - smoothstep(-0.5, 0.5, uv.y) inside offsetAt. (Do not swap the edges of smoothstep instead; GLSL leaves the result undefined when the first edge is not below the second.)
  2. Add a second, faster wave with a different frequency, for example 7 waves per unit at a third of the amplitude, so the motion stops looking regular.

You are done when the bottom rows of the checker wobble, the top rows stay straight, and the motion no longer repeats in an obvious rhythm.

Takeaways

  • A shader cannot move pixels; it bends a picture by reading the pattern from q = uv + offset.
  • A sine of the other coordinate makes the offset: amplitude sets how far, frequency how many waves, phase where they are.
  • The picture moves the opposite way to the offset.
  • Keep 2π × frequency × amplitude below 1 to avoid folds, and accumulate the phase on the CPU.
  • The wave is cheap; a dependent texture read can cost more on old phones.
