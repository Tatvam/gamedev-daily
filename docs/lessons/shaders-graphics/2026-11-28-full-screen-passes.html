Full-screen passes: one shader over the whole frame

Draw the game into a texture, then draw that texture over the screen through one shader: the pattern behind every post-processing effect.

The player dies and the whole world drains to grey. A flashback turns everything sepia. You could add greyscale to every sprite, tile and particle shader, but you would miss one. A full-screen pass does it once, for everything, after the frame is drawn.

Draw the frame twice: once into a texture, once through a shader

A fragment shader is a small function that runs once per pixel and returns a colour. Until now, its inputs were coordinates and a few uniforms. A full-screen pass gives it one more input: the colour the game already drew at this pixel.

To get that colour, the frame is drawn in two passes. A pass is one round of drawing into one target.

  1. Pass 1: draw the game as usual, but into an off-screen texture instead of the screen. A texture you can draw into is called a render target; LÖVE calls it a Canvas, Godot a Viewport or the screen texture, Unity a RenderTexture.
  2. Pass 2: draw one shape that covers the whole screen, usually a quad made of two triangles, textured with that render target and drawn with your post-processing shader. The shape covers every pixel, so the shader runs once for every pixel on screen.

What goes in, what comes out

Inside the pass, the shader for one pixel does three things: work out its screen UV (0 to 1 across the screen), read the frame texture at that UV, and return a changed colour.

vec2 uv = gl_FragCoord.xy / u_resolution;   // where am I on screen, 0 to 1
vec3 src = texture2D(u_frame, uv).rgb;      // what the game drew here
gl_FragColor = vec4(post(src), 1.0);        // what I want it to be

The simplest effects only need src. Take a green ground pixel, (0.25, 0.60, 0.30):

  • Invert is 1.0 - src, which gives (0.75, 0.40, 0.70), a pink.
  • Greyscale is a weighted average: dot(src, vec3(0.2126, 0.7152, 0.0722)), which gives about 0.50 in all three channels. Green weighs most because our eyes are most sensitive to it.
  • Sepia is three weighted averages, one per output channel, that lean towards brown.

A strength uniform blends between the two with mix(src, post(src), u_strength), so the world can fade to grey over a second instead of switching at once.

Origins and why they do not matter yet

WebGL's gl_FragCoord has (0, 0) at the bottom-left. LÖVE's texture coordinates and Godot's SCREEN_UV start at the top-left. In a pass that reads the texel at the same UV it writes, that makes no difference: the picture is read and written the same way up. It starts to matter when you offset the lookup, as blur and chromatic aberration do. In Unity, a render texture can be stored upside down on some graphics APIs; Graphics.Blit handles that for a simple pass like this one.

The code

In LÖVE the render target is a Canvas. Draw the scene into it, switch back to the screen, then draw the canvas through the post shader. The HUD is drawn last, without the shader. Press space to cycle the effects.

local effect = 2             -- 0 none, 1 invert, 2 greyscale, 3 sepia
local strength = 1.0         -- 0 = untouched, 1 = full effect
local time = 0
local frame                  -- the render target: a Canvas the size of the window
local post

local pixelcode = [[
uniform float u_effect;
uniform float u_strength;

vec3 post(vec3 c)
{
  if (u_effect > 2.5) {
    return min(vec3(dot(c, vec3(0.393, 0.769, 0.189)),
                    dot(c, vec3(0.349, 0.686, 0.168)),
                    dot(c, vec3(0.272, 0.534, 0.131))), 1.0);
  }
  if (u_effect > 1.5) return vec3(dot(c, vec3(0.2126, 0.7152, 0.0722)));
  if (u_effect > 0.5) return 1.0 - c;
  return c;
}

vec4 effect(vec4 color, Image tex, vec2 texture_coords, vec2 screen_coords)
{
  vec4 src = Texel(tex, texture_coords);       // what the game drew here
  return vec4(mix(src.rgb, post(src.rgb), u_strength), src.a) * color;
}
]]

function love.load()
  frame = love.graphics.newCanvas()
  post = love.graphics.newShader(pixelcode)
end

function love.keypressed(key)
  if key == "space" then effect = (effect + 1) % 4 end
end

function love.update(dt)
  time = time + dt
end

local function drawScene(w, h)
  love.graphics.clear(0.25, 0.45, 0.85)                        -- sky
  love.graphics.setColor(1.00, 0.85, 0.25)
  love.graphics.circle("fill", 0.25 * w, 0.28 * h, 0.12 * h)   -- sun
  love.graphics.setColor(0.25, 0.60, 0.30)
  love.graphics.rectangle("fill", 0, 0.7 * h, w, 0.3 * h)      -- ground
  local bx = (0.5 + 0.3 * math.sin(time * 0.7)) * w
  local by = (0.63 - 0.4 * math.abs(math.sin(time * 2.2))) * h
  love.graphics.setColor(0.90, 0.20, 0.25)
  love.graphics.circle("fill", bx, by, 0.07 * h)               -- bouncing ball
end

local function drawHud(h)
  love.graphics.setColor(0.10, 0.10, 0.12)
  love.graphics.rectangle("fill", 0.05 * h, 0.08 * h, 0.4 * h, 0.06 * h)
  love.graphics.setColor(0.95, 0.25, 0.45)
  love.graphics.rectangle("fill", 0.06 * h, 0.09 * h, 0.266 * h, 0.04 * h)
end

function love.draw()
  local w, h = love.graphics.getDimensions()
  love.graphics.setCanvas(frame)          -- pass 1: into the texture
  drawScene(w, h)
  love.graphics.setCanvas()                 -- back to the screen
  love.graphics.setColor(1, 1, 1)
  post:send("u_effect", effect)
  post:send("u_strength", strength)
  love.graphics.setShader(post)           -- pass 2: the whole frame, once
  love.graphics.draw(frame, 0, 0)
  love.graphics.setShader()
  drawHud(h)                                -- after the pass: stays in colour
  love.graphics.setColor(1, 1, 1)
end
precision mediump float;

uniform vec2 u_resolution;
uniform vec2 u_ball;         // ball centre: x as a fraction of the width, y in screen heights
uniform float u_effect;      // 0 none, 1 invert, 2 greyscale, 3 sepia
uniform float u_strength;    // 0 = untouched, 1 = full effect
uniform float u_split;       // pixels left of this fraction of the width skip the pass
uniform float u_hudAfter;    // 1 = HUD drawn after the pass, 0 = HUD inside the frame
uniform float u_stage;       // 0 screen UV, 1 frame texture, 2 effect alone, 3 final

// ---- pass 2: the post-processing function. Colour in, colour out. ----
vec3 post(vec3 c) {
  if (u_effect > 2.5) {
    return min(vec3(dot(c, vec3(0.393, 0.769, 0.189)),
                    dot(c, vec3(0.349, 0.686, 0.168)),
                    dot(c, vec3(0.272, 0.534, 0.131))), 1.0);
  }
  if (u_effect > 1.5) return vec3(dot(c, vec3(0.2126, 0.7152, 0.0722)));
  if (u_effect > 0.5) return 1.0 - c;
  return c;
}

// ---- pass 1 stand-in: what the game drew. p is in screen heights, y up. ----
vec3 scene(vec2 p, float aspect) {
  vec3 col = vec3(0.25, 0.45, 0.85);                                   // sky
  float sun = length(p - vec2(0.25 * aspect, 0.72)) - 0.12;
  col = mix(col, vec3(1.0, 0.85, 0.25), 1.0 - smoothstep(0.0, 0.004, sun));
  if (p.y < 0.3) col = vec3(0.25, 0.60, 0.30);                         // ground
  float ball = length(p - vec2(u_ball.x * aspect, u_ball.y)) - 0.07;
  col = mix(col, vec3(0.90, 0.20, 0.25), 1.0 - smoothstep(0.0, 0.004, ball));
  return col;
}

// the HUD: a health bar, 70% full. rgb is its colour, a is 1 where it covers.
vec4 hud(vec2 p) {
  vec2 q = p - vec2(0.05, 0.86);
  float inside = step(0.0, q.x) * step(q.x, 0.4) * step(0.0, q.y) * step(q.y, 0.06);
  vec3 c = vec3(0.10, 0.10, 0.12);
  if (q.x > 0.01 && q.x < 0.276 && q.y > 0.01 && q.y < 0.05) c = vec3(0.95, 0.25, 0.45);
  return vec4(c, inside);
}

void main() {
  vec2 uv = gl_FragCoord.xy / u_resolution;          // screen UV, (0, 0) bottom-left
  float aspect = u_resolution.x / u_resolution.y;
  vec2 p = vec2(uv.x * aspect, uv.y);

  vec4 ui = hud(p);
  vec3 src = scene(p, aspect);                       // in a real pass: texture2D(u_frame, uv)
  if (u_hudAfter < 0.5) src = mix(src, ui.rgb, ui.a); // HUD baked into the frame
  vec3 fx = post(src);
  vec3 result = mix(src, fx, u_strength);
  if (uv.x < u_split) result = src;                  // the untouched side of the split
  if (u_hudAfter > 0.5) result = mix(result, ui.rgb, ui.a); // HUD drawn on top afterwards
  if (u_split > 0.0 && u_split < 1.0 && abs(gl_FragCoord.x - u_split * u_resolution.x) < 1.5) {
    result = vec3(1.0);
  }

  // the stage selector: show an intermediate value instead of the final colour
  vec2 g = abs(fract(uv * 10.0) - 0.5);
  vec3 uvView = vec3(uv, 0.0);
  if (max(g.x, g.y) > 0.47) uvView = mix(uvView, vec3(1.0), 0.35);

  vec3 shown = result;
  if (u_stage < 2.5) shown = fx;
  if (u_stage < 1.5) shown = src;
  if (u_stage < 0.5) shown = uvView;
  gl_FragColor = vec4(shown, 1.0);
}
// Godot 4. Add a CanvasLayer with a ColorRect child, set the ColorRect's
// anchors to Full Rect and its Mouse Filter to Ignore, and give it a
// ShaderMaterial with this shader. Put the HUD on a CanvasLayer with a
// higher layer number so it is drawn after the effect.
shader_type canvas_item;

uniform sampler2D screen_texture : hint_screen_texture, repeat_disable, filter_nearest;
uniform float effect : hint_range(0.0, 3.0, 1.0) = 2.0;   // 0 none, 1 invert, 2 grey, 3 sepia
uniform float strength : hint_range(0.0, 1.0) = 1.0;

vec3 post(vec3 c) {
    if (effect > 2.5) {
        return min(vec3(dot(c, vec3(0.393, 0.769, 0.189)),
                        dot(c, vec3(0.349, 0.686, 0.168)),
                        dot(c, vec3(0.272, 0.534, 0.131))), vec3(1.0));
    }
    if (effect > 1.5) return vec3(dot(c, vec3(0.2126, 0.7152, 0.0722)));
    if (effect > 0.5) return 1.0 - c;
    return c;
}

void fragment() {
    vec3 src = texture(screen_texture, SCREEN_UV).rgb;   // what was drawn below this rect
    COLOR = vec4(mix(src, post(src), strength), 1.0);
}
// Built-in render pipeline. Make a material with this shader and assign it
// to the ScreenEffect script (next tab) on the camera.
Shader "GameDevDaily/ScreenEffect"
{
    Properties
    {
        _MainTex ("Frame", 2D) = "white" {}
        _Effect ("Effect (0 none, 1 invert, 2 grey, 3 sepia)", Range(0, 3)) = 2
        _Strength ("Strength", Range(0, 1)) = 1
    }
    SubShader
    {
        Cull Off ZWrite Off ZTest Always
        Pass
        {
            CGPROGRAM
            #pragma vertex vert_img
            #pragma fragment frag
            #include "UnityCG.cginc"

            sampler2D _MainTex;     // Graphics.Blit puts the frame here
            float _Effect;
            float _Strength;

            float3 post (float3 c)
            {
                if (_Effect > 2.5)
                {
                    return saturate(float3(dot(c, float3(0.393, 0.769, 0.189)),
                                           dot(c, float3(0.349, 0.686, 0.168)),
                                           dot(c, float3(0.272, 0.534, 0.131))));
                }
                if (_Effect > 1.5) return dot(c, float3(0.2126, 0.7152, 0.0722)).xxx;
                if (_Effect > 0.5) return 1.0 - c;
                return c;
            }

            fixed4 frag (v2f_img i) : SV_Target
            {
                float3 src = tex2D(_MainTex, i.uv).rgb;
                return float4(lerp(src, post(src), _Strength), 1.0);
            }
            ENDCG
        }
    }
}
// Built-in render pipeline only. Add to the camera.
using UnityEngine;

[RequireComponent(typeof(Camera))]
public class ScreenEffect : MonoBehaviour
{
    public Material material;   // uses GameDevDaily/ScreenEffect

    void OnRenderImage(RenderTexture source, RenderTexture destination)
    {
        // source is pass 1, the finished frame. Blit draws a full-screen
        // quad into destination with the material's shader.
        Graphics.Blit(source, destination, material);
    }
}

The Unity tabs are for the Built-in render pipeline. URP does not call OnRenderImage. In URP (2022.2 and later) add a Full Screen Pass Renderer Feature to the renderer asset and give it a material made from a Shader Graph with the Fullscreen material type; inside the graph, the URP Sample Buffer node set to BlitSource gives you the frame colour, and the rest is the same maths. In every engine, anything drawn before the pass is affected by it, so draw the HUD afterwards.

Pitfalls

  • The HUD turns grey too. Everything drawn before the pass goes through it. Draw the HUD after the pass, as the demo's toggle shows; in Godot, put it on a higher CanvasLayer.
  • The render target is the wrong size. Make it match the window and recreate it when the window is resized, or the frame comes out stretched or blurry. love.graphics.newCanvas() with no arguments uses the window size at the time you call it.
  • A full-screen ColorRect eats your clicks. In Godot, set its Mouse Filter to Ignore.
  • Colour space changes the answer. The greyscale weights are defined for linear colour. The demo, LÖVE and Godot 2D (without HDR 2D) store sRGB-encoded values, so there the result is a close approximation, which is what most games ship. In a Unity project set to Linear colour space the frame is linear, so the weights are exact but invert looks different: mid grey on screen is about 0.21 in linear, and 1.0 - 0.21 is not mid grey.
  • Forgetting to clear the canvas. If pass 1 does not clear the render target, last frame's pixels stay under this frame.

What it costs

The maths here is trivial: invert is three subtractions, greyscale is one dot product. The branches on u_effect are cheap too, because every pixel takes the same path. The real cost is memory traffic. A 1080 by 2400 phone screen has about 2.6 million pixels; at 4 bytes each, a pass reads about 10 MB and writes about 10 MB, so 60 frames a second moves over 1.2 GB per second for one simple effect. Phone GPUs also draw in small tiles kept on the chip, and switching render targets forces the whole frame out to main memory and back. So on mobile, merge your effects into one pass (one shader that does tint, greyscale and vignette together) instead of chaining several, and consider rendering the frame at a lower resolution.

In real games

Nearly every modern engine ends its frame with full-screen passes. Unity's post-processing (the Volume system in URP and HDRP) runs bloom, colour grading and vignette as full-screen passes, and Godot's Environment resource has built-in adjustments for brightness, contrast and saturation. Godot's documentation describes custom post-processing in 2D exactly as above: a full-screen ColorRect whose shader reads the screen texture.

Your turn (15 minutes)

Start from the LÖVE program.

  1. Add a "damage" effect: when you press d, set strength to 1 with effect = 1 (invert), then make love.update lower strength by dt * 3 each frame until it reaches 0. You get a flash that fades in a third of a second.
  2. Add a fifth effect, a red tint: vec3(dot(c, vec3(0.2126, 0.7152, 0.0722))) * vec3(1.0, 0.3, 0.3). Remember to update the % 4.
  3. Handle love.resize(w, h) by creating a new canvas of the new size.

You are done when pressing d flashes the world but not the health bar, and resizing the window keeps the picture sharp.

Takeaways

  • A full-screen pass draws the game into a texture, then draws that texture over the screen through one shader.
  • The post shader runs once per screen pixel: the colour the game drew goes in, a new colour comes out.
  • mix(src, post(src), strength) lets any effect fade in and out.
  • Draw the HUD after the pass unless you want it affected.
  • The cost is reading and writing the whole frame, not the maths; on phones, combine effects into one pass.
