Hit flash: mixing a sprite towards white

One mix() in the sprite's shader pushes its colour towards white while its alpha stays put, and a timer fades the amount back to zero.

You hit an enemy and nothing tells you it landed, so you keep swinging at a target that may already be dead. A sprite that turns white for a tenth of a second fixes that, and it is one line of shader code.

The first thing most people try is tinting the sprite with love.graphics.setColor(1, 1, 1), or with the sprite's colour property in Godot or Unity. Nothing changes. This lesson explains why, and what to do instead.

Tinting multiplies, flashing mixes

A fragment shader is a small function that runs once per pixel and returns a colour. For a sprite, that function reads one texel (a pixel of the sprite's texture) and returns it, usually multiplied by a tint colour. That multiply is the problem. A tint can only scale each channel between 0 and its current value. White, (1, 1, 1), leaves the sprite unchanged, and nothing you can multiply by turns a dark pupil into white.

A flash needs to replace the colour, a bit at a time. That is exactly what mix does:

rgb = mix(texel.rgb, flashColor, amount)   -- texel.rgb * (1 - amount) + flashColor * amount

At amount = 0 you get the sprite. At amount = 1 every visible pixel is flashColor, so the sprite becomes a flat white silhouette. In between, the sprite's colours show through.

Leave alpha alone

The texel has a fourth channel, alpha, which says how much of the pixel is covered by the sprite. The empty corners of a sprite's rectangle have alpha 0. If you mix all four channels, those corners get alpha too, and the whole rectangle flashes. So the flash touches rgb only and returns the texel's own alpha. The shape of the flash is the shape of the sprite, for free.

The game drives the amount

The shader has no idea a hit happened. It reads amount from a uniform, a value the game sets before drawing that is the same for every pixel of the draw. The game keeps a timer:

flashTimer = FLASH_DURATION                          -- on a hit
flashTimer = math.max(flashTimer - dt, 0)            -- every update
local amount = flashTimer / FLASH_DURATION           -- 1 down to 0

That gives a straight fade. Other curves change the feel: amount * amount drops away quickly and leaves a short afterglow, and a hard cut (1 while the timer runs, then 0) is the crisp blink of older games. Keep the duration short. At 60 frames per second, 0.1 seconds is only five or six frames, and that is plenty.

Colour space and coordinates

The demo and LÖVE mix the colour values as they are stored (sRGB). In a Unity project set to linear colour space, and in Godot when it renders in linear space, the mix happens on linear values, so amount = 0.5 looks lighter there than here. The flash itself does not care where (0, 0) is. The demo draws its sprite from gl_FragCoord, which starts at the bottom-left with y up; LÖVE's image rows start at the top, so the Lua flips y when it builds the same sprite.

Try it

Click or tap the slime, press Hit, or focus the canvas and press space. Then set Method to Multiply with a white flash: nothing happens, which is the tint problem. Try Mix rgba too to see the sprite's rectangle light up. Step through Stage with Scrub by hand on to see the texel, the alpha mask and the amount separately.

The code

The LÖVE program builds the same 24 by 20 slime in code, so there is no image file, and draws it eight times larger with the flash shader. Click or press space to hit it.

local FLASH_DURATION = 0.12              -- seconds
local FLASH_COLOR = { 1.0, 1.0, 1.0 }    -- white
local flashTimer = 0                     -- seconds of flash left
local sprite, shader

local pixelcode = [[
uniform vec3 u_flashColor;
uniform float u_amount;

vec4 effect(vec4 color, Image tex, vec2 texture_coords, vec2 screen_coords)
{
  vec4 texel = Texel(tex, texture_coords) * color;
  vec3 rgb = mix(texel.rgb, u_flashColor, u_amount);
  return vec4(rgb, texel.a);   // alpha untouched: only the sprite flashes
}
]]

local function inside(x, y, cx, cy, rx, ry)
  local dx = (x - cx) / rx
  local dy = (y - cy) / ry
  return dx * dx + dy * dy < 1
end

-- the demo's slime, 24 by 20 pixels; py counts upwards like the demo
local function slimePixel(x, y)
  local px, py = x + 0.5, 19.5 - y
  local r, g, b, a = 0, 0, 0, 0
  if inside(px, py, 12, 9, 10.5, 8.5) and py > 1 then r, g, b, a = 0.10, 0.30, 0.14, 1 end
  if inside(px, py, 12, 9, 9.5, 7.5) and py > 2 then
    local t = py / 17
    r, g, b, a = 0.20 + 0.16 * t, 0.58 + 0.22 * t, 0.28 + 0.12 * t, 1
  end
  if inside(px, py, 7.5, 13, 1.6, 1.6) then r, g, b, a = 0.78, 0.96, 0.74, 1 end
  if inside(px, py, 9, 9.5, 2.2, 2.2) or inside(px, py, 15, 9.5, 2.2, 2.2) then
    r, g, b, a = 0.96, 0.96, 0.96, 1
  end
  if inside(px, py, 9.5, 9, 1.1, 1.1) or inside(px, py, 15.5, 9, 1.1, 1.1) then
    r, g, b, a = 0.08, 0.08, 0.12, 1
  end
  return r, g, b, a
end

function love.load()
  local data = love.image.newImageData(24, 20)
  data:mapPixel(function(x, y) return slimePixel(x, y) end)
  sprite = love.graphics.newImage(data)
  sprite:setFilter("nearest", "nearest")
  shader = love.graphics.newShader(pixelcode)
end

local function hit()
  flashTimer = FLASH_DURATION
end

function love.mousepressed()
  hit()
end

function love.keypressed(key)
  if key == "space" then hit() end
end

function love.update(dt)
  flashTimer = math.max(flashTimer - dt, 0)
end

function love.draw()
  local amount = flashTimer / FLASH_DURATION   -- 1 at the hit, 0 when done
  local w, h = love.graphics.getDimensions()
  love.graphics.clear(0.15, 0.17, 0.22)
  shader:send("u_flashColor", FLASH_COLOR)
  shader:send("u_amount", amount)
  love.graphics.setShader(shader)
  love.graphics.draw(sprite, w / 2 - 96, h / 2 - 80, 0, 8, 8)
  love.graphics.setShader()
end
precision mediump float;

uniform vec2 u_resolution;
uniform float u_amount;      // flash amount: 0 = normal, 1 = full flash
uniform vec3 u_flashColor;   // the colour to flash towards
uniform float u_method;      // 0 mix rgb, 1 add, 2 multiply, 3 mix rgba (bug)
uniform float u_stage;       // 0 texel, 1 alpha, 2 amount, 3 final

const vec2 SPRITE_SIZE = vec2(24.0, 20.0);   // in sprite pixels

float ellipse(vec2 p, vec2 c, vec2 r) {
  return length((p - c) / r);   // below 1.0 inside the ellipse
}

// The "texture": colour and alpha of one sprite pixel, y up.
vec4 sprite(vec2 sp) {
  vec4 col = vec4(0.0);
  if (ellipse(sp, vec2(12.0, 9.0), vec2(10.5, 8.5)) < 1.0 && sp.y > 1.0)
    col = vec4(0.10, 0.30, 0.14, 1.0);                                   // outline
  if (ellipse(sp, vec2(12.0, 9.0), vec2(9.5, 7.5)) < 1.0 && sp.y > 2.0)
    col = vec4(mix(vec3(0.20, 0.58, 0.28), vec3(0.36, 0.80, 0.40), sp.y / 17.0), 1.0);  // body
  if (length(sp - vec2(7.5, 13.0)) < 1.6) col = vec4(0.78, 0.96, 0.74, 1.0);    // shine
  if (length(sp - vec2(9.0, 9.5)) < 2.2) col = vec4(0.96, 0.96, 0.96, 1.0);     // eyes
  if (length(sp - vec2(15.0, 9.5)) < 2.2) col = vec4(0.96, 0.96, 0.96, 1.0);
  if (length(sp - vec2(9.5, 9.0)) < 1.1) col = vec4(0.08, 0.08, 0.12, 1.0);     // pupils
  if (length(sp - vec2(15.5, 9.0)) < 1.1) col = vec4(0.08, 0.08, 0.12, 1.0);
  return col;
}

void main() {
  vec2 p = (gl_FragCoord.xy - 0.5 * u_resolution) / u_resolution.y;   // (0, 0) centre, y up

  // background: a dark tiled floor
  vec2 tile = floor(p * 8.0);
  vec3 bg = mix(vec3(0.15, 0.17, 0.22), vec3(0.19, 0.21, 0.27), mod(tile.x + tile.y, 2.0));

  // the sprite's rectangle (its quad): 0.6 of the canvas height wide, centred
  float pixelSize = 0.6 / SPRITE_SIZE.x;
  vec2 sp = (p - vec2(-0.3, -0.25)) / pixelSize;   // sprite pixel coordinates
  bool inQuad = sp.x >= 0.0 && sp.x < SPRITE_SIZE.x && sp.y >= 0.0 && sp.y < SPRITE_SIZE.y;

  vec3 col = bg;
  if (inQuad) {
    vec4 texel = sprite(floor(sp) + 0.5);                // 1. read the texel
    vec4 outc;                                           // 2. flash it
    if (u_method < 0.5)      outc = vec4(mix(texel.rgb, u_flashColor, u_amount), texel.a);
    else if (u_method < 1.5) outc = vec4(min(texel.rgb + u_flashColor * u_amount, 1.0), texel.a);
    else if (u_method < 2.5) outc = vec4(texel.rgb * mix(vec3(1.0), u_flashColor, u_amount), texel.a);
    else                     outc = mix(texel, vec4(u_flashColor, 1.0), u_amount);   // bug: alpha too
    col = mix(bg, outc.rgb, outc.a);                     // 3. blend over the background

    if (u_stage < 2.5) col = vec3(u_amount);
    if (u_stage < 1.5) col = vec3(texel.a);
    if (u_stage < 0.5) col = mix(bg, texel.rgb, texel.a);
  } else if (u_stage > 0.5 && u_stage < 2.5) {
    col = bg * 0.4;   // outside the quad the sprite's shader never runs
  }
  gl_FragColor = vec4(col, 1.0);
}
// Godot 4, a ShaderMaterial on a Sprite2D.
shader_type canvas_item;

uniform vec4 flash_color : source_color = vec4(1.0, 1.0, 1.0, 1.0);
uniform float flash_amount : hint_range(0.0, 1.0) = 0.0;

void fragment() {
    vec4 texel = texture(TEXTURE, UV);
    COLOR = vec4(mix(texel.rgb, flash_color.rgb, flash_amount), texel.a);
}

// From GDScript, every frame while the timer runs:
//   material.set_shader_parameter("flash_amount", flash_timer / FLASH_DURATION)
// Built-in render pipeline, for a SpriteRenderer.
Shader "GameDevDaily/HitFlashSprite"
{
    Properties
    {
        [PerRendererData] _MainTex ("Sprite", 2D) = "white" {}
        _FlashColor ("Flash colour", Color) = (1, 1, 1, 1)
        _FlashAmount ("Flash amount", Range(0, 1)) = 0
    }
    SubShader
    {
        Tags { "Queue" = "Transparent" "RenderType" = "Transparent" "IgnoreProjector" = "True" }
        Cull Off
        ZWrite Off
        Blend SrcAlpha OneMinusSrcAlpha

        Pass
        {
            CGPROGRAM
            #pragma vertex vert
            #pragma fragment frag
            #include "UnityCG.cginc"

            sampler2D _MainTex;
            fixed4 _FlashColor;
            float _FlashAmount;

            struct appdata
            {
                float4 vertex : POSITION;
                float2 uv : TEXCOORD0;
                fixed4 color : COLOR;
            };

            struct v2f
            {
                float4 pos : SV_POSITION;
                float2 uv : TEXCOORD0;
                fixed4 color : COLOR;
            };

            v2f vert (appdata v)
            {
                v2f o;
                o.pos = UnityObjectToClipPos(v.vertex);
                o.uv = v.uv;
                o.color = v.color;   // SpriteRenderer.color arrives here
                return o;
            }

            fixed4 frag (v2f i) : SV_Target
            {
                fixed4 c = tex2D(_MainTex, i.uv) * i.color;
                c.rgb = lerp(c.rgb, _FlashColor.rgb, _FlashAmount);
                return c;            // alpha untouched
            }
            ENDCG
        }
    }
}
// From C#: spriteRenderer.material.SetFloat("_FlashAmount", amount);

HLSL spells mix as lerp. For URP, build it in Shader Graph with a Sprite Unlit graph: a Sample Texture 2D node feeds the RGB of a Lerp node as A, a flash colour property is B, a flash amount property is T, the Lerp output goes to Base Color and the texture's A output goes to Alpha. The Godot version ignores the node's modulate; multiply texel by COLOR first if you need it.

Pitfalls

  • Using the tint colour. setColor, modulate and SpriteRenderer.color multiply. They can darken or tint, never whiten. Use the Multiply method in the demo to see it.
  • Flashing the alpha. Mixing the whole vec4 fills the transparent corners of the sprite's rectangle. Mix rgb and return the texel's alpha.
  • Every enemy flashes at once. A material is shared between all nodes that use it. In Godot, turn on Local to Scene for the material or give each enemy its own copy. In Unity, renderer.material makes a copy for that renderer while sharedMaterial changes them all; a MaterialPropertyBlock sets per-renderer values without a copy.
  • Counting frames instead of seconds. "Flash for 6 frames" lasts twice as long at 60 Hz as at 120 Hz. Subtract dt from a timer.
  • Too long, too often, too big. A flash longer than about a quarter of a second starts to hide the sprite. Large areas flashing several times a second can be a problem for players with photosensitive epilepsy; WCAG 2.3.1 sets a limit of three flashes in any one second. Keep flashes small and short, or offer an option to soften them.

What it costs

One mix per pixel is about as cheap as shader work gets, even on a phone. The hidden cost is batching. LÖVE and the engines group sprites that share a texture, shader and settings into one draw call; a sprite with its own shader or its own uniform value can break that group. With hundreds of bullets that flash, pass the amount in data the batch already carries per sprite, such as the vertex colour's alpha, and decode it in the shader.

In real games

Hit flashes are so common in action games that most players read them without noticing. On older palette-based consoles a flash was often made by changing the palette for a few frames instead of running a per-pixel shader; palette swaps are the subject of a later lesson. A close cousin is the blink used for invincibility after taking damage, where the sprite is simply not drawn on some frames.

Takeaways

  • A tint multiplies, so it cannot make a sprite white. A flash mixes the texel's colour towards the flash colour.
  • Mix rgb only and keep the texel's alpha, so the flash has the sprite's shape.
  • The game owns a timer; the shader only sees amount, from 1 at the hit down to 0.
  • Measure the flash in seconds, keep it short, and give each sprite its own material value.
