Cellular patterns: the distance to the nearest random point

Scatter one random point in every cell and measure the distance to the nearest one. That single number draws cells, scales, stones and cracks.

Cracked dry mud, a lizard's scales, cobblestones, the bright web of light on the bottom of a pool. None of these look like yesterday's soft noise. They are made of cells: blobs with clear borders between them. A shader can draw all of them with one search and two distances.

Every pixel asks: which point is closest to me?

A fragment shader is a small function that runs once per pixel: a position goes in, a colour comes out. For a cellular pattern, the function in the middle answers one question. Somewhere on the screen there are scattered feature points. How far is this pixel from the nearest one?

Shade every pixel by that distance and you get dark spots at the points and bright ridges where two points are equally far away. The regions that share a nearest point are called Voronoi cells. The pattern is often called Worley noise or cellular noise, after Steven Worley, who described it for textures in 1996.

Step 1: one point per grid cell

A shader has no list of points, and checking a long list per pixel would be far too slow. So divide space into a grid, as in the last two lessons, and give each cell exactly one point. The hash invents it from the cell's coordinates, so every pixel that asks gets the same answer:

vec2 p = gl_FragCoord.xy / u_resolution.y * u_scale;
vec2 i = floor(p);                  // which cell
vec2 f = fract(p);                  // where inside it, 0 to 1
vec2 pt = 0.5 + u_jitter * (hash2(i) - 0.5);   // this cell's point

Jitter says how far the point may wander from the centre of its cell. At 0 every point sits on its cell's centre and the cells come out as perfect squares. At 1 a point can be anywhere in its cell.

Step 2: check the neighbours too

The tempting shortcut is to measure only the distance to your own cell's point, length(pt - f). It fails: a point just across the border is often closer than your own. The demo's stage 2 shows the result, circles that are sliced off at every cell edge.

The fix is to visit the 3 by 3 block of cells around the pixel and keep the smallest distance. That is nine points per pixel instead of millions.

Step 3: keep the two nearest

float d1 = 8.0;   // nearest so far (F1)
float d2 = 8.0;   // second nearest so far (F2)
for (int y = -1; y <= 1; y++) {
  for (int x = -1; x <= 1; x++) {
    vec2 n = vec2(float(x), float(y));            // neighbour offset
    float d = length(n + featurePoint(i + n) - f);
    if (d < d1) { d2 = d1; d1 = d; id = i + n; }
    else if (d < d2) { d2 = d; }
  }
}

The start value 8.0 just means "further than any real point". Adding the offset n moves each neighbour's point into the pixel's cell space.

Three useful outputs fall out of the loop. d1, called F1, is the distance to the nearest point: shade by it for spots and domed scales. id is the cell that owns that point: hash it again and every Voronoi cell gets its own flat colour. d2, called F2, is the second nearest distance.

Step 4: borders from F2 − F1

On the border between two cells the pixel is equally far from both points, so F1 equals F2 there. F2 − F1 is therefore 0 on every border and grows towards the middle of each cell. Threshold it with smoothstep and you have cracks:

float e = d2 - d1;
float crack = 1.0 - smoothstep(u_width, u_width + 0.03, e);

Which corner is (0, 0), and which colours

WebGL's gl_FragCoord starts at the bottom-left with y up. LÖVE's screen_coords and Godot's canvas UV start at the top-left with y down, so the code below flips y to match the demo. Unity's mesh UVs start at the bottom-left. The stone colours are display (sRGB) values; in a linear colour space project they come out lighter.

Try it

Step through the stages from 1 to 6. On stage 2, find the seams where a circle is cut off by a cell border; stage 3 removes them by checking the neighbours. Then set Jitter to 0 and watch the cells turn into a square grid, and slide it back up. Finally, drag the probe in the lower view to see which two points it picks.

The code

In LÖVE the shader is a string with the effect entry point, drawn over the whole window. Up and down change the cell count, left and right the jitter, and space starts or stops the moving points.

local scale = 5          -- cells across the height of the window
local jitter = 1.0       -- 0 = points on the cell centres, 1 = anywhere in the cell
local width = 0.05       -- crack width, in cells
local phase = 0          -- moves the points while moving is on
local moving = false
local shader

local pixelcode = [[
uniform vec2 u_resolution;
uniform float u_scale;
uniform float u_jitter;
uniform float u_width;
uniform float u_phase;

vec2 hash2(vec2 c)
{
  vec2 k = vec2(dot(c, vec2(127.1, 311.7)), dot(c, vec2(269.5, 183.3)));
  return fract(sin(k) * 43758.5453);
}

vec2 featurePoint(vec2 cell)
{
  vec2 o = 0.5 + 0.5 * sin(u_phase + 6.2831853 * hash2(cell));
  return 0.5 + u_jitter * (o - 0.5);
}

vec4 effect(vec4 color, Image tex, vec2 texture_coords, vec2 screen_coords)
{
  // LÖVE's origin is the top-left: flip y so cell (0, 0) is bottom-left, as in the demo
  vec2 pos = vec2(screen_coords.x, u_resolution.y - screen_coords.y);
  vec2 p = pos / u_resolution.y * u_scale;
  vec2 i = floor(p);
  vec2 f = fract(p);

  float d1 = 8.0;
  float d2 = 8.0;
  vec2 id = i;
  for (int y = -1; y <= 1; y++) {
    for (int x = -1; x <= 1; x++) {
      vec2 n = vec2(float(x), float(y));
      float d = length(n + featurePoint(i + n) - f);
      if (d < d1) { d2 = d1; d1 = d; id = i + n; }
      else if (d < d2) { d2 = d; }
    }
  }
  float e = d2 - d1;

  vec2 h = hash2(id);
  vec3 col = vec3(0.56, 0.53, 0.48) * (0.8 + 0.35 * h.x);   // each slab its own shade
  col *= 1.1 - 0.5 * d1;                                    // lighter near its point
  float crack = 1.0 - smoothstep(u_width, u_width + 0.03, e);
  col = mix(col, vec3(0.13, 0.11, 0.10), crack);
  return vec4(col, 1.0) * color;
}
]]

function love.load()
  shader = love.graphics.newShader(pixelcode)
end

function love.keypressed(key)
  if key == "space" then moving = not moving end
  if key == "up" then scale = math.min(scale + 1, 24) end
  if key == "down" then scale = math.max(scale - 1, 2) end
  if key == "right" then jitter = math.min(jitter + 0.1, 1.0) end
  if key == "left" then jitter = math.max(jitter - 0.1, 0.0) end
end

function love.update(dt)
  if moving then
    phase = (phase + 0.8 * dt) % (2 * math.pi)   -- sin repeats, so wrapping is invisible
  end
end

function love.draw()
  local w, h = love.graphics.getDimensions()
  local pw, ph = love.graphics.getPixelDimensions()
  shader:send("u_resolution", { pw, ph })
  shader:send("u_scale", scale)
  shader:send("u_jitter", jitter)
  shader:send("u_width", width)
  shader:send("u_phase", phase)
  love.graphics.setShader(shader)
  love.graphics.rectangle("fill", 0, 0, w, h)
  love.graphics.setShader()
end

precision highp float;   // the hash needs 32-bit floats
#else
precision mediump float;
#endif

uniform vec2 u_resolution;
uniform float u_scale;    // cells across the height of the canvas
uniform float u_jitter;   // 0 = points on the cell centres, 1 = anywhere in the cell
uniform float u_width;    // crack width, in cells
uniform float u_phase;    // moves the points; wrapped to 0..2 pi on the CPU
uniform float u_stage;    // 0 cell position ... 5 final colour
uniform float u_grid;     // 1 draws the cell borders
uniform float u_dots;     // 1 draws the feature points

vec2 hash2(vec2 c) {
  vec2 k = vec2(dot(c, vec2(127.1, 311.7)), dot(c, vec2(269.5, 183.3)));
  return fract(sin(k) * 43758.5453);
}

// the feature point of a cell, 0 to 1 inside that cell
vec2 featurePoint(vec2 cell) {
  vec2 o = 0.5 + 0.5 * sin(u_phase + 6.2831853 * hash2(cell));
  return 0.5 + u_jitter * (o - 0.5);
}

void main() {
  vec2 p = gl_FragCoord.xy / u_resolution.y * u_scale;   // square cells, u_scale tall
  vec2 i = floor(p);                                     // 1. which cell
  vec2 f = fract(p);                                     //    where inside it

  float d0 = length(featurePoint(i) - f);                // 2. own cell's point only

  float d1 = 8.0;                                        // 3. nearest distance, F1
  float d2 = 8.0;                                        //    second nearest, F2
  vec2 id = i;                                           // 4. the cell that owns F1
  for (int y = -1; y <= 1; y++) {
    for (int x = -1; x <= 1; x++) {
      vec2 n = vec2(float(x), float(y));
      float d = length(n + featurePoint(i + n) - f);
      if (d < d1) {
        d2 = d1;
        d1 = d;
        id = i + n;
      } else if (d < d2) {
        d2 = d;
      }
    }
  }
  float e = d2 - d1;                                     // 5. 0 on every border

  // 6. use it: cracked stone slabs
  vec2 h = hash2(id);
  vec3 col = vec3(0.56, 0.53, 0.48) * (0.8 + 0.35 * h.x);   // each slab its own shade
  col *= 1.1 - 0.5 * d1;                                    // lighter near its point
  float crack = 1.0 - smoothstep(u_width, u_width + 0.03, e);
  col = mix(col, vec3(0.13, 0.11, 0.10), crack);

  if (u_stage < 4.5) col = vec3(e);
  if (u_stage < 3.5) col = 0.3 + 0.6 * vec3(h, fract(h.x + h.y));
  if (u_stage < 2.5) col = vec3(d1);
  if (u_stage < 1.5) col = vec3(d0);
  if (u_stage < 0.5) col = vec3(f, 0.0);

  float cellPx = u_resolution.y / u_scale;
  vec2 b = min(f, 1.0 - f) * cellPx;                     // pixels to the nearest cell border
  float line = 1.0 - step(1.0, min(b.x, b.y));
  col = mix(col, vec3(0.35, 0.65, 1.0), line * u_grid * 0.7);
  float dotMask = 1.0 - smoothstep(3.0, 4.5, d1 * cellPx);
  col = mix(col, vec3(1.0, 0.3, 0.2), dotMask * u_dots);
  gl_FragColor = vec4(col, 1.0);
}

shader_type canvas_item;

uniform vec2 rect_size = vec2(640.0, 360.0);  // set this to the ColorRect's size
uniform float scale = 5.0;                    // cells across the height
uniform float jitter : hint_range(0.0, 1.0) = 1.0;
uniform float crack_width : hint_range(0.0, 0.2) = 0.05;
uniform float speed = 0.0;                    // radians per second; 0 holds the points still

vec2 hash2(vec2 c) {
    vec2 k = vec2(dot(c, vec2(127.1, 311.7)), dot(c, vec2(269.5, 183.3)));
    return fract(sin(k) * 43758.5453);
}

vec2 feature_point(vec2 cell, float phase) {
    vec2 o = 0.5 + 0.5 * sin(phase + 6.2831853 * hash2(cell));
    return 0.5 + jitter * (o - 0.5);
}

void fragment() {
    // UV starts at the top-left with y down: flip y to match the demo.
    vec2 pos = vec2(UV.x, 1.0 - UV.y) * rect_size;
    vec2 p = pos / rect_size.y * scale;
    vec2 i = floor(p);
    vec2 f = fract(p);
    float phase = mod(TIME * speed, 6.2831853);

    float d1 = 8.0;
    float d2 = 8.0;
    vec2 id = i;
    for (int y = -1; y <= 1; y++) {
        for (int x = -1; x <= 1; x++) {
            vec2 n = vec2(float(x), float(y));
            float d = length(n + feature_point(i + n, phase) - f);
            if (d < d1) { d2 = d1; d1 = d; id = i + n; }
            else if (d < d2) { d2 = d; }
        }
    }
    float e = d2 - d1;

    vec3 col = vec3(0.56, 0.53, 0.48) * (0.8 + 0.35 * hash2(id).x);
    col *= 1.1 - 0.5 * d1;
    float crack = 1.0 - smoothstep(crack_width, crack_width + 0.03, e);
    COLOR = vec4(mix(col, vec3(0.13, 0.11, 0.10), crack), 1.0);
}

        _Speed ("Point speed (radians per second)", Float) = 0

    {
        Tags { "RenderType" = "Opaque" }
        Pass

            #pragma vertex vert
            #pragma fragment frag
            #include "UnityCG.cginc"

            float _Jitter;
            float _CrackWidth;
            float _Speed;

            struct v2f

                float4 pos : SV_POSITION;
                float2 uv : TEXCOORD0;
            };

            v2f vert (appdata_base v)

                v2f o;

                        if (d < d1) { d2 = d1; d1 = d; id = cell + n; }
                        else if (d < d2) { d2 = d; }
                    }
                }
                float e = d2 - d1;

                float3 col = float3(0.56, 0.53, 0.48) * (0.8 + 0.35 * hash2(id).x);
                col *= 1.1 - 0.5 * d1;
                float crack = 1.0 - smoothstep(_CrackWidth, _CrackWidth + 0.03, e);

HLSL spells mix as lerp and fract as frac. In URP you can skip the hand-written version: Shader Graph's Voronoi node takes a UV, an angle offset that moves the points and a cell density, and outputs the distance (Out) and a random value per cell (Cells). Godot's FastNoiseLite resource has a cellular noise type for CPU-side or baked use.

Pitfalls

  • Checking only your own cell. The nearest point is often next door. Without the 3 by 3 search the pattern shows the square grid as seams, as on stage 2.
  • Trusting 3 by 3 at full jitter. With jitter up to about 0.65 the nine cells always contain the nearest point. At 1, a point two cells away can occasionally be nearer, which shows up as a rare small glitch, and F2 is wrong more often than F1. A 5 by 5 search, 25 points, is exact for both, at nearly three times the cost.
  • Expecting even cracks from F2 − F1. It is 0 on the border, but it is not the true distance to the border. It grows faster where the two points are far apart, so cracks come out thinner there and thicker where the points are close. An exact border distance needs a second pass over the neighbours; Inigo Quilez describes one.
  • mediump on phones. The sine hash needs 32-bit floats, as in the last two lessons. Request highp and keep the cell coordinates small.

What it costs

Per pixel the search does nine hashes, nine point offsets and nine square roots. In this demo that is 36 sines, because each hash and each moving offset costs two. Fine for one layer on a phone, but heavier than value noise. Two savings: compare squared distances inside the loop and take the two square roots only at the end, and drop the moving sin when the points do not move. A cellular pattern in 3D searches 27 cells, so if the pattern never changes, bake it into a texture instead.

In real games

Steven Worley published the technique as "A Cellular Texture Basis Function" at SIGGRAPH 1996, and it has been a standard procedural texture since. Engines and tools ship it ready-made: Unity Shader Graph's Voronoi node, Godot's FastNoiseLite cellular type, and Blender's Voronoi texture node, which offers F1, F2 and a distance-to-edge mode. Typical game uses are stylised water caustics (bright F2 − F1 borders, with the points moving), cracked ground, scales and stained glass.

You are done when the window shows coloured panes separated by dark borders, and you can say how the borders changed when you switched to Manhattan distance.

Takeaways

  • Cellular noise is the distance from a pixel to the nearest of a set of scattered points.
  • One hashed point per grid cell plus a search of the 3 by 3 neighbours makes it cheap enough for a shader.
  • F1 gives spots and scales, the id of the nearest cell gives flat cell colours, and F2 − F1 gives borders and cracks.
  • Jitter goes from a square grid at 0 to irregular cells at 1.
  • It costs nine distance checks per pixel: fine for one layer, worth baking when it never changes.
