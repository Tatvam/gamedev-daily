Stripes and checkerboards: patterns from fract, step and mod

Rotate the UV, scale it, then fract and a threshold give stripes and grid lines, and mod of the cell id gives a checkerboard at any angle.

Hazard tape on a warning zone, a chequered finish line, the debug grid that shows where tiles snap. Each is usually a painted texture that blurs when you scale it.

A shader can draw all three from the pixel's position in a few lines, sharp at any size and angle. You already know every piece.

Four steps from position to pattern

A fragment shader is a small function that runs once per pixel and returns a colour. The input today is the pixel's centred UV: (0, 0) in the middle of the picture, y running from -0.5 at the bottom to 0.5 at the top. The output is one of two colours. Between them sit four steps.

  1. Rotate the coordinates, so the pattern can lean at any angle.
  2. Scale by the frequency, so there are that many lines per unit of height. Call the result st.
  3. Repeat with fract, as in the last lesson: f = fract(st) runs from 0.0 to 1.0 inside every cell, and id = floor(st) numbers the cells.
  4. Threshold the repeated value into a mask, a number that is 1.0 where the pattern is and 0.0 where it is not. Then mix the two colours with it.

Stripes: a sawtooth, folded, then cut

Take only the x part of f. It is a sawtooth: it climbs from 0 to 1 across each cell, then drops back. To draw a line on every cell border we want to know how far each pixel is from the nearest border. That is the smaller of the distance to the left border, f, and to the right one, 1.0 - f:

float d = min(f.x, 1.0 - f.x);   // 0.0 on a border, 0.5 halfway between

This is a triangle wave. Now cut it with a threshold. A line of width w, measured as a fraction of a cell, covers every pixel with d less than w / 2. With w at 0.5 the stripes and the gaps are equal.

The threshold is step from two lessons ago. To keep the edges smooth we use smoothstep across about one pixel, called aa (for anti-aliasing) and measured in cell units:

float m = 1.0 - smoothstep(0.5 * w - aa, 0.5 * w + aa, d);

Grid lines: the same, on both axes

A grid is stripes along x and stripes along y at once. Work out the distance for each axis, and keep the smaller one: a pixel is on a grid line if it is near a vertical line or a horizontal one.

vec2 d2 = min(f, 1.0 - f);       // distance to the nearest line, per axis
float d = min(d2.x, d2.y);       // nearest line of either kind

Checkerboard: count the cells

A checkerboard needs no distance at all. It only asks which cell the pixel is in. Moving one cell right adds 1 to id.x; moving one cell up adds 1 to id.y. Either move changes the sum id.x + id.y from odd to even or back. mod(a, 2.0), the remainder after dividing by 2, turns that into 0.0 for even and 1.0 for odd, so neighbouring cells always differ:

float m = mod(id.x + id.y, 2.0); // 0.0 or 1.0, alternating

Rotation: turn the coordinates, not the pattern

To tilt the pattern by an angle a, rotate each pixel's coordinates the opposite way before anything else. The pattern is drawn in the rotated coordinates, so it appears turned by a counter-clockwise:

vec2 r = vec2(c * uv.x + s * uv.y, -s * uv.x + c * uv.y);  // c = cos(a), s = sin(a)

Because the UV is centred, the pattern turns around the middle of the picture. Track 2 covers rotating UV space in depth.

Rule of thumb

Lines come from the position inside a cell (fract, then a threshold). Alternating fills come from the cell number (floor, then mod).

Try it

Start on Stripes and walk the Stage menu from 1 to 5. Stage 1 shows the rotated coordinates as red and green; drag Angle and watch the gradient turn. Stage 2 is f = fract(st), the repeating sawtooth. Stage 3 is the triangle wave d shown as grey: black on each line, brightest halfway between. Stage 4 is the mask and stage 5 the colour.

Then switch to Checkerboard at stage 3. It shows mod(id.x, 2.0) as red and mod(id.y, 2.0) as green: red columns, green rows. Where exactly one of them is on, the sum is odd, and stage 4 lights up. Finally push Frequency to the top and watch the pattern break into ripples.

The code

The Lua version runs the same shade function in LÖVE, whose pixel shaders use the entry point effect instead of main. Up and down change the frequency, left and right the angle, [ and ] the line width, P cycles the pattern and S the stage. Clicking prints the cell under the mouse and its checker value, using the same maths in plain Lua.

-- The demo's starting values.
local freq = 6           -- cells per unit of height
local angle = 30         -- degrees, counter-clockwise
local width = 0.5        -- line width, as a fraction of a cell
local pattern = 0        -- 0 stripes, 1 grid, 2 checkerboard
local stage = 4          -- 0 rotated uv, 1 f, 2 wave, 3 mask, 4 final
local rect = { 20, 20, 640, 360 }   -- x, y, width, height in pixels
local shader

local pixelcode = [[
uniform float u_freq;
uniform float u_angle;
uniform float u_width;
uniform float u_pattern;
uniform float u_stage;
uniform vec4 u_rect;

vec3 shade(vec2 uv, float aa)
{
    float c = cos(u_angle);
    float s = sin(u_angle);
    vec2 r = vec2(c * uv.x + s * uv.y, -s * uv.x + c * uv.y); // 1. rotate
    vec2 st = r * u_freq;                         // 2. scale
    vec2 id = floor(st);                          //    which cell
    vec2 f = fract(st);                           // 3. where in the cell
    vec2 d2 = min(f, 1.0 - f);                    //    distance to a line, per axis
    float d = d2.x;                               //    stripes: x only
    if (u_pattern > 0.5) d = min(d2.x, d2.y);     //    grid: either axis
    float m = 1.0 - smoothstep(0.5 * u_width - aa, 0.5 * u_width + aa, d); // 4. mask
    if (u_pattern > 1.5) m = mod(id.x + id.y, 2.0);   //    checkerboard
    vec3 col = mix(vec3(0.1, 0.12, 0.22), vec3(1.0, 0.62, 0.2), m); // 5. final
    vec3 wave = vec3(2.0 * d);
    if (u_pattern > 1.5) wave = vec3(mod(id, 2.0), 0.0);
    if (u_stage < 3.5) col = vec3(m);
    if (u_stage < 2.5) col = wave;
    if (u_stage < 1.5) col = vec3(f, 0.0);
    if (u_stage < 0.5) col = vec3(r + 0.5, 0.0);
    return col;
}

vec4 effect(vec4 color, Image tex, vec2 texture_coords, vec2 screen_coords)
{
    vec2 uv = (screen_coords - u_rect.xy - 0.5 * u_rect.zw) / u_rect.w;
    uv.y = -uv.y;                     // y points down here; make it point up
    float aa = u_freq / u_rect.w;     // one pixel, in cell units
    return vec4(shade(uv, aa), 1.0);
}
]]

function love.load()
  shader = love.graphics.newShader(pixelcode)
end

function love.keypressed(key)
  if key == "up" then freq = math.min(80, freq + 0.5) end
  if key == "down" then freq = math.max(1, freq - 0.5) end
  if key == "left" then angle = (angle + 5) % 180 end
  if key == "right" then angle = (angle - 5) % 180 end
  if key == "]" then width = math.min(0.95, width + 0.05) end
  if key == "[" then width = math.max(0.05, width - 0.05) end
  if key == "p" then pattern = (pattern + 1) % 3 end
  if key == "s" then stage = (stage + 1) % 5 end
end

function love.mousepressed(x, y)
  -- The same maths on the CPU. Lua's % works like GLSL's mod for negatives.
  local u = (x - rect[1] - rect[3] / 2) / rect[4]
  local v = -(y - rect[2] - rect[4] / 2) / rect[4]
  local a = math.rad(angle)
  local c, s = math.cos(a), math.sin(a)
  local idx = math.floor((c * u + s * v) * freq)
  local idy = math.floor((-s * u + c * v) * freq)
  print("cell", idx, idy, "checker", (idx + idy) % 2)
end

function love.draw()
  shader:send("u_freq", freq)
  shader:send("u_angle", math.rad(angle))
  shader:send("u_width", width)
  shader:send("u_pattern", pattern)
  shader:send("u_stage", stage)
  shader:send("u_rect", rect)
  love.graphics.setShader(shader)
  love.graphics.rectangle("fill", rect[1], rect[2], rect[3], rect[4])
  love.graphics.setShader()
end
#ifdef GL_FRAGMENT_PRECISION_HIGH
precision highp float;
#else
precision mediump float;
#endif

uniform vec2 u_resolution;
uniform float u_freq;
uniform float u_angle;
uniform float u_width;
uniform float u_pattern;
uniform float u_stage;

vec3 shade(vec2 uv, float aa) {
  float c = cos(u_angle);
  float s = sin(u_angle);
  vec2 r = vec2(c * uv.x + s * uv.y, -s * uv.x + c * uv.y); // 1. rotate
  vec2 st = r * u_freq;                         // 2. scale
  vec2 id = floor(st);                          //    which cell
  vec2 f = fract(st);                           // 3. where in the cell
  vec2 d2 = min(f, 1.0 - f);                    //    distance to a line, per axis
  float d = d2.x;                               //    stripes: x only
  if (u_pattern > 0.5) d = min(d2.x, d2.y);     //    grid: either axis
  float m = 1.0 - smoothstep(0.5 * u_width - aa, 0.5 * u_width + aa, d); // 4. mask
  if (u_pattern > 1.5) m = mod(id.x + id.y, 2.0);   //    checkerboard
  vec3 col = mix(vec3(0.1, 0.12, 0.22), vec3(1.0, 0.62, 0.2), m); // 5. final
  vec3 wave = vec3(2.0 * d);
  if (u_pattern > 1.5) wave = vec3(mod(id, 2.0), 0.0);
  if (u_stage < 3.5) col = vec3(m);
  if (u_stage < 2.5) col = wave;
  if (u_stage < 1.5) col = vec3(f, 0.0);
  if (u_stage < 0.5) col = vec3(r + 0.5, 0.0);
  return col;
}

void main() {
  vec2 px = gl_FragCoord.xy;                    // pixels, origin bottom-left
  vec2 uv = (px - 0.5 * u_resolution) / u_resolution.y; // centred, y up
  float aa = u_freq / u_resolution.y;           // one pixel, in cell units
  gl_FragColor = vec4(shade(uv, aa), 1.0);
}
// Godot 4. Put this in a ShaderMaterial on a ColorRect.
shader_type canvas_item;

uniform float freq = 6.0;
uniform float angle_deg = 30.0;
uniform float width : hint_range(0.02, 0.95) = 0.5;
uniform float pattern = 0.0;   // 0 stripes, 1 grid, 2 checkerboard
uniform float aspect = 1.0;    // set to the ColorRect's width / height

void fragment() {
    vec2 uv = (UV - 0.5) * vec2(aspect, 1.0);
    uv.y = -uv.y;              // UV (0, 0) is the top-left; make y point up
    float a = radians(angle_deg);
    float c = cos(a);
    float s = sin(a);
    vec2 r = vec2(c * uv.x + s * uv.y, -s * uv.x + c * uv.y);
    vec2 st = r * freq;
    vec2 id = floor(st);
    vec2 f = fract(st);
    vec2 d2 = min(f, 1.0 - f);
    float d = d2.x;
    if (pattern > 0.5) d = min(d2.x, d2.y);
    float aa = fwidth(uv.y) * freq;          // one pixel, in cell units
    float m = 1.0 - smoothstep(0.5 * width - aa, 0.5 * width + aa, d);
    if (pattern > 1.5) m = mod(id.x + id.y, 2.0);
    COLOR = vec4(mix(vec3(0.1, 0.12, 0.22), vec3(1.0, 0.62, 0.2), m), 1.0);
}

Shader "GameDevDaily/StripesCheckers"
{
    Properties
    {
        _Freq ("Frequency (cells per height)", Float) = 6
        _Angle ("Angle (degrees)", Range(0, 180)) = 30
        _Width ("Line width (fraction of a cell)", Range(0.02, 0.95)) = 0.5
        _Pattern ("Pattern (0 stripes, 1 grid, 2 checker)", Float) = 0
        _Aspect ("Aspect (width / height)", Float) = 1
    }
    SubShader
    {
        Tags { "RenderType" = "Opaque" }
        Pass
        {
            CGPROGRAM
            #pragma vertex vert
            #pragma fragment frag
            #pragma target 3.0
            #include "UnityCG.cginc"

            float _Freq, _Angle, _Width, _Pattern, _Aspect;

            struct v2f
            {
                float4 pos : SV_POSITION;
                float2 uv : TEXCOORD0;
            };

            v2f vert (appdata_base v)
            {
                v2f o;
                o.pos = UnityObjectToClipPos(v.vertex);
                o.uv = v.texcoord.xy;
                return o;
            }

            fixed4 frag (v2f i) : SV_Target
            {
                float2 uv = (i.uv - 0.5) * float2(_Aspect, 1.0);  // y already points up
                float a = radians(_Angle);
                float c = cos(a);
                float s = sin(a);
                float2 r = float2(c * uv.x + s * uv.y, -s * uv.x + c * uv.y);
                float2 st = r * _Freq;
                float2 id = floor(st);
                float2 f = frac(st);
                float2 d2 = min(f, 1.0 - f);
                float d = d2.x;
                if (_Pattern > 0.5) d = min(d2.x, d2.y);
                float aa = fwidth(uv.y) * _Freq;
                float m = 1.0 - smoothstep(0.5 * _Width - aa, 0.5 * _Width + aa, d);
                if (_Pattern > 1.5) m = abs(fmod(id.x + id.y, 2.0));  // fmod keeps the sign
                return fixed4(lerp(float3(0.1, 0.12, 0.22), float3(1.0, 0.62, 0.2), m), 1.0);
            }
            ENDCG
        }
    }
}

The Godot and Unity versions leave out the stages and measure one pixel with fwidth, which WebGL 1 lacks without an extension. In URP Shader Graph, the Rotate node (unit set to degrees), Multiply, Fraction, Floor and Modulo nodes build the same chain, and the Checkerboard node draws a checkerboard directly.

Which way is up matters for the angle. WebGL's gl_FragCoord and a Unity Quad's uv have y pointing up. Godot's canvas_item UV and LÖVE's screen_coords have y pointing down, so those two versions flip y first; without the flip, a positive angle would turn the pattern clockwise. The colours are hard-coded numbers, so a Unity project in Linear colour space treats them as linear values, and they will look lighter there than on this page.

Pitfalls

  • A hard edge where fract wraps. The quick version, step(fract(x), w), gives a stripe from 0 to w in each cell. Its far edge can be smoothed, but its near edge is the point where fract jumps from 1.0 back to 0.0, and that jump is always one pixel hard. Folding into a distance with min(f, 1.0 - f) gives both edges a value to smooth.
  • Negative cell numbers. The centred UV makes half the cells negative. GLSL's mod(-1.0, 2.0) is 1.0, which is what a checkerboard needs. HLSL's fmod(-1.0, 2.0) is -1.0, so the Unity version takes abs. Lua's % works like GLSL's mod; math.fmod works like HLSL's.
  • Jagged checker edges. The checker mask is pure 0 or 1, so a rotated board shows small steps along its edges. Unlike the lines, it gets no smoothstep. Smoothing it takes a few more instructions; see the filtering articles under Further reading.
  • Moiré at high frequency. When a cell is only a few pixels across, pixels land on the pattern at uneven phases and wavy patterns appear that are not in the maths. Push Frequency to 80 to see it, and watch the Cell on screen readout. Keep cells several pixels wide, or fade the pattern out; the mipmaps lesson solves the same problem for textures.

What it costs

Everything here is cheap on any GPU, including phones. floor, fract, min and mod are a few arithmetic instructions each. The only notable cost is the cos and sin for the rotation, and the angle is the same for every pixel, so in a real game work them out once in Lua and send the two numbers as uniforms. The demo computes them per pixel to keep the shader readable.

In real games

Prototype levels often put a checkerboard or grid material on everything, so that scale and texture stretching are easy to read. Unity's Shader Graph ships a Checkerboard node for exactly this.

Stripes moving along their own direction are hazard markings, conveyor belts and loading bars. Add time to st.x and they scroll, which is where the Track 2 lessons on time and scrolling UVs pick up.

Your turn (15 minutes)

Turn the LÖVE example into animated hazard tape:

  1. Set angle to 45, width to 0.5 and pattern to 0. Change the two colours in mix to yellow and near-black.
  2. Add a uniform u_time, send love.timer.getTime() from love.draw, and add u_time * 2.0 to st.x right after the scale line.
  3. Change the rectangle to a long thin strip, for example 600 by 40 pixels.

You are done when the stripes slide along the strip at a steady speed and stay crisp when you change freq.

Takeaways

  • Rotate, scale, repeat, threshold: four lines turn a position into a pattern.
  • min(f, 1.0 - f) folds the fract sawtooth into a distance to the nearest line; a threshold on it draws stripes, and taking the smaller of the two axes draws a grid.
  • mod(id.x + id.y, 2.0) alternates between neighbouring cells, which is a checkerboard.
  • Rotate the coordinates the opposite way to turn the pattern. Check which way y points in your engine.
  • Patterns are almost free to draw, but break into moiré when cells shrink to a few pixels.
