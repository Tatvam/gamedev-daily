Polar coordinates in shaders: slices, spirals and a cooldown ring

Turn each pixel's UV into an angle and a radius, and a circle becomes a strip where fract slices it, a twist spirals it and step fills it.

An ability icon with a ring that sweeps around like a clock hand while the spell recharges. A health ring split into eight segments. A sunburst of rays behind a "Level complete" banner. All three are hard to draw with x and y, and each takes only a few lines once the shader asks "which way, and how far?" instead.

Ask the pixel a different question

A fragment shader is a small function that runs once per pixel and returns a colour. So far its input has been the centred UV: x and y, with (0, 0) in the middle and y up. Polar coordinates describe the same point by its radius, how far it is from the centre, and its angle, which direction it lies in. The pixel does not move; it describes itself differently.

The radius

From the circles lesson: float r = length(uv);. A band of r gives a ring.

The angle

GLSL's two-argument atan(y, x) returns the angle of (x, y) in radians, from −π to π. Zero points right and the angle grows counter-clockwise when y points up. A cooldown starts at the top and runs clockwise instead, and swapping the arguments gives exactly that:

float a = atan(uv.x, uv.y);          // 0 at the top, growing clockwise
float t = fract(a / 6.2831853);      // in turns: 0 to 1 once around

atan(x, y) measures from the +y axis towards +x, which is clockwise when y is up. Dividing by 2π, one turn in radians, gives −0.5 to 0.5, and fract wraps the negative half on to 0.5 to 1. So t is the angle in turns: 0 at the top, 0.25 right, 0.5 bottom, 0.75 left, then back to 0 at the top. That jump is the seam.

A circle becomes a strip

Treat (t, r) as a new pair of coordinates and a ring becomes a straight band, each wedge a column. In that strip the earlier tools work unchanged: fract and floor cut cells, step and smoothstep draw edges.

Building the cooldown ring, one line at a time

Each step adds one line; the demo's Stage menu shows each result.

  1. Slices. float s = t * u_segments; then floor(s) is the slice number and fract(s) the position inside it, 0 to 1: the tiling from the fract lesson, done on the angle.
  2. A twist. Before slicing, add an angle that grows with the radius: fract(t + u_twist * r). The columns lean, and wrapped back into a circle they become spiral arms.
  3. The ring. One minus a smoothstep of abs(r - 0.32) keeps radii from 0.22 to 0.42.
  4. Gaps. A slice is a fixed fraction of a turn, so it gets wider the further out you go. For gaps of even width, convert the distance to the slice edge into length along the arc: multiply by 2π and by r, divide by the slice count.
  5. The fill. The cooldown is t < u_fill. For a soft edge, measure along the arc too: smoothstep(-aa, aa, (u_fill - t) * 6.2831853 * r), where aa is one pixel in UV units.

For a sunburst, colour alternate slices with mod(floor(s), 2.0). The demo draws one behind the ring.

Rule of thumb

If a shape goes around a point, convert to (t, r) and draw it as if it were straight. Widths in turns grow with the radius, so multiply by r for an even width.

Try it

Drag Fill and watch the sweep start at the top and run clockwise, or switch on Run the cooldown. Change Slices and Gap: the gaps stay the same width across the ring. Drag Twist to bend everything into spirals.

Drag on the picture to move the probe; the readout gives its angle and radius. Walk the Stage menu from 1 to 7. In stage 2, look straight up from the centre to find the seam. Try an odd slice count and find where two rays of the same colour meet.

The code

The Lua version runs the demo's shader in LÖVE, whose pixel shaders use the entry point effect instead of main. Click to place the probe. Left and right change the slice count, up and down change the twist, space starts and stops the cooldown, M toggles the maths angle and S cycles the stage.

-- The demo's starting values. Centred uv: (0, 0) in the middle, y up.
local segments = 8          -- slices around the ring
local twist = 0             -- extra turns per uv unit of radius
local fill = 0.65           -- 0 to 1, how much has recharged
local gap = 0.012           -- gap between slices, in uv units
local mathAngle = 0         -- 1 starts at the right and turns counter-clockwise
local running = false       -- when on, the ring refills every 3 seconds
local duration = 3
local stage = 6             -- 0 uv, 1 angle, 2 radius, 3 slices, 4 mask, 5 fill, 6 final
local probe = { 0.25, 0.2 } -- in uv units
local rect = { 20, 20, 640, 360 }   -- x, y, width, height in pixels
local shader

local pixelcode = [[
uniform float u_segments;   // slices around the ring
uniform float u_twist;      // extra turns per uv unit of radius
uniform float u_fill;       // 0 to 1, how much has recharged
uniform float u_gap;        // gap between slices, in uv units
uniform float u_math;       // 1.0 starts at the right and turns counter-clockwise
uniform float u_stage;
uniform vec2 u_probe;       // centred uv of the probe
uniform vec4 u_rect;        // x, y, width, height in pixels

const float TWO_PI = 6.2831853;

vec3 shade(vec2 uv, float aa) {
  float r = length(uv);                            // radius: distance from the centre
  vec2 p = r > 0.0001 ? uv : vec2(0.0, 1.0);       // atan(0, 0) is undefined
  float a = atan(p.x, p.y);                        // 0 at the top, clockwise
  if (u_math > 0.5) a = atan(p.y, p.x);            // 0 at the right, counter-clockwise
  float t = fract(a / TWO_PI);                     // angle in turns, 0 to 1
  float s = fract(t + u_twist * r) * u_segments;   // twisted angle, in slices
  float id = floor(s);                             // which slice
  float f = fract(s);                              // where inside the slice, 0 to 1
  float edge = min(f, 1.0 - f) * TWO_PI * r / u_segments;   // to the slice edge, uv units
  float ring = 1.0 - smoothstep(0.1 - aa, 0.1 + aa, abs(r - 0.32));   // radius 0.22 to 0.42
  float gaps = smoothstep(0.5 * u_gap - aa, 0.5 * u_gap + aa, edge);
  float mask = ring * gaps;
  float filled = smoothstep(-aa, aa, (u_fill - t) * TWO_PI * r);   // edge along the arc
  if (u_fill <= 0.0) filled = 0.0;
  if (u_fill >= 1.0) filled = 1.0;

  vec3 dark = vec3(0.1, 0.12, 0.2);
  vec3 light = vec3(0.17, 0.2, 0.32);
  vec3 bg = mix(dark, light, mod(id, 2.0));                            // sunburst rays
  bg = mix(0.5 * (dark + light), bg, smoothstep(0.0, 1.5 * aa, edge));  // soften ray edges
  vec3 ringCol = mix(vec3(0.3, 0.34, 0.44), vec3(1.0, 0.62, 0.2), filled);
  vec3 col = mix(bg, ringCol, mask);

  if (u_stage < 5.5) col = vec3(filled);
  if (u_stage < 4.5) col = vec3(mask);
  if (u_stage < 3.5) col = vec3(f, id / u_segments, 0.0);
  if (u_stage < 2.5) col = vec3(r * 2.0);
  if (u_stage < 1.5) col = vec3(t);
  if (u_stage < 0.5) col = vec3(uv + 0.5, 0.0);

  float h = clamp(dot(uv, u_probe) / max(dot(u_probe, u_probe), 0.0001), 0.0, 1.0);
  float line = length(uv - u_probe * h);           // the probe's radius line
  col = mix(col, vec3(0.0), 1.0 - smoothstep(1.5 * aa, 3.0 * aa, line));
  col = mix(col, vec3(1.0), 1.0 - smoothstep(0.5 * aa, 1.5 * aa, line));
  float pd = length(uv - u_probe) - 0.012;         // the probe's dot
  col = mix(col, vec3(0.0), 1.0 - smoothstep(aa, 2.5 * aa, pd));
  col = mix(col, vec3(1.0), 1.0 - smoothstep(-aa, aa, pd));
  return col;
}

vec4 effect(vec4 color, Image tex, vec2 texture_coords, vec2 screen_coords)
{
  vec2 uv = (screen_coords - u_rect.xy - 0.5 * u_rect.zw) / u_rect.w;
  uv.y = -uv.y;                      // y points down here; make it point up
  float aa = 1.0 / u_rect.w;         // one pixel, in uv units
  return vec4(shade(uv, aa), 1.0);
}
]]

function love.load()
  shader = love.graphics.newShader(pixelcode)
end

function love.update(dt)
  if running then
    fill = fill + dt / duration
    if fill >= 1 then fill = fill - 1 end
  end
end

function love.keypressed(key)
  if key == "right" then segments = math.min(16, segments + 1) end
  if key == "left" then segments = math.max(1, segments - 1) end
  if key == "up" then twist = math.min(3, twist + 0.5) end
  if key == "down" then twist = math.max(-3, twist - 0.5) end
  if key == "space" then running = not running end
  if key == "m" then mathAngle = 1 - mathAngle end
  if key == "s" then stage = (stage + 1) % 7 end
end

function love.mousepressed(x, y, button)
  -- screen pixels to centred uv with y up: the same maths as the shader
  probe[1] = (x - rect[1] - 0.5 * rect[3]) / rect[4]
  probe[2] = -(y - rect[2] - 0.5 * rect[4]) / rect[4]
end

function love.draw()
  shader:send("u_segments", segments)
  shader:send("u_twist", twist)
  shader:send("u_fill", fill)
  shader:send("u_gap", gap)
  shader:send("u_math", mathAngle)
  shader:send("u_stage", stage)
  shader:send("u_probe", probe)
  shader:send("u_rect", rect)
  love.graphics.setShader(shader)
  love.graphics.rectangle("fill", rect[1], rect[2], rect[3], rect[4])
  love.graphics.setShader()
end

void main() {
  vec2 px = gl_FragCoord.xy;                             // pixels, origin bottom-left
  vec2 uv = (px - 0.5 * u_resolution) / u_resolution.y;  // centred, y up
  float aa = 1.0 / u_resolution.y;                       // one pixel, in uv units
  gl_FragColor = vec4(shade(uv, aa), 1.0);
}
// Godot 4. A segmented cooldown ring with a sunburst behind it.
// Put this in a ShaderMaterial on a ColorRect.
shader_type canvas_item;

uniform float segments : hint_range(1.0, 16.0, 1.0) = 8.0;
uniform float twist = 0.0;                   // extra turns per uv unit of radius
uniform float fill : hint_range(0.0, 1.0) = 0.65;
uniform float gap = 0.012;                   // in uv units
uniform float aspect = 1.0;                  // set to the ColorRect's width / height

const float TWO_PI = 6.2831853;

void fragment() {
    vec2 uv = (UV - 0.5) * vec2(aspect, 1.0);  // centred
    uv.y = -uv.y;                              // UV.y points down in Godot; make it point up
    float aa = fwidth(uv.y);                   // one pixel, in uv units
    float r = length(uv);
    vec2 p = uv;
    if (r < 0.0001) { p = vec2(0.0, 1.0); }    // atan(0, 0) is undefined
    float t = fract(atan(p.x, p.y) / TWO_PI);  // 0 at the top, clockwise
    float s = fract(t + twist * r) * segments;
    float f = fract(s);
    float edge = min(f, 1.0 - f) * TWO_PI * r / segments;
    float ring = 1.0 - smoothstep(0.1 - aa, 0.1 + aa, abs(r - 0.32));
    float mask = ring * smoothstep(0.5 * gap - aa, 0.5 * gap + aa, edge);
    float filled = smoothstep(-aa, aa, (fill - t) * TWO_PI * r);
    if (fill <= 0.0) { filled = 0.0; }
    if (fill >= 1.0) { filled = 1.0; }
    vec3 ray_a = vec3(0.1, 0.12, 0.2);
    vec3 ray_b = vec3(0.17, 0.2, 0.32);
    vec3 bg = mix(ray_a, ray_b, mod(floor(s), 2.0));
    bg = mix(0.5 * (ray_a + ray_b), bg, smoothstep(0.0, 1.5 * aa, edge));
    vec3 ring_col = mix(vec3(0.3, 0.34, 0.44), vec3(1.0, 0.62, 0.2), filled);
    COLOR = vec4(mix(bg, ring_col, mask), 1.0);
}

// Put it on a material and apply it to a Quad.
Shader "GameDevDaily/PolarCooldown"
{
    Properties
    {
        _Segments ("Slices", Range(1, 16)) = 8
        _Twist ("Twist (turns per uv unit)", Float) = 0
        _Fill ("Fill", Range(0, 1)) = 0.65
        _Gap ("Gap (uv units)", Float) = 0.012
        _Aspect ("Aspect (width / height)", Float) = 1
    }
    SubShader
    {
        Tags { "RenderType" = "Opaque" }
        Pass
        {
            CGPROGRAM
            #pragma vertex vert
            #pragma fragment frag
            #pragma target 3.0
            #include "UnityCG.cginc"

            float _Segments, _Twist, _Fill, _Gap, _Aspect;
            static const float TWO_PI = 6.2831853;

            struct v2f
            {
                float4 pos : SV_POSITION;
                float2 uv : TEXCOORD0;
            };

            v2f vert (appdata_base v)
            {
                v2f o;
                o.pos = UnityObjectToClipPos(v.vertex);
                o.uv = v.texcoord.xy;
                return o;
            }

            fixed4 frag (v2f i) : SV_Target
            {
                float2 uv = (i.uv - 0.5) * float2(_Aspect, 1.0);  // centred, y up
                float aa = fwidth(uv.y);
                float r = length(uv);
                float2 p = uv;
                if (r < 0.0001) p = float2(0.0, 1.0);             // atan2(0, 0) is undefined
                float t = frac(atan2(p.x, p.y) / TWO_PI);         // 0 at the top, clockwise
                float segs = floor(_Segments);
                float s = frac(t + _Twist * r) * segs;
                float f = frac(s);
                float edge = min(f, 1.0 - f) * TWO_PI * r / segs;
                float ring = 1.0 - smoothstep(0.1 - aa, 0.1 + aa, abs(r - 0.32));
                float mask = ring * smoothstep(0.5 * _Gap - aa, 0.5 * _Gap + aa, edge);
                float filled = smoothstep(-aa, aa, (_Fill - t) * TWO_PI * r);
                if (_Fill <= 0.0) filled = 0.0;
                if (_Fill >= 1.0) filled = 1.0;
                float3 dark = float3(0.1, 0.12, 0.2);
                float3 light = float3(0.17, 0.2, 0.32);
                float ray = frac(floor(s) * 0.5) * 2.0;  // 0 or 1; HLSL fmod differs from GLSL mod
                float3 bg = lerp(dark, light, ray);
                bg = lerp(0.5 * (dark + light), bg, smoothstep(0.0, 1.5 * aa, edge));
                float3 ringCol = lerp(float3(0.3, 0.34, 0.44), float3(1.0, 0.62, 0.2), filled);
                return fixed4(lerp(bg, ringCol, mask), 1.0);
            }
            ENDCG
        }
    }
}

WebGL's gl_FragCoord and a Unity Quad's uv start at the bottom-left with y up, so atan(x, y) runs clockwise from the top. Godot's canvas_item UV and LÖVE's screen_coords start at the top-left with y down; without the y flip, the same line would start at the bottom and run counter-clockwise. HLSL's atan2 takes y first, like GLSL's atan. In URP Shader Graph, the Polar Coordinates node outputs a radius and an angle; check where its angle starts and which way it runs before relying on it. In a Unity project set to Linear colour space, the hard-coded colours look lighter than on this page.

Pitfalls

  • One-argument atan. atan(y / x) only returns −π/2 to π/2, so the left half copies the right half. Use the two-argument form.
  • Swapped arguments by accident. Swapping them changes both where the angle starts and which way it turns. Do it on purpose or not at all.
  • A line along the seam. Anything that compares neighbouring pixels sees a huge jump at the seam: fwidth(t) for anti-aliasing, or a texture sampled with t, can draw a thin line there. Measure edges in UV units, as this shader does.
  • The centre pixel. atan(0.0, 0.0) is undefined in GLSL. The guard costs one comparison.
  • Odd slice counts. With 7 slices, slices 6 and 0 are both even, so two same-coloured rays meet at the seam. Use an even count for sunbursts.

What it costs

length is a square root, which GPUs do quickly. atan is the expensive line: on most GPUs it is not one instruction but a short sequence the compiler expands, so it costs several times a multiply. One per pixel is fine even on a phone, especially on an icon a few thousand pixels big. Be more careful with full-screen effects that call it several times per pixel on low-end mobiles.

In real games

The radial cooldown sweep over an ability icon is a long-standing convention in MMOs and action games; World of Warcraft's action bar is a familiar example. Games draw it in different ways, with a shader or with a fan of triangles, so this is one way, not how a particular game does it.

Both engines ship the same parameters. Unity's UI Image has an Image Type of Filled with a Fill Method of Radial 360, a Fill Origin, a Fill Amount and a Clockwise option. Godot's TextureProgressBar has clockwise and counter-clockwise fill modes and a radial_initial_angle property. A custom shader earns its place when you want even gaps, spirals or a sunburst.

Your turn (15 minutes)

Start from the LÖVE example:

  1. Add a bright line at the leading edge of the fill, like a clock hand: inside the ring, add white where abs(u_fill - t) * 6.2831853 * r is less than two pixels.
  2. Make the sunburst turn: keep a time variable that grows in love.update(dt), send it as u_spin, and add it to t before slicing for the background rays only.

You are done when the hand has the same width at the inside and the outside of the ring, and the rays turn while the ring's slices stay still.

Takeaways

  • r = length(uv) and t = fract(atan(uv.x, uv.y) / 2π) describe a pixel by how far and which way, with t in turns from the top, clockwise when y points up.
  • In (t, r) space a ring is a straight band, so fract, floor and step slice it and fill it as on ordinary UVs.
  • Adding twist * r to the angle before slicing turns slices into spirals.
  • Distances in turns grow with the radius; multiply by 2π·r to get even widths.
  • Watch the seam at t = 0 and the undefined centre; atan is the one costly line.
