Time and animation: pulsing and looping with u_time

One time uniform makes a shader move: sin of time gives a pulse that swings back and forth, fract of time gives a loop that grows and starts again.

A health pickup that gently breathes so the player notices it. A shockwave ring that grows and fades, again and again. A row of lights that ripple like a crowd doing a wave.

None of these need a sprite sheet or a tween. Give the shader one extra number, the time, and the shapes from the last few lessons start to move.

Time is just another input

A fragment shader is a small function that runs once per pixel and returns a colour. So far its inputs were the pixel position and a few sliders. A shader has no memory between frames: it cannot add a little to a position each frame the way game code does. To animate, it must work out the whole picture from scratch each frame, from a number that changes.

That number is a time uniform: the seconds since the effect started, sent by the CPU before each frame. Like every uniform, it has the same value for every pixel in the draw. On this site it is u_time. Godot calls it TIME, Unity _Time.y, Shadertoy iTime, and in LÖVE you send it yourself.

float phase = u_time * u_speed;   // cycles completed so far
float w = sin(6.2832 * phase);    // swings from -1 to 1 and back
float d = length(uv) - (0.2 + u_amp * w);  // a circle whose radius breathes

Read it as three steps. First, phase turns seconds into cycles: with u_speed = 0.5, half a cycle passes each second. Second, a shaping function turns cycles into a value with a useful range. Third, that value goes into something you already know how to draw, here the radius of the circle from the distance lesson.

sin: back and forth

sin takes an angle in radians and returns a value between -1 and 1. One full turn is 2π, about 6.2832, so multiplying the phase by 6.2832 makes one cycle of phase one full swing. The speed is then in cycles per second: 0.5 means one breath every 2 seconds.

The amplitude is how far the value swings. u_amp * w moves between -u_amp and +u_amp, so a radius of 0.2 + 0.08 * w breathes between 0.12 and 0.28.

fract: grow, then start again

fract(phase) keeps only the part after the decimal point. It climbs from 0 to 1 over each cycle, then drops back to 0. This shape is called a sawtooth. Use it for anything that plays once and repeats: a growing ring, a sweeping scan line. Hide the hard drop by fading out as the value nears 1, with 1.0 - fract(phase).

Same time, different phase

Every pixel sees the same u_time, but nothing stops you mixing it with something that differs per pixel or per shape. Subtract a little from the phase for each dot in a row, sin(6.2832 * (phase - 0.1 * i)), and each dot reaches its peak a tenth of a cycle after its neighbour. The row carries a travelling wave. The offset is called a phase offset.

Rule of thumb

Time in, cycles out, shape last: multiply by a speed, shape with sin or fract, then scale and add to a size, a position or a colour you already know how to draw.

Try it

The code

The Lua version runs the demo's shader in LÖVE, whose pixel shaders use the entry point effect instead of main. LÖVE has no time uniform, so love.update(dt) adds up the seconds and love.draw sends them. Keys 1 to 3 pick the motion, up and down change the speed, left and right the amplitude, S cycles the stage and space pauses time.

-- The demo's starting values. Centred uv: (0, 0) in the middle, y up.
local speed = 0.5      -- cycles per second
local amp = 0.08       -- uv units
local mode = 0         -- 0 pulse, 1 ping, 2 wave
local stage = 3        -- 0 driver, 1 distance, 2 mask, 3 final
local paused = false
local time = 0         -- seconds, added up in love.update
local rect = { 20, 20, 640, 360 }   -- x, y, width, height in pixels
local shader

local pixelcode = [[
uniform float u_time;
uniform float u_speed;
uniform float u_amp;
uniform float u_mode;
uniform float u_stage;
uniform vec4 u_rect;

vec3 bands(float d, float aa) {
    vec3 side = mix(vec3(0.35, 0.6, 1.0), vec3(1.0, 0.62, 0.2), step(d, 0.0));
    vec3 c = side * (0.75 + 0.25 * cos(6.2832 * 20.0 * d));
    return mix(c, vec3(1.0), 1.0 - smoothstep(aa, 2.0 * aa, abs(d)));
}

vec3 shade(vec2 uv, float aa) {
    float phase = u_time * u_speed;            // 1. cycles so far
    float w = sin(6.2832 * phase);             // 2. -1 to 1 and back
    float f = fract(phase);                    //    0 to 1, then back to 0
    float shown = 0.5 + 0.5 * w;               //    the driver as a grey
    float fade = 1.0;
    float d = length(uv) - (0.2 + u_amp * w);  // 3. pulse: radius breathes
    if (u_mode > 0.5 && u_mode < 1.5) {      // ping: ring grows and fades
        d = abs(length(uv) - (0.05 + 3.0 * u_amp * f)) - 0.015;
        fade = 1.0 - f;
        shown = f;
    }
    if (u_mode > 1.5) {                        // wave: each dot a bit behind
        d = 1.0;
        for (int k = 0; k < 7; k++) {
            float i = float(k) - 3.0;
            float y = u_amp * sin(6.2832 * (phase - 0.1 * i));
            d = min(d, length(uv - vec2(0.12 * i, y)) - 0.04);
        }
    }
    float m = (1.0 - smoothstep(-aa, aa, d)) * fade;                // 4. mask
    vec3 col = mix(vec3(0.1, 0.12, 0.22), vec3(1.0, 0.62, 0.2), m); // 5. final
    if (u_stage < 2.5) col = vec3(m);
    if (u_stage < 1.5) col = bands(d, aa);
    if (u_stage < 0.5) col = vec3(shown);
    return col;
}

vec4 effect(vec4 color, Image tex, vec2 texture_coords, vec2 screen_coords)
{
    vec2 uv = (screen_coords - u_rect.xy - 0.5 * u_rect.zw) / u_rect.w;
    uv.y = -uv.y;                     // y points down here; make it point up
    float aa = 1.0 / u_rect.w;        // one pixel, in uv units
    return vec4(shade(uv, aa), 1.0);
}
]]

function love.load()
  shader = love.graphics.newShader(pixelcode)
end

function love.update(dt)
  if not paused then
    time = time + dt               -- the clock the shader reads
  end
end

function love.keypressed(key)
  if key == "1" then mode = 0 end
  if key == "2" then mode = 1 end
  if key == "3" then mode = 2 end
  if key == "up" then speed = math.min(2, speed + 0.05) end
  if key == "down" then speed = math.max(0, speed - 0.05) end
  if key == "right" then amp = math.min(0.15, amp + 0.01) end
  if key == "left" then amp = math.max(0, amp - 0.01) end
  if key == "s" then stage = (stage + 1) % 4 end
  if key == "space" then paused = not paused end
end

function love.draw()
  shader:send("u_time", time)
  shader:send("u_speed", speed)
  shader:send("u_amp", amp)
  shader:send("u_mode", mode)
  shader:send("u_stage", stage)
  shader:send("u_rect", rect)
  love.graphics.setShader(shader)
  love.graphics.rectangle("fill", rect[1], rect[2], rect[3], rect[4])
  love.graphics.setShader()
end

void main() {
  vec2 px = gl_FragCoord.xy;                             // pixels, origin bottom-left
  vec2 uv = (px - 0.5 * u_resolution) / u_resolution.y;  // centred, y up
  float aa = 1.0 / u_resolution.y;                       // one pixel, in uv units
  gl_FragColor = vec4(shade(uv, aa), 1.0);
}

// Put this in a ShaderMaterial on a ColorRect.
shader_type canvas_item;

uniform float speed = 0.5;                        // cycles per second
uniform float amp : hint_range(0.0, 0.15) = 0.08; // uv units
uniform float aspect = 1.0;    // set to the ColorRect's width / height

void fragment() {
    vec2 uv = (UV - 0.5) * vec2(aspect, 1.0);    // centred; y points down
    float phase = TIME * speed;
    float w = sin(6.2832 * phase);
    float d = length(uv) - (0.2 + amp * w);
    float aa = fwidth(uv.y);   // one pixel, in uv units
    float m = 1.0 - smoothstep(-aa, aa, d);
    COLOR = vec4(mix(vec3(0.1, 0.12, 0.22), vec3(1.0, 0.62, 0.2), m), 1.0);
}

// Put it on a material and apply it to a Quad.
Shader "GameDevDaily/PulseCircle"
{
    Properties
    {
        _Speed ("Speed (cycles per second)", Float) = 0.5
        _Amp ("Amplitude", Range(0, 0.15)) = 0.08
        _Aspect ("Aspect (width / height)", Float) = 1
    }
    SubShader
    {
        Tags { "RenderType" = "Opaque" }
        Pass
        {
            CGPROGRAM
            #pragma vertex vert
            #pragma fragment frag
            #pragma target 3.0
            #include "UnityCG.cginc"

            float _Speed, _Amp, _Aspect;

            struct v2f
            {
                float4 pos : SV_POSITION;
                float2 uv : TEXCOORD0;
            };

            v2f vert (appdata_base v)
            {
                v2f o;
                o.pos = UnityObjectToClipPos(v.vertex);
                o.uv = v.texcoord.xy;
                return o;
            }

            fixed4 frag (v2f i) : SV_Target
            {
                float2 uv = (i.uv - 0.5) * float2(_Aspect, 1.0);  // y points up
                float phase = _Time.y * _Speed;   // _Time.y is seconds
                float w = sin(6.2832 * phase);
                float d = length(uv) - (0.2 + _Amp * w);
                float aa = fwidth(uv.y);
                float m = 1.0 - smoothstep(-aa, aa, d);
                return fixed4(lerp(float3(0.1, 0.12, 0.22), float3(1.0, 0.62, 0.2), m), 1.0);
            }
            ENDCG
        }
    }
}

The Godot and Unity versions show the pulse; swap in the ping or wave lines from the GLSL tab for the others. In URP Shader Graph, the Time node gives the seconds, and a Multiply, Sine or Fraction node does the rest.

The pulse looks the same with y up or down; the wave does not. WebGL's gl_FragCoord and a Unity Quad's uv start at the bottom-left with y up; Godot's canvas_item UV and LÖVE's screen_coords start at the top-left with y down, which is why the LÖVE version flips y. In a Unity project set to Linear colour space, the hard-coded colours are treated as linear values and look lighter than on this page.

Pitfalls

  • Changing the speed makes the shape jump. u_time * u_speed recomputes the phase from the start of time. At 103 seconds, raising the speed from 0.50 to 0.55 moves the phase forward by 5.15 cycles at once, so the shape snaps to a different point in its swing. If speed changes during play, add up the phase on the CPU and send that instead: 
    phase = phase + speed * dt   -- in love.update(dt)
shader:send("u_phase", phase)
  • Time grows without limit, and floats run out of precision. A 32-bit float carries about 7 significant digits; mediump on many phones carries closer to 3. With mediump time, after a minute or so the gaps between representable values are longer than a frame, and the animation starts to stutter. Desktop GPUs often run mediump at full precision, so you only see it on a phone. Wrap the value on the CPU, for example time % 60 when every loop divides 60 seconds evenly. Godot wraps TIME for this reason, by default every 3600 seconds (a project setting).
  • Forgetting the 6.2832. sin(u_time) repeats every 6.28 seconds, not every second.
  • A visible restart. fract jumps from 1 back to 0. Fade the effect to nothing before the jump, or make the end of the loop look the same as its start.
  • Marching in step. Ten pickups sharing one phase pulse together like a metronome. Give each a phase offset, from its position or an id, so they breathe independently.

What it costs

sin, fract and a multiply are a few cycles each on any GPU, and sending one float per frame is free. The wave mode's seven sin calls per pixel are still cheap. The real cost of animation is that the shader now runs again every frame. A still effect can be drawn once and kept; a moving one keeps the GPU busy every frame it is on screen, which on a phone means battery. Keep animated full-screen shaders small and stop updating the ones that are off screen, as this page does.

In real games

Every major engine passes the time to shaders as a built-in: TIME in Godot, _Time in Unity's built-in shader variables (with _SinTime and _CosTime precomputed), and a Time node in Unity's Shader Graph. Shadertoy gives every shader iTime.

The patterns here are everyday ones: pickups that pulse to catch the eye, buttons that glow while waiting for a press, and expanding rings for shockwaves and click markers. Animating in the shader means a hundred pickups share one material and need no per-object scripts.

Your turn (15 minutes)

Turn the LÖVE example into a heartbeat for a low-health warning:

  1. In pulse mode, replace w with a sharp beat: float beat = pow(0.5 + 0.5 * sin(6.2832 * phase), 8.0);, then use 0.2 + u_amp * beat as the radius. Raising to a high power keeps the value near 0 most of the cycle and makes it spike briefly.
  2. Set the speed to 1.2 cycles per second, about 72 beats per minute.
  3. Fix the speed-jump pitfall: keep a phase variable in Lua, add speed * dt to it in love.update(dt), send it as u_phase, and use it in place of u_time * u_speed.

You are done when the circle gives a quick thump and rests, and holding the up arrow speeds the heartbeat up without the circle ever jumping.

Takeaways

  • A shader has no memory between frames; it animates by recomputing everything from a time uniform that is the same for every pixel.
  • Multiply time by a speed to get cycles, then shape it: sin(6.2832 * phase) swings from -1 to 1, fract(phase) ramps from 0 to 1 and restarts.
  • Scale by an amplitude and add a base value, then feed the result into a size, position or colour you can already draw.
  • A phase offset per shape or per pixel turns one clock into waves and keeps copies out of step.
  • Accumulate the phase on the CPU if speed changes, and wrap time so it stays precise on phones.
