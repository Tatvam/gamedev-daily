Point lights and attenuation: light that fades with distance

A point light gives every pixel its own direction and distance. N·L handles the direction; a falloff curve that reaches zero at a range handles the distance.

A torch on a dungeon wall should light the floor around it and leave the far corner dark. A sun cannot do that: it lights the whole room equally. You need a light that sits at a point, and brightness that drops the further a pixel is from it.

From a direction to a position

A fragment shader is a small function that runs once per pixel and returns a colour. Last lesson it took a normal N and one light direction L, shared by every pixel, and returned albedo × max(N·L, 0).

A point light is a light at a position that shines equally in all directions, like a bare bulb. Now every pixel has to work out its own L, because each one sees the bulb from a different angle. That takes one more input: the surface point's position in the world. The shader subtracts it from the light's position:

local tx, ty, tz = lightX - px, lightY - py, lightZ - pz   -- surface to light
local d = math.sqrt(tx * tx + ty * ty + tz * tz)          -- distance to the light
local lx, ly, lz = tx / d, ty / d, tz / d                 -- L, length 1

Dividing by d normalises the vector, so the distance we need anyway is the same number that makes L a unit vector. N·L works exactly as before.

Why light fades: the inverse square law

A bulb's light spreads over a sphere around it. Twice as far, the sphere has four times the area, so each patch gets a quarter. Brightness goes as 1 / d². That is the inverse square law, and the fading it describes is called attenuation, or falloff.

Pure 1 / d² has two problems in a game. Close to the light it shoots towards infinity. Far away it gets small but never reaches zero, so every light touches every pixel on screen. A game wants to skip a light for pixels it cannot visibly reach, and that only works if the light has a range: a distance past which it contributes exactly nothing.

Four falloff curves

The demo lets you switch between these, with r = d / range:

none             1
linear           max(1 - r, 0)
inverse square   1 / d²
windowed         max(1 - r⁴, 0)² / (d² + 1)

Linear is cheap and reaches zero, but it does not look like a real light: the bright spot is too wide and the edge too sudden. The windowed curve is the one Brian Karis described for Unreal Engine 4 in 2013. The d² + 1 keeps it finite near the bulb, and the window (1 − r⁴)² stays close to 1 for most of the range, then eases the light down to exactly zero at the range.

The whole effect, with the demo's Stage menu showing each line:

d      = length(lightPos - pos)             -- 1. how far is the light?
att    = intensity * falloff(d)             -- 2. how much survives the trip?
ndotl  = max(dot(N, (lightPos - pos) / d), 0) -- 3. do I face it?
light  = att * ndotl                        -- 4. light arriving here
colour = albedo * (lightColour * light + ambient) -- 5. tint it

Axes, units and colour space

The demo looks straight down at a floor: x right, y up the screen, z the height above the floor, towards you. gl_FragCoord has (0, 0) at the bottom-left; LÖVE's screen_coords and Godot's UV start at the top-left, so those tabs flip y. Distances are in world units, with the canvas 4 units tall. The page skips gamma correction, which makes inverse square look harsher than in a linear pipeline; a later lesson covers gamma.

Try it

Drag on the floor, or use the arrow keys, to move the light. Stage 1 draws a blue line every unit of distance. Stage 2 shows the falloff alone, yellow where it reaches 1 and the screen clips to white. Pick Inverse square and lower the light: the yellow patch grows and the corners never go black. Pick Windowed and drag Range: the light ends at the ring.

Pick None at Stage 4: the floor still darkens away from the light, from N·L alone. The ball's lit side always turns towards the light.

The code

In LÖVE the shader is a string with the effect entry point, drawn over a full-window rectangle. The mouse moves the light, up/down set its height, left/right the range, and 1 to 4 the curve. The numbers match the demo; the floor is flat instead of tiled.

local VIEW = 4.0                              -- the window is 4 world units tall
local light = { x = 0.6, y = 0.4, z = 1.0 }  -- x right, y up, z height above the floor
local range = 3.0
local intensity = 2.0
local curve = 3                               -- 0 none, 1 linear, 2 inverse square, 3 windowed
local shader

local pixelcode = [[
uniform vec2 u_resolution;
uniform vec3 u_lightPos;
uniform float u_range;
uniform float u_intensity;
uniform float u_curve;
const float VIEW = 4.0;
const vec2 BALL = vec2(-1.0, -0.3);
const float BALL_R = 0.45;
const vec3 LIGHT_COL = vec3(1.0, 0.86, 0.65);
const float AMBIENT = 0.04;

float falloff(float d) {
  float r = min(d / u_range, 2.0);
  if (u_curve < 0.5) return 1.0;
  if (u_curve < 1.5) return clamp(1.0 - r, 0.0, 1.0);
  if (u_curve < 2.5) return 1.0 / (d * d);
  float w = clamp(1.0 - r * r * r * r, 0.0, 1.0);
  return w * w / (d * d + 1.0);
}

vec3 shade(vec3 pos, vec3 n, vec3 albedo) {
  vec3 toLight = u_lightPos - pos;
  float d = max(length(toLight), 0.05);
  float lit = u_intensity * falloff(d) * max(dot(n, toLight / d), 0.0);
  return albedo * (LIGHT_COL * lit + AMBIENT);
}

vec4 effect(vec4 color, Image tex, vec2 texture_coords, vec2 screen_coords)
{
  vec2 q = (screen_coords - 0.5 * u_resolution) / u_resolution.y * VIEW;
  q.y = -q.y;                          // LÖVE's y grows downwards: make it grow up
  vec3 col = shade(vec3(q, 0.0), vec3(0.0, 0.0, 1.0), vec3(0.62, 0.58, 0.52));
  vec2 b = (q - BALL) / BALL_R;
  if (dot(b, b) < 1.0) {
    vec3 n = vec3(b, sqrt(1.0 - dot(b, b)));
    col = shade(vec3(BALL, BALL_R) + BALL_R * n, n, vec3(0.85, 0.4, 0.2));
  }
  return vec4(col, 1.0) * color;
}
]]

function love.load()
  shader = love.graphics.newShader(pixelcode)
end

function love.keypressed(key)
  if key == "1" or key == "2" or key == "3" or key == "4" then
    curve = tonumber(key) - 1
  end
end

function love.update(dt)
  local w, h = love.graphics.getDimensions()
  local mx, my = love.mouse.getPosition()
  light.x = (mx - 0.5 * w) / h * VIEW
  light.y = -(my - 0.5 * h) / h * VIEW       -- flip: screen y goes down
  if love.keyboard.isDown("up") then light.z = light.z + dt end
  if love.keyboard.isDown("down") then light.z = math.max(0.1, light.z - dt) end
  if love.keyboard.isDown("right") then range = range + 2 * dt end
  if love.keyboard.isDown("left") then range = math.max(0.5, range - 2 * dt) end
end

function love.draw()
  shader:send("u_resolution", { love.graphics.getPixelDimensions() })
  shader:send("u_lightPos", { light.x, light.y, light.z })
  shader:send("u_range", range)
  shader:send("u_intensity", intensity)
  shader:send("u_curve", curve)
  love.graphics.setShader(shader)
  love.graphics.rectangle("fill", 0, 0, love.graphics.getDimensions())
  love.graphics.setShader()
  love.graphics.print(string.format("height %.2f  range %.2f  curve %d", light.z, range, curve), 10, 10)
end
precision mediump float;

uniform vec2 u_resolution;
uniform vec3 u_lightPos;   // light in world units: x right, y up the screen, z height above the floor
uniform vec2 u_lightPx;    // where the light marker is drawn, device pixels, origin bottom-left
uniform float u_range;     // distance at which the windowed and linear curves reach 0
uniform float u_intensity; // brightness multiplier
uniform float u_curve;     // 0 none, 1 linear, 2 inverse square, 3 windowed inverse square
uniform float u_ring;      // 1 draws the floor circle where d equals the range
uniform float u_stage;     // 0 distance ... 4 final colour

const float VIEW = 4.0;                       // the canvas is 4 world units tall
const vec2 BALL = vec2(-1.0, -0.3);           // where the ball rests on the floor
const float BALL_R = 0.45;                    // ball radius
const vec3 LIGHT_COL = vec3(1.0, 0.86, 0.65); // warm light
const float AMBIENT = 0.04;

float falloff(float d) {
  float r = min(d / u_range, 2.0);            // capped so r * r * r * r stays small
  if (u_curve < 0.5) return 1.0;
  if (u_curve < 1.5) return clamp(1.0 - r, 0.0, 1.0);
  if (u_curve < 2.5) return 1.0 / (d * d);
  float w = clamp(1.0 - r * r * r * r, 0.0, 1.0);
  return w * w / (d * d + 1.0);
}

vec3 floorColour(vec2 q) {
  vec2 cell = q * 2.0;                        // tiles half a unit wide
  vec2 id = floor(cell);
  vec2 f = fract(cell);
  float v = fract((id.x * 3.0 + id.y * 5.0) / 7.0);
  vec3 tile = vec3(0.62, 0.58, 0.52) + 0.1 * (v - 0.5);
  float edge = min(min(f.x, 1.0 - f.x), min(f.y, 1.0 - f.y));
  return mix(vec3(0.3, 0.28, 0.26), tile, smoothstep(0.03, 0.07, edge));
}

vec3 shade(vec3 pos, vec3 n, vec3 albedo, float px) {
  // 1. distance and direction from this surface point to the light
  vec3 toLight = u_lightPos - pos;
  float d = max(length(toLight), 0.05);
  vec3 L = toLight / d;
  // 2. how much of the light survives the distance
  float att = u_intensity * falloff(d);
  // 3. Lambert: how squarely the surface faces the light
  float ndotl = max(dot(n, L), 0.0);
  // 4. light arriving at this point
  float lit = att * ndotl;
  // 5. tint by the light and surface colours, plus a little ambient
  vec3 col = albedo * (LIGHT_COL * lit + AMBIENT);

  if (u_stage < 3.5) col = vec3(lit);
  if (u_stage < 2.5) col = vec3(ndotl);
  if (u_stage < 1.5) col = mix(vec3(att), vec3(1.0, 0.8, 0.2), step(1.0, att));
  if (u_stage < 0.5) {
    float band = abs(fract(d + 0.5) - 0.5);   // 0 on every whole unit of distance
    col = vec3(clamp(d / 6.0, 0.0, 1.0));
    col = mix(col, vec3(0.25, 0.6, 1.0), 1.0 - smoothstep(px, 2.0 * px, band));
  }
  return col;
}

void main() {
  vec2 q = (gl_FragCoord.xy - 0.5 * u_resolution) / u_resolution.y * VIEW;
  float px = VIEW / u_resolution.y;           // one pixel, in world units

  // the floor: height 0, normal straight up
  vec3 col = shade(vec3(q, 0.0), vec3(0.0, 0.0, 1.0), floorColour(q), px);

  // the ball resting on the floor, seen from above
  vec2 b = (q - BALL) / BALL_R;
  float ball = 1.0 - smoothstep(1.0 - px / BALL_R, 1.0, length(b));
  vec3 n = vec3(b, sqrt(max(1.0 - dot(b, b), 0.0)));
  vec3 ballCol = shade(vec3(BALL, BALL_R) + BALL_R * n, n, vec3(0.85, 0.4, 0.2), px);
  col = mix(col, ballCol, ball);

  // the range ring: the circle on the floor where d equals the range
  float h = u_lightPos.z;
  float rr = sqrt(max(u_range * u_range - h * h, 0.0));
  float ring = 1.0 - smoothstep(px, 2.0 * px, abs(length(q - u_lightPos.xy) - rr));
  col = mix(col, vec3(0.3, 0.75, 1.0), ring * u_ring * step(h, u_range) * (1.0 - ball));

  // the light marker
  float lw = max(1.0, u_resolution.y / 300.0);
  float dm = length(gl_FragCoord.xy - u_lightPx);
  col = mix(col, vec3(0.0), 1.0 - smoothstep(lw, 2.0 * lw, abs(dm - 8.5 * lw)));
  col = mix(col, vec3(1.0, 0.86, 0.4), 1.0 - smoothstep(4.5 * lw, 5.5 * lw, dm));
  gl_FragColor = vec4(col, 1.0);
}
// Godot 4, a ShaderMaterial on a ColorRect. A flat floor lit by one hand-made point light.
shader_type canvas_item;

uniform vec2 world_size = vec2(7.1, 4.0);       // match the rect's aspect ratio
uniform vec3 light_pos = vec3(0.6, 0.4, 1.0);   // x right, y up, z height above the floor
uniform float light_range = 3.0;
uniform float intensity = 2.0;
uniform vec3 light_colour = vec3(1.0, 0.86, 0.65);
uniform vec3 albedo = vec3(0.62, 0.58, 0.52);

float falloff(float d) {
    float r = min(d / light_range, 2.0);
    float w = clamp(1.0 - r * r * r * r, 0.0, 1.0);
    return w * w / (d * d + 1.0);
}

void fragment() {
    vec2 q = (UV - 0.5) * world_size;
    q.y = -q.y;                                 // Godot's UV (0, 0) is the top-left, y grows down
    vec3 to_light = light_pos - vec3(q, 0.0);
    float d = max(length(to_light), 0.05);
    float ndotl = max(to_light.z / d, 0.0);     // the floor's normal is (0, 0, 1)
    float lit = intensity * falloff(d) * ndotl;
    COLOR = vec4(albedo * (light_colour * lit + 0.04), 1.0);
}
// Built-in render pipeline, unlit, on a Quad facing the camera. The light position is in the
// quad's own units (x right, y up, z height above the quad), not a Unity Light component.
Shader "GameDevDaily/PointLightFloor"
{
    Properties
    {
        _Albedo ("Albedo", Color) = (0.62, 0.58, 0.52, 1)
        _LampColor ("Lamp colour", Color) = (1, 0.86, 0.65, 1)
        _LampPos ("Lamp position (x, y, height)", Vector) = (0.6, 0.4, 1, 0)
        _Range ("Range", Float) = 3
        _Intensity ("Intensity", Float) = 2
        _WorldSize ("Quad size in world units", Vector) = (7.1, 4, 0, 0)
    }
    SubShader
    {
        Tags { "RenderType" = "Opaque" }
        Pass
        {
            CGPROGRAM
            #pragma vertex vert_img
            #pragma fragment frag
            #include "UnityCG.cginc"

            fixed4 _Albedo;
            fixed4 _LampColor;
            float4 _LampPos;
            float _Range;
            float _Intensity;
            float4 _WorldSize;

            float Falloff (float d)
            {
                float r = min(d / _Range, 2.0);
                float w = saturate(1.0 - r * r * r * r);
                return w * w / (d * d + 1.0);
            }

            fixed4 frag (v2f_img i) : SV_Target
            {
                float2 q = (i.uv - 0.5) * _WorldSize.xy;   // uv (0, 0) is the bottom-left: y is already up
                float3 toLight = _LampPos.xyz - float3(q, 0.0);
                float d = max(length(toLight), 0.05);
                float ndotl = max(toLight.z / d, 0.0);    // the floor's normal is (0, 0, 1)
                float lit = _Intensity * Falloff(d) * ndotl;
                return fixed4(_Albedo.rgb * (_LampColor.rgb * lit + 0.04), 1.0);
            }
            ENDCG
        }
    }
}

The engine tabs light a flat floor with the windowed curve only. In real scenes you place the engine's own OmniLight3D (Godot) or Point Light (Unity), which do this maths for you. In a Unity project set to Linear colour space the falloff looks softer than on this page.

Pitfalls

  • Normalising before measuring. Call normalize(lightPos - pos) first and the length you take afterwards is always 1. Take the length once, then divide by it.
  • Dividing by zero. When the light touches a surface, d is 0 and 1 / d² is infinite. Clamp d to a small minimum, or use the d² + 1 form. On phones, mediump floats are often 16-bit: the GLSL ES spec only promises a range of about ±16,000, so large intermediate values overflow sooner than you expect. That is why the demo caps d / range at 2 before raising it to the fourth power.
  • Cutting pure 1 / d² at the range. If an engine stops drawing a light at its range but the curve has not reached zero, the light's edge pops when objects cross it. Use a curve that is already zero there.
  • Mixing up units. A curve tuned with d in metres is useless with d in pixels. Convert positions to one world unit before measuring.
  • Positions in different spaces. Light and surface positions must both be in world space (or both in view space), or the light slides when the object moves.

What it costs

One point light is a subtraction, a length (a square root), a divide, a dot product and a few multiplies per pixel: cheap even on a phone. The cost is lights × pixels. A light only has to run on pixels inside its range, and engines use that to skip work, so keep ranges as small as the scene allows. Unity's URP also caps how many extra lights affect each object.

In real games

The fixed-function lighting of classic OpenGL and Direct3D attenuated point lights by 1 / (constant + linear × d + quadratic × d²), with the three numbers set per light. Unreal Engine 4 switched to the windowed inverse square curve shown here, as described in Karis's 2013 course notes. Godot's OmniLight3D has a Range and an Attenuation property that bends its curve. Godot's 2D PointLight2D works differently: its falloff comes from a texture, often a radial gradient. Unity's Point Light has a Range, and in URP the falloff is an inverse square that is smoothed to zero at that range.

Takeaways

  • A point light needs each pixel's position: L = (lightPos − pos) / d, where d is the distance between them.
  • Physical light fades as 1 / d², but that curve never reaches zero and blows up near the light.
  • Games use a falloff that reaches exactly zero at a range, such as max(1 − (d / range)⁴, 0)² / (d² + 1).
  • Final light is intensity × falloff × max(N·L, 0). Even with no falloff, a floor darkens away from the light through N·L.
  • Cost scales with lights × pixels. A small range lets the engine skip pixels the light cannot reach.
