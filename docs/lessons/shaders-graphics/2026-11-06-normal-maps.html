Normal maps: bumps that are only in the lighting

A normal map stores a tilted normal in each texel's colour. Decode it with rgb × 2 − 1, light with it, and a flat quad shades like a bumpy wall.

Walk a torch along a brick wall in a game and every brick catches the light on the edge facing you and goes dark on the edge facing away. Yet the wall is often two triangles. The bricks exist only in a texture that tells the lighting which way each pixel would face if the bricks were real.

Lighting only sees the normal

A fragment shader is a small function that runs once per pixel and returns a colour. In the last three lessons the lighting part of that function took the surface normal N, the direction to the light L and the direction to the eye V, and returned a brightness from N·L and N·H.

Notice what is missing: the shape of the surface. The lighting only asks which way the pixel faces. Hand it a different normal and the pixel shades as if the surface faced that way, even though the triangle is flat.

A normal map is a texture that stores one such normal per texel. The shader reads it and uses the result instead of the mesh's own normal. Jim Blinn described the underlying idea, bump mapping, in 1978: perturb the normal, keep the geometry.

Storing a vector in a colour

A unit normal has components from −1 to 1. A texture channel holds 0 to 1. So the tool that makes the map stores rgb = n × 0.5 + 0.5, and the shader undoes it:

nx = r * 2 - 1      -- red:   tilt along the texture's u direction
ny = g * 2 - 1      -- green: tilt along the texture's v direction
nz = b * 2 - 1      -- blue:  how much the normal points straight out

A flat texel stores (0, 0, 1), which becomes (0.5, 0.5, 1.0), or about (128, 128, 255) in 8 bits. That pale violet is why normal maps look the way they do. Edges facing right are pinker, edges facing up are greener.

Tangent space: "up" is relative to the surface

The stored normal is not in world directions. Blue means "out of this surface", red "along the texture's u axis", green "along its v axis". This frame is tangent space, with axes tangent T, bitangent B and normal N. Because it is relative, one brick texture works on a wall, a floor or a curved pillar.

On a mesh, each vertex carries T and N, and B is their cross product. The shader turns the decoded normal into world space with T × nx + B × ny + N × nz. The demo's quad faces the camera with u right and v up, so T, B and N are just x, y and z.

Strength

Engines give normal maps a strength. One common way to apply it: scale x and y, then normalise. At 0 the surface is flat; above 1 the bumps look deeper than baked.

Which way is green?

OpenGL style (Y+) stores "facing up the image" as more green; Godot, Unity and Blender expect it. DirectX style (Y−) stores it the other way; Unreal Engine expects that. In the wrong convention, top and bottom edges look lit from the wrong side while side edges look right. The fix is g = 1 - g. The demo works with y up and gl_FragCoord's (0, 0) at the bottom-left; the LÖVE tab flips y because its screen_coords start at the top-left.

The code

With no image files, the shader bakes its own normal map: it samples a height function on either side of each pixel, turns the slope into a normal and rounds it to 8 bits, as a texture would. In a game those lines become one texture read, shown in the comment. The mouse moves the light; [ ] set the strength, m toggles the map, f flips green, up / down move the light's height.

local strength = 1.0     -- normal map strength: scales the tilt
local height = 0.2       -- light height above the wall, in window heights
local useMap = 1         -- 1 = use the normal map, 0 = flat normal
local flipY = 0          -- 1 = read green upside down (DirectX-style map)
local shader

local pixelcode = [[
uniform vec2 u_resolution;
uniform vec3 u_light;        // light position: x, y from the centre, z above the wall
uniform float u_strength;
uniform float u_useMap;
uniform float u_flipY;
const float ROWS = 5.0;      // brick rows across the window height
const float DEPTH = 0.08;    // brick height used when baking, in brick heights

float edgeDist(vec2 p) {     // distance to the nearest brick edge
  p.x += mod(floor(p.y), 2.0);
  vec2 c = vec2(mod(p.x, 2.0), fract(p.y));
  return min(min(c.x, 2.0 - c.x), min(c.y, 1.0 - c.y));
}
float height(vec2 p) { return smoothstep(0.04, 0.2, edgeDist(p)); }

vec4 effect(vec4 color, Image tex, vec2 texture_coords, vec2 screen_coords)
{
  vec2 q = (screen_coords - 0.5 * u_resolution) / u_resolution.y;
  q.y = -q.y;                                // LÖVE's y grows downwards: make it grow up
  vec2 p = q * ROWS;

  // bake the normal map from the height map. With a real normal map image:
  // vec3 stored = Texel(tex, texture_coords).rgb;
  float e = 0.01;
  float hx = height(p + vec2(e, 0.0)) - height(p - vec2(e, 0.0));
  float hy = height(p + vec2(0.0, e)) - height(p - vec2(0.0, e));
  vec3 baked = normalize(vec3(-DEPTH * hx / (2.0 * e), -DEPTH * hy / (2.0 * e), 1.0));
  vec3 stored = floor((baked * 0.5 + 0.5) * 255.0 + 0.5) / 255.0;

  vec3 n = stored * 2.0 - 1.0;                  // 1. decode
  n.y = mix(n.y, -n.y, u_flipY);                // 2. green convention
  n.xy *= u_strength;                           // 3. strength
  n = normalize(mix(vec3(0.0, 0.0, 1.0), n, u_useMap));

  vec3 l = normalize(u_light - vec3(q, 0.0));   // point light, as two lessons ago
  float ndotl = dot(n, l);
  vec3 h = normalize(l + vec3(0.0, 0.0, 1.0));
  float spec = pow(max(dot(n, h), 0.0), 40.0) * step(0.0, ndotl);
  vec3 albedo = mix(vec3(0.62, 0.6, 0.55), vec3(0.72, 0.33, 0.24),
                    smoothstep(0.02, 0.05, edgeDist(p)));
  vec3 col = albedo * (max(ndotl, 0.0) + 0.08) + vec3(0.35 * spec);
  return vec4(col, 1.0) * color;
}
]]

function love.load()
  shader = love.graphics.newShader(pixelcode)
end

function love.keypressed(key)
  if key == "]" then strength = math.min(strength + 0.25, 3) end
  if key == "[" then strength = math.max(strength - 0.25, 0) end
  if key == "m" then useMap = 1 - useMap end
  if key == "f" then flipY = 1 - flipY end
end

function love.update(dt)
  if love.keyboard.isDown("up") then height = math.min(height + 0.5 * dt, 1) end
  if love.keyboard.isDown("down") then height = math.max(height - 0.5 * dt, 0.05) end
end

function love.draw()
  local w, h = love.graphics.getDimensions()
  local mx, my = love.mouse.getPosition()
  local lx = (mx - 0.5 * w) / h
  local ly = -(my - 0.5 * h) / h               -- flip: screen y goes down
  shader:send("u_resolution", { love.graphics.getPixelDimensions() })
  shader:send("u_light", { lx, ly, height })
  shader:send("u_strength", strength)
  shader:send("u_useMap", useMap)
  shader:send("u_flipY", flipY)
  love.graphics.setShader(shader)
  love.graphics.rectangle("fill", 0, 0, w, h)
  love.graphics.setShader()
  love.graphics.print("strength " .. strength, 10, 10)
end
#ifdef GL_FRAGMENT_PRECISION_HIGH
precision highp float;
#else
precision mediump float;
#endif

uniform vec2 u_resolution;
uniform vec3 u_light;      // light position: x, y in canvas heights from the centre, z = height above the wall
uniform vec2 u_lightPos;   // where the light marker is drawn, device pixels, origin bottom-left
uniform float u_strength;  // normal map strength: scales the tilt (x and y) of the decoded normal
uniform float u_useMap;    // 1 = use the normal map, 0 = use the flat normal of the quad
uniform float u_flipY;     // 1 = read the green channel upside down (a DirectX-style map)
uniform float u_stage;     // 0 brick UV ... 4 final colour

const float ROWS = 5.0;                  // brick rows across the canvas height
const float DEPTH = 0.08;                // brick height used when baking, in brick heights
const vec3 FLAT = vec3(0.0, 0.0, 1.0);   // the quad's own normal: straight out of the screen
const vec3 V = vec3(0.0, 0.0, 1.0);      // towards the eye
const vec3 BRICK = vec3(0.72, 0.33, 0.24);
const vec3 MORTAR = vec3(0.62, 0.6, 0.55);

// distance from p to the nearest brick edge; bricks are 2 wide and 1 tall, odd rows shifted by 1
float edgeDist(vec2 p) {
  p.x += mod(floor(p.y), 2.0);
  vec2 c = vec2(mod(p.x, 2.0), fract(p.y));
  return min(min(c.x, 2.0 - c.x), min(c.y, 1.0 - c.y));
}

// the height map: 0 in the mortar, 1 on top of a brick, with a rounded bevel between
float height(vec2 p) {
  return smoothstep(0.04, 0.2, edgeDist(p));
}

void main() {
  vec2 q = (gl_FragCoord.xy - 0.5 * u_resolution) / u_resolution.y;  // y up, in canvas heights
  vec2 p = q * ROWS;                                                 // in brick heights

  // bake: the normal map a tool would store, made here from the height map
  float e = 0.01;
  float hx = height(p + vec2(e, 0.0)) - height(p - vec2(e, 0.0));
  float hy = height(p + vec2(0.0, e)) - height(p - vec2(0.0, e));
  vec3 baked = normalize(vec3(-DEPTH * hx / (2.0 * e), -DEPTH * hy / (2.0 * e), 1.0));
  vec3 stored = floor((baked * 0.5 + 0.5) * 255.0 + 0.5) / 255.0;    // 8 bits per channel

  // 1. decode: colour 0..1 back to a vector -1..1
  vec3 n = stored * 2.0 - 1.0;
  // 2. green is "up the texture"; a DirectX-style map stores it the other way
  n.y = mix(n.y, -n.y, u_flipY);
  // 3. strength scales the tilt, then the vector is made unit length again
  n.xy *= u_strength;
  n = normalize(mix(FLAT, n, u_useMap));

  // 4. light with the new normal: a point light, Lambert diffuse and a Blinn-Phong highlight
  vec3 l = normalize(u_light - vec3(q, 0.0));
  float ndotl = dot(n, l);
  float diffuse = max(ndotl, 0.0);
  vec3 h = normalize(l + V);
  float spec = pow(max(dot(n, h), 0.0), 40.0) * step(0.0, ndotl);
  vec3 albedo = mix(MORTAR, BRICK, smoothstep(0.02, 0.05, edgeDist(p)));
  vec3 col = albedo * (diffuse + 0.08) + vec3(0.35 * spec);

  // the stages: brick UVs, height map, stored normal map, diffuse, final
  vec2 b = p;
  b.x += mod(floor(b.y), 2.0);
  vec2 uv = vec2(mod(b.x, 2.0) * 0.5, fract(b.y));
  if (u_stage < 3.5) col = vec3(diffuse);
  if (u_stage < 2.5) col = stored;
  if (u_stage < 1.5) col = vec3(height(p));
  if (u_stage < 0.5) col = vec3(uv, 0.0);

  // the light marker
  float lw = max(1.0, u_resolution.y / 300.0);
  float d = length(gl_FragCoord.xy - u_lightPos);
  vec3 sun = vec3(1.0, 0.82, 0.25);
  col = mix(col, vec3(0.0), 1.0 - smoothstep(lw, 2.0 * lw, abs(d - 8.5 * lw)));
  col = mix(col, sun, 1.0 - smoothstep(6.0 * lw, 7.0 * lw, d));
  gl_FragColor = vec4(col, 1.0);
}
// Godot 4, a spatial shader on any mesh with UVs and tangents (a PlaneMesh, a BoxMesh).
// Godot decodes the map and applies tangent space for you.
shader_type spatial;

uniform sampler2D albedo_tex : source_color;
uniform sampler2D normal_tex : hint_normal;     // an OpenGL-style (Y+) normal map
uniform float strength : hint_range(0.0, 3.0) = 1.0;

void fragment() {
    ALBEDO = texture(albedo_tex, UV).rgb;
    NORMAL_MAP = texture(normal_tex, UV).rgb;    // the stored colour, 0 to 1
    NORMAL_MAP_DEPTH = strength;
}
// Built-in render pipeline, surface shader. Import the texture with Texture Type "Normal map".
Shader "GameDevDaily/NormalMapped"
{
    Properties
    {
        _MainTex ("Albedo", 2D) = "white" {}
        _BumpMap ("Normal map", 2D) = "bump" {}
        _Strength ("Strength", Range(0, 3)) = 1
    }
    SubShader
    {
        Tags { "RenderType" = "Opaque" }
        CGPROGRAM
        #pragma surface surf Lambert

        sampler2D _MainTex;
        sampler2D _BumpMap;
        float _Strength;

        struct Input
        {
            float2 uv_MainTex;
            float2 uv_BumpMap;
        };

        void surf (Input IN, inout SurfaceOutput o)
        {
            o.Albedo = tex2D(_MainTex, IN.uv_MainTex).rgb;
            float3 n = UnpackNormal(tex2D(_BumpMap, IN.uv_BumpMap));  // decode
            n.xy *= _Strength;
            o.Normal = normalize(n);                                 // tangent space
        }
        ENDCG
    }
    FallBack "Diffuse"
}

In both engines you give the tangent-space normal and the engine applies the mesh's tangent frame. In URP Shader Graph, use a Sample Texture 2D node with its Type set to Normal, through a Normal Strength node, into the Fragment block's Normal (Tangent Space) input.

Pitfalls

  • Importing the map as a colour texture. sRGB textures are converted to linear when sampled, which bends every vector. Mark normal maps as data: Texture Type "Normal map" in Unity, hint_normal in Godot, "Non-Color" in Blender.
  • The wrong green convention. If bumps look like dents only on their top and bottom edges, flip green.
  • Skipping the normalise. Filtering and mipmaps average vectors, and averages are shorter than 1; strength changes the length too. Normalise, or N·L comes out too dark.
  • Tangents that do not match the baker. A map baked with one tangent frame and lit with another shows seams, especially on mirrored UVs. MikkTSpace is the common standard; Blender and Unity both use it.
  • Expecting a new silhouette. Only the shading changes. The outline, cast shadows and grazing views stay flat.

What it costs

In a game a normal map costs one texture read per pixel, a multiply-add to decode, a few more for the tangent rotation, and a normalise. That is cheap even on a phone, and far cheaper than the triangles it replaces. The real cost is memory and bandwidth: a second texture the size of the albedo. Two-channel formats such as BC5 store only x and y and rebuild z as sqrt(1 - x² - y²); Unity's UnpackNormal does that for you. The demo costs more than a game would, because it bakes the map every frame. It asks for highp because its small height differences turn to noise at the 16-bit precision mediump often means on phones.

In real games

Normal maps are on almost every surface in modern 3D games. Doom 3 (id Software, 2004) was an early, famous example, using them across its characters and levels, baked from far more detailed models. That is still the usual workflow: model in high detail, then bake the detail onto a low-polygon mesh as a normal map. Godot's StandardMaterial3D and Unity's Standard shader both have a normal map slot with a strength value.

Your turn (15 minutes)

Start from the LÖVE program.

  1. In height, add a small smoothstep dome at each brick's centre. The stud should catch a highlight that slides with the mouse.
  2. Rebuild z from x and y, as a two-channel map would: n.z = sqrt(max(1.0 - dot(n.xy, n.xy), 0.0)). At strength 1 it should look almost identical.
  3. Allow negative strength. At −1 the bricks should look sunk into the wall. Work out why before you try it.

You are done when the studs shine and you can explain what a negative strength does to each component of the normal.

Takeaways

  • Lighting reads only the normal, so changing the normal per pixel fakes detail the mesh does not have.
  • A normal map stores n × 0.5 + 0.5; decode it with rgb × 2 − 1. Flat is (128, 128, 255).
  • The stored normal is in tangent space: red along u, green along v, blue out of the surface. The mesh's T, B and N turn it into world space.
  • Treat the texture as data, not colour, check its green convention, and normalise after filtering and scaling.
