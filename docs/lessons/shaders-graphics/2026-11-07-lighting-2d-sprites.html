Lighting 2D sprites: a normal map for every frame

Pair a sprite with a normal map, give the light a height in front of the screen, and a flat pixel-art character shades towards a passing torch.

In many 2D games a torch only brightens a circle of the screen. A slime that walks past it gets lighter as a whole, but its left edge brightens exactly as much as its right, so it still looks like a sticker. Give the slime a normal map and the edge facing the torch lights up while the far edge stays dark, and the same flat sprite looks round.

A sprite is a flat quad with one more texture

A fragment shader is a small function that runs once per pixel and returns a colour. For a lit sprite, four things go in: the sprite's colour at this pixel (its albedo), the normal map's texel at the same UV, the pixel's position, and the light. One colour comes out.

Yesterday's lesson already did the lighting: decode the normal with rgb × 2 − 1, take its dot product with the direction to the light, and multiply. A sprite is a quad that faces the camera with u to the right and v up, so tangent space is simply screen space and no tangent frame is needed. What is new in 2D is where the light sits, where the normal maps come from, and what happens when the sprite is mirrored.

The light needs a height

In a 2D game a light has an x and a y. If the direction to the light lay flat in the screen, every pixel would see it at a grazing angle and only the very edges of the sprite would catch it. So 2D engines give the light a height: how far it hangs in front of the screen, towards the viewer. Godot's 2D lights call it Height; Unity's 2D lights have a similar distance setting for normal maps.

The vector from a pixel to the light is (light.x − pixel.x, light.y − pixel.y, height). A low light skims across the sprite and brings out its edges. A high light hits it head on, so every normal sees it at about the same angle and the sprite looks flat again.

Brightness from distance works as in the point lights lesson: a falloff that reaches zero at the light's range. In 2D it is usually measured in the plane of the screen, ignoring the height, and that is what the demo does.

Coloured light multiplies

The whole lighting step is one line:

lit = albedo * (ambient + lightColour * max(dot(N, L), 0) * falloff)

Colours multiply channel by channel. An orange torch (1.0, 0.6, 0.25) at full strength on the mint slime (0.45, 0.8, 0.6) gives (0.45, 0.48, 0.15): a warm olive. The ambient term is a small constant so the side facing away is dim, not black.

Where sprite normal maps come from

Each frame of the sprite sheet needs a matching normal map, pixel for pixel, laid out the same way. Artists paint them by hand, generate them from the sprite with tools such as Laigter or SpriteIlluminator, or draw the sprite lit from several sides and let a tool such as Sprite Lamp combine the drawings. Transparent texels usually hold the flat normal (128, 128, 255); the shader never uses them, because the sprite's alpha hides those pixels.

Mirrored sprites break the normals

2D games reuse one walk cycle for both directions by drawing the sprite with a horizontal scale of −1. The colour texture does not mind. The normal map does: the texel now on the right side of the screen was painted for the left side, so its normal still points left. The edge facing the light goes dark. The fix is one line, n.x = n.x * flipX, with flipX set to −1 while the sprite is mirrored. Rotation is the same problem in general form: rotate the normal's x and y by the sprite's angle.

Which way is up?

The demo's shader reads gl_FragCoord, whose (0, 0) is the bottom-left corner with y going up, and the normal map stores "up the image" as more green (the OpenGL style). LÖVE's screen_coords start at the top-left with y going down, so the LÖVE code negates the normal's y. Godot's 2D coordinates also have y going down; Unity's world has y going up. When in doubt, light a test sprite from above: its top edge must brighten.

Try it

Drag on the canvas, or focus it and use the arrow keys, to carry the light around the slime. Turn off Use normal map: the slime only gets brighter or darker as a whole. Turn it back on, then lower Light height to see the edges catch the light, and raise it to flatten the slime.

Set Facing to "left, normals not fixed" and keep the light beside the slime: the edge facing it goes dark. Choose "left, n.x × −1" to fix it. The Stage menu shows each value the shader works with.

The code

The LÖVE program builds the same 32 by 32 slime and its normal map into two images with setPixel, using the same numbers as the demo. In your game you would load two image files instead. The mouse carries the light, f turns the slime around, x switches the normal fix off and on, and n toggles the normal map. The wall is drawn with the same shader and the flat normal.

local TEX = 32                 -- the sprite is 32 by 32 texels
local SPRITE_SIZE = 0.7        -- drawn 0.7 window heights tall
local lightHeight = 0.12       -- in window heights, in front of the screen
local lightRange = 1.2         -- in window heights
local lightColour = { 1.0, 0.6, 0.25 }   -- torch orange
local ambient = 0.15
local facing = 1               -- 1 = right, -1 = drawn mirrored
local fixFlip = true
local useMap = 1
local slime, slimeNormals, shader

local pixelcode = [[
uniform Image u_normalMap;
uniform vec2 u_light;          // light position in pixels, origin top-left
uniform float u_lightHeight;
uniform float u_range;
uniform vec3 u_lightColour;
uniform float u_ambient;
uniform float u_flipX;         // -1 while the sprite is mirrored
uniform float u_useMap;

vec4 effect(vec4 color, Image tex, vec2 texture_coords, vec2 screen_coords)
{
  vec4 albedo = Texel(tex, texture_coords) * color;
  vec3 n = Texel(u_normalMap, texture_coords).rgb * 2.0 - 1.0;
  n.x *= u_flipX;              // a mirrored sprite needs mirrored normals
  n.y = -n.y;                  // green points up the image; screen y points down
  n = normalize(mix(vec3(0.0, 0.0, 1.0), n, u_useMap));
  vec3 toLight = vec3(u_light - screen_coords, u_lightHeight);
  float diffuse = max(dot(n, normalize(toLight)), 0.0);
  float atten = clamp(1.0 - length(toLight.xy) / u_range, 0.0, 1.0);
  atten *= atten;
  vec3 lighting = vec3(u_ambient) + u_lightColour * diffuse * atten;
  return vec4(albedo.rgb * lighting, albedo.a);
}
]]

-- one texel: (cx, cy) is its centre in texels, y up. Returns colour and normal.
local function slimeTexel(cx, cy)
  local ex, ey = (cx - 16) / 14, (cy - 5) / 18
  local r = math.sqrt(ex * ex + ey * ey)
  if r > 1 or cy < 5 then return 0, 0, 0, 0, 0, 0, 1 end
  local cr, cg, cb = 0.45, 0.8, 0.6                          -- slime
  if r > 0.9 or cy < 6 then cr, cg, cb = 0.1, 0.16, 0.14 end  -- outline
  for _, x0 in ipairs({ 18, 24 }) do                         -- eyes
    local dx, dy = (cx - x0) / 1.6, (cy - 13) / 2.8
    if dx * dx + dy * dy < 1 then cr, cg, cb = 0.06, 0.07, 0.1 end
  end
  if cy == 14.5 and (cx == 18.5 or cx == 24.5) then cr, cg, cb = 1, 1, 1 end
  if cy == 8.5 and cx > 20 and cx < 23 then cr, cg, cb = 0.06, 0.07, 0.1 end
  local nz = math.sqrt(1 - r * r) + 0.3                      -- a dome, tilted out at the edges
  local len = math.sqrt(ex * ex + ey * ey + nz * nz)
  return cr, cg, cb, 1, ex / len, ey / len, nz / len
end

function love.load()
  local colour = love.image.newImageData(TEX, TEX)
  local normal = love.image.newImageData(TEX, TEX)
  for py = 0, TEX - 1 do
    for px = 0, TEX - 1 do
      local r, g, b, a, nx, ny, nz = slimeTexel(px + 0.5, TEX - py - 0.5)
      colour:setPixel(px, py, r, g, b, a)
      normal:setPixel(px, py, nx * 0.5 + 0.5, ny * 0.5 + 0.5, nz * 0.5 + 0.5, 1)
    end
  end
  slime = love.graphics.newImage(colour)
  slimeNormals = love.graphics.newImage(normal)
  slime:setFilter("nearest", "nearest")
  slimeNormals:setFilter("nearest", "nearest")
  shader = love.graphics.newShader(pixelcode)
  shader:send("u_normalMap", slimeNormals)
end

function love.keypressed(key)
  if key == "f" then facing = -facing end
  if key == "x" then fixFlip = not fixFlip end
  if key == "n" then useMap = 1 - useMap end
end

function love.draw()
  local w, h = love.graphics.getDimensions()
  shader:send("u_light", { love.mouse.getPosition() })
  shader:send("u_lightHeight", lightHeight * h)
  shader:send("u_range", lightRange * h)
  shader:send("u_lightColour", lightColour)
  shader:send("u_ambient", ambient)
  love.graphics.setShader(shader)

  shader:send("u_useMap", 0)                       -- the wall: flat normal
  shader:send("u_flipX", 1)
  love.graphics.setColor(0.36, 0.37, 0.41)
  love.graphics.rectangle("fill", 0, 0, w, h)

  local scale = SPRITE_SIZE * h / TEX
  shader:send("u_useMap", useMap)
  shader:send("u_flipX", fixFlip and facing or 1)
  love.graphics.setColor(1, 1, 1)
  love.graphics.draw(slime, w / 2, h / 2 + 0.05 * h, 0, scale * facing, scale, TEX / 2, TEX / 2)
  love.graphics.setShader()
end
precision mediump float;

uniform vec2 u_resolution;
uniform vec3 u_light;        // x, y in canvas heights from the centre (y up); z = height in front of the screen
uniform vec2 u_lightPos;     // where the light marker is drawn, device pixels, origin bottom-left
uniform vec3 u_lightColour;
uniform float u_range;       // distance at which the light fades to zero, canvas heights
uniform float u_ambient;
uniform float u_useMap;      // 1 = the sprite uses its normal map, 0 = flat normal
uniform float u_mirror;      // 1 = the sprite is drawn mirrored (facing left)
uniform float u_flipX;       // -1 = negate the normal's x to match the mirror, 1 = leave it
uniform float u_stage;       // 0 texel UVs ... 4 final colour

const float TEX = 32.0;                     // the sprite is 32 by 32 texels
const vec2 SPRITE_POS = vec2(0.0, -0.05);   // centre of the sprite, canvas heights
const float SPRITE_SIZE = 0.7;              // drawn 0.7 canvas heights tall
const vec3 FLAT = vec3(0.0, 0.0, 1.0);
const vec3 SLIME = vec3(0.45, 0.8, 0.6);
const vec3 INK = vec3(0.1, 0.16, 0.14);
const vec3 EYE = vec3(0.06, 0.07, 0.1);

bool inEye(vec2 c, float x0) {
  vec2 d = (c - vec2(x0, 13.0)) / vec2(1.6, 2.8);
  return dot(d, d) < 1.0;
}

// the sprite's colour texture: c is a texel centre in texels, y up
vec4 slimeColour(vec2 c) {
  vec2 e = vec2((c.x - 16.0) / 14.0, (c.y - 5.0) / 18.0);
  float r = length(e);
  if (r > 1.0 || c.y < 5.0) return vec4(0.0);
  vec3 col = SLIME;
  if (r > 0.9 || c.y < 6.0) col = INK;
  if (inEye(c, 18.0) || inEye(c, 24.0)) col = EYE;
  if (abs(c.y - 14.5) < 0.1 && (abs(c.x - 18.5) < 0.1 || abs(c.x - 24.5) < 0.1)) col = vec3(1.0);
  if (abs(c.y - 8.5) < 0.1 && c.x > 20.0 && c.x < 23.0) col = EYE;
  return vec4(col, 1.0);
}

// the sprite's normal map before encoding: a dome, flat where the sprite is transparent
vec3 slimeNormal(vec2 c) {
  vec2 e = vec2((c.x - 16.0) / 14.0, (c.y - 5.0) / 18.0);
  float r = length(e);
  if (r > 1.0 || c.y < 5.0) return FLAT;
  return normalize(vec3(e, sqrt(1.0 - r * r) + 0.3));
}

void main() {
  vec2 q = (gl_FragCoord.xy - 0.5 * u_resolution) / u_resolution.y;   // canvas heights, y up

  // the wall behind: flat stone tiles
  vec2 w = q * 6.0;
  vec2 f = fract(w);
  float tile = step(0.06, min(min(f.x, 1.0 - f.x), min(f.y, 1.0 - f.y)));
  vec3 stone = mix(vec3(0.38, 0.39, 0.43), vec3(0.33, 0.34, 0.38), mod(floor(w.x) + floor(w.y), 2.0));
  vec3 wall = mix(vec3(0.2, 0.2, 0.23), stone, tile);

  // which texel of the sprite is under this pixel (nearest filtering)
  vec2 uv = (q - SPRITE_POS) / SPRITE_SIZE + 0.5;
  uv.x = mix(uv.x, 1.0 - uv.x, u_mirror);
  float inQuad = step(0.0, uv.x) * step(uv.x, 1.0) * step(0.0, uv.y) * step(uv.y, 1.0);
  vec2 c = floor(uv * TEX) + 0.5;
  vec4 albedo = slimeColour(c) * inQuad;
  vec3 stored = floor((slimeNormal(c) * 0.5 + 0.5) * 255.0 + 0.5) / 255.0;   // 8 bits per channel

  // 1. decode  2. undo the mirror  3. sprite pixels use the map, wall pixels the flat normal
  vec3 n = stored * 2.0 - 1.0;
  n.x *= u_flipX;
  n = normalize(mix(FLAT, n, u_useMap * albedo.a));

  // 4. the light: a 3D direction thanks to its height, falloff measured in the screen plane
  vec3 toLight = vec3(u_light.xy - q, u_light.z);
  float diffuse = max(dot(n, normalize(toLight)), 0.0);
  float atten = clamp(1.0 - length(toLight.xy) / u_range, 0.0, 1.0);
  atten *= atten;
  vec3 lighting = vec3(u_ambient) + u_lightColour * diffuse * atten;

  // 5. albedo times light, sprite over wall by its alpha
  vec3 col = mix(wall, albedo.rgb, albedo.a) * lighting;

  // the stages: texel UVs, albedo, stored normal map, lighting, final
  vec3 checker = mix(vec3(0.8), vec3(0.62), mod(floor(c.x * 0.5) + floor(c.y * 0.5), 2.0));
  if (u_stage < 3.5) col = lighting;
  if (u_stage < 2.5) col = mix(wall * 0.35, stored, inQuad);
  if (u_stage < 1.5) col = mix(wall * 0.35, mix(checker, albedo.rgb, albedo.a), inQuad);
  if (u_stage < 0.5) col = mix(wall * 0.35, vec3(c / TEX, 0.0), inQuad);

  // the light marker
  float lw = max(1.0, u_resolution.y / 300.0);
  float d = length(gl_FragCoord.xy - u_lightPos);
  col = mix(col, vec3(0.0), 1.0 - smoothstep(lw, 2.0 * lw, abs(d - 8.5 * lw)));
  col = mix(col, u_lightColour, 1.0 - smoothstep(6.0 * lw, 7.0 * lw, d));
  gl_FragColor = vec4(col, 1.0);
}
// Godot 4. Without any shader: set the Sprite2D's texture to a CanvasTexture,
// put the sprite in Diffuse Texture and its normal map in Normal Map Texture,
// and add a PointLight2D. The light's Height property is the demo's light height.
//
// With your own canvas_item shader, hand Godot the normal yourself and it lights it:
shader_type canvas_item;

uniform sampler2D normal_tex : hint_normal;
uniform float flip_x = 1.0;    // set to -1.0 from a script while the sprite is mirrored

void fragment() {
    vec3 n = texture(normal_tex, UV).rgb * 2.0 - 1.0;
    n.x *= flip_x;
    NORMAL_MAP = n * 0.5 + 0.5;    // stored form, 0 to 1; Godot decodes it
}

//
// 1. Sprite Editor > Secondary Textures: add an entry named _NormalMap
//    and assign the sprite's normal map texture.
// 2. Use a Sprite-Lit material (the default for sprites under the 2D Renderer).
// 3. Add a Light 2D and enable its Normal Maps quality setting.
//    Its Distance value plays the role of the demo's light height.
//
// A custom Shader Graph (Material: Sprite Lit) does the same with nodes:
//   Sample Texture 2D (_MainTex)                -> Base Color and Alpha
//   Sample Texture 2D (_NormalMap, Type: Normal) -> Normal (Tangent Space)
// Unity's 2D lighting then computes N·L for every Light 2D that reaches the sprite.

Godot and Unity read the light's position and colour from their own light nodes, so your shader only supplies the normal. Whether an engine corrects the normals for its own flip option has changed between versions; test it with a light on one side, as in the demo.

Pitfalls

  • Mirroring or rotating without the normals. The colour texture survives a flip; the normals point the wrong way. Multiply n.x by −1 when mirrored, and rotate n.xy with the sprite.
  • The wrong y direction. Screen y goes down in LÖVE and Godot 2D and up in WebGL and Unity. If a light above lights the bottom edge, negate n.y once, in one place.
  • The light at height 0. The direction lies in the screen and the face of the sprite never catches it. Start around a fifth of the sprite's size and adjust by eye.
  • Normal map and sprite out of step. Each animation frame needs its own normal map, packed into the atlas at exactly the same place. A normal map one frame behind makes the lighting swim.
  • Filtering the normal map smoothly on pixel art. Use nearest filtering for both textures, or the normals blend across texel edges while the colours stay sharp.
  • Importing the normal map as colour. As yesterday, mark it as data, not sRGB colour. The demo and the LÖVE code do their lighting on the stored sRGB values directly, as many simple 2D setups do; the gamma lesson later in this course explains what that costs.
  • Expecting shadows. A normal map shades the sprite itself. It does not cast a shadow onto the wall; 2D engines use separate shadow casters for that.

What it costs

One extra texture read per sprite pixel, a decode, a normalise and a dot product: cheap, even on a phone. The memory is the bigger cost, because every sprite sheet now has a second sheet the same size. Each extra light adds its own direction, falloff and N·L to every pixel it reaches, so on phones keep few lights and keep their range tight. Transparent pixels of a sprite still run the shader, so large, mostly empty sprites pay for lighting nobody sees.

In real games

Both big engines support this out of the box. Godot 4 uses a CanvasTexture with a normal map slot together with its 2D lights, and Unity's URP 2D Renderer uses a _NormalMap secondary texture with Light 2D. Tools built for the job, such as Sprite Lamp, Laigter and SpriteIlluminator, exist because pixel artists wanted their sprites to react to light. This page does not name particular games, because I could not check which shipped titles use per-sprite normal maps.

Your turn (15 minutes)

Start from the LÖVE program.

  1. Add a second, cool blue light that stays at the top-left of the window. Give it its own position, height and colour uniforms, and add its colour × diffuse × falloff to lighting.
  2. Let r rotate the slime by 0.1 radians. Pass the angle to the shader and rotate n.xy by it with the same formula LÖVE uses for the sprite's corners: x' = x cos a − y sin a, y' = x sin a + y cos a, applied after the y flip.

You are done when, at any angle and facing either way, the edge nearest the torch is orange and the edge nearest the corner is blue.

Takeaways

  • A lit sprite is the normal map lesson on a quad that faces the camera: decode, N·L, multiply. Tangent space is screen space.
  • Give the 2D light a height, so the direction to it points out of the screen. Low lights show edges; high lights flatten.
  • Coloured light multiplies the albedo channel by channel, plus a small ambient so the far side is dim, not black.
  • Mirroring a sprite mirrors where the normals are, not where they point: multiply n.x by −1. Rotate n.xy when the sprite rotates.
  • Know your y direction. WebGL and Unity go up, LÖVE and Godot 2D go down.
