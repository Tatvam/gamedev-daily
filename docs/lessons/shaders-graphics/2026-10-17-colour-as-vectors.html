Colour as vectors: add, multiply and swizzle

A colour in a shader is a vec3 of red, green and blue. Add it to brighten, multiply it to tint, and swizzle it to reorder the channels.

Your enemy sprite should look red when it is poisoned and blue when it is frozen. You call setColor with red, and the white parts of the sprite turn red, but the black outline stays black. You try adding red instead, and the whole sprite washes out to pink.

Both are correct: two kinds of vector maths. See a colour as three numbers and you can predict which one you want.

A colour is three numbers

A fragment shader is a small function that runs once per pixel and returns a colour. That colour is not a special type. It is a vec3, a list of three floats, or a vec4 with a fourth number for alpha. In GLSL the three numbers are red, green and blue, each from 0.0 (none) to 1.0 (full). Orange is vec3(0.9, 0.4, 0.1).

So the maths you use for positions works on colours too. Each operator works component-wise: it does the same thing to red, to green and to blue separately, and the channels never mix.

Four operations

Add: a + b adds each channel. Adding colour is adding light, so the result is brighter. Red plus green gives yellow.

Multiply by a colour: a * b multiplies each channel. Since every value is at most 1.0, the result can only get darker or stay the same. Think of b as a coloured filter: white lets everything through, black blocks everything. This is a tint, and it is why the black outline in the hook stayed black: 0 times anything is 0.

Multiply by a number: a * 1.5 scales all three channels by the same amount. The hue stays, the brightness changes.

Swizzle: a swizzle reads the components of a vector in any order you write after the dot. a.bgr is a new vec3 with blue first and red last, so orange becomes blue. a.rrr repeats red three times, which shows the red channel as grey.

Swizzle rules

The names .rgba and .xyzw are two spellings of the same four slots: c.r is c.x. You can use either set, but not both in one swizzle, so c.rgz does not compile. You can repeat a letter when reading (c.rrr) but not when writing: c.rg = vec2(1.0, 0.0); is fine, c.rr = ... is an error.

vec3(0.5) fills all three channels with 0.5, a mid grey, and vec4(c, 1.0) adds an opaque alpha to a vec3.

One more: brightness with a dot product

To turn a colour into grey you need one number that says how bright it looks. Our eyes are most sensitive to green and least to blue, so the channels get different weights: dot(c, vec3(0.299, 0.587, 0.114)). The dot product multiplies each channel by its weight and adds the results. These weights come from Rec. 601. Wrap the result in vec3(...) to get a grey colour.

Rule of thumb

Multiply to tint, because it keeps the shading: dark stays dark. Add to glow, because it brightens everything, including black.

Try it

The left panel is colour A, the middle is colour B, and the right is what the shader returns. Under each swatch, three bars show the red, green and blue numbers; the white line across them is 1.0. With A * B, drag B's sliders down: the result only gets darker. Switch to A + B: all three channels pass the line, the part above 1.0 is hatched, and the swatch shows plain white.

Then use the Show menu to view one channel at a time as grey, and notice that changing one channel never moves the others.

The code

The Lua version draws A and B with setColor and the result with the demo's combine function. Keys 1 to 6 pick the operation, in the order of the demo's menu.

-- The demo's starting values.
local a = { 0.90, 0.40, 0.10 }   -- orange
local b = { 0.50, 0.80, 1.00 }   -- light blue
local k = 1.5
local op = 2   -- 0 add, 1 subtract, 2 multiply, 3 scale, 4 swizzle, 5 grey
local shader

local pixelcode = [[
uniform vec3 u_a;
uniform vec3 u_b;
uniform float u_k;
uniform float u_op;

vec3 combine(vec3 a, vec3 b)
{
    vec3 c = a + b;                                              // 0. add
    if (u_op > 0.5) c = a - b;                                   // 1. subtract
    if (u_op > 1.5) c = a * b;                                   // 2. multiply
    if (u_op > 2.5) c = a * u_k;                                 // 3. scale
    if (u_op > 3.5) c = a.bgr;                                   // 4. swizzle
    if (u_op > 4.5) c = vec3(dot(a, vec3(0.299, 0.587, 0.114))); // 5. grey
    return c;
}

vec4 effect(vec4 color, Image tex, vec2 texture_coords, vec2 screen_coords)
{
    return vec4(combine(u_a, u_b), 1.0);
}
]]

function love.load()
  shader = love.graphics.newShader(pixelcode)
end

function love.keypressed(key)
  local n = tonumber(key)   -- nil for keys that are not digits
  if n and n >= 1 and n <= 6 then
    op = n - 1
  end
end

function love.draw()
  love.graphics.setColor(a)
  love.graphics.rectangle("fill", 20, 20, 120, 120)
  love.graphics.setColor(b)
  love.graphics.rectangle("fill", 160, 20, 120, 120)

  love.graphics.setColor(1, 1, 1)
  shader:send("u_a", a)
  shader:send("u_b", b)
  shader:send("u_k", k)
  shader:send("u_op", op)
  love.graphics.setShader(shader)
  love.graphics.rectangle("fill", 300, 20, 120, 120)
  love.graphics.setShader()
end
precision mediump float;

uniform vec2 u_resolution;
uniform float u_dpr;
uniform vec3 u_a;
uniform vec3 u_b;
uniform float u_k;
uniform float u_op;
uniform float u_channel;

// The lesson: every operation works on all three channels at once.
vec3 combine(vec3 a, vec3 b) {
  vec3 c = a + b;                                              // 0. add
  if (u_op > 0.5) c = a - b;                                   // 1. subtract
  if (u_op > 1.5) c = a * b;                                   // 2. multiply
  if (u_op > 2.5) c = a * u_k;                                 // 3. scale
  if (u_op > 3.5) c = a.bgr;                                   // 4. swizzle
  if (u_op > 4.5) c = vec3(dot(a, vec3(0.299, 0.587, 0.114))); // 5. grey
  return c;
}

// The Show menu: one channel as grey, using a swizzle.
vec3 pickChannel(vec3 c) {
  if (u_channel > 2.5) return c.bbb;
  if (u_channel > 1.5) return c.ggg;
  if (u_channel > 0.5) return c.rrr;
  return c;
}

// Demo only: 1.0 inside the rectangle lo..hi, 0.0 outside.
float box(vec2 p, vec2 lo, vec2 hi) {
  vec2 s = step(lo, p) * step(p, hi);
  return s.x * s.y;
}

// Demo only: one panel is a swatch on top and three channel bars below.
// q.x runs 0 to 1 across the panel, q.y 0 to 1 up the canvas.
vec3 panel(vec3 col, vec2 q, vec2 e, vec3 c, float dim) {
  vec2 lo = vec2(0.0, 0.42);
  vec2 hi = vec2(1.0, 0.84);
  col = mix(col, vec3(0.55), box(q, lo - e, hi + e));
  col = mix(col, clamp(pickChannel(c), 0.0, 1.0), box(q, lo, hi));

  float base = 0.06;
  float hgt = 0.28;
  float one = base + 0.5 * hgt;   // the height of the value 1.0
  float hatch = step(0.5, fract((gl_FragCoord.x + gl_FragCoord.y) / (6.0 * u_dpr)));
  for (int i = 0; i < 3; i++) {
    float x0 = 0.06 + float(i) * 0.32;
    float v = c.r;
    vec3 hue = vec3(0.92, 0.30, 0.26);
    if (i == 1) { v = c.g; hue = vec3(0.30, 0.78, 0.36); }
    if (i == 2) { v = c.b; hue = vec3(0.34, 0.52, 0.98); }
    float active = 1.0;
    if (u_channel > 0.5 && abs(u_channel - float(i + 1)) > 0.5) active = 0.3;
    float top = base + clamp(v, 0.0, 2.0) * 0.5 * hgt;
    col = mix(col, vec3(0.24), box(q, vec2(x0, base), vec2(x0 + 0.24, base + hgt)));
    vec3 bar = mix(hue, hue * 0.45, hatch * step(one, q.y));
    bar = mix(vec3(0.24), bar, active);
    col = mix(col, bar, box(q, vec2(x0, base), vec2(x0 + 0.24, top)));
  }
  col = mix(col, vec3(0.92), box(q, vec2(0.0, one - e.y * 0.5), vec2(1.0, one + e.y * 0.5)));
  float inPanel = box(q, vec2(-e.x, 0.0), vec2(1.0 + e.x, 1.0));
  return mix(col, vec3(0.16, 0.17, 0.19), 0.7 * dim * inPanel);
}

void main() {
  vec2 p = gl_FragCoord.xy / u_resolution;
  vec3 col = vec3(0.16, 0.17, 0.19);
  float w = 0.28;
  float gap = 0.05;
  vec2 e = vec2(1.5 * u_dpr / (w * u_resolution.x), 1.5 * u_dpr / u_resolution.y);
  vec3 result = combine(u_a, u_b);
  for (int i = 0; i < 3; i++) {
    float x0 = 0.03 + float(i) * (w + gap);
    vec2 q = vec2((p.x - x0) / w, p.y);
    vec3 c = u_a;
    float dim = 0.0;
    if (i == 1) { c = u_b; dim = step(2.5, u_op); }   // B is unused from "scale" on
    if (i == 2) c = result;
    col = panel(col, q, e, c, dim);
  }
  gl_FragColor = vec4(col, 1.0);
}
// Godot 4. Put this in a ShaderMaterial on a ColorRect.
shader_type canvas_item;

uniform vec3 color_a = vec3(0.90, 0.40, 0.10);
uniform vec3 color_b = vec3(0.50, 0.80, 1.00);
uniform float k = 1.5;
uniform float op = 2.0;

vec3 combine(vec3 a, vec3 b) {
    vec3 c = a + b;
    if (op > 0.5) c = a - b;
    if (op > 1.5) c = a * b;
    if (op > 2.5) c = a * k;
    if (op > 3.5) c = a.bgr;
    if (op > 4.5) c = vec3(dot(a, vec3(0.299, 0.587, 0.114)));
    return c;
}

void fragment() {
    COLOR = vec4(combine(color_a, color_b), 1.0);
}
// Built-in render pipeline, unlit. Put it on a material and apply it to a Quad.
Shader "GameDevDaily/ColourMaths"
{
    Properties
    {
        _ColorA ("Colour A", Color) = (0.9, 0.4, 0.1, 1)
        _ColorB ("Colour B", Color) = (0.5, 0.8, 1.0, 1)
        _K ("k", Range(0, 2)) = 1.5
        _Op ("Operation (0 to 5)", Float) = 2
    }
    SubShader
    {
        Tags { "RenderType" = "Opaque" }
        Pass
        {
            CGPROGRAM
            #pragma vertex vert
            #pragma fragment frag
            #include "UnityCG.cginc"

            float4 _ColorA, _ColorB;
            float _K, _Op;

            struct v2f
            {
                float4 pos : SV_POSITION;
            };

            v2f vert (appdata_base v)
            {
                v2f o;
                o.pos = UnityObjectToClipPos(v.vertex);
                return o;
            }

            float3 combine (float3 a, float3 b)
            {
                float3 c = a + b;
                if (_Op > 0.5) c = a - b;
                if (_Op > 1.5) c = a * b;
                if (_Op > 2.5) c = a * _K;
                if (_Op > 3.5) c = a.bgr;
                if (_Op > 4.5)
                {
                    float g = dot(a, float3(0.299, 0.587, 0.114));
                    c = float3(g, g, g);
                }
                return c;
            }

            fixed4 frag (v2f i) : SV_Target
            {
                return fixed4(combine(_ColorA.rgb, _ColorB.rgb), 1.0);
            }
            ENDCG
        }
    }
}

HLSL uses float3 where GLSL says vec3, but the operators and swizzles are the same. In URP Shader Graph the same nodes exist: Add, Subtract, Multiply, Swizzle (with a mask such as bgr) and Dot Product, all of which work per channel on Vector3 inputs.

Pitfalls

  • Integer literals. In GLSL ES 1.0, c * 2 does not compile, because 2 is an int and there is no automatic conversion. Write c * 2.0. Constructors are the exception: vec3(1, 0, 0) converts its arguments, but writing 1.0 everywhere is a habit that never fails.
  • Expecting * to be a dot product. For two vectors, * multiplies component by component and returns a vector. Use dot() when you want one number. (For matrices, * is a true matrix product, which later lessons use.)
  • Clamping too early. Inside the shader a channel can be 1.7 or -0.3, and the maths still works. The value is only cut to 0 to 1 when it is written to a normal 8-bit screen.
  • Different numbers in the engine. The demo writes its numbers straight to the screen, where the browser treats them as sRGB. In a Unity project set to the Linear colour space, Unity converts Color properties to linear before the shader sees them, so _ColorA.r is not the 0.9 you typed. In Godot 4, adding the source_color hint to a uniform gives a colour picker, and in 3D shaders the value is converted to linear. The gamma lesson in Track 5 covers this.

What it costs

All of this is cheap. A vec3 add or multiply is three float operations; many modern GPUs, mobile ones included, do them one number at a time. A swizzle usually costs nothing at all, because the compiler just reads the registers in a different order. dot on a vec3 is three multiplies and two adds.

On phones, colours are a good place for mediump. Values from 0 to 1 need about 8 bits of precision for display, and mediump guarantees at least 10.

In real games

The tint in the hook is a colour multiply in every engine here. LÖVE's default shader returns Texel(tex, texture_coords) * color, where color is whatever you passed to love.graphics.setColor. Godot's modulate property on a CanvasItem and Unity's SpriteRenderer.color do the same: they multiply the sprite's colour. That is why one white sprite can become many team colours, but never brighter than its texture.

Additive blending, used for fire, sparks and magic particles, is colour addition between the particle and what is already on screen. Overlapping sparks get brighter and turn towards white.

Your turn (15 minutes)

Make a "flashback" shader for a sprite in LÖVE:

  1. In effect, read the sprite's colour with vec4 t = Texel(tex, texture_coords);.
  2. Turn it grey with the dot product from this lesson.
  3. Multiply the grey by a warm tint uniform, for example vec3(1.0, 0.85, 0.6), and return it with the sprite's own alpha: vec4(grey * u_tint, t.a).
  4. Add a key that switches the shader on and off.

You are done when the sprite turns sepia, its dark outline stays dark, and its transparent areas stay transparent.

Takeaways

  • A colour is a vec3 (or vec4) of floats, normally 0 to 1, and vector operators work on it channel by channel.
  • Adding brightens, like adding light. Multiplying by a colour tints, like a filter: it keeps dark areas dark.
  • Swizzles such as .bgr and .rrr reorder or repeat channels, and usually cost nothing.
  • Values above 1.0 or below 0.0 are fine inside a shader; the screen clamps them only at the end.
  • Engines may convert colour properties to linear space before your shader sees them, so check which numbers you are actually getting.
