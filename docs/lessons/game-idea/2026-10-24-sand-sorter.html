Sand Sorter: draw the walls, let the sand decide

A falling sand puzzle where you draw and erase thin walls to route two colours of sand into their jars, with a playable prototype and the sand rule in Lua.

Two spouts pour amber and blue sand into an empty room, and two jars wait at the bottom, never quite where the sand would fall. You have a little ink to draw walls with, and every grain you send to the wrong jar undoes two good ones.

The core loop: draw, pour, watch the leak, redraw

Sand Sorter is a falling sand game: the world is a grid of tiny cells, and each cell of sand follows one simple rule every tick. Piles, streams and leaks all come out of that rule, so the player can see why sand went where it did.

The player never touches the sand. They draw thin walls with the pointer or the keyboard, and they can erase them again. Walls cost ink, a fixed budget per level, and erasing a wall gives its ink back. The refund makes the game about editing, not one perfect drawing.

The rules

  • Pouring. Nothing falls until you press Pour, so you can plan first. After that the spouts never stop, and the clock runs until both jars are full.
  • Jars. Each jar wants 200 grains of its own colour. A wrong grain takes two off its count. Sand that misses every jar drains through the floor and is simply lost.
  • Walls. One cell thick, one ink per cell. Erasing gives the ink back and also clears any sand in the eraser's circle, which is how you unblock a jammed pile.
  • The switch. In the last room one spout changes colour every six seconds, so a fixed drawing cannot win. You have to re-route the stream on time.

The sand rule

Every tick, each grain tries three moves in order: straight down, then one diagonal, then the other. The side it tries first is random, so a stream landing on a point splits evenly. If all three are blocked, the grain stays put, and stuck grains build sloped piles.

A one cell wall drawn on a slant has gaps at its corners, and a grain moving diagonally could slip through them. The fix is the corner rule: a diagonal move is allowed only if the cell beside the grain is empty too.

What makes it different

The player fantasy is the quiet craftsperson tending a machine that runs by itself. The constraint is ink with a refund, which turns play into live editing: cut a wall here to pay for a ramp there while the sand keeps coming.

The hardest part to build is not the sand rule but walls that feel good to draw: a fast stroke must leave no gaps, and a slanted line must hold sand. Joining pointer samples with straight lines of cells and the corner rule solve both.

Try it

In the first room, press Pour before drawing and watch both streams drain away, then draw a ramp under each spout towards its jar. In the second, the blue stream falls right where the amber ramp must go. In the third, re-route the stream before the spout changes colour.

The code

The heart of the mechanic in LÖVE: one tick of the sand rule with the corner rule, and what happens when a grain reaches a jar or the floor. The grid size, jar row and the first room's jars match the prototype. Call step 60 times a second with a fixed step, flipping flip each time so that the scan direction alternates and piles do not lean to one side.

local W, H, JAR_TOP = 120, 80, 66
local EMPTY, AMBER, BLUE, WALL = 0, 1, 2, 3
local grid = {}                  -- grid[y][x]; jar sides are WALL cells
local jars = {                   -- the first room
  { x0 = 44, x1 = 56, colour = AMBER, fill = 0 },
  { x0 = 64, x1 = 76, colour = BLUE,  fill = 0 },
}

local function empty(x, y)
  return x >= 1 and x <= W and grid[y][x] == EMPTY
end

local function land(x, y, c)     -- a grain arrives at (x, y)
  if y >= JAR_TOP then
    for _, j in ipairs(jars) do
      if x >= j.x0 and x <= j.x1 then
        if c == j.colour then j.fill = j.fill + 1
        else j.fill = math.max(0, j.fill - 2) end
        return
      end
    end
  end
  if y < H then grid[y][x] = c end -- the floor row drains it away
end

local function step(flip)
  for y = H - 1, 1, -1 do        -- bottom up: no grain moves twice
    for i = 1, W do
      local x = flip and (W + 1 - i) or i
      local c = grid[y][x]
      if c == AMBER or c == BLUE then
        local d = (math.random() < 0.5) and -1 or 1
        local nx = nil
        if empty(x, y + 1) then nx = x
        elseif empty(x + d, y) and empty(x + d, y + 1) then nx = x + d
        elseif empty(x - d, y) and empty(x - d, y + 1) then nx = x - d end
        if nx then grid[y][x] = EMPTY; land(nx, y + 1, c) end
      end
    end
  end
end

In the highlighted elseif lines, empty(x + d, y) is the corner rule. Remove it and slanted walls leak. Drawing a wall fills a straight line of cells from the last pointer position to the current one, one ink per new cell.

Pitfalls

  • Rooms that cannot be solved. In 2D, two streams cannot cross without mixing. If amber's spout is left of blue's but amber's jar is right of blue's jar, the two paths must meet, and no drawing fixes that. The first draft of this prototype's second room had exactly that layout. Check every room: if the left-to-right order of the spouts and jars differs, the room needs a timing mechanic like the switch, or it is broken.
  • Ink that is too generous. With unlimited ink, the answer is "draw a box around everything" and the puzzle disappears. Test each room with the shortest drawing you can find, and give about one and a half times that much ink.
  • Piles that jam. A flat wall collects a pyramid of sand before anything flows off it. A pile that reaches the spout stops the pour. The eraser also clears sand as an escape hatch; watch whether testers find it.
  • Colours that only differ by hue. Amber and blue were chosen because they differ in brightness as well as hue. For a full game, add a second cue, such as a pattern on each jar and a different grain texture, and test in greyscale.

In real games

Falling sand is an old and well-loved toy. Sandspiel by Max Bittker (2019) is a modern browser sandbox of interacting materials. Noita (Nolla Games, 2020) built a whole action roguelike on a world where every pixel is simulated.

Drawing lines to guide falling sugar into cups is the idea of Sugar, Sugar by Bart Bonte, and Crayon Physics Deluxe by Petri Purho turns drawn shapes into physical objects. Sand Sorter is close to the first in spirit. Its own angle is the economy: ink that comes back when you erase, a penalty for every wrong grain, and a spout that switches colour, so the drawing is never finished.

Your turn: the first playtest

In one sitting, build the Lua above with one colour, one spout and one jar. Add mouse drawing that joins the last mouse position to the current one with wall cells, and an ink counter.

Put the jar a little to one side of the spout and hand it to a friend with no explanation beyond "get the sand in the jar". The one question to answer: do they erase? If they redraw and erase freely as the stream misbehaves, the live editing loop works. If they draw once and wait, the refund is not visible enough: make the ink bar grow back visibly.

Takeaways

  • Weekend version: the prototype above with ten rooms, a par time for each, and a soft sound when a jar fills.
  • One-month version: thirty rooms with new pieces introduced one at a time: fixed stone, a fan cell that pushes grains sideways, a filter that lets only one colour through, and the colour-switching spout.
  • Cut first: extra materials such as water. Each one multiplies the rules and the testing; a filter adds more puzzles for less work.
  • The hardest part is wall drawing that never leaks. Get the corner rule and gap-free strokes right before designing any rooms.
