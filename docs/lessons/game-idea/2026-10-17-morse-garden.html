Morse Garden: plant flowers with dots and dashes

A one-button gardening game where short and long presses spell the seed you plant, with a playable prototype and the press reader in Lua.

A customer wants a tulip, then a daisy, then a poppy, and you have one button. Tap tap and a daisy opens. Tap and hold and a tulip comes up. Get the rhythm wrong and the seed wilts, and the clock takes back a few seconds.

The core loop: read, tap, bloom

Most one-button games use the button for one action, like jump or let go. Morse Garden reads how long you hold it. A short press is a dot, a long press is a dash, and two symbols together make a code, the way letters are sent in Morse code. Each code is a different seed. One button becomes a small keyboard, and playing well feels like tapping out a tune.

The rules

The press reader works like this. When you let go, the game measures how long you held. Under 0.22 seconds is a dot, anything longer is a dash. After the second symbol the code is read at once, so there is no waiting for a pause.

  • The order: the bed shows the requested bouquet as faint outlines, left to right. You always plant into the next empty spot.
  • Right code: the flower blooms and the next spot lights up.
  • Wrong code: the seed wilts, the spot stays empty and the clock loses 2 seconds. Dash dash always wilts.
  • Changing your mind: if you tap one symbol and then wait 1.2 seconds, it fades away for free. Waiting is the undo.
  • The clock: you start with 45 seconds and every finished bouquet adds 3. The next bouquet is one flower longer every two orders, up to six. The run ends when the clock hits zero.

What makes it different

The player fantasy is the telegraph operator: fingers that know the code without thinking. The constraint is the single button, which forces every choice through rhythm. The skill you build is not reaction speed but memory and timing together. A beginner reads the code key for every flower. After a few minutes most players stop looking and start hearing the bouquet as a rhythm.

The gardening theme matters too. It keeps the mood calm, so the clock feels like a shop getting busy rather than a bomb. That makes it a good fit for short sessions and for players who do not like twitchy games.

The hardest part to build is the press reader feeling fair. People hold "short" for very different lengths, and a single threshold that is wrong for a player makes the game feel broken. The prototype draws a live hold bar with the threshold marked, so you can see a dot turn into a dash while you are still holding.

The code

This is the heart of the mechanic in LÖVE: time each press, turn it into a dot or a dash, and plant when two symbols are in. The numbers are the ones the prototype uses. Drawing is left out.

local DOT_MAX, FORGET = 0.22, 1.2    -- seconds
local BONUS, WRONG = 3, 2            -- clock seconds won and lost
local CODES = { [".."] = "daisy", [".-"] = "tulip", ["-."] = "poppy" }
local NAMES = { "daisy", "tulip", "poppy" }
local clock, score, idle = 45, 0, 0
local pattern, pressedAt = "", nil
local bed, slot, order = {}, 1, {}

local function newOrder(n)
  local o = {}
  for i = 1, n do o[i] = NAMES[love.math.random(3)] end
  return o
end
order = newOrder(3)

local function plant(code)
  local flower = CODES[code]               -- nil for "--": nothing grows
  if flower == order[slot] then
    bed[slot] = flower
    slot = slot + 1
    if slot > #order then                  -- bouquet finished
      score, clock = score + 1, clock + BONUS
      bed, slot = {}, 1
      order = newOrder(math.min(6, 3 + math.floor(score / 2)))
    end
  else
    clock = clock - WRONG                  -- the seed wilts
  end
end

function love.keypressed(key)
  if key == "space" and not pressedAt then pressedAt = love.timer.getTime() end
end

function love.keyreleased(key)
  if key ~= "space" or not pressedAt then return end
  local held = love.timer.getTime() - pressedAt
  pattern = pattern .. (held < DOT_MAX and "." or "-")
  pressedAt, idle = nil, 0
  if #pattern == 2 then plant(pattern); pattern = "" end
end

function love.update(dt)
  clock = clock - dt
  if #pattern == 1 and not pressedAt then
    idle = idle + dt
    if idle > FORGET then pattern = "" end  -- waiting cancels a half code
  end
end

Measuring on release, with love.timer.getTime(), means the symbol does not depend on the frame rate. Left out for space: the end of the run, the start screen, and drawing the bed, the hold bar and the code key.

Pitfalls

  • The wrong threshold. If a player's natural "short" is 0.25 seconds, every dot becomes a dash and they blame the game. Log every hold time from five players and look at the two humps. Put the threshold in the valley between them, and consider an option to change it.
  • A memory wall. Three codes are easy. Eight would be a test, not a game. Add one flower at a time and watch whether players still read the key. If they stare at it for every press, you added too many too fast.
  • Mashing pays. Random taps match the wanted flower one time in four. With a 2 second penalty and about half a second per try, mashing loses time, which is what you want. Check this sum again every time you change a number.
  • A clock that kills the mood. The theme is calm, and a harsh timer can fight it. Playtest one version with the clock and one without, where the score is how few mistakes you make. Keep whichever players ask to replay.
  • Unclear cancel. The fade after 1.2 seconds is invisible unless you show it. If players do not discover it, they will think the game ate their press. Fade the waiting symbol slowly so it is clearly leaving.

In real games

Morse Garden sits between two families. One is games where a sequence of inputs is a command. Fighting games such as Street Fighter II (Capcom, 1991) trigger special moves from short joystick and button sequences, and Patapon (Sony, 2007) has players drum four-beat patterns on the face buttons to give their army orders. The other is typing games, such as The Typing of the Dead (Sega, 1999), where knowing the input by heart is the whole skill.

The code itself comes from telegraphy, where operators sent letters as short and long signals. The prototype uses its own codes rather than real Morse letters, so it does not teach Morse, though a variant could.

What this idea changes is that there is only one button, so the meaning sits in the length of the press, not in which button is pressed. I do not know of a published game built on exactly this rule, but I have not searched thoroughly, so check before calling it new.

Your turn: the first playtest

In one sitting, build the Lua above with the plainest drawing you can: coloured circles for the three flowers, a row of outlines for the order, and the code key printed at the bottom. Skip the clock. Add one line that prints every hold time to the console.

Give it to someone and say only "fill the order". The one question to answer: after five bouquets, are they still looking at the code key? If they are not, the codes are learnable and you can add the clock. If they are, try fewer flowers or codes that sound more different, such as dot dot against dash dash, before adding anything else.

Takeaways

  • Weekend version: the prototype above with a soft tone while the button is held, a gentle bloom animation, a saved best score and a setting for the dot threshold.
  • One-month version: a shop day with several customers, each with a patience bar, and new seeds unlocked with three-symbol codes. A garden that keeps what you planted between days gives the session loop a reason to come back.
  • Cut first: extra symbol lengths, such as a very long press as a third symbol. They make the reader much harder to tune and break the clean dot or dash choice.
  • The hardest part is the press threshold. Measure real players before tuning anything else.
