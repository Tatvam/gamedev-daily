Clockwork Locksmith: every turn pushes back

A gear lock puzzle where turning one gear turns its neighbours the other way, and every mark must point up. Playable prototype and Lua code.

Six brass gears sit behind the glass of an old lock, each with a scratched mark, and the bolt slides back only when every mark points straight up. Turn one gear a notch and the gears touching it lurch a notch the other way, so every fix undoes something you fixed a moment ago.

The core loop: pick a gear, turn it, read the marks

Clockwork Locksmith is a calm puzzle about one lock at a time. The lock is a small set of gears. Each gear has a mark, an arrow painted on its face, and the mark can point in four directions: up, right, down or left. The lock opens when all marks point up.

You click a gear and it turns a quarter turn clockwise. Every gear whose teeth touch it, its neighbours, turns a quarter turn anticlockwise. Gears further away do not move.

Every ten seconds the player picks a gear, turns it and reads the marks again. Every minute a lock opens and a harder one arrives. Every session is a run of locks, each with a par, the smallest number of turns that opens it, for players who want to do better than just open it.

The rules

  • One click, one quarter turn. The gear you click turns clockwise by a quarter.
  • Neighbours push back. Each gear touching it turns anticlockwise by a quarter. Nothing else moves.
  • Four clicks do nothing. Four quarter turns bring every affected gear back to where it was.
  • All marks up. The lock opens when every mark points up. There is no timer and no way to lose.
  • Par. Each lock knows its shortest solution. Matching it is the stretch goal.

What makes it different

The player fantasy is the locksmith with patient fingers who feels the mechanism instead of forcing it. The constraint is that you can never move one gear alone: every action has a side effect on its neighbours, and the puzzle is choosing side effects you can live with.

A confession about the fiction: in a real gear train every connected gear turns, so all six would spin together and nothing would change. This lock has ratchets that stop each neighbour after one notch. Show that in the first room, with a click and a visible pawl, so players read the rule as part of the lock rather than a bug.

The insight players reach after a few locks is that the order of clicks does not matter. Clicking gear 2 then gear 5 ends in the same place as gear 5 then gear 2. A lock is really a question of how many times to click each gear, from zero to three. That is when the game turns from fiddling into planning.

The hardest part to build is the lock generator: most random arrangements of marks cannot be opened at all, so locks must be made by scrambling a solved lock.

Try it

Lock 1 needs two clicks. Each lock after it needs one more, up to eight. Watch which marks move when you click, and look for the gear whose side effects help you.

The code

The heart of the mechanic in LÖVE: the gear links, the click rule and a generator that only makes locks you can open. A mark is stored as the number of quarter turns clockwise from up, so 0 means up. Drawing is left out.

local marks = {}                  -- 0 up, 1 right, 2 down, 3 left
local links = {                   -- two rows of three gears
  {2, 4}, {1, 3, 5}, {2, 6},      -- 1 2 3
  {1, 5}, {2, 4, 6}, {3, 5},      -- 4 5 6
}
local clicks = 0

local function click(i)
  marks[i] = (marks[i] + 1) % 4             -- a quarter turn clockwise
  for _, j in ipairs(links[i]) do
    marks[j] = (marks[j] - 1) % 4           -- each neighbour turns back
  end
  clicks = clicks + 1
end

local function isOpen()
  for i = 1, #marks do
    if marks[i] ~= 0 then return false end
  end
  return true
end

local function newLock(scrambles)
  for i = 1, #links do marks[i] = 0 end
  repeat                                     -- scramble a solved lock with real clicks
    for _ = 1, scrambles do click(love.math.random(1, #links)) end
  until not isOpen()
  clicks = 0
end

function love.load()
  newLock(4)
end

The highlighted lines are the whole rule. In Lua, % always returns a result with the sign of the divisor, so (0 - 1) % 4 is 3: up turned back once points left, with no special case. Because the lock is built from real clicks, it can always be opened, by clicking each scrambled gear three more times if nothing better. The demo goes one step further: it tries every combination of clicks once at load time, so it knows each lock's par and can pick locks of an exact difficulty.

Pitfalls

  • Random locks that cannot open. With six gears there are 4,096 ways to set the marks, but I checked every combination of clicks on this two-by-three layout and only 512 arrangements can be reached. Seven in eight random locks would be impossible. Always generate by scrambling, or check against the list of reachable states, and test this for every new layout.
  • The puzzle turns into arithmetic. Once players know the order does not matter, some will solve locks on paper by counting. Test it: give a player five locks and watch whether the fifth is more fun than the first, or only faster.
  • Marks that are hard to read. If testers click and then ask what changed, make the arrows bolder, show a fixed "up" notch on every gear, and turn the neighbours a beat after the clicked gear.
  • Three clicks to go back. With clockwise only, undoing a turn by hand takes three clicks. Give undo a key from day one, and see whether players want an anticlockwise click. Adding one makes locks easier, so measure par again if you do.

In real games

The closest relative is Lights Out, the handheld electronic puzzle from Tiger Electronics (1995): pressing a light toggles it and its neighbours, and the board is solved when every light is off. Clockwork Locksmith is that family of puzzle with four states per piece instead of two, and with the neighbours pushed the opposite way instead of the same way. That second change matters: in Lights Out pressing twice undoes a press, while here a gear needs four turns to come back, so planning ahead pays off more.

Rotating-piece locks are also a familiar mini-game in adventure games, usually a single screen to pass. The bet here is that the neighbour rule can carry a whole game, with layouts that change which gears touch.

Your turn: the first playtest

In one sitting, build the Lua above with six circles, an arrow line on each, mouse clicks and an undo key. Skip teeth, animation and sound. Make ten locks with newLock(3) to newLock(6).

Give it to a friend with only the five rules. The one question: do they notice, without being told, that the order of clicks does not matter? Watch for the moment they stop clicking and start counting. If it comes by the fifth lock, the game has a real insight to build on. If it never comes, the marks are too hard to read or the locks are too easy to brute-force by clicking.

Takeaways

  • Weekend version: the six-gear lock from the demo, generated locks with par, undo, a hint, and a satisfying bolt animation when the lock opens.
  • One-month version: twenty hand-picked layouts with different links (a chain, a ring of six, a star), gears that are rusted and refuse to turn by hand, and a daily lock with a par leaderboard kept on the player's own device.
  • Cut first: gears of different sizes. Gear ratios sound right for the theme but turn the rule into arithmetic nobody can see at a glance.
  • Hardest part: the lock generator. Brute force is fine for six gears (4,096 combinations); for twelve gears, generate by scrambling and estimate par with a search instead.
