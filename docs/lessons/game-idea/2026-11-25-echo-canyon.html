Echo Canyon: shout the bridge before you walk it

A rhythm platformer where every shout returns two seconds later as a brief platform, so you build the path ahead on the beat. Playable prototype and Lua code.

A small traveller walks through a canyon and will not stop, and the only thing you can do is shout. Every shout bounces off the far wall and comes back two seconds later as a ledge of solid sound under their feet, so you are always singing the bridge for a gap you have not reached yet.

The core loop: see the gap, shout early, walk the echo

The traveller walks to the right at a steady 100 units per second over a canyon floor broken by gaps. You have one action, the shout. A shout does nothing right away. Two seconds later its echo returns and becomes a short platform exactly where the traveller is at that moment. If the traveller is over a gap, the echo holds them up for a few steps. If the traveller is over rock, the echo is wasted.

Because the traveller never changes speed, two seconds in time is always 200 units of distance. So the real skill is reading space as time: when the gap is 200 units ahead, it is time to shout. A shout that has not returned yet is a pending echo, and the prototype draws it as a dashed outline so you can see where it will land.

Every ten seconds you watch a gap slide toward the landing point and tap a short rhythm to cover it. Every minute you cross a run of gaps that grow wider, managing your breath between them. Every session you push your best distance on a canyon that is the same every time, so you can learn its rhythm like a song.

The rules

  • Echoes return after two seconds. Each echo is a platform 80 units long that starts 20 units behind the traveller and reaches 60 ahead. It lasts 1.2 seconds, then fades.
  • The traveller needs something underfoot. Their feet are 16 units wide. If neither rock nor an echo is under them, they fall and the run ends.
  • Shouts cost breath. You hold up to five breaths. Each shout uses one. Breath comes back at one every 0.9 seconds, but only while walking on rock, never on echoes.
  • Echoes too close cancel. If a new shout would land within 30 units of a pending echo, the two sound waves cancel and both are lost. Mashing builds nothing.

Put those numbers together and a rhythm falls out. One echo carries the traveller 68 units, which is 0.68 seconds of walking. Shouts closer than 0.3 seconds cancel. So a long gap needs a steady beat somewhere between those two limits, and half a second, 120 beats per minute, sits comfortably in the middle.

What makes it different

The player fantasy is a voice that shapes the world: you are not jumping over danger, you are singing a path into it. The constraint is the delay. Every action is a promise to your future self, and you are always living with choices made two seconds ago while making the next ones.

That split attention is the hook. Your eyes are on the gap ahead while your feet are on a bridge you built earlier, and a mistake shows up after you can no longer fix it. Breath stops you from shouting all the time, so quiet stretches of rock matter: they are where you recover.

The hardest part to build is making the delay readable. If players cannot tell where an echo will land, the game feels random. The landing guide and the dashed pending echoes in the prototype exist for that reason.

Try it

Tap once to set the traveller walking. Watch the dashed "lands here" line ahead of them: when it reaches the start of a gap, shout, then keep shouting on a steady beat until the line reaches rock again. Then try mashing, and try shouting all the time, and see what breaks.

The code

The heart of the mechanic in LÖVE: shouts go into a list of pending echoes, each counts down, and when it reaches zero it becomes a platform. Drawing, the start screen and level generation are left out. The names and numbers match the demo.

local SPEED, DELAY, LIFE = 100, 2.0, 1.2
local BACK, AHEAD, FOOT, TOO_CLOSE = 20, 60, 8, 30
local MAX_BREATH, REGEN = 5, 0.9
local walkerX, breath, falling = 0, MAX_BREATH, false
local pending, platforms = {}, {}
local ground = { {a = -400, b = 600}, {a = 660, b = 900} }  -- rock

local function shout()
  if falling or breath < 1 then return end
  breath = breath - 1
  local target = walkerX + SPEED * DELAY   -- where I will be when it returns
  for i = #pending, 1, -1 do
    if math.abs(pending[i].x - target) < TOO_CLOSE then
      table.remove(pending, i)              -- too close: both echoes cancel
      return
    end
  end
  table.insert(pending, {x = target, t = DELAY})
end

local function standsOn(list)
  for _, s in ipairs(list) do
    if walkerX + FOOT > s.a and walkerX - FOOT < s.b then return true end
  end
  return false
end

function love.update(dt)
  if falling then return end
  walkerX = walkerX + SPEED * dt
  for i = #pending, 1, -1 do
    local e = pending[i]
    e.t = e.t - dt
    if e.t <= 0 then                        -- the echo returns as a platform
      table.remove(pending, i)
      table.insert(platforms, {a = e.x - BACK, b = e.x + AHEAD, life = LIFE})
    end
  end
  for i = #platforms, 1, -1 do
    platforms[i].life = platforms[i].life - dt
    if platforms[i].life <= 0 then table.remove(platforms, i) end
  end
  local onRock = standsOn(ground)
  if onRock then breath = math.min(MAX_BREATH, breath + dt / REGEN) end
  if not onRock and not standsOn(platforms) then falling = true end
end

function love.keypressed(key)
  if key == "space" or key == "up" or key == "z" then shout() end
end

The highlighted lines are the whole idea. The echo's position is fixed at the moment of the shout, as walkerX + SPEED * DELAY. Because the traveller moves at a constant speed, that is exactly where they will be when the timer runs out, so the platform always arrives under their feet. If you later add anything that changes the traveller's speed, this promise breaks, and you must decide whether the echo follows the place or the traveller.

Pitfalls

  • A constant beat solves everything. If breath refills too fast, players tap a steady rhythm forever and never look at the canyon. Test it: tap at 120 beats per minute without looking and see how far you get. In the prototype you run dry on the long stretches of rock and have nothing left for the gap. If a blind rhythm survives, slow the refill.
  • The guide becomes the game. With the landing line on, the task is "tap when the line touches the gap", which is pure reaction. Ask testers to turn it off after a few runs and watch whether they still cross the first gaps. If not, the delay needs a louder cue, such as a rising tone that peaks as the echo lands.
  • Mistakes that land too late to understand. A fall caused by a bad shout two seconds ago can feel unfair. Show the cause: the prototype draws cancelled and pending echoes, and a replay of the last three seconds after a fall would help even more.
  • Sound latency. Audio delay varies by device, so let the platform's visual appearance be the true signal and the sound follow it.
  • Sameness. Gaps of different widths are only rhythms of different lengths. After a few minutes, vary the pattern: a narrow pillar of rock in the middle of a gap breaks one long beat into two short ones.

In real games

Auto-running with a single action is well explored. Canabalt is a one-button runner where you press to jump between rooftops, and Geometry Dash and the BIT.TRIP RUNNER games tie an auto-moving character to music, so levels play like songs. Protecting a walker who will not stop is the heart of Lemmings, where you give skills to marching creatures, including builders who lay down stairs.

Echo Canyon sits between those: like a runner it is about timing, and like Lemmings you build the floor instead of dodging. The difference is the fixed delay. You never act on what is under you now, only on what will be under you in two seconds. I am not aware of a game built around exactly this, but delayed and recorded actions appear in many puzzle games, so similar ideas may well exist.

Your turn: the first playtest

In one sitting, build the Lua above with rectangles for rock and platforms, a circle for the traveller, a dashed rectangle for each pending echo and a short click sound when an echo lands. Hand-place five gaps of widths 50, 90, 130, 90 and 170 units.

Give it to a friend with the landing guide off and explain only "shouts come back two seconds later". The one question: by their third run, do they start shouting before they can see the gap reach them, by counting? If they do, the delay has become a rhythm in their head and the game works. If they still shout late, the delay is too long for this speed: try 1.5 seconds before adding any visual help.

Takeaways

  • Weekend version: one hand-made canyon, shouts, pending echoes, breath, cancelling, a distance score and an echo sound.
  • One-month version: ten canyons each set to a piece of music, pillars and overhangs that change the rhythm, a short replay after each fall, and a timing calibration screen.
  • Cut first: story, characters and anything that changes the traveller's speed. The fixed delay and the steady walk are the game.
  • Hardest part: making a two-second delay feel learnable rather than random. Spend your playtests on readability before content.
