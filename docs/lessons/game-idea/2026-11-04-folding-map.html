Folding Map: fold the paper, shorten the road

A calm grid puzzle where folding a paper map folds the land, so far tiles meet and the traveller steps across. Playable prototype and Lua code.

A river stands between you and the town, and there is no bridge. So you take out your map, pinch the river between two creases and fold it under, and on the paper and in the world the two banks now touch. You step across, unfold the map, and the river flows on behind you.

The core loop: look, fold, step

Folding Map is a turn-based puzzle on a six by six grid. Each tile is grass, water, mountain, a tower or the goal town. The traveller walks one tile per key press and cannot enter water, mountains or towers. Columns are numbered 1 to 6 and rows lettered A to F, like the grid references on a real map.

Between every pair of columns and every pair of rows is a crease, a line where the paper can bend. Folding a strip (one whole column or one whole row) tucks it under the paper like a pleat in a skirt. The strip is still there, but it is out of sight, and the tiles on either side of it become neighbours. Walk right from column 2 with column 3 folded and you land in column 4.

Every ten seconds the player reads the map and makes one fold or one step. Every minute they deliver a letter to a town and open the next map. Every session brings maps with more pins, tighter fold limits, and a par to beat.

Here is what a single fold does to one row of the map. Column 3 is water. Fold it, and the grass in column 2 sits right beside the grass in column 4.

The rules

  • Folding. Any whole column or row can be folded away, and unfolded again at any time. Folding and unfolding each cost one step, the same as walking.
  • Pins. A tower is a pin stuck through the map, and the goal town is pinned too. A strip that holds a pin cannot be folded. Nor can the strip the traveller stands on: you cannot fold the ground out from under yourself.
  • Two folds thick. The paper takes at most two folds at once. A third fold means unfolding an old one first.
  • Folds are global. Folding column 3 removes it from every row, not only the row you care about. That is where the puzzles come from.
  • The goal. Reach the town. The score is the number of steps, and each map has a par, the fewest steps that solve it.

What makes it different

The player fantasy is the traveller whose map is the land itself. The constraint is that folds are whole strips: you cannot cut out one inconvenient tile, so every fold also removes things you might need, and pins stop you from folding exactly where you want. The second map in the demo is built on that: the river column is pinned by a tower, so you have to fold rows instead, and find a different place to cross.

The mood is quiet, closer to a crossword than an action game. There is no timer and no way to die.

The hardest part to build is not the rule, which is a few lines, but the level design. You need maps where the obvious fold fails, and you need to know every map is solvable and what its par is. The prototype's maps were checked with a small breadth first search over every step and fold, which also gives each par.

The code

The heart of the mechanic in LÖVE: a folded strip is skipped when looking for the next tile, and a strip can be folded only if it has no pin, is not under the traveller, and the paper is not already two folds thick. Drawing is left out; the demo draws folded strips as thin seams.

local N, MAX_FOLDS = 6, 2
local map = { "..~...", "..~...", "S.~..G", "..~...", "..~...", "..~..." }  -- map 1
local foldedCol, foldedRow, folds = {}, {}, 0
local hero = {row = 3, col = 1}

local function tile(r, c) return map[r]:sub(c, c) end

local function walkable(r, c)
  if r < 1 or r > N or c < 1 or c > N then return false end
  local t = tile(r, c)
  return t ~= "~" and t ~= "^" and t ~= "P"   -- water, mountain, tower
end

local function nextVisible(i, d, folded)       -- skip strips tucked under
  i = i + d
  while i >= 1 and i <= N and folded[i] do i = i + d end
  return i
end

local function step(dr, dc)
  local r, c = hero.row, hero.col
  if dr ~= 0 then r = nextVisible(r, dr, foldedRow) end
  if dc ~= 0 then c = nextVisible(c, dc, foldedCol) end
  if walkable(r, c) then hero.row, hero.col = r, c end
end

local function pinned(isRow, i)                -- towers and the town pin a strip
  for j = 1, N do
    local t = isRow and tile(i, j) or tile(j, i)
    if t == "P" or t == "G" then return true end
  end
  return (isRow and hero.row or hero.col) == i  -- so does standing on it
end

local function toggleFold(isRow, i)
  local folded = isRow and foldedRow or foldedCol
  if folded[i] then folded[i] = false; folds = folds - 1; return end
  if folds >= MAX_FOLDS or pinned(isRow, i) then return end
  folded[i] = true; folds = folds + 1
end

function love.keypressed(k)
  if k == "left" then step(0, -1) elseif k == "right" then step(0, 1)
  elseif k == "up" then step(-1, 0) elseif k == "down" then step(1, 0) end
  local n, row = tonumber(k), ("abcdef"):find(k, 1, true)
  if n and n >= 1 and n <= N then toggleFold(false, n) end
  if row and #k == 1 then toggleFold(true, row) end
end

Nothing is ever deleted: folding only changes which index counts as "next", so unfolding has nothing to put back. The demo adds a step counter, undo, and the win check when the traveller stands on G.

Pitfalls

  • The fold is a teleport in disguise. If players stop picturing paper and just see tiles that jump, the charm is gone and it plays like a list of switches. Test: after map 1, ask a tester what happened to the river. If they say "it disappeared" rather than "I folded it under", spend time on the fold animation and the seam.
  • Folding everything. With unlimited folds the answer to every map is "fold all the obstacles". The two-fold limit and the pins are what make it a puzzle. Check every map with a solver at fold limits of zero, one and two, and make sure the fold limit you ship actually matters.
  • Brute force beats thinking. With only twelve strips, a player can try each in turn and stumble into the answer. Par helps, but the real fix is maps where the wrong fold looks right.
  • Lost in the folded view. After two folds, the map on screen no longer looks like the land. Keep the grid labels on the tabs, so column 4 stays "4" even when it sits second, and keep the seam visible so players can count what is hidden.

In real games

Changing the map to change the world is explored ground. In Carto (Sunhead Games, 2020) the player moves and rotates pieces of a map, and the world rearranges to match. Gorogoa (Jason Roberts, 2017) is a puzzle game about moving and layering illustrated panels so that scenes connect.

Folding Map is narrower. Nothing moves to a new place; whole strips are hidden, and adjacency is the only thing that changes. Its puzzles come from folds being global and from pins. I expect other paper folding puzzle games exist, but I have not checked enough of them to say how close any of them is.

Your turn: the first playtest

In one sitting, build the Lua above with map 1 and a simple drawing: one rectangle per tile, skipping folded strips. Then make map 2 by hand on paper and type it in. Skip animation, undo and par.

Give it to a friend with only the controls. The one question: on map 2, when the column fold is refused, do they think of folding rows on their own? If they do within a couple of minutes, the idea has depth. If they give up, the rule that folds are whole strips is not yet clear, and the first map needs to show a row fold too.

Takeaways

  • Weekend version: the demo's rules, fifteen hand-made maps checked by a breadth first solver, par for each, and a fold animation that sells the paper.
  • One-month version: larger maps that scroll, diagonal or partial creases marked on the paper, a level editor that runs the solver as you build, and a short story told through the letters you deliver.
  • Cut first: extra tile types such as keys, enemies or moving things. The fold and the pin are enough for many maps, and each new tile multiplies the cases to test.
