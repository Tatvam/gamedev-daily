Pigment Slide: every block moves, every collision mixes

A sliding puzzle where all the paint moves at once and every collision mixes colours, so you must keep some apart. Playable prototype and Lua code.

You are the apprentice in a fresco workshop, and the master has chalked a colour on each patch of wall: green here, purple there. Your paints are blocks on a slippery table, and when you tilt it every block slides at once, and any two that touch mix for good.

The core loop: read, slide, mix

Pigment Slide is a turn-based puzzle on a five by five grid. Some tiles are walls. Some are targets, floor tiles marked with the colour they want. The rest is open floor. On the floor sit blocks of the three painter's primaries: red, yellow and blue.

Each move is one direction. Every block on the board slides that way until it hits a wall, the edge, or another block. This is the same "slide until stopped" rule as an ice floor, applied to everything at once. When a sliding block runs into another block, the two become one block of the mixed colour.

Every ten seconds the player reads where each block would stop and picks a direction. Every minute they finish a canvas, when every target holds a block of its colour at the end of a move. Every session brings canvases with more targets, more blocks of the same colour, and a par, the fewest moves that solve it.

The mixing rules fit on one card. Two different primaries make a secondary colour. Two blocks of the same colour make one block of that colour, so you lose a block without gaining anything. Anything else turns to mud, a brown block that matches no target.

The rules

  • One direction moves everything. Blocks nearest the far wall settle first, then the ones behind them slide up and stop or mix.
  • One mix per block per move. A block that was just made by a mix cannot mix again in the same move. A third block stops beside it. Without this rule a whole row would collapse into mud in one press.
  • Mixing is permanent. There is no way to split a block. A canvas becomes unsolvable the moment a colour you still need is spent.
  • The goal. At the end of a move, every target holds a block of its colour. Extra blocks elsewhere do not matter.

What makes it different

The player fantasy is the careful apprentice. The constraint is that you cannot move one block on its own. That turns the puzzle inside out: the hard part is rarely making green, it is keeping the blue you need for purple away from the yellow while you make green. Canvas 2 in the demo opens with two blues side by side, and any sideways move merges them into one, which leaves you a blue short.

The mood is calm: no timer, and the only way to fail is to spend a colour, which Undo gives back.

The hardest part to build is the level design, not the rule. The slide is thirty lines, but knowing that every canvas is solvable and what its par is takes a solver. The prototype's canvases were checked with a breadth first search over all four directions. Each has fewer than two hundred reachable states, so the demo also runs that search after every move and tells you when a board becomes unsolvable.

The colour model is the traditional painter's red, yellow and blue. Real pigments do not mix this neatly, which is fine for a game.

The code

The heart of the mechanic in LÖVE: walk the grid starting from the side the blocks slide toward, push each block until something stops it, and mix it into the block it hits unless that block has already mixed this move. Drawing, the win check and the key bindings are left out: the arrow keys call slide(0, -1), slide(0, 1), slide(-1, 0) and slide(1, 0), and a move counts only when slide returns true.

local N = 5
local grid, wall = {}, {}   -- one table per row, filled from the level
local MIX = { ry = "o", yr = "o", yb = "g", by = "g", rb = "p", br = "p" }
local function mix(a, b)
  if a == b then return a end            -- blue into blue is still one blue
  return MIX[a .. b] or "m"              -- anything else is mud
end

local function span(d)                   -- start from the side we slide toward
  if d > 0 then return N, 1, -1 else return 1, N, 1 end
end

local function slide(dr, dc)             -- returns false if nothing moved
  local mixed, moved = {}, false
  local r0, r1, rs = span(dr)
  local c0, c1, cs = span(dc)
  for r = r0, r1, rs do
    for c = c0, c1, cs do
      local paint, cr, cc = grid[r][c], r, c
      if paint then
        grid[r][c] = nil
        while true do
          local nr, nc = cr + dr, cc + dc
          if nr < 1 or nr > N or nc < 1 or nc > N or wall[nr][nc] then break end
          if grid[nr][nc] then
            if not mixed[nr * N + nc] then  -- one mix per block per move
              grid[nr][nc] = mix(paint, grid[nr][nc])
              mixed[nr * N + nc], paint, moved = true, nil, true
            end
            break
          end
          cr, cc = nr, nc
        end
        if paint then grid[cr][cc] = paint end
        if cr ~= r or cc ~= c then moved = true end
      end
    end
  end
  return moved
end

The loop order is the whole trick. The block nearest the far wall is handled first, so it has already stopped when the block behind it arrives. The demo's solver uses the same function, so its par and its "unsolvable" warning always agree with what you see.

Pitfalls

  • Prediction overload. With six or more blocks, players stop predicting and start pressing at random. The fun is in thinking one move ahead and being right. Test: ask a tester to say where every block will stop before each press. If they cannot on your third canvas, it has too many blocks.
  • Silent dead ends. A canvas can become unsolvable many moves before the player notices, and then they push blocks around for minutes. Detect it with the solver and say so straight away, as the demo does, or the game feels unfair.
  • Colour alone is not enough. Many players cannot tell red from green, or orange from yellow, at a glance. Put a letter or a shape on every block and every target from the first prototype, not as a late accessibility pass.
  • Every canvas has the same answer. If the trick is always "make the secondary first", players solve by habit. Vary what is scarce: twin primaries, a pure colour that must survive, a wall that is the only place a block can stop.

In real games

Moving every tile at once with one swipe is well known from 2048 (Gabriele Cirulli, 2014), where equal numbered tiles merge when they slide together. Sliding until something stops you is the rule of the ice floor puzzles found in many role-playing games.

Pigment Slide puts those two rules on a fixed board with targets. Where 2048 is about growing numbers in an endless game, here the merge is something to avoid as often as something to seek, because different colours mix and mixing is final. Colour mixing has surely appeared in other puzzle games, but I have not surveyed them enough to say how close any comes.

Your turn: the first playtest

In one sitting, build the Lua above with canvas 1 and canvas 2 typed in by hand, one coloured rectangle with a letter per block, and a win check. Skip animation, the solver and par. Add undo, though: without it the first mud ends the session.

Give it to a friend with only the controls. The one question: on canvas 2, do they spot the twin blues before their first sideways move, or only after merging them? If they spot it, or groan and understand why, the "keep them apart" idea carries the game. If they never notice what went wrong, the mix needs a louder moment on screen.

Takeaways

  • Weekend version: the demo's rules, fifteen hand-made canvases checked by a breadth first solver, par for each, letters on every block, and a satisfying splash when two colours mix.
  • One-month version: larger walls of fresco made of several canvases, a level editor that runs the solver as you place blocks, and a gentle story about the workshop told between commissions.
  • Cut first: extra colours such as white and black for tints and shades. Seven colours are plenty, and each new one multiplies the mixing table and the levels you must test.

Next

Further reading

  • Josef Albers, Interaction of Color (Yale University Press, 1963). A classic on how colours affect each other, useful for picking paints that read well side by side.
  • Jesse Schell, The Art of Game Design: A Book of Lenses (CRC Press). The chapter on puzzles, especially the advice on giving a clear goal and making progress visible.
  • Stephen Lavelle, PuzzleScript. A free tool for turn-based grid puzzles, quick for trying many canvases before building them in LÖVE.
