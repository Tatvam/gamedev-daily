Statue Garden: creep while the eyes are shut

A one-button stealth game where you hold to creep and let go to freeze as a statue, with a playable prototype and the eye timers in Lua.

You are a garden statue that wants to get out of the garden. Three stone guards blink on their own slow rhythms, and the moment an eye opens you must be perfectly still, because a statue that moves while someone is watching is caught.

The core loop: read the eyes, creep, freeze

Statue Garden is a one-button stealth game: the only input is a button you hold or release. Holding makes you creep along a garden path. Releasing freezes you, and a frozen statue is invisible to the guards. There is no hiding place and no other move.

Each guard's eye follows a fixed rhythm, a repeating cycle of shut and open, and watches only part of the path. Where two guards overlap, you must find moments when both eyes are shut.

The rules

Distances are in path units: the path runs from 0 at the start to 100 at the gate.

  • Creeping. Holding moves you 12 path units per second. Release and you stop at once.
  • Guards stand at 30, 62 and 90 and face the start. The first sees the path from 0 to 30, the second 18 to 62, the third 42 to 90. Once you pass a guard, it cannot see you.
  • Eyes. The three eyes are shut then open for 2.4 + 1.6, 1.8 + 1.4 and 3.0 + 2.2 seconds, so they drift in and out of step.
  • The warning. For the last 0.6 seconds before it opens, an eye flutters half open. It cannot see you yet, but it is your signal to let go.
  • Caught. If you are moving while an open eye can see your spot, you are sent back to the start. Standing still is always safe, even under an open eye.
  • Goal. Reach the gate. Your score is the total time taken.

What makes it different

The player fantasy is a statue coming to life, the eerie thing that moves only when nobody is looking. The constraint is that you never steer and never hide: danger is in the moment, and the place only decides which moments count.

The guards are layered on purpose: one rhythm to learn, then a second on top, then the first falls behind you and the third joins. A level is a sequence of rhythm mixes that you can design on paper as a timeline.

The hardest part is not the code, which is small. It is tuning the rhythms so every overlap has windows short enough to be tense and long enough to be fair.

Try it

Click or tap the canvas to focus it, then hold to start creeping. Watch the eyes, not your statue: let go as soon as an eye that can see you starts to flutter. Then set the warning to None and feel how the same garden goes from tense to unfair.

The code

This is the whole mechanic in LÖVE: the eye cycle, what each guard can see, creeping and getting caught. The names and numbers match the prototype. Drawing and the end screen are left out, and won is your own function. The prototype also pauses for a moment before sending you back; here the reset is instant.

local SPEED, EXIT, WARN = 12, 100, 0.6
local guards = {
  { x = 30, reach = 30, shut = 2.4, open = 1.6, offset = 0 },
  { x = 62, reach = 44, shut = 1.8, open = 1.4, offset = 0.3 },
  { x = 90, reach = 48, shut = 3.0, open = 2.2, offset = 1.0 },
}
local player = { x = 0, caught = 0, needRelease = false }
local t = 0

local function eyeState(g, time)
  local p = (time + g.offset) % (g.shut + g.open)  -- where we are in the cycle
  if p < g.shut - WARN then return "closed" end
  if p < g.shut then return "warning" end            -- fluttering: still safe
  return "open"
end

local function watching(g, x)
  return x >= g.x - g.reach and x < g.x             -- guards face the start
end

function love.update(dt)
  t = t + dt
  local held = love.keyboard.isDown("space") or love.mouse.isDown(1)
  if not held then player.needRelease = false end
  local moving = held and not player.needRelease
  if moving then
    player.x = math.min(EXIT, player.x + SPEED * dt)
  end
  for _, g in ipairs(guards) do
    if moving and watching(g, player.x) and eyeState(g, t) == "open" then
      player.x, moving = 0, false                    -- back to the start
      player.caught = player.caught + 1
      player.needRelease = true                      -- must let go before moving again
    end
  end
  if player.x >= EXIT then won() end
end

The eyes need no timers of their own. The % operator wraps the shared clock into each guard's cycle, and offset shifts where it starts, so the whole garden is the table of numbers. Without needRelease, a player still holding the button would be caught again the moment they land back at the start.

Pitfalls

  • Waiting is boring. If the best plan is always to wait for one huge safe window, the game becomes a slow walk with long pauses. Measure how long players stand still. If it is most of the run, shorten the open times or add a par time.
  • No warning, no game. Without the flutter, getting caught feels like bad luck, because nobody can react to an eye that opens with no warning. Try the None setting in the demo. As the game gets harder, keep the warning readable.
  • Too many eyes to read. Three rhythms at once is more than most people can track. Overlap at most two guards, and show which guards are watching the player.
  • Rhythms that line up. If two cycles share a simple ratio, such as 2 and 4 seconds, the same windows repeat forever, and an overlap can have none. Draw the timeline to check every overlap has gaps.
  • Back to the start is harsh. On a long path it feels cruel. Compare it with a checkpoint at each guard you pass, and keep whichever makes players want another try.

In real games

The core rule is a playground game. In Red Light, Green Light, and in the British version called Grandmother's Footsteps, players creep towards a caller and must freeze whenever the caller turns round. Anyone seen moving goes back to the start. Here the one caller becomes several watchers on their own clocks.

Video games often use the opposite side of the same idea. The Boo ghosts in the Super Mario games chase Mario while he faces away and stop to hide their faces when he turns to look. Here you play the thing that moves when unseen. Stealth games such as Metal Gear Solid (Konami, 1998) show guards' fields of view so the player can plan around them, as the sight bars do here. I have not searched for video games built on one held button and blinking watchers; some probably exist, so check before calling the idea new.

Your turn: the first playtest

In one sitting, build the Lua above with a rectangle for the statue, three circles for the eyes and a line for each guard's view. Print the run time, the catches and the time spent standing still.

Give it to someone and say only "get to the gate without being seen moving". The one question to answer: do players start moving before an eye shuts, because they have learned the rhythm? If they only react to what they see, the rhythms are too irregular or too fast to learn. If they start counting under their breath, the garden is working.

Takeaways

  • Weekend version: the prototype above with three short gardens, a par time for each, and a stony scrape sound while you move that plays only after the player turns sound on.
  • One-month version: twenty gardens built from overlapping rhythms, plus a few guard types that each change one rule, such as a guard who looks back the other way or one whose rhythm speeds up when you are close.
  • Cut first: new guard types. Rhythm, reach and position are enough for many levels.
  • The hardest part is tuning the overlaps. Draw each one as a timeline before you play it.
