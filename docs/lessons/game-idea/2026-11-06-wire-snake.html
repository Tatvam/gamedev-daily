Wire Snake: the route you crawl is the circuit you build

A grid puzzle where a snake made of wire crawls from a battery to a lamp on a fixed reel, never crossing itself or water. Playable prototype and Lua code.

You are a snake made of copper wire, and your tail is plugged into a battery. Every tile you crawl over stays wired behind you. Reach the lamp before the reel runs out, without crossing yourself or dipping into a puddle, and the room lights up.

The core loop: plan, crawl, back up

Wire Snake is a turn-based puzzle on a seven by seven grid. One tile is the battery, where the wire starts. One tile is the lamp, where it must end. Walls block the way, and so does water, because a live wire must stay dry. The level also gives you a reel: the number of tiles of wire you may lay, shown as a bar at the top.

Each press of a direction moves the snake's head one tile and lays one tile of wire. Your own body is now an obstacle, as in Snake, but nothing moves unless you move it. Pressing back toward the tile you came from pulls the wire back in.

Every ten seconds the player crawls a few tiles, sees that the route is going to run out of wire or box itself in, and backs up. Every minute they light a lamp. Every session the circuits add bulbs, small lamps that must be wired in along the way, so the order of the route starts to matter.

The rules

  • One tile per move. The head moves up, down, left or right onto floor. Water, walls, the board edge and the wire itself all refuse the move.
  • Backing up is free. Moving onto the tile just behind the head reels in the last tile of wire. There is no move counter and no penalty.
  • The reel is fixed. When every tile on the reel is laid, the head cannot go further.
  • Bulbs are in series. The lamp only accepts the wire once every bulb is on it, because current has to pass through each one to get there.
  • The goal. The head reaches the lamp. Wire left on the reel is a bonus, not a requirement.

What makes it different

The player fantasy is the careful electrician who runs one cable through a flooded cellar. The constraint is the reel. In Snake your length grows and you try to survive. Here your length is a budget and you try to spend it well. A route that works in space can still fail in length, and a short route can fail because it walls off a bulb you still need.

That second failure is where the puzzle lives. In circuit 3 of the demo the gap below the battery points straight at the lamp. Take it first and there is not enough wire left to fetch both bulbs. The real route climbs to the top bulb, sweeps round to the left bulb, and only then comes down.

The hardest part to build is the level design. Each reel in the prototype is exactly the length of the shortest route, found by a depth first search that tries every route that does not cross itself. The demo runs the same search after each move and tells you when your current wire can no longer reach the lamp.

Try it

Circuit 1 teaches the reel: the way under the puddle is too long. Circuit 2 adds a bulb. On circuit 3, try the obvious gap below the battery first, then watch the message bar tell you why it cannot work.

The code

The heart of the mechanic in LÖVE: one function that tries to move the head, and either lays a tile of wire, reels one in, or says why it refused. The wire is a list of tiles starting at the battery, and onWire is a lookup table so the crossing check is one line. Drawing is left out. Bind the arrow keys to step(0, -1), step(0, 1), step(-1, 0) and step(1, 0), and backspace to retract() in love.keypressed. The wire starts as one tile on the battery, which sits in row 2, column 2 of circuit 1.

local N = 7
local level = { reel = 8, map = { ".......", ".B.~...", "...~...", "...~.L.",
                                   "...~...", ".......", "......." } }
local function tile(r, c) return level.map[r]:sub(c, c) end
local function key(r, c) return (r - 1) * N + c end
local wire, lit = { { r = 2, c = 2 } }, false   -- wire[1] is the battery
local onWire = { [key(2, 2)] = true }

local function bulbsDone()
  for r = 1, N do
    for c = 1, N do
      if tile(r, c) == "o" and not onWire[key(r, c)] then return false end
    end
  end
  return true
end

local function retract()
  if #wire <= 1 then return end
  local h = table.remove(wire)
  onWire[key(h.r, h.c)] = nil
  lit = false
end

local function step(dr, dc)                -- returns why it refused, or nil
  if lit then return "lit" end
  local h, prev = wire[#wire], wire[#wire - 1]
  local r, c = h.r + dr, h.c + dc
  if prev and prev.r == r and prev.c == c then retract() return nil end
  if r < 1 or r > N or c < 1 or c > N then return "edge" end
  local t = tile(r, c)
  if t == "#" then return "wall" end
  if t == "~" then return "water" end
  if onWire[key(r, c)] then return "crossing" end
  if #wire - 1 >= level.reel then return "reel empty" end
  if t == "L" and not bulbsDone() then return "bulbs first" end
  wire[#wire + 1] = { r = r, c = c }
  onWire[key(r, c)] = true
  if t == "L" then lit = true end
end

The two highlighted lines are the whole game: your body blocks you, and your length is limited. Everything else is bookkeeping. Backing up is tested first, so it works even when the reel is empty.

Pitfalls

  • Trial and error instead of planning. If a circuit has dozens of shortest routes, any wiggle wins and nobody plans. If it has one route through an open field, players find it by luck. Count the solutions with a solver: the prototype's circuits have between three and eight.
  • Learning too late that it was hopeless. Running out of wire on tile eleven because of a mistake on tile two feels unfair. Show the reel at all times and say as soon as no route is left, as the demo does.
  • Backing up feels like a chore. If undoing ten tiles takes ten presses, players restart instead. Let them tap any wired tile to cut back to it.
  • Slack that is not really slack. On a grid, every route between two tiles has a length of the same parity, odd or even, like the colours of a chessboard. A reel of 9 for a shortest route of 8 gives no extra freedom at all. Add slack in steps of two.

In real games

A body that becomes your obstacle is the idea behind the Snake family, which many people first played on Nokia phones in the late 1990s. There the threat is time: you move whether you like it or not. Line-drawing puzzles take the opposite stance. In The Witness (Thekla, 2016) you trace a line from a start to an end that cannot cross itself, and in Flow Free (Big Duck Games) you join pairs of coloured dots with pipes that cannot cross. Snakebird (Noumenon Games, 2015) is a turn-based puzzle game about snakes, built around gravity.

Wire Snake sits between the two: a snake you steer tile by tile, judged like a line puzzle. Its own rule is the reel, a length budget, together with bulbs that force an order. A length budget has very likely appeared in some path puzzle before; I have not surveyed them all.

Your turn: the first playtest

In one sitting, build the Lua above with circuits 1 and 3 typed in, coloured rectangles for tiles, a thick line through the wire and a bar for the reel. Skip the solver, the drag controls and the animation. Keep retract on a key: without it, every mistake means a restart.

Give it to a friend with only the controls. The one question: when the reel runs out on circuit 3, do they back up part of the way and try a different branch, or press restart? Backing up means they are reasoning about the route, which is the game. Restarting means backing up is not discoverable, or the circuit is too long to reason about.

Takeaways

  • Weekend version: the demo's rules, fifteen hand-made circuits with reels checked by a solver, tap-to-cut retract, and a satisfying moment when current runs down the wire and the lamp comes on.
  • One-month version: a house of rooms, each a circuit, where lit rooms open the next; a level editor that runs the solver as you paint water; and a star for each tile of wire left over.
  • Cut first: extra components such as switches and two-way junctions. The reel and bulbs already carry a full game.
