Spinning Top Sumo: a duel where you only choose when

A one-button duel where each top's aim arrow spins on its own and a press dashes that way, with a playable prototype and the dash and collision code in Lua.

Two spinning tops face off in a ring that keeps getting smaller. Your aim arrow sweeps around by itself, and your only move is to press at the moment it points at your rival, before their arrow comes round to point at you.

The core loop: watch the sweep, strike, recover

Spinning Top Sumo is a one-button duel: each player has a single input, and the whole game is about when to use it. Nobody steers. Each top has an aim arrow that rotates around it at a fixed speed, and a press launches the top in the direction the arrow points right now.

That gives every press two sides. A dash aimed well hits the rival and sends them towards the edge. A dash aimed badly sends you towards the edge, and the arrow takes more than two seconds to come all the way round again.

The rules

Positions are measured in ring units, where the starting ring has a radius of 1. That keeps the numbers the same whatever the screen size.

  • The arrow turns at 2.6 radians per second, so it goes all the way round in about 2.4 seconds.
  • The dash sets the top's velocity to 1.3 ring units per second in the arrow's direction. It replaces the old velocity rather than adding to it, so a dash can also be used to brake or turn back. After a dash the top must wait 0.5 seconds before it can dash again.
  • The swing back. Each dash reverses the direction the arrow turns. If you dash towards the edge and miss, your arrow is already sweeping back towards the middle.
  • Friction slows a moving top smoothly, so a dash from rest glides about 0.65 ring units and stops.
  • Collisions. The tops are equal circles. When they hit, the speed along the line between them is passed across, so a dashing top nearly stops and the top it hit flies off with most of its speed.
  • Ring out. The ring shrinks from radius 1 to 0.3 over 35 seconds. A top whose centre crosses the edge loses the round. If both go out at once, nobody scores. The first to win two rounds wins the match.

What makes it different

The player fantasy is a tiny gladiator in a schoolyard ring. The constraint is that you never choose a direction, only a moment. Both arrows are always visible, so each player can read the other's next threat: "their arrow reaches me in half a second, so I must strike first or dash away first". A single button becomes a game of reading and bluffing.

The shrinking ring is the pressure. Early on, a dash from the middle cannot carry you out, so mistakes are cheap. Later, a dash from the middle in the wrong direction is a ring-out, and every press is a risk.

The hardest part to build is the computer rival. It has to be beatable, it must not dash the instant its arrow lines up, and it must not throw itself out of the ring. The prototype's rival waits a random short time between dashes, aims slightly off target on purpose, and only dashes away from you when its landing point stays inside the ring.

The code

This is the heart of the mechanic in LÖVE: the turning arrow, the dash, friction, the collision between two equal tops, and the ring-out check. The numbers and names match the prototype. Drawing, the round flow and the computer rival are left out. roundLost is your own function.

local SPIN, DASH, FRICTION, COOLDOWN = 2.6, 1.3, 2.0, 0.5
local TOP_R, BOUNCE = 0.09, 0.9
local ringR = 1                          -- ring units; shrinks to 0.3 over 35 s
local tops = {
  { x = -0.3, y = 0, vx = 0, vy = 0, aim = -math.pi / 2, turn = 1, cool = 0, key = "a" },
  { x =  0.3, y = 0, vx = 0, vy = 0, aim =  math.pi / 2, turn = 1, cool = 0, key = "l" },
}

local function dash(t)
  if t.cool > 0 then return end
  t.vx, t.vy = math.cos(t.aim) * DASH, math.sin(t.aim) * DASH  -- set, not add
  t.cool, t.turn = COOLDOWN, -t.turn     -- the arrow swings back the other way
end

function love.keypressed(key)
  for _, t in ipairs(tops) do
    if key == t.key then dash(t) end
  end
end

local function collide(a, b)
  local dx, dy = b.x - a.x, b.y - a.y
  local d = math.sqrt(dx * dx + dy * dy)
  if d >= TOP_R * 2 or d == 0 then return end
  local nx, ny, push = dx / d, dy / d, (TOP_R * 2 - d) / 2
  a.x, a.y, b.x, b.y = a.x - nx * push, a.y - ny * push, b.x + nx * push, b.y + ny * push
  local rel = (a.vx - b.vx) * nx + (a.vy - b.vy) * ny
  if rel <= 0 then return end            -- already moving apart
  local j = rel * (1 + BOUNCE) / 2       -- equal masses share the impulse
  a.vx, a.vy, b.vx, b.vy = a.vx - j * nx, a.vy - j * ny, b.vx + j * nx, b.vy + j * ny
end

function love.update(dt)
  ringR = math.max(0.3, ringR - 0.02 * dt)
  local slow = math.exp(-FRICTION * dt)  -- smooth slowdown at any frame rate
  for _, t in ipairs(tops) do
    t.aim, t.cool = t.aim + SPIN * t.turn * dt, math.max(0, t.cool - dt)
    t.vx, t.vy = t.vx * slow, t.vy * slow
    t.x, t.y = t.x + t.vx * dt, t.y + t.vy * dt
  end
  collide(tops[1], tops[2])
  for i, t in ipairs(tops) do
    if math.sqrt(t.x * t.x + t.y * t.y) > ringR then roundLost(i) end
  end
end

Friction uses math.exp(-FRICTION * dt) so the glide is the same length at 30 or 144 frames per second. With speed 1.3 and friction 2.0, a dash from rest travels 1.3 / 2.0 = 0.65 ring units. The tops start 0.3 from the centre, so at the start no single dash can carry you out, and a dash from the centre only becomes deadly once the ring is smaller than 0.65. If both tops go out on the same frame, have roundLost check both before awarding the point.

Pitfalls

  • Whoever presses first wins. If one well-timed dash always means a ring-out, rounds become a reaction test and nobody reads anybody. Check that a hit from the centre of the full-size ring cannot push the rival out alone. Here it cannot: the rival starts 0.3 from the centre and a hit makes it glide at most about 0.65 units. Two or three hits, or one hit late in the round, should be needed.
  • Turtling. If sitting still in the middle is the best plan, the game stalls. The shrinking ring is the fix. Time a few rounds: if most last until the ring stops shrinking, speed up the shrink.
  • An arrow you cannot read. The whole game is reading two arrows at once. If players lose and say "I did not see it", make the arrows longer, thicker and higher in contrast before touching any other number.
  • A rival that is perfect or stupid. A computer that dashes the exact frame its arrow lines up feels like cheating, and one that walks out of the ring feels like a joke. Give it a reaction delay and an aim error, and tune those two numbers only.
  • Lag between friends. Online, a few frames of delay change who hit first. Build it for two players on one device first, where timing is fair.

In real games

Spinning top battles are an old playground game, and Beyblade (from Takara Tomy) turned them into a toy line where tops are launched into a shallow stadium and knock each other out. In those toys the player's input ends at the launch, so the battle is watched rather than played.

The ring-out goal comes from sumo, where a wrestler loses by being forced out of the ring or touching the ground with anything other than the soles of the feet. Video games use the same idea: in Super Smash Bros. (Nintendo, 1999) you win by knocking rivals off the stage rather than by draining a health bar.

What this idea changes is that the direction is never chosen, only the moment. I have not searched thoroughly for other games that use a constantly rotating aim on one button, and such games may well exist, so check before calling this new.

Your turn: the first playtest

In one sitting, build the Lua above with two circles, two lines for the arrows and one circle for the ring. Skip the computer rival: two players on one keyboard, A and L. Print the length of each round and how many dashes each player made.

Sit two people down and say only "push the other one out". The one question to answer: do players ever wait on purpose because the other arrow is about to point at them? If they only mash, the cooldown is too short or the arrow too fast. If you see someone hold back, then strike, the duel is working.

Takeaways

  • Weekend version: the prototype above with a spark when tops collide, a little screen shake on a big hit, a click sound that plays only after a player turns sound on, and four players on one keyboard.
  • One-month version: a handful of tops that differ in only one number each, such as a heavy top, a fast-spinning arrow or a long dash, plus a few ring shapes and a tournament ladder against computer rivals with names and habits.
  • Cut first: online play. It is the most work and it damages the timing that makes the game fair. Local play is the game.
  • The hardest part is a computer rival that is fun to lose to. Tune it with only a reaction delay and an aim error.
