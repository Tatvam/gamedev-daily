F-Zero and Mode 7: a flat map tilted into a racetrack

How F-Zero's flat track map becomes a floor in perspective: the Super Nintendo scales one background layer, and a new scale on every line adds depth.

In Nintendo's F-Zero, a launch game for the Super Famicom in Japan in November 1990, the track stretches away to a horizon and swings round as you steer. Yet the track is one flat picture, the same kind of picture a top-down racer would scroll. The console never knows it is drawing a floor.

The constraint: no time to draw pixels

The Super Nintendo screen is 256 pixels wide and usually 224 lines tall: about 3.4 million pixels per second at sixty frames. The main processor, a 65816, runs at about 3.58 MHz at most, roughly one clock cycle per pixel. Working out a floor pixel by pixel in software is impossible. The graphics chip has to do it.

That chip draws background layers: big pictures built from 8 by 8 pixel tiles, which it scrolls for free. Most of its eight background modes can only slide a layer. Mode 7 offers only one real layer, but that layer can be rotated and scaled.

What Mode 7 does

The Mode 7 layer is a map of 128 by 128 tiles: a plane of 1024 by 1024 pixels, built from up to 256 different tiles, with every pixel free to use any of the 256 palette colours. It fills 32 KB of the console's 64 KB of video memory.

Four registers, A, B, C and D (addresses $211B to $211E), form a 2 by 2 matrix, a small grid of numbers that turns one position into another. Each is a signed 16-bit fixed-point number with 8 bits after the point, so 256 means 1.0 and 128 means 0.5.

The emulator code shows how simple the work is. Each line starts at an origin, a map position worked out from the matrix, a centre point, the scroll and the line number. Then, for each pixel to the right, the chip adds A to the map x and C to the map y. With A = 256 and C = 0 it walks the map one pixel per pixel. With A = 512 it skips every other map pixel and the picture shrinks. Add some C and the walk runs at an angle: the picture rotates.

The trick: a new matrix on every line

One matrix for the whole screen gives a flat map seen from above, turned and zoomed. For a floor every line must differ. From a camera at height h, a line n lines below the horizon sees ground at a distance proportional to h / n, so its scale, in map pixels per screen pixel, is

scale = h / n

Lines just below the horizon sweep a wide strip of distant map. Lines at the bottom magnify a narrow strip near the camera. The rotation is the same on every line; only the step size and the start point change.

Rewriting registers by hand 224 times a frame would also be too slow. The console has a helper: HDMA (horizontal-blank direct memory access). Each of its eight channels walks a table in memory and copies a few bytes into a chosen register in the short pause before each line. The game fills a table with one set of matrix values per line, once per frame, and the hardware feeds it in.

Fact and legend

Mode 7 is often called "3D". It is not: the plane is flat, and each line is a plain 2D rotate and scale. The register layout and sums above come from the emulator source listed below. That F-Zero feeds per-line matrix values through HDMA is how the game is generally described, and it fits the hardware, but I could not open a breakdown of F-Zero's own code, so its exact tables are not shown. The rebuild uses its own track.

The idea in one line

Give the hardware one cheap transform per line, and change it from line to line to fake a perspective it cannot do.

The lesson for today

A ground plane in a shader is the same sum: work out the distance from the pixel's row, then look up the texture. Retro-style racers on phones and the web still draw floors this way. The wider habit carries to any tight budget: the processor fills a small table once per frame, and fast, simple hardware applies it.

The code

The demo's renderer in LÖVE, with the same numbers. buildLines is the HDMA table: one step and start point per line, in 8.8 fixed point like the registers. love.draw is the graphics chip: it starts each line at its origin and adds the step for every pixel.

-- Mode 7 style floor: one step and start point per screen line.
local SW, SH, F = 256, 224, 256
local HORIZON, CAM_H, SPEED, TURN = 80, 64, 120, 1.5
local cam = { x = 512, y = 792, angle = -math.pi / 2 }   -- facing west
local function rgb(r, g, b) return { r / 255, g / 255, b / 255 } end
local SKY, ROAD, RED, WHITE = rgb(120, 170, 230), rgb(96, 96, 104), rgb(200, 56, 48), rgb(236, 236, 236)
local BLACK, GRASS1, GRASS2 = rgb(24, 24, 24), rgb(70, 150, 70), rgb(58, 128, 60)
local data, img

local function mapColour(mx, my)                 -- the flat 1024 x 1024 map
  mx, my = mx % 1024, my % 1024
  local qx = math.max(math.abs(mx - 512) - 200, 0)
  local qy = math.max(math.abs(my - 512) - 120, 0)
  local d = math.abs(math.sqrt(qx * qx + qy * qy) - 160)   -- distance from track centre
  if d < 36 then
    if my > 700 and math.abs(mx - 512) < 8 then        -- start line
      return (math.floor(mx / 4) + math.floor(my / 4)) % 2 == 0 and WHITE or BLACK
    end
    return ROAD
  elseif d < 44 then
    return (math.floor(mx / 16) + math.floor(my / 16)) % 2 == 0 and RED or WHITE
  end
  return (math.floor(mx / 64) + math.floor(my / 64)) % 2 == 0 and GRASS1 or GRASS2
end

local function buildLines()                      -- the per-line table
  local lines = {}
  local fx, fy = math.sin(cam.angle), -math.cos(cam.angle)   -- forward
  local rx, ry = -fy, fx                                     -- right
  for y = HORIZON + 1, SH - 1 do
    local scale = CAM_H / (y - HORIZON)          -- map pixels per screen pixel
    local depth = scale * F
    local a = math.floor(scale * rx * 256 + 0.5) -- like register A
    local c = math.floor(scale * ry * 256 + 0.5) -- like register C
    lines[y] = { a = a, c = c,
      ox = (cam.x + fx * depth) * 256 - a * SW / 2,
      oy = (cam.y + fy * depth) * 256 - c * SW / 2 }
  end
  return lines
end

function love.load()
  data = love.image.newImageData(SW, SH)
  img = love.graphics.newImage(data)
  img:setFilter("nearest", "nearest")
end

function love.update(dt)
  if love.keyboard.isDown("left") then cam.angle = cam.angle - TURN * dt end
  if love.keyboard.isDown("right") then cam.angle = cam.angle + TURN * dt end
  cam.x = (cam.x + math.sin(cam.angle) * SPEED * dt) % 1024
  cam.y = (cam.y - math.cos(cam.angle) * SPEED * dt) % 1024
end

function love.draw()
  local lines = buildLines()
  for y = 0, SH - 1 do
    local L = lines[y]
    for x = 0, SW - 1 do
      local col = SKY
      if L then
        col = mapColour(math.floor((L.ox + L.a * x) / 256), math.floor((L.oy + L.c * x) / 256))
      end
      data:setPixel(x, y, col[1], col[2], col[3], 1)
    end
  end
  img:replacePixels(data)
  love.graphics.draw(img, 0, 0, 0, 3, 3)
end

The screen is drawn three times larger, so set the window to 768 by 672 in conf.lua. mapColour works out the map on the fly; the demo bakes it once into a 1024 by 1024 buffer, closer to video memory. The controls match the demo's Steer yourself mode at its default speed.

Pitfalls

  • Dividing by zero at the horizon. scale = h / n blows up when n is 0. Start the floor one line below the horizon, as buildLines does, and leave the lines above to another layer.
  • Overflowing the fixed-point registers. A holds at most 32767, which is a scale just under 128. The first floor line has scale h / 1, so a camera height of 128 or more overflows it. The demo stops at 120.
  • Sparkle in the distance. A far line skips many map pixels per step, with no averaging, so the far track shimmers as the camera moves. Modern GPUs fix this with mipmaps, smaller pre-averaged copies of a texture.
  • Forgetting that the floor is flat. Mode 7 cannot do hills or walls. Anything that stands up, such as cars and signs, has to be a sprite scaled by the same h / n rule.

In real games

On the Super Nintendo, Pilotwings and Super Mario Kart also draw their ground with Mode 7, and many games used it without perspective, for one rotating or zooming picture. In all of them, the racers and objects on the ground are sprites. The Game Boy Advance later added rotating and scaling background layers of its own, used for the same kind of floor.

Takeaways

  • Mode 7 rotates and scales one 1024 by 1024 pixel layer with a fixed-point 2 by 2 matrix.
  • A new matrix on every line, with scale = height / lines below horizon, turns the flat map into a floor.
  • HDMA feeds a per-line table into the registers, so the processor builds one table per frame.
  • The floor is flat: everything that stands up is a sprite.
