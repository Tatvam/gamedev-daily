Super Mario Bros.: the cloud and the bush share their tiles

Why Super Mario Bros. bushes look like clouds: NES tiles store colour numbers, not colours, so one shape drawn with two palettes became two objects.

In the first level of Super Mario Bros., look up at a cloud, then down at a bush. The bumpy outline is the same, the shading is the same. One is white and the other is green.

That is not an artist running out of ideas. Every piece of scenery had to fit in a small, fixed number of tiles, and colour was stored somewhere else.

The constraint: 256 tiles for all the scenery

The NES (the Famicom in Japan) builds its background from tiles: 8 by 8 pixel squares placed on a grid, 32 tiles across. Super Mario Bros. (1985) shipped on a cartridge with 32 KB of program code and 8 KB of graphics, the CHR ROM. Those 8 KB hold two pattern tables of 256 tiles each: one for the background, one for sprites (the moving objects).

So ground, bricks, pipes, hills, clouds, bushes, the flagpole and the letters and digits of the score all share one table of 256 background tiles.

A tile does not store colours. Each pixel stores a 2-bit colour number from 0 to 3. That makes a tile 64 pixels times 2 bits, which is 16 bytes, and the whole background table 4 KB.

Where the colour comes from

Colours live in palettes. The background has four palettes. Each one says which colours numbers 1, 2 and 3 become. Number 0 means the same backdrop colour in every palette: the sky blue of a daytime level.

A second table, the attribute table, picks one of the four palettes for each 16 by 16 pixel area of the screen, a block of 2 by 2 tiles. The screen is therefore described by two small lists: which tile sits in each cell, and which palette each area uses.

That split is the whole trick. One tile can appear in many cells, and each area can paint it in different colours, at no extra cost in tile memory.

The trick: one shape, two objects

The developers drew the puffy shape once. In the sky, painted with a white and pale blue palette, it is a cloud. On the ground, painted with a green palette, it is a bush. In Nintendo's Iwata Asks interviews, Toshihiko Nakago of the original team recalled that they used the same image for clouds and grass and changed only the colour, and the interviews link this to the limit on how many tiles fit in the cartridge.

Fact and legend

The popular version is "the clouds and bushes are the same sprite". Two corrections. They are background tiles, not sprites. And the bush is not the whole cloud: descriptions of the game's tile set say the bush uses only the cloud's upper tiles, cut off flat where it meets the ground. The demo below rebuilds it that way.

In the rebuild below, sharing saves 8 tiles, 128 bytes: a small slice of a 4 KB table. The habit, applied wherever one shape can play two parts, is what lets a whole world fit.

The idea in one line

Store shape and colour separately, and any shape can be reused in any colour for free.

The lesson for today

Modern graphics cards have no fixed palettes, but the idea is everywhere. A grey texture tinted at draw time gives red, blue and green enemies from one image; in LÖVE, love.graphics.setColor multiplies the colour of everything drawn after it. A palette texture repeats the NES split exactly: an image of colour numbers plus a small strip of colours that a shader looks up. On phones and the web, every extra texture is more to download and more graphics memory, and drawing many things from one texture lets the engine batch them.

The code

A cut-down version in LÖVE: only the middle piece of the puff, 2 tiles wide and 4 tall, using the same shape numbers and colours as the demo. addTile cuts an 8 by 8 tile out of the shape and stores it only if an identical tile is not stored already. The cloud places all four rows with the sky palette; the bush places the top two rows with leaf. It prints 7 tiles stored, 112 bytes: eight cells, but the two solid middle tiles are identical and stored once, and the bush added nothing.

-- One shape, two objects: tiles hold colour numbers 0-3, palettes give the colours.
local TILE, SCALE = 8, 3
local BACKDROP = {0.44, 0.66, 1.0}                  -- colour number 0, shared
local PALETTES = {
  sky  = { {0.17, 0.30, 0.55}, {0.99, 0.99, 0.99}, {0.66, 0.85, 1.0} },
  leaf = { {0.04, 0.30, 0.10}, {0.24, 0.69, 0.26}, {0.65, 0.91, 0.42} },
}
local tiles, ids, cells = {}, {}, {}

local function circle(px, py, cx, cy, r) return (px - cx)^2 + (py - cy)^2 <= r * r end
local function inside(px, py, g)                     -- g = -1.2 shrinks the shape
  return (py >= 12 - g and py <= 27 + g) or circle(px, py, 8, 11, 7 + g) or circle(px, py, 8, 25, 5 + g)
end
local function colourNumber(x, y)                    -- x 0..15, y 0..31
  local px, py = x + 0.5, y + 0.5
  if not inside(px, py, 0) then return 0 end         -- backdrop
  if not inside(px, py, -1.2) then return 1 end      -- outline
  if circle(px, py, 6, 9, 3.1) then return 3 end     -- highlight
  return 2                                           -- fill
end

local function addTile(ox, oy)
  local t = {}
  for y = 0, TILE - 1 do
    for x = 0, TILE - 1 do t[#t + 1] = colourNumber(ox + x, oy + y) end
  end
  local key = table.concat(t)
  if not ids[key] then tiles[#tiles + 1] = t; ids[key] = #tiles end   -- store once
  return ids[key]
end

local function place(col, row, tileRows, palette)
  for ty = 0, tileRows - 1 do
    for tx = 0, 1 do
      cells[#cells + 1] = { col = col + tx, row = row + ty, tile = addTile(tx * TILE, ty * TILE), palette = palette }
    end
  end
end

function love.load()
  love.window.setMode(256 * SCALE, 112 * SCALE)
  place(4, 2, 4, "sky")      -- cloud: all four tile rows
  place(10, 10, 2, "leaf")   -- bush: the top two rows, recoloured
  print(#tiles .. " tiles stored, " .. #tiles * 16 .. " bytes")
end

function love.draw()
  love.graphics.clear(BACKDROP[1], BACKDROP[2], BACKDROP[3])
  for _, cell in ipairs(cells) do
    local t, pal = tiles[cell.tile], PALETTES[cell.palette]
    for i = 1, TILE * TILE do
      if t[i] > 0 then
        love.graphics.setColor(pal[t[i]])           -- number -> colour, at draw time
        local x = cell.col * TILE + (i - 1) % TILE
        local y = cell.row * TILE + math.floor((i - 1) / TILE)
        love.graphics.rectangle("fill", x * SCALE, y * SCALE, SCALE, SCALE)
      end
    end
  end
end

The tile table never mentions a colour, and the cells never contain pixels. Only love.draw brings the two together, which is the job the NES graphics chip did for every line of the picture.

Pitfalls

  • Shared tiles mean shared edits. Touch up the cloud and the bush changes too. That is the point, but it surprises people who forget which objects share art.
  • Palettes are chosen per area, not per tile. On the NES each 16 by 16 area has one palette, so a white cloud and a green bush cannot overlap the same area. Scenery is placed on that 16 pixel grid. The demo does the same.
  • The shape has to work in both roles. Sharing only works when the silhouette reads as the right thing in context. Sky behind it says cloud; ground under it says bush.
  • Tinting multiplies. Modern tinting multiplies the texture colour, so it can only darken. Paint the shared image in white and greys, then tint. For true remapping, use a palette texture and a shader.
  • The Lua above is slow on purpose. It draws every pixel every frame so the lookup is visible. In a real game, build each tile-and-palette pair into an image once and draw that.

In real games

Super Mario Bros. uses palettes the same way for its characters. Luigi is Mario's sprite tiles with a different palette, and the Fire Mario look is also a palette change rather than new art.

Palette swaps became a standard tool of the 8-bit and 16-bit eras: recoloured enemies that signal a tougher version, and alternative colours for the second player in fighting games.

Takeaways

  • NES background tiles store a 2-bit colour number per pixel, 16 bytes per tile, and Super Mario Bros. had one table of 256 of them for all its scenery.
  • Colour comes from one of four palettes, chosen per 16 by 16 area by the attribute table.
  • The cloud and the bush share tiles: the bush is the cloud's upper tiles drawn with a green palette.
  • "Same sprite" is the legend; "shared background tiles, partly" is the accurate version.
  • Keep shape and colour apart today too: tint, masks and palette textures reuse one image many times.
