Silent Hill's fog: hiding the edge of the world

How Silent Hill's fog hid the PlayStation's short draw distance, and how to choose a fog density that makes distant objects fade in instead of popping.

In many 3D games of the late 1990s, a building suddenly appears at the far end of a street as you walk towards it. One frame it is not there, the next it is. Silent Hill's town has the same limit, but you rarely see it happen. The street ahead fades into grey fog, and shapes come out of it slowly.

The constraint: every polygon costs, and the far ones cost the most

Silent Hill (Konami, 1999) was made for the original PlayStation. Where Resident Evil used fixed painted backgrounds, Silent Hill built its town in real-time 3D with a moving camera, so the console had to draw the visible town again every frame.

Sony's published peak figures for the PlayStation are about 360,000 flat polygons per second, or 180,000 with textures and lighting, and real games reached well below those peaks. Its graphics chip has no depth buffer, so games sorted polygons into order themselves. A long street holds many polygons, and each one costs time to transform, sort and draw.

The usual answer is a draw distance, also called the far clip plane: a distance beyond which the game draws nothing. A short draw distance keeps the frame rate up. Its side effect is pop-in: an object crossing that line switches from absent to fully drawn in one frame.

The trick: fade to the fog colour before the cut

Distance fog blends each object's colour towards one fixed fog colour, more strongly the further away it is. If the fog is thick enough that an object is almost pure fog colour by the time it reaches the draw distance, and the empty background behind everything is painted in the same fog colour, then the moment of pop-in is invisible. The object appears, but it appears as grey on grey.

Silent Hill used heavy fog in its outdoor daytime areas and deep darkness, lit only by the hero's torch, in its night and nightmare areas. Darkness is the same trick with black fog. Retrospectives and the game's Wikipedia article say the fog and darkness hid the console's limits and also created the atmosphere. How much was necessity and how much was choice is told differently in different places, and I could not check the developers' own words, so treat "it was only a workaround" as often repeated, not confirmed.

How strong should the fog be?

A common fog formula is exponential fog. The share of the object's own colour that survives at distance d is:

visibility = math.exp(-density * d)   -- 1 = clear, 0 = pure fog

Exponential fog never quite reaches zero, so the question is how little is little enough. A useful working rule: if an object keeps under about 2% of its own colour when it appears, nobody notices it arrive. Since e−3.9 ≈ 0.02, that gives a density of at least 3.9 divided by the draw distance. For a 40 m draw distance, a density of 0.10 per metre leaves e−4 ≈ 1.8%.

Rule of thumb

Pick the draw distance your frame budget allows, then set the fog so that almost nothing is left at that distance: density ≥ 3.9 ÷ draw distance. Paint the background in the fog colour.

The code

The demo's street with the same numbers: walls 5 m either side, a pair every 5 m, the eye 1.6 m up, a 40 m draw distance and density 0.10. The demo's foggy ground is left out.

local FOG = {0.62, 0.64, 0.66}  -- fog colour, also the background colour
local drawDistance = 40         -- metres: walls further away are not drawn
local density = 0.10            -- fog thickness per metre
local CAM_H, NEAR, WALK, STREET = 1.6, 0.5, 4, 240
local camZ = 0
local walls = {}

function love.load()
  love.graphics.setBackgroundColor(FOG[1], FOG[2], FOG[3])
  for i = 0, 95 do
    local x = 5
    if i % 2 == 0 then x = -5 end
    walls[#walls + 1] = { x = x, z = math.floor(i / 2) * 5, len = 3.5,
                          h = 4 + (i * 7) % 5, shade = 0.2 + (i % 3) * 0.1 }
  end
end

local function visibility(d)       -- 1 = clear, 0 = lost in the fog
  return math.exp(-density * d)
end

local function project(x, y, z)    -- a point in metres to screen pixels
  local w, h = love.graphics.getDimensions()
  local f = w * 0.55
  return w / 2 + x / z * f, h * 0.42 + (CAM_H - y) / z * f
end

function love.update(dt)
  camZ = (camZ + WALK * dt) % STREET  -- the street repeats every 240 m
end

function love.draw()
  local list = {}
  for i = 1, #walls do
    local d = walls[i].z - camZ
    if d < -6 then d = d + STREET end   -- walls passed come round again
    if d < drawDistance and d + walls[i].len > NEAR then
      list[#list + 1] = { wall = walls[i], d = d }
    end
  end
  table.sort(list, function(a, b) return a.d > b.d end)  -- far walls first

  for _, item in ipairs(list) do
    local wall, d = item.wall, item.d
    local z0, z1 = math.max(d, NEAR), d + wall.len
    local ax, ay = project(wall.x, 0, z0)
    local _, by = project(wall.x, wall.h, z0)
    local cx, cy = project(wall.x, wall.h, z1)
    local _, dy = project(wall.x, 0, z1)
    local v = visibility(math.max(d, 0))
    local r = FOG[1] + (wall.shade - FOG[1]) * v
    local g = FOG[2] + (wall.shade - FOG[2]) * v
    local b = FOG[3] + (wall.shade - FOG[3]) * v
    love.graphics.setColor(r, g, b)
    love.graphics.polygon("fill", ax, ay, ax, by, cx, cy, cx, dy)
  end
end

The highlighted if is the draw distance, and it is what saves the time. The fog only hides where it starts to say no: set density to 0 and walls pop in at 40 m.

Pitfalls

  • A background that is not the fog colour. If the sky differs from the fog colour, faded objects show up as shapes against it and the edge of the world shows as a line.
  • Fog too thin for the draw distance. Exponential fog never reaches zero. Check the visibility at the draw distance, not just how the scene looks up close. Linear fog, which reaches full strength at a chosen end distance, makes the guarantee exact if you set that end at or before the draw distance.
  • Changing one setting without the other. Lowering the draw distance without thickening the fog brings pop-in back. Raising it without thinning the fog spends time on objects nobody can see.
  • Fog per vertex on large polygons. Older hardware worked out fog at each polygon's corners and blended across it, so a long wall fades in a straight line instead of the true curve. Splitting big polygons hides this.

In real games

Silent Hill is the best known case. Turok: Dinosaur Hunter (1997) on the Nintendo 64 is another game famous for thick distance fog. On the PlayStation, the geometry coprocessor (the GTE) has depth cueing instructions that blend a colour towards a programmer-chosen "far colour" by an amount set from depth, which is one way games of the time produced fog. I could not confirm exactly how Silent Hill built its fog layers, so this page rebuilds the general technique rather than the game's own code.

Modern engines all offer distance fog: Unity has linear, exponential and squared exponential fog in its render settings, Godot's Environment resource has a fog section, and Unreal has Exponential Height Fog. On phones and in browser games, a short draw distance hidden by haze is still a cheap way to keep a large outdoor scene at a steady frame rate.

Takeaways

  • A draw distance saves time by skipping far objects, but objects then pop into view.
  • Distance fog blends objects towards a fog colour with distance; if they are nearly pure fog when they cross the draw distance, the pop cannot be seen.
  • For exponential fog, a density of about 3.9 divided by the draw distance leaves under 2% at the edge.
  • The background must be the fog colour, and fog and draw distance must change together.
