PlayStation: why the textures warp and the polygons wobble

The original PlayStation mapped textures without perspective and drew vertices at whole pixels. See both shortcuts, and how subdividing hid the warp.

Watch the floor in almost any original PlayStation game as you walk. Straight lines in the texture bend as the camera turns, and a crease runs across big flat surfaces. Nudge the stick and the edges of walls twitch by a pixel at a time. Both effects come from two shortcuts in the console itself.

The constraint: 3D in 1994, with integer maths

The PlayStation went on sale in Japan in December 1994. Its main processor, a MIPS R3000A running at about 33.9 MHz, had no floating-point unit. Next to it sat the GTE (Geometry Transformation Engine), a coprocessor that rotates and projects vertices using fixed-point numbers: whole numbers in which some bits stand for a fraction, so precision is limited.

The graphics chip, the GPU, is then given 2D screen positions. It fills textured, shaded triangles and four-sided polygons, but it never receives the depth of a vertex, and it has no depth buffer; games sort their polygons back to front themselves. That cheap design leads directly to both effects.

Shortcut one: affine texture mapping

Each vertex carries a texture coordinate, written u and v: the spot in the texture image it should show. For the pixels in between, the GPU blends those coordinates in a straight line across the screen. This is affine texture mapping.

But equal steps on screen are not equal steps in the world. A receding floor squeezes its far half into a few rows near the horizon, so its middle pixel on screen shows a point much nearer than the middle of the floor.

The correct method, perspective-correct mapping, blends u divided by depth and 1 divided by depth across the screen, then divides one by the other at every pixel. For a floor edge from depth 2 to depth 8 with u running from 0 to 64, the pixel halfway along the edge on screen should show u = 12.8. Affine mapping shows u = 32. That one division per pixel is exactly the work the PlayStation GPU does not do.

Affine mapping is still exact at the three corners of a triangle. A four-sided polygon is drawn as two triangles, each bending the texture its own way, so straight lines break where they meet along the diagonal: the crease across PlayStation floors.

Shortcut two: vertices at whole pixels

The GPU takes vertex positions as whole pixel coordinates. There is no sub-pixel precision, no record that a vertex sits a third of the way between two pixels. Each projected vertex is snapped to a grid point before drawing.

On a still image this costs little. In motion it is the wobble: as the camera glides, each vertex holds still and then jumps a whole pixel, and neighbours jump at different moments, so triangles stretch and the texture inside them shimmers. The GTE's limited fixed-point precision adds error before the snap.

The causes are separate: correcting perspective would not stop the wobble, and sub-pixel precision would not straighten the textures.

The trick: more, smaller polygons

Developers could not add the missing division, but they could shrink the error. It grows with a polygon's size on screen and with how much its depth changes across it, so cutting a large polygon into a grid of smaller ones adds vertices where the texture is exact. Every extra triangle cost GTE and GPU time, so the usual compromise was to subdivide only large polygons near the camera.

The lesson for today

Modern GPUs correct perspective for you; GLSL even has a noperspective keyword to switch it off, which retro-styled games use on purpose. The idea that survives is that precision is a budget. Large open worlds get the same wobble when 32-bit floats run short of fraction far from the origin, and the fix is the same thinking: keep numbers small where precision matters, and spend detail only where the error shows.

The code

The two rules from the demo along one floor edge, in plain Lua with LÖVE printing the result. project snaps a vertex to whole pixels when snap is on. affineU is what the PlayStation does; correctU is the perspective-correct version. The last column adds one subdivision: a real vertex at depth 5, halfway along the floor.

local SCREEN_W, SCREEN_H, FOCAL = 160, 120, 100
local snap = true

local function project(x, y, z, u)               -- camera space to screen
  local sx = SCREEN_W / 2 + x * FOCAL / z
  local sy = SCREEN_H / 2 - y * FOCAL / z
  if snap then sx, sy = math.floor(sx + 0.5), math.floor(sy + 0.5) end
  return { x = sx, y = sy, u = u, invz = 1 / z }
end

local function affineU(a, b, t)                  -- straight blend on screen
  return a.u + (b.u - a.u) * t
end

local function correctU(a, b, t)                 -- blend u/z and 1/z, then divide
  local uOverZ = a.u * a.invz + (b.u * b.invz - a.u * a.invz) * t
  local invz = a.invz + (b.invz - a.invz) * t
  return uOverZ / invz
end

local near = project(-1, -1, 2, 0)
local far  = project(-1, -1, 8, 64)
local mid  = project(-1, -1, 5, 32)              -- one subdivision vertex

function love.draw()
  local tm = (mid.y - near.y) / (far.y - near.y) -- where mid sits on screen
  for i = 0, 4 do
    local t = i / 4                              -- fraction along the edge on screen
    local split
    if t <= tm then split = affineU(near, mid, t / tm)
    else split = affineU(mid, far, (t - tm) / (1 - tm)) end
    love.graphics.print(string.format("t %.2f  affine %5.1f  split %5.1f  correct %5.1f",
      t, affineU(near, far, t), split, correctU(near, far, t)), 10, 10 + i * 20)
  end
end
// Vertex shader: snap to a 320 by 240 grid and pass UVs without perspective.
#version 330 core
uniform mat4 mvp;
uniform vec2 grid;                // for example vec2(320.0, 240.0)
in vec3 position;
in vec2 uv;
noperspective out vec2 vUv;       // affine: blended in screen space
void main() {
  vec4 clip = mvp * vec4(position, 1.0);
  vec2 pixel = (clip.xy / clip.w * 0.5 + 0.5) * grid;
  pixel = floor(pixel + 0.5);     // whole pixels, like the PlayStation
  clip.xy = (pixel / grid * 2.0 - 1.0) * clip.w;
  vUv = uv;
  gl_Position = clip;
}

// Fragment shader
#version 330 core
uniform sampler2D tex;
noperspective in vec2 vUv;
out vec4 color;
void main() { color = texture(tex, vUv); }

At t 0.5 the three columns read 32, about 20 and 12.8: one subdivision already removes more than half of the error. The exact middle figure moves a little with snap, because snapping shifts where mid lands on screen.

Pitfalls

  • Blaming one cause for both effects. Bending comes from affine mapping, jitter from snapping and precision. Treat them separately.
  • Subdividing everything. Small or distant polygons barely warp. Subdivide by size on screen and by depth change across the polygon.
  • Snapping to the real screen resolution. At 1920 by 1080 a one-pixel snap is invisible. A retro look snaps to a coarse grid such as 320 by 240, as in the GLSL tab.
  • Snapping each triangle separately. Snap shared vertices once. If two triangles round the same corner differently, cracks open between them.
  • Forgetting the diagonal. Under affine mapping, which way a quad is split changes how the texture bends. Choose it on purpose.

In real games

Every 3D game on the original PlayStation had to work within these rules, which is why the look is so recognisable. PC software renderers faced the same divide cost and chose differently: Michael Abrash has described how Quake did the exact divide only every 16 pixels and blended linearly in between. Some emulators, DuckStation among them, offer an option called PGXP that keeps the precision the hardware threw away, removing most of the wobble. Modern games with a deliberate PlayStation style recreate both effects in shaders like the GLSL tab.

Takeaways

  • The PlayStation GPU received only 2D vertex positions, with no depth, so it blended texture coordinates in a straight line across the screen: affine mapping.
  • Affine mapping is exact at the corners and wrong in between, most of all on big polygons that recede from the camera.
  • Vertices were drawn at whole pixels, so smooth motion became one-pixel jumps: the wobble.
  • Subdividing large near polygons hid the warp, at the cost of more triangles.
  • Precision is a budget. Modern hardware moved the limits, but large worlds and retro shaders meet the same trade.
