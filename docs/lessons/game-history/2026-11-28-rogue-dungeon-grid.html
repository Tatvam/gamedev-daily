Rogue: a new dungeon from a three by three grid

How Rogue built a fresh dungeon floor every game from nine grid cells, a random tree of corridors and a few extra loops, and how to build one yourself.

Play a game with hand-built levels a few times and you learn them by heart: the trap is behind the second door, the key is in the far corner. Rogue, a dungeon game for Unix computers from around 1980, never let you learn the map, because it drew a new one every time you went down the stairs. The way it did this is short enough to rebuild in an afternoon, and it never makes a floor you cannot finish.

The constraint: a text screen and a wish to be surprised

Rogue was written by Michael Toy and Glenn Wichman, and Ken Arnold joined them later; the copyright line in the 1981 source names all three. It ran on terminals that showed text only. In version 5.4 the map is fixed at 80 columns by 24 rows, the size of a common terminal. Walls were - and |, floors were dots, corridors were # and the player was @.

A goal often attributed to the authors is a game that would surprise even the people who wrote it. Hand-made levels cannot do that, so Rogue makes each level from a seed: a starting number for a random number generator, which then produces the same sequence of numbers every time. In the version 5.4 source the seed is the clock time plus the program's process number, so each game is different.

Random is easy. Random and always playable is the hard part. Rooms must not overlap, they must fit on the screen, and every room must be reachable. Rogue gets all three from one simple structure.

The trick, step by step

The descriptions below come from the game's source code, which is public. Version 3.6 (1981) and version 5.4 build levels the same way, apart from small details.

1. Cut the screen into nine cells. The map is split into a three by three grid. On an 80 by 24 screen each cell is 26 columns by 8 rows. Each cell can hold at most one room, and each room stays inside its cell, so two rooms can never overlap. That one rule replaces all the collision checks a free placement would need.

2. Leave a few cells empty. The game picks zero to three cells to be gone rooms. A gone room has no walls or floor. It is a single point where corridors meet, so floors look less like a neat noughts-and-crosses board.

3. Size and place each room. Every other cell gets a room of random width and height, at a random spot inside the cell. Rooms deeper in the dungeon are more often dark.

4. Link the rooms with a tree. Each room may only connect to the cells directly beside it, above it or below it, never diagonally. This list of allowed links is fixed in the code. The builder starts in a random room and keeps adding a corridor to a random neighbour that is not linked yet. When the current room has no unlinked neighbours, it jumps to a random room that is already linked and carries on. It stops when all nine are in.

The result is a spanning tree: a set of links that reaches every room with no loops. Nine rooms need exactly eight corridors. Because every new corridor reaches a room that was not linked before, the whole floor is always connected. That is the guarantee.

5. Add a few loops. A tree has exactly one route between any two rooms, which makes running from a monster dull. So the builder tries a random number of extra corridors, zero to four, each between neighbours that are not linked yet. Some tries find nothing and are skipped.

6. Dig the corridors. A corridor starts at a door on the wall facing the neighbour, runs straight, makes one sideways jog at a random point, and runs straight to the door on the other room.

After that the game drops in the stairs, the player, gold and monsters, each on a random floor tile.

Rule of thumb

Build the guarantee first, then add the variety. Here the tree makes the floor playable and the extra links make it interesting. Random choices never get the chance to break the first part.

The code

The same builder in Lua for LÖVE, with the demo's names and numbers. Rooms are numbered 1 to 9, left to right and top to bottom, and NEIGHBOURS is the fixed list of allowed links. Press space to try the next seed.

-- A Rogue-style floor: 3 by 3 cells, a tree of corridors, a few extra loops
local COLS, ROWS, CW, CH = 78, 24, 26, 8
local NEIGHBOURS = { {2,4}, {1,3,5}, {2,6}, {1,5,7}, {2,4,6,8}, {3,5,9}, {4,8}, {5,7,9}, {6,8} }
local map, rooms, rng
local seed = 42

local function rand(a, b) return rng:random(a, b) end
local function put(x, y, ch) map[y + 1][x + 1] = ch end  -- x, y start at 0

local function placeRoom(i, gone)
  local cx, cy = ((i - 1) % 3) * CW, math.floor((i - 1) / 3) * CH
  if gone then                                       -- just a junction point
    local r = { gone = true, x = rand(cx + 3, cx + CW - 4), y = rand(cy + 2, cy + CH - 3) }
    put(r.x, r.y, "#")
    return r
  end
  local w, h = rand(5, 22), rand(4, 6)               -- size includes the walls
  local r = { x = rand(cx + 1, cx + CW - 1 - w), y = rand(cy + 1, cy + CH - 1 - h), w = w, h = h }
  for y = r.y, r.y + h - 1 do
    for x = r.x, r.x + w - 1 do
      local ch = "."
      if y == r.y or y == r.y + h - 1 then ch = "-"
      elseif x == r.x or x == r.x + w - 1 then ch = "|" end
      put(x, y, ch)
    end
  end
  return r
end

local function doorSpot(r, side)                     -- a spot on the facing wall
  if r.gone then return r.x, r.y end
  if side == "right" then return r.x + r.w - 1, rand(r.y + 1, r.y + r.h - 2) end
  if side == "left" then return r.x, rand(r.y + 1, r.y + r.h - 2) end
  if side == "down" then return rand(r.x + 1, r.x + r.w - 2), r.y + r.h - 1 end
  return rand(r.x + 1, r.x + r.w - 2), r.y           -- "up"
end

local function dig(a, b)
  if a > b then a, b = b, a end                      -- b is right of a, or below it
  local A, B, across = rooms[a], rooms[b], (b - a == 1)
  local sx, sy = doorSpot(A, across and "right" or "down")
  local ex, ey = doorSpot(B, across and "left" or "up")
  put(sx, sy, A.gone and "#" or "+")
  put(ex, ey, B.gone and "#" or "+")
  if across then
    local turn = rand(sx + 1, ex - 1)                -- the one sideways jog
    for x = sx + 1, ex - 1 do
      if x == turn then
        for y = math.min(sy, ey), math.max(sy, ey) do put(x, y, "#") end
      else
        put(x, x < turn and sy or ey, "#")
      end
    end
  else
    local turn = rand(sy + 1, ey - 1)
    for y = sy + 1, ey - 1 do
      if y == turn then
        for x = math.min(sx, ex), math.max(sx, ex) do put(x, y, "#") end
      else
        put(y < turn and sx or ex, y, "#")
      end
    end
  end
end

local function freeNeighbours(i, taken)
  local free = {}
  for _, n in ipairs(NEIGHBOURS[i]) do
    if not taken[n] then free[#free + 1] = n end
  end
  return free
end

local function generate()
  rng = love.math.newRandomGenerator(seed)
  map, rooms = {}, {}
  for y = 1, ROWS do
    map[y] = {}
    for x = 1, COLS do map[y][x] = " " end
  end
  local gone, count, goneCount = {}, 0, rand(0, 3)   -- step 2: empty cells
  while count < goneCount do
    local i = rand(1, 9)
    if not gone[i] then gone[i] = true; count = count + 1 end
  end
  for i = 1, 9 do rooms[i] = placeRoom(i, gone[i]) end

  local inGraph, linked = {}, {}                     -- step 4: the spanning tree
  for i = 1, 9 do linked[i] = {} end
  local function link(a, b) linked[a][b] = true; linked[b][a] = true; dig(a, b) end
  local cur, joined = rand(1, 9), 1
  inGraph[cur] = true
  while joined < 9 do
    local free = freeNeighbours(cur, inGraph)
    if #free == 0 then
      repeat cur = rand(1, 9) until inGraph[cur]     -- jump to a linked room
    else
      local n = free[rand(1, #free)]
      inGraph[n] = true; joined = joined + 1; link(cur, n)
    end
  end

  for _ = 1, rand(0, 4) do                           -- step 5: extra loops
    local a = rand(1, 9)
    local free = freeNeighbours(a, linked[a])
    if #free > 0 then link(a, free[rand(1, #free)]) end
  end
end

function love.load() generate() end

function love.keypressed(key)
  if key == "space" then seed = seed + 1; generate() end
end

function love.draw()
  for y = 1, ROWS do
    for x = 1, COLS do
      love.graphics.print(map[y][x], 10 + (x - 1) * 10, 10 + (y - 1) * 16)
    end
  end
  love.graphics.print("seed " .. seed .. "  (space for the next one)", 10, 410)
end

The gaps between cells are wide enough that a corridor always has at least one square to jog in: a room's right wall is at most column 24 of its cell, and the next room starts at column 27 or later. Each character is drawn on its own at a fixed spacing, because LÖVE's default font is not monospaced.

Pitfalls

  • Linking rooms at random. Joining random pairs of rooms can leave a group of rooms cut off from the rest. Grow a tree, where each new link must reach a room outside the tree, and connectivity is guaranteed.
  • Stopping at the tree. A pure tree has many dead ends and one route between any two rooms. A few extra links make chases and escapes possible.
  • Rooms that touch the cell edge. If a room can fill its whole cell, the corridor to its neighbour may have no room to turn, or no room at all. Keep a margin, as the demo does.
  • Unseeded randomness. If you cannot replay a level from its seed, you cannot reproduce the bug a player reports on it. Print the seed somewhere in debug builds. The 5.4 source lets a debug build take a fixed seed.
  • A loop that can run forever. "Pick a random room until it is linked" ends only because at least one room is linked. Write down why every repeat loop in a generator must finish.

In real games

Rogue was shared widely on university Unix systems and gave its name to a genre: roguelikes, games with generated levels, turn-based moves and permanent death. Hack was inspired by it, and NetHack grew out of Hack. The source shows that Rogue kept the same grid for its whole life and layered depth on top: dark rooms grow more common as you descend, version 5.4 adds rare maze rooms, and deeper corridors sometimes hide squares that the player has to search for.

The grid of room slots returns later in this track. Spelunky lays out each level as a four by four grid of rooms and picks a guaranteed path through it before filling in the rest.

The lesson for today: when content has to be both random and correct, split the problem. Give each piece a slot so pieces cannot collide, build a structure that guarantees the rule you care about, and only then add randomness on top. The same pattern makes daily-challenge seeds shareable in modern games, keeps generated quest chains completable and makes procedural levels testable: run ten thousand seeds and check that every floor is connected.

Your turn (15 minutes)

Run the Lua code and add a check. After generate(), start a flood fill from the first floor tile you find and spread through every non-space character. Count the floor dots it reaches and compare with all the floor dots on the map. Then loop over seeds 1 to 1000 and print any seed where the two counts differ. You are done when the loop prints nothing. For a bonus, remove the tree step, link random pairs instead, and watch the bad seeds appear.

Takeaways

  • Rogue builds each floor from a three by three grid of cells with at most one room per cell, so rooms never overlap.
  • Zero to three cells become gone rooms: a single junction point instead of a room.
  • Corridors first form a spanning tree over the nine cells, which guarantees every room can be reached.
  • Zero to four extra corridor tries then add loops, and each corridor makes one random sideways jog.
  • A seed makes the whole floor repeatable. Build the guarantee first, then add the randomness.
