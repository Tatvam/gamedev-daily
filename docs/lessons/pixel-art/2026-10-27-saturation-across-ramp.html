Saturation across a ramp: strongest in the middle

Why a ramp's saturation usually peaks in the mid-tones and falls at the light and dark ends, and what goes wrong when it stays flat.

Your orange fruit has even value steps and a clean light direction, but its highlight looks like a lit bulb and its shadow looks like spilled ink. The values are right. Every step of the ramp has the same saturation, and the ends of a ramp usually cannot carry that much colour.

Saturation is the ramp's third dial

Saturation is how far a colour is from grey: 0% is grey, 100% is the purest version of that hue. So far we have built ramps by stepping value and turning hue, and left saturation at one number for every step. That is a flat saturation ramp.

The usual convention is different: saturation is highest in the mid-tones, the base colour and the steps next to it, and it falls towards both ends. It usually falls clearly at the light end and a little at the dark end.

Why the ends lose colour

  • Highlights take the colour of the light. The brightest spot on a surface is mostly light bouncing straight off it, called a specular highlight. That light keeps the colour of the light source, which is often close to white, not the colour of the material. So the top step of a ramp drifts towards white, and that means less saturation.
  • Shadows get mixed light. A shadow gets no direct light. It is lit by light bounced from everything around it, and that mix tends to be greyer. A strongly saturated dark also pulls the eye: it reads as stained glass or ink rather than shade.
  • The screen cannot show bright, pure colours for most hues. Measured as grey (the same weighted average of red, green and blue the earlier lessons used), the brightest fully saturated blue reaches only 29 out of 255. Pure red reaches 76, pure yellow 226. If a light step needs to sit at grey 153, an orange or a blue simply cannot stay fully saturated there.

The light end is partly forced on you; the dark end is a taste decision. Some artists keep rich, saturated darks, and that can work, as long as it is a choice. Lowering it a little is the safe start.

What breaks when you ignore it

With flat, high saturation, the lightest step reads as a light source: the sprite seems to glow. That is exactly what you want for lava, magic and neon signs, so the convention is broken on purpose there. On an ordinary object, it looks like plastic under a lamp. With flat, low saturation, the opposite happens: the whole ramp looks muddy, because no step is strong enough to name the colour.

Saturation moves the grey

Changing saturation in HSV also changes how light a colour looks. Lower the saturation of the top step from 70% to 35% at the same HSV value, and its grey rises from 153 to 195. Raise the saturation and the grey falls. So after you bend the saturation, check the value ladder again in greyscale, exactly as with hue shifting.

Rule of thumb

Give the base step the strongest saturation. Keep the steps beside it close to the base. Take the darkest step down to about three quarters of the base and the lightest to about half. Then check the greys.

The code

A ramp with a saturation curve is still five colours. This LÖVE program builds the flat ramp and the curved ramp with the demo's starting numbers and draws the fruit at 8x. Press space to swap between them. Each curved step gets the same grey as the flat step, as with Keep greys equal turned on.

local HUE = 20                                      -- orange, in degrees
local VALUES = { 0.37, 0.51, 0.65, 0.79, 0.93 }     -- value ladder, dark to light
local SAT_CURVE = { 0.50, 0.65, 0.70, 0.55, 0.35 }  -- peaks at the base, step 3
local FLAT_SAT = SAT_CURVE[3]
local ZOOM = 8
local OUTLINE = { 0.16, 0.10, 0.08 }

local FRUIT = {
  ".........o......", "........o.......", "......oooo......", "....oo4443oo....",
  "...o44444333o...", "..o4455443332o..", "..o4555443332o..", ".o444554433321o.",
  ".o444444333221o.", ".o344443333221o.", ".o333333332211o.", "..o3333322211o..",
  "..o2222222111o..", "...o22221111o...", "....oo1111oo....", "......oooo......",
}

-- h in degrees, s and v from 0 to 1. Returns r, g, b from 0 to 1.
local function hsvToRgb(h, s, v)
  local c = v * s
  local hp = (h % 360) / 60
  local x = c * (1 - math.abs(hp % 2 - 1))
  local r, g, b = 0, 0, 0
  if hp < 1 then r, g = c, x
  elseif hp < 2 then r, g = x, c
  elseif hp < 3 then g, b = c, x
  elseif hp < 4 then g, b = x, c
  elseif hp < 5 then r, b = x, c
  else r, b = c, x end
  local m = v - c
  return r + m, g + m, b + m
end

local function luma(r, g, b)
  return 0.299 * r + 0.587 * g + 0.114 * b
end

local function buildRamp(hue, sats)
  local ramp = {}
  for i = 1, #VALUES do
    -- the grey this step has in the flat ramp
    local grey = luma(hsvToRgb(hue, FLAT_SAT, VALUES[i]))
    -- new saturation, value scaled so the grey stays the same
    local v = math.min(1, grey / luma(hsvToRgb(hue, sats[i], 1)))
    ramp[i] = { hsvToRgb(hue, sats[i], v) }
  end
  return ramp
end

local flat, curved, current

function love.load()
  local flatSats = {}
  for i = 1, #VALUES do flatSats[i] = FLAT_SAT end
  flat = buildRamp(HUE, flatSats)
  curved = buildRamp(HUE, SAT_CURVE)
  current = curved
end

function love.keypressed(key)
  if key == "space" then
    if current == curved then current = flat else current = curved end
  end
end

function love.draw()
  for y, row in ipairs(FRUIT) do
    for x = 1, #row do
      local c = row:sub(x, x)
      if c ~= "." then
        if c == "o" then
          love.graphics.setColor(OUTLINE)
        else
          love.graphics.setColor(current[tonumber(c)])
        end
        love.graphics.rectangle("fill", 40 + (x - 1) * ZOOM, 40 + (y - 1) * ZOOM, ZOOM, ZOOM)
      end
    end
  end
end

The highlighted lines do the work. Value scales red, green and blue together, so the grey scales in proportion, and one division finds the value that puts the new saturation at the old grey. The math.min catches a step that cannot get bright enough at that saturation; it comes out darker, which is the screen limit from earlier.

Pitfalls

  • Pure white highlights. Taking the top step all the way to 0% makes it the colour of every other highlight in the game, so materials stop telling apart. Usually keep a little of the hue.
  • Darks dropped to grey. Too much desaturation at the dark end gives dead, dirty shadows. A little goes a long way.
  • Forgetting the greys. A saturation change is also a value change. Check the ramp in greyscale after every edit.
  • Every ramp peaking at a different strength. If the grass is at 90% and the stone at 20%, the grass wins every glance. Decide which ramps should stand out.
  • Desaturating glowing things. Fire, magic and screens are light sources. Their brightest steps often stay saturated, and that is what makes them glow.

In real games

The saturation curve is described in the pixel art guides listed below, and many palettes shared online are built from ramps that are most saturated in the middle. I will not claim from memory which game used which exact numbers.

To check for yourself, pick the darkest, middle and lightest colour of one shaded object in a screenshot and read their saturation. Often the middle one is highest. Where the lightest is highest, the object is often meant to glow.

Your turn (15 minutes)

Take a ramp from your project, or the one from the last lesson, and write down each step's saturation, value and grey. In a copy, keep the base step's saturation, lower the darkest step to about three quarters of it and the lightest to about half, and set each step between them to about halfway. Adjust each step's value until its grey matches the original.

Recolour one sprite with the new ramp and put it beside the old one at 1x. You are done when both look identical in greyscale, and the new one's highlight looks like light on a surface rather than a light source. If it looks washed out, raise the lightest step by 10%.

Takeaways

  • Saturation usually peaks in the mid-tones and falls towards both ends of a ramp.
  • Highlights drift towards the colour of the light, and shadows get greyer bounced light.
  • For most hues, a very light step cannot be fully saturated on screen anyway.
  • Saturated light steps read as glowing: avoid them on ordinary objects and use them for light sources.
  • Changing saturation changes the grey, so check the value ladder after every edit.
