Nearest neighbour scaling: keep every pixel sharp

Why pixel art must be enlarged with nearest neighbour sampling, how bilinear filtering blurs it and invents colours, and the setting that fixes it.

You finish a crisp 16 by 16 sprite, load it into your engine, draw it six times larger, and it comes out soft and smudged. The black outline has turned into a grey haze, the one-pixel eyes are blurry dots, and the colour picker finds dozens of colours you never chose.

Your art is fine. The engine enlarged it with the wrong rule. This lesson shows what that rule is and how to switch it.

Enlarging means choosing colours for new pixels

When a 16 pixel sprite is drawn six times larger, it covers 96 screen pixels across instead of 16. The screen has to decide a colour for each of those 96 pixels, and only 16 of them can come straight from the art. The rule the graphics card uses to make that decision is called the texture filter (engines also call it the filter mode or sampling mode).

For every screen pixel, the card works out which point of the original image lies under it. That point usually falls somewhere between the centres of the art pixels. There are two common ways to turn it into a colour.

  • Nearest neighbour: take the one art pixel that the point falls inside, and copy its colour unchanged.
  • Bilinear filtering: take the four art pixel centres around the point and blend their colours, giving more weight to the closer ones. It is called bilinear because it blends in a straight line along x, then again along y.

The diagram shows one row of four art pixels, dark, light, dark, light, enlarged four times with each rule.

Why smooth is the default

Most engines filter with bilinear unless you tell them otherwise. For photos, painted backgrounds and 3D textures that is the right choice: when a low-resolution texture is stretched across a wall, smooth blending hides the blocks and looks closer to the real thing.

Pixel art is the opposite case. The blocks are the art. Every pixel was placed on purpose, and the hard edge between two pixels is part of the design. Bilinear filtering does three kinds of damage:

  • Edges turn soft. Every border between two colours becomes a ramp about one art pixel wide, at any zoom.
  • New colours appear. A dark outline next to a red cap produces a row of muddy dark reds. The 8 colour sprite in the demo below shows 865 different colours at 6×.
  • Small details dissolve. A one-pixel eye or highlight has nothing of its own colour around it, so it gets blended with its neighbours from all four sides and fades.

Nearest neighbour adds nothing

Nearest neighbour only copies. Enlarged by any amount, the sprite shows exactly the colours in its palette and the same shapes you drew, just bigger. That is why it is the usual choice for pixel art.

Rule of thumb

For pixel art, set the filter to nearest for every texture and every off-screen canvas that holds pixel art, for both enlarging and shrinking. Use smooth filtering only on purpose, for example on a painted background or a soft glow that is not pixel art.

The code

In practice you never write the filter yourself. You tell the engine which one to use. LÖVE filters with "linear" by default, so one line at the start of the game switches everything to nearest:

local ZOOM = 6
local mushroom

function love.load()
  -- Sets the filter for every image and canvas created after this line.
  -- The two arguments are the filter for shrinking and for enlarging.
  love.graphics.setDefaultFilter("nearest", "nearest")
  mushroom = love.graphics.newImage("mushroom.png")

  -- Or for a single image that was already loaded:
  -- mushroom:setFilter("nearest", "nearest")
end

function love.draw()
  -- Whole-number position and scale: each art pixel becomes a ZOOM by ZOOM block.
  love.graphics.draw(mushroom, 40, 40, 0, ZOOM, ZOOM)
end
# Godot 4. For the whole project:
# Project Settings > Rendering > Textures > Canvas Textures >
# Default Texture Filter = Nearest

# Or for one node and the children that inherit from it:
func _ready() -> void:
    texture_filter = CanvasItem.TEXTURE_FILTER_NEAREST
    scale = Vector2(6, 6)
// Unity. Usually set in the texture's Import Settings:
// Filter Mode = Point (no filter), Compression = None.
// The same filter setting from code:
void Start()
{
    Texture2D tex = GetComponent<SpriteRenderer>().sprite.texture;
    tex.filterMode = FilterMode.Point;
}

Here are the two rules written out in plain Lua, so you can see exactly what the graphics card does for each screen pixel. The demo above runs the same functions with the same palette. Screen and art pixels are counted from 0 here, and pixel adds 1 when it reads the Lua tables.

local ZOOM = 6
local SPRITE = { "................", ".....oooooo.....", --[[ 14 more rows ]] }
local PALETTE = { ["."] = {169, 207, 224}, o = {42, 31, 51}, r = {204, 63, 63} } -- and 5 more

-- Read one art pixel. Points past the edge use the nearest edge pixel.
local function pixel(x, y)
  x = math.max(0, math.min(15, x))
  y = math.max(0, math.min(15, y))
  return PALETTE[SPRITE[y + 1]:sub(x + 1, x + 1)]
end

-- Screen pixel (sx, sy) covers the point ((sx + 0.5) / ZOOM, (sy + 0.5) / ZOOM) of the art.
local function sampleNearest(sx, sy)
  return pixel(math.floor((sx + 0.5) / ZOOM), math.floor((sy + 0.5) / ZOOM))
end

local function sampleBilinear(sx, sy)
  local u = (sx + 0.5) / ZOOM - 0.5     -- measured from pixel centres
  local v = (sy + 0.5) / ZOOM - 0.5
  local x0, y0 = math.floor(u), math.floor(v)
  local fx, fy = u - x0, v - y0         -- 0 at one centre, 1 at the next
  local a, b = pixel(x0, y0), pixel(x0 + 1, y0)
  local c, d = pixel(x0, y0 + 1), pixel(x0 + 1, y0 + 1)
  local out = {}
  for i = 1, 3 do                       -- red, green, blue
    local top = a[i] + (b[i] - a[i]) * fx
    local bottom = c[i] + (d[i] - c[i]) * fx
    out[i] = math.floor(top + (bottom - top) * fy + 0.5)   -- often a brand new colour
  end
  return out
end

Pitfalls

  • Setting the filter too late. In LÖVE, setDefaultFilter only affects images and canvases created after it runs. Call it at the top of love.load, before loading anything.
  • Fixing the sprites but not the screen. Many pixel art games draw the level into a small canvas and then enlarge that canvas to the window. If the canvas still uses linear filtering, the whole picture blurs at the last step even though every sprite is set to nearest.
  • Shrinking pixel art. Nearest neighbour is clean when enlarging, but when shrinking it skips whole rows and columns of pixels, so outlines and eyes can vanish. Mipmaps, the pre-shrunk copies engines make for distant 3D textures, blend pixels instead. For 2D pixel art both are usually a sign the art is the wrong size: draw a smaller version instead.
  • Zooming by fractions. With nearest neighbour at 2.5×, some art pixels become 2 screen pixels wide and some 3. The edges stay sharp but the pixels are uneven. That is the subject of the next lesson.
  • Blur from somewhere else. Lossy texture compression and JPEG files also invent colours. Save pixel art as PNG and turn texture compression off for it. If you show pixel art on a web page, the CSS property image-rendering: pixelated asks the browser for nearest neighbour scaling.

In real games

Smooth filtering is the out-of-the-box setting in the three engines used in these lessons: LÖVE images use "linear", Godot 4 canvas textures use Linear, and Unity imports textures with Bilinear. Pixel art games made with them switch to nearest, usually once for the whole project.

Emulators for old consoles and many modern pixel art games let the player choose between a sharp and a smooth look in their video options. Some offer a middle ground: enlarge with nearest neighbour to a whole multiple first, then smooth only the small remaining step, which hides uneven pixels without blurring the whole picture.

Your turn (15 minutes)

Take any small sprite of yours, or draw a 16 by 16 one with a dark outline and one-pixel eyes. Draw it in your engine at 6× with the default settings and take a screenshot. Switch the filter to nearest, as shown above, and take a second screenshot.

Open both screenshots in your pixel editor and use the colour picker along the outline. You are done when, in the second screenshot, every colour you pick is one from your own palette and each art pixel is a solid 6 by 6 block with hard edges.

Takeaways

  • When an image is enlarged, the texture filter decides the colour of every new screen pixel.
  • Nearest neighbour copies the art pixel under each point, so shapes stay sharp and only your palette colours appear.
  • Bilinear blends the four nearest pixel centres, which softens every edge and invents colours you never chose.
  • Most engines default to smooth filtering. Switch pixel art, and any canvas it is drawn into, to nearest early in the project.
