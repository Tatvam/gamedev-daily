Building a colour ramp: even steps from dark to light

How to build an ordered ramp of shades around a base colour, how many steps to use, and why even value steps shade a form cleanly.

You shade a ball by picking each colour as you go: a bit darker for the shadow, a bit darker again for the deep shadow, then something bright for the highlight. Zoomed in it looks fine. At real size the two shadows melt into one patch and the highlight looks pasted on. You did not run out of colours; you spent them unevenly.

A ramp is a ladder of values

A colour ramp is an ordered list of colours for one material, running from dark to light. Each colour in it is a step. Once a material has a ramp, shading stops being "pick a new colour" and becomes "go one step down" or "go one step up". Every object of that material reuses the same ladder.

The last lesson showed that value carries the form. A ramp is where you decide the values once, on purpose.

Four decisions

  1. The base colour. The base is the colour the material has in plain light, the one you would use to fill its flat shape. It usually sits in the middle of the ramp, with shadows below it and lights above.
  2. The number of steps. For small sprites, three to five steps per material is the usual range. Every step needs room to show as a band; a 16 pixel ball has space for about four. Extra steps end up as thin slivers that read as noise.
  3. The step size. How far each step moves in value. Big steps look punchy, small steps soft. Too small and neighbours merge at 1x.
  4. Even spacing. Keep the value jump between every pair of neighbours about the same. This is the decision beginners usually skip.

Why even steps

On a shaded form, each boundary between two bands is an edge the eye notices. When the steps are even, every edge has the same strength, so the eye reads one smooth turn of the surface. When they are uneven, two things break at once:

  • A small jump vanishes. Two steps that are only a few grey levels apart look like one colour at 1x. You paid for a colour and got nothing.
  • A big jump looks like a corner. A sudden leap in value reads as a crease or a sharp edge in the form, because that is what a sharp change in lighting means in the real world. A round ball starts to look faceted or pasted together.

The hook's ball is a typical case. With the darkest at 37% value and the lightest at 93%, the bunched ladder in the demo below has neighbours only about 5 grey apart at the dark end and 44 apart at the top. The even ladder in the diagram spends the same range with every neighbour 24 apart.

Building one in HSV

HSV from two lessons ago makes a first ramp easy. Keep hue and saturation fixed, put the base value in the middle, and add or subtract the same amount of value for each step:

value of step i = base value + (i - base index) * step size

With hue and saturation fixed, red, green and blue all scale together with value, so the grey value (luma) scales with it too. Even steps in V are then even steps in grey, which is exactly what you want. This only holds while hue and saturation stay fixed.

A ramp built like this is called a straight ramp. It is a good start, not usually the end: straight ramps often look flat or muddy in the shadows, and the next two lessons bend them with hue and saturation. The even value ladder stays underneath both.

Rule of thumb

Usually keep the darkest step above pure black and the lightest below pure white. Black is often kept for outlines and white for small specular glints, and a ramp that already uses both has nowhere left to go. When a step hits 0% or 100% value it is clipped, and clipped steps pile up into duplicates.

Try it

Both balls use the same hue, saturation, darkest and lightest colour, and the same bands. Only the spacing between the steps differs: on the left the steps bunch in the shadows, on the right they are even. Check the 1x previews first, then try:

  • Raise Steps to 7 and lower Step size to 4. Neighbours turn red on the right too: too many steps, too close.
  • Push Base value to 90. The light steps clip at 100% and merge.
  • Move Hue to 240 and Saturation to 100. The same step size now gives gaps of about 4 grey, because pure blue is far darker than it looks.

The code

In a game, a ramp is just a list of colours, and shading picks an index into it. This LÖVE program builds the demo's even ramp with the demo's numbers and shades the same 24 by 24 ball, once, into a small canvas that is then drawn at 8x with nearest neighbour filtering.

-- h in degrees, s and v from 0 to 1. Returns r, g, b from 0 to 1.
local function hsvToRgb(h, s, v)
  local c = v * s
  local hp = (h % 360) / 60
  local x = c * (1 - math.abs(hp % 2 - 1))
  local r, g, b = 0, 0, 0
  if hp < 1 then r, g = c, x
  elseif hp < 2 then r, g = x, c
  elseif hp < 3 then g, b = c, x
  elseif hp < 4 then g, b = x, c
  elseif hp < 5 then r, b = x, c
  else r, b = c, x end
  local m = v - c
  return r + m, g + m, b + m
end

-- A straight ramp: same hue and saturation, value in even steps.
local function buildRamp(hue, sat, baseValue, steps, stepSize)
  local ramp = {}
  local baseIndex = math.floor(steps / 2) + 1     -- base sits in the middle
  for i = 1, steps do
    local v = baseValue + (i - baseIndex) * stepSize
    v = math.max(0, math.min(1, v))              -- clipped steps become duplicates
    ramp[i] = { hsvToRgb(hue, sat, v) }
  end
  return ramp
end

local SIZE, RADIUS = 24, 11.6
local LX, LY, LZ = -1, -1, 1.2                   -- light from the top left, towards us
local len = math.sqrt(LX * LX + LY * LY + LZ * LZ)
LX, LY, LZ = LX / len, LY / len, LZ / len
local DMIN = -math.sqrt(LX * LX + LY * LY)       -- darkest point on the visible rim

-- Which step of the ramp a pixel of the ball uses, or nil outside the ball.
local function shadeIndex(x, y, steps)
  local nx = (x + 0.5 - SIZE / 2) / RADIUS
  local ny = (y + 0.5 - SIZE / 2) / RADIUS
  local d2 = nx * nx + ny * ny
  if d2 > 1 then return nil end
  local d = nx * LX + ny * LY + math.sqrt(1 - d2) * LZ
  local t = ((d - DMIN) / (1 - DMIN)) ^ 2           -- 0 on the dark rim, 1 facing the light
  return math.max(1, math.min(steps, math.floor(t * steps) + 1))
end

local ball

function love.load()
  local ramp = buildRamp(15, 0.6, 0.65, 5, 0.14)  -- the demo's starting values
  ball = love.graphics.newCanvas(SIZE, SIZE)
  ball:setFilter("nearest", "nearest")
  love.graphics.setCanvas(ball)
  for y = 0, SIZE - 1 do
    for x = 0, SIZE - 1 do
      local i = shadeIndex(x, y, #ramp)
      if i then
        love.graphics.setColor(ramp[i])
        love.graphics.rectangle("fill", x, y, 1, 1)
      end
    end
  end
  love.graphics.setCanvas()
  love.graphics.setColor(1, 1, 1)
end

function love.draw()
  love.graphics.draw(ball, 40, 40, 0, 8, 8)       -- whole-number zoom only
end

Because the ball stores step numbers, not colours, a different ramp recolours it without touching the shape. The squared t only makes the bands roughly equal in area so that each step gets a fair amount of the ball; it is a demo choice, not a rule of shading.

Pitfalls

  • Judging the ramp as a row of swatches. Large flat swatches make small differences look clear; on a sprite at 1x the same pair can merge. Always test the ramp on a shaded shape at real size.
  • More steps than pixels. Seven steps on a 12 pixel object leave bands one or two pixels wide, which read as speckle, not smoothness. When in doubt, drop a step and widen the gap.
  • Even in V is not even in grey once hue changes. The neat link between value and grey only holds while hue and saturation are fixed. Once you shift hue along a ramp in the next lesson, check the grey values again.
  • A private ramp for every object. The palette grows fast and the game loses its unity. A ramp is meant to be shared by everything made of that material.

In real games

On the NES, each sprite could use a palette of three colours plus transparency. A character's ramp was therefore at most three steps, and artists had to choose which three values mattered most.

Many pixel editors treat ramps as a working tool. Aseprite, for example, has a shading ink mode that moves a pixel one colour along the palette each time you paint over it, which only works well when the palette is laid out as ordered ramps.

Your turn (15 minutes)

Pick one material in your game, such as a rock, a slime or a wooden crate. In your editor, choose its base colour and write down its HSV values. Build a four-step straight ramp by hand: same hue and saturation, base as step three, and the same value change between every step, for example 15%.

Shade a 16 by 16 ball with it, with light from the top left, and view it at 1x next to the same ball shaded with the colours you used before. You are done when all four bands are visible at 1x and no band boundary looks like a crease.

Takeaways

  • A colour ramp is an ordered list of shades for one material; shading means moving up or down it.
  • Decide the base, the number of steps and the step size once, and reuse the ramp everywhere.
  • Three to five steps is usually enough for small sprites. More steps need more pixels to show.
  • Keep neighbouring steps about equally far apart in value: small gaps vanish, big gaps look like edges.
  • With hue and saturation fixed, even steps in V are even steps in grey.
