Choosing a canvas size for your sprites

How picking 8, 16, 32 or 64 pixel sprites sets the game's screen resolution, how much level the player sees, and how many pixels you must draw.

You spend an evening on a detailed 64 by 64 pixel hero, drop it into your game, and it fills half the screen. The player cannot see the next platform. So you zoom the camera out, and now the hero's pixels are smaller than the pixels of the tiles around it, and it looks pasted in from another game.

The canvas size was picked on its own, when it is really half of a decision about the whole screen.

A sprite size is a screen decision

The canvas size of a sprite is the width and height of the image you draw it on, such as 16 × 16. Most pixel art games also have a game resolution (sometimes called the internal resolution): the size of the small image the game draws each frame before it is enlarged to fill the monitor. Every art pixel in the game is one pixel of that small image.

Those two numbers are tied together by one division:

tilesAcross = GAME_W / TILE    -- 320 / 16 = 20
tilesDown   = GAME_H / TILE    -- 180 / 16 = 11.25

Here TILE is the size of one tile, the square block the level is built from. A main character is usually about one tile wide and one or two tiles tall, so the tile size and the character's canvas size tend to be chosen together.

So choosing a canvas size means choosing three things at once: how much level fits on screen, how much detail each sprite carries, and how much drawing you sign up for.

What each size costs

The work grows with the area, not the width. Every animation frame is a full canvas to fill, and a character has many frames:

Going from 16 to 32 is four times the drawing, for every frame of every animation.

What each size does to the style

Small canvases push you towards iconic art: shapes are simplified, features are exaggerated, and each pixel carries a lot of meaning. Large canvases push you towards illustration: real proportions, more shades, texture. Neither is better, but anatomy and shading mistakes that hide inside 16 pixels become obvious at 64.

Why powers of two?

Sizes like 8, 16, 32 and 64 are a habit rather than a law. Older consoles built their graphics from 8 by 8 pixel tiles, and these sizes still divide common game resolutions evenly. A 24 or 48 pixel character is fine. What usually matters is that every sprite in the game shares the same pixel size.

Picking a game resolution

The game resolution should usually divide the monitor by a whole number, so every art pixel covers the same number of screen pixels. All three of these divide 1920 × 1080 and 3840 × 2160 evenly, and two of them also fit 2560 × 1440:

320 × 1806×8×12×20
480 × 2704×5.33× (not whole)8×30
640 × 3603×4×6×40

Rule of thumb

Decide how many tiles the player must see to play well, for example "at least 18 across so they can see the next jump". Pick the smallest sprite size that still shows what the player must read. Then pick a game resolution that gives you that many tiles and scales to the monitor by a whole number.

The code

In LÖVE you make the game resolution real by drawing the whole level into a small canvas of GAME_W by GAME_H pixels, then drawing that canvas enlarged by the largest whole number that fits the window. 

-- The two numbers this lesson is about.
local TILE = 16                   -- sprite and tile canvas, in art pixels
local GAME_W, GAME_H = 320, 180   -- the game's own screen, in art pixels

local screen                      -- the small image the level is drawn into

function love.load()
  love.graphics.setDefaultFilter("nearest", "nearest")   -- keep pixels crisp
  screen = love.graphics.newCanvas(GAME_W, GAME_H)
  print("Tiles on screen: " .. GAME_W / TILE .. " x " .. GAME_H / TILE)   -- 20 x 11.25
end

local function drawLevel()
  -- A row of ground tiles along the bottom. Real games draw tile images here.
  love.graphics.setColor(0.35, 0.72, 0.42)
  for x = 0, GAME_W - 1, TILE do
    love.graphics.rectangle("fill", x, GAME_H - TILE, TILE, TILE)
  end
end

function love.draw()
  love.graphics.setCanvas(screen)
  love.graphics.clear(0.66, 0.85, 0.92)   -- sky
  drawLevel()
  love.graphics.setCanvas()

  -- Enlarge by the biggest whole number that fits, and centre it.
  local w, h = love.graphics.getDimensions()
  local scale = math.max(1, math.floor(math.min(w / GAME_W, h / GAME_H)))
  local x = math.floor((w - GAME_W * scale) / 2)
  local y = math.floor((h - GAME_H * scale) / 2)
  love.graphics.clear(0, 0, 0)
  love.graphics.setColor(1, 1, 1)
  love.graphics.draw(screen, x, y, 0, scale, scale)
end

On a 1920 by 1080 window, scale comes out as 6, as in the table. Set TILE to 32 and the ground tiles double while the screen stays the same.

Pitfalls

  • Choosing the sprite before the screen. A size that feels nice in the editor may leave the player no room to see what is coming. Mock up one screen with rough tiles first.
  • Shrinking sprites to fit. If a 32 pixel character is drawn at half size in a 16 pixel world, its art pixels are half the size of everyone else's. The usual convention is one pixel size for the whole game; mixed sizes look like sprites from different games.
  • Underestimating animation. Count frames before committing. Ten animations of eight frames at 32 by 32 is over 80,000 pixels to place for one character.
  • Forgetting the interface. Text and health bars live on the same small screen. A font whose letters are 5 pixels wide plus 1 pixel of spacing fits about 53 characters across 320 pixels, which is enough for short lines and too little for long dialogue.
  • Leaving the resolution until last. Changing it late means reworking camera distances, jump heights and every interface layout. Decide early.

In real games

On old hardware the screen set the size. The original Game Boy screen is 160 by 144 pixels and its graphics are made of 8 by 8 tiles, so exactly 20 by 18 tiles fit. The NES draws a 256 by 240 pixel picture, also from 8 by 8 tiles, and its background colour choices apply to 16 by 16 pixel areas, which is one reason so many NES levels are built from 16 by 16 blocks. The fantasy console PICO-8 keeps the same idea on purpose: a 128 by 128 screen and 8 by 8 sprites, so 16 by 16 of them fit.

Modern pixel art games have no hardware limit, so they pick their own game resolution and the tile size that goes with it.

Your turn (15 minutes)

Before drawing any final art, write down how many tiles across your player needs to see. Pick a game resolution from the table and work out the tile size with GAME_W / tilesAcross, rounding to a size you like, such as 16.

Then make a mock-up at that exact resolution in your pixel editor: a flat-colour ground row, three platforms, and a plain rectangle the size of your character. You are done when you can see the next jump from where the character stands, and you have written the tile size and game resolution at the top of your project notes.

Takeaways

  • A sprite's canvas size and the game resolution are one decision: tiles on screen equals game resolution divided by tile size.
  • Doubling the canvas size quarters how many tiles fit on the same screen and multiplies the drawing work by four.
  • Powers of two are a convenient habit, not a rule. Keep one pixel size for the whole game.
  • Choose a game resolution, such as 320 by 180, that scales to common monitors by a whole number.
