Symmetry and mirroring: draw half, then break it

How to draw half a sprite and mirror it, why a perfect mirror looks stiff, and which few pixels to change so it comes alive.

You draw the left half of a creature, switch on the mirror tool, and the right half appears for free. It is balanced and tidy, yet at real size it looks like a printed badge rather than something that could move. The mirror saved you half the work and took away the life.

Draw half, mirror the rest

Many things in games are seen from the front: a character facing the camera, a potion, a shield, a door. Their shape is usually the same on both sides. The line that splits a sprite into two matching halves is its axis of symmetry, or mirror line.

Mirror drawing is an editor mode that copies every pixel you place to the matching spot on the other side of that line. You draw half the pixels, and the result is always balanced, which makes trying out silhouettes fast.

Each pixel has a partner across the line. On a canvas W pixels wide, with columns counted from 0, column x pairs with column W - 1 - x. The width decides where the line falls, just as with circles in the last lesson:

  • Even width, such as 16: the line runs between two columns. Every column has a partner, and a centred feature such as a mouth or a nose must be 2, 4 or 6 pixels wide.
  • Odd width, such as 15: the line runs through the middle column, which has no partner. Use odd widths when a single-pixel feature, such as a gem on a forehead, must sit exactly in the centre.

Why a perfect mirror looks stiff

Real creatures are never exactly symmetric. They stand with their weight on one leg, hold things in one hand, and are lit from one side. A sprite where every pixel matches its partner has none of that, so it usually reads as an emblem or a statue: something stamped rather than alive.

The mirror also copies things that should not be copied. The most common one is light. If you shade the left half with a highlight near the top left, the mirror puts a second highlight at the top right, and the sprite looks lit from both sides at once, or flatly from the front. Eyes show it most clearly: a mirrored highlight sits on the outer side of each eye, so the two eyes no longer seem to look the same way.

Mirror the shape, not the light

The usual workflow has two phases. First, with the mirror on, block in the silhouette, the outline and the main areas of colour. Then switch the mirror off and break the symmetry on purpose, in this order:

  1. Light. Pick the side the light comes from. Move highlights to that side and add shadow on the other. Both eye highlights go to the same side.
  2. Silhouette. Change the outline in one place: a chipped horn, a bent ear, a raised arm, an item held in one hand. The player reads the silhouette first, so one change there does a lot.
  3. Detail. One or two small touches inside the shape: a lopsided smile, a scar, a patch on one side.

Rule of thumb

Mirror the form, then break it with a few deliberate changes. In the demo's example, 18 of the 128 mirror pairs differ and the creature still reads as a balanced front view. Break much more and it starts to look drawn wrong rather than alive.

When to keep it symmetric

Symmetry is a choice, not a mistake. Icons, menu frames, coins and crests are usually kept exactly symmetric, because there an orderly look is the point. A robot or a formal boss can stay symmetric to look rigid. The question is whether the stiffness is intended.

Try it

The creature starts perfectly mirrored. With Mirror drawing on, paint on one side and watch the other side fill in. Then press Example breaks and compare the two previews at 1x: the light now comes from the left, both eyes share a highlight, one horn is chipped and the mouth is a smirk. Then switch the mirror off and change pixels yourself; any pixel that no longer matches its partner gets a red frame.

Keyboard: focus the canvas with Tab, move with the arrow keys, paint with Space, choose a colour with 0 to 6, and toggle the mirror with M.

The code

An in-game editor can offer the same mirror mode; the whole trick is the partner function. loadHalf builds the demo's creature from its left half only, paint writes a pixel and its partner, and brokenPairs counts the pairs that differ, as the demo's readout does. Keys 0 to 6 pick a colour, M toggles the mirror.

local W, H, SCALE = 16, 16, 20
local mirror = true
local colour = 2
local grid = {}

local function rgb(r, g, b) return { r / 255, g / 255, b / 255 } end
local palette = {
  [0] = rgb(233, 228, 212),   -- 0 empty
  [1] = rgb(41, 36, 56),      -- 1 outline
  [2] = rgb(86, 164, 132),    -- 2 body
  [3] = rgb(48, 104, 106),    -- 3 shadow
  [4] = rgb(164, 214, 150),   -- 4 light
  [5] = rgb(246, 244, 232),   -- 5 eye white
  [6] = rgb(226, 168, 92),    -- 6 horn
}

-- The left half of the creature, one string per row. "." is empty.
local HALF = {
  "...1....", "..161...", "..161111", "..162444",
  ".1222444", ".1222222", ".1225122", ".1221122",
  ".1221122", "12222222", "12222221", ".1333333",
  "..133333", "...11111", "..1661..", "..1111..",
}

local function partner(x)
  return W - 1 - x                       -- the column across the mirror line
end

local function paint(x, y, c)
  if x < 0 or x >= W or y < 0 or y >= H then return end
  grid[y][x] = c
  if mirror then grid[y][partner(x)] = c end
end

local function loadHalf()
  for y = 0, H - 1 do
    grid[y] = {}
    for x = 0, W / 2 - 1 do
      local c = tonumber(HALF[y + 1]:sub(x + 1, x + 1)) or 0   -- "." becomes 0
      grid[y][x] = c
      grid[y][partner(x)] = c
    end
  end
end

-- How many mirror pairs hold different colours: 0 means perfectly symmetric.
local function brokenPairs()
  local n = 0
  for y = 0, H - 1 do
    for x = 0, W / 2 - 1 do
      if grid[y][x] ~= grid[y][partner(x)] then n = n + 1 end
    end
  end
  return n
end

function love.load()
  loadHalf()
end

function love.update(dt)
  if love.mouse.isDown(1) then
    local mx, my = love.mouse.getPosition()
    paint(math.floor((mx - 20) / SCALE), math.floor((my - 40) / SCALE), colour)
  end
end

function love.keypressed(key)
  if key == "m" then mirror = not mirror end
  local n = tonumber(key)
  if n and n <= 6 then colour = n end
end

function love.draw()
  for y = 0, H - 1 do
    for x = 0, W - 1 do
      love.graphics.setColor(palette[grid[y][x]])
      love.graphics.rectangle("fill", 20 + x * SCALE, 40 + y * SCALE, SCALE, SCALE)
      love.graphics.rectangle("fill", 360 + x, 40 + y, 1, 1)   -- real size
    end
  end
  love.graphics.setColor(1, 1, 1)
  love.graphics.print("mirror " .. tostring(mirror) .. ", colour " .. colour
    .. ", broken pairs " .. brokenPairs(), 20, 12)
end

Games also mirror whole sprites at run time. A side-view character is usually drawn facing one way and flipped with a negative horizontal scale when it turns around. With the origin at the middle of the image, it flips in place:

-- facing is 1 when the sprite looks right and -1 when it looks left.
local ox = image:getWidth() / 2
love.graphics.draw(image, math.floor(x), math.floor(y), 0, facing, 1, ox, 0)

Keep ox a whole number. On an odd-width image, getWidth() / 2 ends in .5, and the flipped sprite lands half a pixel off the grid; use math.floor there.

Pitfalls

  • Mirroring the light. Shading with the mirror on gives highlights on both sides. Block in shapes with the mirror on; shade with it off.
  • Forgetting the mirror is still on. Your careful asymmetric change gets copied straight back. Check the mode before each break.
  • The axis is not where the sprite is. Editors usually mirror around the middle of the canvas. If your sprite sits one pixel off centre, every copy lands one pixel wrong. Centre the sprite first.
  • Breaking too much, or at random. Each change needs a reason: the light, the pose, the character. Eyes at different heights read as damage unless you meant them to.
  • Flipping at run time flips everything. A flipped sprite also flips its light and its hands: the sword moves to the other hand and the shading now comes from the right. Where that matters, draw separate frames for each direction.

In real games

Pixel editors commonly offer a symmetry mode; Aseprite, for example, can mirror drawing across a horizontal or vertical line.

Flipping is also built into old game hardware. The NES and the Game Boy both store a horizontal and a vertical flip flag with each hardware sprite, so the same tile graphics can be drawn facing either way. A symmetric object can be stored as one half and drawn twice, saving scarce graphics memory.

Your turn (15 minutes)

On a 16 by 16 canvas, draw a front-facing creature, robot or potion bottle with your editor's mirror mode on: outline, main colours, eyes. Save a copy. Then switch the mirror off and make exactly three changes: one for the light, one to the silhouette and one small detail.

You are done when the two versions sit side by side at 1x, the second one looks more alive while still balanced, and you can name the reason for each of your three changes.

Takeaways

  • Mirror drawing copies each pixel to its partner, column W - 1 - x. You draw half and the shape is always balanced.
  • Even widths put the mirror line between columns; odd widths put it through a centre column with no partner.
  • A perfect mirror usually looks stiff, and it copies the light, so highlights end up on both sides.
  • Mirror the form, then break it on purpose: light first, then one silhouette change, then a detail or two.
  • Keep exact symmetry where an orderly look is the point: icons, frames, crests and formal or mechanical things.
