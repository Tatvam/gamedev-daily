Breaking up repetition: tile variants and scattered details

Why a seamless tile still looks like wallpaper over a big area, and how weighted tile variants and off-grid details hide the grid.

Your grass tile is seamless now. No edges, no seams. Then you fill a whole meadow with it, step back, and the meadow looks like a shirt pattern: the same light patch every 16 pixels, lined up in neat rows and diagonals.

Seamless solves the joins. It does nothing about the fact that every copy is identical.

The eye joins identical things into lines

People are very good at spotting a repeat. When the same feature appears at a fixed spacing, the eye links the copies into rows, columns and diagonals, and those lines show where the tiles are even though no edge is visible. This is usually called visible repetition or tiling pattern.

The more a feature stands out, the stronger the lines it forms. And the larger the area, the more copies line up, so a tile that passes a 3 by 3 test can still look like wallpaper across a whole screen.

Fix 1: draw variants that share their edges

A tile variant is another version of the same tile: same material, same palette, same overall brightness, but with its tufts, patches and specks in different places. Three or four are usually enough.

The important constraint is the edges. Any variant can end up next to any other, so every variant needs the same outer pixels. Draw one seamless tile, duplicate it, keep a border ring one or two pixels wide exactly as it is, and redraw only the inside. Then every pair joins as cleanly as the original did with itself.

Mixing them at random already does a lot. With one tile, every tile matches its right-hand neighbour. With the four variants above and their weights, only about one neighbour in four is the same tile, and the same 2 by 2 block of tiles almost never comes back in the same spot.

Fix 2: weight the variants

Not every variant should appear equally often. A weight is a number that says how likely a variant is compared with the others. Quiet variants usually get high weights and variants with a standout feature get low ones. A dark clump in every tile is a pattern; a dark clump in one tile out of six is an accent.

Picking by weight is simple. Add the weights (4 + 3 + 3 + 2 = 12), roll a whole number from 1 to 12, and walk the list: 1 to 4 picks variant 1, 5 to 7 variant 2, 8 to 10 variant 3, and 11 or 12 variant 4.

Fix 3: scatter details off the grid

Variants still live on the tile grid: each feature sits at one of a few fixed spots inside a 16 by 16 cell. Scattered details such as flowers, pebbles and leaves are small separate sprites placed at any pixel position, usually on their own layer above the ground. Because they ignore the grid, they break the lines that are left and cross tile edges.

Keep them sparse. One detail for every eight or so tiles reads as a meadow with flowers in it. One per tile turns into a new, busier texture.

Rule of thumb

Judge ground at its real size over a whole screen. If you can follow a straight line from one copy of a feature to the next, add a variant or lower that variant's weight.

This is a convention, not a law. A puzzle board can show its grid on purpose. It matters when ground should feel natural: a visible pattern tells the player they are looking at tiles.

The code

Pick once, when the level is built, and store the result. The sheet grass.png holds the four variants side by side, followed by a 4 by 4 flower and a 4 by 4 stone, so it is 72 by 16 pixels. The weights and the one detail per eight tiles match the demo.

local TILE = 16
local weights = { 4, 3, 3, 2 }   -- quiet variants common, the busy one rare
local map, scatter = {}, {}
local sheet, quads

local function pickVariant(count)
  local total = 0
  for i = 1, count do total = total + weights[i] end
  local roll = math.random(total)          -- a whole number from 1 to total
  for i = 1, count do
    if roll <= weights[i] then return i end
    roll = roll - weights[i]
  end
  return count
end

local function buildField(cols, rows, count, seed)
  math.randomseed(seed)                    -- same seed, same field every time
  for y = 1, rows do
    map[y] = {}
    for x = 1, cols do map[y][x] = pickVariant(count) end
  end
  for i = 1, math.floor(cols * rows / 8) do  -- one detail per 8 tiles
    scatter[i] = { x = math.random(0, cols * TILE - 4),   -- any pixel, not the grid
                   y = math.random(0, rows * TILE - 4), kind = math.random(2) }
  end
end

function love.load()
  sheet = love.graphics.newImage("grass.png")
  sheet:setFilter("nearest", "nearest")
  quads = {}
  for i = 1, 4 do quads[i] = love.graphics.newQuad((i - 1) * TILE, 0, TILE, TILE, 72, 16) end
  quads[5] = love.graphics.newQuad(64, 0, 4, 4, 72, 16)   -- flower
  quads[6] = love.graphics.newQuad(68, 0, 4, 4, 72, 16)   -- stone
  buildField(20, 12, 4, 7)
end

function love.draw()
  love.graphics.scale(3)
  for y = 1, #map do
    for x = 1, #map[y] do
      love.graphics.draw(sheet, quads[map[y][x]], (x - 1) * TILE, (y - 1) * TILE)
    end
  end
  for _, d in ipairs(scatter) do love.graphics.draw(sheet, quads[4 + d.kind], d.x, d.y) end
end

buildField(20, 12, 1, 7) gives the before. A fixed seed gives the same field on every start; change it to reshuffle.

Pitfalls

  • Variants with different edges. If one variant's border differs, the seams come back wherever it meets the others. Copy the tile and only redraw inside the ring.
  • Rolling again every frame. Calling the random pick inside love.draw() makes the ground flicker. Pick once when the level is built and store the result.
  • A busy variant with a high weight. A standout feature that appears often simply becomes the new pattern. Give it the lowest weight.
  • Too much variety. Ground is usually background. Loud variants and dense details turn it into noise that fights the characters. Keep variants close in value.
  • A busy border ring. Anything in the shared ring appears on every tile whatever the variant, so keep it quiet.

In real games

Level editors build this in. The Tiled map editor has a random mode for its stamp brush and a probability property on each tile. Godot 4 tiles have a probability value that its tile map editor uses when painting random tiles. Unity's 2D Tilemap Extras package includes a Random Tile that picks one of several sprites by position.

Grass, sand and floors in tile-based games are commonly built from a few variants of a base tile plus a separate layer of small decorations.

Takeaways

  • Seamless tiles hide edges, but identical copies still line up into a visible pattern.
  • Three or four variants that share the same outer pixels can sit next to each other in any order.
  • Weights keep quiet variants common and standout variants rare.
  • Small details placed at any pixel position break the lines that the tile grid leaves behind.
  • Choose variants once when the level is built, with a fixed seed, and judge the result at real size.
