Pixel-perfect lines: removing doubles

Why the extra corner pixels called doubles make a stroke look heavy, and the three-pixel rule that removes them as you draw.

You sketch an outline with the pencil tool, and at real size the slanted and curved parts look thicker than the straight parts, as if they were drawn with a heavier pen. Zoom in and every step of the staircase has an extra pixel tucked into its inside corner.

A double is a pixel the line does not need

Two pixels can touch in two ways: by a side, like squares next to each other on a chessboard, or only by a corner, like squares on a diagonal. A one-pixel-wide line needs both. Along a run the pixels touch by their sides. Where the line steps to the next row, one corner touch is enough to keep it joined.

A double is an extra pixel that fills the inside corner of such a step. With it, three pixels form a small L shape: the pixels before and after the step already touch at a corner, and the double sits in the angle between them. Pixel artists often call these doubles because the line is two pixels thick at that spot. A stroke without them is called pixel-perfect.

Why doubles make a line look heavy

Count the pixels. A 45 degree line six columns wide needs six pixels. Drawn with a double at every step it uses eleven, nearly twice as many, so it looks nearly twice as heavy as the clean version.

The weight is also uneven. On a shallow line or a curve, doubles appear only where the line changes row. Long runs stay thin and every step gets a little clump. At real size those clumps read as knots in the line, and a curve whose runs are in perfect order, as in the curves lesson, still looks lumpy.

Where doubles come from

Your hand. When you drag the mouse or pen diagonally, the pointer almost never passes exactly through the corner where four pixels meet. It crosses into the pixel beside or below first. A plain pencil paints every pixel the pointer passes over, so nearly every diagonal step gets a double.

The rule: look at the last three pixels

Take any three pixels in a row along a stroke, A, B and C. If A and C touch at a corner, and B touches each of them by a side, then B is a double and can go. The line stays joined through the corner touch between A and C.

A pixel-perfect mode in an editor applies this rule while you draw. Each time the stroke reaches a new pixel, it checks the newest three. If they form an L, it deletes the middle one before you even notice it. Aseprite calls this option Pixel-perfect on its pencil. Other editors may name it differently or lack it; then you clean by hand with the same rule.

Rule of thumb

Count the pixels touching a pixel, including corners. In a clean one-pixel stroke, a pixel in the middle of the line usually touches exactly two others. A pixel that touches three is usually next to a double.

Doubles are a convention, not a crime

A stroke with doubles is not wrong, just heavier. Some artists keep them on purpose, for example on the shadow side of an outline. A double your hand added by accident is noise; a double you placed is a decision.

Try it

The grid starts with a leaf drawn freehand, with doubles marked in red. Switch on Pixel-perfect and watch the red pixels vanish. Then compare the two leaves at 3x and at real size on the right: the left one looks drawn with a blunt pencil.

Now draw your own curves and diagonals by dragging on the grid. With the keyboard, focus the grid, move the cursor with the arrow keys, and press Space to put the pen down or lift it. Arrow keys cannot move diagonally, so they make a double at every step, much as a hand does.

The code

A game with a drawing feature, such as a level editor or a paint minigame, has the same problem when the player draws on a pixel grid. The fix is the same rule, run each time the stroke reaches a new cell. The mouse can skip several cells between frames, so strokeTo walks along the movement in steps of a tenth of a cell, as the demo does. Press P to switch the mode.

local CELL = 16           -- each art pixel is 16 screen pixels wide
local pixelPerfect = true
local strokes = {}        -- each stroke is a list of { x = ..., y = ... } cells
local current = nil
local lastX, lastY = 0, 0

-- A and C touch at a corner, and B touches each of them by a side.
local function isLCorner(a, b, c)
  local diagonal = math.abs(a.x - c.x) == 1 and math.abs(a.y - c.y) == 1
  local sideAB = math.abs(a.x - b.x) + math.abs(a.y - b.y) == 1
  local sideBC = math.abs(b.x - c.x) + math.abs(b.y - c.y) == 1
  return diagonal and sideAB and sideBC
end

local function addCell(stroke, x, y)
  local last = stroke[#stroke]
  if last and last.x == x and last.y == y then return end
  stroke[#stroke + 1] = { x = x, y = y }
  local n = #stroke
  if pixelPerfect and n >= 3 and isLCorner(stroke[n - 2], stroke[n - 1], stroke[n]) then
    table.remove(stroke, n - 1)   -- drop the double
  end
end

local function cellAt(px, py)
  return math.floor(px / CELL), math.floor(py / CELL)
end

-- Walk from the last mouse position to the new one in tenths of a cell.
local function strokeTo(px, py)
  local far = math.max(math.abs(px - lastX), math.abs(py - lastY))
  local steps = math.max(1, math.ceil(far / (CELL * 0.1)))
  for i = 1, steps do
    local t = i / steps
    local cx, cy = cellAt(lastX + (px - lastX) * t, lastY + (py - lastY) * t)
    addCell(current, cx, cy)
  end
  lastX, lastY = px, py
end

function love.mousepressed(x, y, button)
  if button ~= 1 then return end
  current = {}
  strokes[#strokes + 1] = current
  lastX, lastY = x, y
  local cx, cy = cellAt(x, y)
  addCell(current, cx, cy)
end

function love.mousemoved(x, y)
  if current then strokeTo(x, y) end
end

function love.mousereleased(x, y, button)
  if button == 1 then current = nil end
end

function love.keypressed(key)
  if key == "p" then pixelPerfect = not pixelPerfect end
end

function love.draw()
  love.graphics.setColor(0.16, 0.14, 0.22)
  for _, stroke in ipairs(strokes) do
    for _, p in ipairs(stroke) do
      love.graphics.rectangle("fill", p.x * CELL, p.y * CELL, CELL, CELL)
    end
  end
end

Like an editor, and unlike the demo, this throws doubles away for good. Keep a raw copy of each stroke if you want the toggle to work afterwards.

Pitfalls

  • Square corners get cut. A right-angle corner is also three pixels in an L, so pixel-perfect mode removes the corner pixel of a box drawn in one stroke. Lift the pen at a corner you want sharp, because the rule only looks inside one stroke.
  • Joins between strokes. For the same reason, a double can form where a new stroke meets an old one. Check the joints by eye.
  • Clean weight is not a clean rhythm. Removing a double takes one pixel off the end of a run, and which run loses it depends on how your hand moved. A pixel-perfect stroke can still have jaggies. Read its runs as in the jaggies lesson.
  • Fills can leak. A pixel-perfect outline has gaps at its corner touches. A fill tool that spreads to corner neighbours flows straight through them. If your editor's bucket has an option to fill diagonally, turn it off for outlines like these.

In real games

The one-pixel outlines on small sprites are usually drawn without doubles on their diagonals and curves, which is part of why they look crisp at real size.

Lines that a game draws at run time, such as a laser, a rope or a selection box, are often drawn with Bresenham's line algorithm. For a shallow line it moves one column at a time, and when it changes row it steps diagonally, so its lines come out free of doubles without any clean-up.

Your turn (15 minutes)

In your pixel editor, switch off any pixel-perfect option. On a 16 by 16 canvas, draw a round outline in one freehand stroke, and a 45 degree line beside it. Find every double: look for two pixels that each touch three others, and the double is the corner pixel between them. Delete them by hand using the A, B, C rule.

Then switch pixel-perfect on, if your editor has it, and draw the same shapes again. You are done when neither drawing has an L of three pixels except at corners you chose, and both look even in weight at real size.

Takeaways

  • A double is the extra pixel in the inside corner of a step, where three pixels form an L.
  • Doubles make lines heavier and uneven: a 45 degree line with them uses nearly twice the pixels.
  • Hands and arrow keys make doubles naturally, because the pointer crosses a side neighbour before the diagonal one.
  • The rule: if A and C touch at a corner and B touches both by a side, remove B. Pixel-perfect mode does this as you draw.
  • Keep a double only when you chose it, for example at a sharp corner or for extra weight.
