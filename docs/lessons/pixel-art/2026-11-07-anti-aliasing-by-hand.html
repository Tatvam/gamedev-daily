Anti-aliasing by hand: colours between colours

How a few in-between colours placed at the steps of a jagged edge make it look smooth at real size, and where to leave them out.

You draw a big round moon. Every run of pixels is clean, the curve follows all the rules from the linework lessons, and still, at real size, its edge looks like a flight of stairs. You cannot put a pixel between two pixels. You can put a colour between two colours, and that is enough.

Colours between colours

A jaggy is the visible step where a run of pixels ends and the next one starts. On a straight or curved edge between two very different colours, such as a pale moon on a dark sky, each step is a sharp corner, and the eye picks out every one.

Anti-aliasing, usually shortened to AA, softens those corners by placing pixels of an in-between colour where the edge steps. At real size the eye blends the in-between pixel with its neighbours and reads the edge as passing through the pixel instead of around it. Doing it by hand means you decide which pixels get an in-between colour and which colour from your palette they get.

How much of the pixel does the edge cover?

Imagine the smooth edge you wanted to draw, laid over the pixel grid. Most pixels are fully on one side. Pixels along the edge are cut by it: part sky, part moon. The share of a pixel on the moon side is its coverage. A hard edge rounds every coverage to 0 or 100 percent. Anti-aliasing gives the in-between pixels an in-between colour instead.

You do not measure anything when you draw. The idea is simply that a pixel that should be mostly sky gets a colour that is mostly sky.

Picking the in-between colours

One or two in-between shades are usually enough. A colour about a third of the way from the sky to the moon, and one about two thirds of the way, covers most steps. Take them from your palette if you can: often a step of an existing ramp sits close to the right value, and reusing it keeps the colour count down. Value matters most here. An in-between pixel that is darker than both of its neighbours does not smooth the edge; it adds a dent.

Where to put them

These are conventions, and most pixel artists follow them:

  • At the steps, nowhere else. The in-between pixels go at the corner where one run ends and the next begins: the darker one on the sky side, the lighter one on the moon side.
  • Long runs get long tapers. A run of five can take two or three in-between pixels that fade along it. A run of two gets one at most.
  • Leave 1:1 diagonals alone. A diagonal that steps one pixel at a time already reads as smooth. AA on it turns a crisp line into a soft, blurry band.
  • Fewer is better. If removing an AA pixel makes no difference at 1x, remove it.

Why not let the computer do it?

An editor or a downscaling filter can do automatic smoothing: it measures the coverage of every cut pixel and mixes a colour for each one. The edge does look smooth at 1x on the background it was mixed for. The costs are the reason most pixel artists do it by hand: every edge pixel gets its own new colour, so the curve in the demo below gains 17 colours that belong to no ramp; faint pixels with 10 percent coverage add fuzz that shows up as blur once the game is scaled up; and every edge gets the same treatment, including the 1:1 stretches and corners you wanted sharp.

Know what is behind the edge

An in-between colour is a mix of two colours. If one of them is the background and the background changes, the mix is wrong. A sprite whose outer edge was anti-aliased against a dark sky gets a grey fringe, often called a halo, when it walks in front of a pale wall. That is why the usual advice is to anti-alias inside a sprite, where you know both colours, and to leave the outer edge of a moving sprite hard, or to anti-alias it only towards its own dark outline.

Rule of thumb

Anti-alias only where you know both colours, use one or two in-between shades from your palette, put them at the steps, and stop as soon as the edge reads smooth at 1x.

The code

This LÖVE program builds the demo's tile twice: once with a hard edge, and once with the two-shade rule. It measures coverage by testing 8 by 8 points inside each pixel, then snaps the result to one of four palette indexes. Press Space to switch between the two. In a real project, run a rule like this once at most, save the result as art, and finish it by hand.

local N, ZOOM = 24, 12
local CX, CY, R = 24, 24, 20.25   -- the true moon: centre and radius, in pixels
local SS = 8                      -- test points per side when measuring coverage
local PALETTE = {
  { 0.15, 0.17, 0.33 },   -- 1 sky
  { 0.41, 0.40, 0.44 },   -- 2 a third of the way from sky to moon
  { 0.67, 0.63, 0.54 },   -- 3 two thirds of the way
  { 0.93, 0.86, 0.64 },   -- 4 moon
}

local function inside(x, y)
  local dx, dy = x - CX, y - CY
  return dx * dx + dy * dy <= R * R
end

-- Share of pixel (x, y) that lies inside the moon, from 0 to 1.
local function coverage(x, y)
  local hits = 0
  for j = 0, SS - 1 do
    for i = 0, SS - 1 do
      if inside(x + (i + 0.5) / SS, y + (j + 0.5) / SS) then hits = hits + 1 end
    end
  end
  return hits / (SS * SS)
end

local function hardIndex(x, y)
  if inside(x + 0.5, y + 0.5) then return 4 else return 1 end
end

-- The two-shade rule from the diagram.
local function ruleIndex(x, y)
  local c = coverage(x, y)
  if c < 0.25 then return 1
  elseif c < 0.5 then return 2
  elseif c < 0.75 then return 3
  else return 4 end
end

local hard, smooth, showSmooth = {}, {}, true

function love.load()
  love.graphics.setDefaultFilter("nearest", "nearest")   -- keep scaled art crisp
  for y = 1, N do
    hard[y], smooth[y] = {}, {}
    for x = 1, N do
      hard[y][x] = hardIndex(x - 1, y - 1)
      smooth[y][x] = ruleIndex(x - 1, y - 1)
    end
  end
end

function love.keypressed(key)
  if key == "space" then showSmooth = not showSmooth end
end

function love.draw()
  local tile = hard
  if showSmooth then tile = smooth end
  for y = 1, N do
    for x = 1, N do
      love.graphics.setColor(PALETTE[tile[y][x]])
      love.graphics.rectangle("fill", (x - 1) * ZOOM, (y - 1) * ZOOM, ZOOM, ZOOM)
    end
  end
end

The highlighted lines are the whole rule. Because the tile stores palette indexes, not colours, the two in-between shades are ordinary palette entries: a palette swap recolours them along with everything else. The setDefaultFilter call matters once you draw the tile into an image or canvas and scale it; LÖVE's default filter is linear, which would blur your carefully placed pixels.

Pitfalls

  • Anti-aliasing the outer edge of a moving sprite. The in-between colours were mixed with one background. Over a different one they become a halo. Keep AA inside the sprite, or towards its outline.
  • Too much AA. Three or four shades along every step make the edge look out of focus. Pixel art is meant to look crisp; one or two shades, at the steps only, is usually the limit.
  • AA on 1:1 diagonals. They are already as smooth as a diagonal can be. In-between pixels there only thicken and blur them.
  • The wrong value. An in-between pixel must sit between its two neighbours in value. If it is darker or lighter than both, it reads as a speck or a notch, not a smooth edge.
  • AA that lines up into a stripe. On a long edge, in-between pixels in a neat row read as a third band. Vary the taper with the run lengths, as in the banding lesson.
  • Colour creep. A fresh in-between colour for every step soon adds a dozen near-identical colours. Reuse the same one or two.

In real games

On consoles such as the NES and the Super NES, a sprite pixel is either fully opaque or fully transparent: colour 0 of a sprite palette is the see-through one. A sprite cannot blend its own edge with whatever happens to be behind it, so any anti-aliasing on its outer edge has to assume a background. Keeping sprite silhouettes hard and anti-aliasing only inside them fits that limit, and it is still the common habit today.

Modern engines can store partial transparency per pixel, so some games give edge pixels partial alpha instead of a mixed colour. That blends correctly on any background, but those pixels are no longer a single palette colour, which complicates palette swaps and the crisp look.

Your turn (15 minutes)

Pick a sprite or tile of 16 by 16 pixels or larger with a curved internal edge between two contrasting colours, such as a shield rim, a hill against the sky or the inside of a ring. Make a copy. On the copy, find the three longest runs along that edge and add one or two in-between pixels at each of their steps, using colours already in your palette. Leave any 1:1 stretch alone.

You are done when the copy, viewed at 1x next to the original, reads as smoother, and you have added no more than two new colours to the palette (ideally none).

Takeaways

  • Anti-aliasing places in-between colours at the steps of an edge, so the eye reads the edge as passing through the pixels.
  • A pixel's in-between colour follows its coverage: mostly sky gets a colour that is mostly sky.
  • One or two shades from your palette, at the steps only, with longer tapers on longer runs. Leave 1:1 diagonals hard.
  • Automatic smoothing is smooth but adds many colours and soft fuzz. Hand AA spends a few pixels where they help.
  • Anti-alias only where you know both colours. Against a changing background, AA turns into a halo.
