Jaggies: how to spot a line that breaks its rhythm

How to find jaggies by reading a line's runs: one-row steps, two run lengths one apart, and the odd length spread out.

You draw the slope of a ramp by hand, pixel by pixel. Zoomed in, every pixel looks reasonable. At real size the ramp has a nick in it, or a flat spot, or a little bump, and you cannot tell which pixel is to blame.

Those faults are jaggies. This lesson gives you three quick checks that point at the exact pixels causing them.

A jaggy is a run that breaks the pattern

As the previous lesson showed, a slanted pixel line is a staircase of runs: groups of pixels in a row, separated by one-pixel steps. Equal runs give a perfect slope.

Most lines in real sprites are not perfect, and that is fine. Trouble starts when one spot breaks the rhythm of the rest. Pixel artists call that spot a jaggy: a place where the steps of a line change suddenly, so the eye sees a notch, a bump or a flat spot. (In general graphics, "jaggies" can mean the staircase of any slanted edge; pixel artists usually mean only the irregular steps.)

Three checks

Read the line as a list of run lengths, from one end to the other. A straight line that reads cleanly usually passes three checks. They are written for a line wider than it is tall; for a steep line, swap rows and columns.

  1. Every step moves exactly one row, always the same way. A step of two rows leaves a hole, a break. A step in the wrong direction makes a bump. These are the loudest jaggies.
  2. At most two run lengths, one pixel apart. A line of 2s and 3s is fine. A run of 4 in a line of 2s is a long run and reads as a flat spot. A single run of 1 in a line of 3s reads as a notch.
  3. The less common length is spread out, never doubled. In a line made mostly of 2s, a 3 here and there is invisible. Two 3s next to each other form a clump, and the eye sees the line bend flatter for a moment.

Rule of thumb

Say the runs out loud: "two, two, two, four, two". If one number sounds wrong in the rhythm, that run is your jaggy.

Why the eye catches them

At real size you cannot see single pixels, but you can see changes in rhythm. A regular staircase blends into a slanted edge; one irregular step differs from all its neighbours, so it pulls the eye. That is why a jaggy that seems harmless at 800 percent zoom stands out at 100 percent.

A line drawn by a standard line algorithm has runs that differ by at most one pixel, with the odd ones spread through it. The checks ask whether your hand-drawn line could have come from a ruler.

Fixing a jaggy

Move pixels between runs, but keep the total. Take the starting line in the demo below: runs 2 2 2 4 2 2 3 3 2 2 2 with one break. It covers 26 columns and climbs 11 rows from its first pixel to its last, so it needs 12 runs that add up to 26. Ten runs of 2 and two runs of 3 do it: 2 2 2 3 2 2 2 2 3 2 2 2. Same ends, no jaggies.

If that needs three different lengths, the line is the wrong size: move an endpoint instead.

These checks are conventions for lines that should look straight. A curve is supposed to change its run lengths, but steadily: 1 1 2 3 4 bends smoothly, 1 3 1 4 wobbles. Curves get their own lesson next.

The code

A jaggy checker is useful in a game too, for example to test slopes from a level generator. This is the demo's checker in plain Lua. ys[x] is the row of the line's pixel in column x; the result marks every pixel that breaks one of the three checks.

-- Split a line (one pixel per column) into runs of equal rows.
local function getRuns(ys)
  local runs = {}
  local first = 1
  for x = 2, #ys + 1 do
    if ys[x] ~= ys[first] then             -- past the end, ys[x] is nil
      runs[#runs + 1] = { first = first, last = x - 1, length = x - first }
      first = x
    end
  end
  return runs
end

local function sign(v)
  if v > 0 then return 1 elseif v < 0 then return -1 end
  return 0
end

-- Returns bad[x] = true for every pixel that breaks the line's rhythm.
local function findJaggies(ys)
  local runs = getRuns(ys)
  local bad = {}
  local function mark(run)
    for x = run.first, run.last do bad[x] = true end
  end

  -- Check 1: every step moves one row, always the same way.
  local dir = sign(ys[#ys] - ys[1])
  for i = 2, #runs do
    if ys[runs[i].first] - ys[runs[i - 1].last] ~= dir then
      bad[runs[i - 1].last] = true
      bad[runs[i].first] = true
    end
  end

  -- Check 2: at most two run lengths, one pixel apart.
  local count = {}
  for _, run in ipairs(runs) do
    count[run.length] = (count[run.length] or 0) + 1
  end
  local main = runs[1].length               -- most common length
  for len, n in pairs(count) do
    if n > count[main] or (n == count[main] and len < main) then main = len end
  end
  local second = main + 1
  if (count[main - 1] or 0) > (count[main + 1] or 0) then second = main - 1 end
  for _, run in ipairs(runs) do
    if run.length ~= main and run.length ~= second then mark(run) end
  end

  -- Check 3: the second length never appears twice in a row.
  for i = 2, #runs do
    if runs[i].length == second and runs[i - 1].length == second then
      mark(runs[i - 1])
      mark(runs[i])
    end
  end
  return bad
end

In the same file, the demo's starting line drawn at 16 times its size, with the jaggies in red:

-- Rows of the demo's starting line, one per column (26 columns).
local ys = { 12, 12, 11, 11, 10, 10, 9, 9, 9, 9, 8, 8, 7, 7,
             6, 6, 6, 5, 5, 5, 4, 4, 2, 2, 1, 1 }
local bad = findJaggies(ys)

function love.draw()
  for x = 1, #ys do
    if bad[x] then
      love.graphics.setColor(0.84, 0.2, 0.16)   -- jaggy
    else
      love.graphics.setColor(0.16, 0.14, 0.22)  -- ink
    end
    love.graphics.rectangle("fill", (x - 1) * 16, ys[x] * 16, 16, 16)
  end
end

Pitfalls

  • Judging only at high zoom. At 800 percent every step looks deliberate. Keep a real size preview open while you work.
  • Fixing one run in isolation. Shortening a long run pushes a pixel into the next run. Re-read the whole list after each change, not just the spot you touched.
  • Ignoring the ends. A stub of 1 at the end of a line of 3s is a jaggy too, often from a line one pixel too long.
  • Straightening organic shapes. A rock, a cloud or a cape should not pass these checks perfectly. The checks are for things that should read as straight.
  • Hoping smoothing will hide it. In-between colours along an edge (anti-aliasing, a later lesson) soften the staircase but usually do not hide a jaggy. Fix the runs first.

In real games

Jaggies are mostly a hand-drawing problem. Lines a game draws at run time, such as laser sights or ropes, usually come from a line algorithm, whose runs differ by at most one pixel. Hand-drawn outlines in sprites and tiles are where artists hunt for jaggies.

They also appear when pixel art is rotated in game: the rotated edges end up with irregular runs. A later lesson covers how games deal with that.

Open a sprite of your own that has at least one long straight edge: a sword, a table, a roof or a ramp. Zoom in and write down the run lengths of that edge from end to end.

Circle every run that fails a check, then fix it by moving pixels between runs, keeping the end pixels in place. You are done when the list passes all three checks and the edge looks straight at 100 percent. If it cannot pass without three lengths, move one end.

Takeaways

  • A jaggy is a spot where a line's steps change suddenly, so the eye sees a notch, bump or flat spot.
  • Read a line as a list of run lengths. A straight line usually has one-row steps, at most two run lengths one pixel apart, and the less common length spread out.
  • Breaks and bumps are the loudest jaggies; long runs and clumps are quieter but still visible at real size.
  • Fix jaggies by moving pixels between runs while keeping the total, and re-check the whole line after each change.
