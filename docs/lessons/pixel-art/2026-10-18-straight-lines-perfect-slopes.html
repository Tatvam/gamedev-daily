Straight lines and perfect slopes

Why pixel lines built from equal runs such as 1:1, 2:1 and 3:1 look clean, and how to move an endpoint to the nearest perfect slope.

You draw the edge of a roof with the line tool, from one corner to the other. It is mathematically straight, yet when you zoom out it looks bent, as if the roof sags in the middle. Move the end of the line by a single pixel and the same edge suddenly looks crisp.

The difference is not the angle you chose. It is the pattern of steps the line is made of, and you can learn to read it.

A pixel line is a staircase of runs

A screen cannot draw a slanted line, only squares on a grid. So a diagonal line in pixel art is really a staircase: a few pixels in a row, one step up, a few more pixels, another step. Each horizontal (or vertical) group of pixels between two steps is called a run.

We describe a slope by its runs. A 2:1 slope goes two pixels across for every one pixel up, so every run is 2 pixels long. A 1:1 slope is the plain 45 degree diagonal, one pixel per step. A 1:2 slope is the steep version of 2:1, with vertical runs of 2.

Why equal runs look straighter

Your eye does not see the true mathematical line. It sees the staircase and guesses the line from its rhythm. When every step is the same size, the guess is a clean straight edge. When one run is longer, the eye reads the change in rhythm as a bend or a flat spot, even if the line is as close to the true angle as the grid allows.

Lines with equal runs are often called perfect slopes (some artists say clean or ideal lines). The common ones are:

  • Horizontal and vertical: a single run. Always clean.
  • 1:1, about 45 degrees: one pixel per step.
  • 2:1 and 1:2, about 26.6 and 63.4 degrees. The 2:1 slope is the backbone of most pixel art "isometric" views.
  • 3:1, 4:1 and so on. These get shallower, and the steps become more visible as separate flat segments.

Where uneven runs come from

A line that covers W columns and H rows, and is wider than it is tall, must be split into H runs that add up to W. If W divides evenly by H, every run is the same. If not, some runs must be one pixel longer: a line 9 wide and 4 tall gets runs of 2, 3, 2 and 2, while 8 by 4 gets four runs of 2.

So the fix is usually not to nudge pixels in the middle. It is to move one endpoint until the width is a whole multiple of the height. Decide before you draw: "this roof edge is 2:1, so if it is 5 pixels tall it must be 10 wide."

Rule of thumb

Count the columns and rows your line covers. If the bigger number divides evenly by the smaller one, the slope is perfect. If not, stretch or shrink the line until it does.

This is a convention, not a law. Uneven lines that repeat a regular pattern, such as runs of 2, 1, 2, 1, can look fine at small sizes, and organic shapes like hills should not be perfectly straight anyway. But for built things, such as buildings, crates, swords and UI frames, perfect slopes usually look more deliberate.

The code

Games draw pixel lines too: lasers, ropes, aiming guides. Here is the demo's method in plain Lua. lineRuns splits the long side of a line into as many runs as the short side has pixels, spreading any extra pixels evenly.

-- Split a line into runs. long = pixels along the main axis,
-- short = pixels along the other axis, which is also the number of runs.
local function lineRuns(long, short)
  local runs = {}
  local previous = 0
  for i = 1, short do
    local edge = math.floor(i * long / short + 0.5)
    runs[i] = edge - previous
    previous = edge
  end
  return runs
end

-- The pixels of a line from (x0, y0) to (x1, y1), drawn run by run.
local function linePixels(x0, y0, x1, y1)
  local w = math.abs(x1 - x0) + 1
  local h = math.abs(y1 - y0) + 1
  local sx = (x1 >= x0) and 1 or -1
  local sy = (y1 >= y0) and 1 or -1
  local pixels = {}
  local x, y = x0, y0
  if w >= h then
    for _, run in ipairs(lineRuns(w, h)) do
      for k = 1, run do
        pixels[#pixels + 1] = { x, y }
        x = x + sx
      end
      y = y + sy
    end
  else
    for _, run in ipairs(lineRuns(h, w)) do
      for k = 1, run do
        pixels[#pixels + 1] = { x, y }
        y = y + sy
      end
      x = x + sx
    end
  end
  return pixels
end

Snapping keeps the short side and makes the long side a whole multiple of it, exactly like the demo's toggle. In the same file, below the functions above:

-- Move the end of a line so that every run has the same length.
local function snapEnd(x0, y0, x1, y1)
  local w = math.abs(x1 - x0) + 1
  local h = math.abs(y1 - y0) + 1
  local sx = (x1 >= x0) and 1 or -1
  local sy = (y1 >= y0) and 1 or -1
  if w >= h then
    w = math.floor(w / h + 0.5) * h     -- 23 by 10 becomes 20 by 10: 2:1
  else
    h = math.floor(h / w + 0.5) * w
  end
  return x0 + sx * (w - 1), y0 + sy * (h - 1)
end

local canvas

function love.load()
  love.graphics.setDefaultFilter("nearest", "nearest")
  canvas = love.graphics.newCanvas(32, 18)   -- the demo's grid
end

function love.draw()
  local ex, ey = snapEnd(2, 15, 24, 6)       -- returns 21, 6
  love.graphics.setCanvas(canvas)
  love.graphics.clear(0.91, 0.89, 0.83)      -- paper
  love.graphics.setColor(0.16, 0.14, 0.22)   -- ink
  for _, p in ipairs(linePixels(2, 15, ex, ey)) do
    love.graphics.rectangle("fill", p[1], p[2], 1, 1)
  end
  love.graphics.setCanvas()
  love.graphics.setColor(1, 1, 1)            -- do not tint the canvas
  love.graphics.draw(canvas, 0, 0, 0, 16, 16)
end

The demo also shortens a snapped line when its end would fall off the grid. In a game, check the snapped end against your own bounds the same way.

Pitfalls

  • Choosing the angle first. Starting from "this roof is 25 degrees" leads straight to uneven runs. Choose the slope as a ratio of pixels instead, then pick lengths that fit it.
  • Forgetting the end pixels. A 2:1 line that is 4 rows tall covers 8 columns, so its ends are 7 pixels apart, not 8. Counting the distance instead of the pixels gives you a stub run of 1 at one end.
  • Mismatched sides. Where two roof edges meet, their runs should mirror each other. A run of 3 on one side only makes the roof look lopsided.
  • Trusting the line tool. An editor's or engine's line function picks pixels for whatever endpoints you give it. It knows nothing about perfect slopes; the endpoints are your decision.
  • Forcing it everywhere. On a rock, a cloud or a cape, a line that is too regular looks stiff. Break the rule there on purpose.

In real games

The clearest example is "isometric" pixel art. Most of it is not true isometric projection, whose lines rise at 30 degrees. It uses 2:1 lines at about 26.6 degrees instead, because a 30 degree line has uneven runs while a 2:1 line repeats perfectly. Tiles drawn this way are usually twice as wide as they are tall.

The same habit shows across hand-made pixel art: building outlines, swords and UI frames tend to use 1:1, 2:1 and 1:2 edges, while organic shapes are drawn more freely.

Your turn (15 minutes)

Open your pixel editor and make a 32 by 32 canvas. Draw a simple house: a box for the walls and two roof edges meeting at the top. First draw the roof with the line tool at whatever angle looks right, then count the runs of each edge.

Now redraw the roof twice, as 1:1 and as 2:1, moving the eaves until every run is equal. Compare all three at 100 percent zoom. You are done when you can say, for each version, how wide and tall the roof edge is and why its runs are or are not equal.

Takeaways

  • A pixel line is a staircase of runs, and the eye judges straightness from the rhythm of those runs.
  • Lines with equal runs, such as 1:1, 2:1 and 3:1, usually look the cleanest. One run of a different length reads as a kink.
  • A line that covers W columns and H rows has equal runs only when W divides evenly by H (or H by W for steep lines).
  • Fix a wobbly line by moving an endpoint until the counts divide evenly, not by nudging pixels in the middle.
