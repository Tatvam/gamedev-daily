Props larger than one tile: footprints and sorting by feet

How trees, houses and rocks span several tiles, why only their base should block, and how sorting by the base lets a hero walk in front and behind.

You place a tall tree in your three-quarter village. The hero walks up behind it, and instead of disappearing under the leaves, the hero is painted on top of the canopy as if standing on a cloud. You swap the layers, and now the tree covers the hero's head even when the hero stands in front of the trunk.

Neither layer order is right, because the right order changes as the hero moves. Draw big props so the game can work out that order by itself.

A prop is bigger than the ground it stands on

A prop is any object placed on top of the ground tiles: a tree, a house, a rock. Big ones span several tiles: the trees in the demo are 16 by 32 pixels, two tiles wide and four tall.

In three-quarter view, "up the screen" means both "higher" and "further back". So most of a tall prop's pixels are not ground it occupies; they are height. Split every prop in your head into three parts:

  • The footprint: the small patch of ground the prop really stands on. For a tree it is the bottom of the trunk. This is the only part that should block movement.
  • The overhang: everything above the footprint, such as the canopy or the roof. A character can stand behind it and be partly hidden.
  • The anchor (also called the pivot or origin): one point in the middle of the base, where the prop touches the ground. The game stores the prop's position as this point.

Whatever is drawn last ends up on top

A 2D game paints the screen like a painter on canvas: each sprite covers whatever was painted before it. This is called the painter's algorithm, and the order of the sprites is the draw order. There are three common ways to choose it for big props:

  1. Fixed layers, hero on top. Simple, and right only while the hero is in front of everything. Behind a tree, the hero is drawn over the leaves.
  2. Split the prop into two layers. The bottom tile row goes on a ground layer under the hero, the rest on an overhead layer above the hero. Walking behind now works, but standing just in front of the trunk, the hero's head pokes up into the overhead layer and gets covered.
  3. Sort by feet. Before drawing, sort every prop and character by the screen y of its anchor, smallest first. The thing whose base is higher up the screen is further back, so it is drawn earlier. This is often called y-sorting.

The split works for tile maps with no sorting at all, as long as the art keeps heads out of the overhead part. Sorting by feet is right wherever the hero stands, because it compares the one thing that decides depth in three-quarter view: where each object touches the ground.

What this means when you draw the prop

  • Put the base on the bottom row of the canvas. Engines anchor a sprite by its canvas, not its visible pixels. Empty rows under the roots move the anchor too low, and the tree sorts in front of a hero who is behind it.
  • Keep the footprint small and readable. Give the trunk a clear base, such as roots, so the player sees where the solid part is. A footprint as big as the sprite turns the canopy into an invisible wall.
  • Leave room under the overhang. A canopy that hangs down to the roots hides the footprint. Usually the lowest leaves stop a few pixels above the base.
  • Flat things are not props. Paint shadows, paths and rugs into the ground layer so they never sort in front of a character.

A convention, not a law

The anchor is usually the bottom centre, but some engines default to the top-left corner or the centre of the image. If you sort by the top of the image, tall props sort as if they stood further back, and a character behind them is drawn on top. Whatever point you choose, use it for every sprite in the game.

The code

Each thing stores its anchor as x, y, its sprite size and its footprint. Movement checks footprints; drawing sorts by y. The numbers match the demo; rectangles stand in for sprites.

local SCALE = 5
local SPEED = 40   -- art pixels per second

-- x, y: the anchor, the middle of the base where the thing meets the ground.
-- w, h: sprite size. fw, fh: footprint, the box at the base that blocks.
local things = {
  { x = 24, y = 40, w = 16, h = 32, fw = 6,  fh = 3,  color = { 0.21, 0.44, 0.29 } },  -- tree A
  { x = 64, y = 32, w = 32, h = 32, fw = 32, fh = 12, color = { 0.69, 0.29, 0.26 } },  -- house
  { x = 80, y = 56, w = 16, h = 32, fw = 6,  fh = 3,  color = { 0.21, 0.44, 0.29 } },  -- tree B
  { x = 24, y = 64, w = 16, h = 8,  fw = 14, fh = 4,  color = { 0.54, 0.56, 0.63 } },  -- rock
}
local hero = { x = 48, y = 52, w = 8, h = 16, fw = 6, fh = 2, color = { 0.25, 0.43, 0.60 } }
table.insert(things, hero)

local function overlaps(a, ax, ay, b)
  return ax - a.fw / 2 < b.x + b.fw / 2 and ax + a.fw / 2 > b.x - b.fw / 2
     and ay - a.fh < b.y and ay > b.y - b.fh
end

local function canStand(x, y)
  for _, t in ipairs(things) do
    if t ~= hero and overlaps(hero, x, y, t) then return false end
  end
  return true
end

local function byFeet(a, b)
  if a.y ~= b.y then return a.y < b.y end   -- higher base = further back = drawn first
  return a.x < b.x                           -- tie: left first, so the order never flickers
end

function love.update(dt)
  local dx, dy = 0, 0
  if love.keyboard.isDown("left") then dx = dx - 1 end
  if love.keyboard.isDown("right") then dx = dx + 1 end
  if love.keyboard.isDown("up") then dy = dy - 1 end
  if love.keyboard.isDown("down") then dy = dy + 1 end
  local nx = hero.x + dx * SPEED * dt
  local ny = hero.y + dy * SPEED * dt
  if canStand(nx, hero.y) then hero.x = nx end   -- try each axis on its own,
  if canStand(hero.x, ny) then hero.y = ny end   -- so the hero slides along walls
end

function love.draw()
  love.graphics.scale(SCALE)
  table.sort(things, byFeet)
  for _, t in ipairs(things) do
    love.graphics.setColor(t.color)
    -- the sprite hangs up and out from its anchor
    love.graphics.rectangle("fill", math.floor(t.x - t.w / 2), math.floor(t.y - t.h), t.w, t.h)
  end
end

With real art, replace the rectangle with love.graphics.draw(t.image, math.floor(t.x), math.floor(t.y), 0, 1, 1, t.w / 2, t.h). The last two numbers are the origin, which puts the anchor at the bottom centre of the image. Call love.graphics.setDefaultFilter("nearest", "nearest") before loading images so they stay crisp.

Pitfalls

  • Sorting by the top-left corner. A 32 pixel tree and an 8 pixel bush placed on the same ground line have tops 24 pixels apart, so the tree sorts as if it were far behind the bush. Sort by the base.
  • Empty rows under the art. Padding at the bottom of the canvas moves the anchor below the visible base. Crop it, or set the anchor by hand in your engine.
  • One sort point for a long prop. A long fence has one anchor, but a character near its far end may need a different answer. Split long props into pieces, each with its own anchor and footprint.
  • Sorting shadows and rugs. Flat things sorted with characters end up on top of feet. Keep them on the ground layer.
  • Performance. Sorting a few hundred sprites per frame is cheap. With thousands, sort only those on screen.

In real games

Engines build sorting by feet in. Godot 4 has a Y Sort Enabled property on 2D nodes and tile map layers (Godot 3 had a separate YSort node). Unity's 2D renderer can sort transparent sprites along a custom axis set to (0, 1, 0), and its Sprite Renderer can use the sprite's pivot instead of its centre as the sort point. The Tiled map editor offers a "top down" draw order for object layers, which draws objects in order of their y position.

Stardew Valley lets the farmer walk behind trees and buildings, and it fades a tree's canopy while the farmer stands behind it so the player is never lost from view.

Your turn (15 minutes)

  1. Draw a tree on a 16 by 32 canvas: a trunk at least 4 pixels wide whose roots sit on the very bottom row, and a canopy whose lowest leaves stop 6 or more pixels above the roots.
  2. Mark its anchor at the bottom centre and its footprint around the roots, no wider than the trunk plus one pixel on each side.
  3. Place two copies and a character in your engine, sort by anchor y, and walk around each tree.

You are done when the character can stand behind the canopy and be hidden by it, stand in front of the trunk with nothing covering its head, and never walk through the roots.

Takeaways

  • A big prop is a small footprint plus an overhang. Only the footprint blocks movement.
  • Store every prop and character by its anchor: the middle of its base.
  • Draw in order of anchor y, smallest first, and the hero walks in front of and behind props correctly.
  • Fixed layers and overhead splits are each right only in some positions.
  • Draw the base on the bottom row of the canvas, and keep flat things on the ground layer.
