Avoiding banding: stagger your shade edges

Why shade bands that run side by side at the same width turn into stripes, how to spot their lined-up steps, and how staggering the edges fixes it.

You shade a ball from one light, as the last lesson asked. No pillow shading, a good ramp, the dark side away from the light. Yet the shadow side looks like a stack of nested outlines: three stripes of equal width that stair-step down the edge together. The light is right. The edges are too alike.

When bands line up

A band is a run of pixels in one shade of your ramp. Where one band meets the next there is a band edge, and on a curved form that edge is a staircase of short steps, just like a curved line.

Banding is when neighbouring band edges run parallel and step in the same places. Each band keeps the same width all the way along, and the corners of one band sit right next to the corners of the band beside it. The eye stops reading a gradual turn of the surface and reads a set of stripes instead.

Why it looks wrong

  • Stripes read as lines. A thin band of constant width looks like an extra outline inside the sprite, not like light.
  • The grid shows. Every stair step is repeated by its neighbour, so the jaggies are doubled and the eye sees the pixel grid instead of the form.
  • The form goes flat. On a sphere the shadow is a crescent: thin at the top, widest where the surface turns furthest from the light, thin again at the bottom. Constant width says the surface turns at the same rate everywhere.

Why it happens

The quickest way to shade a curve is to copy the outline a few pixels inwards for each band. Each copy inherits every step of the outline, so all the edges step together.

The fix: stagger the edges

  1. Find the matching steps: rows where two neighbouring edges both step by the same amount.
  2. Move one of the two corners. Shift a step on one edge up or down a row, or make it a pixel longer, so the edges step on different rows.
  3. Let the widths change. Wider where the surface turns away slowly, narrower where it turns fast. On a ball that gives the tapering crescent.
  4. Keep each edge clean by itself. Stagger edges against each other, but each edge should still follow the run-length rules from the curves lesson.
  5. Check at 1x, where stripes stand out most.

Rule of thumb

Two neighbouring edges should not keep stepping on the same rows by the same amounts. One shared step is normal; a run of them is a stripe. The outline counts as an edge too, so a band that copies the outline is banded against it.

This is a convention, not a law. Some styles use hard, even bands on purpose for a poster-like look, and tiny sprites may have no room to stagger. Ignore it and you get the stripes and visible grid above, so break it on purpose, not by habit.

The code

This LÖVE program builds the demo's banded ball and runs the same detector on it. Each row stores five edges: the left outline, the three band edges, and the right outline. Band b runs from edge b to edge b + 1, so band 1 is the lightest.

local SIZE, ZOOM, W = 20, 12, 3   -- W: width of each band in the banded version
local CX, CY, RAD = 10, 10, 9.6
local RAMP = { { 0.95, 0.76, 0.48 }, { 0.82, 0.45, 0.31 },
               { 0.54, 0.23, 0.32 }, { 0.23, 0.14, 0.28 } }   -- band 1 (light) to band 4 (dark)

-- edges[y] = { left outline, e1, e2, e3, right outline }
local edges = {}
for y = 0, SIZE - 1 do
  local l, r
  for x = 0, SIZE - 1 do
    local dx, dy = x + 0.5 - CX, y + 0.5 - CY
    if dx * dx + dy * dy <= RAD * RAD then
      l = l or x
      r = x + 1
    end
  end
  local row = { l }
  for k = 1, 3 do
    row[k + 1] = math.max(row[k], r - (4 - k) * W)   -- copy the right outline inwards
  end
  row[5] = r
  edges[y + 1] = row
end

-- A band is banded in a row when both its edges step by the same amount as in the row above.
local function bandedSteps()
  local marks = {}
  for y = 2, SIZE do
    local prev, cur = edges[y - 1], edges[y]
    for b = 1, 4 do
      local stepA, stepB = cur[b] - prev[b], cur[b + 1] - prev[b + 1]
      local wide = cur[b + 1] > cur[b] and prev[b + 1] > prev[b]
      if wide and stepA ~= 0 and stepA == stepB then
        marks[#marks + 1] = { b = b, y = y }
      end
    end
  end
  return marks
end

local marks = bandedSteps()

function love.draw()
  for y = 1, SIZE do
    local row = edges[y]
    for b = 1, 4 do
      love.graphics.setColor(RAMP[b])
      love.graphics.rectangle("fill", row[b] * ZOOM, (y - 1) * ZOOM, (row[b + 1] - row[b]) * ZOOM, ZOOM)
    end
  end
  love.graphics.setColor(1, 0.2, 0.3)
  for _, m in ipairs(marks) do
    love.graphics.rectangle("fill", (SIZE + 1) * ZOOM, (m.y - 1) * ZOOM + 4, 6, ZOOM - 8)
  end
  love.graphics.print("banded steps: " .. #marks, 4, SIZE * ZOOM + 8)
end

The highlighted lines are the detector. A step of zero is a straight vertical stretch and never counts, and empty bands are skipped. It reports 28, like the left panel. The line that copies the outline inwards is the habit that causes banding; replace it with the demo's staggered edges and the count drops to zero.

To check your own sprite, note the column where each shade starts in every row. This only works for rows that run light to dark, like this ball lit from the side; for other lights, check columns too, or trust your eye.

Pitfalls

  • Staggering into noise. Moving corners at random hides the banding but breaks each edge into jaggies. Stagger whole steps.
  • Forgetting the outline. A dark band of constant width hugging the outline is banded against it, and reads as a second, thicker outline.
  • One pixel bands. A one pixel band that follows its neighbours step for step is the easiest banding to see. Widen it in places or let it end.
  • Checking only at zoom. At 12x every edge looks deliberate; at 1x the stripes jump out. Keep a real-size preview open.
  • Hiding it with dithering. A checker pattern along a banded edge is just a dithered stripe. Fix the edges first.

In real games

"Banding" in this sense is a term from pixel art tutorials and critique, where it is a common note on beginners' shading. You will not usually find it in an engine manual.

Do not confuse it with colour banding: visible steps in a smooth digital gradient, such as a sky, when there are not enough colour levels. It is a related problem, a change that should be invisible turning into hard lines, and engines fight it with a little noise or dithering. Godot 4 has a debanding project setting, and Unity's Universal Render Pipeline has a dithering option on the camera. The pixel art kind has no setting: it is fixed by hand, one edge at a time.

Your turn (15 minutes)

Take a shaded sprite of yours, 16 to 32 pixels, with at least three shades. On a new layer above it, put a bright dot on every row where two neighbouring edges step together. Then stagger: move one corner of each marked pair by a row, let the darkest band taper where the form turns, and keep each edge clean.

You are done when no two neighbouring edges step together on more than two rows in a row, and the 1x preview reads as a rounded form instead of stripes.

Takeaways

  • Banding is when neighbouring shade edges run parallel and step in the same places, so bands keep one width and read as stripes.
  • It usually comes from copying the outline inwards to make each band.
  • It makes the pixel grid visible and flattens the form, because constant width hides how the surface turns.
  • Fix it by staggering: move one of each pair of matching steps and let band widths grow and shrink with the form.
  • Stagger edges against each other, not against themselves, and check the result at 1x.
