Clean curves: runs that grow and shrink in order

How a pixel curve stays smooth when its run lengths change in one steady direction, and how sorting the runs removes wobbles without moving the ends.

You draw a round shape, such as a slime or a shield, and at real size its edge looks lumpy: a flat spot here, a dent there, even though every pixel follows a careful guide.

The fault is not in any single pixel. It is in the order of the runs, and it can be fixed in one move.

A curve is a line whose runs change

In the lines lesson a slanted line was a staircase of runs: groups of pixels in a row, joined by one-pixel diagonal steps. A run's length sets the slope: a run of 4 is shallow, a run of 1 is 45 degrees.

A straight line keeps its runs (nearly) the same. A curve's slope keeps changing, so its runs must change too. On the top-right quarter of a round shape, the edge starts almost flat (long runs across), passes 45 degrees (single pixels) and ends almost vertical (long runs down).

In this lesson →3 means a run of three pixels across and ↓3 a run of three pixels down. A single pixel is just 1. A clean top-right quarter might read, from the top: →4 →3 →2 1 1 ↓2 ↓3 ↓4.

Rule 1: the runs change in one direction

Think of each run as having a steepness: →4 is the flattest, then →3, →2, 1, ↓2, ↓3, and ↓4 is the steepest. Along a clean curve that bends one way, every run is at least as steep as the one before. The across runs shrink, the single pixels sit in the middle, and the down runs grow.

When one run breaks that order, the curve gets flatter for a moment and then bends again. This lesson calls that a wobble. At real size it reads as a dent or a bump in the edge.

Rule 2: the change is gradual

Runs in order can still change too quickly. →5 1 1 jumps from very flat to 45 degrees, and the eye reads a corner, not a bend. Smooth curves usually step through the lengths in between: →5 →3 →2 1. The demo marks a sharp turn when a run is more than three times as steep as the one before. That cut-off is a rough guide, and sometimes a corner is what you want.

Repeats are usually fine on a curve. →3 →3 →2 →2 just holds each slope a little longer, which makes the curve wider. That differs from a straight line, where a pair of the odd length was a jaggy.

The fix: same runs, sorted

An across run of length n moves the curve n pixels right wherever it sits in the list, and a down run does the same for height. So reordering the runs never moves the end of the curve. Sorting them from flattest to steepest removes every wobble at once and keeps the ends and the pixel count the same.

If sorting leaves a sharp turn, the runs themselves are the problem: split a long run, or move an end of the curve.

Rule of thumb

Read the runs aloud from one end of the curve. They should sound like a countdown and then a count-up, as in "four, three, two, one, one, two, three, four". Any number that goes back the wrong way is a wobble.

Where wobbles come from

A curve tool rounds each point of a perfect mathematical curve to the nearest pixel, on its own, so neighbouring runs can come out a pixel too long or too short. The demo rounds a Bézier curve (a smooth curve pulled towards a control point) this way, and most control point positions give at least one wobble. Hand-drawn curves wobble for the same reason: each pixel looks right on its own.

The code

A game can use the same steps to tidy curves it rounds at run time, such as procedural hills or rounded UI panels. The pixels are a list of { x = ..., y = ... } going right and down, one pixel wide with no corner pixels. getRuns splits them at each diagonal step, and buildPixels lays the runs back down from the start pixel.

-- Split a curve into runs. dir is "across", "down" or "single".
local function getRuns(pts)
  local runs = {}
  local run = { dir = "single", length = 1 }
  for i = 2, #pts do
    local dx = pts[i].x - pts[i - 1].x
    local dy = pts[i].y - pts[i - 1].y
    if dx == 1 and dy == 1 then                -- diagonal step: next run
      runs[#runs + 1] = run
      run = { dir = "single", length = 1 }
    else
      if dx == 1 then run.dir = "across" else run.dir = "down" end
      run.length = run.length + 1
    end
  end
  runs[#runs + 1] = run
  return runs
end

-- Flat runs are near 0, single pixels are 1, tall runs are large.
local function steepness(run)
  if run.dir == "across" then return 1 / run.length end
  if run.dir == "down" then return run.length end
  return 1
end

-- "wobble" or "sharp" for each pair of runs that breaks the rules.
local function checkCurve(runs)
  local problems = {}
  for i = 2, #runs do
    local before, now = steepness(runs[i - 1]), steepness(runs[i])
    if now < before then problems[i] = "wobble"
    elseif now > 3 * before then problems[i] = "sharp" end
  end
  return problems
end

-- Same runs, flattest first. The ends of the curve do not move.
local function sortRuns(runs)
  local sorted = {}
  for i, run in ipairs(runs) do sorted[i] = run end
  table.sort(sorted, function(a, b) return steepness(a) < steepness(b) end)
  return sorted
end

local function buildPixels(runs, x, y)
  local pts = {}
  for i, run in ipairs(runs) do
    if i > 1 then x, y = x + 1, y + 1 end      -- diagonal step between runs
    for k = 1, run.length do
      if k > 1 and run.dir == "across" then x = x + 1 end
      if k > 1 and run.dir == "down" then y = y + 1 end
      pts[#pts + 1] = { x = x, y = y }
    end
  end
  return pts
end

In the same file, the demo's starting curve: a Bézier curve from (0, 0) to (11, 11) with its control point at (11, 2), rounded to pixels and drawn at 16 times its size before and after sorting.

-- Round a Bézier curve to pixels, then drop corner pixels (doubles).
local function bezierPixels(cx, cy, ex, ey)
  local pts = {}
  for i = 0, 200 do
    local t = i / 200
    local u = 1 - t
    local x = math.floor(2 * u * t * cx + t * t * ex + 0.5)
    local y = math.floor(2 * u * t * cy + t * t * ey + 0.5)
    local last = pts[#pts]
    if not last or last.x ~= x or last.y ~= y then pts[#pts + 1] = { x = x, y = y } end
  end
  local clean = { pts[1] }
  for i = 2, #pts do
    local a, nxt = clean[#clean], pts[i + 1]
    local corner = nxt and math.abs(nxt.x - a.x) == 1 and math.abs(nxt.y - a.y) == 1
    if not corner then clean[#clean + 1] = pts[i] end
  end
  return clean
end

local raw = bezierPixels(11, 2, 11, 11)
local fixed = buildPixels(sortRuns(getRuns(raw)), raw[1].x, raw[1].y)

local function drawCurve(pts, left)
  for _, p in ipairs(pts) do
    love.graphics.rectangle("fill", left + p.x * 16, 16 + p.y * 16, 16, 16)
  end
end

function love.draw()
  love.graphics.setColor(0.16, 0.14, 0.22)
  drawCurve(raw, 16)       -- runs →2 →3 →2 1 1 1 ↓2 ↓4: one wobble
  drawCurve(fixed, 240)    -- runs →3 →2 →2 1 1 1 ↓2 ↓4: clean
end

Pitfalls

  • Moving one pixel to fix a wobble. It shortens one run and lengthens its neighbour, often creating a new wobble next door. Reorder the run list, then redraw.
  • Reading the runs the wrong way. Across runs and down runs are measured differently. Near 45 degrees, a ↓2 is steeper than any 1, even though 2 is the bigger number.
  • Expecting perfection at tiny sizes. A quarter curve only 4 pixels wide has room for two or three runs, so some sharp turns cannot be avoided. Small round shapes get their own lesson soon.
  • Over-smoothing organic shapes. A rock or a cloud need not be a perfect countdown. These rules are for edges meant to read as smooth.
  • Leaving corner pixels in. The demo removes the extra pixel at each inside corner (a double), which makes a curve look thicker in places. That is the next lesson.

In real games

Curves are everywhere in sprites: heads, wheels, shields, bubbles, rounded dialog box corners and hilltops. When a round edge reads as clean at real size, its runs are usually in order.

Curve and ellipse tools in pixel editors round a mathematical shape to the grid, like the demo, so their output can wobble. A common habit is to use the tool for a first draft and tidy the runs by hand.

Takeaways

  • A curve is a line whose runs change: long across runs where it is flat, single pixels at 45 degrees, long down runs where it is steep.
  • On a clean curve each run is usually at least as steep as the one before. A run that goes back is a wobble and reads as a dent or bump.
  • Change the runs gradually. A big jump in steepness reads as a corner.
  • Sorting the runs removes every wobble and keeps both ends and the pixel count the same.
