Autotiling with a 4-bit mask

How checking the four neighbours of a cell gives a number from 0 to 15 that picks the right tile from a set of 16, so terrain draws itself.

You built a level from the nine platform pieces, then decided one ledge should be a tile lower. Now every corner, edge and centre piece around it must be swapped by hand, and a pillar one tile wide fits none of the nine.

The game already knows where the ground is. It can pick each piece itself.

Four questions, four bits

Yesterday's rule asked which sides of a cell face the sky. That depended on the platform being a rectangle. Autotiling asks the same question about any shape: for each ground cell, look at the four neighbours that share a side with it, up, right, down and left, and check whether each one is ground.

Four yes-or-no answers have 2 × 2 × 2 × 2 = 16 possible combinations. To turn a combination into one number, give each neighbour its own value: up is 1, right is 2, down is 4, left is 8. Add up the values of the neighbours that are ground. The result is the mask, a number from 0 to 15.

The values are powers of two for a reason. In binary, 1, 2, 4 and 8 are 0001, 0010, 0100 and 1000: each one sets a different digit, called a bit. Adding them never carries into another neighbour's digit, so no two combinations can collide. That is why it is called a 4-bit mask.

Now draw 16 tiles and save them in mask order. Tile 0 is a lone block with no neighbours, so it has an edge on every side. Tile 15 has ground all round, so it is plain fill. Tile 5 (up 1 + down 4) is a slice of a pillar: closed above and below, open left and right.

What the 16 tiles cover

The nine platform pieces are in here: the corners are 6, 12, 3 and 9, the edges are 14, 13, 11 and 7, and the centre is 15. The other seven are new. Tiles 2, 10 and 8 are the left end, middle and right end of a ledge one tile high. Tiles 4, 5 and 1 are the top, middle and bottom of a pillar one tile wide. Tile 0 is a single floating block. These are exactly the shapes the nine pieces could not close.

Drawing the set

Every tile is built from the same few parts: a top edge with grass, a bottom edge, a lit left edge, a shaded right edge, and the fill. A tile with mask m gets the edge for every side whose bit is missing. Draw the parts once, then assemble the 16 from them, and every tile automatically matches every other.

Keep the fill identical and seamless in all 16, as in the seamless tiling lesson, because any two tiles can end up side by side.

Rule of thumb

The order of the bits is a convention, not a law. Up 1, right 2, down 4, left 8 is common, but other tools use other orders. Whatever order you pick, the tile sheet must be laid out in the same order, or every tile will be the wrong one.

The 4-bit mask has one known weakness. It only looks at the four sides, never at the diagonals. Where a shape turns inwards, an inner corner, the cell in the crook has ground on all four sides and gets tile 15, plain fill, even though sky touches its corner. In the demo you will see the edges meet there with a sharp notch. The next lesson fixes it.

Try it

A small map of 8 by 8 pixel tiles. Every ground cell picks its tile from the 16 by its mask.

  • Click or drag on the map to paint ground, or start on ground to erase. With a keyboard, focus the map, move with the arrow keys and press Space to toggle a cell.
  • The selected cell shows its four neighbours on its edges: a filled badge with the value if that neighbour is ground, a hollow 0 if it is sky. The Selected cell line adds them up.
  • Paint a single block, then extend it into a ledge and a pillar. Watch the tiles of the neighbours change too, and which tiles in the set light up.
  • Turn off Autotile with the 4-bit mask for the before: the same map with one boxed tile everywhere.
  • Look at the inner corners near the bottom left.

The code

The sheet terrain16.png is 32 by 32 pixels: tiles 0 to 15, four per row, in mask order. The map is the demo's starting map. maskAt is the whole idea; everything else is loading and drawing.

local TILE = 8
local SCALE = 4
local UP, RIGHT, DOWN, LEFT = 1, 2, 4, 8
local sheet
local quads = {}
local map = {}          -- map[y][x] is true where there is ground

local START = {
  "............",
  "..#......##.",
  "..#......##.",
  "..#.####....",
  ".........#..",
  "##.......#..",
  "####...#####",
  "############",
}

local function solid(x, y)
  local row = map[y]
  return row ~= nil and row[x] == true    -- outside the map counts as sky
end

local function maskAt(x, y)
  local mask = 0
  if solid(x, y - 1) then mask = mask + UP end
  if solid(x + 1, y) then mask = mask + RIGHT end
  if solid(x, y + 1) then mask = mask + DOWN end
  if solid(x - 1, y) then mask = mask + LEFT end
  return mask                             -- 0 to 15
end

function love.load()
  love.graphics.setDefaultFilter("nearest", "nearest")
  sheet = love.graphics.newImage("terrain16.png")
  for mask = 0, 15 do                     -- Lua tables start at 1, so tile m is quads[m + 1]
    quads[mask + 1] = love.graphics.newQuad(
      (mask % 4) * TILE, math.floor(mask / 4) * TILE, TILE, TILE, 32, 32)
  end
  for y = 1, #START do
    map[y] = {}
    for x = 1, #START[y] do
      map[y][x] = START[y]:sub(x, x) == "#"
    end
  end
end

function love.draw()
  love.graphics.scale(SCALE)
  for y = 1, #map do
    for x = 1, #map[y] do
      if map[y][x] then
        local tile = maskAt(x, y)
        love.graphics.draw(sheet, quads[tile + 1], (x - 1) * TILE, (y - 1) * TILE)
      end
    end
  end
end

Because love.draw works out every mask from the map each frame, changing map[y][x] anywhere in your game is enough: the cell and its four neighbours redraw with the right tiles.

Pitfalls

  • Sheet order that does not match the bits. If your sheet puts the tiles in a different order from your values, everything still draws, just with the wrong edges. Label the tiles with their mask numbers while you draw them.
  • Forgetting the neighbours. Painting one cell changes the masks of up to four other cells. If you store tile numbers instead of computing them, update all five cells, not just the one you clicked.
  • The edge of the map. The code treats outside the map as sky, so the bottom row of the demo has an outline along the bottom of the screen. If the ground carries on past the screen, make solid return true outside the map for that side.
  • Expecting inner corners. Four bits cannot see diagonals, so a crook in the terrain gets plain fill. Keep the outline light, or move up to corner-aware autotiling.

In real games

Neighbour masks are the usual way level editors place terrain automatically. Godot 4's TileSet has terrains with a Match Sides mode, which compares the four side neighbours like this lesson, alongside modes that also match corners. The Tiled map editor has terrain sets with an edge type that works on sides. Unity's 2D Tilemap Extras package has a Rule Tile that picks a sprite from rules about its neighbours.

Your turn (15 minutes)

  1. Make a 32 by 32 canvas with an 8 by 8 grid and write the numbers 0 to 15 on a separate layer, four per row.
  2. Draw tile 15 first: a seamless fill. Copy it into all 16 cells.
  3. For each tile, add a top edge if bit 1 is missing, a right edge if 2 is missing, a bottom edge if 4 is missing and a left edge if 8 is missing.
  4. On a second canvas, assemble a 1 by 1 block, a 1 by 4 pillar and a 4 by 1 ledge by hand from your tiles.

You are done when all three shapes look like single solid objects. For a bonus, export the sheet as terrain16.png and run the LÖVE code.

Takeaways

  • The mask is the sum of the neighbour values that are ground: up 1, right 2, down 4, left 8.
  • Powers of two give each neighbour its own bit, so the 16 combinations give 16 different numbers.
  • Save the tile set in mask order and the mask becomes the tile index.
  • A 16-tile set closes every shape, including single blocks, thin ledges and pillars.
  • Four sides cannot see diagonals, so inner corners stay plain.
